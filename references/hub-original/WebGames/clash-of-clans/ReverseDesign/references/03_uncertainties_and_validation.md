# 출처 충돌·미확인 규칙·추가 검증 계획

> 기준일: 2026-11-13 KST. 이 문서는 무엇을 알고 있으며 무엇을 아직 확인하지 못했는지 추적한다. 아래 실험은 제안이며 이번 조사에서 인게임 실측을 수행했다는 의미가 아니다.

## 1. 조사 범위의 한계

- 사용자 지정 나무위키는 직접 접근 오류로 본문을 확보하지 못했다. 실제 규칙 근거로 사용하지 않았다.
- 공식 블로그 본문과 공식 지원 페이지의 검색 추출 내용을 조사했다. 일부 지원 URL은 직접 열기에 readable lines 0 또는 포털 리다이렉트가 있어 이 사실을 출처 카탈로그에 표시했다.
- 계정 로그인·앱 버전 확인·리플레이 표본 수집·수치 데이터 추출은 수행하지 않았다.
- 서버 아키텍처·AI 알고리즘·정확한 tick rate·매칭 가중치·실제 수익 지표는 확인되지 않았다.
- 공개된 기능이 모든 계정에 같은 시점에 노출되었다고 단정하지 않는다. 테스트 배포와 지원 문서의 현재 설명을 구분했다.

## 5. 문서의 검증 범위

문서 작성에서는 시스템 간 공유 규칙, 상대 파일 링크, 코드 블록 구분, 파일 구성, 출처 URL의 등록 여부를 점검한다. 본문에 있는 QA 시나리오 수는 **제안된 수용 기준의 수**이며, 실제 게임에서 실행해 통과한 테스트 수가 아니다.

실제 재구현을 시작할 때는 [25 QA·분석](../docs/25_qa_and_analytics.md)의 항목에 빌드 버전·입력 데이터·예상 결과·관찰 결과·판정자를 추가한다. 기대한 결과와 다르면 원작 규칙 해석 오류와 구현 오류를 먼저 구분한다.

## 6. 업데이트 절차

1. 새 공식 글의 발표일과 실제 적용일을 분리해 기록한다.
2. [예고] 항목이 적용되었는지 확인한다.
3. 영향을 받는 문서·테이블·모드·보상 정책을 식별한다.
4. 기존 규칙을 삭제하기보다 변경 이력으로 남기고 현행 기본값을 교체한다.
5. 공통 규칙을 다루는 문서들을 함께 수정한다.
6. 상대 링크·출처와 새 QA 경계를 검증한다.

예를 들어 11월 후반 별 보너스 개편이 적용되면 04 경제, 12 랭크, 20 패스·과제, 21 아이템, 22 UI, 23 운영의 관련 부분을 함께 확인해야 한다. 신규 화폐가 생겼다는 한 줄만 추가하면 보상 생성·지급처·저장 상한·UI·이벤트 종료가 서로 맞지 않을 수 있다.
