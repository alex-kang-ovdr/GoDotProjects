# 용어집과 시스템 간 구분

> 기준일: 2026-11-13 KST. 공식 영어 명칭을 함께 적고, 한국어는 문서 내 이해를 위한 표현으로 통일했다. 일부 최신 고유명은 현행 한국어 클라이언트의 정식 번역과 다를 수 있다. 구체 규칙의 출처는 연결된 시스템 문서에서 확인한다.

## 1. 전장·시설·성장

| 용어 | 문서에서 사용하는 뜻 | 혼동하기 쉬운 항목 |
|---|---|---|
| Home Village / 본 마을 | 계정의 주 전장·성장 공간 | 장인 기지·클랜 수도와 자원 분리 |
| Town Hall / TH / 마을회관 | 본 마을 성장 단계와 다수 해금의 기준 | TH19 예고와 기준일 현행 TH18 구분 |
| Builder Hall / BH / 장인회관 | 장인 기지의 성장 단계 | 본 마을 TH와 다른 축 |
| Capital Hall / 수도회관 | 클랜 수도의 공동 성장 기준 | 개인 계정 성장과 구분 |
| District Hall / 구역회관 | 수도 각 구역의 성장 중심 | 수도 전체 회관과 구분 |
| Builder / 장인 | 건설·일부 성장 작업을 점유하는 작업자 | Helper는 기본 슬롯을 그대로 추가하지 않음 |
| B.O.B | 장인 기지 목표로 본 마을에 합류하는 장인 | 장인 기지 작업자와 구분 |

| Helper Hut / 조력자 시설 | 도제·연구 조수·연금술사·Prospector 관련 관리 | 영웅 시설·추가 장인 오두막과 구분 |

| Blacksmith / 대장간 | 영웅 장비·광석과 연결 | 영웅 본체 레벨과 장비 레벨 분리 |
| Supercharge / 초과강화 | 최대 기본 레벨 이후의 추가 강화 | 새 기본 레벨·이벤트에 따른 수명 별도 |
| Crafted Defense / 제작 방어 | 시즌성 제작 규칙을 가진 방어 콘텐츠 | 영구 건물·초과강화와 수명 차이 |

## 2. 전투와 편성

| 용어 | 의미 | 설계상 구분 |
|---|---|---|
| Army Recipe / 군대 편성 | 저장한 공격 조합 | 저장 가능·사용 가능·실제 투입은 다른 상태 |
| Housing Space / 수용량 | 병력·지원군이 점유하는 편성 예산 | 인원 수·탄약·HP와 다름 |
| Funnel / 진입 유도 | 주변 목표 제거로 병력의 다음 선택을 유도 | 직접 이동 명령이 아님 |
| Target Priority / 목표 우선순위 | 먼저 찾는 대상의 범주 | 가장 가까운 건물 규칙 하나로 환원 불가 |
| Ground/Air / 지상·공중 | 이동 및 타깃 적격성의 층 | 시각적 높이와 논리 판정은 별개 |
| AoE / 범위 효과 | 일정 영역의 다수 대상에 적용되는 효과 | 여러 효과가 있을 때 합성 정책 필요 |
| DPS | 일정 시간당 평균 피해 | 한 발 피해·공격 주기·실제 생존 시간과 구분 |
| DoT | 시간에 걸친 피해 | 즉시 피해·시각 지속 시간과 구분 |
| TTK | 특정 대상을 처치하는 데 걸린 시간 | 단순 HP/DPS만으로 항상 계산되지 않음 |
| Siege Machine / 시즈 머신 | 경로·탑재 병력·투입 방식을 바꾸는 공격 수단 | 일반 병력과 탑재물 수명 차이 |
| Super Troop / 슈퍼 유닛 | 별도 활성화·기간 규칙이 있는 강화 병력 | 이벤트 임시 병력과 구분 |
| Hero Equipment / 영웅 장비 | 영웅 행동·능력을 바꾸는 선택 및 성장 요소 | 영웅 레벨·외형 스킨과 구분 |
| Pet / 펫 | 영웅에 연결하는 보조 전투 단위 | 수비 전용 가디언과 구분 |
| Guardian / 가디언 | 마을회관 방어와 연결되는 선택 요소 | 공격 영웅·펫 슬롯에 넣지 않음 |
| Destruction / 파괴율 | 모드가 정한 파괴 진행 지표 | 별·시간·약탈률과 별개 |

## 5. 기술 표현은 재구현 제안 용어

| 표현 | 문서 내 의미 |
|---|---|
| Snapshot | 특정 시점의 전투용 상태 사본 |
| Revision | 같은 계정·배치·구역 데이터가 갱신된 순번 |
| Idempotency / 중복 처리 방지 | 같은 요청을 재전송해도 결과가 한 번만 발생하는 성질 |
| Ledger / 원장 | 자원·점수 변화의 원인과 내역을 보관하는 기록 |
| Transaction / 원자적 처리 | 관련 변경이 모두 성공하거나 모두 적용되지 않게 묶는 처리 |
| Compare-and-swap | 읽은 버전이 아직 맞을 때만 갱신하는 충돌 방지 방식 |
| Determinism / 결정론 | 같은 초기 상태·규칙·입력에서 같은 결과를 얻는 성질 |
| Rule Catalog | 해금·시간·점수·효과 정책을 버전별로 보관하는 정의 집합 |
| Battle Contract | 한 전투의 상대·편성·규칙·보상을 고정한 계약 |

이 이름들은 원작에서 추출한 클래스·서버 이름이 아니다. 구체 모델은 [24 아키텍처](../docs/24_data_architecture_and_network.md)에 있다.
