# V3 조준·표적 선택·전투 피드백 시스템

## 1. 목적과 범위

플레이어가 화면에서 읽은 정보와 실제 발사 결과를 일치시킨다. 담당 파일은 `dist/game.js`, `dist/interaction.js`, `dist/render.js`이다. 시뮬레이션의 실제 발사 가능 여부는 `sim.js`의 `getWeaponSolution`이 결정한다.

기능은 일반 자유 작전, 원정, 기초 훈련에서 같은 입력·판정을 사용한다. 선행 조준은 관측한 현재 속도에 대한 예측이며, 적의 이후 기동이나 숨겨진 위치를 사용하지 않는다.

## 2. 카메라와 좌표

한 프레임의 순서는 다음과 같다.

1. 일반 시점·전술 지도·조준경 중 현재 모드의 카메라 위치와 배율을 계산한다.
2. `renderer.setViewTransform(cameraX, cameraY, zoom)`으로 이번 프레임 변환을 확정한다.
3. 마우스 화면 좌표가 있으면 확정된 변환의 `screenToWorld`로 조준점을 계산한다.
4. 1/60초 고정 간격으로 실제 전투를 진행한다.
5. 2번과 같은 카메라 변환으로 화면을 그린다.

이 순서로 이전 프레임 카메라를 이용해 조준하고 새 카메라로 그릴 때 생기던 포인터·조준점 오차를 제거한다. 고정 월드 좌표를 사용한 선행 조준 뒤에는 포인터 투영을 중단한다. 이후 플레이어가 다시 마우스를 움직이거나 바다를 터치하면 수동 조준으로 돌아간다.

변환 함수는 유효하지 않은 숫자에서 기존 값을 보존하며, 배율을 0.08–3으로 제한한다. 일반 전투의 사용자 배율은 별도의 더 좁은 범위를 사용한다.

## 3. 표적 선택

### 선택 사건

| 입력 | 결과 |
|---|---|
| 적 함체·이름표 클릭 또는 터치 | 해당 적을 선택 |
| Tab 또는 표적 선택 버튼 | 현재 보이는 적을 거리순으로 순환 |
| 일반 마우스 이동 | 조준점만 이동 |
| 최초 적 접촉, 아직 표적을 선택한 적 없음 | 최초 가까운 적을 한 번 선택 |

명시적 선택은 `targetId`로 보존한다. 단순히 커서가 적 근처를 지나가는 것으로 표적을 바꾸지 않는다.

`pickTarget`은 컨트롤러가 전달한 **현재 보이는 적 목록**만 검사한다. 회전한 함체의 화면상 길이·폭과 이름표 위치를 이용하며 작은 함체도 최소 48px 폭의 터치 영역을 갖는다. 여러 영역이 겹치면 정규화한 거리가 가장 가까운 항목을 선택한다. 함체에서 멀리 떨어진 커서로 자동 선택되지 않는다.

### 접촉 상실

시야에서 벗어난 표적의 ID를 유지하고 HUD에 접촉 상실을 표시한다. 남은 HP나 현재 위치를 갱신하지 않는다. 조준경은 마지막으로 관측한 안전한 위치를 유지하며 다른 적으로 자동 전환하지 않는다. 선행 조준과 아군 집중 공격 버튼은 비활성화된다. 새 표적은 플레이어가 다시 선택한다.

현재 적 위치는 `isVisible`을 통과한 경우에만 읽어 표시·선행 조준에 사용한다. 마지막 접촉 표시는 `lastKnown` 또는 마지막으로 보였을 때 기록한 좌표를 이용한다.

## 4. 선행 조준

L 또는 선행 조준 버튼을 누르면 선택한 보이는 적에 대해 `predictIntercept`를 한 번 호출한다. 주포에서는 함종의 포탄 속도를, 어뢰에서는 어뢰 속도를 적용한다. 반환한 좌표가 월드 조준점이 된다.

- 현재 속도와 방향이 유지된다는 가정이다.
- L 입력 자체는 발사하지 않는다.
- 적의 이후 선회에 맞춰 조준점을 자동 이동하지 않는다.
- 조준경 카메라는 선택한 보이는 표적을 따라갈 수 있지만 사격 조준점은 별개이다.
- 예측점이 사거리·발사각·사선 조건을 벗어나면 실제 무장은 발사하지 않는다.

짧게 한 번 누른 발사는 포탑 정렬을 기다리는 제한된 대기열을 사용한다. 최대 대기는 4.5초이며, 남은 재장전이 0.8초를 넘으면 한 번 누른 입력을 저장하지 않는다. 계속 발사하려면 마우스·Space·FIRE를 유지한다. 무장 변경, 표적 변경, 선행 조준, 일시정지·지도 등 입력 초기화 시 대기열을 제거한다.

## 5. 명중과 지속 피해 표시

### 직접 명중

명중 안내는 마지막으로 처리한 이벤트 ID보다 새로운 이벤트만 읽는다. `type=hit`, 플레이어 `ownerId`, `ammo ∈ {HE, AP, TORP}`, `secondary !== true`인 이벤트를 한 묶음으로 요약한다. 이전 이벤트나 단순 누적 피해 증가만으로 결과를 추정하지 않는다.

같은 UI 갱신에 여러 발이 맞으면 실제 적용 피해를 합산하고 대표 결과를 선택한다. 우선순위는 집중방호구역 → 어뢰 → 일반 관통 → 과관통 → 일반 명중 → 도탄 → 비관통이다. 피해가 0인 도탄·비관통도 별도 결과를 표시한다. 음향은 실제 직접 명중에서 발생하며 지속 피해가 이전 포격 음향을 반복시키지 않는다.

### 지속 피해와 부포

`damageBreakdown.FIRE`, `FLOOD`, `SECONDARY`의 증가를 별도로 추적한다. 증가한 종류의 누적 피해를 작은 안내에 표시한다. 이 값들은 주포의 관통·도탄 결과와 합치지 않는다. 결과 보고서에서는 같은 분류의 최종 피해를 막대와 수치로 제시한다.

## 6. 저장과 재개

시뮬레이션 스냅샷 외부의 `control` 객체에 다음 정보를 저장한다.

```json
{
  "ammo": "AP",
  "spread": "narrow",
  "aimX": 2100,
  "aimY": 1630,
  "binocular": false,
  "targetId": "red-ca",
  "sessionType": "free",
  "campaignRunId": null,
  "campaignStage": null
}
```

복원은 열거값·유한 좌표·표적 ID·원정 ID와 단계 범위를 검증한다. 아군 ID는 표적 선택으로 복원하지 않고, 전함의 어뢰 선택도 거부한다. 눌린 키·마우스·터치 상태는 저장하지 않는다. V2처럼 `control`이 없으면 시뮬레이션에 저장된 함선 조준점을 사용하고 HE·좁은 확산·일반 시점으로 시작한다.

훈련의 별도 진도 저장에는 이 객체나 실제 전투 스냅샷을 넣지 않는다. 현재 훈련 장면은 새로 생성한다.

## 7. 검증

`node tests/interaction.test.cjs`는 다음 회귀 위험을 검사한다.

- V2 조준점 기본 복원과 V3 무장·확산·조준경·표적 복원.
- NaN·과도한 좌표·잘못된 표적·전함 어뢰 선택 거부.
- 원정 메타데이터의 범위 검증.
- 0 피해 도탄 표시와 다발 명중 합산.
- 지속 피해·부포·다른 함선 명중을 플레이어 주포 결과로 잘못 표시하지 않음.
- 카메라와 배율이 바뀌어도 화면↔월드 좌표의 왕복 일치.
- 작은 함체·이름표·회전한 함체의 선택과 빈 가시 표적 목록의 안전성.

실제 화면 크기·버튼 접근·훈련 조작·저장 후 재개는 별도의 브라우저 확인 대상이며 결과는 `CHANGELOG.md`에 기록한다.
