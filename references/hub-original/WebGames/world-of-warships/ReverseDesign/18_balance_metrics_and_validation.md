# 18. 밸런스 구조·지표·검증·재현 실험

> 이 문서의 지표·실험·계산은 **분석 및 제안**이다. 실제 WoWS 운영 데이터에 접근하거나 실험을 수행한 보고서가 아니다.
> 공식 발표 수치를 인용한 부분만 별도로 [확인]을 표시한다.

[전체 목차](README.md) · [함종](02_ship_classes_and_nations.md) · [통합 구현·QA](19_implementation_architecture_and_qa.md)

## 1. 무엇을 균형 잡는 게임인가

[분석] 함선의 가치를 DPS 하나로 표현하기 어렵다. 공격 결과는 정보, 도달 가능한 위치, 장갑과 탄종, 재장전, 아군 지원, 목표 규칙에 의해 달라진다.

밸런스는 적어도 다음 다섯 영역의 교환으로 읽어야 한다.

| 영역 | 강점이 의미하는 것 | 지불할 수 있는 대가 |
|---|---|---|
| 화력 | 유효 피해·순간 폭발력·명중 기회 | 긴 장전·나쁜 사격각·낮은 은폐 |
| 생존 | 버틸 수 있는 시간·회복·위험 흡수 | 큰 선체·저속·긴 노출 |
| 정보 | 적 발견·위치 추론·아군 사격 허용 | 접근 위험·직접 피해 기회 감소 |
| 기동 | 유리한 각도·퇴로·재배치 | 장갑·화력·사거리의 제한 |
| 목표 기여 | 거점·호위·시간 압박 | 특정 구역 체류·예측 가능한 경로 |

다섯 축은 완전히 독립하지 않는다. 은폐는 생존과 첫 사격 기회를 함께 바꾸고, 가속은 회피와 점령 도달 시간을 함께 바꾼다.

## 2. 이론 DPM과 실제 유효 화력

[분석] 기초 비교식은 다음과 같다.

```text
이론 DPM = 포문 수 × 표시 탄 피해 × 60 / 재장전 시간
유효 DPM의 설명 모형
         ≈ 이론 DPM × 사격 기회 비율 × 명중 확률 × 명중당 피해 전환율
```

뒤의 식은 원작 공식 계산식이 아니다. 각 변수는 서로 영향을 주므로 정확한 전투 예측에는 부족하지만, 무엇을 따로 측정해야 하는지 보여 준다.

### 2.1 자체 계산 예제

가상의 함선 A: 8문, 표시 피해 10,000, 장전 30초.

- 이론 DPM: `8 × 10,000 × 2 = 160,000`.
- 사격 기회 비율 0.8, 명중 확률 0.25, 평균 피해 전환율 0.33 가정.
- 유효 DPM 근사: `160,000 × 0.8 × 0.25 × 0.33 = 10,560`.

표시 피해가 10% 증가해도 사격 가능한 각도·생존·명중이 바뀌면 실전 변화는 달라진다. 처음부터 재장전 완료 상태로 시작하는 유한한 교전에서는 발사 횟수도 경계 효과를 갖는다.

## 3. 갑작스러운 성능 변화가 생기는 임계점

| 변경 | 연속적으로 바뀌는 부분 | 불연속적으로 바뀔 수 있는 부분 |
|---|---|---|
| 포 구경 | 표시 피해·탄도 등 | 특정 장갑 오버매치 가능 여부 |
| HE 관통 | 일부 대상 명중 피해 | 기존 비관통 구획이 관통으로 전환 |
| 피탐 거리 | 접근 가능 거리 | 레이더·어뢰·거점과의 선후 관계 |
| 재장전 | 장기 평균 화력 | 적 소모품 공백 안에 한 발 추가 |
| 수리 성능 | 총 회복 가능량 | 다음 적 일제사격 생존 여부 |
| 대공 사거리 | 항공기 노출 시간 | 아군과 겹치는 방공 구역 형성 |
| 속도·가속 | 이동 시간 | 특정 안전 구간을 닫히기 전에 통과 |

관련 실제 경계는 [05](05_armor_penetration_and_damage.md), [08](08_detection_vision_and_information.md), [11](11_consumables_and_tactical_cycles.md)에서 확인한다. 밸런스 조정에서는 평균 변화 외에 **어떤 상대 집합의 상성이 바뀌는지**를 따로 계산해야 한다.

## 4. 함종 상성을 행렬 하나로 끝내면 안 되는 이유

[분석] 구축함과 전함의 관계만 해도 거리·레이더 지원·어뢰 준비·아군 탐지에 따라 역전된다. 따라서 상성은 다음 조건을 붙인 관계로 정의한다.

```text
상성 결과 = f(두 함선의 구성,
              거리·각도·지형,
              탐지 상태,
              소모품·장전 상태,
              아군 지원,
              목표·점수·남은 시간)
```

'이 함종이 저 함종을 이긴다'보다 '어떤 상태에서 어떤 선택이 강해지는가'가 재현과 밸런스에 더 유용하다.

## 5. 전투 지표의 최소 집합

[제안]

| 지표 | 단위 | 단독으로 보면 생기는 오해 |
|---|---|---|
| 승률 | 전투 | 사용자 숙련·분대·모드 선택 영향 |
| 피해량 | HP | 상대 최대 HP·회복 가능 피해 차이 |
| 최대 HP 대비 피해 비율 | 정규화 피해 | 목표 기여·탐지 누락 |
| 첫 격침까지 시간 | 초 | 빠른 조기 격침과 수동적 플레이 혼동 |
| 생존 시간 | 초 | 유효 전투를 피한 생존도 높게 평가 |
| 탐지 지원 피해 | HP | 아군 조준·시야·중복 탐지 영향 |
| 거점 유효 기여 | 점령·방해·수익 시간 | 위험한 거점 진입을 과잉 보상 가능 |
| 잠재 피해 | 표시 잠재량 | 승리와 무관한 위험 노출 포함 |
| 회복 유효량 | 실제 HP 회복 | 소모품 낭비·회복 가능 원장 제한 |
| 무장 가동률 | 유효 시간 비율 | 사거리·발사각·장전·손상 원인 분리 필요 |
| 항공 자원 손실 | 기체·재생 시간 | 실제 공격 기회 상실과 차이 |
| 플레이 중단·이탈 | 계정·전투 | 기술 장애와 경험 불만 구분 |

## 6. 지표를 나눠 보는 축

[제안] 최소한 아래 조건을 보존한다.

- 패치 버전·서버 지역·전투 종류.
- 함선·모듈·강화·함장 스킬·신호기.
- 상위/동일/하위 티어 참가 여부.
- 솔로와 분대, 팀 구성의 비대칭.
- 사용자 숙련·해당 함선 경험·복귀 여부.
- 맵·목표·날씨.
- 전투 시간대·매칭 대기 시간.
- 항모·잠수함 존재와 수.

같은 함선의 전체 승률이 높아도 고숙련 사용자만 소유했다면 함선 자체의 원인이라고 확정할 수 없다. 특히 새 보상 함선과 무료 연구 함선은 획득 경로부터 사용자 분포가 다를 수 있다.

## 7. 원인 분석의 예

관측: '함선 B가 A보다 평균 피해량이 높다'는 결과가 나왔다고 가정한다.

가능한 설명:

1. B의 화력이 강하다.
2. B가 주로 최대 HP가 큰 대상을 공격한다.
3. B 이용자가 더 숙련되어 있다.
4. B의 전투가 더 오래 지속된다.
5. B가 회복 가능한 지속 피해를 많이 준다.
6. B가 생존·목표·탐지를 희생해 개인 피해를 늘린다.

[제안] 같은 사용자의 A/B 기록, 같은 티어·맵·모드, 생존 시간과 목표 기여, 적 대상 구성을 함께 비교한다. 모든 교란을 제거할 수 없으므로 결과에는 관측 비교와 인과 실험을 구분해 표시한다.

## 8. 공식 운영 사례: 항공 탐지 축소

[확인] 개발사의 2026년 하반기 로드맵 회고는 14.6 대비 15.4에서 항모의 평균 탐지 지원 피해가 약 30% 줄었다고 설명한다. 이는 개발사 발표이며 본 문서가 원시 데이터를 독립 분석한 결과는 아니다. [R23]

[분석] 이 사례에서 읽을 수 있는 것은 '항모 승률이 얼마인가' 외에도 **항공 탐지가 다른 플레이어의 행동 자유에 어떤 영향을 주는지**를 별도 목표로 측정한다는 점이다.

단, 공개된 감소율만으로 특정 변경 한 개의 순수 효과나 모든 티어·모드의 동일 감소를 주장할 수는 없다. 항공 탐지 조정, 전투기 변경, 이용자 구성 변화가 시간에 걸쳐 함께 작용했을 수 있다.

## 9. 표본 수와 불확실성

[제안] 승패를 서로 독립인 이항 시행으로 단순화하면 승률 추정의 표준오차는 다음과 같다.

```text
SE ≈ sqrt(p × (1-p) / n)
95% 근사 오차폭 ≈ 1.96 × SE
```

승률 50% 부근의 예:

| 표본 전투 수 | 95% 근사 오차폭 |
|---:|---:|
| 100 | ±9.8%p |
| 1,000 | ±3.1%p |
| 10,000 | ±1.0%p |

실전 기록은 같은 사용자·분대·시간대가 반복되어 독립성이 약하다. 따라서 위 표를 정밀한 밸런스 신뢰구간으로 사용하기보다, 작은 표본에서 1~2%p 차이를 과신하지 않는 설명으로 활용한다. 실제 분석에는 사용자·전투 군집을 고려한다.

## 10. 재현 가능한 실험 설계

### 10.1 관통·피해 실험

1. 공격자·대상·모듈·스킬·신호기·탄종을 기록한다.
2. 거리·방향·명중 구획을 고정한다.
3. 판정 경계의 양쪽 값을 시험한다.
4. 순수한 규칙 시험과 분산이 포함된 명중률 시험을 분리한다.
5. 포화·화재·회복으로 다음 시행이 오염되지 않도록 상태를 초기화한다.
6. 결과 리본, 실제 HP 감소, 회복 가능량을 각각 기록한다.

### 10.2 탐지 실험

- 관측자 종류·거리·시야 차단·연막·발포·화재를 하나씩 변경한다.
- 자기 관측, 아군 공유, 월드 모델, 미니맵 표시를 따로 기록한다.
- 화면 캡처 한 장만으로 탐지 갱신 지연을 확정하지 않는다.
- 함선의 이동과 서버 갱신 간격을 분리해 측정한다.

### 10.3 기동 실험

- 정지→전진, 최고속도→정지, 전진→후진, 일정 속도 선회를 분리한다.
- 표시 속도와 월드 이동량의 관계를 따로 기록한다.
- 조타 시간·선회 반경·속도 손실을 동시에 하나의 상수로 맞추지 않는다.
- 시각 파도와 실제 선체 충돌·명중 판정을 구분한다.

## 11. 규칙 변경 실험의 범위

[제안]

| 변경 크기 | 적절한 검증 | 확인할 위험 |
|---|---|---|
| 한 함선 계수 | 대조 함선·상대별 비교 | 특정 장갑·거리 임계점 |
| 한 무장군 | 여러 함종·티어 교차 | 역할 잠식·극단 빌드 |
| 탐지·장갑 공통 규칙 | 전투 구성 전체 비교 | 전술·학습·UI의 동시 변화 |
| 매칭 규칙 | 대기 시간·편성·승패 격차 | 특정 시간대 큐 붕괴 |
| 경제 | 보상·지출·모드 선택 변화 | 재화 인플레이션·행동 왜곡 |
| 이벤트 | 임무 참여·승리 기여 비교 | 목표 충돌·막판 과부하 |

일반 라이브 전투에서 한쪽 팀만 더 강한 규칙을 받는 방식은 검증 설계 자체가 경험을 훼손할 수 있다. 테스트 서버·모드별 분리·대칭 규칙 등 적합한 배치를 선택한다.

## 12. 밸런스 변경 제안서 양식

```yaml
BalanceChangeProposal:
  problem_statement: measurable_player_problem
  evidence_window: patch_and_dates
  affected_population: ships_modes_skill_groups
  suspected_mechanism: causal_hypothesis
  proposed_change: one_or_more_config_deltas
  expected_effect: direction_and_range
  guardrail_metrics: collateral_risks
  validation_plan: controlled_and_live_observation
  rollback_condition: explicit_threshold
```

'승률이 높으니 피해량을 줄인다'만으로는 부족하다. 문제가 근거리 폭발력인지, 안전한 장거리 피해인지, 정보 독점인지 먼저 구분해야 한다.

## 14. 재현 프로젝트의 합격 기준

[제안] 다음 순서로 완료를 판정한다.

1. **규칙 일치**: 주요 상태 전이와 경계 결과가 설계표와 일치한다.
2. **정보 일치**: 볼 수 없는 정보가 UI·로그·네트워크에 노출되지 않는다.
3. **상호작용 일치**: 무장·피해·탐지·회복이 결합되어도 일관적이다.
4. **결과 일치**: 같은 입력·구성·난수 조건의 재생에서 판정이 재현된다.
5. **경제 일치**: 전투 결과와 보상·소모가 중복 없이 연결된다.
6. **경험 검증**: 수치가 맞더라도 이해·반응·재배치가 가능한지 확인한다.

이 문서에 적힌 검증 항목은 실행 결과가 아니다. 실제 실험 시에는 빌드·설정·관측 자료·실패 사례를 별도 기록해야 한다.
