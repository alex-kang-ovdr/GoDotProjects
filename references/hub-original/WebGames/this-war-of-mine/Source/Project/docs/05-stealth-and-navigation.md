# 05. 소음 유인·탐색 지도·귀환 안내

LAST LIGHT 4.0의 야간 전술과 길 안내 구현 명세입니다. 기준 코드는 [expedition.js](../dist/expedition.js), 입력과 일시정지 연결은 [app.js](../dist/app.js), 지도와 조준 표현은 [scene.js](../dist/scene.js)입니다. 수치와 동작은 이 프로젝트의 구현을 설명합니다.

## 1. 플레이 목적

소음 유인은 가방 속 부품을 사용해 다른 위치로 관심을 돌리는 행동입니다. 물자를 아끼면 시설과 구호 준비에 사용할 수 있고, 현장에서 사용하면 경비가 이동하는 동안 다른 길을 선택할 기회를 얻습니다.

공격·회피와 달리 상대에게 피해를 주지 않습니다. 그러나 투척 성공 자체가 안전 확보를 의미하지는 않습니다. NPC가 소리를 들을 수 있는지, 이미 수색자를 보고 있는지, 조사 중 수색자를 다시 발견하는지가 결과를 결정합니다.

탐색 지도는 발견한 장소와 현재 보이는 사람을 정리하고 귀환 방향을 안내합니다. 미탐험 공간이나 보지 못하는 경비의 위치를 알아내는 수단으로 사용하지 않습니다. 기존 야간 전투·문·주민 허락 규칙은 [02. 야간 탐색·전투·주민 상호작용](02-night-and-encounters.md)을 따릅니다.

## 2. 조작과 시간 흐름

| 입력 또는 상황 | 동작 |
|---|---|
| `T` 또는 소음 유인 버튼 | 던질 위치 선택 시작, 현장 시간 정지 |
| 장면 클릭 또는 탭 | 화면 좌표를 세계 좌표와 층으로 변환하여 투척 요청 |
| `Esc`, 다시 `T`, 조준 취소 버튼 | 투척 없이 조준 종료, 조준 전 일시정지 상태 복원 |
| 올바르지 않은 위치 선택 | 이유 표시, 비용 차감 없이 조준 유지 |
| 투척 성공 | 조준 종료, 현장 시간 재개 |
| 이동·공격·회피 등 다른 행동 | 조준을 취소하고 해당 행동의 규칙 적용 |
| 창 포커스 이탈 또는 숨겨진 탭 | 조준과 입력을 정리하고 게임 일시정지 |
| 대화상자 열기 | 조준을 취소한 뒤 기존 대화상자 일시정지 규칙 적용 |

조준 중에는 100초 수색 제한시간, NPC 행동, 재사용 대기 시간이 진행하지 않습니다. 성공한 투척은 새 행동을 확정한 것이므로, 조준에 들어오기 전 수동 일시정지 상태였더라도 시간을 재개합니다. 취소했을 때만 이전 일시정지 상태를 돌려줍니다.

UI의 `distractionAim`과 `aimTarget`은 입력 상태입니다. 영구 캠페인 데이터에 넣지 않습니다. 저장 파일을 불러온 뒤에는 조준 상태로 돌아가지 않으며, 멈춘 게임에서 다시 조준을 시작할 수 있습니다.

## 3. 비용과 유효 범위

| 규칙 | 값 | 의미 |
|---|---:|---|
| 가방 비용 | 부품 1 | 은신처 공용 재고가 아니라 수색자가 들고 있는 물품 |
| 최소 수평 거리 | 60 | 바로 발밑에는 던질 수 없음 |
| 최대 수평 거리 | 260 | 현재 위치에서의 수평 거리 |
| 재사용 대기 | 8초 | 현장 시뮬레이션이 진행할 때 감소 |
| 착지점 소리 표시 | 2.5초 | 제한된 수명의 소리 사건과 시각 효과 |
| NPC 청취 거리 | 최대 350 | 같은 층이며 닫힌 문이 사이에 없어야 함 |
| 조사 기억 | 4.5초 | NPC가 유인 소리를 받아들인 시점부터 시작 |

투척 좌표는 유한한 숫자여야 하고, 층은 현재 층과 같아야 합니다. 수평 세계 범위 `65..1215`, 현재 시야 구간, 최소·최대 거리 조건을 모두 만족해야 합니다. 닫힌 문 너머로 물체를 보내는 투척은 거부합니다.

현재 시야는 같은 층의 최대 330 범위를 문으로 잘라 얻습니다. 투척 사거리 260보다 시야가 길어도, 닫힌 문이나 세계 끝 때문에 실제 선택 가능한 구간은 더 짧아질 수 있습니다.

좌표를 지정하지 않은 조회는 바라보는 쪽 200 거리를 기본 조준점으로 제안합니다. 문과 세계 경계 안으로 줄인 뒤 최소 거리 60을 확보하지 못하면 반대 방향을 제안합니다. 이 보정은 명시적으로 클릭한 좌표를 다른 곳으로 바꾸지 않습니다.

계단 이동·회피·조사·응급처치·공격 동작 중에는 투척을 시작할 수 없습니다. 사망했거나 이미 종료한 수색, 남은 재사용 대기, 부족한 부품도 실패 조건입니다.

## 4. 조회와 실행 API

```javascript
const preview = getDistraction(expedition, targetX, targetFloor);
// {
//   available, reason, target: { x, floor } | null,
//   cost: { parts: 1 }, cooldown: 8, remainingCooldown,
//   range: 260, minRange: 60
// }

const result = throwDistraction(expedition, targetX, targetFloor);
// 성공: { ok: true, event: { x, floor, remaining, total }, cost, message }
// 실패: { ok: false, reason }
```

`getDistraction`은 읽기 전용입니다. 재고, 탐험 기록, 난수, 시간, 저장 버전을 변경하지 않습니다. 조준선을 매 프레임 그려도 캠페인 결과에 영향을 주지 않습니다.

`throwDistraction`은 전체 가능 조건을 다시 검사합니다. UI가 가능하다고 표시한 뒤 상태가 바뀌어도, 엔진의 재검사에서 거부할 수 있습니다. 실패 시 부품·사용 횟수·소리·이동 경로를 변경하지 않습니다.

성공하면 다음 변화가 하나의 동기 호출 안에서 일어납니다.

1. 가방의 부품 1개를 차감하고, 수량이 0이면 해당 품목 키를 제거합니다.
2. 착지점에 소리 사건과 표시용 `distraction`을 생성합니다.
3. 재사용 대기를 8초로 설정하고 성공한 투척 횟수를 1 증가시킵니다.
4. 수색자의 기존 이동 경로·목적지·이동 플래그와 열린 물품 패널을 정리합니다.
5. 결과 메시지를 기록하고 UI가 시간 재개를 처리하도록 반환합니다.

물체를 던지기로 선택한 뒤 이전 클릭 이동이 계속되어 위험한 방으로 들어가는 것을 막기 위해 경로를 취소합니다. 은신처 안에서 던졌다면 `player.hidden`은 유지합니다. 투척 소리를 플레이어 위치의 일반 소음으로 바꾸지 않기 때문에, 소리의 출처는 착지점입니다.

입력 기반 호출도 지원합니다. `stepExpedition`의 `input.distraction`은 누르기 시작한 프레임에만 반응하며, `input.distractionTarget`으로 좌표를 전달할 수 있습니다. 버튼을 계속 누른 채 8초가 지나도 자동으로 다시 던지지 않습니다.

## 5. NPC 판단과 우선순위

유인 소리는 기존 소리 배열에 `kind: 'distraction'`으로 들어갑니다. 걷기·문 열기·조사 등 일반 소음과 출처를 구분합니다. NPC는 자신이 이미 처리한 소리보다 새로운 사건만 검토합니다.

| NPC 상황 | 유인 처리 |
|---|---|
| 현재 수색자를 직접 봄 | 유인으로 주의를 바꾸지 않음 |
| 공격 예고 또는 공격 동작 진행 | 기존 공격 판정이 우선 |
| 계단 이동 중 | 현재 층의 유인으로 즉시 방향을 바꾸지 않음 |
| 도주·제거·사망 | 유인 대상으로 처리하지 않음 |
| 다른 층에 있음 | 유인 소리를 듣지 않음 |
| 착지점과 사이에 닫힌 문이 있음 | 유인 소리를 듣지 않음 |
| 청취 범위 안이고 수색자를 보지 못함 | 착지점을 마지막 확인 위치로 삼아 조사 |

소리를 받아들인 NPC는 `investigate` 상태가 되고, 착지점을 `lastKnown`으로 기록하며, 조사 기억을 4.5초로 설정합니다. 기존 경로와 목적지를 비워 실제 이동 경로를 다시 계산합니다. 이동은 기존 경로·계단·문 처리와 NPC 속도의 90%를 사용하며 좌표를 순간 이동시키지 않습니다.

착지 효과가 2.5초 후 사라져도, 이미 시작한 조사는 남은 기억 시간 동안 계속할 수 있습니다. 조사 중 수색자를 다시 발견하면 기존 시야·경고·추격·공격 규칙이 적용됩니다. 이후의 다른 소음도 기존 청취 규칙에 따라 새 조사 방향을 만들 수 있습니다.

유인은 NPC의 `hostile`이나 `aggression`을 지우지 않습니다. 적대 경비는 여전히 적대적이며, 다시 보이면 추격합니다. 중립 주민은 투척 소리를 조사했다는 이유만으로 적대화하지 않습니다. 기존 출입·물품 허락 역시 유인만으로 철회되지 않습니다.

투척은 상대가 듣기 전에 수색자에게 이미 보이는 경우, 청취 범위 밖인 경우에도 정상적으로 성공할 수 있습니다. 이 경우에도 부품을 사용합니다. 행동의 성공과 전술적 효과를 분리하여 자원 선택에 대가가 남도록 했습니다.

## 6. 직렬화 상태와 불러오기

| 위치 | 필드 | 저장 값 |
|---|---|---|
| 원정 | `distraction` | `null` 또는 `{ x, floor, remaining, total }` |
| 원정 | `distractionCooldown` | 남은 재사용 대기, `0..8` |
| 원정 | `_distractionHeld` | 입력 상승 에지 기억, 불리언 |
| 원정 통계 | `stats.distractions` | 성공한 투척 횟수, 정수 `0..100` |
| 소리 배열 | `kind` | 기존 소음은 생략, 유인은 `'distraction'` |
| 소리 배열 | `aggressive` | 유인 소리는 `false` |
| 완료 결과 | `result.distractions` | 정수 `0..100` |
| NPC | `lastKnown`, `memory`, `state` | 기존 직렬화 구조로 조사 지점과 남은 행동을 유지 |

`distraction.total`은 2.5이고, 존재하는 효과의 `remaining`은 0보다 크고 2.5 이하여야 합니다. 효과 시간이 끝나면 0짜리 객체를 남기지 않고 `null`로 바꿉니다. 좌표·층·재사용 대기·횟수·소리 종류가 잘못된 가져오기 자료는 거부합니다.

유인 소리 사건의 남은 시간은 최대 2.5초까지 허용하고, 공격적인 소리로 위장한 유인 사건은 허용하지 않습니다. 소리 배열은 기존과 같이 최대 12개로 제한합니다. 배열 전체나 NPC 객체를 화면 컴포넌트에 영구 참조로 저장하지 않습니다.

이전 저장에 새 필드가 없으면 `distraction:null`, 재사용 대기 0, 횟수 0, 입력 플래그 `false`를 보완합니다. 진행 중 유인이 있는 저장은 가방 비용·남은 시간·NPC 조사 위치를 유지하며 재실행하거나 비용을 다시 차감하지 않습니다.

원정 결과의 횟수는 [engine.js](../dist/engine.js)의 밤 정산에서 캠페인 통계에 누적되고 보고서에 표시됩니다. 이 수치는 **실제로 성공한 투척 호출 수**이며, 경비를 속인 횟수나 안전을 확보한 횟수가 아닙니다. 저장 전반의 경계는 [03. 캠페인·결말·저장 시스템](03-campaign-and-saving.md)을 참고하세요.

## 7. 탐색 정보 API

```javascript
const navigation = getNavigation(expedition);
// {
//   floor, exploredPercent,
//   exit: { x: 100, floor: 0, reached, distance,
//           knownRoute, blockedDoorId, route: [{ x, floor }, ...] },
//   marks: { loot, doors, hides, stairs, npcs }
// }
```

`getNavigation`도 읽기 전용입니다. 저장된 탐험 구간과 현재 시야를 합친 복사 자료를 사용합니다. 조회로 새 상자를 조사하거나 NPC를 발견 처리하거나 물자를 생성하지 않습니다.

`exploredPercent`는 세 층 각각의 수평 구간 `65..1215` 중 확인한 길이의 합을 전체 길이 3450으로 나눈 정수 백분율입니다. 방 개수, 수집한 물품 비율, 상자 조사 완료율을 뜻하지 않습니다.

| 지도 표시 | 노출 조건과 범위 |
|---|---|
| 상자 | 발견한 ID만 표시, 좌표·이름·조사·비어 있음·잠금·소유·현재 가시 여부 제공 |
| 상자 내용 | 지도 API에 품목별 수량을 넣지 않음 |
| 문 | 발견한 문만 표시, 열린 상태·잠금·현재 가시 여부 제공 |
| 숨을 곳 | 확인한 수평 구간 안의 지점만 표시 |
| 계단 | 한쪽 끝을 발견하면 그쪽 위치 표시 가능 |
| NPC | 현재 시야에 있는 살아 있는 인물만 표시, 화면 밖 기억 표식 없음 |

현재 보이지 않는 상자·문은 발견한 지점으로 남을 수 있습니다. NPC는 한 번 보았더라도 시야를 벗어나면 지도에서 사라집니다. 상자 색이나 이름을 통해 아직 조사하지 않은 품목 수량을 미리 알 수 없도록 데이터를 제한합니다.

## 8. 귀환 경로 계산

귀환 기준점은 `x:100, floor:0`입니다. 실제 귀환 가능 영역은 기존 규칙대로 아래층 `x<=130`이며, 계단 이동이나 회피 중이 아니어야 `exit.reached`가 참입니다.

경로 그래프는 현재 위치, 출구, 발견한 계단의 양쪽 끝을 노드로 사용합니다. 수평 간선은 양 끝 사이 전체 구간이 탐험 기록으로 이어질 때만 연결합니다. 층간 간선은 실제 계단이며 양쪽 끝이 모두 확인된 경우에만 사용할 수 있습니다.

알려진 그래프에서 출구 경로를 찾지 못하면 `knownRoute:false`, `distance:null`을 반환합니다. `route`에는 현재 위치만 남습니다. 보이지 않는 계단이나 방을 추측해 완성된 길처럼 표시하지 않습니다.

경로를 알고 있더라도 첫 닫힌 문이 있으면 표시용 경로는 문 앞 여유 거리 18에서 끝납니다. `blockedDoorId`로 해당 문을 알려주고, UI는 가까이 가서 `E`로 열도록 안내합니다. 길 안내가 잠긴 문을 자동 해제하거나 부품·도구를 사용하지 않습니다.

`distance`는 알려진 전체 경로의 수평 거리와 계단 한 연결당 가중치 125를 더한 값입니다. 닫힌 문이 있어도 계산된 전체 이동 비용을 뜻하며, 화면 경로가 잘린 길이와 같지 않을 수 있습니다. 미터나 귀환까지 남은 초로 표시하면 안 됩니다.

## 9. 렌더링과 정보 경계

미니맵은 탐험한 구간만 바탕선을 그리고, 현재 시야는 더 밝게 표시합니다. 계단 양쪽이 모두 알려져야 전체 층간 연결선을 그리며, 한쪽만 알면 그쪽의 작은 표식만 사용합니다. 귀환 경로도 렌더러에서 탐험 구간으로 한 번 더 잘라 그립니다.

착지점의 소리 파문은 해당 지점이 현재 시야 안에 있을 때만 보입니다. 다른 층으로 이동하거나 문을 닫아 착지점이 가려졌다면 소리 사건이 남아 있어도 파문을 통해 위치를 드러내지 않습니다.

조준선과 유효 거리 표시는 현재 층의 시야 안에 제한합니다. 잘못된 위치는 유효한 초록 표시와 구분하고, 문 너머나 다른 층의 미확인 지형에 목표 표식을 만들지 않습니다. 실제 가능 여부는 렌더러 자체 계산이 아닌 `getDistraction` 결과를 사용합니다.

미니맵은 경로 확인용 표시이며 별도의 지도 이동 명령을 생성하지 않습니다. 지도를 숨겨도 탐험 기록과 이동 규칙은 같습니다. 움직임 줄이기 설정은 표현을 조절하며 청취 거리·NPC 속도·타이머를 바꾸지 않습니다.

## 10. 검증과 재현 사례

검증 코드는 [expedition.test.js](../tests/expedition.test.js)에 있습니다. 기존 야간 규칙을 포함해 77개 테스트가 통과한 상태이며, 이번 기능에 14개 테스트를 추가했습니다. 전체 프로젝트의 최종 검증 결과는 [VALIDATION.md](../VALIDATION.md)를 기준으로 합니다.

주요 검증 항목은 비용 1회 차감, 실패 원자성, 거리·층·문 차단, 행동 중 거부, 은신 유지, 중립 관계 유지, 시야·공격 우선, 실제 조사 이동, 재사용 대기, 눌림 반복 방지, 중간 저장 복원, 잘못된 필드 거부, 조회의 불변성, 미탐험 경로 비공개입니다.

특히 다음 사례는 새 게임부터 실제 공개 API만 사용합니다.

1. 시드 31의 캠페인을 생성하고, 낮 종료·야간 수면·밤 정산·다음 날 API로 5일째에 도달합니다.
2. 레오가 부품 2개를 들고 철도 보급 창고로 출발합니다.
3. 조용한 이동으로 `x:660`에 도착해 하역장 문을 열고, `x:610`으로 돌아와 숨을 곳을 사용합니다.
4. `x:850`에 부품을 던지고 시뮬레이션을 진행합니다. 경비가 실제로 걸어가 착지점을 조사합니다.
5. 발각·피격·살해·절도 없이 왼쪽 출구로 돌아가 17초 안에 정상 귀환합니다.
6. 남은 부품 1개와 유인 1회 결과를 실제 밤 정산에 넘기고 캠페인 저장 검증을 통과합니다.

이 통합 사례는 플레이어·NPC 좌표, 재고, 건강, 시간, 난수 값을 직접 덮어쓰지 않습니다. 개별 규칙의 단위 테스트는 경계 조건을 분리하기 위한 작은 상태 자료를 사용하므로 이 사례와 검증 방법을 구분합니다.

```bash
node --test tests/expedition.test.js
```

이 명세의 테스트 통과는 규칙과 API 연결의 근거입니다. 실제 브라우저의 조준 감각, 휴대전화 터치 오차, 시각적 가독성을 모든 기기에서 검증했다는 뜻은 아닙니다. 브라우저·Canvas·단일 HTML 검증 범위는 최종 검증 문서에 별도로 기록합니다.
