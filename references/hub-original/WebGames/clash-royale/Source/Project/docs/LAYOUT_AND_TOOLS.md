# PC 작업 공간, 모바일 화면, 자유 연습 도구

**기준 버전: 4.4.** 이 문서는 Crownfall의 화면 배치와 입력 방식, 2D·3D 전환, 실시간 대상 검사, 자유 연습 치트의 사용법 및 개발 계약을 설명한다. 전투 규칙과 카드 수치는 [코어 게임플레이 문서](CORE_GAMEPLAY.md), 여섯 단계의 도전과 진척 저장은 [싱글플레이 문서](SINGLE_PLAYER.md)를 참고한다.

화면 방향이나 2D·3D 렌더링 방식을 바꾸어도 같은 전투가 이어진다. 시간, 손패, 엘릭서, 유닛 위치, AI의 판단 기준은 유지되며, 표시와 조작 좌표의 변환만 바뀐다. 별도 브라우저 탭이나 두 번째 게임 인스턴스를 띄우는 방식이 아니다.

## 1. 화면 구성

PC에서는 좌측 설정, 중앙 전투, 우측 상세·통계를 한 작업 공간에 배치한다. 일반 설정은 중앙 게임 화면에서 분리했다. 좁은 화면에서는 전장 바깥의 **☰ 설정** 버튼으로 같은 좌측 패널을 여는 방식으로 대전, 캠페인, 훈련, 덱 편집, 일시정지와 리플레이에 접근한다.

| 영역 | 내용 | 사용 목적 |
|---|---|---|
| 좌측 `설정 · 전역 도구` | 화면 방향, 2D·3D, 일시정지·음향·도움말·기록·사거리, 상대·난이도, 캠페인·대전·연습·훈련·밀집보병 체험, 덱, 전역 치트, 모드별 설명·제어 | 일반 설정과 준비 작업을 전장 밖에서 수행한다. |
| 중앙 게임 화면 | 점수·시간, 엘릭서, 아레나, 다음 카드·손패, 선택 카드의 정보·취소 버튼, 밀집보병 스킬, 시작·일시정지·결과 overlay | 현재 전투의 상태와 즉시 조작에 집중한다. |
| 우측 `디테일 · 통계` | 고정 선택 대상, 체력·전투 상태, 선택 대상 치트, 양 팀 실시간 통계, 카드 참고 정보, 전투 로그 | 현재 전장의 상태와 카드 정의를 구분해 살펴본다. |

좌우 패널은 높이가 부족하면 자체적으로 세로 스크롤된다. 승리 조건, 조작법, 선택 카드의 긴 설명을 전투 HUD에 상시 표시하지 않는다. 조작법과 승리 조건은 외부 도움말에서, 카드 설명은 우측 카드 상세 또는 선택 카드의 정보 버튼으로 여는 상세 창에서 확인한다. 캠페인·훈련 설명과 리플레이 제어도 외부 설정 패널에 둔다.

### 1.1 PC 패널이 보이는 조건

[workspace.css](../dist/workspace.css)는 기존 [styles.css](../dist/styles.css) 뒤에 로드되어 작업 공간의 배치를 정의한다.

- 뷰포트 폭이 **1,100 CSS 픽셀 이상**이고 주 입력 장치가 `pointer: fine`이면 좌우 패널을 표시한다.
- 폭이 **1,099 CSS 픽셀 이하**이거나 `pointer: coarse` 또는 `pointer: none`이면 좌우 상시 패널을 숨긴다. 좌측 설정은 전장 바깥의 버튼으로 여는 drawer에서 계속 사용할 수 있다. 우측 상세·통계 패널은 PC용으로 유지한다.
- 따라서 큰 터치 화면에서도 주 입력 장치를 브라우저가 `coarse`로 판단하면 중앙 전용 배치가 사용된다. 포인팅 장치가 없는 `none` 환경도 중앙 전용이다. 단순히 운영체제 이름이나 기기 모델로 PC와 휴대폰을 나누지 않는다.
- 작은 가로 뷰포트에서는 외부 머리글과 바닥글을 숨기고 게임 화면에 높이를 배분한다. 네 장의 손패는 세로 한 열로 표시한다. 일반 설정은 drawer에서 스크롤하고, 내용이 긴 시작·일시정지·결과 창은 해당 창 안에서 스크롤한다.

가로 게임 화면의 바깥 비율과 아레나의 논리 비율은 다르다. 4.3의 일반 가로 화면은 16:9를 기준으로 하고, 높이가 작은 모바일 가로 화면에서는 가용 높이에 맞춘다. 바깥 화면에는 HUD와 손패가 포함되므로 이 비율을 전투 필드 자체의 비율로 사용하면 안 된다.

### 1.2 작은 화면의 외부 설정 drawer

좌측 설정의 실제 DOM 노드를 native `#workspace-settings-dialog`로 옮긴다. 설정을 복제하지 않으므로 PC 패널과 drawer는 같은 값, 버튼, 이벤트 리스너를 사용한다. PC 조건으로 돌아오면 comment 앵커를 기준으로 원래 좌측 위치에 복원한다.

설정 drawer를 여는 것만으로 게임을 자동 일시정지하지 않는다. drawer 안의 일시정지 버튼으로 직접 멈추거나 계속할 수 있다. 도움말·덱 편집·훈련 선택 등 다른 모달을 열면 설정 drawer를 먼저 닫고 해당 모달의 기존 일시정지·재개 규칙을 적용한다. native modal이 열린 동안 배경 전장은 직접 조작할 수 없으며, 전역 게임 단축키도 처리하지 않는다. 탭이 숨겨질 때의 일시정지 처리는 그대로 유지한다.

## 2. 세로·가로 화면 전환

PC에서는 좌측 `게임 화면 방향`의 **세로 / 가로** 버튼을 누른다. 작은 화면에서는 전장 바깥의 **☰ 설정**을 열어 같은 버튼을 사용한다. 중앙 전투 화면에 방향 전환 버튼을 중복해서 두지 않는다.

| 구분 | 세로 화면 | 가로 화면 |
|---|---|---|
| 아군 진영 | 아래쪽 | 오른쪽 |
| 상대 진영 | 위쪽 | 왼쪽 |
| 손패 | 아레나 아래 | 아레나 오른쪽의 별도 영역 |
| 손패 4장 | 가로 한 줄 | 세로 한 열, 네 행 |
| 엘릭서 | 손패 아래 가로 바 | 왼쪽 세로 바, 아래에서 위로 충전 |
| 시간·점수 | 아레나 위 | 왼쪽 HUD |
| 다음 카드 | 손패 옆 | 오른쪽 손패 위 |
| 일반 설정·모드 제어 | 전장 바깥 좌측 패널 또는 설정 drawer | 전장 바깥 좌측 패널 또는 설정 drawer |
| 선택 카드 정보·취소 | 손패 부근 | 선택 중에만 보이는 작은 맥락 버튼 |
| 밀집보병 고유 스킬 | 전장 내부 하단 오른쪽 | 전장 내부 하단 오른쪽 |
| 렌더링에 사용하는 필드 범위 | 폭 480 × 높이 640 | 폭 640 × 높이 480 |
| 엔진의 실제 좌표 범위 | 폭 480 × 높이 640 | 폭 480 × 높이 640 |

방향을 바꾸면 선택 중인 카드와 드래그가 취소된다. 전환 직전의 화면 좌표로 의도하지 않은 배치가 발생하지 않도록 하기 위한 동작이다. 진행 중인 전투를 새로 시작하거나 시뮬레이션 시간을 되돌리지는 않는다.

방향은 이 브라우저의 프로필 설정에 저장된다. 기기를 물리적으로 회전하는 것과 게임 안에서 방향을 선택하는 것은 별개다. CSS는 실제 뷰포트에 맞춰 공간을 조정하고, 전장 투영은 사용자가 선택한 방향을 따른다.

### 2.1 같은 월드 좌표를 다른 방향으로 보여준다

2D 렌더러에서 원본 전투 좌표를 `(x, y)`, 가로 화면의 논리 투영 좌표를 `(px, py)`라고 하면 다음 관계를 사용한다. 3D는 같은 진영 방향을 유지하면서 카메라 투영을 추가한다.

```text
세로: (px, py) = (x, y)
가로: (px, py) = (y, 480 - x)

가로 역변환: (x, y) = (480 - py, px)
```

예를 들어 아군 킹 타워의 월드 위치 `(240, 575)`는 가로 화면의 `(575, 240)`에, 상대 킹 타워 `(240, 65)`는 `(65, 240)`에 표시된다. 상대가 왼쪽, 아군이 오른쪽이라는 배치와 일치한다. 엔진에 저장된 두 타워의 좌표는 바뀌지 않는다.

2D의 강과 다리 등 지형은 새 방향으로 투영한다. 유닛·타워의 그림, 체력 표시, 숫자와 문구는 투영된 위치에서 기존 그림 자세와 읽는 방향을 유지한다. 3D는 월드에 놓인 모델을 카메라로 투영하고 문구는 별도 HUD에 똑바로 그린다. 캔버스 전체에 CSS 회전을 적용해 문자와 손패까지 옆으로 눕히는 방식은 사용하지 않는다.

### 2.2 가로 화면의 정보와 조작 분리

가로 게임 화면은 왼쪽 최소 HUD, 가운데 전장, 오른쪽 다음 카드·손패의 세 열이다. PC의 바깥 좌우 도구 패널과는 별개의 배치다.

| 왼쪽 HUD | 오른쪽 손패 영역 |
|---|---|
| 시간·국면, 양 팀 점수·크라운 | 맨 위의 NEXT 카드 |
| 세로 엘릭서·현재 수치·생성 배율 | 네 장의 손패를 세로 한 열로 표시 |
| 긴 설명이나 일반 설정 없음 | 카드 선택 중에만 정보·취소 버튼 표시 |

오른쪽 손패는 `repeat(4,minmax(44px,1fr))`의 네 행이며 NEXT 아래의 공간을 사용한다. 일반 설정을 나열하던 별도 보조 버튼 열은 사용하지 않는다. 선택 카드의 정보·취소 버튼은 선택한 카드가 있을 때만 나타나고, 선택을 취소하면 컨테이너까지 숨긴다. 시작·일시정지·결과 패널은 전장의 오른쪽에 정렬하고 내용이 길면 패널 안에서 스크롤한다.

점수판, 자원, NEXT, 손패와 맥락 버튼은 같은 DOM 노드를 옮기고 세로 복원을 위한 comment 앵커를 남긴다. 노드를 복제하지 않으므로 ID와 이벤트 리스너를 유지한다. 훈련 설명·힌트와 리플레이 제어는 이 전장 내부 이동 대상에서 제외하고 외부 설정 패널에 둔다. 전환할 때 게임 안의 포커스를 복원하고 진행 중 카드 드래그는 취소한다.

엘릭서는 `--elixir-level`에 0~100%를 전달한다. 세로 게임 화면에서는 기존 가로 폭, 가로 게임 화면에서는 바닥에 고정한 세로 높이에 같은 값을 적용한다. 눈금과 접근성 방향도 함께 전환하며 `aria-valuenow`는 실제 자원을 표시한다.

### 2.3 2D·3D 전환

외부 설정의 **2D 탑뷰 / 3D 입체**에서 렌더링 방식을 선택한다. 화면 방향과 독립적인 설정이므로 세로·가로 각각에서 두 방식을 사용할 수 있다. 전환하면 진행 중인 카드 선택·드래그를 취소하지만 전투는 새로 만들지 않는다.

3D는 별도 WebGL 캔버스에 높이가 있는 지형·타워·병력 모델을 그리고, 공통 입력 캔버스에는 투명한 2D HUD를 얹는다. 직교 카메라, 깊이 검사, 모델 normal을 사용하며 높이와 지면 위치가 함께 투영된다. 2D 전장 이미지를 기울여 붙인 화면은 아니다. 두 방식 모두 엔진의 480×640 월드와 `previewDeployment()`의 실제 배치 계획을 사용한다.

WebGL 초기화·shader/link 실패, 그리기 오류, context loss가 발생하면 같은 게임 인스턴스를 유지한 채 2D로 전환하고 안내한다. 실제 브라우저와 GPU에서의 표시·성능 검증 범위는 10절에 구분한다.

## 3. 카드 배치와 대상 선택

카드 배치와 전장 대상 선택은 서로 다른 동작이다. 일반 클릭의 의미는 현재 카드 선택 상태에 따라 달라진다.

| 조작 상태 | 아레나를 누르면 |
|---|---|
| 카드가 선택되어 있음 | 해당 월드 위치에 카드 배치를 시도한다. |
| 카드가 선택되어 있지 않음 | 살아 있는 유닛이나 타워를 찾아 선택한다. |
| `대상 선택 도구`가 켜져 있음 | 카드 배치 대신 전장의 대상을 선택한다. |
| `Shift`를 누른 채 클릭 | 카드 배치 대신 대상 검사를 수행한다. |

우측의 `대상 선택 도구`를 켜면 선택 중인 카드가 취소된다. 다시 카드를 선택하면 배치 조작으로 돌아간다. 대상 선택을 해제하는 버튼은 카드 취소 버튼과 구분되어 있다.

### 3.1 카드 입력

카드는 누른 뒤 필드에 배치하거나, 손패에서 필드로 끌어 놓을 수 있다. 터치 드래그는 손가락에 가려지지 않도록 조준점을 화면 위쪽으로 보정한다. 이 보정은 월드 좌표를 직접 움직이는 것이 아니라 화면 좌표에서 처리한다.

배치 가능 여부는 실제 `Game.canDeploy()` 및 `Game.playCard()` 규칙을 따른다. 가로 화면에서도 아군 진영, 전진 배치 구역, 엘릭서 비용, 카드 순환 규칙이 동일하다. 주문의 사용 범위와 병력·건물의 배치 범위도 화면 방향 때문에 달라지지 않는다.

드래그가 아레나 밖에서 끝나거나 합법적인 배치 지점이 아니면 정상 배치가 성립하지 않는다. 화면에 보이는 여백을 전투 좌표의 일부로 늘려 계산하지 않는다.

### 3.2 PC 키보드

| 키 | 동작 |
|---|---|
| `1`–`4` | 해당 손패 슬롯의 카드를 선택한다. |
| 방향키 | 선택한 카드의 조준점을 화면 방향에 맞게 움직인다. |
| `Shift` + 방향키 | 더 작은 간격으로 조준점을 움직인다. |
| `Enter` | 조준점에 카드 배치를 시도한다. |
| `Escape` | 카드 선택을 취소하고 대상 선택 도구를 끈다. 고정 선택 대상의 해제는 별도 버튼으로 한다. |
| `P` / `Space` | 전투 또는 리플레이의 일시정지·계속 조작을 수행한다. `Space`는 버튼·링크의 기본 조작을 우선한다. |
| `E` | 현재 선택한 아군 밀집보병 분대의 고유 스킬을 시도한다. 키를 누르고 있어도 반복 발동하지 않는다. |
| `Shift` + 클릭 | 배치 대신 전장 대상을 선택한다. |

숫자 입력창, 선택 상자, 텍스트 입력 영역에 포커스가 있을 때는 게임의 전역 단축키를 처리하지 않는다. `contenteditable` 요소와 `Ctrl`·`Meta`·`Alt` 조합도 게임 단축키보다 해당 입력 작업을 우선한다. 예를 들어 피해량 입력창에서 `1`을 입력하거나 화살표로 수치를 바꾸는 동작이 카드를 고르거나 조준점을 움직여서는 안 된다.

방향키는 현재 렌더러의 `worldToScreen()`으로 조준점을 화면에 옮기고, 화면상의 이동량을 더한 뒤 `screenToWorld()`로 되돌린다. 따라서 3D의 지면 압축과 현재 화면 배율에도 화면 방향이 유지된다. 가로 화면에서 `오른쪽`은 월드 Y 증가, `왼쪽`은 월드 Y 감소, `위쪽`은 월드 X 증가, `아래쪽`은 월드 X 감소에 해당한다. 레인 A는 가로 화면 아래쪽, 레인 B는 위쪽이다. 엔진에는 마지막에 얻은 원래 월드 좌표를 전달한다.

### 3.3 밀집보병 분대 스킬

아군 밀집보병 분대가 있으면 `arena-wrap` 내부 하단 오른쪽에 **방패 돌격** 패널이 나타난다. 이 패널은 실제 전투 조작이므로 외부 설정이 아니라 전장 안에 둔다. 시작·일시정지·결과 overlay보다 아래에 있어 덮개를 통과해 스킬을 누르지 못한다.

한 분대만 있으면 해당 분대를 사용하고, 여러 분대가 있으면 선택 상자로 발동 대상을 고른다. 아레나에서 아군 밀집보병을 선택해도 그 병사가 속한 분대로 바뀐다. 선택 상자를 직접 바꿀 때는 기존 개체 선택을 비워 자동 선택과 충돌하지 않게 한다. 개체 선택 직후와 스킬 발동 직전에 현재 분대를 다시 확인하므로 HUD 갱신 주기 사이에 이전 분대에 발동하는 일을 막는다.

버튼 또는 `E`로 스킬을 시도한다. UI는 `getAbilities('player')`가 제공하는 준비 여부, 비용, 생존 인원, 남은 돌격·대기 시간과 실패 사유를 표시한다. 실제 사용은 `activateAbility()`에서 다시 판정하며, 일시정지·종료·훈련·리플레이에서는 사용하지 않는다. 리플레이에 분대가 있으면 상태만 확인할 수 있다. 패널과 선택 상자는 분대가 사라지거나 모드가 바뀌면 갱신된다.

밀집보병의 방진 표식은 `formationProtected`가 실제로 참인 병사만 반영한다. 돌격 시간은 `chargeRemaining`을 사용하고, 재집결과 배치 대기를 구분한다. 2D에서는 분대 표식 하나를 사용해 여섯 개의 문구가 겹치지 않도록 한다. 그림을 바꾸는 것만으로 보호 효과나 돌격을 부여하지 않는다.

## 4. 선택 대상의 상세 정보

우측 상세 패널은 카드 종류의 기본 정보를 보여주는 `선택 카드 상세`와, 전장에 실제로 존재하는 개체의 상태를 보여주는 `선택 대상`을 구분한다. 같은 종류의 병력이 여러 개 있어도 각 개체는 별도 ID를 가진다.

고정 선택은 마우스를 대상 위에 올려 놓는 호버와 독립적이다. 마우스를 우측 패널로 옮겨도 선택한 대상이 유지되므로, 수치가 변하는 것을 보거나 해당 대상에 도구를 적용할 수 있다.

2D에서는 월드 위치와 개체 반경으로 선택 대상을 찾는다. 3D에서는 지면 배치와 개체 선택을 구분한다. 카드 배치는 카메라 ray와 지면의 교점을 사용하고, 개체 선택은 실제 모델 삼각형을 화면으로 투영해 클릭 점이 들어가는지 검사한다. 여러 모델이 겹치면 보간한 카메라 깊이로 가장 앞의 살아 있는 개체를 고른다. 따라서 타워나 병사의 머리·몸통, 공중 병력을 누를 때 지면 중심만 맞춰야 하는 것은 아니다. 캔버스 바깥·레터박스·빈 공간·죽거나 파괴된 개체는 선택하지 않는다.

선택 대상에서 확인할 수 있는 항목은 다음과 같다.

- 개체 ID, 카드·타워 이름, 아군·상대 구분, 지상·공중 병력·건물·타워 구분
- 현재 체력과 최대 체력, 체력 막대
- 한 번의 공격 피해, 공격 간격, 사거리, 이동 속도
- 현재 공격 대기와 배치 대기 시간
- 엔진 기준 월드 X·Y
- 기절, 동결, 감속의 남은 상태, 건물 수명, 현재 공격 대상 ID
- 아직 활성화되지 않은 킹 타워의 대기 상태

공격 간격은 초 단위이며 초당 공격 횟수와 다르다. 이동 속도와 사거리는 엔진 월드 단위를 기준으로 한다. 화면을 확대하거나 가로로 바꿔도 같은 개체의 월드 좌표와 속도 값은 유지된다.

### 4.1 선택 수명의 처리

앱은 개체 객체를 오래 보관해 직접 수정하지 않는다. `selectedEntityId`와 선택 시점의 `Game` 인스턴스를 보관하고, 갱신할 때 현재 게임의 살아 있는 개체를 다시 찾는다.

대상이 죽거나 제거되면 상세 정보가 사라지고 다시 선택하라는 안내가 표시된다. 새 대전, 저장 복원, 리플레이 시작·처음부터 재생·탐색 등으로 `Game` 인스턴스가 바뀌면 이전 선택을 해제한다. 재생 전의 오래된 객체나 같은 ID를 가진 다른 게임의 개체에 도구를 잘못 적용하지 않기 위한 처리다.

## 5. 전역 치트: 자유 연습의 조건 조절

좌측 **치트 연습 시작** 버튼은 자유 연습을 연다. 자유 연습에서는 AI 배치 없이 시작하고, 필요할 때 AI를 켤 수 있다. 전역 치트와 대상 치트는 일반 대전, 캠페인, 전술 훈련, 리플레이에서 비활성화된다.

| PC 도구 | 실제 동작 |
|---|---|
| AI ON / OFF | 자유 연습에서 상대 AI가 카드를 내도록 켜거나 끈다. 이미 전장에 있는 유닛의 전투를 멈추는 버튼은 아니다. |
| 연습 속도 | 1×·2×·4× 중에서 선택한다. 시뮬레이션 진행량을 조절하지만 각 엔진 스텝은 고정 1/60초로 처리된다. |
| 내 엘릭서 10 | 아군 엘릭서를 상한 10으로 설정한다. |
| 양쪽 엘릭서 10 | 아군과 상대의 엘릭서를 각각 10으로 설정한다. |
| 모든 타워 회복 | 양 팀의 살아 있는 타워를 각 최대 체력까지 회복한다. 파괴된 타워를 부활시키지 않는다. |
| 적 병력 제거 | 상대의 살아 있는 병력과 소환 건물에 남은 체력만큼 피해를 준다. 타워를 제거하는 버튼은 아니다. |

작은 화면에서도 **☰ 설정** drawer에서 같은 전역 치트를 사용한다. AI ON/OFF, 속도 선택 상자와 자원·타워·병력 도구는 PC와 동일한 DOM 및 검증 경로를 사용한다. 중앙 전투 화면에 있던 별도의 연습 제어와 핸들러는 제거했다. 개체별 편집 패널은 우측 PC 작업 공간에 유지한다. 모바일에서도 카드를 선택하지 않은 상태로 개체를 누르면 이름과 체력을 간단한 안내로 확인할 수 있다.

치트 실행 자체는 전투 시간이나 틱을 전진시키지 않는다. 일시정지 상태에서도 적용할 수 있으며, 단순 회복·충전·준비 작업은 일시정지를 해제하지 않는다. 피해 적용으로 킹 타워가 파괴되는 등 정상 종료 조건이 성립하면 전투가 끝날 수 있다.

일시정지 후 대상 선택 도구를 켜면 일시정지 덮개만 숨겨 전장 클릭을 허용한다. 엔진은 계속 멈춘 상태다. 도구를 끄면 기존 일시정지 덮개가 다시 표시되며, 실제 재개는 게임의 계속하기 버튼이나 단축키로 수행한다.

## 6. 선택 대상 치트

자유 연습에서 살아 있는 대상을 선택하면 우측 대상 도구가 활성화된다. 대상이 없어졌거나 전투가 끝나면 도구를 다시 사용할 수 없다.

| 도구 | 실제 동작과 제한 |
|---|---|
| 체력 회복 | 선택 대상의 HP를 최대 HP로 바꾼다. 다른 상태나 건물의 남은 수명을 초기화하지 않는다. |
| 즉시 준비 | 유닛의 배치 대기를 끝내고, 공격 대기와 기절·동결·감속을 해제한다. 잠든 킹 타워를 활성화하는 기능은 아니다. |
| 3초 기절 | 대상에게 3초의 기절 효과를 적용한다. 피해를 함께 주는 기능은 아니다. |
| 대상 제거 | 대상의 현재 체력만큼 피해를 적용한다. 타워도 선택할 수 있으므로 크라운과 승패에 영향을 줄 수 있다. |
| 피해 적용 | 입력한 수치만큼 피해를 시도한다. 허용 범위는 0 초과 100,000 이하의 유한한 수다. |

UI의 피해량 입력창은 기본값 200을 사용한다. 최대 체력을 넘는 피해를 입력해도 실제 피해 통계에는 제거한 HP만 반영된다. 예를 들어 HP가 80 남은 상대 병력에 200을 적용하면 아군의 누적 피해는 80 증가한다.

피해와 제거는 엔진의 일반적인 피해·파괴 처리로 연결된다. 타워 파괴, 크라운, 킹 타워 활성화, 승패 계산을 우회해 화면의 숫자만 바꾸지 않는다. 따라서 아군 대상을 제거하면 상대에게 해당 피해가 집계된다. 회복, 엘릭서 충전, 즉시 준비, 기절만 적용한 경우에는 인위적인 피해량을 추가하지 않는다.

### 6.1 권장 확인 흐름

1. 좌측에서 치트 연습을 시작한다.
2. 카드를 실제 비용을 지불해 배치하고, 카드 선택을 취소하거나 `대상 선택 도구`를 켠다.
3. 해당 개체를 선택해 체력, 공격 대기와 위치를 확인한다.
4. 필요하면 전투를 일시정지한 뒤 피해·회복·기절을 적용한다.
5. 다시 진행해 정상 공격과 이동에 어떤 영향을 주는지 관찰한다.

이 도구는 카드의 원본 능력치나 AI의 판단 코드를 편집하는 기능은 아니다. 특정 전투 인스턴스의 현재 상태를 바꿔 배치와 전투 반응을 살펴본다.

## 7. 실시간 통계의 의미

우측 표는 양 팀을 나란히 보여준다. 대상 상세와 통계는 HUD 갱신 주기에 맞춰 표시되며, 엔진의 모든 스텝마다 DOM을 다시 만드는 방식은 아니다.

| 표시 | 집계 기준 |
|---|---|
| TICK | 현재 게임의 고정 시뮬레이션 스텝 수 |
| 엘릭서 | 각 팀의 현재 엘릭서, 소수 첫째 자리 |
| 병력 수 | 살아 있고 제거되지 않은 유닛 중 소환 건물을 제외한 수 |
| 건물 수 | 살아 있는 소환 건물 수. 킹·프린세스 타워 수와 구분한다. |
| 사용 카드 | 해당 팀이 정상 카드 배치로 사용한 카드 수 |
| 엘릭서 소비 | 정상 카드 배치와 분대 고유 스킬에 실제로 소비한 엘릭서 합 |
| 누적 피해 | 해당 팀에 집계된 실제 HP 감소량 |
| 크라운 | 엔진이 계산한 현재 크라운 |

검사 패널은 사용자에게 상대의 엘릭서를 포함한 양 팀 상태를 보여준다. 이것은 AI의 정보 접근 규칙과 별개다. AI가 플레이어의 손패나 엘릭서를 읽어 판단하는 기능이 추가된 것은 아니다.

치트로 엘릭서를 충전해도 `사용 카드`와 `엘릭서 소비`가 증가하지 않는다. 반대로 피해·제거 치트는 실제 피해 처리에 연결되므로 연습 중 누적 피해에는 포함될 수 있다. 일반 대전의 성과와 비교할 때는 현재 모드가 자유 연습인지 함께 확인해야 한다.

## 8. 저장, 복원과 일반 기록의 구분

화면 방향과 렌더링 방식은 기존 프로필 저장 키 `crownfall.v1`의 `orientation`, `renderMode` 필드에 저장된다. 4.3에서는 저장된 값이 명시적인 `portrait`이면 세로를, 그 외에는 가로를 기본으로 사용한다. 렌더링은 명시적인 `3d`를 복원하며 그 외에는 `2d`를 사용한다. 3D를 복원할 수 없으면 2D fallback을 적용한다. 표시 설정은 캠페인 진척이나 전투 리플레이의 명령 기록을 바꾸지 않는다.

자유 연습을 저장하면 기존 전투 체크포인트에 현재 엔진 상태와 AI 상태, 연습 여부, 연습 AI 사용 여부와 속도가 포함된다. 도구로 바꾼 현재 체력이나 상태도 엔진 스냅샷에 들어가므로, 허용되는 스냅샷을 복원하면 그 상태에서 계속할 수 있다.

선택한 대상, 호버, 카드 조준과 드래그는 일시적인 UI 상태다. 프로필이나 전투 저장에서 해당 개체를 자동으로 다시 선택하는 기능은 제공하지 않는다.

치트 명령은 정상 카드 배치 리플레이의 명령 목록에 추가하지 않는다. 그러므로 치트가 사용된 자유 연습을 정상 대전 리플레이처럼 재생 가능한 기록으로 취급하지 않는다. 앱은 자유 연습을 일반 승수·전수, 캠페인 완료·메달, 일반 전투 기록과 리플레이 저장 대상에서 제외한다.

전술 훈련도 엔진의 연습 성격을 이용하지만, 자유 연습 치트를 허용하는 모드는 아니다. UI와 도구 API가 훈련·리플레이 여부를 추가로 검사하는 이유다. 훈련 과제와 일반 경기 기록의 자세한 구분은 [싱글플레이 문서](SINGLE_PLAYER.md)에 정리되어 있다.

### 9.1 렌더러 좌표 계약

```js
import { ArenaView } from './view.js';

const renderer = new ArenaView(inputCanvas, webglCanvas, {
  onFallback: message => showMessage(message),
});
renderer.setMode('2d'); // 또는 '3d'; 실제 선택된 '2d'/'3d' 반환
renderer.setOrientation('portrait'); // 또는 'landscape'

// 브라우저 client 좌표 → 엔진 월드 좌표
const world = renderer.screenToWorld(clientX, clientY);

// 엔진 월드 좌표 → 캔버스 안의 로컬 CSS 좌표
const local = renderer.worldToScreen(worldX, worldY);

renderer.draw(game, {
  selectedCard,
  pointer,
  hoveredEntityId,
  selectedEntityId,
  showRanges,
  reducedMotion,
  arenaTheme,
  trainingTarget,
});
```

`worldToScreen()`의 반환값은 페이지의 `clientX/clientY`가 아니다. 페이지 좌표가 필요하면 현재 캔버스 경계의 `left/top`을 더한다. 반대로 `screenToWorld()`는 이미 페이지 내 client 좌표를 받으므로 미리 경계를 빼서 전달하면 이중 보정이 발생한다.

두 변환은 실제 캔버스의 현재 경계와 레터박스 여백을 사용한다. 창 크기나 주변 패널 배치가 바뀐 직후에도 포인터와 화면이 같은 투영을 사용해야 한다. 포인터와 키보드에서 얻은 최종 좌표는 모두 원래 480×640 월드 좌표로 엔진에 전달한다.

3D의 `worldToScreen(x, y)`는 개체의 머리가 아니라 해당 월드 위치의 **지면 높이 0**을 투영한다. `screenToWorld()`도 지면의 교점을 반환하며 바깥 입력을 전장 안으로 강제 보정하지 않는다. 높은 모델의 선택에는 별도 API를 사용한다.

```js
const entity = renderer.pickEntity(clientX, clientY, entities);
// 3D: 앞에 보이는 살아 있는 원본 entity 참조 또는 null
// 2D facade: null. 앱의 기존 월드 반경 선택 경로를 사용한다.
```

모델 picking의 반환값은 그리기와 조회를 위한 참조이며 이 경로에서 개체를 수정하지 않는다. 분리된 복사본이 필요한 검사·편집 UI는 아래 `inspectTarget()` 계약을 사용한다. 직접 `ArenaRenderer3D`를 만들 때는 입력/HUD 캔버스와 별도의 WebGL 캔버스를 전달한다. HUD의 최초 2D 컨텍스트 요청은 `alpha:true`여야 한다. `ArenaView`가 이 최초 요청과 GL 캔버스 숨김을 관리한다.

`ArenaRenderer`와 `ArenaRenderer3D`는 같은 `draw()` 옵션을 사용한다. `selectedEntityId`는 고정 선택, `hoveredEntityId`는 호버이며 서로 독립적이다. `pointer`와 `trainingTarget`은 항상 월드 좌표다. 두 renderer는 애니메이션 루프나 시뮬레이션을 소유하지 않으며 그리기·방향 전환으로 `Game` 상태를 변경하지 않는다.

### 9.2 읽기 전용 대상 조회

```js
import { inspectTarget } from './debug.js';

const info = inspectTarget(game, entityId);
// { entity: 복사된 현재 개체, card: 복사된 카드 정의 또는 null }
// 대상을 찾을 수 없거나 살아 있지 않으면 null
```

이 함수는 실제 `Game` 인스턴스를 검사하고, 내부 상태와 분리된 JSON 복사본을 반환한다. 반환된 `entity.hp`를 수정해도 게임의 HP는 바뀌지 않는다. 일반 대전, 훈련, 리플레이에서도 조회할 수 있다. 대상 범위는 살아 있는 타워와 유닛이며 주문 효과 영역이나 투사체를 개체 편집 대상으로 반환하지 않는다.

### 9.3 자유 연습 상태 변경

```js
import { applyCheat } from './debug.js';

const result = applyCheat(
  game,
  { type: 'damage-target', id: entityId, amount: 200 },
  { training: false, replay: false },
);

// 성공: { ok: true, affectedIds?, affectedTeams?, actualDamage? }
// 실패: { ok: false, reason: 사용자에게 표시 가능한 설명 }
```

모든 요청은 실제 `Game` 인스턴스, `game.practice === true`, 미종료 상태를 요구한다. `options.training` 또는 `options.replay`가 참이면 거절한다. 앱은 여기에 플레이 시작 여부와 현재 UI 모드도 확인한다. 일시정지는 변경 요청을 거절하는 조건이 아니다.

| `action.type` | 입력 |
|---|---|
| `fill-elixir` | `team: 'player' \| 'enemy' \| 'both'` |
| `heal-towers` | 같은 `team` 값 |
| `clear-units` | 같은 `team` 값 |
| `heal-target` | 살아 있는 개체의 `id` |
| `ready-target` | 살아 있는 개체의 `id` |
| `remove-target` | 살아 있는 개체의 `id` |
| `damage-target` | `id`, 유한한 `amount`, `0 < amount <= 100000` |
| `stun-target` | `id`, 선택적인 유한한 `duration`, `0 < duration <= 10`; 생략하면 3초 |

전역 API는 아군·상대·양쪽을 지정할 수 있지만, UI는 자주 사용하는 조합을 버튼으로 제공한다. UI에 없는 임의 입력을 지원한다고 해서 모든 파라미터를 화면에 편집기로 노출하는 것은 아니다.

### 9.4 분대 스킬 연결

```js
const abilities = game.getAbilities('player');
const selected = abilities.find(ability => ability.groupId === selectedGroupId);
const result = game.activateAbility('player', selectedGroupId);
// 엔진이 준비 여부·비용·분대 상태를 다시 검사하고 { ok, reason? } 반환
```

UI는 `groupId`와 현재 살아 있는 `memberIds`로 대상을 다시 확인한다. 카드 슬롯 번호나 과거의 유닛 객체를 스킬 대상으로 보관하지 않는다. 이 API는 정상 전투 스킬이고 자유 연습의 `applyCheat()`와 구분한다. 리플레이에서는 기록된 명령을 재생하며 사용자의 새 스킬 입력은 차단한다.

별도로 실행한 4.3 전체 회귀는 **159/159개 통과**했으며 JavaScript 문법과 DOM 구조 검사도 통과했다. 이 전체 결과에는 위 표 외의 전투·AI·저장·리플레이 등 다른 모듈 검사가 포함된다.

3D 테스트는 [WebGL recorder fixture](../tests/fixtures/webgl-recorder.mjs)를 사용한다. 업로드한 카메라 행렬과 실제 viewport를 별도로 계산해 좌표 변환과 비교하고, 높이·normal·색을 가진 유한한 메시, 깊이 검사와 삼각형 그리기 호출을 확인한다. 실제 모델의 머리·몸통·공중 유닛을 누르는 경우, 빈 공간·죽은 개체·바깥 입력의 제외, 겹친 모델의 깊이 우선 선택도 검사한다. shader/link 실패와 context loss·복원·자원 해제는 모의 GL의 응답을 통해 검증한다.

2D·3D 모두 엔진의 실제 배치 미리보기를 사용하며 그리기와 전환이 스냅샷, RNG와 명령 기록을 바꾸지 않는지 확인한다. facade 검사는 2D 컨텍스트의 첫 요청이 `alpha:true`인지, 2D 모드에서 GL 캔버스를 숨기는지, GL 초기화·실행 실패 후 같은 전투가 2D로 이어지는지 구분한다. recorder는 GPU 드라이버에서 shader를 실행하는 장치가 아니다.

4.3의 실제 HTML을 파싱한 구조 모델에서는 **이동 대상 7개 노드를 8회 가로·세로 왕복**해 부모·형제 순서 복원을 확인했다. 여기서 일곱 노드는 점수판, 엘릭서 배율, 엘릭서 바, NEXT, 손패, 카드 정보 버튼, 취소 버튼이다. 이 결과는 DOM 이동·복원의 검사이며 브라우저의 실제 크기 계산이나 터치 조작을 검증한 결과는 아니다.

### 10.2 독립 Canvas 출력과 미검증 범위

Native Canvas로 세 아레나 테마의 세로·가로 장면과 주문 표시를 생성해 확인했고, 4.3에서는 밀집보병 SVG 및 방진·돌격·재집결·배치 대기 표현도 확인했다. 이 출력은 렌더러를 별도로 호출해 만든 이미지이며 실제 웹페이지의 브라우저 스크린샷이 아니다.

**실제 브라우저와 GPU에서의 최종 시각·터치·성능 검증은 수행하지 않았다.** 현재 결과로 native dialog의 실제 포커스 흐름, 모바일 주소창 높이 변화, 운영체제 회전, 확대, 키보드 입력기, 여러 손가락 입력이나 기기별 WebGL 표시 품질을 보장하지 않는다. 실제 기기의 초당 프레임 수와 입력 지연도 측정하지 않았다. 코드 검토, Node 검사와 독립 Canvas 출력의 범위 안에서 결과를 해석해야 한다.

후속 브라우저 검증에서는 다음 사용자 경로를 우선 확인한다.

1. 카드 선택·드래그 중 방향 또는 2D·3D를 바꿀 때 선택이 취소되고, 같은 전투가 의도하지 않은 배치 없이 이어지는지 확인한다. 양 방향·두 렌더러의 지면 배치와 3D의 높은 타워·병력 선택도 함께 확인한다.
2. 작은 화면의 외부 설정 drawer에서 모드·덱·훈련·리플레이·치트에 접근할 수 있는지 확인한다. 설정 열기만으로는 시간이 멈추지 않고, 명시적 일시정지·다른 모달 열기·닫기·PC 패널 복귀가 각각 의도대로 작동해야 한다.
3. 가로 화면에서 NEXT가 오른쪽 손패 위에 있고 네 장의 카드가 한 열로 보이는지, 왼쪽에는 시간·점수·세로 엘릭서만 남는지 확인한다. 선택 정보·취소는 카드 선택 중에만 나타나고, 긴 설명은 외부 도움말·상세 창에서 확인할 수 있어야 한다.
4. 여러 밀집보병 분대 중 개체 또는 선택 상자로 대상을 바꾼 직후 버튼·`E`를 누르면 현재 분대가 사용되는지 확인한다. 일시정지·결과 overlay가 스킬보다 위에 있고, 입력창·설정 drawer의 키보드 조작과 게임 단축키가 간섭하지 않아야 한다.
5. 대상 선택 후 우측 패널로 포인터를 옮겨도 선택이 유지되고, 대상 사망·재시작·리플레이 탐색 뒤에는 오래된 선택이 남지 않는지 확인한다.
6. 치트 연습에서 승리해도 일반 전적, 캠페인 메달과 일반 리플레이 기록이 늘지 않는지 확인한다.

전투 계산은 고정 시간 간격을 유지하며, 화면 방향과 렌더링 방식은 AI 난이도나 카드 수치를 보정하지 않는다. 화면 배치의 검증과 전투 규칙의 검증을 각각 유지하는 것이 이 작업 공간의 개발 기준이다.

## 4.4 추가: 외부 개발자 테스트

좌측 외부 패널의 개발자 테스트에서 두 팀의 실제 손패를 함께 표시합니다. 진영 버튼·`T`·특정 진영 손패 선택은 인게임 손패·다음 카드·엘릭서·조준·분대 스킬을 같은 조작 진영으로 전환합니다. 전장 진영 위치는 계속 적 왼쪽·아군 오른쪽입니다. 대상 병사를 선택하면 개발자 모드에서만 그 소속 진영으로 제어를 바꿉니다. 일반 게임은 계속 아군만 제어합니다.

카드 수치 편집은 외부 패널에서 즉시 적용하며, 실제 적용 진영과 편집 진영은 별도로 선택할 수 있습니다. 적군 조작일 때는 카드 선택·조준·스킬과 상태 라벨에 적군 색과 이름을 표시합니다. 좁은 화면에서 손패나 전체 카드 배치를 고르면 외부 서랍을 닫고 전장 조준으로 돌아갑니다. 직접 배치 도구는 반복 클릭을 지원하고 `Esc`로 취소합니다.

밸런스·치트와 초기화·저장의 전체 동작은 [DEVELOPER_MODE.md](DEVELOPER_MODE.md)를 참고하세요. 4.3의 검증 이력은 당시 결과이며 4.4의 최종 검사 수는 [RELEASE_NOTES.md](RELEASE_NOTES.md)에 기록합니다.
