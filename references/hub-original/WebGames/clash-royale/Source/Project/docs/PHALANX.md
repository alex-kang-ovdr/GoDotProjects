# 밀집보병과 방패 돌격

밀집보병은 여섯 병사가 실제 위치를 맞추며 이동하는 분대 카드다. **현재 기본 규칙 4에서는 방어 대형의 피해 감소가 70%이며, 돌격 중에만 공격한다.** 방어 대형에서는 공격을 멈추고 천천히 전진한다. 분대의 고유 능력인 **방패 돌격**을 사용하면 엘릭서 1을 지불하고 5초 동안 대형과 피해 감소를 해제해 빠르게 이동하며 공격한다. 시간이 끝나면 공격을 멈추고 살아 있는 병사들이 다시 모인다.

이전 규칙 3으로 저장한 경기와 리플레이는 35% 피해 감소와 대형 중 공격을 포함한 기존 동작을 유지한다. 아래의 기본 수치와 플레이 설명은 규칙 4를 기준으로 하며, 구버전 호환은 별도 항목에서 설명한다.

이 문서는 Crownfall Arena의 구현 계약을 설명한다. 수치, 카드, 분대 능력은 이 프로젝트의 독자적인 규칙이며 상용 게임의 공식 카드나 밸런스를 재현한 값이 아니다.

관련 구현은 [전투 엔진](../dist/js/engine.js), [밸런스 스키마](../dist/js/balance.js), [상대 AI](../dist/js/ai.js), [저장·리플레이](../dist/js/session.js), [분대 회귀 검사](../tests/phalanx.test.mjs)에 있다. 전체 전투 규칙은 [코어 게임플레이](CORE_GAMEPLAY.md), 화면과 도구는 [레이아웃 안내](LAYOUT_AND_TOOLS.md), 실시간 수치 편집은 [개발자 테스트](DEVELOPER_MODE.md)를 함께 참고한다.

## 1. 플레이 방법과 역할

덱 편집에서 밀집보병을 8장 중 하나로 넣거나, **방패의 진군** 프리셋을 선택한다. 카드를 배치하면 엘릭서 5를 소비하고 여섯 병사를 한 분대로 소환한다. 다른 카드처럼 손패를 순환하며 다음 카드를 가져온다. 스킬 버튼만으로 새 분대를 만들 수는 없다.

대형을 유지하는 동안 원거리 지원 병력을 뒤에 붙일 수 있다. 병사 한 명을 선택하면 그 병사가 속한 분대의 돌격 상태와 재사용 대기시간을 확인한다. 여러 분대를 소환했다면 각각의 식별자와 대기시간이 따로 존재한다.

방어 대형은 적이 사거리 안에 있어도 공격하지 않는다. `forming`, `guard`, `regroup` 모두 이 제한을 적용한다. 타워 앞에 도착한 뒤 피해를 주려면 돌격을 사용하거나 다른 병력의 공격을 지원해야 한다. 보호 조건을 잃었다고 해서 자동으로 공격 상태가 되지는 않는다.

방패 돌격은 먼 적에게 접근하거나 살아남은 분대로 역공하는 데 쓰인다. 발동 중에는 방어 효과가 사라지므로 광역 피해를 맞기 직전에 쓰는 선택은 불리할 수 있다. 지상 전용 병력이므로 공중 병력을 공격하지 못한다. 돌격도 공격 대상 규칙을 바꾸지 않는다.

## 2. 확정 수치

| 항목 | 구현값 | 적용 범위 |
|---|---:|---|
| 카드 ID / 이름 | `phalanx` / 밀집보병 | 카드 풀의 한 카드 |
| 카드 비용 | 엘릭서 5 | 분대 소환 1회 |
| 소환 수 | 6명 | 분대별 최초 인원 |
| 체력 | 340 | 병사 한 명 |
| 공격력 | 65 | 돌격 중 공격 1회, 병사 한 명 |
| 공격 간격 | 1.15초 | 스킬로 단축되지 않음 |
| 사거리 | 32 월드 픽셀 | 실제 타격 범위에는 양쪽 개체 반경도 적용 |
| 병사 반경 | 8 월드 픽셀 | 충돌·배치·강 경계 판정 |
| 공격 대상 | 지상 | 타워와 지상 건물 포함 |
| 방어 대형 이동 속도 | 24 월드 픽셀/초 | `guard` 상태 |
| 집결·재집결 이동 속도 | 36 월드 픽셀/초 | 각 병사가 자신의 위치를 찾는 동안 |
| 대형의 피해 감소 | 70% | 보호 조건을 모두 만족할 때 |
| 능력 ID / 이름 | `shield_charge` / 방패 돌격 | 소환된 분대에 귀속 |
| 능력 비용 | 엘릭서 1 | 성공한 발동마다 소비 |
| 돌격 이동 속도 | 68 월드 픽셀/초 | 5초 동안 |
| 돌격 지속시간 | 5초 | 전투 시뮬레이션 시간 |
| 재사용 대기시간 | 14초 | 발동 순간부터 계산 |

재사용 대기시간 14초에는 돌격 5초가 포함된다. 돌격이 끝난 직후에는 약 9초의 대기시간이 남는다. 일시정지하면 두 타이머와 분대 이동이 함께 멈춘다. 자유 연습의 배속을 높이면 화면의 실제 경과시간보다 전투 시간이 빨리 흐르지만, 능력 수치 자체는 바뀌지 않는다.

돌격은 이동 속도, 대형 상태와 공격 허용 여부를 바꾼다. 체력 회복, 추가 공격력, 공격 간격 감소, 공격 대기시간 초기화, 기절 해제 효과는 없다. 공격 간격 1.15초는 실제 공격을 허용하는 돌격 상태에서 사용하는 수치다.

## 3. 대형이 실제로 유지되는 방식

### 소환과 공간 확보

최초 대형은 3열×2행이다. 병사 중심 사이의 가로 간격은 17, 앞뒤 간격은 20 월드 픽셀이다. 몸체를 포함한 전체 폭은 50, 높이는 36이다. 분대 안의 각 병사는 독립적인 체력·공격·충돌·상태 이상을 가진다.

배치 검사는 여섯 위치를 한 번에 계획한다. 선택한 지점에 그대로 들어가지 못하면 최대 48픽셀 이내에서 **대형 전체를 같은 거리만큼 옮길 자리**를 찾는다. 병사마다 서로 다른 빈 공간에 흩어 소환하지 않는다. 아군 배치 구역, 기존 개체, 타워, 강 경계를 모두 만족하는 계획이 없으면 비용과 손패를 바꾸지 않고 실패한다.

`previewDeployment()`와 실제 `playCard()`는 같은 배치 계획을 사용한다. 성공한 미리보기의 여섯 좌표가 실제 소환 좌표와 일치한다. 소환 후 각 병사의 배치 지연이 끝나기 전에는 돌격을 사용할 수 없다. 기본 배치 시간은 0.65초이며 병사 순서마다 0.06초씩 차이가 있으므로 마지막 병사는 0.95초에 배치를 마친다.

### 공유 중심과 개별 몸체

분대는 공유 중심을 따라 이동한다. 각 병사는 자신의 행·열 위치를 향해 움직이고, 자기 몸체에 대해 건물 우회와 강 경계 검사를 받는다. 단순히 렌더링에서 병사들을 묶어 그리는 기능이 아니다. 피해 판정과 이동 좌표에도 대형이 적용된다.

강을 건널 때는 공유 중심을 다리 중심의 ±1픽셀 안으로 정렬한다. 3열 전체의 몸체가 54픽셀 폭의 다리에 들어가기 위한 제약이다. 후방 소환에서는 자신의 타워를 우회하며, 건물이 한 다리 입구를 막으면 통과 가능한 다른 다리를 고른다. 병사 개별 충돌이 대형을 밀어내면 전진을 멈추고 위치를 다시 맞출 수 있다.

병사가 죽으면 살아 있는 병사만 남겨 위치 번호를 다시 부여한다. 5명은 3명+2명, 4명은 2×2, 3명 이하는 한 줄로 재배열한다. 죽은 병사의 빈자리를 영구적으로 유지하지 않는다. 전멸한 분대는 목록에서 제거된다.

집결·재집결 중 위치 오차가 크면 현재 앞뒤 위치로 행을 정하고, 같은 행 안에서 좌우 위치로 열을 정해 슬롯을 결정적으로 교환한다. 전열 병사가 적에게 밀려 후열 뒤로 넘어갔을 때, 아군 몸체를 뚫고 원래 위치로 돌아가려다 전체 분대가 멈추는 문제를 막기 위한 규칙이다. 병사 ID와 체력은 유지하며 좌표를 순간이동시키지 않는다. 시뮬레이션의 같은 상태에서는 같은 순서가 선택된다.

### 상태 전이

| 상태 | 동작 | 다음 상태의 조건 |
|---|---|---|
| `forming` | 공격하지 않고 최초 위치로 집결 | 전원이 준비되고 위치 오차 6 이하를 0.2초 유지하면 `guard` |
| `guard` | 공격하지 않고 중심을 따라 느리게 이동 | 큰 이탈 또는 행동 불가가 생기면 `regroup`; 능력 성공 시 `charge` |
| `charge` | 개별 경로로 빠르게 움직이며 지상 대상을 공격 | 5초가 끝나면 `regroup` |
| `regroup` | 공격을 멈추고 살아 있는 병사들이 분대 위치로 복귀 | 준비·정렬 상태를 0.2초 유지하면 `guard` |

`guard`에서도 위치가 벌어지면 공유 중심은 대기한다. 오차가 16을 넘거나 준비되지 않은 병사가 있으면 재집결 상태로 바뀐다. 돌격 종료 시에는 생존자들의 중심과 주변 건물·강 경계를 고려해 재집결 중심을 정한다. 즉시 병사들을 순간이동시키지 않는다.

## 4. 방어 판정과 피해 예시

실제 피해 감소는 다음 조건을 모두 충족해야 적용된다.

- 분대 상태가 `guard`다.
- 살아 있는 병사가 최소 3명이다.
- 전원이 배치를 끝내고 활성 상태이며 기절하지 않았다.
- 모든 병사가 현재 대형 위치에서 10픽셀 이내에 있다.

`guard`라는 상태 이름만으로 항상 보호되는 것은 아니다. UI와 렌더러는 `formationProtected` 또는 `getAbilities()`의 `protected`를 사용해야 한다. 이 값은 방향성 방패 판정을 의미하지 않는다. 조건을 충족하면 어느 방향에서 받은 일반 피해든 70%를 줄인다. 보호와 공격 허용은 별도 조건이다. `formationProtected`가 거짓이어도 `charge`가 아니면 공격하지 않는다.

예를 들어 보호 중인 병사가 공격력 100의 피해를 받으면 실제 피해는 30이다. 체력 340인 병사의 체력은 310이 되며, 상대의 실제 피해 통계에는 30이 기록된다. 돌격 중에는 같은 공격으로 100을 받는다. 피해 감소는 병사·타워의 일반 공격, 광역 공격, 즉발 주문, 지속 주문의 각 피해 틱에 적용된다. 규칙 3 기록에서는 동일한 예시의 피해가 기존 값 65로 유지된다.

한 번의 광역 충돌은 피해를 적용하기 **직전**의 보호 상태를 모든 피격 병사에 대해 먼저 계산한다. 첫 병사에게 적용된 밀치기·기절·사망 때문에 같은 폭발의 나머지 병사가 더 큰 피해를 받지 않는다. 이후의 별도 공격은 변경된 대형과 상태 이상을 기준으로 새로 계산한다.

주문 미리보기는 현재 위치와 현재 보호 상태의 단일 피해를 보여 준다. 주문이 도착할 때도 같은 대형이 유지된다고 예측하지 않으며, 독 안개의 전체 지속 피해를 보장하지 않는다.

자유 연습 도구의 명시적 HP 피해·제거는 예외다. 도구에 지정한 HP를 정확히 조정하기 위해 방어 감소를 우회한다. 따라서 보호 중인 병사도 ‘제거’로 실제 삭제된다. 이 조작은 일반 전투 공격과 구분되며 기존 연습 기록 제외 규칙을 따른다.

## 5. 능력 사용 조건과 실패 처리

`activateAbility(team, groupId)`는 다음 사항을 엔진에서 다시 검사한다. UI 버튼의 활성 상태만 신뢰하지 않는다.

| 검사 | 거절하는 경우 |
|---|---|
| 진영 | `player`, `enemy` 외의 값 |
| 전투 모드 | 규칙 2 또는 `abilityMode: 'training'` |
| 재생 상태 | 리플레이를 보면서 새 능력을 직접 사용하려는 요청 |
| 진행 상태 | 시작 전, 일시정지, 이미 종료된 전투 |
| 소환 출처 | 원본 덱의 실제 소환 명령과 분대가 일치하지 않음. 명시적 개발자 테스트의 직접 소환은 별도 출처로 검증 |
| 소유권 | 상대 분대, 존재하지 않는 분대, 이미 전멸한 분대 |
| 배치 | 생존 병사 중 아직 배치 중이거나 비활성인 병사가 있음 |
| 기절 | 생존 병사 전원이 기절 중 |
| 분대 타이머 | 이미 돌격 중이거나 재사용 대기시간이 남음 |
| 자원 | 해당 진영의 엘릭서가 1 미만 |

실패하면 `{ ok: false, reason }`을 반환하며 비용, 손패, 기록, 타이머를 바꾸지 않는다. 성공하면 엘릭서 1을 차감하고 능력 명령을 기록한 뒤 `{ ok: true, groupId, cost: 1 }`을 반환한다.

일부 병사만 기절한 경우 능력 사용은 가능하지만 그 병사의 기절이 사라지지는 않는다. 살아 있는 병사가 1~2명이어도 플레이어는 능력을 사용할 수 있다. 다만 그 인원으로는 방어 대형의 피해 감소를 얻지 못한다. AI는 생존자가 3명 이상일 때만 발동 후보로 삼는다.

능력은 카드 소환이 아니다. 손패와 대기열을 회전시키지 않고 `cardsPlayed`를 늘리지 않는다. `elixirSpent`에는 실제로 지불한 1을 포함한다.

## 6. UI와 AI에 공개한 API

### 조회

```js
const abilities = game.getAbilities('player');
const selected = abilities.find(ability =>
  ability.memberIds.includes(selectedEntityId)
);

if (selected?.ready) {
  const result = game.activateAbility('player', selected.groupId);
  if (!result.ok) showMessage(result.reason);
}
```

`getAbilities(team)`는 해당 진영의 살아 있는 분대만 반환하는 순수 조회다. 반환 배열과 `memberIds`를 UI가 수정해도 엔진의 분대가 바뀌지 않는다. 잘못된 진영에는 빈 배열을 반환한다.

| 반환 필드 | 의미 |
|---|---|
| `groupId`, `cardId`, `abilityId`, `name` | 소환 분대·카드·능력의 식별과 표시명 |
| `cost` | 이 분대에 적용된 발동 비용, 기본값 1 |
| `mode` | `forming`, `guard`, `charge`, `regroup` |
| `ready`, `reason` | 지금 요청하면 사용할 수 있는지와 현재 실패 사유 |
| `chargeRemaining` | 현재 돌격의 남은 전투 시간 |
| `cooldownRemaining` | 분대의 남은 재사용 대기시간 |
| `duration`, `cooldown` | 이 분대에 적용된 지속시간·대기시간, 기본값 5와 14 |
| `aliveCount`, `memberIds` | 현재 살아 있는 병사 수와 식별자 목록 |
| `x`, `y` | 현재 공유 중심의 월드 좌표 |
| `protected` | 현재 실제 피해 감소 조건 충족 여부 |

병사 개체에는 `formationGroupId`, `formationSlot`, `formationState`, `formationProtected`, `chargeRemaining`이 추가된다. 카드 ID만으로 소속 분대를 정하면 같은 카드를 여러 번 소환했을 때 잘못된 분대에 능력을 사용할 수 있다. 선택된 병사의 ID와 `memberIds`를 대조해야 한다.

### 상대 AI

AI는 자신의 분대와 엘릭서, 공개된 전장 위치만 사용한다. 상대의 손패나 엘릭서를 읽지 않는다. 보이는 지상 대상과의 거리를 좁히거나 위험한 킹 타워를 지원할 때 돌격을 검토한다. 규칙 4에서는 대형 중 공격할 수 없으므로 이미 가까운 적과 싸우기 위해서도 준비된 돌격을 사용한다. 규칙 3의 근접 교전 판단은 기존 방어 중 공격 규칙을 따른다.

능력 사용도 `getAbilities('enemy')`와 `activateAbility('enemy', groupId)`를 통한다. 별도의 비용 면제나 재사용 대기시간 단축이 없다. 난이도에 따른 판단 주기와 남길 자원 차이는 기존 AI 설정을 따른다. 발동 결정은 `intent: 'charge'`와 `groupId`로 AI 스냅샷에 남기며, 최근 **카드 배치** 목록에는 넣지 않는다. 따라서 이를 밀집보병 카드를 한 장 더 낸 것으로 계산하지 않는다.

## 7. 저장·복원·리플레이

### 호환 범위

전투 스냅샷과 리플레이의 포맷 버전은 2를 유지하고, 새 경기의 기본 전투 규칙은 4로 올렸다. 규칙 3 밀집보병은 35% 방어와 대형 중 공격을 보존하며, 규칙 4는 70% 방어와 돌격 중에만 공격하는 동작을 사용한다. 규칙 2에서 밀집보병 덱을 만들거나 배치하는 요청은 거절한다.

전역 `CARDS`에는 현재 기본값인 70%가 들어 있다. 실제 경기 수치는 `game.getCard(cardId, team)`로 읽어야 한다. 같은 카드라도 규칙 3에서는 35%를 반환하며, 개발자 테스트에서는 해당 경기·진영의 수정값을 반환한다. 기존 규칙 2/3 경기의 일반 카드 수치와 저장 형태는 유지한다.

일반 경기에서 밀집보병이 양쪽 덱 어디에도 없으면 `state.formations` 필드를 새로 추가하지 않는다. 개발자 테스트에서 덱 밖 밀집보병을 직접 소환하면 그때 실제 분대 목록을 만든다. `abilityMode`도 명시한 경우에만 설정 스냅샷에 포함한다. 기존 저장에 규칙 버전이 없으면 기존 정책대로 규칙 2로 복원한다.

`abilityMode`의 허용값은 `battle`, `practice`, `training`이다. 값을 생략하면 자유 연습 여부에 따라 기본값을 정한다. 전술 훈련은 생성할 때 `training`을 명시해 엔진 수준에서 능력 사용을 막는다. 복원한 게임은 다른 저장과 마찬가지로 일시정지 상태로 시작한다.

### 분대 상태와 명령

스냅샷은 분대 중심, 구성원, 공유 경로, 상태, 돌격·재사용 타이머, 재집결 유지시간을 보존한다. 각 분대의 `spawnCommandIndex`와 소환 명령의 `groupId`가 일치해야 한다. 구성원이 실제로 존재하는지, 다른 분대와 중복되지 않는지, 카드·진영·상태·타이머가 맞는지 검사한 후 복원한다.

기존 카드 명령의 형태는 유지한다. 새 밀집보병 소환 명령에만 `groupId`를 추가하고, 능력 명령은 다음 형태로 기록한다.

```js
{
  type: 'ability',
  tick: currentTick,
  team: 'player',
  cardId: 'phalanx',
  abilityId: 'shield_charge',
  groupId: summonedGroupId
}
```

리플레이는 먼저 기록된 소환과 분대 식별자를 확인하고, 그 분대의 능력 명령을 같은 틱·같은 순서에 적용한다. AI를 다시 실행해 결정을 추측하지 않는다. 내부 재생 경로도 배치 완료, 실제 비용, 재사용 대기시간, 생존 여부 검사를 거친다. 관람 중 외부에서 직접 호출한 능력은 거절한다.

같은 틱에서 두 번 발동하거나 배치 직후 너무 일찍 발동하도록 조작한 기록, 다른 진영의 분대를 사용한 기록은 실패한다. 마지막 기록 틱에 입력된 능력과 같은 틱의 항복도 보존한다. 돌격·재집결 도중 저장했다가 계속하는 경우와 능력이 포함된 리플레이 모두 전체 엔진 스냅샷의 동일성을 검사한다.

### 전투 분석

`summarizeBattle()`은 카드 사용과 능력 사용을 구분한다. `cards`, `byCard`, 레인 배치 횟수는 카드 명령만 센다. `abilities`와 `abilityElixirSpent`에 능력을 별도로 집계한다. 전체 `elixirSpent`에는 두 비용이 모두 들어간다. `averageCost`는 능력 비용을 뺀 카드 평균이다.

예를 들어 밀집보병을 한 번 소환하고 돌격을 한 번 쓰면 카드 1회, 능력 1회, 전체 엘릭서 6, 능력 엘릭서 1, 카드 평균 비용 5가 된다.

## 8. 개발자 테스트에서 분대 수치 조정

개발자 기능은 `new Game({ practice: true, developerMode: true, rulesVersion: 4 })`처럼 명시한 자유 테스트에서만 사용할 수 있다. 일반 경기·기존 자유 연습·훈련·리플레이에는 이 권한이 없다. 생성 조건이 잘못되면 거절하며, 진행 중인 개발자 경기에서도 일시정지 상태의 수치 변경만 허용하고 배치·능력 사용은 실행 중에만 허용한다.

분대 전용 편집 필드는 `damageReduction`, `chargeSpeed`, `abilityCost`, `abilityDuration`, `abilityCooldown`이다. 일반 병력의 체력·공격력·공격 간격·사거리·이동 속도 등도 해당 진영별로 조절할 수 있다. 전체 필드·최소값·최대값·UI 증감 간격은 `game.getBalanceFields('phalanx')`에서 조회한다. 모든 수정은 현재 경기의 패치이며 전역 `CARDS`를 바꾸지 않는다.

```js
game.setCardBalance('phalanx', {
  damageReduction: 0.8,
  chargeSpeed: 90,
  abilityDuration: 10,
  abilityCooldown: 28,
}, { team: 'player', applyExisting: true });
```

`applyExisting: true`가 기본이다. 현재 살아 있는 병사의 HP 비율과 공격 대기시간의 진행률을 보존하면서 새 값을 적용한다. 분대의 남은 돌격 시간과 재사용 대기시간도 이전 기본 길이에 대한 비율을 유지한다. 예를 들어 5초 돌격 중 4초가 남았을 때 지속시간을 10초로 바꾸면 8초가 남는다. 기절·동결 등 독립 상태를 해제하거나 죽은 병사를 되살리지 않는다.

`applyExisting: false`이면 새 소환과 새 시전에만 수정값을 사용한다. 이미 소환된 분대의 속도·방어·능력 수치는 `balanceStats`에 보존하므로 다음 틱에 현재 카드 값을 다시 읽어 몰래 바꾸지 않는다. UI는 선택한 기존 분대의 `getAbilities()` 결과와 실제 개체 값을 우선 표시한다. 이미 발사된 투사체, 예약 주문과 생성된 독 지역도 당시 수치를 유지한다.

`spawnDeveloperCard(team, 'phalanx', x, y)`는 원래 8장 덱에 없는 분대도 정상 배치·비용 경로로 생성한다. 손패는 순환하지 않으며, 분대 ID를 실제 `developer-spawn` 명령과 연결한 뒤 그 진영의 능력을 허용한다. 무한 엘릭서는 명목 비용을 기록하고 즉시 10으로 보충한다. 재사용 대기시간을 없애도 진행 중인 돌격을 중복 발동할 수 없다.

개발자 스냅샷에는 `config.developerMode: true`와 최상위 `developer: { version: 1, balance, cheats }`가 함께 들어간다. 모드 표시, 팀별 패치, 분대 적용값과 명령의 출처를 검증해 같은 개발자 상태로만 복원한다. 일반 스냅샷에는 이 필드를 추가하지 않는다. 개발자 경기의 `exportReplay()`와 일반 리플레이 가져오기는 거절하며, 일반 승수·캠페인 진척에 편집값을 전달하지 않는다. 전체 사용법은 [개발자 테스트 문서](DEVELOPER_MODE.md)에 있다.

## 9. 검증 범위와 남은 한계

[분대 회귀 검사](../tests/phalanx.test.mjs)의 20개 검사는 다음 기능을 검증한다. 기존 규칙 3 사례를 명시적으로 유지하면서 규칙 4와 개발자 분대의 새 검사를 추가했다.

- 비용·순환·여섯 병사·소환 명령의 결합과 미리보기의 정확성.
- 양 진영의 3×2 대형 유지, 다리 통과, 후방 타워 우회, 막힌 다리의 대체 경로.
- 단일 피해와 광역 피해의 실제 감소량, 동일 충돌 내 처리 순서 독립성, 기절·사망 후 방어 조건.
- 전열 병사가 후열 뒤로 밀린 상황의 양 진영 재현과, 실제 위치에 따른 슬롯 교환 후 전진 재개.
- 돌격 속도의 실제 이동 차이, 재집결, 분대별 대기시간, 일시정지, 잘못된 사용 요청의 무변경 처리.
- 훈련 제한, 관람자의 리플레이 입력 차단, 손상된 분대·명령의 복원 거절.
- 돌격·재집결 저장의 정확한 미래, AI의 정상 자원 지불과 숨은 정보 미조회, 전체 리플레이 일치.
- 이전 엔진에서 채취한 규칙 2/3 전체 스냅샷 해시와의 일치.
- 자유 연습에서 보호된 병사의 절대 HP 제거와 일시정지 중 기절 표시 갱신.
- 규칙 4의 70% 방어, 집결·방어·재집결 중 공격 금지, 돌격 시작·종료에 따른 실제 공격 허용.
- 규칙 4의 분대 저장·리플레이 일치와, 규칙 4 도입 전에 채취한 규칙 3 분대의 전체 스냅샷 해시 2개 일치.
- 개발자 조정 중 돌격·재사용 진행률 보존, 진영별 격리, 기존 분대를 유지하는 미래 소환 전용 설정과 복원.

실행 명령은 다음과 같다.

```sh
node --test tests/phalanx.test.mjs
```

분대 20개, 기존 전투 규칙·호환 10개, [개발자 검사](../tests/developer.test.mjs) 12개를 함께 실행한 엔진 관련 검증은 **42/42 통과**했다. 전역 수치 불변, 잘못된 입력의 원자적 거절, 양 팀 조작, HP·공격 진행률 보존, 예약 피해 고정, 덱 밖 분대와 엄격한 복원·리플레이 경계를 포함한다.

이 검사는 고정 시간 간격 `1/60`을 사용하는 결정적 시뮬레이션 검사다. 렌더링이 예쁘게 보이는지만 확인하는 검사가 아니며, UI의 실제 클릭·터치 품질이나 기기별 3D 성능을 증명하지 않는다. 사람의 대전 경험을 통한 장기 밸런스 평가는 아직 별도 과제다. 분대의 피해 감소, 전멸 위험, 발동 비용과 타이밍은 실제 플레이 피드백에 따라 조정할 수 있다.

규칙 3으로 분대를 처음 도입할 당시 [코어 스트레스 검사](../tests/core_stress.test.mjs)의 3상대×3난이도×2시드, 총 18경기도 같은 정체 기준을 유지한 채 완료했다. 네 번째 프리셋이 포함되면서 드러난 세라·도전 난이도·시드 951의 아군 후열 막힘은 슬롯 교환으로 해결했다. 당시 이 경기의 ‘사거리 밖에서 체력 변화 없이 서 있던 연속 시간’은 수정 전 12초에서 수정 후 1초로 줄었고, 전체 18경기의 최대값은 2초였다. 이 수치는 규칙 3의 경로 결함 재현·수정 기록이며 새 규칙 4의 승률이나 난이도 수치로 해석하지 않는다.

스트레스의 양쪽 AI 어댑터는 카드 배치로 경기를 진행하며, 이 18경기는 능력 사용 빈도나 사람의 승률을 평가하는 표본이 아니다. 능력을 사용하는 AI의 합법성·숨은 정보 미조회·정확한 저장 및 리플레이는 별도 분대 검사에서 확인한다.

경로는 공유 중심과 지역적인 건물 우회를 사용한다. 일반적인 다리·타워 배치의 진행을 검사했지만, 임의의 치트로 조밀하게 쌓은 모든 장애물 배치에 대해 전역 최적 경로를 보장하는 방식은 아니다.
