# STARWARD v7 — 최종 검증·저장 호환 기록

**검증 기준일: 2026-11-16 · 상태 버전: 7 · EXPEDITION / 07**

최종 회귀 시험은 **225/225 통과**, 공개 명령으로 진행한 캠페인은 **4/4 승리**했다. 실제 브라우저에서는 시스템 설치·확장, 타일 이동·근접전·후퇴, 화면 전환과 저장 불변성, 최종 독립 HTML의 실제 사격을 확인했다. 브라우저의 3D 검증은 **호환 3D 출력**을 사용했다. WebGL GPU 출력은 이 환경에서 활성화되지 않아 실제 GPU 화면 검증에 포함하지 않는다.

이 기록은 STARWARD 구현의 동작을 검증한다. 원작 FTL 실행 파일이나 원본 내부 코드를 실행·대조한 결과는 아니다. 기능과 규칙은 [시스템 설치](v7_system_slots.md), [타일 이동·근접전](v7_crew_grid_combat.md), [화면·그래픽](v7_render_modes.md)을 함께 참조한다.

## 1. 검증 방법과 근거의 구분

| 구분 | 실제 수행 방법 | 결과가 뒷받침하는 범위 |

규칙 시험은 문 봉쇄, 특정 손상, 경계 좌표 같은 상황을 직접 준비할 수 있다. 이 전제 구성은 아래의 공개 명령 완주와 구분한다. 완주 정책은 선체·스크랩·승무원 HP·좌표·경험치·난수·승리 상태를 직접 대입하지 않는다. 마지막 기함까지 모든 전투 결과가 실제 전투 틱에서 발생한다. 구현은 [playthrough.cjs](../tests/playthrough.cjs)에 보존한다.

최종 집계의 입력 기록은 `verification-v7-draft.json`, `v7-final-regression.tap`, `v7-all-policies.json`이다. 마지막 파일은 JSON 결과 배열 뒤에 `PASS: 4/4` 실행 요약이 붙은 원시 출력이다. 배포용 기계 판독 기록은 [verification-v7.json](../tests/verification-v7.json)을 사용한다. 브라우저와 독립 HTML의 최종 사격·콘솔 결과는 초안 이후 완료된 확인 결과를 이 문서에 반영했다.

### v7에서 집중한 경계

- **설치:** 조회는 상태를 바꾸지 않고, 성공 시 비용을 한 번 차감한다. 신규 설비는 선택한 실제 방에 1단계·전력 0으로 설치된다. 확장은 40→60 순서를 따르며, 전투·사건에서는 설치·확장·강화를 거부한다.
- **피해와 수리:** 설치실의 물리적 피해·수리는 해당 설비를 참조한다. 빈 방은 포격·빔 피해 대상이지만 존재하지 않는 시스템을 이온으로 잠그지 않는다.
- **타일 이동:** 상하좌우 경로, 실제 문, 정지 중 재지시, 점유·목적지 예약, 이동 도중 저장을 검사한다. 닫힌 문과 벽, 대각선 너머에서는 근접 피해가 발생하지 않는다.
- **공격과 전송:** 추격 후 실제 타격, 수동 후퇴의 공격 취소, 종족 피해·공격 대기, 정신 지배 중 진영 변경, 귀환 직후 표적 해제, 전송 도착 타일 예약을 검사한다.
- **검증 실패:** 잘못된 설치 위치, 가짜 경로, 부적절한 타일 좌표·공격 참조·이전 도면 교체는 현재 항해를 변경하지 않고 거부한다.

네 경우 모두 **1~8섹터를 방문하고 기함 3단계와 중계망 복구·피난민 호송·설계도 회수의 세 퀘스트를 완료**했다. 누적 전투 시간은 시뮬레이션에서 흐른 전투 시간이며 사용자의 실제 플레이 시간이나 시험 프로그램의 실행 시간이 아니다.

정책은 보상을 받아 장비를 회수·분해하고, 실제 화물 보관·교체·판매를 수행한다. 보급 구매·반응로/실드/선체 강화·인원 고용·설치 마운트 확장·능력 사용도 자원과 상태 조건을 통과한다. 40 HP는 항해 중 선체 강화를 구매한 결과이며 시작 선체가 아니다.

처음 아틀라스 경로에서 정지 인원의 통로 점유와 서로 마주 선 수리 인원의 예약이 진행을 막는 실패를 발견했다. 같은 방 안의 양보 이동과 인접 문 교행을 수정한 뒤 최종 네 경로가 모두 승리했다. 이 결함 해결을 위해 전투 피해나 적 선체 밸런스를 완화하지 않았다.

이 네 결과는 준비된 정책의 재현 시험이다. 초보 사용자의 승률, 모든 난수 시드의 완주 가능성, 최적 전략을 뜻하지 않는다. 이 네 경로의 환경 교전 기록은 비어 있으므로 위험 환경의 검증 근거는 별도 규칙 시험에서 찾는다.

## 4. 실제 브라우저에서 확인한 범위

관리되는 데스크톱 브라우저에서 실제 UI 입력과 저장 파일 가져오기/내보내기를 사용했다. 긴 항해의 중간 상황은 공개 명령으로 얻은 **v7** 저장을 파일 UI로 가져와 이어갔다. 이 항목은 브라우저에서 캠페인 네 번을 처음부터 끝까지 직접 조작했다는 뜻이 아니다.

## 5. 3D 경로와 성능 확인의 한계

이 브라우저는 WebGL 컨텍스트를 제공하지 않았다. 실제 화면에서는 `backend='software'`, `supported=true`인 **호환 3D**가 동작했다. 같은 3D 기하와 카메라 행렬을 투영해 Canvas2D에 면을 그리며, 투영된 삼각형과 깊이로 클릭 대상을 고른다. 실제 브라우저에서 높이 있는 선체·시설·승무원, 사각 바닥, 스타일 변경, 카메라와 선택 입력을 확인했다.

WebGL 경로는 mock 컨텍스트로 기하 업로드·선택 payload·리사이즈·자원 해제·실패 처리를 검사했다. 실제 GPU 드라이버의 셰이더 출력, 기기별 색상·깊이 정밀도, 프레임률은 이번 결과에 포함되지 않는다. Canvas2D 자동화 시험도 그리기 메서드는 mock이며 실제 화면의 근거는 위 브라우저 확인이다.

호환 3D에는 **18 fps 렌더링 상한**과 바뀌지 않은 일시정지 장면의 재사용이 있다. 18 fps는 최대 그리기 빈도를 제한하는 설정이며 **최저 성능 보장이나 측정된 평균 프레임률이 아니다.** 시뮬레이션의 `tick()`은 UI가 별도로 진행한다. 선택·명령·스타일·카메라가 바뀌면 해당 표시를 다시 그리며 렌더 제한이 전투 시간을 대신 진행하지 않는다.

## 9. 확인하지 않은 범위

- 원작 FTL과 전체 규칙·수치·콘텐츠가 완전히 같다는 검증은 하지 않았다. 이 게임은 자체 사건·경제·적 수치·정비 규칙을 사용한다.
- 실제 모바일 기기, 모든 브라우저·GPU·해상도·보조 입력 장치를 시험하지 않았다. 이번 실제 3D 화면은 호환 출력이며 GPU 화면의 실기 검증은 남아 있다.
- 네 캠페인 경로는 모든 시드·상점 조합·전술의 성공이나 일반 사용자 승률을 대표하지 않는다.
- 슬롯 확장은 미리 정의한 여섯 구획을 사용하는 방식이다. 방을 자유 배치하거나 선체를 편집하는 건조 도구는 없다.
- 빔은 두 방의 중심으로 조준한다. 자유 좌표 드래그 빔, 원작의 모든 시스템·종족·장비·이벤트·해금·업적은 구현 범위에 포함되지 않는다.

이 한계를 포함한 최종 전달 상태는 자동화 시험 225개, 공개 명령 완주 4회, 실제 브라우저의 확인 항목 및 위 독립 파일 해시로 식별한다.
