# STARWARD v6 — 검증·저장 호환·원작과의 차이

> 기준일: 2026-11-16. 실제 구현과 실행 검증의 범위를 기록합니다. 자동 시험 결과는181/181, 공개 명령 완주는4/4입니다. 브라우저 증거는 별도 절에 실제 확인한 조작만 기록합니다.

## 1. 두 종류의 항해

새 항해는 `campaign.routeMode='expanded'`, `totalSectors=8`입니다. v1~v5에서 가져온 항해는 `routeMode='legacy'`, `totalSectors=3`으로 보존합니다. 이전 저장의 세 번째 섹터를 갑자기 새 캠페인의 중간으로 바꾸거나 비콘·함선·보상·승무원을 재생성하지 않습니다.

상태 버전은6입니다. 코어 로더는 입력을 별도 후보로 파싱하고 필요한 변환을 적용한 뒤 코어·전술·공간·캠페인 전체 검증을 통과한 경우에만 현재 항해를 교체합니다. `migrateCampaignV6(state)`와 `validateCampaignV6(state)`는 캠페인 모듈이 맡고 최종 교체는 엔진이 맡습니다.

| 보존할 기존 항목 | 추가할 v6 항목 |
|---|---|
| 선체·승무원·장비·화물·자원 | 항해 종류·총 섹터·월드 경로 |
| 실제 도면·문·물리 좌표·이동 큐 | 텔레포터 송신실·정원 |
| 조준·충전·수동 예약·비행 탄 | 해킹·정신 지배·배터리 상태 |
| 은폐·전송 대기·이온·환경 | 임시 진영 `controlledBy`·임시 HP `mindBonusHp` |
| 현재 비콘·사건·보상·상점 | 퀘스트·플래그·방문/재고 상태 |
| 난수·ID·통계·로그 | 캠페인의 추가 검증 필드 |

v5 은폐의 남은 시간이6초였다는 이유로 새1단계5초 규칙에 맞춰 즉시 깎거나 정상 저장을 거절하지 않습니다. 이미 진행한 항해를 유지하는 변환과 새 명령의 규칙을 구분합니다.

## 3. 발사 수정의 완료 기준

실제 브라우저에서 무기 모드 버튼에 초점이 있는 상태로 Space를 누르면 전투 재개 대신 버튼의 자동/수동 전환이 실행되는 경로를 재현했습니다. 이 재현의 수정 여부와 별도로 실제 탄이 발사되고 피해가 발생하는지 확인합니다.

- 새 항해에서 세 함선의 실제 충전·조준·첫 유효 공격.
- 충전 중 단발 예약, 정지 중 비용 불변, 재개 후 단 한 번 발사.
- 자동 표적 유지와 반복 발사, 예약 취소, 탄약·전력·표적별 실패사유.
- 빔의 두 방 조준과 실제 상대 도면의 통과 방·피해.
- 브라우저 클릭·키보드·초점·갱신 중 버튼 동작·저장 재개.

단위 시험에서 충전값을 직접 채운 사례는 개별 규칙을 검증하는 fixture로 표시합니다. 그것을 실제 사용자가 조작한 공격이나 전체 항해의 근거로 대신하지 않습니다.

## 4. 능력과 캠페인 검증 범위

전송은 실제 집결·정원·같은 방 회수·가동 단계·상대 은폐·특수 실드·죽음과 도약 손실을 구분합니다. 해킹은 발사/접근/요격/부착/펄스/쿨다운과 실제 문·시스템 효과를 확인합니다. 정신 지배는 소유 배열·물리 위치·임시 진영·AI·만료/사망/해제의 일관성을 확인합니다. 배터리는 만료·손상·폭풍에서 실제 전력 예산을 확인합니다.

월드맵은8깊이·연결·현재 경로·출구 선택을, 비콘은 양방향 연결·재방문 비용·보상 중복 방지·점령을 확인합니다. 사건·퀘스트·상점은 실행 순간 조건·원자적 비용·재고 유지·진행/완료·다음 섹터 이월과 저장 후 결과 일치를 다룹니다. 실패한 불법 명령이나 저장은 현재 자원·난수·ID·로그를 바꾸지 않아야 합니다.

기존137개 회귀 시험을 유지하면서 현재 버전·원작에 맞춰 바뀐 시간/집결·새8섹터와 이전3섹터를 구분하는 전제를 명시적으로 갱신합니다. 새 규칙을 만족시키기 위해 기존 검사를 삭제하지 않습니다.

## 5. 공개 명령 완주와 브라우저 자료

[playthrough.cjs](../tests/playthrough.cjs)는 UI에서 사용할 수 있는 공개 명령과 실제 틱만 실행합니다. 게임 상태는 읽고 HP·자원·경험치·위치·승리·난수를 대입하지 않습니다. 기본 검증은 세 함선 표준과 아르고 베테랑 각1시드입니다. 실제8섹터·기함3단계·회수/거래·퀘스트와 능력 사용을 결과에 기록합니다. 이 정책의 승리 비율은 일반 플레이어 승률이 아닙니다.

브라우저용 JSON은 같은 실제 항해의 특정 시점에서 `serialize()`한 저장입니다. 가져오기 화면을 통해 지도·상점·진행 중 퀘스트·준비된 능력을 확인하되, 개발 도구로 UI나 자원을 직접 주입하지 않습니다. 모든 능력이 한 저장에 동시에 준비되어 있어야 하는 것은 아닙니다.

### 5.3 JSON 전달 검증

검토용 저장 생성기의 첫 출력은 `serialize()`가 반환한 문자열을 다시 `JSON.stringify`하여 문자열을 담은 JSON이 되었습니다. 메모리 안의 원래 저장만 검사한 탓에 파일 형식 문제를 놓쳤습니다. 생성기를 `writeFileSync(serializedString)`으로 수정하고 **실제 파일을 다시 읽어 객체 JSON인지 확인한 뒤 그 바이트 그대로 `load()`**하도록 변경했습니다. 잘못된 출력을 제품 저장 호환 통과로 집계하지 않습니다.

수정된 지도·퀘스트·상점·월드 선택·정신 지배 교전·해킹 접근·집결 완료 저장은 모두 공개 명령 항해에서 얻고 정확한 파일 바이트로 로더 승인을 확인했습니다. 집결 완료 저장은 실제 승무원 이동168틱 뒤 정지한 상태입니다. 상태를 직접 수정해 준비된 것처럼 꾸미지 않았습니다.

모바일 실제 기기·모든 브라우저·전체 원작 콘텐츠를 확인한 것으로 확대하지 않습니다.


### 5.4 실제 브라우저와 오프라인

데스크톱 브라우저의 실제 클릭·키보드·파일 선택으로 다음을 확인했습니다. UI 상태나 재화를 개발 도구로 직접 주입하지 않았습니다. 후반 능력의 준비는 앞에서 설명한 공개 명령 항해 JSON을 정상 가져오기 경로로 복원했습니다.

입력 점검 과정에서 동적으로 갱신되는 버튼의 추가 문제도 찾았습니다. 원래 문자열과 브라우저가 정규화한 `innerHTML`을 비교하면 동일한 화면도 매 프레임 재생성되어 키 입력 중 초점이 사라질 수 있었습니다. 생성 문자열을 `WeakMap`에 보존해 같은 내용의 중복 패치를 막도록 수정했습니다. 최종 오프라인에서 무기 모드 버튼에 초점을 둔 Space 재개·수동 모드 유지·예약 발사와 실제 피해를 다시 확인했습니다. 모든 키보드 조합을 확인했다고 확대하지 않습니다.

최종 전달용 오프라인은 **505,704바이트**, 내장 JavaScript4개·CSS1개입니다. 자동 엔진 시험, 정상 파일 가져오기, 실제 오프라인 귀환을 서로 다른 검증 근거로 구분합니다. 최종 확인 구간의 앱 자체 콘솔 오류는0이었습니다. Chrome 확장 프로그램 메타데이터 오류는 별도로 구분했으며 전체 브라우저 콘솔의 모든 메시지가 없었다는 뜻은 아닙니다. 모바일 실제 기기는 확인하지 않았습니다.
