# 10. 미션·목표·전력망 역기획

[전체 목차](00_README_문서안내.md)

> 범위: PC판 및 Advanced Edition 공개 규칙. 조사일: 2026-11-13.
> [확인]은 문헌 근거이며 실기 검증과 다르다. [분석]은 설계 해석, [제안]은 구현 명세, [미확인]은 별도 확인 항목이다.

## 1. 전투에서 지켜야 하는 것은 무엇인가

**[분석]** 이 게임의 전투는 적 제거량만으로 평가할 수 없다. 지금 턴의 건물 피해를 막는 일, 미션 목표를 완료하는 일, 다음 전투에 가져갈 파일럿과 장비를 보전하는 일이 서로 다른 성과이기 때문이다.

| 층위 | 대표 지표 | 의미 |
| --- | --- | --- |
| 전투 진행 | 남은 턴·행동 가능한 기체 | 이번 전장을 버틸 수 있는가 |
| 전력망 | 현재 Grid Power | 시간선을 계속 유지할 수 있는가 |
| 목표 | 보호·파괴·처치·행동 조건 | 보상과 섬 완벽 완료를 얻는가 |
| 인명 기록 | 건물 손실·구조 인원 | 전투 결과를 서사·점수로 표현 |
| 성장 | 파일럿 생존·코어·장비 | 다음 전투의 선택지가 늘어나는가 |

**[제안]** 이 다섯 지표를 하나의 `MissionWin` 불리언으로 압축하지 않는다. 미션은 종료됐지만 목표는 일부 실패할 수 있고, 도시 피해가 있어도 모든 보너스 목표를 달성할 수 있다.

## 2. 전력망의 확인된 규칙

| 규칙 | 요약 | 근거 |
| --- | --- | --- |
| 시작·상한 | Grid Power는 5로 시작, 최대 7 | P08 |
| 지속성 | 손익은 미션·섬 사이에 유지 | P08 |
| 패배 | 전력이 0에 도달하면 현재 런 종료 | P08 |
| 피해 | 민간 건물 피해가 전력 손실로 연결 | P08, P09 |
| 회복 | 목표 보상, 섬 상점, 특정 장비·보상으로 회복 | P08 |
| 저항 | Grid Defense는 건물 피해를 저항할 확률 | P08 |
| 기본 저항 | 일반 기본값 15%, Unfair 0% | P08 |
| 초과 전력 | 상한을 넘는 획득량은 방어 보너스로 전환 | P08 |
| 초과 보너스 | 초과 전력 첫 5단위는 단위당 2%p, 이후 단위당 1%p, 최대 +25%p | P08 |

**[분석]** 메크의 HP는 국지적 여유이고 전력망은 런 전체의 생명력이다. 전투 종료 후 정비되는 메크에게 피해를 대신 받게 하는 선택은 이러한 시간 단위 차이에서 가치를 얻는다.

**[분석]** 방어 확률은 계획을 세우는 기본 자원이 아니라 피해를 받을 상황에 남아 있는 구제 가능성으로 해석하는 편이 일관된다. 예측 UI에는 “실패 시 손실”과 “저항 가능성”을 함께 보여 주어야 한다.

### 2.1 초과 전력의 계산 예시

아래는 위 수치의 산술 예시다. 파일럿 보너스가 없고 일반 난이도의 기본 방어가 적용된다고 가정한다.

| 시작 상태 | 입력 | 결과 |
| --- | --- | --- |
| 전력 5, 방어 15% | 전력 +1 | 전력 6, 방어 15% |
| 전력 6, 방어 15% | 전력 +2 | 전력 7, 초과 1에 따른 방어 증가 |
| 전력 7, 초과 전력 누적 0단위 | 전력 +5 | 초과 보너스 +10%p |
| 전력 7, 초과 전력 누적 5단위 | 전력 +1 | 이후 증가량 +1%p |

**[제안]** 계산 데이터는 `gridHealth`, `overpowerContribution`, `pilotContribution`으로 분리한다. 파일럿을 교체할 때 방어 수치를 올바르게 다시 계산할 수 있고, 초과 전력의 상한을 전체 방어 상한과 혼동하지 않게 된다.

## 3. 건물 피해와 다른 파괴 대상

**[확인]** 건물은 Grid Defense에 따라 피해를 저항할 수 있으며, 잃은 건물은 전력과 구조 인원 기록에 영향을 준다. 건물의 얼음은 보호 수단으로 사용할 수 있다. [P09, P27]

| 대상 | 시스템 분류 | 잃었을 때 확인할 항목 |
| --- | --- | --- |
| 민간 건물 | 전력망 공급원 | 전력·민간 피해 |
| 보호 목표 건물 | 목표와 연결된 구조물 | 목표 실패·보상 손실·전력 관계 |
| 아군 이동 유닛 | 특수 행동 또는 호위 대상 | 목표와 전장 장애물 변화 |
| 파괴 목표 오브젝트 | 의도적으로 제거할 대상 | 파괴 보상·지형 변화 |
| 타임 포드 | 회수 가능한 보상 오브젝트 | 포드 보상·완벽 완료 조건 |
| 적 생성물 | 적의 기능 확장 | 공격 취소·소환 제한·처치 집계 |

**[제안]** 건물처럼 보이는 모든 스프라이트에 `LoseGridPower()`를 연결하지 않는다. `GridConnected`, `ObjectiveTarget`, `CivilianPopulation`, `DamageResistancePolicy`를 구분해야 한다. 보호 목표의 HP 감소와 민간 건물 1동 파괴는 같은 이벤트가 아닐 수 있다.

### 3.1 피해 예측의 출력

**[제안]** 건물 타일을 향한 공격 미리보기에는 다음 정보를 포함한다.

- 대상 타일과 현재 남아 있는 건물 수 또는 내구 표현.
- 예상되는 최대 전력 손실과 조건부 저항 여부.
- 해당 타일이 보호 목표인지 여부.
- 충돌·연쇄·후속 공격으로 인한 추가 위협.
- 얼음·실드 등 선행 방어층 소모 여부.

**[미확인]** 다중 건물 타일의 개별 손실, 한 공격의 다단히트, 얼음과 실드가 함께 있을 때의 우선순위는 실제 엔진 판정 순서를 확인해야 한다. 상세 상태 규칙은 [05 상태·지형](05_상태이상_지형_환경.md)에서 다룬다.

## 4. 미션 목표의 구성

**[확인]** 일반 기업 섬은 지역 미션 4회와 HQ 전투로 구성된다. 목표 보상은 평판·전력·코어로 나뉘며, 타임 포드처럼 미션 중 추가되는 목표도 있다. [P10]

**[분석]** 목표는 전투 규칙에 예외를 계속 추가하기보다 기존 동사를 새로운 대상에 적용하게 한다. 보호, 파괴, 특정 횟수 수행, 특정 상태 유지라는 적은 수의 조건으로 다양한 전투를 만들 수 있다.

| 목표 계열 | 표현 예 | 플레이어에게 요구하는 판단 |
| --- | --- | --- |
| 생존 보호 | 발전 시설·열차·위성 보호 | 공격 방향과 아군 피해 관리 |
| 대상 파괴 | 댐·산·특정 기계 제거 | 방어 행동과 별도 공격 행동 배분 |
| 상태 달성 | 로봇 동결 후 보전 | 죽이지 않고 무력화 |
| 누적 행동 | 스폰 차단·정해진 적 처치 | 턴 수와 적 수 관리 |
| 피해 제한 | 기체 피해 제한 | 자해 무기의 기회비용 평가 |
| 회수 | 타임 포드 보호·획득 | 보상 지점으로 접근할 비용 |
| 종료 시 유지 | 특정 대상이 남아 있어야 함 | 마지막 턴의 순서 검토 |

표의 계열화는 **[분석]**이며 원작의 내부 목표 클래스 목록을 뜻하지 않는다. 실제 대표 목표의 예는 Archive의 댐·위성[P12], Pinnacle의 동결 로봇[P14] 자료로 확인할 수 있다.

## 5. 목표 판정의 시간

**[제안]** 목표는 “현재 성공처럼 보이는 상태”와 “보상 확정”을 구분한다.

| 평가 방식 | 적합한 목표 | 상태 변경 규칙 |
| --- | --- | --- |
| 누적 카운터 | 처치·스폰 차단 | 적격 이벤트만 합산 |
| 즉시 실패 | 보호 대상 파괴 | 해당 조건을 되돌릴 수 없을 때 확정 |
| 종료 시 스냅샷 | 생존·동결 유지 | 최종 정산 순간의 상태 평가 |
| 시간 제한 성공 | 지정 턴의 발사·행동 | 행동 실행과 중단 사유를 기록 |
| 복합 조건 | 여러 대상 보호 | 부분 보상과 전체 성공을 분리 |

### 5.1 예시: 두 보호 대상

**[분석·가상 모델]** A와 B를 각각 지키면 평판 1을 얻는 목표가 있다고 하자. A가 파괴되고 B가 살아 있다면 평판은 일부 획득할 수 있어도 목표 전체를 완벽하게 수행한 상태는 아니다. 화면에 `1/2`를 보이는 것과 섬 완벽 보상 자격을 표시하는 것은 다른 UI다.

### 5.2 예시: 피해 제한 목표

**[제안]** “받은 총 피해”와 “종료 시 누적된 손상”은 서로 다른 조건으로 정의한다. 수리 후 값이 낮아지는 목표인지, 한 번이라도 맞으면 기록되는 도전인지 문구와 내부 카운터를 맞춘다. 원작의 개별 업적과 미션 문구를 한 규칙으로 합치지 않는다.

## 6. 타임 포드는 새로운 제약을 추가한다

**[확인]** 포드는 아군으로 회수하거나 전투 종료까지 보전해 획득할 수 있다. 공격을 받거나 Vek가 포드 타일을 점유하면 파괴 위험이 있다. 포드는 코어와 추가 보상 가능성을 제공한다. [P11]

**[분석]** 갑자기 보상이 생기면 기존의 최선 이동 경로가 달라진다. 공격을 막는 데 충분했던 3개의 행동 중 하나를 이동·회수에 쓰면 방어 여유가 줄어든다. 포드 자체의 보상과 섬 완벽 완료 자격을 함께 고려해야 한다.

**[제안]** 포드 목표는 `Spawned → Exposed → Collected/Destroyed/RecoveredAtEnd` 상태로 표현한다. 이미 회수한 포드를 나중의 지형 변화로 다시 파괴하지 않도록 전장 오브젝트와 보상 소유권을 분리한다.

## 7. 임무 종료·패배·완벽 완료

| 결과 | 처리 원칙 | 근거 상태 |
| --- | --- | --- |
| 정해진 전투 종료 | 남은 적이 있어도 미션 정산 가능 | 공개 플레이 구조 |
| 보너스 목표 일부 실패 | 해당 보상·완벽 완료 자격에 영향 | P10 |
| 일반 미션에서 메크 전부 비활성 | 지역 패배로 종료되고 런은 계속될 수 있음 | P10 및 P26 사용자 보고 |
| 전력망 0 | 런 종료 | P08 |
| 섬 모든 보너스 목표 달성 | 완벽 완료 보상 선택 | P10 |
| 최종전 폭탄 손실 | 즉시 런 종료로 취급하지 않음 | [11 최종전](11_아일랜드_캠페인_최종전.md) |

**[미확인]** 전 메크 비활성의 정확한 검사 시점, 이미 완료한 목표의 취소 범위, HQ에서의 차이는 추가 실행 확인이 필요하다. 따라서 “메크 전멸 = 모든 모드의 즉시 게임오버”라는 범용 규칙을 구현하지 않는다.

**[분석]** 일반 건물 무피해와 모든 목표 달성은 서로 다른 숙련 기준이다. 한쪽을 위해 다른 쪽을 포기할 수 있게 하는 것이 이 게임의 의사결정 범위를 넓힌다.

## 8. 재구현 목표 데이터

```yaml
# 제안: 원작 데이터 포맷이 아님
objective:
  id: protect_two_assets
  category: protect
  targets: [asset_a, asset_b]
  evaluation: mission_end
  progress_mode: surviving_targets
  target_count: 2
  reward_per_target:
    reputation: 1
  required_for_perfect_island: true
  permanent_failure_events: [target_destroyed]
  display_key: objective.protect_two_assets
```

**[제안]** 실제 제작 데이터에는 적격 태그와 제외 태그도 둔다. 소형 소환체를 처치 수에 넣는지 같은 판정은 콘텐츠 패치로 바뀔 수 있다. 패치 이력과 회귀 검증은 [18 검증](18_검증체크리스트_미확인항목.md)에서 관리한다.

## 9. 보상 선택을 비교하는 방법

**[분석·가상 예시]** 전력이 1이고 남은 미션이 두 개라면 즉시 전력 +1 보상은 상점에서만 쓸 수 있는 평판 +1보다 안전성이 높다. 반대로 이미 충분한 전력을 보유했다면 평판은 코어·무기·전력 중 선택할 수 있어 유연성이 크다.

다음 식은 원작 AI나 실제 점수식이 아니라 보상 설계 검토용이다.

`목표의 기대가치 = 직접 보상 + 완벽 완료 자격의 추가가치 - 실패 위험 - 목표 수행에 쓴 행동의 기회비용`

**[분석]** 마지막 항목이 중요하다. 적을 때리는 행동과 목표 오브젝트를 파괴하는 행동은 같은 메크의 행동권을 쓴다. 보상이 높아도 해당 스쿼드가 방어를 유지하면서 목표를 수행할 수 없다면 실현 가치는 낮다.
