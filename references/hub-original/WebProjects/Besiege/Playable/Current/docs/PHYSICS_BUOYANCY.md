# IRONWOOD 3.0 — 부력·선박 시스템

이 문서는 IRONWOOD의 실제 구현을 설명합니다. Besiege의 내부 알고리즘을 재현했다는 의미는 아닙니다. 기준 소스는 [physics.js](../dist/physics.js)의 `_applyFluidForces()`·`_applyControlTorques()`·`_checkTerminal()`과 [parts.js](../dist/parts.js)의 `float`·`boat` 정의입니다.

## 1. 설계 목적

같은 격자 조립 규칙으로 지상 차량을 선박으로 바꿀 수 있게 합니다. 부유체가 충분하면 떠오르고, 무게·부력의 배치가 나쁘면 기울어지며, 추진기 방향이 잘못되면 원하는 방향으로 움직이지 않아야 합니다. 선박 위치를 수면에 고정하거나 기체 전체를 하나의 강체로 대체하지 않습니다.

## 2. 수상 환경

| 항목 | 값 |
| --- | ---: |
| 해협 항로 수면 Y | 0.45m |
| 해저 평면 Y | -5m |
| 중력 | 9.82m/s² |
| 물리 시간 간격 | 1/120초 |
| 부유체 1개의 질량 | 0.7kg |
| 부유체 1개의 HP / 자재 | 65 / 3 |
| 완전히 잠긴 온전한 부유체의 최대 부력 | 35N |

수면은 일정한 높이의 평면입니다. 해저는 실제 충돌 평면이고 강둑은 별도 고정 강체입니다. 부유체를 받치는 보이지 않는 바닥은 수면에 두지 않습니다. 렌더링 수면과 물리 수면은 공유된 mission layout을 사용합니다.

## 3. 침수율

부품의 로컬 축을 월드 축으로 변환하고 월드 Y 방향의 수직 반경 `h`를 근사합니다. 부유체는 로컬 Y 반경 0.42, 나머지 축은 0.46을 사용합니다. 최소 반경은 0.08입니다.

```text
h = max(0.08,
        abs(localUp.y) * halfY
      + abs(localRight.y) * 0.46
      + abs(localForward.y) * 0.46)

s = clamp((waterY - centerY + h) / (2*h), 0, 1)
```

이는 회전된 상자의 실제 침수 부피를 잘라 적분한 결과가 아닙니다. 물에 잠긴 높이 비율을 사용하여 계산량을 제한합니다. 기체가 기울어지면 각 부품의 수직 반경과 침수율이 달라집니다.

## 4. 부력과 항력

살아 있는 부유체에는 월드 +Y 방향으로 `F = 35*s`를 가합니다. 힘은 부유체 강체의 질량중심에 작용합니다. 서로 떨어진 부유체의 힘이 연결부를 통해 전달되어 기체 전체에 회전 효과를 만듭니다. 부유체 내부에서 별도의 부력 중심을 계산하지는 않습니다.

물에 잠긴 모든 기체 부품에는 로컬 속도에 따른 방향별 항력을 적용합니다. 아래 값은 각 로컬 축의 힘이며 마지막에 월드 좌표로 변환합니다.

| 축 | 항력 |
| --- | --- |
| 좌우 X | `-vx * (1.4 + 2.4*abs(vx)) * s` |
| 수직 Y | `-vy * (8 + 3*abs(vy)) * s` |
| 전후 Z | `-vz * (0.18 + 0.16*abs(vz)) * s` |

각 성분은 ±600N으로 제한합니다. 좌우 미끄러짐과 상하 진동은 강하게, 전후 이동은 상대적으로 약하게 감쇠합니다. 회전에는 `-0.7*s*angularVelocity`의 감쇠 토크를 추가합니다. HP 0인 부품도 물속 항력은 받습니다.

## 5. 추진과 조타

프로펠러는 자신의 로컬 -Z 방향으로 힘을 냅니다. 물 환경에서 기본 추력은 `55 * power * throttle` N입니다. `power`는 0.3~2.0, 정규화된 `throttle`은 -1~1입니다. W/S는 목표 추진량을 정하고 실제 추진량은 초당 1.8씩 변화합니다. 브레이크·파괴·코어 연결 단절 시에는 즉시 0으로 만듭니다.

프로펠러를 왼쪽·오른쪽 분배로 지정하면 A/D 조타 명령을 추진량에 더합니다. 공통 분배는 양쪽 조타에 대한 추력 차이를 만들지 않습니다. 수상 기체에 연결된 부유체가 2개 이상이면 별도의 유한한 yaw 제어 토크도 사용합니다. 이 조타는 실제 유체에 잠긴 방향타를 해석한 모델은 아닙니다.

자세 보조를 켜면 피치·롤을 수평으로 돌리려는 제한된 토크를 코어에 가합니다. 끄면 복원 목표 대신 회전 감쇠를 사용합니다. 실제 부력과 질량 배치는 어느 경우에도 유지되므로 부유체 수가 부족한 기체를 보조 기능만으로 띄우지는 못합니다.

## 6. 파손 규칙

| 상태 | 부력 | 항력 | 추진·조타 제어 |
| --- | --- | --- | --- |
| 살아 있고 코어에 연결됨 | 부유체에 적용 | 적용 | 조건을 만족하면 적용 |
| 살아 있으나 연결이 끊김 | 부유체에 계속 적용 | 적용 | 끊긴 추진기는 정지 |
| HP 0 | 부력 없음 | 적용 | 없음 |

구조 파단과 부품 HP 파괴는 다릅니다. 부유체가 떨어져도 자체로 떠 있을 수 있지만, 기체가 그 부력을 더 이상 전달받지는 못합니다. 부유체가 파괴되면 해당 부품의 부력 자체가 사라집니다.

## 7. 기본 선박

`boat`는 19부품, 질량 18.5kg, 자재 47입니다. 부유체 10개를 X=-2와 X=+2에 각각 5개씩 배치하고 목재 연결부로 묶습니다. 코어는 부유체보다 한 격자 높으며 추진기는 뒤쪽 낮은 위치에 있습니다.

온전한 부유체의 최대 부력 합은 350N입니다. 실제 중량은 약 181.7N이므로 모든 부유체가 완전히 잠기기 전에 정적 균형을 만들 수 있습니다. 이 합산은 단순 부력 여유를 설명하며 회전 안정성이나 동적 파손까지 보증하지 않습니다. 좌우·앞뒤 간격과 무게중심 높이도 함께 중요합니다.

## 8. 침수 실패

코어 중심이 수면보다 0.8m 아래에 있는 시간이 **연속 1.5초**에 도달하면 실패합니다. 그보다 위로 올라오면 누적 시간을 0으로 되돌립니다. 한 번 잠깐 물에 닿은 것만으로 실패하지 않습니다.

HUD 침수율은 경고용 표시이며 종료 판정은 위의 코어 중심·연속 시간 조건을 사용합니다. 같은 스텝에 마지막 관문과 실패 조건을 만족하면 실패가 우선입니다.

## 9. 구현 한계와 검증

이 모델에는 파도, 수면 변형, 선체 내부 침수, 압력 중심 적분, 캐비테이션, 물·공기 혼합 추진 효율은 없습니다. 물의 종류에 따른 밀도 변화도 사용하지 않습니다. 수상 감각과 구조 설계 차이를 만드는 게임용 근사입니다.

온전한 선박의 부양·완주, 부유체 제거 시 침수, 분리 부유체의 부력 유지, 파괴된 부유체의 부력 소실, 추진 방향·역추진·브레이크·연결 단절을 실제 물리 엔진으로 검사합니다. 결과와 실행 명령은 [VALIDATION.md](../VALIDATION.md)에 정리합니다.
