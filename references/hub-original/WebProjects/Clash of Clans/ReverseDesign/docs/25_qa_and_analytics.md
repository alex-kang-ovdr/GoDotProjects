# 25. 검증 시나리오·측정 설계·밸런스 지표

> **[제안]** 이 문서는 원작의 실제 QA 문서나 운영 대시보드가 아니다. 역기획 규칙을 재구현할 때 필요한 검증 계약과 측정 모델이다. 실제 계정 플레이·전투 표본 수집은 이번 조사에서 수행하지 않았다.

## 1. 검증을 세 층으로 나누는 이유

| 층 | 질문 | 대표 실패 |
|---|---|---|
| 규칙 정확성 | 명세대로 작동하는가? | 마법 중첩·별 계산·공격권 소비 오류 |
| 상태 일관성 | 모든 화면과 서버 결과가 같은 사실을 보는가? | 중복 보상·다른 방어 배치·완료 타이머 불일치 |
| 경험과 밸런스 | 정상 작동해도 재미·공정성에 문제가 없는가? | 단일 조합 독점·과도한 의무 공격·성장 병목 |

세 층을 혼합하면 구현 오류를 밸런스 조정으로 가리거나, 특정 집단만 어려운 문제를 평균 성적으로 놓치게 된다. 예를 들어 강한 유닛의 성공률이 높아도 그 유닛만 사망 이벤트가 누락되는 버그인지, 고수들이 주로 선택하는 것인지부터 구분해야 한다.

**[제안]** 임의로 큰 기지 하나를 만드는 대신 목적이 분명한 최소 기지를 준비한다.

| 데이터 세트 | 구성 | 검증 목적 |
|---|---|---|
| 빈 경로 | 병력 1개·건물 1개 | 이동속도·사거리·첫 공격 시점 |
| 선택 갈림길 | 거리·종류가 다른 목표 2~3개 | 타깃 선택과 재선정 |
| 장벽 구획 | 입구 유무·파괴 가능한 벽 | 경로·공격 선택·막힘 탈출 |
| 동시 사망 | 같은 tick에 여러 객체 HP 0 | 소환·폭발·전리품·별의 순서 |
| 효과 중첩 | 강화·치유·독·무적 조합 | 효과 우선순위와 해제 |

| 공동 목표 | 공격 2개·클랜전 또는 수도 | 최고 기록과 누적 피해의 차이 |
| 버전 전환 | 동일 배치·입력·패치 전후 규칙 | 리플레이 및 마이그레이션 |

목표 선택의 정확한 내부 우선순위처럼 미확인인 항목은 “공식 동일성 테스트”가 아니라 선택한 제안 모델의 일관성 테스트로 표시한다.

## 6. 분석 이벤트 스키마

```text
EventEnvelope
  eventId, playerId, sessionId?, occurredAtUtc
  schemaVersion, contentVersion, ruleVersion
  mode, townHallLevel, leagueId?, experimentCohort?
  causeId, payload
```

| 이벤트 | 핵심 속성 | 분석 질문 |
|---|---|---|
| `battle_started` | 편성 해시·상대 성장·모드·배치 버전 | 어떤 조건의 전투가 시작되었는가? |

| `upgrade_started` | 대상·비용·기간·가속·선행 상태 | 무엇이 성장의 우선순위인가? |
| `upgrade_completed` | 실제 완료·확인 시점·다음 작업 | 장인 유휴가 얼마나 생기는가? |
| `wallet_changed` | 화폐·변화량·원인·잔고 | 재화가 어디서 생겨 어디에 쓰이는가? |
| `army_changed` | 이전/새 구성·변경 이유 | 편성 다양성이 실제 전투로 이어지는가? |

`battle_started`만으로 시도 횟수를 계산하면 중복 이벤트가 분모를 부풀린다. `battleId` 기준 중복 제거와 최종 상태를 결합해야 한다. 미완료·서버 실패·정상 0별 패배도 서로 다른 종료 원인으로 보관한다.

## 7. 전투 밸런스 지표

### 7.1 기본 성과

```text
3별률 = 3별로 끝난 유효 공격 / 전체 유효 공격
시간 초과 비율 = 시간 초과로 종료한 공격 / 전체 유효 공격
조합 선택률 = 해당 조합 사용 공격 / 비교 가능한 공격
잔여시간 분포 = 완파 공격에 한정한 (제한시간 - 사용시간)
```

전투 모드, 공격·방어 TH, 영웅·장비 성장, 리그 보정, 기지 버전, 플레이어 숙련을 가능한 범위에서 나눈다. 장인 기지의 6별 결과를 본 마을의 3별률과 합산하지 않는다.

[확인] Supercell의 2026년 10월 밸런스 설명 역시 분석 대상을 TH18 대 TH18의 전쟁·CWL 최근 4주로 한정했다. 이는 표본 범위를 명시해야 한다는 좋은 사례이며, 그 표본의 성공률을 전체 유저에게 일반화하지 않는다. [공식 밸런스 설명](https://supercell.com/en/games/clashofclans/blog/news/balance-changes-incoming-october-2026/)

### 7.2 조합 다양성

군대 전체가 조금씩 다르면 매번 별도 조합으로 계산하는 것은 의미가 없다. 핵심 딜러·진입 수단·영웅 역할 등 기준을 먼저 정해 `strategyFamily`를 분류한다. 분류 규칙이 바뀌면 과거 추세와 비교할 수 없으므로 버전을 둔다.

```text
조합 집중도 HHI = Σ (조합 계열별 점유율)^2
```

HHI 상승이 항상 나쁜 것은 아니다. 새 기능 학습기에는 일시적으로 인기 조합이 집중될 수 있다. 장기 독점과 짧은 이벤트 실험을 구분한다.

### 7.3 방어의 대응 가능성

특정 공격을 막기 위해 다른 모든 공격에 취약해지는가? 함정 위치와 핵심 건물 배치가 실제로 결과를 바꾸는가? 방어 배치 수정을 반복해도 성과가 전혀 바뀌지 않으면 방어 선택의 가치가 약해질 수 있다. 유사 계정·유사 공격을 대상으로 배치 변경 전후를 비교한다.

## 8. 경제·성장 지표

| 지표 | 정의 | 해석 주의 |
|---|---|---|
| 자원 순생성 | 생성량 - 시스템 소각량 | 사용자 간 이전을 신규 생성으로 세지 않음 |
| 장인 가동률 | 작업한 장인시간 / 보유 가능 장인시간 | 접속 불가·고의 비축·완료 대기 구분 |
| 성장 병목 | 자원·장인·선행조건 때문에 지연된 시간 | 가장 부족한 한 요소만 원인으로 단정하지 않음 |
| 창고 초과 손실 | 저장 불가로 소멸한 보상 / 제시 보상 | 초과 지급 허용 보상은 별도 |
| 전략 해금 지연 | 목표 선택부터 사용 가능까지 | 해금했지만 연구·영웅 때문에 실사용 불가할 수 있음 |
| 전용 재화 편중 | 획득원·소비처별 비중 | 특정 모드 강제 참여 여부 확인 |

`성장에 필요한 총비용 / 평균 시간당 약탈`만으로 완료 시간을 예측하면 장인·연구 병렬성, 영웅 출전 제한, 보상 주기, 창고 상한을 놓친다. [03 성장](03_progression_research_and_unlocks.md)의 선행 그래프와 함께 계산한다.

## 9. 참여·소셜 지표

주간 참가 여부, 실제 공격 참여, 공격 소진, 다음 주 재참가는 각각 다른 단계다. 자동 등록 때문에 참가자 수만 높아질 수 있다. 클랜 기여도는 지원 수량·전쟁 별·수도 파괴·클랜게임 점수를 무작정 한 점수로 합치지 말고 활동별 분포와 연속 참여를 본다.

클랜의 소수 인원에게 기여가 집중된다면 그 구성원의 피로와 나머지 구성원의 참여 장벽을 구분해야 한다. 해결책은 단순한 보상 증액이 아니라 쉬운 기여 경로·명확한 역할·실패 후 회복 경로일 수 있다.

## 10. 밸런스 변경의 검증 절차

1. 해결할 문제와 대상 집단을 한 문장으로 정의한다.
2. 버그·콘텐츠 성능·사용자 구성 변화 중 원인을 분리한다.
3. 변경할 매개변수와 영향받을 조합·모드를 기록한다.
4. 핵심 결과 지표와 부작용 지표를 변경 전에 정한다.
5. 콘텐츠 버전·이벤트·리그 보정을 고정하거나 층화해 비교한다.
6. 표본 수와 불확실성을 함께 보고 유지·추가 관찰·재조정 중 하나를 선택한다.

예를 들어 성공률이 50%에서 55%로 올라도 표본이 20회라면 우연 변동일 수 있다. 동일 플레이어가 반복한 공격은 독립 표본으로 단순 계산할 수 없으므로 계정·클랜 단위의 의존성도 고려한다. 관찰 데이터만으로 특정 장비가 성공률 상승의 유일한 원인이라고 결론내리지 않는다.

## 11. 미확인 규칙을 검증하는 실험 목록

| 항목 | 최소 실험 | 관찰해야 할 결과 |
|---|---|---|
| AI 동률 목표 | 동일 조건 목표 2개 배치, 방향·생성 순서 변경 | 선택 안정성·우선순위 |
| 보호막 30% | 화폐 구성과 약탈 비율 통제 | 발급 조건과 반올림 |
| 랭크 배치 잠금 | 그룹 편성 전후·전투 시작 전후 수정 | 실제 방어 리플레이의 배치 |
| 랭크 점수 곡선 | 별별 파괴율 경계 재현 | 정수 점수·절삭 방식 |
| 임시 효과 만료 | 시작 직전/직후 만료 | 전투 스냅샷 유지 범위 |
| 수도 동시 공격 | 같은 구역에 겹치는 참가 요청 | 배정·잠금·진행도 적용 |
| 보상 초과 | 지급처별 저장 용량 경계 | 보관·소멸·초과 적립 정책 |

위 실험은 계획이며 이번 문서에서 실행했다고 주장하지 않는다.
