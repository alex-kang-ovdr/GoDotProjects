## 1. 선택의 목적

승리 보상은 모듈 증설, 탄약, 수리, 정비 자재와 기술 개량에 함께 사용한다. 기술 개량은 새 모듈을 놓을 공간을 쓰지 않고 현재 함선의 발전·인력 이동·추진 성능을 높인다. 다만 막힌 통로, 가려진 사선, 잘못된 추진 방향은 그대로 남는다. 각 개량은 관련 동작의 계수에 적용한다.

기술은 **현재 원정 전체에 적용되는 세 가지 레벨**로 보관한다. 함선 부품을 바꾸거나 다음 구간으로 이동해도 유지하며, 새 원정에서 0으로 초기화한다. 사용자 청사진 목록을 새 원정에 남겨도 이전 기술 레벨이 함께 따라오는 것은 아니다.

기술 창은 **U**, 헤더의 **기술 개량**, 도크의 **기술 개량·정비 보급**, 모바일 메뉴에서 연다. 구매는 도크에서 가능하다.

## 2. 기술 목록과 가격

| ID | UI 이름 | 레벨당 효과 | 1단계 | 2단계 | 3단계 | 3단계까지 합계 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| `reactor` | 원자로 효율 | 발전량 +10% | 350 C | 650 C | 1,000 C | 2,000 C |
| `logistics` | 함내 작업 동선 | 승무원 이동 속도 +8% | 300 C | 550 C | 850 C | 1,700 C |
| `drive` | 추진 제어 개량 | 추력 +10% | 300 C | 550 C | 850 C | 1,700 C |

모두 최대 3단계다. 효과는 기본값에 단계별 비율을 합산한다.

```text
성능 계수 = 1 + 레벨 × 단계당 증가율
```

따라서 3단계 효과는 원자로 +30%, 승무원 이동 +24%, 추력 +30%다. 이전 단계의 결과에 다시 같은 비율을 곱하는 복리 방식은 사용하지 않는다. 세 기술을 모두 최대치로 올리는 구매 합계는 5,400 C다. [가격·계수 구현](../../dist/sim.js)

## 3. 실제 적용 위치와 한계

### 원자로 효율

플레이어 원자로가 매 시뮬레이션 단계에 생성하는 전지량에 계수를 곱한다. 원자로 저장 용량을 늘리거나 장치까지 전지를 자동 전달하지는 않는다. 생산량이 늘어도 승무원 경로와 운반량이 부족하면 소비 장치가 전지를 기다릴 수 있다.

자동 검사에서는 같은 초기 함선에서 승무원 운반을 제거하고 원자로를 비운 뒤 같은 시간 동안 가동한다. 개량한 쪽에 실제 사용 가능한 에너지가 더 많이 쌓이는지 확인한다.

### 함내 작업 동선

승무원의 실제 걷는 속도에 계수를 적용한다. 기존 통로·장비 칸의 속도 차이, 혼잡, 불타는 칸의 이동 제약은 함께 유지한다. 운반 한 번의 적재량이나 픽업·배달 자체의 처리 시간을 기술이 직접 바꾸지는 않는다.

이동은 보급 작업과 현장 정비가 공유하므로 두 작업 모두 도착 시간이 달라질 수 있다. 검사에서는 같은 함선의 첫 전지 배달이 개량 후 더 일찍 끝나는지 확인한다. 경로가 없으면 속도 계수가 높아도 도착할 수 없다.

### 추진 제어 개량

실제 추진기 힘에 계수를 곱한다. 설치 방향·설치 위치·배기 차폐·전지·질량·회전 관성은 기존 규칙을 따른다. 앞으로 힘을 내지 못하는 배치에 전방 추진기를 새로 만들어 주는 효과는 없다.

검사에서는 같은 엔진과 같은 이동 명령을 사용해 개량한 함선의 실제 전진 위치·속도가 더 커지는지 확인한다. UI에 표시한 퍼센트만 바뀌는지를 검사하는 방식은 사용하지 않는다.

이 계수는 플레이어 함선에 적용하며, 적의 성능을 플레이어 구매와 함께 올리지 않는다. [생산·이동·추진 적용 구현](../../dist/sim.js)

## 4. 구매 계약

| API | 결과 |
| --- | --- |
| `getUpgrades()` | id, name, description, level, maxLevel, cost, currentEffect, nextEffect 목록 |
| `purchaseUpgrade(id)` | 현재 단계의 가격을 결제하고 해당 레벨을 1 올림 |
| `game.upgrades` | reactor, logistics, drive의 현재 정수 레벨 |

`cost`는 다음 단계 가격이며 최대 단계에서는 0으로 표시한다. 최대 단계에서 다시 구매를 요청하면 거부한다. 알 수 없는 기술, 자금 부족, 도크가 아닌 상태에서도 구매를 거부한다. 실패한 요청은 크레딧과 레벨을 포함한 게임 상태를 유지한다.

구매는 단계마다 한 번의 결제·레벨 증가로 처리한다. 연속 요청으로 최대 레벨을 넘거나 같은 마지막 단계를 중복 결제하지 않는다. 구매한 기술은 저장 파일에 기록한다. 현재 UI에는 기술 환불·초기화·연구 시간·선행 기술 트리가 없다.

## 5. 정비 자재 구매

정비 자재는 플레이어 함선의 `repairStock`에 보관한다. 새 원정의 플레이어 초기량은 80, 상한은 240이다. 적 함선은 별도의 초기 자재 60으로 생성한다.

| 항목 | 현재 규칙 |
| --- | --- |
| 한 번에 구매하는 최대량 | 80 |
| 단가 | 자재 1당 2 C |
| 공간이 부족할 때 | 남은 공간만큼 부분 구매 |
| 실제 결제 | 구매량 × 2를 올림한 정수 C |
| 현장 수리 효율 | 자재 1당 최대 4 HP |
| 소화 | 자재 소모 없음 |

구매 견적은 다음과 같다.

```text
구매량 = min(80, max(0, 240 - 현재 자재))
가격   = ceil(구매량 × 2)
```

자재가 237.25라면 2.75를 보충하고 6 C를 결제한다. 자재량은 계산 중 소수 정밀도를 유지하며, 화면의 표시 자릿수로 내부 재고를 반올림하지 않는다.

`getStats()`의 `repairSupplyAmount`와 `repairSupplyCost`가 현재 실제 견적이다. `buyRepairSupplies()`는 이 견적으로 결제한다. 가득 찬 경우, 자금이 부족한 경우, 도크 밖에서는 거부한다. 실패 시 재고와 크레딧은 바뀌지 않는다.

## 6. 수리 방식과 예산의 차이

현장 수리는 실제 승무원·경로·시간·자재를 사용한다. 완전히 파괴된 모듈을 다시 만들지 못하며, 먼저 불을 끄고 살아 있는 부품을 수리한다. 전체 수리와 귀환 시의 설계 복구는 별도의 도크 정산으로 수행한다. 도크 복구로 HP와 승무원을 회복해도 정비 자재는 자동 충전하지 않는다.

자재를 정수 단가로 충분히 구매해 사용한다면 현장 회복의 자재비는 HP당 0.5 C다. 작은 부분 묶음의 마지막 구매에는 올림 때문에 차이가 생긴다. 이 값에는 승무원을 보급에서 빼는 비용이나 도착 시간을 화폐로 환산해 포함하지 않는다.

기본 850 C로 세 기술의 첫 단계를 모두 구매하려면 필요한 950 C가 부족하다. 예를 들어 원자로 1단계와 동선 1단계에 650 C를 쓰면 200 C가 남는다. 여기서 자재 80을 160 C에 구매하면 모듈 증설에 쓸 잔액은 40 C다. 생산·물류 개량과 즉시 화력 증설을 같은 자금으로 선택하게 된다.

자동 완주 검사에서는 기술을 무료로 제공하지 않으며, 세 기술이 모두 0인 상태로 순찰 세 구간을 완료한다. 실제 승리 보상으로 두 차례 각 1,940 C 증설과 탄약을 구매하고 구간 사이 저장도 복원한다. 이 경로는 기술 구매가 캠페인 진행을 위해 반드시 필요한 세금처럼 작동하지 않는지 확인하는 기준이다. 다른 설계와 작전의 승률 전체를 대표하지는 않는다.

## 7. 저장·조립 경계

`upgrades`와 `repairStock`은 원정 저장에 포함한다. v1·v2 파일에 새 상태가 없으면 기술 0과 정비 초기값으로 이관한다. 청사진은 모듈의 종류·위치·방향을 저장하는 별도 형식이므로, 그 파일 자체에 원정의 개량 구매 내역을 복제하지 않는다.

기술·자재를 구매하거나 정비로 HP·fire 상태가 바뀐 뒤에 오래된 조립 이력을 적용해 결제나 작업 결과를 되돌리지 않도록 편집 경계를 관리한다. 원정을 새로 시작하면 기술은 0, 플레이어 정비 자재는 80으로 초기화하며, 저장한 사용자 청사진 목록은 앱에서 유지한다.

## 8. 검증 범위

검사는 각 기술의 실제 가격 결제와 최대 단계, 자금 부족·잘못된 ID·전투 중 구매의 원자적 거부, 구매 내역의 저장·새 원정 초기화, 발전량·배달 시간·전진 속도의 실제 차이를 확인한다. 자재의 정상 묶음·소수 부분 묶음·상한·빈 지갑·전투 중 구매도 검사한다.

기술은 함선 전체에 적용되는 단순한 세 계수다. 개별 모듈별 장착 개량, 연구 재료, 진영 해금, 기술 교환·판매는 현재 구현하지 않았다. 가격과 효과는 현재 세 구간 프로토타입의 튜닝 값이다.
