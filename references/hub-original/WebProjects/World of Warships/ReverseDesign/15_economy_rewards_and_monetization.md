# 15. 경제·전투 보상·재화·수익화

> 범위: 전투 행동이 성장·소비로 연결되는 구조와 공개된 계산 방식.
> 현재 상점 구매 조언이나 모든 상품의 가격표가 아니라, 경제 시스템의 역기획이다.

[전체 목차](README.md) · [성장·함장](14_progression_commanders_and_builds.md) · [이벤트](17_missions_events_and_liveops.md)

## 1. 경제가 전투에 주는 목적

[분석] 전투 승패가 짧은 목표라면 경제는 패배한 전투에서도 다음 행동을 남긴다. 같은 함선으로 반복 플레이할 이유, 다른 계통을 시작할 이유, 장기 수집 목표, 특정 모드를 다시 방문할 이유를 각각 다른 재화와 진척으로 제공한다.

경제를 다음 네 층으로 구분한다.

1. **행동 평가**: 전투 기여로 기본 보상을 계산한다.
2. **성장 가속**: 프리미엄 계정·보너스로 획득량을 조절한다.
3. **자원 소모**: 구매·연구·정비·소모성 아이템을 통해 회수한다.
4. **목표 분리**: 석탄·강철·연구 점수·이벤트 재화로 서로 다른 장기 경로를 만든다.

## 2. 재화별 기능 계약

[확인] 크레딧, 더블룬, 여러 종류의 경험치, 자원은 용도가 구분된다. 프리미엄 계정은 보상 획득을 가속하며 함선의 전투 제원 자체를 올리는 효과와는 다르다. [R09]

| 자원 | 주된 기능 | 저장 범위의 설계 해석 | 혼동을 막아야 할 점 |
|---|---|---|---|
| 크레딧 | 함선·모듈·강화·정비 등 | 계정 공용 지갑 | 총 수입과 순이익 구분 |
| 함선 경험치 | 해당 함선의 연구 진행 | 함선별 잔고 | 다른 함선에 자동 자유 이동하지 않음 |
| 자유 경험치 | 연구 경로 보조 | 계정 공용 성장 자원 | 함선 XP 보너스와 별도 계산 |
| 함장 경험치 | 함장 성장 | 함장별 진척 | 함선 티어와 별개 |
| 정예 함장 경험치 | 함장 성장·재훈련 등 보조 | 계정 공용 함장 자원 | 일반 함선 XP와 다른 통화 |
| 더블룬 | 프리미엄 기능·상품·전환 | 계정 프리미엄 지갑 | 실제 지역별 현금 가격은 별도 |
| 석탄·강철 | 특정 장기 교환품 | 각기 다른 계정 자원 | 모든 자원을 하나의 골드로 합치지 않음 |
| 연구 점수 | 연구처 보상 경로 | 별도 장기 자원 | 계통 리셋의 재플레이 비용 수반 |
| 이벤트 토큰 | 행사별 교환 | 이벤트 네임스페이스 | 유효 기간·환전 정책 확인 필요 |

구체적인 연구·재훈련 조건은 [14번](14_progression_commanders_and_builds.md)이 담당한다. 상품별 교환 가능 여부와 전환 비율은 최신 상품 설정으로 검증해야 한다.

## 3. 전투 기여 → 기본 보상

[확인] 기본 XP·크레딧의 완전한 내부 함수는 공개되지 않았다. 피해, 탐지 지원, 목표 기여 등 여러 활동이 보상에 관여하며, 피해 보상은 단순 원시 피해량보다 대상 HP에서 제거한 비율을 고려한다. [R10][R12]

| 전투 행동 | 기획상 목적에 대한 분석 | 단독 최적화의 위험 |
|---|---|---|
| 직접 피해 | 적 전력을 줄이는 행동 보상 | 회복 가능한 큰 함선만 공격 |
| 적 격침 | 전력 제거의 완료 보상 | 마지막 일격만 추구 |
| 정찰·탐지 지원 | 직접 포격 외 역할 보상 | 의미 없는 장기 노출 |
| 점령·방어 | 승리 조건 수행 보상 | 안전한 거점만 반복 점령 |
| 항공기 피해 등 | 방어·지원 역할 인정 | 위협 없는 대상만 처리 |
| 잠재 피해 | 위험 부담의 일부 인정 | 승리 기여 없는 피격 유도 |

위 표의 목적과 위험은 분석이며, 각 행동의 현행 보상 계수는 아니다.

### 3.1 HP 비율 예제

설명용 가정: 같은 티어의 A는 최대 HP 20,000, B는 80,000이다.

- A에 10,000 피해: 최대 HP의 50%.
- B에 20,000 피해: 최대 HP의 25%.

후자가 표시 피해량은 두 배지만, 피해 비율은 전자가 두 배다. 실제 보상에는 상대 티어와 다른 행동·보정이 들어갈 수 있으므로 이 예제만으로 최종 XP를 계산하지 않는다.

## 4. 기본·총획득·순이익을 분리

```text
기본 크레딧 = 전투 기여 평가 결과
총획득 크레딧 = 기본 크레딧에 계정·보너스 적용 + 별도 지급
순 크레딧 = 총획득 크레딧 - 정비·탄약·재보급 등 지출
```

[확인] 기본 획득, 보너스 후 총획득, 비용 공제 후 순획득은 다른 값이다. 임무의 '획득 크레딧'을 순이익으로 바꾸어 집계하면 의미가 달라진다. [R10][R11]

[분석] 세금처럼 보이는 지출 숫자를 숨기기보다, 전투 결과에서 어떤 선택이 비용을 발생시켰는지 드러내야 한다. 이를 통해 고티어 플레이의 유지 비용과 경제용 함선의 역할이 이해된다.

## 5. 공개 계산식의 구조

[확인] 공개 위키의 경제 계산 설명은 다음처럼 **기본량 × 계정 배율 × 합산 보너스 + 별도 지급**의 구조를 제시한다. 아래는 기호를 다시 정리한 것이다. [R11]

```text
CreditsGross = BaseCredits × AccountCredit × (1 + SumCreditBonuses) + DirectCredits
ShipXP       = BaseXP      × AccountXP     × (1 + SumShipXPBonuses) + DirectShipXP
CommanderXP  = BaseXP      × AccountXP     × (1 + SumCommanderXPBonuses) + DirectCXP
FreeXP       = BaseXP × 0.10 × AccountXP   × (1 + SumFreeXPBonuses) + DirectFXP
```

- 일반 계정 배율은 1.
- Warships Premium의 공개 설명은 XP 계열 1.65, 크레딧 1.5다.
- 함선 XP 증가 보너스를 자유 XP 식에 다시 곱하지 않는다.
- Base XP는 프리미엄·소모 보너스 후 표시 XP와 구별한다.
- 특정 이벤트·함선·모드의 추가 처리와 실제 반올림은 별도 확인한다.

오래된 경제 설명의 보너스 최대 범위는 15.7의 새 등급을 포함하지 않을 수 있다. **계산 구조**와 **현재 선택 가능한 보너스 목록**을 분리해야 한다.

### 5.1 자체 계산 예제

가정 입력: 기본 크레딧 100,000, 기본 XP 1,000, Warships Premium, 크레딧 +40%, 함선 XP +200%, 함장 XP +100%, 자유 XP +600%. 영구 보너스·첫 승·임무 추가 지급·기타 보정은 전부 0이라고 가정한다.

| 결과 | 계산 | 값 |
|---|---|---|
| 총 크레딧 | 100,000 × 1.5 × 1.4 | 210,000 |
| 함선 XP | 1,000 × 1.65 × 3 | 4,950 |
| 함장 XP | 1,000 × 1.65 × 2 | 3,300 |
| 자유 XP | 1,000 × 0.10 × 1.65 × 7 | 1,155 |
| 순 크레딧 | 비용을 90,000으로 가정 | 120,000 |

이 예시는 계산 구조를 보여 주며 실제 특정 함선·전투의 예상 수입이 아니다.

## 6. 보너스와 외형의 분리

[확인] 0.11.6 경제 개편에서 위장 외형과 경제 보너스가 분리되었다. 소모성 경제 보너스는 자원 유형별로 선택하고 영구 보너스와 조합하는 구조다. [R13][R24]

[분석] 외형 취향과 수입 최적화를 분리하면 '좋아하는 위장을 포기해야 하는 비용'이 줄어든다. 반면 보너스 재고·자동 재보급·무료 획득을 이해해야 하는 새 UI 복잡성이 생긴다.

### 6.1 15.7 이후 등급표

[확인·버전 의존] 아래는 15.7 변경과 현재 위키를 대조한 소모성 경제 보너스다. 수치는 **추가 비율**이다. [R13][R14]

| 등급 | 크레딧 | 함선 XP | 함장 XP | 자유 XP |
|---|---:|---:|---:|---:|
| Common | +20% | +100% | +100% | +300% |
| Uncommon | +40% | +200% | +200% | +600% |
| Rare | +160% | +800% | +800% | +2,400% |
| Epic | +320% | +1,600% | +1,600% | +4,800% |
| Legendary | +480% | +2,400% | +2,400% | +7,200% |

15.7에서 Legendary가 추가되고 Epic 자유 XP 보너스가 조정되었다. 과거의 네 등급·Epic 자유 XP +7,200%를 현재 표에 그대로 넣지 않는다.

## 7. 수익화 구성의 역기획

| 수단 | 판매하는 가치 | 전투와의 접점 | 확인해야 할 설정 |
|---|---|---|---|
| 프리미엄 계정 | 시간당 성장 효율 | 보상 배율 | 기간·적용 시작·중첩 |
| 프리미엄 함선 | 특정 플레이 경험·수집·경제 | 고유 성능·함장 운용 | 함선별 경제 특성과 상품 내용 |
| 특별 함선 | 별도 획득 경로의 전투 콘텐츠 | 고유 제원·구성 | 프리미엄과 같은 수입 배율로 간주 금지 |
| 이벤트 패스 | 행사 진행 보상 확대 | 임무→레벨→보상 | 무료/추가 경로·가격·조건 |
| 조선소 | 단계적 함선 획득 | 장기 임무와 유료 단계 | 무료 완료 가능 단계·필수 구매 |
| 외형·음성·효과 | 표현·수집 | 전투 식별·감각 | 표시 옵션·적용 대상 |
| 컨테이너 | 확률형 보상 | 수집·자원 | 개별 확률표·보장·중복 처리 |
| 편의·전환 | 진행 마찰 감소 | 재훈련·전환 등 | 전환비·무료 대안·이벤트 할인 |

표는 여러 상품을 설계 관점에서 분류한 것이다. 상품 소유만으로 승리가 보장된다거나, 모든 유료 콘텐츠가 전투력과 무관하다고 단정하지 않는다. 전투 제원과 경제 혜택, 접근 속도를 각각 평가해야 한다.

## 8. 조선소 사례: 무료 단계와 완성 조건

[확인·종료 사례] Marlborough B 조선소는 2026년 9~11월 사례다. 총 28단계 중 임무로 23단계, 나머지 최소 5단계는 더블룬이 필요했다. 15.10 시작과 함께 종료된 사례이며 현재 구매 가능한 행사로 소개하지 않는다. [R15]

[분석] '함선을 만든다'는 목표에는 두 진행률이 존재한다.

- 플레이로 확보 가능한 최대 진행률.
- 최종 함선 획득에 필요한 전체 진행률.

이 둘을 합쳐 보여 주면 남은 시간과 비용을 사용자가 잘못 예상하기 쉽다. 재현 설계에서는 행사 진입 시점에 두 값을 함께 공개하고, 이미 완료한 단계·구매한 단계·임무 획득 단계를 분리한다.

## 9. 컨테이너: 확률·보장·중복을 분리

[확인·이벤트별] 2026 Black Friday 공식 안내의 함선 그룹 확률은 Premium 12%, 일반 0.4%이며, 해당 그룹의 보장은 각각 15번째와 600번째에 적용되는 구조다. 이 수치를 다른 컨테이너에 일반화하지 않는다. [R16]

컨테이너를 역기획할 때는 최소한 다음 네 단계를 구분해야 한다.

1. 어떤 보상 그룹이 당첨되는가.
2. 그룹 안에서 어느 아이템이 선택되는가.
3. 이미 소유한 아이템을 어떻게 처리하는가.
4. 보장 카운터가 언제 증가·초기화되는가.

공개 위키도 보장 카운터와 중복 처리를 설명한다. 정확한 제외 목록·대체 보상은 개별 상품 설명을 우선한다. [R17]

### 9.1 가정 계산: 보장이 있는 첫 성공까지의 기대 횟수

각 시도 성공 확률이 일정한 `p`, 첫 성공 전 보장이 `H`번째에 발생하고 그 외 상태 변화가 없다고 가정한다.

```text
E[N] = Σ(k=0..H-1) (1-p)^k
     = (1 - (1-p)^H) / p
```

`p=0.12`, `H=15`이면 약 **7.11회**다. 이것은 **첫 함선 그룹 성공**까지의 제한된 모형이다. 특정 원하는 함선까지의 기대 횟수, 실제 구매 가치, 소유 함선에 따른 보상 재분배를 계산한 값이 아니다.

## 10. 제안 데이터와 정산 경계

```yaml
BattleRewardInput:
  battle_id: id
  ruleset_version: id
  participant_id: id
  contribution_summary: typed_metrics
  ship_economy_profile: data_id
  equipped_bonus_snapshot: data_ids
  premium_snapshot: entitlement_at_defined_time

LedgerEntry:
  transaction_id: unique_id
  account_id: id
  resource_type: enum
  delta: integer
  reason: battle_or_purchase_or_conversion
  source_id: battle_or_offer_id
  created_at: server_time
```

[제안] 전투 완료 이벤트는 한 번만 확정하고, 지갑 기록·보너스 소모·임무 진행에 같은 원인 ID를 전달한다. 통신 재시도 때문에 크레딧은 두 번 지급되고 보너스는 한 번만 소모되는 식의 비대칭을 방지한다.
