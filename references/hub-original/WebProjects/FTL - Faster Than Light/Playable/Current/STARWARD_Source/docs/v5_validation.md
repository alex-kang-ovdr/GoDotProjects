# STARWARD v5 — 레이아웃 상태·이전 저장·검증

이 문서는 v5의 저장 구조와 테스트 근거를 설명합니다. 기존 장비·회수품·전술·스키마 검사는 [v4 검증 명세](v4_validation.md)를 유지합니다. 신규 규칙의 코드 근거는 [engine.js](../dist/engine.js), 정규 데이터는 [data.js](../dist/data.js), 실행 검증은 `tests/`입니다.

## 1. 새 상태와 정규 기하

저장 버전은 `5`이며 플레이어와 존재하는 적 함선 각각에 명시적 `layoutId`를 저장합니다. 여섯 방의 ID는 유지합니다. 문 상태·방의 산소·화재·균열·승무원 좌표·경로·장비·회수품은 기존 JSON 상태 안에 남습니다.

```js
{
  version: 5,
  player: { layoutId: 'atlas', rooms: [/* 실제 상태 */], doors: [/* 실제 상태 */] },
  enemy: { layoutId: 'interceptor', rooms: [/* 실제 상태 */], doors: [/* 실제 상태 */] }
}
```

위 예시는 부분 스키마이며 단독 실행용 저장 파일은 아닙니다. `getLayout(ship)`은 정규 데이터 조회입니다. `getCrewRoute(id)`는 실제 움직임에서 파생한 경로 조회이고 저장 카운터나 난수를 소비하지 않습니다.

| 참조 | 검증 기준 |
|---|---|
| 방 사각형 | `layoutId`의 정규 방 ID·좌표·크기 |
| 내부 문·에어록 | 정규 문 ID·양끝 방·좌표·방향·외부 여부 |
| 승무원의 현 방·위치·경로 | `crew.shipId`가 가리키는 실제 함선 |
| 승무원의 저장 배치 | 승무원을 소유한 함선 |
| 무기 표적·빔 좌표 | 존재하는 상대 함선 |
| 비행 중 탄 | 탄이 향하는 함선 |
| 이전 전투의 남은 조준 기록 | 실제 구 저장의 legacy 기하 |

알 수 없거나 없는 레이아웃, 변조된 방·문, 존재하지만 연결되지 않은 이동 구간, 잘못된 목적지·좌표는 거절해야 합니다. 여섯 방의 문자열이 맞는다는 이유만으로 잘못된 구조를 허용하지 않습니다.

## 2. v1~v4 호환

변환 순서는 `v1 → v2 → v3 → v4 → v5`입니다. 입력 버전부터 필요한 단계만 실행합니다. v4→v5는 기존 함선에 `layoutId='legacy'`를 추가하며 선체·체력·장비 ID·화물·회수 영수증·문·배치·좌표·경로·조준·환경·XP·난수·진행을 바꾸지 않습니다.

기존 아틀라스·레이스 저장도 새 도면으로 재생성하지 않습니다. 새 항해에서 선택한 함선은 새 레이아웃으로 출항합니다. 현재 항해를 보존하는 것과 새 항해의 설계를 적용하는 것을 분리합니다.

기존 v4 저장에는 보상이 `pending`인 상태와 이미 회수한 장비·화물·실제 배치 변경이 들어갈 수 있습니다. 마이그레이션은 회수품을 다시 만들거나 ID를 재발급하지 않으며, 미결정 선택을 자동으로 처리하지 않습니다. 검증 실패 시 현재 항해·난수·ID·로그는 유지합니다.

## 3. 실제 v4 fixture

실제 v4 코드에서 공개 명령으로 만든 다섯 저장을 보존했습니다. 원래 v4 `load()`로 모두 승인했습니다. 읽은 세 소스 파일의 SHA-256은 배포 기준 `21a19454feeb3ab5c240fd19533a027dec653267`과 일치합니다. 재지시 두 사례는 같은 해시의 배포 ZIP 소스로 추가 생성했습니다. 출처·해시는 [fixture README](../tests/fixtures/README.md)에 기록합니다.

| 파일 | 실제 생성 상태 |
|---|---|
| `v4-pending-salvage.json` | 시드42 레이스 첫 교전 승리, 아직 선택하지 않은 이온 회수품 |
| `v4-inventory-stations-combat.json` | 이온 회수·기존 레이저와 교환, 소행성 도약, 실제 산소실 이동·배치 저장, 이온 발사·은폐·정지 |
| `v4-midlegacy-route.json` | 구 직선 이동 중 이미 다음 방에 들어갔지만 원래 방 ID가 남아 있는 실제 경계 |
| `v4-retarget-oxygen.json` | 같은 경계에서 원래 산소실로 돌아가도록 정지 중 재지시 |
| `v4-retarget-shields.json` | 같은 경계에서 실드실로 정지 중 재지시 |

두 번째 저장은 전투 약20.47초, 선체26, 스크랩83·연료13·미사일9·부품5, 화물의 원래 레이저 ID, 회수 이온 ID, 산소실 저장 배치, 소행성 경보 약1.27초, 은폐6초, 비행 중 이온과 실제 빔 경로를 포함합니다. HP·자원·좌표·경험치·승리 결과를 직접 대입하지 않았습니다.

세 번째 저장은 `roomId='oxygen'`, 좌표 `(4.035,3)`, `movePath=['medbay','bridge']`입니다. 당시 이동은 다음 방 중심에 도착할 때까지 원래 방 ID를 유지했으므로 정상적인 구 저장입니다. 같은 지점에서 목적지를 바꾸면 큐는 `['oxygen']`나 `['shields']`가 될 수 있어 첫 큐 방만으로 실제 위치를 판단해서는 안 됩니다.

legacy 검사는 원래 방과 문으로 연결된 인접 방에 들어간 좌표를 제한적으로 인정합니다. 로드는 원본 값을 바꾸지 않으며 경로 조회·첫 실제 틱에서 현재 좌표가 들어간 물리 방을 찾고 원래 최종 목적지로 남은 문 경로를 계산합니다. 조회는 상태를 쓰지 않고, 실제 틱만 물리 방·경로를 정정합니다. 현재 방으로 뒤로 순간이동시키지 않습니다. 구 버전 사망 인원이 이동 경로를 잃은 상태도 legacy의 실제 방 내부인지 확인합니다.

## 4. 자동 검증 결과

2026-11-14 Node.js v24.22.1에서 최종 엔진의 **137/137 시험이 통과**했습니다. 규칙 시험은 필요한 상황을 직접 준비하는 fixture를 포함하며, 아래 실제 완주 정책과 구분합니다.

|---|---:|---|

| [corev2.test.cjs](../tests/corev2.test.cjs) | 25 | 문·산소·침투·드론·수동/빔·기함 |

| [corev5.test.cjs](../tests/corev5.test.cjs) | 22 | 실제 구조·이동·적선 기하·이전 저장 |

기존115개를 삭제하지 않았습니다. 현재 저장 버전 기대치를 갱신하고 기존 문 ID·빔 교차를 전제로 삼는 독립 fixture에는 `legacy`를 명시했습니다. 기존 문 파괴 시험은 실제 문 접근에 걸리는 시간을 기다린 뒤 내구도 감소를 확인하도록 변경했습니다. 초당 파괴량과 정지 중 불변 조건은 유지합니다. 신규 구조와 실제 캠페인은 각 함선의 새 레이아웃으로 검증합니다.

v5 시험은 여섯 구조의 방 비겹침·공유벽 문·외부 에어록·연결성을 확인하고, 모든 구조의 **순서 있는 방 쌍180개**에서 실제 문 좌표·목적지·거리를 비교합니다. 실제 틱에서는 이동이 경로 위에 남는지, 문에 접근하기 전에 열거나 파괴하지 않는지, 이동·파괴가 같은 시간을 중복 소비하지 않는지 확인합니다. 레이스 승무원이 요격함에 침투한 뒤에는 상대 문 그래프로 이동합니다. 다른 구조의 빔 교차·실제 방별 피해·지역 감압·저장 배치도 별도로 확인합니다.

이동·적선 문 파괴 중 저장은 원본과 복원본의 이후 실제 틱 결과까지 비교합니다. v4 다섯 fixture는 원본 필드 보존과 재저장을 검증하며, 문 경계·정지 재지시 사례는 첫 틱의 이동량·실제 방·목적지 도착까지 검사합니다. 변조된 구조·가짜 이동 연결·잘못된 물리 좌표·빔은 거절하고 현재 상태·난수·ID·로그가 그대로인지 확인합니다.

```bash
node --test tests/engine.test.cjs tests/corev2.test.cjs tests/corev3.test.cjs tests/corev4.test.cjs tests/corev5.test.cjs
node tests/playthrough.cjs
```

## 6. 오프라인·소스 산출물

최종 로직·UI로 생성한 단일 HTML은 **358,864바이트**입니다. CSS1개·classic script4개를 인라인하고 외부 코드 참조가 없는 것을 확인했습니다. 네 인라인 스크립트의 구문 검사와 포함된 엔진의 실제 VM 실행에서 레이스→요격함, 세 문을 지나는 약4.8칸 경로, 요격함4방 빔, 저장 roundtrip의 완전 일치가 통과했습니다.

```bash
node scripts/build-offline.cjs
python3 scripts/package-source.py
```

[package-source.py](../scripts/package-source.py)는 명시적 허용 목록으로 소스를 묶습니다. 기존 v3/v4 자료와 v5 세 문서를 합친 명세9개, 실제 화면7개, 게임 소스·README·변경 이력·빌드 스크립트·독립 HTML, 모든 CJS 시험과 JSON/MD fixture를 포함합니다. 내부 저장소 정보·환경 메타데이터·ZIP 자체를 제외하며 생성 후 ZIP CRC를 검사합니다. 최종 문서까지 저장한 동일 소스에서 ZIP을 생성해야 합니다.
