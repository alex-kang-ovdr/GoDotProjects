# STARWARD — 마지막 신호

**EXPEDITION / 07 · 실시간 일시정지 함선 전술 게임**

v7은 **빈 시스템 슬롯의 설치·확장, 사각 타일 이동과 승조원 근접전, 2D / 입체 3D 전투 화면, 그래픽 스타일 3종**을 추가합니다. 같은 항해 상태를 두 화면으로 표시하며 설치 위치·점유·이동 경로·문·전력·피격·수리가 서로 연결됩니다. 기존의 8섹터 월드맵·3종 다단계 퀘스트·수동 발사 예약·텔레포터·해킹·정신 지배·은폐·배터리도 이어집니다.

FTL의 핵심 구조를 참고한 자체 게임입니다. 원작의 모든 콘텐츠·수치·장비·상호작용을 동일하게 복제한 버전은 아닙니다. 구현과 차이는 시스템별 문서에 명시했습니다.

## 1. 실행

웹: [STARWARD — 마지막 신호](https://starward-last-signal.taru00.chatgpt.site)

독립 실행은 `artifacts/STARWARD_Offline.html`을 최신 브라우저로 열면 됩니다. CSS와 다섯 스크립트가 들어 있어 설치·외부 라이브러리·네트워크가 필요하지 않습니다. 웹의 **오프라인 버전 / 소스 ZIP**으로도 받을 수 있습니다. 다운로드 창이 막히면 링크를 새 탭에서 열거나 로컬 서버를 사용하세요.

소스는 `dist/index.html`을 열거나 다음 명령으로 실행합니다.

```bash
python3 -m http.server 8000 --directory dist
```

브라우저에서 `http://localhost:8000`에 접속합니다. Windows에서는 `python3` 대신 `py -3`를 쓸 수 있습니다. 게임 실행에는 Node.js·npm이 필요하지 않습니다.

## 2. 첫 공격을 실행하는 순서

1. 격납고에서 함선·난이도를 선택하고 출항합니다. 첫 전투는 일시정지입니다.
2. 무기 카드 또는 **1~4**를 누르고 적의 방을 지정합니다. 빔은 시작 방과 끝 방을 차례로 누릅니다.
3. 자동 모드는 충전마다 반복 발사합니다. 수동 모드는 **발사/예약**을 누르면 충전 중에도 한 발사를 예약합니다. **F / 일제사격**은 조건을 갖춘 여러 무기에 같은 명령을 냅니다.
4. **Space / 전투 시작**으로 시간을 진행합니다. 일시정지 중에는 충전도 탄의 이동도 진행하지 않습니다. 무기 카드의 전력·탄약·표적·예약 상태를 확인하세요.
5. 아틀라스의 이온은 선체 피해가 없습니다. 이온으로 실드를 잠그고 중형 레이저 또는 전개한 공격 드론으로 피해를 줍니다.
6. 승리 후 회수품이 있으면 **화물칸으로 회수 / 분해**를 결정합니다. 다음 비콘, 출구, 다음 섹터를 선택하고 마지막 기함의 세 단계를 추격합니다.

충전 중 명령을 내렸다고 즉시 탄약이 사라지지는 않습니다. 실제 발사 때 한 번 소비하며 같은 예약을 중복 실행하지 않습니다. 전력 부족·미지정 표적·상대 은폐·탄약 부족은 서로 다른 사유를 표시합니다.

## 3. 시작 함선과 공간 구조

| 함선 | 장비·승무원·특수 능력 | 선체/반응로 | 스크랩·연료·미사일·부품 |
|---|---|---:|---|
| 아르고 | 삼연장 레이저·아르테미스, 인간·엔지·록, 방어 드론, 배터리1 | 30 / 10 | 60 · 12 · 10 · 4 |
| 아틀라스 | 이온·중형 레이저, 인간·엔지·엔지, 공격·방어 드론, 해킹1 | 28 / 11 | 50 · 12 · 6 · 6 |
| 레이스 | 삼연장 레이저·빔, 인간·엔지·인간, 방어 드론, 은폐1 | 26 / 11 | 45 · 12 · 6 · 3 |

새 함선은 고유한 기존 여섯 핵심 시스템 방에 **독립 보조 구획 여섯 개**를 연결합니다. 보조 구획은 각각 2×2칸이며, 네 설치 마운트가 열려 있고 나머지 두 개는 증설합니다. 드론·텔레포터·시작 능력이 세 구획을 사용하므로 처음부터 사용 가능한 빈 슬롯이 하나 있습니다. 잠긴 설치 마운트의 방도 이동·환기·피격 공간으로 존재합니다.

### 시스템 설치와 확장

**시스템 설치** 또는 주 전술 화면의 빈 구획 타일을 선택합니다. 별도 함선 구조 안내 도면은 읽기 전용입니다. 빈 마운트에는 정신 제어(정신 지배)50·해킹55·은폐60·비상 배터리(보조 배터리)35스크랩으로 새 시스템을 설치할 수 있습니다. 이미 있는 시스템은 중복 설치하지 않습니다. 처음 두 확장은 순서대로40·60스크랩이며, 시설 개량은 별도 비용을 사용합니다. 새 시설은1레벨·전력0으로 시작하므로 전력 패널에서 배분하세요. 설치와 증설은 출항 준비·지도·상점·보상 상태에서 가능합니다.

### 사각 타일과 승조원 전투

승조원을 선택하고 **원하는 사각 타일**을 누릅니다. 이동은 상하좌우 인접 칸과 실제 연결 문을 이용하며 목적지와 진행 경로를 표시합니다. 다른 인원이 점유하거나 예약한 칸에는 겹쳐 도착하지 않습니다. 적 승조원을 지정하면 접근한 뒤 인접한 칸에서 공격합니다. 문이나 벽 너머, 대각선에서는 근접 피해를 주지 않습니다. 다른 타일로 이동을 명령하면 직접 지정한 공격을 해제하고 퇴각합니다. 양측 인공지능도 같은 이동·교전 규칙을 사용합니다.

### 2D / 3D와 스타일

보기 제어에서 **2D / 3D**를 바꾸고 **현대 SF / 로우폴리 / 청사진** 중 그래픽 스타일을 고릅니다. 3D는 높이가 있는 함선·격실·시설·승조원을 원근 카메라와 깊이 판정으로 그립니다. WebGL을 우선 사용합니다. 드래그로 시점을 회전하고 휠로 확대·축소하며 초기 시점으로 복귀할 수 있습니다. 단순 클릭은 선택·이동·조준 명령이고 드래그는 카메라 조작입니다. 두 화면에서 같은 항해·체력·무기 충전·표적·이동 경로를 사용합니다. 표시 설정은 항해 저장과 별도로 보관합니다. WebGL을 제공하지 않는 환경에서는 같은 입체 장면과 카메라를 사용하는 **호환 3D**로 표시합니다. 두 출력 방식이 모두 없는 경우2D로 이어집니다.

베테랑은 적 선체를20% 늘려 올림하고 적 무기 충전 시간을10% 줄입니다. 플레이어 시작 자원과 보상 규칙은 표준과 같습니다. 설치된 드론도 전투당 첫 전개에는 부품이 필요합니다.

## 5. 전술 규칙

**텔레포터:** 새 함선에서는 텔레포터가 설치된 독립 구획이 송신실입니다. 이전 도면의 항해는 기존 송신실을 유지합니다. 기본 송신 정원2, 실효 전력1/2/3에 재사용 대기20/15/10초입니다. 송신실 안에서 이동을 마친 생존 인원만 보냅니다. 회수는 같은 적 방의 최대4명이며 본함 송신실의 실제 수용 한도와 빈 타일을 함께 검사합니다. 상대 은폐는 양방향 전송, 특수 실드는 송신만 막습니다. 적 선체 파괴·도주 전에 생존 강습대를 회수하세요.

**은폐:** 가동 단계1/2/3에서5/10/15초, 회피+60%p·최대95%, 상대 일반 무기 충전 정지. 일반 무기의 한 차례 발사는 최대 지속시간20%를 차감하며 빔은 예외입니다. 종료 후20초 대기입니다. 이미 날아가는 탄·드론·환경·특수 공격은 계속 진행합니다.

**해킹:** 부품1로 접근 기체를 발사합니다. 준비된 방어 드론은 요격할 수 있습니다. 부착 후 펄스는4/7/10초, 종료 후20초 대기이며 같은 기체의 재활성화는 무료입니다. 전력이 있는 부착 기체는 해당 방 문을 잠그고 성운에서도 그 방의 시야를 제공합니다. 무기 충전 역행·실드 배출·산소 배출·의료 역치료·기관/함교 교란이 실제 상태에 작용합니다.

**정신 지배:**14/20/28초 동안 임시 진영만 바꾸고 원래 소유 배열은 유지합니다. 지배된 적은 자율적으로 싸우며 수동 이동할 수 없습니다.2단계는 임시 HP+15·근접 피해×1.25,3단계는 HP+30·피해×2입니다. 종료 시 보너스를 제거하며 죽은 인원을 부활시키지 않고 보너스 회수만으로 생존자를 죽이지 않습니다. 시야·상대 특수 실드·재사용 대기20초를 검사합니다.

**보조 배터리:** 전력 배분 없이30초간 임시 전력+2/+4, 종료 후20초 대기. 이온 폭풍에서도 추가량은 온전히 적용합니다. 만료/손상으로 공급이 끝나면 예산을 넘는 배분을 정리합니다. 명목 반응로를 영구 강화하지 않습니다.

기존 전력·산소·문·대인전·수리·이온·숙련도 유지합니다. 숙련은 실제 운용/작업/타격으로40/120XP에서 성장합니다. 이온은 선체 피해 없이 시스템 전력을 잠급니다. 소행성·태양·이온 폭풍 비콘은 지도에 위험과 승리 보너스+8을 표시합니다.

## 6. 월드·이벤트·퀘스트·경제

월드맵은8깊이·20개 섹터 후보이며 매번 연결된 다음 섹터를 고릅니다. 각 지역은 시작·6열×3행·출구의20비콘입니다. 양방향 연결로 재방문할 수 있지만 지역 도약과 섹터 이동은 각각 연료1을 사용합니다. 이미 해결한 비콘은 보상을 반복 지급하지 않습니다.

반군 전선은 기본-2열에서 도약당0.75열 전진합니다. 성운·지연 효과가 이를 바꾸며 도착 시점의 점령도 미리 표시합니다. 점령된 상점에서는 거래 대신 반군 전투가 발생합니다. 점령지 전투 보상은 탈출용 연료1이며 스크랩을 반복 얻는 장소가 아닙니다. 연료0이면 구조 선택으로 회복할 수 있지만 시간이 흘러 추격과 퀘스트에 영향을 줍니다.

자체 사건15정의·55선택, 중계망 복구·피난민 호송·설계도 회수3종의2단계 퀘스트가 있습니다. 퀘스트는 목적지·이월·기한·이력·완료/실패를 저장합니다. 조건 선택은 실행 때 종족·숙련·장비·능력·자원을 다시 검사합니다. 일부 조건이 사라지면 다른 선택을 택해야 합니다.

상점 보급품은 종류별4팩, 장비와 종족별 고용은 각1개의 재고를 보존합니다. 수리와 시스템 강화는 자기 한도까지 제공됩니다. 다른 상점은 독립 재고입니다. 설치 무기4·드론2·화물6, 첫 승리/짝수 일반 승리/적 승무원 전멸의 회수품 규칙도 유지합니다. 회수와 장착은 별개이며 정비·판매는 전투와 사건 도중 할 수 없습니다.

8섹터에서는 기함이 지도에서 기지로 이동합니다. 단계 승리 뒤 다음 위치를 추격해야 합니다. **현 위치 대기**도 지도1턴이며 기함이 기지에서3턴을 버티면 패배합니다. 화면을 열어 생각하는 동안에는 지도 턴이 흐르지 않습니다.

## 7. 저장과 이전 항해

상태 버전은7이며 기존 브라우저 저장 키를 유지합니다. JSON 가져오기는 실제 로더로 검증하고 미리 보기와 확인을 거친 뒤 적용합니다. 교체 전 현재 항해의 복구용 사본을 보관합니다.

- v6 항해는 기존8섹터 월드·임무·능력 진행을 유지합니다. 기존 도면에 새 보조 구획을 억지로 추가하지 않으므로 빈 슬롯 확장은 새 출항에서 이용합니다.
- v1~v5 항해는 **기존3섹터 항해**로 이어갑니다. 기존 비콘·도면·선체·승무원·XP·장비/화물·표적·예약·문/경로·임시 효과·난수·ID를 보존합니다.
- 새 항해는8섹터 월드와12방 모듈형 도면을 받습니다. 기존3섹터를 중간부터8섹터로 확장하거나 소유 장비를 다시 뽑지 않습니다.
- v5의6초 은폐처럼 당시 유효했던 진행 중 값도 보존합니다. 새 명령부터 현재 규칙을 사용합니다.
- 이전 연속 좌표와 경로는 가져오기 직후 보존하며, 전투 재개 시 호환 이동으로 타일 중심에 정렬합니다. v7은 칸 위치·이동 진행·예약 목적지·공격 대상·재타격 대기·슬롯 배치를 추가 저장합니다.
- 신규 능력의 접근/부착/활성/대기, 정신 지배와 임시 HP, 배터리, 퀘스트·상점 재고·기함 위치까지 저장합니다.
- 손상·지원하지 않는 버전·없는 참조·과도한 전력·가짜 경로·잘못된 임시 상태는 거절하고 현재 항해를 유지합니다.
- 웹과 로컬 파일의 저장 공간은 다를 수 있습니다. JSON 내보내기로 옮기세요. 내보낸 파일은 JSON 문자열을 다시 인코딩한 값이 아니라 상태 객체를 담습니다.

## 8. 검증과 소스 구조

`data.js → engine.js → campaign.js → render3d.js → app.js`의 classic script 순서입니다. `Starward.Game`이 상태와 공개 명령, UI가 SVG·HTML·입력·Web Audio를, `render3d.js`가 읽기 전용 WebGL 표시를 담당합니다.

```bash
node --test tests/*.test.cjs
node tests/playthrough.cjs
node tests/playthrough.cjs --loadout argo --difficulty veteran 42
```

Node.js18 이상에서 별도 패키지 설치 없이 실행합니다. 규칙 시험은 제한된 상황을 직접 준비할 수 있습니다. 별도의 완주 정책은 자원·HP·좌표·경험치·난수·승리 상태를 대입하지 않고 공개 명령과 실제 전투 틱만 사용합니다. v7은 규칙 시험 **225/225**, 공개 명령 완주 **4/4**를 통과했습니다. 실제 브라우저에서 슬롯 설치·확장, 타일 이동·근접전·퇴각, 표시 전환, 최종 단일 HTML의 사격 피해를 확인했습니다. WebGL이 제공되지 않은 검증 환경에서는 호환 3D를 사용했습니다. 자세한 결과는 [v7 검증 기록](docs/v7_validation.md)과 [기계 판독 결과](tests/verification-v7.json)를 확인하세요. v6 결과는 이전 버전의 기록으로 따로 유지합니다. 모바일 실제 기기와 모든 브라우저를 검증한 것은 아닙니다.

## 9. 구현 한계

3함선·2난이도·4종족·5무기·2드론과 자체15사건·3퀘스트를 제공합니다. 원작 전체 함선/종족/무기/이벤트/해금/업적·클론실·폭탄/플랙·모든 강화장치·펄서/ASB·정밀 센서 모델은 없습니다. 적 보조 시스템·기함 수치·상점 구성·비콘 정비는 자체 규칙입니다.

시스템 슬롯 확장은 미리 배치된 여섯 구획의 마운트를 해제하는 방식입니다. 격실을 임의로 끌어 놓거나 선체 형태를 편집하는 건조 도구는 없습니다. 이전6방 저장의 공유 보조 시설은 호환용으로 유지합니다. 빔은 방 두 곳의 중심으로 조준하며 자유 좌표 드래그는 지원하지 않습니다. 경로는 이동 가능 칸을 사용하며 화재 위험을 자동 최적화하지 않습니다. 3D는 절차형 도형과 셰이더를 사용하고 외부3D모델·텍스처를 다운로드하지 않습니다. 서버·계정·멀티플레이는 없습니다.
