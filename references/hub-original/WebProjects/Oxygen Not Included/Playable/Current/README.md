# 숨 · BREATH COLONY

**작은 숨에서 시작하는 지하의 세계.** 세 명의 대원이 지하 정착지를 만들고, 플레이어가 채굴·건설·생산 계획을 세우는 한국어 브라우저 게임입니다. v4에서는 **기밀문과 실제 방 구획, 침실·식당·온실의 생활 효과, 산소 충전소와 휴대 산소, 작업 경험과 수동 기술 배분**을 기존 물·식량·운반·전력·교대 시스템에 연결합니다. 다섯 단계의 20개 목표를 따라 초기 생존에서 안전한 심부 확장까지 진행합니다.

Oxygen Not Included의 자원 순환과 간접 지시에서 영감을 얻은 독립 프로토타입입니다. 캐릭터, 그림, 설비 표현, 수치와 규칙은 이 프로젝트용으로 구성했습니다. 원작의 자산이나 전체 물리·콘텐츠를 복제한 게임은 아닙니다.

## 플레이 목표

대원은 직접 조종하는 유닛이 아니라 작업 예약과 생활 필요에 따라 움직입니다. **채굴 → 바닥의 자원 더미 → 대원 운반 → 수거 거점 입고 → 건설 → 전선·배관 연결 → 생산 → 조리·식사·교대 생활**을 이어 가세요. 게임은 시작 직후부터 흐르므로 먼저 `Space`로 멈추고 계획을 세워도 됩니다.

| 단계 | 실제 달성 조건 |
|---|---|
| 1. 초기 정착 | 블록 12칸 채굴, 산소 확산기 완공, 연결된 배터리 충전, 재배 상자 3개 새로 건설, 연구 30, 대원 3명 이상과 5주기 생존 |
| 2. 생활 기반 | 화장실·세면대 각각 3회 이용, 물 20L 실제 취수, 오수에서 청수 8L 이상 실제 회수 |
| 3. 자립 운영 | 수소로 2,000J 발전, 연구 100, 필요한 생활·생산 조건을 연속 180초 유지 |
| 4. 잘 사는 기지 | 고체 80개 실제 운반, 조리식 12끼 실제 생산, 식탁 식사 6회, 생활 조건 연속 240초 유지 |
| 5. 안전한 확장 | 침실과 식당 각각 1개, 획득한 기술 3등급 배분, 휴대 산소로 실제 호흡한 시간 합계 30초, 확장 조건 연속 180초 유지 |

1주기는 게임 시간 **120초**입니다. 시작 재배 상자에 새 상자 3개를 더하면 총 4개입니다. 초기 목표는 다음 확장을 위한 보급품을 주지만, 취수·정화·수소 발전 목표는 설비를 세우는 것만으로 완료되지 않습니다. 해당 생산이 실제로 일어나야 합니다.

**3단계 자립 조건**은 생존 대원 3명 이상이며 모든 생존 대원의 건강 70 이상, 생활 구역 산소 55% 이상, 식량 8 이상, 청수 20L 이상, 대원 위생 65 이상, 용변 욕구 90 이하와 충분한 오수 저장 여유입니다. 연구와 실제 생산 이력에 더해 현재 연결된 화장실·세면대·정화기·전해장치·취수기·수소 발전기도 필요합니다. 조건이 깨지면 유지 시간이 0으로 돌아가고 이유가 표시됩니다. 산소가 충분하거나 정화할 오수가 없어 자동 대기하는 것은 정상 운영에 해당합니다. 모든 목표를 완료한 뒤에도 계속 플레이할 수 있습니다.

**4단계 정착 조건**은 이 자립 기반에 더해 모든 생존 대원의 건강 80 이상·스트레스 35 이하, 전체 식품 20끼 이상·조리식 3끼 이상, 대원마다 교대표를 선택하고 침상에서 계획 수면을 1회 이상 마친 이력을 요구합니다. 사용 가능한 자원 보관함, 전력·청수에 연결된 조리대, 모든 대원이 도달할 수 있는 식탁, **실제로 전력을 공급받는 냉장고**와 운반·조리·식탁 누계를 함께 검사합니다. 하나라도 깨지면 정착 유지 시간이 0으로 돌아갑니다. 완료한 목표와 승리 기록은 이후 계속 운영해도 유지되며, 현재 생활 판정은 계속 갱신됩니다.

**5단계 확장 조건**은 현재 정착 조건을 만족하면서 사용 가능한 침실·식당, 배분한 기술 3등급 이상, 휴대 호흡 누계 30초 이상, 완공·활성·전력 연결·비침수 상태의 산소 충전소를 요구합니다. 생존 대원 모두가 필요한 방과 충전소에 도달할 수 있어야 합니다. 충전소 탱크가 가득 차서 압축을 멈춘 상태는 정상입니다. 조건이 끊어지면 현재 확장 시간은 0으로 돌아가고 미달 이유를 표시합니다. 20개 목표를 완료한 뒤에도 기지를 계속 운영할 수 있습니다.

## 처음 플레이할 때 따라갈 수 있는 경로

아래는 **기본 시드 73**에서 실제로 검증한 진행 순서입니다. 좌표는 타일을 선택했을 때 정보 패널에 표시되는 `x, y`이며, 오른쪽으로 갈수록 x가 커지고 아래로 갈수록 y가 커집니다. 시작 코어는 `(24,11)`, 상층 작업 바닥은 `y=11`, 아래층 작업 바닥은 `y=16`, 두 층을 잇는 사다리는 `x=23`입니다.

### 1. 생활 설비와 농장을 예약합니다

| 위치 | 건설할 설비 | 필요한 연결 |
|---|---|---|
| `(25,11)` | 수세식 화장실 | 청수관·오수관 |
| `(26,11)` | 산소 확산기 | 전선 |
| `(27,11)` | 축전지 | 전선 |
| `(28,11)` | 연구 작업대 | 전선·청수관 |
| `(29,11)` | 세면대 | 청수관·오수관 |
| `(31,11)` | 급수 탱크 | 청수관·오수관; 두 물은 별도 구획에 저장 |
| `(28,16)`, `(29,16)`, `(30,16)` | 새 재배 상자 3개 | 청수관 |

시작 공간의 전선은 상층과 아래층의 `x=14~33`을 잇고 있습니다. 코어에서 시작 농장까지의 청수관은 `(24,11)`부터 `(30,11)`까지 설치되어 있습니다.

**청수관**을 상층 `(23,11)`부터 `(31,11)`까지 이어 주세요. 사다리 옆으로 `(23,11)`에서 `(23,16)`까지 내린 뒤, 아래층 `(23,16)`부터 `(30,16)`까지 연결하면 세 농장이 같은 공급망을 사용합니다. **오수관**은 상층 `(25,11)`부터 `(32,11)`까지 연결합니다. 청수관·오수관·전선은 같은 칸에 함께 놓을 수 있습니다. 설비가 놓인 칸까지 선을 연결해야 합니다.

배관과 전선은 금속 1을 내고 즉시 놓습니다. 건물은 대원이 실제로 접근해 완성합니다. 일을 많이 예약하면 수동 발전·연구·건설이 인력을 나누어 쓰므로 잠시 기다려 주세요.

### 2. 물까지 갈 길과 추가 금속을 확보합니다

상층의 오른쪽 끝에서 `(36,11)`, `(37,11)`을 채굴하면 오른쪽 물 웅덩이 옆에 닿을 수 있습니다. 이곳에 취수기를 놓을 예정이므로 바닥인 `y=12`는 유지하세요. 물 웅덩이 안의 `(40,10)`에는 표시된 **지하수 유입구**가 있어 물이 계속 공급됩니다.

고급 시설에는 추가 금속이 필요합니다. 시작 공간의 왼쪽에서 `(11,11)`을 판 뒤 `(10,11)`, `(10,10)`, `(10,9)`의 구리 광맥 3칸을 채굴하면 금속 27이 바닥의 더미로 남습니다. 대원이 코어 또는 완공 보관함에 운반해야 건설에 쓸 수 있습니다. 주변에서 접근 가능한 블록을 더 채굴해 누적 12칸 목표를 채우면 금속·광석 보상도 받습니다. 추가 설비나 배관을 많이 늘렸다면 구리 광맥을 더 확보하세요.

### 3. 취수와 정화를 연결합니다

| 위치 | 설비 | 해금·배관 |
|---|---|---|
| `(37,11)` | 물 수집기 | 바로 건설 가능. 인접한 물과 전선·청수 출력관 필요 |
| `(32,11)` | 오수 정화기 | 연구 15. 전선·청수 출력관·오수 입력관 필요 |

상층 전선을 `(33,11)`에서 `(37,11)`까지 연장하고, 청수관도 `(31,11)`에서 `(37,11)`까지 잇습니다. 앞서 연결한 오수관은 화장실·세면대·탱크·정화기까지 이어집니다.

**물 수집기가 완성되고 대원 세 명이 모두 기지 쪽으로 돌아오면 `(36,11)`에 바닥 타일 1개를 지어 방수벽을 만드세요.** 이 칸이 막히면 웅덩이에서 기지로 흘러드는 물을 차단하면서 이미 연결한 전선과 청수관은 유지합니다. 대원은 모두 `x<36`인 쪽에 있어야 하며, 취수기는 대원의 상주 없이 작동합니다. 이 벽이 없으면 저장고가 가득 차 취수가 대기할 때 지하수가 아래층 농장까지 넘칠 수 있습니다. 나중에 취수 구역에 작업자가 들어가야 한다면 벽을 해체해 다시 길을 만드세요.

탱크는 **빈 저장 용량**을 추가합니다. 물을 새로 만들지 않습니다. 취수기가 웅덩이의 물을 연결된 청수망으로 보내고, 화장실과 세면대가 만든 오수를 정화기가 회수합니다. 청수 총 재고가 많더라도 설비와 해당 저장고 사이의 관이 끊어졌다면 사용할 수 없습니다.

### 4. 물을 산소와 전력으로 바꿉니다

연구 35가 되면 `(33,11)`에 **물 전해장치**, `(34,11)`에 **수소 발전기**를 건설합니다. 전해장치는 청수와 전력이 필요하고, 수소 발전기는 전선과 공용 수소 재고를 사용합니다. 이 위치는 앞 단계에서 연장한 전선·청수관을 그대로 사용합니다.

기본 자동 제어를 유지해도 위 경로를 완료할 수 있습니다. 수동 발전기는 초기 전력과 생산 공백을 메우고, 수소 발전은 대원의 운전 없이 전기를 만듭니다. 산소가 충분하면 전해장치가 쉬면서 수소 공급도 줄어들기 때문에 배터리와 보조 발전은 계속 의미가 있습니다.

### 5. 생활 시설을 위한 추가 구리를 실제로 수거합니다

물 순환 설비가 완공되면 아래층 왼쪽의 `(13,16)` → `(12,16)` → `(11,16)`을 차례대로 채굴하세요. 마지막 칸은 구리 광맥입니다. 다음은 중앙 사다리를 확장하는 경로입니다.

1. `(24,20)`을 먼저 채굴합니다. 대원이 기존 사다리를 따라 내려가면서 21행을 탐사합니다. 아직 보이지 않는 칸에는 작업을 예약할 수 없습니다.
2. `(23,21)`을 채굴하고, 같은 칸에 사다리를 건설해 아래로 내려갈 길을 완성합니다.
3. `(24,21)`의 구리를 채굴합니다. 공사마다 실제 완공을 기다리며 사다리와 귀환 경로를 유지하세요.
4. 나루의 역할을 **운반**으로 바꾸고 공용 재고에 **금속 30·광석 67 이상**이 들어올 때까지 기다립니다. 바닥의 구리 더미는 아직 쓸 수 있는 금속 재고가 아닙니다.

고체 80개를 실제 입고하면 운반 목표의 금속 12 보급도 받습니다. 깊은 작업 구역에서는 산소 보기와 대원의 호흡을 확인하세요. 대원은 위험해지면 작업을 멈추고 안전한 칸으로 피하며, 들고 있던 자원은 바닥에 내려놓습니다. 초기에 방수벽을 닫기 전 흘러든 물은 하부에 남아 있을 수 있습니다.

### 6. 보관·조리·식탁·냉장을 연결합니다

| 위치 | 설비 | 비용·연결 |

### 7. 세 교대를 나누고 정착 시간을 확인합니다

대원 탭에서 나루는 **주간**, 모아는 **중간**, 솔은 **야간** 교대로 지정합니다. 세 일정은 서로 40초씩 어긋나 있어 같은 시간에 전원이 자러 갈 가능성을 줄입니다. 시작 침상 3개를 보존하세요. 교대표만 선택해서는 수면 이력이 생기지 않으며, 해당 수면 구간에 실제 침상에서 6초 이상 쉬어야 기록됩니다.

첫 화장실 필요는 기본 시작 상태에서 약 300초 전후부터 나타납니다. 시설과 청수·오수·접근 경로를 유지하면 대원이 직접 방문합니다. 식탁 식사도 포만감이 내려간 뒤 실제로 찾아가 먹어야 누적됩니다. 연구 100과 생산 목표를 채운 뒤 **목표 탭의 자립·정착 미달 이유**로 남은 조건을 확인하세요.

### 8. 추가 구리를 수거하고 휴대 산소를 준비합니다

기존 심부 사다리 아래 `(23,22)`의 구리를 판 뒤 같은 칸에 사다리를 놓습니다. `(22,22)`, `(21,22)`, `(20,22)` 순서로 왼쪽 통로를 엽니다. 두 구리 광맥이 실제로 입고되면 상층 `(21,11)`에 **산소 충전소**를 예약합니다. 비용은 광석 20·금속 12, 연구 해금은 45이며 기존 전선에서 8W를 사용합니다.

충전소는 주변 공기의 산소를 실제로 빼서 탱크에 압축합니다. 배관은 필요 없지만 산소가 부족한 곳에서는 충전하지 못합니다. 대원의 휴대 산소가 자동 모드인지 확인하고 실제로 충전소에 찾아가 보충할 시간을 주세요. 빈 통을 가진 상태에서 깊은 통로를 계속 파기보다 대원들의 휴대량을 먼저 확인하는 것이 좋습니다.

이어서 `(19,22)`, `(18,22)`, `(17,22)`를 채굴합니다. **`(17,22)`에 사다리를 먼저 완공한 다음** 바로 아래 `(17,23)` 구리를 캐고 그 칸에도 사다리를 놓습니다. 바닥을 먼저 없애면 귀환·운반 동선이 끊길 수 있습니다. 방에 쓸 광석은 `(22,21)`부터 `(17,21)`까지의 통로 천장과 `(16,22)`, `(16,21)`을 채굴해 보충합니다. 모두 대원이 실제로 접근해 캐고 코어나 보관함에 운반해야 사용할 수 있습니다.

### 9. 낮은 침실과 식당을 완성합니다

침실과 식당에 필요한 합계 재료는 **광석 75·금속 16**입니다. 벽·천장 17칸과 기밀문 4개가 포함되며 기존 침상·보관함·식탁을 그대로 사용합니다.

| 구획 | 천장 — 먼저 완공 | 옆벽 — 천장 뒤 시공 | 출입문 | 내부 |
|---|---|---|---|---|
| 침실 | `y=9`, `x=14~19` 바닥 타일 | `(14,10)`, `(19,10)` 타일 | `(14,11)`, `(19,11)` 기밀문 | `x=15~18`, `y=10~11`; 기존 침상 3개 |
| 식당 | `y=14`, `x=16~22` 바닥 타일 | `(16,15)`, `(22,15)` 타일 | `(16,16)`, `(22,16)` 기밀문 | `x=17~21`, `y=15~16`; 기존 보관함·식탁 |

이 높이는 대원이 기존 바닥에서 천장까지 실제로 손이 닿는 배치입니다. **천장을 완공한 뒤 옆벽과 문을 건설**하세요. 옆벽부터 세우면 일부 높은 타일에 접근할 수 없어 사다리나 추가 작업 발판이 필요해질 수 있습니다. `R` 구역 보기에서 침실·식당 이름과 경계를 확인합니다. 처음에는 자동문으로 작동하지만, 아래의 지역 산소 공급과 환기를 함께 준비해야 장기간 생활할 수 있습니다.

### 10. 획득한 기술을 배분하고 확장 시간을 유지합니다

대원 패널에서 실제 작업으로 얻은 포인트를 배분합니다. 예제 경로는 나루에게 **굴착 1**, 모아에게 **생활 1**, 솔에게 **공학 1**을 줍니다. 역할을 선택하는 것과 기술에 포인트를 쓰는 것은 별개입니다. XP만 쌓인 상태에서는 작업 속도가 자동으로 빨라지지 않습니다.

휴대 산소 목표는 탱크를 채우거나 장비를 짓는 것으로 완료되지 않습니다. 자동 모드 대원이 저산소 통로에서 실제로 호흡한 시간의 합계가 30초여야 합니다. 필요하면 같은 심부 통로의 `(15,22)`부터 왼쪽으로 탐사를 이어 갑니다. 마스크는 호흡을 도와주지만 열 피해나 침수로 인한 이동 지연은 막아주지 않습니다.

### 11. 방 안의 산소 공급을 보강하고 안전한 확장을 마칩니다

벽을 세운 뒤에는 기존 상층 확산기 한 대의 산소가 먼 침상과 아래층 식탁까지 충분히 도달하지 않습니다. 정상 경로에서도 좁은 식당의 산소가 약0.16까지 내려가 대원이 휴대 산소를 쓰고, 생활 구역 산소 55% 조건이 반복해서 끊겼습니다. 기밀문 네 개를 **열림**으로 바꿔 환기하되 각 방에 실제 산소 공급도 추가합니다. 구조 판정에서는 열린 출입문도 경계이므로 침실·식당 효과는 유지됩니다.

추가 확산기 두 대는 **광석 50·금속 30**이 필요합니다. 심부에서 `(15,22)`, `(15,21)`, `(14,21)`을 순서대로 채굴해 구리를 수거합니다. 이어 기존 `(17,23)` 사다리에서 `(16,23)`부터 `(9,23)`까지 왼쪽 통로를 열면 `(10,23)`, `(9,23)`의 두 구리를 더 얻습니다. 채굴로 밝혀지는 범위와 사다리·귀환 경로를 유지하고, 필요한 재료가 실제 창고에 들어올 때까지 기다립니다.

침실의 빈칸 **`(18,11)`**과 식당의 빈칸 **`(19,16)`**에 산소 확산기를 짓습니다. 두 칸 모두 기존 전선을 사용합니다. 확산기는 방의 금지 산업 설비에 포함되지 않으며 실제로 12W와 조류를 소비해 주변 셀의 산소를 늘립니다. 이 예제는 연구대가 연구 100을 마친 뒤 남는 전력과 기존 수동·수소 발전 및 축전지를 사용합니다.

이 보강 뒤 **안전한 확장 미달 이유**를 확인하며 180초를 유지합니다. 공개 명령만으로 생성한 정상 경로는 게임 시간 **2,188.5초, 19주기째에 20개 목표를 완료**했습니다. 실제 휴대 호흡은 합계617.9초, 배분한 기술은3등급이며 전원 건강100이었습니다. 화면 배속·명령 시점·동선에 따라 완료 시점은 달라집니다. 이후1,200초 운영 수치는 [실행 수치 파일](examples/validation-report.json)에 기록합니다.

## 실제 설비 수지

아래 수치는 v4의 게임용 단위입니다. 표는 **정상 가동 중**을 기준으로 하며 이동·휴식·전력 부족·환경 부적합·자동 대기로 인한 중단 시간은 포함하지 않습니다. 구현 기준은 [engine.js](dist/engine.js), [utilities.js](dist/utilities.js), [community.js](dist/community.js), [frontier.js](dist/frontier.js)입니다.

### 생산·전력·연구

| 항목 | 입력·제약 | 결과 |
|---|---|---|
| 시작 재고 | 광석 240, 금속 140, 조류 100, 석탄 30, 청수 60L, 식량 35 | 초기 준비에 사용 |
| 수동 발전기 | 대원의 실제 운전 | 45W |
| 석탄 발전기 | 연구 20, 석탄 0.025/초 | 60W, 열·이산화탄소 발생 |
| 수소 발전기 | 연구 35, 수소 0.04/초 | 70W, 열 발생 |
| 축전지 | 연결된 회로의 잉여 전력 | 1대당 1,200J 저장 |
| 산소 확산기 | 12W, 조류 0.025/초 | 주변 산소 증가·열 발생 |
| 재배 상자 | 청수 0.012L/초, 12~35°C, 충분한 산소, 침수되지 않은 환경 | 성장 120초 후 대원이 수확하면 식량 1.5 |
| 연구 작업대 | 8W, 청수 0.008L/초, 대원 작업 | 연구 0.24/초, 최대 100 |
| 탄소 정화기 | 연구 10, 10W | 주변 이산화탄소 감소 |
| 물 수집기 | 8W, 상하좌우의 물, 연결된 청수망의 저장 여유 | 최대 0.40L/초 취수 |
| 지하수 유입구 | 월드의 표시된 유입 셀에 공간이 있을 때 | 최대 0.30L/초의 외부 물 공급 |

대원은 초당 포만 0.20을 소모하며 원식량 1끼는 포만 24, 조리식 1끼는 포만 30을 회복합니다. 조리식을 먼저 먹고 부족하면 원식량을 먹습니다. 장기 평균으로 대원 1명당 한 주기에 원식량 약 1끼 또는 조리식 약 0.8끼가 필요합니다. 화면의 식량 잔여 주기는 원식량과 조리식의 합계를 대원 수로 나눈 간단한 지표입니다. 농장 1개는 한 주기에 최대 1.5끼를 생산하므로 시작 농장만으로 세 명을 계속 유지할 수 없습니다. 농장 4개는 이론상 한 주기에 6끼를 만들지만 수확 노동·급수·온도·침수 때문에 실제 생산은 낮아질 수 있습니다.

### 운반·조리·보관·식사

| 항목 | 실제 규칙 |
|---|---|
| 고체 채굴 | 광석·금속·조류·석탄은 채굴 칸의 자원 더미에 남음. 얼음은 기존 물 규칙 적용 |
| 화물 | 대원 한 명이 최대 12개 운반. 약 0.6초 수거 → 실제 이동 → 거점에서 약 0.6초 정리 |
| 코어·보관함 | 코어 기본 고체 용량 600, 완공 보관함마다 +240. 더미·이동 중 화물은 공용 재고에 아직 포함되지 않음 |
| 조리대 | 연구 10, 10W, 청수 0.3L·원식량 2끼·기본 작업 6초 → 조리식 3끼 |
| 조리 목표 | 정수 0~60끼, 기본 12. 목표 도달 시 추가 진행 대기, 0이면 조리 중지 |
| 냉장고 | 연구 30, 6W. 실제 전력 공급 중 공용 식품의 부패 속도 80% 감소 |
| 원식량 부패 | 실온에서 현재 재고의 초당 0.015%, 냉장 중 0.003% |
| 조리식 부패 | 실온에서 현재 재고의 초당 0.030%, 냉장 중 0.006% |
| 실제 식사 | 2초, 조리식 우선. 조리식은 스트레스 3 감소, 식탁 식사는 추가로 4 감소 |
| 식탁 여가 | 실제 방문해 최대 8초 휴식, 초당 스트레스 0.9 감소 |

부패율은 **현재 남은 재고에 적용하는 비율**입니다. 운영 패널의 부패량과 `foodStatus.*DecayPerSecond`는 이 비율을 실제 재고에 적용한 **끼/초**입니다. 냉장고가 설치되어 있어도 전력이 끊기면 실온 비율로 돌아갑니다. 부패한 수량은 재고에서 제거되고 `production.foodSpoiled`에 누적됩니다.

운반 중 필수 생활 행동·역할 변경·교대 변경·경로 단절·사망이 발생하면 화물을 현재 위치의 더미로 되돌립니다. 다른 대원이 다시 수거할 수 있습니다. 공유 창고가 가득 차면 더미는 남고 부족한 용량을 설명합니다. 기존 재고와 철거 환불을 보존할 수 없게 되는 보관함 해체는 거부합니다. 수거 거점은 완공·활성 상태이며 침수되지 않고 도달할 수 있어야 합니다.

**공간별 운반은 채굴품의 수거와 입고까지 구현했습니다.** 입고 뒤 고체는 공용 비축이므로 건설·정화·발전의 최종 투입 자원을 각 설비에 다시 배달하는 작업은 없습니다. 냉장고도 개별 음식 상자가 아닌 공용 식품 재고에 효과를 적용합니다.

### 배관·위생·냉각

| 설비 | 입력 | 출력·효과 |
|---|---|---|
| 코어 | 초기 청수 저장 | 기본 청수 용량 120L |
| 급수 탱크 | 연결된 망의 물 | 청수 80L와 오수 80L를 분리 저장 |
| 각 청수관·오수관 셀 | 해당 레이어의 물 | 레이어별 1L 완충 저장 |
| 수세식 화장실 | 청수 2L, 대원 이용 약 4초, 오수 공간 | 오수 2.2L, 용변 욕구 해소, 위생 감소 |
| 세면대 | 청수 0.65L, 대원 이용 약 2.5초, 오수 공간 | 오수 0.65L, 위생 100 회복 |
| 오수 정화기 | 연구 15, 14W, 오수 최대 0.16L/초, 처리 오수 1L당 광석 0.05 | 처리량의 95%를 청수로 회수 |
| 물 전해장치 | 연구 35, 22W, 청수 0.18L/초 | 산소 스칼라 0.30/초, 수소 0.055/초, 열 |
| 순환 냉각기 | 연구 60, 18W, 청수 0.025L/초, 오수 공간 | 같은 양의 오수, 주변 열린 셀 냉각 |

화장실의 입력보다 많은 오수 0.2L는 이 게임에서 대원의 배설물에 해당하는 추가 물질로 취급합니다. 정화 과정에는 5% 손실이 있어 완전히 닫힌 물 순환은 성립하지 않습니다. 전해장치와 농장도 물을 소비하므로 지하수 취수처럼 지속적인 공급원이 필요합니다.

수소는 **최대 40의 공용 가스 재고**로 단순화했습니다. 수소 배관은 필요하지 않습니다. 전해장치가 멈추면 수소 생산도 멈추고, 발전기는 남아 있는 수소를 소비합니다. 이 숫자는 실제 kg 단위나 화학량론을 뜻하지 않습니다.

냉각기는 설비 주변의 열린 셀을 가동 중 최대 0.10°C/초씩 낮추며 23°C 아래로 냉각하지 않습니다. 배출할 열을 다른 월드 셀에 보존하는 열교환 모델 대신 외부로 제거하는 게임 규칙을 사용합니다. 청수 공급 또는 오수 배출이 끊기면 냉각도 중단됩니다.

### 연결·저장·철거 규칙

- 전선, 청수관, 오수관은 각각 **상하좌우로 인접한 같은 레이어**끼리 연결됩니다. 설비의 입출력 포트는 모두 설비가 놓인 한 칸으로 단순화했습니다.
- 청수·오수는 물리적 저장 슬롯에 남습니다. 전역 재고 표시는 모든 저장의 합계이며, 다른 망의 설비가 그 물을 사용할 수 있다는 보장은 아닙니다.
- 분리된 파이프 안에 남은 소량의 물은 그 망에서 사용할 수 있습니다. 소진되면 원격 저장고에 재고가 남아 있어도 가동이 멈춥니다.
- 탱크를 새로 놓으면 빈 용량이 생깁니다. 연결된 망은 용량에 비례해 물을 재분배합니다. 방향성 파이프 패킷·압력·유속을 개별적으로 계산하지 않습니다.
- 배관 철거 시 관 속 물을 같은 망의 다른 저장칸으로 옮깁니다. 옮길 공간이 없으면 철거가 거부됩니다. 탱크 철거에도 같은 보존 원칙을 적용합니다.
- 건설 계획은 비용을 먼저 냅니다. 미완공 계획 취소는 전액 환불되고, 완공 건물 해체는 각 건설 자원의 75%를 내림해 돌려줍니다. 물 환불도 실제 청수 저장에 반영됩니다.
- 전선·청수관·오수관은 한 칸당 금속 1입니다. 중복 설치·중복 철거로 비용이 반복 차감되거나 자원이 증가하지 않습니다. 청수관·오수관은 정보 패널의 전용 철거로 설비와 다른 선을 보존하며 제거할 수 있습니다. 취소 도구는 완공 배관을 철거하지 않습니다.

## 기밀문·방·휴대 산소·전문 기술

배치 도해와 세부 문제 해결은 [방·장비·안전한 확장 안내](docs/rooms-and-expansion.md)에 있습니다.

### 문은 실제 통로와 유체 경계입니다

기밀문은 광석 6·금속 4를 쓰며 바닥이 있는 한 칸에 건설합니다. **자동**은 대원이 가까이 접근하거나 통과할 때 열리고 비면 닫히며, **열림**은 계속 열리고, **잠금**은 닫힌 채 대원의 경로를 차단합니다. 대원이 서 있는 문을 잠그는 명령은 거부합니다. 잠긴 문 때문에 기존 작업 경로가 막히면 경로와 예약을 다시 판단해야 하므로, 필요한 출입문을 모두 잠그면 생활 설비가 있어도 이용할 수 없습니다.

닫힌 문은 양쪽의 산소·이산화탄소 교환과 지면 물 이동을 막습니다. 셀에 있던 기체나 물을 지우지는 않으며 열은 전도됩니다. 전선·청수관·오수관은 문 칸을 통과할 수 있습니다. 문만 열어도 먼 산소 생산이 모든 방에 충분히 도달한다는 뜻은 아닙니다. 생활 위치의 산소를 확인하고 필요하면 방 내부에 확산기를 두세요. 문이 열려 있으면 실제 기체·물도 지나가지만 **방의 구조 판정에서는 완공된 문을 계속 출입 경계로 취급**합니다. 대원이 한 번 통과할 때마다 침실이 사라지는 식으로 판정하지 않습니다.

### 방은 시설 배치에 따라 효과가 달라집니다

벽은 자연 지형이나 완공한 타일을 사용할 수 있습니다. 전문 방은 내부 6~64칸, 완공한 출입문 1개 이상과 닫힌 외곽이 필요합니다. 월드 끝이나 미탐사 빈 공간으로 열리면 밀폐되지 않은 것으로 판정합니다. `R` 구역 보기와 선택 정보에 실제 범위·유형·충족하지 못한 조건이 표시됩니다.

| 유형 | 필요한 활성 시설 | 함께 두면 성립하지 않는 시설 | 실제 이용 효과 |
|---|---|---|---|
| 침실 | 침상 1개 이상 | 농장·식탁·조리대·화장실·산업 시설 | 침상에서 쉬는 동안 기력 회복 +25%, 초당 스트레스 추가 0.2 회복 |
| 식당 | 식탁 1개 이상 | 침상·농장·화장실·산업 시설 | 실제 식탁 식사 1회마다 스트레스 추가 3 회복; 조리대·냉장고·보관함은 허용 |
| 온실 | 재배 상자 2개 이상 | 침상·식탁·조리대·화장실·산업 시설 | 기본 급수·온도·산소·비침수 조건을 만족할 때 실제 성장 +20% |

여기서 산업 시설은 수동·석탄·수소 발전기, 연구대, 정화기, 전해장치, 취수기입니다. 비활성 시설은 필요한 가구 수에 포함되지 않습니다. 천장이나 벽을 해체하면 연결된 공간을 다시 계산하고, 방이 너무 커지거나 금지 시설과 합쳐지면 효과를 잃습니다. 방 존재만으로 휴식·식사·수확 누계가 늘지는 않습니다. 침실 휴식 초, 식당 식사 횟수, 온실 수확 횟수는 대원의 실제 행동을 기록합니다.

온실의 빠른 성장은 물 공급을 대체하지 않습니다. 급수가 끊기거나 온도·산소·침수 조건이 맞지 않으면 성장도 멈춥니다. 완료 목표에 필요한 방은 침실과 식당 두 종류이며 온실은 선택 가능한 농업 확장입니다.

### 산소는 공기에서 통으로, 통에서 실제 호흡으로 이동합니다

산소 충전소는 연구 45, 광석 20·금속 12로 건설하고 정상 압축 중 8W를 씁니다. 가까운 탐사된 열린 셀에서 초당 최대 0.08의 산소를 압축하되 공급 셀의 산소를 0.35 아래로 빼지 않습니다. 자체 탱크 용량은 18입니다. 전력·주변 산소·비침수·정상 온도가 필요하며 탱크가 가득 차면 대기합니다. 압축 누계는 주변 셀에서 실제로 빠져나간 양입니다.

대원의 휴대 산소통 용량은 6입니다. 자동 모드에서 잔량이 낮고 생활·긴급 행동이 허용하면 대원이 사용 가능한 충전소까지 직접 이동합니다. 충전소 재고에서 휴대통으로 초당 최대 1.5를 옮깁니다. 탱크에 이미 저장된 산소를 옮길 때는 전력이 필요하지 않으며, 충전소가 비활성·침수·접근 불가 상태라면 보충할 수 없습니다. 작업 중단이나 저장 후 재개도 그 시점의 양만 보존합니다.

**자동 사용**은 현재 셀의 공기로 호흡할 수 없을 때만 휴대 산소를 초당 0.055 소비하고 정상적으로 숨을 회복합니다. 물에 잠긴 셀에서도 작동합니다. **사용 안 함**은 잔량을 보존하고 보충·소비를 중지합니다. 빈 통은 일반 숨 감소와 긴급 피난 규칙으로 돌아갑니다. 산소통은 온도 피해·이동 속도·배고픔·기력·위생을 해결하지 않습니다. 사망한 대원의 잔량도 저장 상태에서 사라지지 않습니다.

운영 화면의 충전소 저장량과 대원 휴대량은 실제 탱크 합계입니다. 압축, 대원에게 이송한 양, 실제 소비, 보호받은 호흡 시간은 서로 다른 누계입니다. 설비 해체는 저장 산소를 주변 기체 셀로 반환할 여유가 있어야 하며, 반환할 수 없다면 거부합니다.

### 실제 작업 경험은 직접 배분해야 효과가 생깁니다

대원은 실제로 생산적인 일을 한 시간에 따라 XP를 얻고 **60 XP마다 1레벨·1포인트**, 최대 6레벨까지 성장합니다. 이동·대기·유휴·전력 부족으로 멈춘 시간은 XP가 아닙니다. 포인트를 쓰기 전에는 작업 속도가 변하지 않습니다. 각 기술은 1포인트당 1등급, 최대 3등급이며 역할·교대를 바꿔도 유지됩니다.

| 기술 | 등급당 실제 효과 | 최대 3등급 |
|---|---|---|
| 굴착 | 채굴 작업 속도 +20% | +60% |
| 공학 | 건설·해체 +15%, 연구 작업 +10% | 건설·해체 +45%, 연구 +30% |
| 생활 | 조리·수확 작업 속도 +15% | +45% |

기술은 기존 스트레스 효율에 곱해집니다. 생산 수량이나 자원 보상을 늘리지 않으며, 농장 자체의 성장 속도는 온실 조건이 담당합니다. XP 대상은 실제 채굴·건설·해체 진척 시간, 수동 발전 시간, 전력을 받아 연구가 진행된 시간, 성숙 작물의 수확 작업 시간, 실제 조리 진척 시간입니다. 완료 직전의 마지막 틱은 남은 일에 해당하는 시간만 인정합니다. 성공한 화물 집기·하역은 각각 0.6 XP, 산소 보충은 실제 옮긴 산소량을 초당 이송률 1.5로 나눈 작업 시간만 인정합니다. 이동·유휴·대기·휴식·식사와 전력 없는 연구·조리에서는 XP를 얻지 않습니다.

## 자동 제어와 운영 판단

설비를 선택하고 정보 패널에서 지원되는 자동 제어를 고릅니다. **수동 정지는 모든 자동 제어보다 우선**합니다. 자동화는 충분한 연결·재료·작업자·전력이 있을 때만 가동을 허용하는 추가 조건입니다.

| 제어 | 지원 설비 | 동작 |
|---|---|---|
| 항상 가동 | 일반 설비 | 자동 임계 판정을 생략; 기본 가동 조건은 계속 적용 |
| 배터리 기준 | 수동·석탄·수소 발전기 | 충전율 25% 이하에서 재개, 90% 이상에서 대기 |
| 산소 기준 | 확산기·전해장치 | 주변 산소가 낮아지면 재개하고 충분하면 대기 |
| 온도 기준 | 냉각기 | 주변 평균 27°C 이상에서 재개, 23.5°C 이하에서 대기 |

재개와 정지 기준 사이에서는 직전 상태를 유지하는 **히스테리시스**를 사용합니다. 이 기억은 저장 후에도 유지됩니다. 산소 제어는 내부 산소 스칼라 0.65/1.25를 기준으로 하며, 생활 구역의 표시 백분율과 동일한 숫자는 아닙니다.

빈 배터리만 연결한 경우에도 수동 발전 대원이 충전을 시도합니다. 자동 발전으로 전력 수요를 채울 수 있으면 수동 발전 인력은 다른 일을 할 수 있습니다. 전력량이 충분해도 관이 끊긴 설비는 작동하지 않으므로 정보 패널의 실제 중단 원인을 확인하세요.

## 대원과 실패 회복

대원 카드에서 균형·채굴·건설·운영·농사·운반·조리 역할을 고를 수 있습니다. 역할은 작업 우선 성향이며 식사·호흡·휴식·화장실 같은 필수 행동을 제거하지 않습니다. **연구 12, 금속 20, 청수 10L, 식량 8**을 준비하면 생존 대원 4명까지 영입할 수 있습니다. 추가 대원에게는 침상·식량·산소·위생 처리 여유도 필요합니다.

### 교대와 스트레스

자율 교대는 기존처럼 필요에 따라 일하고 쉽니다. 주간·중간·야간은 한 주기 안에 **작업 79.2초·여가 21.6초·수면 19.2초**를 두고 서로 40초씩 위상을 어긋나게 합니다. 여가는 사용 가능한 식탁에서, 계획 수면은 실제 침상에서 수행합니다. 위험한 호흡·굶주림·용변·기력 고갈은 일정에 우선합니다.

한 번의 계획 수면 기록은 해당 대원의 교대 주기마다 최대 1회입니다. 침상 수면을 6초 이상 해야 인정하며, 저장·불러오기나 일정 변경으로 같은 교대 주기를 반복 적립하지 않습니다. 역할이나 일정을 바꾸면 현재 작업 예약을 해제하고 들고 있던 화물을 보존합니다.

작업은 스트레스를 높이고 조리식·식탁·여가·침상 수면은 이를 낮춥니다. 스트레스 35까지 작업 효율은 100%이며, 이를 넘으면 초과 1점당 효율이 0.8%p씩 내려가 최저 48%가 됩니다. 이 효율은 채굴·건설·해체·연구·조리의 실제 진행에 반영됩니다. 수확 작업 시간과 수동 발전기의 정격 출력은 기존 값을 유지합니다.

| 상황 | 확인할 것 | 회복 방법 |
|---|---|---|
| 채굴했는데 금속이 늘지 않음 | 바닥 더미·운반 역할·거점 접근·용량 | 실제 수거를 기다리고 가까운 보관함·통로 확보 |
| 조리대가 멈춤 | 원식량 2, 청수 0.3L, 전선, 10W, 작업 대원, 목표량 | 막힌 입력·전력·노동을 복구하거나 목표량 조정 |
| 냉장이 꺼짐 | 실제 전력 공급, 침수, 수동 정지 | 발전·축전지·전선과 설비 상태 복구 |
| 계획 수면이 0회 | 교대표, 수면 구간, 침상 접근·예약 | 교대 분산과 침상 경로 확보 후 6초 실제 수면 |
| 건설이 0%에서 멈춤 | 작업 목록의 도달 불가 설명 | 사다리·바닥·옆 칸 접근 경로 확보 |
| 물 재고는 많은데 농장이 멈춤 | 해당 농장의 청수관과 연결된 망 | 포트까지 관 연결, 고립된 공급망 합류 |
| 화장실을 못 씀 | 청수 부족, 오수 공간, 대원 접근·예약 | 양쪽 관·탱크·정화기 및 동선 확보 |
| 정화기가 멈춤 | 오수 입력, 청수 출력 여유, 광석, 전력 | 막힌 포트와 저장 공간을 복구 |
| 전해장치가 멈춤 | 산소 자동 대기, 청수·전력, 수소 저장고 | 실제 중단 이유에 맞춰 공급·소비 조정 |
| 농장 과열 | 온도와 근처 열 발생 설비 | 열원 배치 조정 또는 급·배수 연결 냉각기 |
| 자립·정착 시간이 다시 0 | 목표 패널의 현재 미달 이유 | 연결·비축·건강·위생·냉장·스트레스 조건을 다시 유지 |

용변을 오래 해결하지 못하면 위생과 스트레스에 불이익이 생깁니다. 이 버전은 대원의 생활 필요와 작업 이동을 모델링하며, 원작 수준의 질병·병원균·오염 전파는 구현하지 않습니다.

## 저장과 이전 버전 호환

상단 **저장** 버튼과 15초 간격의 자동 저장은 현재 브라우저의 저장 공간을 사용합니다. 페이지를 떠나거나 숨길 때도 저장을 시도합니다. **조작법** 창에서 저장을 불러오거나 JSON을 내보내고 가져올 수 있습니다. 다른 기기로 옮길 때는 JSON 내보내기를 사용하세요.

v4 저장은 기존 월드·작업·대원·배관·생산·물류·조리·교대·정착 진행에 더해 문 모드와 열림 상태, 충전소·휴대 산소, 마스크 모드, XP·레벨·미배분 포인트·기술, 방 사용 누계와 확장 시간을 포함합니다. 방은 실제 구조로 다시 판정하고 저장된 합계와 모순되는 수치는 검증합니다. 잘못된 값·누락 필드·음수·무한대·물/고체/식품/산소 합계 불일치·예약과 화물 작업 불일치·일정 위상·XP와 기술 포인트 불일치·승리와 목표 불일치는 현재 기지를 덮어쓰기 전에 거부합니다.

정상 **v1·v2·v3 저장을 v4로 변환**합니다. 지형·기존 설비·재고·작업 진행·생산 이력·완료한 목표를 보존합니다. 새 장비·경험·기술 값은 0에서, 휴대 마스크는 자동 모드에서 시작하므로 이전 작업을 소급해 XP나 산소를 지급하지 않습니다. v3에서 16개 목표를 완료했다면 그 이력을 그대로 남기고 네 개의 확장 목표를 계속 도전합니다.

v1 저장은 실제 청수관을 추가해야 할 수 있고, v1·v2 저장은 새 물류·조리·교대 필드를 초기화합니다. 이전에 공용 비축에 있던 고체를 소급해 바닥으로 옮기지 않습니다. v3 저장의 더미·화물·부분 조리·교대·계획 수면은 보존합니다. 이전 저장을 처음 복원하면 새 규칙 안내와 함께 잠시 멈추므로 필요한 동선·설비·장비를 확인한 뒤 재개합니다. 마이그레이션은 원본 JSON이나 이전 브라우저 저장 키를 지우지 않습니다.

### 완성된 기지 예제 가져오기

[examples/self-sustaining-colony.json](examples/self-sustaining-colony.json)은 위의 공개 명령 진행 경로로 실제 승리한 기지입니다. 취수 구역 방수벽도 포함되어 있습니다. 소스 ZIP에 포함된 이 파일을 **조작법 → 세이브 가져오기**에서 선택하면 청수·오수·정화·전해·수소 발전, 보관함·조리대·식탁·냉장고, 세 교대·기밀문·침실·식당·휴대 산소·배분한 기술과 완료한 20개 목표를 관찰할 수 있습니다. 처음에는 `Space`로 멈추고 배관 보기(`V`)·물류 보기(`H`)·구역 보기(`R`)와 정보·대원·물류·운영·목표 탭을 살펴본 뒤 진행하세요. 현재 기지를 남기려면 먼저 세이브 내보내기로 보관합니다. 기본 게임의 시작 상태는 계속 새 기지이며, 예제는 직접 가져올 때만 적용됩니다.

Vanilla JavaScript와 Canvas를 사용합니다. **빠르게 실행하려면 `dist/standalone.html`을 브라우저로 여세요.** 게임의 CSS와 JavaScript를 모두 포함한 파일이므로 정적 서버나 외부 패키지가 필요하지 않습니다. 파일 실행 환경에서 브라우저 저장 정책이 제한되면 조작법의 JSON 내보내기·가져오기로 진행을 보관할 수 있습니다.

소스를 수정하거나 모듈판을 확인할 때는 `dist/`를 정적 HTTP로 제공합니다. 예를 들어 프로젝트 루트에서 다음을 실행한 뒤 `http://localhost:8000`에 접속합니다.

```sh
python3 -m http.server 8000 --directory dist
```

모듈판의 `index.html`을 파일 경로로 직접 열면 브라우저의 ES 모듈 제한에 걸릴 수 있습니다. 소스 변경 뒤 단일 파일을 다시 만드는 명령은 다음과 같습니다.

```sh
npm run build:standalone
```

정적 호스팅 루트는 `dist/`이며 게임 주소에서 기본 제공되는 화면은 모듈판입니다. 두 실행판은 같은 게임 규칙과 저장 형식을 사용합니다.

## 검증

프로젝트 루트에서 Node.js 내장 테스트 러너를 실행합니다.

```sh
npm test
```

동일한 직접 명령은 다음과 같습니다.

```sh
node --test tests/*.test.mjs
```

**회귀 테스트 71개**는 기존 48개를 보존하고 기밀문·구역·장비·기술·v3 호환·20목표 검증 23개를 더한 구성입니다. 저장 버전과 목표 가정은 현재 규칙에 맞췄고, 동굴 붕괴 통제 fixture의 구조 변경에는 새 방 캐시를 함께 재계산합니다. 다음 기능을 실제 시간 진행으로 검증합니다.

- 채굴 완료 직후 공용 재고가 증가하지 않고, 수거→화물→거점 도착 후에만 증가하는지 검사합니다. 역할·교대·긴급 호흡·경로 단절·사망에서 재고+더미+화물 수량을 보존하고 복구 후 한 번만 입고하는지 확인합니다.
- 가까운 실제 보관함 선택, 비활성 거점 회피, 용량이 꽉 찬 더미의 대기, 비축을 사용한 뒤 재수거, 보존 불가능한 창고 해체 거부와 정상 환불을 검사합니다.
- 조리 대원·전력·청수의 실제 요구, 식량2+물0.3→조리식3 수지, 부분 조리 중 급수·전선 단절과 복구, 부분 진행 저장, 목표량 정지를 확인합니다.
- 전력을 받는 냉장고와 꺼진 냉장고의 실제 부패량 차이, 식탁까지 이동한 뒤 소비되는 조리식, 비활성 식탁의 미인정, 침상 6초 계획 수면과 중복 기록 방지, 스트레스에 따른 실제 작업 속도 차이를 확인합니다.
- 실제 v1·v2·v3 진행/승리 fixture 6개의 원본과 진행을 보존하고 v4 저장 왕복을 검사합니다. 재고·예약·화물·조리·일정·XP·산소 탱크/누계·연속 유지·승리 불일치는 현재 기지와 호출자 입력을 바꾸지 않고 거부해야 합니다.
- 닫힌 문이 방의 산소·이산화탄소·물을 보존하고 열은 전도하는지, 열린 문이 실제로 교환하는지, 잠긴 통로의 작업이 멈추고 자동문 복구 뒤 재개하는지 검사합니다. 대원이 점유한 문을 잠글 수 없어야 합니다.
- 완공한 금지 시설은 꺼도 방을 무효화하며, 실제 해체·천장 파괴·복구가 방과 효과를 바꾸는지 검사합니다. 침실의 실제 기력/스트레스 회복, 식당의 소비된 식사와 추가 회복, 온실20%성장·급수 단절·실제 수확을 비교합니다.
- 산소의 주변 셀→충전소→휴대통→호흡 수지와 실제 이동·중단·전력·마스크 전환, 실제 생산 XP와 수동 배분 후 작업 속도 차이를 검사합니다.
- 공개 명령만으로 새 기지부터20개 목표를 완료합니다. 추가 구리를 실제 채굴·운반하고 방과 지역 산소를 구성합니다. 확장 유지 중 충전소를 꺼 시간이 초기화되는 것과 복구 후 승리를 확인합니다. 기존16목표의 냉장 중단·복구 경로도 유지합니다. 승리 뒤 추가10주기 동안 건강·식품·반복 수확·조리·식탁 식사·계획 수면·방 실제 이용과 물/고체/식품/산소 합계를 확인합니다.

정상 경로는 재고·연구·대원 상태·지형을 임의로 주입하지 않습니다. 고립된 경계 테스트만 저장 복제본의 산소·온도·욕구·스트레스·창고 포화·붕괴 벽·시험 작업 상태를 통제해 원인과 결과를 비교합니다. 이 통제 fixture는 예제 승리나 정상 진행에 사용하지 않습니다.

### 예제의 실제 추가 10주기 기록

| 항목 | 첫 승리 | 추가 10주기 뒤 |
|---|---:|---:|
| 게임 시간 | 2,188.5초 | 3,388.5초 |
| 완료 목표·생존 대원 | 20개·3명 | 20개·3명 |
| 대원 건강 | 전원100 | 전원100 |
| 식품 합계 | 약96.8끼 | 약130.3끼 |
| 실제 농업 수확 누계 | 91.5끼 | 145.5끼 |
| 실제 조리 누계 | 51끼 | 75끼 |
| 식탁 식사 누계 | 36회 | 60회 |
| 계획 수면 누계 | 32회 | 57회 |
| 침실에서 실제 휴식 | 합계199.7초 | 합계534.7초 |
| 유효한 식당에서 실제 식사 | 15회 | 39회 |
| 휴대 산소로 실제 호흡 | 합계617.9초 | 합계617.9초 |

검증 기간의 최저 건강은100, 최저 식품은 약96.65끼였고 하층 농장 세 곳은 각각9회씩 수확했습니다. 하층 농장 셀의 물은 최대0.1333으로 중단 임계0.5보다 낮았습니다. 방의 지역 산소 공급을 보강한 뒤 이 추가10주기 동안에는 휴대 산소를 더 소비하지 않았습니다.

완료 목표와 승리 이력은 유지되지만 현재 조건과 연속 유지 시간은 계속 갱신됩니다. 첫 승리에서는 정착240초·확장180초를 채웠고, 추가10주기 끝의 현재 유지 시간은 둘 다140.8초였습니다. 이 기록은10주기 동안 모든 현재 조건이 한 번도 깨지지 않았다는 뜻은 아닙니다. 실제 세부 상태는 [validation-report.json](examples/validation-report.json)에 있습니다.

다음 명령으로 새 기지부터 공개 명령 경로를 다시 실행하고, 첫 승리 저장 왕복·이후10주기 생존/생산을 확인해 예제와 수치를 함께 생성합니다.

```sh
node examples/generate-example.mjs
```

Node 테스트는 시뮬레이션 규칙을 검사합니다. 화면 배치, 모바일 패널, 키보드·터치, 파일 다운로드와 브라우저 저장 동작은 별도 브라우저 검증 대상입니다.

## 확장 지점

- **설비별 최종 배송:** 현재의 실제 채굴품 수거를 건설 현장·조리대·생산 설비의 입력 배송과 지역 재고·컨베이어로 확장할 수 있습니다.
- **배관의 시간 모델:** 현재 망 단위 재분배를 방향성 패킷·유량 제한으로 확장하되 분리·합류·철거의 물 보존 검증을 유지합니다.
- **열과 기체:** 물질별 열용량·질량·상변화를 분리하고, 냉각 폐열과 기체 저장을 명시적인 시스템으로 만듭니다.
- **대원 운영:** 현재 교대·수동 전문 기술·필수 생활 선점을 바탕으로 더 다양한 특성과 질병·사회관계를 추가하고 작업 실패·복구 검증을 유지합니다.
- **콘텐츠와 장기 목표:** 다양한 조리법·축산·지형·복수 거점 등으로 늘리면서, 실제 생산과 공급망 복구가 필요한 목표를 유지합니다.
- **저장 버전 관리:** 현재의 실제 v1·v2·v3 fixture를 보존하고, 이후 버전도 변환 전 검증·비파괴 변환·변환 후 왕복 검증을 분리합니다.
