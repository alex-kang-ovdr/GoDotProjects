# 기술 구현 구조

## 1. 시스템 목적과 역할
시스템: GameLoop, Input, Player, WeaponSystem, ProjectileSystem, EnemySystem, SpawnDirector, Collision, Loot, UpgradeDraft, Evolution, StageDirector, MetaProgression, Save, UI. 데이터 지향적 업데이트와 풀링으로 대량 객체를 처리한다.

## 2. 규칙과 구현 관점
고정 timestep 또는 dt 상한, broadphase spatial hash, 객체 풀, 배치 렌더링, 데이터 테이블 JSON, 결정적 시드 기반 테스트. 저장은 버전 관리와 마이그레이션을 포함한다.

## 3. 주요 상태/데이터
- 설정값은 코드에서 분리해 JSON 또는 데이터 테이블로 관리한다.
- 전투 중 상태 변화와 UI 표시 이벤트를 분리한다.
- 스테이지 시작, 일시정지, 사망, 클리어, 재시작 시 경계 조건을 처리한다.

## 4. 예외 및 QA 항목
- 프레임 드랍 및 일시정지/재개 시 시간 계산 오류가 없어야 한다.
- 중복 보상, 중복 이벤트, 객체 풀 재사용 후 잔존 상태를 검증한다.
- 실제 게임과의 일치 여부는 플레이 영상/버전별 실측으로 확인한다.

## 5. 역기획 검증 상태
- **대표 메커니즘**: 장르와 게임 플레이 관찰에 근거한 개념 분석.
- **구현 제안**: 원작 내부 코드가 아닌 재구성 설계.
- **미확정**: 세부 수치, 드랍 확률, 패치별 콘텐츠.
