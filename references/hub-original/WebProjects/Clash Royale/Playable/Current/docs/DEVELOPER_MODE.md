# 개발자 테스트: 양 팀 조작과 실시간 카드 밸런스

개발자 테스트는 한 경기 안에서 양 팀의 카드를 직접 배치하고 카드별 전투 수치를 바꾸는 실험 모드다. 현재 경기의 카드 정의와 살아 있는 병력에 변경 사항을 적용하며, 기본 카드 데이터나 다른 경기의 설정은 수정하지 않는다. 일반 승수·캠페인 메달·정상 리플레이와 분리된 자유 연습 경기로 실행한다.

화면 방향과 2D·3D 전환, 대상 검사·기존 치트의 기본 조작은 [화면과 도구 문서](LAYOUT_AND_TOOLS.md)를 참고한다. 이 문서는 개발자 테스트에 추가된 양 팀 조작, 실시간 수치 편집과 저장 계약을 설명한다.

## 1. 사용 흐름

외부 좌측 설정 패널의 **개발자 테스트 시작**으로 들어간다. 작은 화면에서는 전장 바깥의 **☰ 설정**을 열어 같은 패널을 사용한다. 일반 대전이나 캠페인의 진행 중 수치를 변경하는 방식이 아니며, 개발자 기능은 해당 모드에서만 활성화된다.

처음 들어가면 양 팀에 현재 선택한 개인 덱을 동일하게 배정하고, AI는 끈 상태로 시작한다. 양 팀 무한 엘릭서는 켜져 있다. 기본 시드는 4401이며, 양 팀을 직접 조작해 같은 조건의 병력을 비교할 수 있다. AI를 함께 시험하려면 연습의 AI 옵션을 켠다.

1. **조작 진영**에서 아군 또는 적군을 선택한다. 키보드에서는 `T`로 전환한다.
2. 선택한 진영의 실제 손패를 고르고 전장에 배치한다. 두 팀은 각자의 손패·대기열·엘릭서를 유지한다.
3. 덱에 없는 카드를 시험하려면 **조절할 카드**에서 고른 뒤 **이 카드 · 아군 배치** 또는 **이 카드 · 적군 배치**를 사용한다. 이후 전장을 누를 때마다 같은 카드를 직접 소환할 수 있고 `Escape`로 선택을 취소한다. 직접 소환은 손패를 순환시키지 않는다.
4. **수치를 적용할 진영**을 양 팀·아군·적군 중에서 고른다. 필드 값을 변경하면 해당 진영의 카드 정의와 현재 병력에 적용한다.
5. 필요하면 일시정지한 상태에서 수치를 바꾼 뒤 계속해 실제 공격·이동·방어 결과를 비교한다.

조작 진영과 수치 적용 진영은 서로 다른 설정이다. 예를 들어 적군 손패로 병력을 내면서 아군 기사의 HP만 올릴 수 있다. 카드별 설정도 따로 유지하므로 한 카드의 초기화가 다른 카드의 변경을 지우지 않는다.

모바일 drawer에서 양 팀 손패나 직접 소환 버튼을 누르면 drawer를 닫고 해당 카드의 선택·조준으로 돌아간다. 진영 선택 버튼만 바꿀 때는 drawer를 유지한다. 키보드 `T`는 게임에 입력할 수 있는 상태에서 동작하며, drawer·다른 모달·입력 필드의 키 조작을 가로채지 않는다. 설정 창을 여는 것만으로는 자동 일시정지하지 않으므로 정지 상태에서 비교하려면 먼저 일시정지를 사용한다.

## 2. 손패 조작과 카드 직접 소환

| 방식 | 손패·대기열 | 비용과 배치 | 사용할 수 있는 카드 |
|---|---|---|---|
| 양 팀 손패 조작 | 해당 팀의 실제 4장 손패와 4장 대기열을 순환한다. | 해당 팀의 현재 카드 비용과 정상 배치 규칙을 검사한다. | 해당 팀의 덱에 포함된 카드 |
| 편집 카드 직접 소환 | 손패와 대기열을 변경하지 않는다. | 같은 비용·배치·피해·분대 생성 경로를 사용한다. | 카드 목록에 있는 모든 카드 |

두 방식 모두 실제 엔진의 배치 가능 여부를 사용한다. 화면 미리보기와 최종 배치는 같은 진영과 같은 월드 좌표를 전달한다. 가로 화면에서는 적군이 왼쪽, 아군이 오른쪽이며 2D·3D에서도 이 진영 배치를 유지한다. 적군을 조작해도 양 팀의 소속 자체를 서로 바꾸지 않는다.

직접 소환은 살아 있는 병력·타워와의 충돌, 전장 범위, 배치 지연과 주문 시전 지연을 유지한다. 분대 카드도 실제 구성원과 분대 ID를 생성하므로 원래 덱에 없던 밀집보병의 스킬을 사용할 수 있다. 일시정지 중에는 카드 소환과 스킬 발동이 거절되며 설정 변경만 허용한다.

## 3. 수치 편집이 적용되는 시점

수치 편집은 팀별 카드 패치를 부분 병합한다. 예를 들어 아군 기사에 `{ hp: 1600 }`을 적용한 다음 `{ damage: 220 }`을 적용하면 두 변경이 모두 유지된다. **양 팀 공통**은 선택한 필드를 양쪽에 적용한다. 이전에 서로 다른 값으로 설정한 다른 필드를 자동으로 같게 만들지는 않는다.

숫자 입력과 슬라이더는 값을 바꾸는 즉시 적용한다. 양 팀 값이 다르면 편집기는 아군 값을 기준으로 표시하고 **값 다름**을 알린다. 그 상태에서 변경한 필드만 양 팀에 같은 값으로 반영한다. 예를 들어 두 팀의 HP와 피해가 모두 다른 상태에서 HP만 바꾸면 피해의 팀별 차이는 유지된다.

| 대상 | 변경 후 동작 |
|---|---|
| 이후 새로 배치하는 병력·건물 | 해당 팀의 최신 카드 정의로 생성한다. |
| 현재 살아 있는 같은 카드의 병력 | UI의 즉시 적용으로 현재 전투 수치를 갱신한다. 위치·소속·개체 ID는 유지한다. |
| 현재 HP | `현재 HP / 기존 최대 HP` 비율을 새 최대 HP에 적용한다. |
| 공격 대기 | 기존 공격 간격 대비 남은 대기의 비율을 유지한다. |
| 죽은 병력·파괴된 타워 | 부활시키지 않는다. |
| 기절·동결·감속 | 독립된 상태 타이머를 초기화하지 않는다. |
| 이미 발사된 투사체 | 발사 당시의 피해와 전투 속성을 유지한다. |
| 시전 대기 중인 주문 | 시전 당시의 카드 수치를 유지한다. 이후 편집으로 예약된 피해가 바뀌지 않는다. |
| 이미 생성된 독 안개 | 해당 지역이 생성될 때의 피해·반경·시간을 유지한다. |

예를 들어 최대 HP 1,000인 기사가 현재 HP 350이라면 최대 HP를 1,600으로 바꾼 뒤 HP는 560이 된다. 이는 체력을 최대치까지 회복하는 동작과 다르다. 공격 간격 1초 중 다음 공격까지 0.6초 남은 상태에서 간격을 2초로 바꾸면 남은 시간은 1.2초가 된다. 같은 시점의 기절·동결·감속은 별도로 유지된다.

편집 중에는 `tick`, 전투 시간과 일시정지 여부를 바꾸지 않는다. 값을 바꿨다는 이유로 유닛을 즉시 공격시키거나 시뮬레이션을 한 프레임 진행하지 않는다. **이 카드 기본값**은 선택한 카드와 적용 진영의 패치를 지우며, 현재 병력에도 같은 비율 보존 원칙으로 기본값을 다시 적용한다.

**모든 카드 기본값**도 현재의 적용 진영 선택을 따른다. 아군만 선택했다면 적군의 편집값은 남겨 두고 아군 카드들을 초기화한다. 카드 수치의 초기화와 무한 엘릭서·배치 구역 같은 개발자 옵션은 별개다.

## 4. 편집 가능한 필드

편집기는 `getBalanceFields(cardId)`가 제공하는 필드만 표시한다. 병력·건물·주문·분대의 성격에 따라 목록이 다르다. 아래 표의 필드를 모든 카드에 일괄 적용할 수 있다는 뜻은 아니다.

| 범주 | 주요 필드 | 해석 |
|---|---|---|
| 공통 비용·배치 | `cost`, `deployTime` | 엘릭서 비용과 배치 대기 시간 |
| 병력·건물 전투 | `hp`, `damage`, `attackInterval`, `range`, `splashRadius` | 최대 HP, 1회 공격 피해, 공격 간격, 사거리, 광역 반경 |
| 이동·투사체 | `speed`, `projectileSpeed` | 월드 단위/초 기준 속도 |
| 주문 | `damage`, `crownDamage`, `spellRadius`, `duration` | 일반 피해, 타워 피해, 효과 반경과 시간 |
| 건물 | `duration` | 소환 건물 수명 |
| 밀집보병 | `damageReduction`, `chargeSpeed`, `abilityCost`, `abilityDuration`, `abilityCooldown` | 방진 피해 감소 비율과 돌격 수치 |

필드별 `min`·`max`는 엔진의 허용 범위다. `step`은 UI 증감 간격이며, 그 배수만 허용하는 서버식 양자화 규칙은 아니다. API는 허용 범위 안의 유한한 수를 받는다. 문자열 `"220"`, `NaN`, `Infinity`, 잘못된 카드·필드 이름, 중첩 객체 값과 허용되지 않은 진영은 거절한다.

여러 필드를 함께 바꿀 때는 모든 값을 먼저 검증한다. `{ hp: 1600, damage: Infinity }`처럼 일부 값이 잘못되면 HP까지 포함한 변경 전체가 거절된다. 양 팀 적용에서도 한쪽만 일부 변경된 상태를 남기지 않는다. 반환된 카드·필드 설명·개발자 설정을 외부에서 수정해도 게임 내부로 변경이 전파되지 않는다.

## 5. 개발자 옵션과 밀집보병 규칙

### 5.1 자원·재사용 대기·배치 구역

| 옵션 | 효과 | 유지되는 제한 |
|---|---|---|
| 아군/적군 무한 엘릭서 | 해당 팀의 자원을 상한 10으로 유지하고 카드·스킬 비용 결제 뒤 보충한다. | 카드 사용 수와 명목 비용에 따른 소비 통계는 기록한다. |
| 스킬 재사용 대기 없음 | 분대의 재사용 대기 조건을 우회한다. | 배치 대기, 일시정지, 이미 진행 중인 돌격과 다른 실제 발동 조건은 유지한다. |
| 양 진영 어디든 배치 | 병력·건물의 아군 구역 제한을 해제한다. | 전장 경계, 다리 밖의 강물, 구조물·병력 충돌 조건은 유지한다. |

이 옵션들도 일시정지 상태에서 설정할 수 있다. 양 팀의 무한 엘릭서는 각각 켜고 끈다. 엔진 API에서 개발자 게임을 새로 만들면 옵션은 모두 꺼져 있으며, UI는 개발자 테스트 시작 시 양 팀 무한 엘릭서를 명시적으로 켠다.

배치 구역 제한을 해제해도 실제 몸체가 강물이나 구조물을 통과해 생성되지는 않는다. 공통 배치 탐색이 근처의 안전한 빈칸을 찾으면 미리보기의 최종 위치로 보정하고, 적절한 공간이 없으면 거절한다. 원래 클릭 중심과 유닛 생성 중심이 항상 같다는 뜻은 아니다.

무한 엘릭서의 소비 통계는 실제로 부족해진 자원을 뜻하지 않는다. 예를 들어 비용 7 카드를 사용하면 엘릭서는 결제 뒤 10으로 보충되고, 소비 통계에는 7이 기록된다. 일반 대전과 직접 비교할 때는 이 개발자 옵션의 사용 여부를 함께 보아야 한다.

### 5.2 규칙 4의 밀집보병

새 경기의 밀집보병은 **방진이 실제로 성립했을 때 피해를 70% 줄이고, 돌격 중에만 공격한다.** 방진·배치·재집결 중에는 이동과 대형 유지에 집중한다. `formationProtected`가 거짓이면 현재 모드 이름이 방진처럼 보이더라도 피해 감소를 적용하지 않는다. 기절, 부족한 생존 인원이나 대형 이탈로 방어 조건을 잃을 수 있다.

기본 피해 감소 비율 0.70에서 보호 조건을 만족한 병사가 원래 피해 100을 받으면 실제 HP 감소는 30이다. 돌격으로 대형을 풀면 이 보호를 잃고 공격을 시작한다. 개발자 편집에서 `damageReduction`을 바꾸면 그 경기·진영의 조건부 감소 비율이 바뀌며, 보호 조건 자체를 무조건 참으로 만들지는 않는다.

구버전 규칙 2·3의 저장과 리플레이는 이전 규칙을 유지한다. 규칙 3 밀집보병의 35% 피해 감소와 이전 공격 동작을 최신 규칙으로 조용히 치환하지 않는다. 캠페인도 새 시도는 규칙 4를 사용하지만, 규칙 버전이 없던 과거 캠페인 context와 진행 중 규칙 3 게임은 기존 규칙으로 이어간다.

## 6. 개발 API

```js
const game = new Game({
  developerMode: true,
  practice: true,
  rulesVersion: 4,
  seed: 4401,
});

const current = game.getCard('knight', 'enemy');
const fields = game.getBalanceFields('knight');
const developer = game.getDeveloperState();

game.setCardBalance('knight', { hp: 1600, damage: 220 }, {
  team: 'enemy',       // 'both' | 'player' | 'enemy', 기본 'both'
  applyExisting: true // 기본 true; false면 현재 병력은 유지
});

game.setDeveloperCheats({ infiniteElixir: { player: true, enemy: true } });
game.start();
game.spawnDeveloperCard('enemy', 'knight', 210, 210);
game.resetCardBalance('knight', 'enemy');
```

`getCard()`의 기본 진영은 `player`다. 그리기·AI·손패 비용·카드 설명은 현재 경기와 진영의 정의를 조회해야 한다. 전역 `CARDS`만 읽으면 개발자 편집 결과를 표시하지 못한다. 이미 전장에 있는 개체의 HP·공격 대기 등은 개체 상태를 우선 읽는다.

| API | 반환·역할 |
|---|---|
| `getCard(cardId, team = 'player')` | 해당 규칙·경기·진영에 적용되는 카드 정의 |
| `getBalanceFields(cardId)` | `{ key, label, min, max, step, unit }` 필드 설명 배열 |
| `getDeveloperState()` | `{ enabled, balance, cheats }` 복사본 |
| `setCardBalance(cardId, patch, options)` | 검증 후 팀별 패치 부분 병합 및 선택적 현재 병력 갱신 |
| `resetCardBalance(cardId, team = 'both')` | 해당 카드·팀의 패치 제거 |
| `setDeveloperCheats(patch)` | 알려진 옵션의 부분 갱신 |
| `spawnDeveloperCard(team, cardId, x, y)` | 손패를 순환시키지 않는 실제 카드 배치 |

상태 변경 API는 성공 시 `{ ok: true, ... }`, 거절 시 `{ ok: false, reason }`을 반환한다. 일반 경기·기존 자유 연습·훈련·리플레이·종료 경기에서 개발자 변경을 허용하지 않는다. 개발자 생성 조건 자체가 잘못된 경우에는 생성자가 예외를 던진다. `developerMode:true`는 `practice:true`, `rulesVersion:4` 및 훈련이 아닌 모드를 함께 요구한다.

## 7. 저장·복원과 리플레이 경계

### 7.1 다시 시작과 이어하기

| 사용자 동작 | 유지되는 설정 |
|---|---|
| 현재 개발자 테스트에서 재시작 | 팀별 카드 편집값과 개발자 옵션을 유지하고 전장을 새로 만든다. |
| 개발자 일시정지 창의 재시작·결과 창의 다시 하기 | 같은 편집값과 옵션으로 새 실험을 시작한다. |
| 일반 모드로 나갔다가 개발자 테스트 시작 | 기본 카드 수치에서 새로 시작한다. UI의 초기 무한 엘릭서 설정을 적용한다. |
| 개발자 경기 저장 후 이어하기 | 현재 병력·전투 상태, 카드 편집값·옵션과 조작 진영을 복원한다. |

이 동작은 실험 조건을 유지한 재시도와 새로운 기본 조건의 실험을 구분한다. 다른 경기나 전역 카드 데이터까지 편집값이 영구 적용되는 방식은 아니다.

### 7.2 엔진 스냅샷

개발자 스냅샷은 기존 엔진 저장 형식의 `config.developerMode:true`와 최상위 `developer` 항목에 설정을 포함한다.

```json
{
  "version": 1,
  "balance": {
    "player": { "knight": { "hp": 1600 } },
    "enemy": {}
  },
  "cheats": {
    "infiniteElixir": { "player": true, "enemy": true },
    "noAbilityCooldown": false,
    "freePlacement": false
  }
}
```

위 예시는 `snapshot.developer` 부분만 나타낸다. 현재 병력, 손패, 시전 대기 주문, 분대 상태와 난수 진행은 기존 엔진 스냅샷의 다른 항목에 함께 저장된다. 복원은 일시정지 상태로 시작한다. 저장 객체의 잘못된 키·자료형·숫자 범위와 개발자 설정·게임 모드의 불일치를 검증한 뒤 게임을 구성한다.

규칙 2·3의 일반 저장에는 새 개발자 필드를 덧붙이지 않는다. 반대로 개발자 저장에서 모드 표시만 지워 일반 경기처럼 가져오거나, 허용되지 않은 규칙 버전으로 바꾸는 입력은 거절한다.

### 7.3 명령과 기록의 분리

개발자 직접 소환 명령은 `type:'developer-spawn'`과 진영·카드·좌표를 기록하며 손패 슬롯 번호를 갖지 않는다. 밀집보병은 소환 명령의 `groupId`와 실제 분대를 연결한다. 이 기록은 스냅샷의 상태 바인딩에 사용되며 일반 리플레이 내보내기 형식으로 제공하지 않는다.

개발자 경기는 `exportReplay()`에서 거절하고, 리플레이 생성자와 파일 직렬화·파싱 경로도 개발자 기록을 차단한다. 실험 결과는 일반 전적·캠페인 메달·일반 리플레이 기록에 합산하지 않는다.

## 8. 검증 범위

전용 [developer.test.mjs](../tests/developer.test.mjs)는 권한 경계, 전역·경기·팀별 격리, 원자 검증, 실시간 HP·공격 진행률, 기존 투사체·주문·독 안개, 양 팀 손패, 직접 소환 분대 바인딩, 옵션의 실제 동작, 엄격한 복원과 리플레이 차단을 확인한다. [campaign.test.mjs](../tests/campaign.test.mjs)는 새 규칙 4 시도와 구 규칙 3 진행 중 캠페인의 구분을 검사한다.

다음 범위 실행에서 개발자 검사 **12개**와 캠페인 검사 **17개**, 총 **29/29개가 통과**했다. 실패·건너뜀은 0개다. 프로젝트 전체 회귀나 렌더러·AI 전용 검사의 합계와 구분한다.

```sh
node --test tests/developer.test.mjs tests/campaign.test.mjs
```

실제 브라우저·GPU의 최종 시각·터치·성능 검증은 이 문서의 Node 검증과 구분한다. 모의 GL 호출이나 독립 Canvas 출력으로 개발자 패널의 실제 모바일 스크롤·포커스·터치 사용성까지 검증한 것으로 보지 않는다.

최종 통합에서는 `node --test --test-reporter=tap tests/*.test.mjs`로 **190개 전체 검사 통과, 실패 0, 건너뜀 0**을 확인했다. 여기에는 위 29개 외에 실제 앱 함수의 양 팀 제어·표시 5개, 개발자 AI 6개와 렌더러 3개, 새 방진 규칙·과거 전투 호환 검사도 포함된다.
