# 문서 범위·자료 기준·확인 수준

## 1. 산출물의 목적

브롤스타즈를 새로 이해하고 유사한 전투·목표 구조를 설계할 수 있도록,
공통 시스템과 모드별 의사결정을 분해한 한국어 역기획서다.
공개 규칙의 요약, 그 규칙이 만드는 플레이 경험, 재구현 시 필요한 명세를 함께 제공한다.

**조사 기준일은 2026-11-13(KST), 가장 최근 확인한 공식 패치 문서는 2026-11-11 갱신본이다.**
실제 설치된 클라이언트의 빌드 번호·현재 이벤트 슬롯·계정별 개인화 화면은 확인하지 않았다.
따라서 “공지에 포함됨”과 “오늘 모두 플레이 가능함”을 같은 의미로 사용하지 않는다.

## 2. 포함 범위

| 구분 | 범위 |
| --- | --- |
| 공통 시스템 | 코어 루프, 조작, 전투, 능력, 맵, 조합, 네트워크 제안, 데이터, 성장, 경제, 퀘스트, 경쟁전, 매칭, 소셜, 운영, UX, 표현, AI |
| 주요 모드 | 기본 3대3·쇼다운·듀얼 등 |
| 인원 변형 | 5대5와 4팀 대전의 별도 분석 |
| 이벤트 | 스포츠·운반·점령·협업·강화·런 변형 |
| 역사 모드 | 과거 규칙을 시점과 함께 기록 |
| 신규 발표 | 공개된 규칙 범위에 한정한 분석 |
| 기술 | 공개 사실과 분리한 데이터·상태·이벤트·QA 제안 |

**56개의 선택된 모드·변형을 개별 문서로 제공한다.**
게임 역사상 모든 단기 실험·2대2 프리셋·콜라보 명칭·이벤트 보스 스킨을 전수 복원한 목록은 아니다.
규칙을 바꾸지 않는 맵·외형 변형과 다수의 단순 이벤트 수치 변경은 시스템 문서에 통합했다.
경쟁전은 여러 전투 모드를 묶는 선발·등급 포맷이므로 시스템 문서로 분리했다.

## 3. 표기 규약

| 표기 | 의미 | 읽을 때 주의 |
| --- | --- | --- |
| [공식] / [확인] | 공식 페이지 또는 공식 검색 색인에서 확보한 공개 규칙 | 두 표기는 같은 확인 범주 |
| [보조] | 명시한 커뮤니티 자료의 설명 | 공식 확정이나 실기 관찰로 승격하지 않음 |
| [해석] | 규칙에서 도출한 독립적인 설계 분석 | 개발팀이 밝힌 의도와 다름 |
| [제안] | 유사 시스템을 구현하기 위한 명세·의사코드·QA | 원작의 내부 구현이 아님 |
| [미확인] | 출처만으로 확정할 수 없는 값·판정·운영 상태 | 임의 숫자로 빈칸을 채우지 않음 |

각 문서의 수식과 코드 블록은 별도 표기가 없는 한 분석 또는 재구현 제안이다.
정확한 서버 틱, 물리 엔진, 충돌 우선순위, 드롭 난수 구현, MMR 공식은 확인하지 않았다.

## 4. 출처 우선순위

1. 같은 기능에 대한 더 최근의 공식 변경·유지보수 공지.
2. 갱신 상태가 확인되는 공식 고객지원 설명.
3. 기능 도입 시점의 공식 자료.
4. 명시적으로 낮은 근거 수준을 표시한 커뮤니티 설명.
5. 독립적인 해석과 재구현 제안.

페이지의 “최근 수집일”은 내용의 규칙 버전과 같지 않다.
오래된 공지가 오늘 검색되었다고 현재 규칙으로 간주하지 않는다.
한 패치 문서 안에서도 맨 위 유지보수 항목이 본문의 초기 수치를 바꿀 수 있다.

## 5. 자료 접근 제한

사용자가 제공한 [나무위키 브롤스타즈 문서](https://namu.wiki/w/%EB%B8%8C%EB%A1%A4%EC%8A%A4%ED%83%80%EC%A6%88)는 열기를 시도했으나 본문을 확보하지 못했다.
읽지 못한 원문을 읽은 것처럼 요약하거나 그 페이지의 세부 항목을 검증 근거로 사용하지 않았다.
공식 블로그·지원 문서로 보완했다.

일부 과거 공식 블로그 URL은 직접 열면 제목과 Loading 화면만 반환했지만,
검색 서비스에 저장된 공식 본문은 확인할 수 있었다.
해당 문서에는 검색 색인의 확인 범위를 표시했다. 검색에서 보이지 않은 문맥이나 전체 규칙을 추정하지 않았다.

## 6. 주요 버전 경계

| 주제 | 혼동하기 쉬운 자료 | 이 문서의 원칙 |
| --- | --- | --- |
| 가젯 | 과거 사용 횟수 제한 | 재사용 대기형으로 분석 |
| 경쟁전 | 구형 진입·레벨·초기화 설명 | 최신 공지와 갱신 지원 페이지 대조 |
| 브롤러 해금 | Starr Road 시기 | Brawler Blast 변경과 구분 |
| Buffies | 출시 범주와 이후 획득 정책 | 능력·외형·경로·사용 자격 분리 |
| 하이스트 | 보호막 없는 과거 레이스 | 단계 보호막의 도입 이력과 미확인 경계 표기 |
| 핫 존 | 점령 게임 일반 관행 | 적 동시 진입이 자동 차단이라는 가정 금지 |
| 녹아웃 | 초기 피해량 타이브레이커 | 독구름 개편과 구분 |
| 보스전 | 역사적 3인·4월 5인 | 20인 변형 언급도 분리, 전체 일괄 인원 단정 금지 |
| 스포츠 변형 | 기본 브롤 볼의 시간·목표 | 변형별 미확인 값을 자동 상속하지 않음 |
| 런 이벤트 | 유사 화면과 이름 | 층수·후보·소모·보상 규칙을 각 버전별 관리 |

정확한 숫자와 출처는 해당 시스템·모드 문서에서 확인한다.
이 표는 수치를 다시 전사하기보다 잘못된 일반화를 막기 위한 색인이다.

공개되지 않은 원작 판정을 확정하지 않으면서 설계 압력·데이터·검증 계획을 상세히 제공한다.

## 8. 이번 작업에서 수행한 검증

- 문서별 확인 사실·해석·제안·미확인 구분 검토.
- 핵심 규칙의 최신 공지와 과거 자료 대조.
- 다른 작성 단위 사이의 교차 검토와 모순 수정.
- UTF-8, 파일 목록, 상대 링크, 코드 펜스, 출처 절 검사.
- ZIP 내용과 원본 파일 일치 검사.

게임 앱 플레이, 서버/클라이언트 코드 분석, 네트워크 캡처, 실제 승률·유저 행동 통계 수집은 수행하지 않았다.
QA 표는 **앞으로 실행할 수용 기준과 실험 계획**이며 실제 통과한 게임 테스트 목록이 아니다.

## 9. 활용 순서

게임 구조를 이해하려면 [시스템 관계도](01_system_map.md)와 [모드 비교](02_mode_comparison.md)를 먼저 읽는다.
특정 모드를 재구현하려면 해당 모드의 확인 규칙을 확정한 뒤 [규칙 데이터](systems/08_data_rules_qa.md)를 사용한다.
미확인 규칙을 선택해 새 게임을 만든 경우에는 “원작 동일”이 아니라 선택한 설계로 기록한다.
