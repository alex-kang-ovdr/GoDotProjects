# Brawl Lab 4.0 — 코어 게임플레이 구현 계약

이 문서는 현재 실행 코드의 모듈 경계와 데이터 규약을 설명한다. 원작의 비공개 사양을 복원한 문서가 아니라, 역기획에서 선택한 핵심 상호작용을 **로컬 봇 대전으로 구현한 프로젝트의 실제 사양**이다. 실행 방법과 변경 내역은 [README.md](README.md)를 참조한다.

## 1. 구성과 실행 순서

```text
index.html → engine.js → renderer.js → app.js
```

| 파일 | 책임 | 외부 의존성 |
|---|---|---|
| `dist/engine.js` | 전투, 충돌, AI, 모드 규칙, 승패, 통계 | 없음 |
| `dist/renderer.js` | Canvas 2D 전장과 시각 효과, 좌표 변환 | 브라우저 Canvas API |
| `dist/app.js` | 입력, 로비, HUD, 모달, 오디오, 설정, 게임 루프 | 브라우저 DOM·WebAudio·localStorage |
| `dist/styles.css` | 화면 크기별 UI 배치 | 없음 |
| `scripts/package.py` | 독립 실행 HTML과 소스 ZIP 생성 | Python 표준 라이브러리 |

빌드 과정이나 서버 연결 없이 실행한다. 전장 좌표는 항상 **1280 × 800 월드 픽셀**이다. 렌더러는 전체 보기의 letterbox와 추적 보기의 확대·이동을 화면 크기에 맞춰 적용한다. 캐릭터와 배경은 Canvas 도형으로 그리는 독자 디자인이다.

## 2. 시뮬레이션 API

브라우저에서는 `globalThis.BrawlCore`, Node에서는 `require('./dist/engine.js')`로 접근한다.

```js
const { Game, HEROES, MODES } = globalThis.BrawlCore;
const game = new Game({
  mode: 'gem',       // gem | showdown | ball | hotzone | heist | knockout | bounty | training
  hero: 'ranger',    // ranger | tank | blaster
  difficulty: 'normal', // easy | normal | hard
  seed: 2026
});

game.update(1 / 60, {
  moveX: 0, moveY: 0,   // 대각선은 엔진에서 정규화
  aimX: 900, aimY: 400, // 절대 월드 좌표
  fire: false,         // 누르고 있는 동안 반복 사격
  super: false,        // 누름 에지
  gadget: false        // 누름 에지
});

const aim = game.getAutoAim(0);
// { x, y, targetId, kind: 'enemy' | 'crate' | 'goal' | 'safe' | 'forward' }
const player = game.player; // actor id 0
```

`update`는 초 단위 시간 값을 받으며 한 호출을 최대 0.25초로 제한하고 내부적으로 최대 1/60초씩 나눈다. 특수 공격과 가젯은 한 번 누른 입력이 여러 내부 스텝에서 중복 발동하지 않는다. 앱은 별도로 60Hz 고정 스텝을 누적 실행한다. 탭 비활성화나 일시정지 이후 밀린 시간을 따라잡으려고 경기 시간을 급진전시키지 않는다.

동일한 seed·입력·스텝 시퀀스는 동일한 시뮬레이션을 만든다. 실제 플레이 시작 시 앱은 매 판 새 seed를 선택한다. 메뉴 미리보기는 일정한 seed로 초기 구도를 만든 뒤 고정한다.

### 캐릭터 설정

| ID / 이름 | 최대 체력 | 속도 | 기본 사거리 | 기본 공격 | 재장전 1칸 | 가젯 대기 |
|---|---:|---:|---:|---|---:|---:|
| `ranger` / 핀 | 3,600 | 238 px/s | 495 px | 직사탄 650 | 1.02초 | 12초 |
| `tank` / 브릭 | 5,900 | 216 px/s | 300 px | 산탄 5발, 총 1,200 | 1.30초 | 16초 |
| `blaster` / 코멧 | 3,250 | 224 px/s | 540 px | 폭발탄 기본 850 | 1.50초 | 15초 |

사거리는 **캐릭터 중심부터의 전체 발사 거리**다. `HEROES`는 `projectileRadius`, `shotSpeed`, `superName`, `superDescription`, `gadgetName`, `gadgetDescription`, `gadgetCooldown`도 제공한다. 폭발 거리 감쇠·파워·보호막·난이도 보정에 따라 실제 피해는 달라질 수 있다.

### 자동 조준

자동 조준은 현재 관찰자에게 보이고 기본 사거리 안에 있으며 투사체 반경을 고려한 시야가 확보된 적을 찾는다. 이동 예측점이 엄폐물 뒤나 사거리 밖이면 현재 위치를 사용한다. 바운티에서는 후보를 고를 때 현상금 가치도 반영한다. 쇼다운에서 적 후보가 없으면 사거리 안의 접근 가능한 파워 상자를 찾는다. 하이스트에서는 적 후보가 없을 때 사거리·사선 조건을 만족하며 보호막이 없는 상대 금고를 찾고 `kind: 'safe'`, 문자열 금고 ID를 반환한다. 공을 들고 있다면 상대 골문 방향을 반환한다. 어느 것도 없으면 캐릭터가 바라보는 방향을 반환한다. 녹아웃에서 사망한 액터의 조회는 적을 고르지 않는 `forward` 결과를 반환한다.

적이 덤불에 숨었거나 엄폐물 뒤에 있으면 자동 조준이 해당 위치를 알려주지 않는다. 골문 조준 결과는 슛의 성공 보장이 아니다. 반사·가로채기·이후 이동은 실제 시뮬레이션이 결정한다.

## 3. 공개 상태

앱과 렌더러는 상태를 읽어서 표현한다. 플레이 중 UI가 엔진 내부를 직접 수정하지 않는다. 테스트에서는 경계 상황을 재현하기 위해 상태를 구성할 수 있다. `_` 접두사 메서드는 내부 구현이며 앱 연결용 API가 아니다.

### `game.state`

| 필드 | 의미 |
|---|---|
| `mode`, `status` | 모드 ID, `playing` 또는 `ended` |
| `elapsed`, `timeLimit` | 경과 초·제한 초. 연습장의 `timeLimit: 0`은 무제한 |
| `width`, `height` | 1280, 800 |
| `actors` | 플레이어·봇·연습 표적 |
| `projectiles`, `walls`, `bushes`, `pickups` | 탄환·지형·덤불·수집물 |
| `effects`, `events` | 수명이 있는 시각 효과, 오디오/피드백 이벤트 |
| `fields` | 지속형 중력장 |
| `score` | `[0팀, 1팀]`. 젬 보유량·골 수·구역 평균 진척·자기 금고 잔여 체력 비율·녹아웃 라운드 승수·바운티 누적 별 등 모드별 의미 |
| `countdown` | 보석 유지 조건 성립 시 `{team, remaining}`, 아니면 `null` |
| `ball`, `goalBounds` | 공과 골문. 해당 모드가 아니면 `null` |
| `zone` | 쇼다운·녹아웃 안전 구역 `{x, y, r}`, 나머지는 `null`. 녹아웃은 라운드 경과 시간을 사용 |
| `round` | 녹아웃의 번호·단계·라운드 시간·휴식·결과 이력. 나머지 모드는 `null` |
| `bounty` | 바운티의 목표 점수와 블루 스타 소유 상태. 나머지 모드는 `null` |
| `captureZones` | 핫 존의 구역 두 개. 다른 모드에서는 빈 배열 |
| `safes` | 하이스트의 팀별 금고. 다른 모드에서는 빈 배열 |
| `goalPause` | 득점 뒤 재시작까지 남은 초 |
| `overtime`, `overtimeDuration` | 연장전 여부·45초 |
| `killFeed` | 최근 처치 최대 6건 |
| `result` | 종료 시 `{winner, won, title, reason, rank?}` |

### 액터

| 범주 | 주요 필드 |
|---|---|
| 식별 | `id`, `name`, `hero`, `team`, `isPlayer`, `isDummy` |
| 공간 | `x`, `y`, `r`, `angle`, `vx`, `vy`, `hidden` |
| 전투 | `hp`, `maxHp`, `ammo`, `maxAmmo`, `superCharge`, `alive`, `respawnIn`, `invulnerable` |
| 상태 | `gadgetCooldown`, `shieldTime`, `slowTime`, `slowFactor`, `hitFlash` |
| 목적물 | `gems`, `power`, `bountyValue` |
| 전투 통계 | `kills`, `deaths`, `assists`, `damage`, `damageTaken`, `shotsFired`, `shotsHit` |
| 목표 통계 | `goals`, `gemsCollected`, `captureTime`, `objectiveDamage`, `roundSurvivals`, `starsEarned`, `starsLost` |

`gadgetCooldown`은 남은 초, `slowFactor: 1`은 정상 속도다. `superCharge` 범위는 0~1, 탄약은 0~3의 연속 값이다. `bountyValue`는 모든 모드에서 기본값 2를 갖고 바운티에서 2~7로 변한다. `roundSurvivals`, `starsEarned`, `starsLost`는 모든 모드에서 0으로 시작한다.

`hidden`은 플레이어 관점의 숨김 상태다. 살아 있는 플레이어는 기존의 자기 시야를 사용한다. 녹아웃에서 플레이어가 죽으면 살아 있는 같은 팀 액터를 관찰자로 사용하며, 그중 하나라도 볼 수 있는 적은 표시한다. 시체는 관찰자에 포함하지 않는다. 생존 아군이 없으면 적을 새로 공개하지 않는다. 관전 대상을 바꾸어도 이 시야 합집합이나 플레이어 팀은 바뀌지 않는다. 봇의 표적 결정은 각 봇 자신의 관찰 조건을 사용한다.

명중 통계는 일반 공격과 투사체형 특수 공격을 발사 동작 단위로 센다. 산탄·관통·광역 공격이 여러 캐릭터나 금고에 실제 피해를 주어도 같은 동작에서는 명중 1회로 기록한다. 돌진 특수 공격·가젯·공 패스 및 슛은 제외한다. 보호막 때문에 금고 체력이 감소하지 않은 공격은 명중 통계를 추가하지 않는다.

어시스트는 같은 팀의 처치에 최근 8초 안에 피해를 기여한 다른 아군에게 기록한다. `damage`는 상대 캐릭터의 실제 체력 감소량이며 `objectiveDamage`는 금고의 실제 체력 감소량이다. 두 수치는 합치지 않는다. `captureTime`은 유효한 구역 점유에 기여한 누적 초이고, 같은 구역에 있는 여러 아군이 각각 기록해도 팀의 점령 속도는 증가하지 않는다.

`roundSurvivals`는 녹아웃 라운드의 승리 팀에 속하면서 라운드 종료 순간 살아 있던 횟수다. `starsEarned`는 바운티에서 유효한 처치와 최초 블루 스타 수집으로 얻은 별의 누계다. `starsLost`는 자기 사망으로 유효한 적 처치자에게 지급한 별의 누계다. 환경 사망에는 별 손실을 기록하지 않으며 K/D/A의 사망 수와 별도 의미를 갖는다.

### 지형·투사체·이벤트

```js
wall = { id, x, y, w, h, hp, maxHp, destructible, kind, dropPower };
// x/y는 좌상단. hp <= 0이면 충돌·렌더에서 제외한다.

pickup = { id, type: 'gem' /* 또는 power */, x, y, r, value };
field = { id, type: 'gravity', ownerId, team, x, y, r, life, maxLife };
kill = { id, killerId, victimId, team, kind, time, stars }; // stars는 유효한 바운티 처치에서만 추가
event = { id: 'e123', type, x, y, team }; // team은 선택적

captureZone = {
  id: 'zone-A', x: 640, y: 245, r: 95,
  progress: [0, 0], occupants: [0, 0], captureSeconds: 40
}; // zone-B는 y: 555

safe = {
  id: 'safe-0', team: 0, x: 180, y: 400, r: 42,
  hp: 24000, maxHp: 24000,
  shieldTime: 0, shieldsTriggered: 0, lastHitTime: -10
}; // safe-1은 team: 1, x: 1100

round = {
  number: 1, phase: 'active', elapsed: 0, timeLimit: 75,
  breakRemaining: 0, lastWinner: null, lastReason: '', history: []
};
// history 항목: { number, winner: 0 | 1 | null, reason, duration }

bounty = {
  target: 20,
  blueStar: { x: 640, y: 400, r: 12, carrierId: null,
    team: null, onGround: true, firstClaimed: false }
};
```

이벤트는 최근 최대 64건을 유지한다. 앱은 문자열 ID의 숫자 부분으로 이미 처리한 이벤트를 제외한다. 효과는 수명이 지나면 제거되고 최대 180개로 제한된다. 처치 알림 UI는 최근 5초 내 최대 3건만 표시한다.

`shieldsTriggered`는 0~3의 소비된 보호막 단계 수이고 `shieldTime`은 남은 면역 초다. 금고는 액터나 일반 벽 배열에 중복 등록하지 않는다. 목표 이벤트에는 `capture`, `safeHit`, `safeShield`가 있으며 금고 파괴로 캐릭터용 `killFeed`를 만들지 않는다.

녹아웃은 첫 생성과 이후 라운드 시작에 `roundStart`, 라운드 확정 시 `roundEnd` 이벤트를 보낸다. `round.phase`는 `active` 또는 `break`이며, 경기 종료의 기준은 항상 `state.status`다. 두 번째 라운드 승리로 경기가 끝나면 phase는 `break`, 남은 휴식은 0일 수 있다. 전체 시간 한도는 미완료 라운드를 임의로 승리 이력에 추가하지 않는다.

바운티의 `blueStar`는 소유권 변경·수집·낙하 이벤트이고 `bountyScore`는 해당 스텝의 일반 점수 변경 이벤트다. `killFeed.stars`는 같은 스텝의 피해 처리 후 확정한다. 땅에 있는 블루 스타의 `carrierId`와 `team`은 모두 `null`이다. `onGround: false`인 소유자는 같은 스텝의 상호 처치 때문에 사망 상태일 수도 있다.

## 4. 전투·모드 규칙

### 공통

탄약은 자동으로 충전된다. 공격과 피해를 3초간 피하면 초당 최대 체력의 12.5%를 회복한다. 상대 캐릭터에 일반 공격 피해를 주면 특수 공격이 충전되며 일반 경기에서도 약한 자연 충전이 있다. 금고 피해로는 특수 공격을 충전하지 않는다. 목재는 파괴되고 석재는 일반 전투로 파괴되지 않는다. 탄환은 이전 위치부터 다음 위치까지를 훑어 검사하며 총구가 벽 너머에서 생성되어 얇은 엄폐물을 건너뛰지 않도록 한다.

덤불 속 적은 가까이 접근하거나 공격·피격으로 드러나면 보인다. 봇도 시야·엄폐물·탄약·체력·목적물을 고려하며, 회복이 필요할 때 사격을 멈추고 물러난다. AI는 캐릭터 이동과 동일한 충돌 제약을 받는다.

### 가젯

| 가젯 | 효과 | 제약 |
|---|---|---|
| 퀵 스텝 | 입력 이동 방향으로 148px 회피, 탄약 +1 | 이동 입력이 없으면 조준 방향. 벽에 막히며 탄약 최대 3 |
| 아이언 가드 | 3초간 직접 피해 45% 감소 | 독가스 피해에는 적용하지 않음 |
| 중력장 | 조준점 방향 최대 260px, 반경 105px, 4초 | 적 이동 속도 35% 감소·초당 100 피해. 설치점은 엄폐물에 막히고 장판 중심과 대상 사이가 벽으로 가려지면 피해·감속도 차단 |

사망·라운드 초기화 때 임시 보호막·감속·장판을 정리한다. 가젯 재사용 대기는 계속 흐르며 사망으로 즉시 초기화되지 않는다. 연습장에서는 세 가젯 모두 3초 대기를 사용한다.

| 젬 그랩 | 플레이어 포함 3 대 3 | 팀 보석 10개 이상이면서 상대보다 많은 상태 15초 유지. 조건이 깨지면 초기화. 180초 한도 |
| 쇼다운 | 플레이어 포함 8명 | 마지막 생존자. 플레이어 탈락 시 순위와 함께 종료. 150초까지 남으면 생존 체력 비율·파워·고정 순서로 판정 |
| 브롤 볼 | 플레이어 포함 3 대 3 | 2골 선취. 180초 비동점이면 선두 승리. 동점이면 45초 서든데스 |
| 핫 존 | 플레이어 포함 3 대 3 | A·B 구역 모두 100% 완료. 180초에는 정밀 평균 진척 비교 |
| 하이스트 | 플레이어 포함 3 대 3 | 상대 금고 파괴. 180초에는 자기 금고의 정밀 잔여 체력 비율 비교 |
| 녹아웃 | 플레이어 포함 3 대 3 | 두 라운드 선승. 라운드별 75초, 휴식 포함 전체 240초에는 라운드 승수 비교 |
| 바운티 | 플레이어 포함 3 대 3 | 팀 별 20개 도달 또는 120초. 최종 별 합계·블루 스타 소유권 순으로 판정 |
| 연습장 | 플레이어 1명 + 비공격 표적 3개 | 시간 제한·승패 없음. 표적은 사망 1.5초 뒤 재생성 |

브롤 볼의 공 소유자는 일반 공격으로 탄약 1칸을 사용해 패스·슛을 한다. 특수 공격으로 강한 슛을 할 수 있다. 공은 벽에 반사되고 다른 액터가 가로챌 수 있다. 골라인을 통과한 **시점의 위치**가 골문 안에 있는지 검사해 빠른 대각선 슛을 판정한다. 득점은 한 번만 기록하고 일반 라운드에서는 2초 뒤 재시작한다.

연장전이 시작되면 벽·덤불·발사체·장판을 정리하고 양 팀과 공을 재배치한다. 다음 골이 즉시 승리이며 225초에도 동점이면 무승부다. 연습장은 시작 시 특수 공격이 준비되어 있고 사용 후 최대 약 3초 동안 자연 재충전된다. 초기화는 새 `Game`을 만드는 앱 동작이다. 연습 결과는 승리/경기 전적에 누적하지 않는다.

### 핫 존

두 구역은 `(640, 245)`, `(640, 555)`를 중심으로 반경 95를 사용한다. 살아 있고 부활 무적이 끝났으며 중심이 구역 원 안에 있는 액터를 유효 점유자로 센다. 한 팀에 유효 점유자가 한 명 이상 있으면 해당 팀의 진척을 초당 `100 / 40 = 2.5`%p 증가시킨다. 같은 팀의 인원이 늘어나도 증가율은 같다. 적이 같은 구역에 있어도 양 팀이 각각 진척한다.

진척은 이탈·사망으로 감소하지 않고 최대 100이다. 완료한 팀은 해당 구역에서 추가 진척이나 `captureTime`을 얻지 않는다. 마지막 부분 프레임은 실제 남은 진척에 해당하는 시간만 각 점유자에게 누적한다. `occupants`는 완료 여부와 관계없이 현재 유효 위치 인원수를 계속 표시한다.

`state.score[team]`은 두 구역 진척의 산술 평균이다. 두 구역이 모두 완료되어야 승리하며, 같은 스텝에 양 팀 모두 완료하면 무승부다. 제한 시간에는 표시 전 평균을 비교한다. 앱의 구역·팀 진척 표시는 정수 내림을 사용해 미완료 상태가 100%로 보이지 않게 한다. 상세 명세는 [HOT_ZONE.md](docs/HOT_ZONE.md)를 참조한다.

### 하이스트

금고는 각 팀에 하나씩 있으며 기본 최대 체력은 24,000이다. 양쪽 금고 모두 캐릭터 이동을 막는 원형 고체다. 일반 투사체, 산탄, 관통·폭발 공격, 돌진·충격파와 중력장의 유효 피해를 처리하지만 아군 금고에는 피해를 주지 않는다. 금고는 체력을 재생하지 않고 회복·감속·밀치기 대상이 아니다.

체력 경계는 75%·50%·25%, 기본 체력 기준 18,000·12,000·6,000이다. 피해가 다음 경계를 넘겨도 그 경계까지만 감소시키고 초과분은 버린다. 경계에 도달하면 해당 단계를 한 번 소비하고 1.8초의 전면 피해 면역을 적용한다. 보호막 타이머는 시뮬레이션 스텝마다 한 번만 감소한다. 보호막 중 피해는 체력·목표 피해·명중 횟수를 바꾸지 않는다.

피해 판정은 그 스텝의 전투 처리가 끝난 뒤 양쪽 금고를 함께 검사한다. 양쪽이 같은 스텝에 파괴되면 무승부다. 한쪽만 파괴되면 반대 팀이 승리하며, 플레이어의 승패에 맞는 금고 파괴 원인을 결과에 표시한다. 제한 시간에는 `hp / maxHp`를 비교한다. `score` 역시 각 팀 자기 금고의 남은 체력 백분율이며, UI는 0.1% 단위 올림을 사용하지만 승패는 원래 정밀 값으로 결정한다. 상세 명세는 [HEIST.md](docs/HEIST.md)를 참조한다.

### 녹아웃

활성 라운드에서는 부활하지 않는다. 플레이어 사망도 경기 종료 조건이 아니다. 해당 스텝의 투사체·장판·독 피해를 모두 처리한 뒤 양 팀 생존 인원을 검사한다. 한 팀만 전멸하면 반대 팀의 라운드 승리, 양 팀이 모두 전멸하면 무승부다. 라운드 75초까지 양 팀이 살아 있으면 체력·피해량 비교 없이 무승부다. 결과는 `history`에 한 번만 추가하고 라운드 승리는 `score`에 1을 더한다.

두 라운드를 먼저 이기면 경기를 끝낸다. 그렇지 않으면 2.4초의 `break`를 거쳐 다음 라운드를 시작한다. 휴식 중 `round.elapsed`는 멈추지만 `state.elapsed`와 가젯 대기는 계속 흐른다. 자연 회복과 슈퍼 자연 충전은 멈춘다. 전체 시간 240초에 도달하면 활성·휴식 어느 단계든 현재 라운드 승수가 많은 팀이 승리하고 같으면 무승부다.

안전 구역 중심은 `(640,400)`이다. 반경은 라운드 25초까지 770, 이후 선형으로 줄어 65초에 20이 된다. 구역 밖의 생존 액터는 초당 `300 + round.elapsed × 9`의 독 피해를 받는다. 독은 기존 부활 무적·돌진·가젯 피해 감소의 예외를 유지한다. 독 피해에서 개별 사망 즉시 경기를 끝내지 않으므로 양 팀 동시 전멸을 온전히 판정한다.

| 다음 라운드에서 복원·정리 | 경기 전체에서 보존 |
|---|---|
| 생존·체력·탄약·초기 위치·방향, 1.4초 시작 무적 | K/D/A·피해·명중·발사 통계 |
| 투사체·장판·수집물·시각 효과 | `roundSurvivals`와 라운드 이력·승수 |
| 파괴된 벽과 수풀을 포함한 원래 맵, 경로 캐시 | `superCharge` |
| 보호막·감속·돌진·속도·공개 시간·발사 대기·피해 기여 내역 | 남은 `gadgetCooldown` |
| 봇의 경로·표적·이전 적 관찰 | 전체 경기 경과 시간 |

`lastHurt`와 `lastShot`은 새 라운드 시작 시 현재 경기 시간으로 설정해 즉시 재생 조건을 상속하지 않게 한다. 상세 상태 흐름·예외는 [KNOCKOUT.md](docs/KNOCKOUT.md)를 참조한다.

### 바운티

개인 현상금은 2로 시작하며 적을 처치할 때마다 1씩, 최대 7까지 증가한다. 사망하면 2로 리셋하고 2.5초 뒤 부활한다. `score`는 현재 현상금의 합이 아니라 팀이 이미 획득한 별의 누계다. 사망 자체가 팀 누적 점수를 감소시키지는 않는다.

모든 내부 스텝은 피해를 주기 전에 액터별 현상금과 블루 스타 소유자를 스냅샷으로 보관한다. 그 스텝에서 발생한 유효한 적 처치를 모아 피해 전 피해자의 현상금을 팀 점수·`starsEarned`·피해자의 `starsLost`와 처치 알림에 기록한다. 환경·자기 자신·유효한 적이 아닌 처치자에게 별을 지급하지 않는다. 처치자가 같은 스텝에 사망했어도 처치 점수는 얻지만 개인 현상금은 2로 유지한다. 살아남은 처치자만 스텝 시작 값에 유효 처치 횟수를 더한다.

땅의 블루 스타는 살아 있고 부활 무적이 끝난 액터가 두 몸체 반경 합 이내로 접근하면 수집한다. 후보가 여럿이면 가까운 액터, 거리가 같으면 ID 순서로 선택한다. 최초 한 번만 일반 점수와 개인 획득 별을 1 늘리고 `firstClaimed`를 켠다. 이후 수집이나 소유권 양도는 점수를 추가하지 않는다.

소유자 사망 처리는 **스텝 시작 시 소유자 한 명**을 기준으로 한다. 유효한 적 처치자가 있으면 그 액터에게 한 번 양도하며 새 소유자도 같은 스텝에 죽었어도 소유권을 보존한다. 다음 스텝에서 그 죽음을 다시 처리하지 않는다. 유효한 적 처치자가 없으면 사망 지점으로 떨어뜨리고 소유 팀·캐릭터를 비운다. `firstClaimed`는 유지한다. 죽은 새 소유자가 부활하면 같은 ID의 소유권이 그대로 이어진다.

모든 처치 점수·소유권 양도·바닥 수집을 처리한 뒤 20점 도달을 검사한다. 한 팀만 도달하면 그 팀이 승리한다. 양 팀이 함께 도달하면 최종 점수가 많은 팀, 점수가 같으면 블루 스타 소유 팀, 소유 팀도 없으면 무승부다. 120초 종료에도 최종 점수와 소유권을 같은 순서로 사용한다. 블루 스타로 결정한 동점에는 그 이유를 결과 문구에 표시하고, 경기 종료 이후 점수·소유권·결과는 더 이상 바뀌지 않는다. 상세 예시는 [BOUNTY.md](docs/BOUNTY.md)를 참조한다.

## 5. 렌더러 API

```js
const renderer = new globalThis.BrawlRenderer(canvas);
renderer.render(game.state, {
  aimX: 900, aimY: 400,
  showAim: true,
  time: performance.now() / 1000,
  menu: false,
  camera: 'follow', // overview | follow; menu:true이면 항상 overview
  focusId: null,   // 녹아웃에서 플레이어 사망 시 살아 있는 아군 ID만 인정
  minimap: true,   // 추적 보기의 미니맵. false로 숨길 수 있음
  reducedEffects: false,
  showGadgetIndicator: true
});
const world = renderer.screenToWorld(clientX, clientY);
const screen = renderer.worldToScreen(worldX, worldY); // client CSS 좌표
renderer.resize(width, height, dpr); // 선택 호출
```

렌더러는 상태를 변경하지 않는다. Canvas 크기를 화면에 맞추고 DPR을 최대 2로 제한한다. 조준선은 캐릭터 중심부터 실제 사거리까지 그리되 투사체 반경을 포함한 첫 엄폐물에서 멈춘다. 산탄은 실제 다섯 발 방향을 표시한다. 주황색 종점은 벽 충돌, 열린 흰색 종점은 사거리 끝이다. 공 조준선은 첫 벽 또는 경기장 가장자리까지의 직선이며 반사 후의 경로는 예측하지 않는다.

`overview`는 전체 전장을 보여 주고, `follow`는 1.5배 확대해 플레이어를 추적하며 뷰를 월드 경계 안으로 제한한다. `menu: true`는 카메라 옵션과 관계없이 전체 보기를 사용한다. 좌표 변환은 마지막 실제 렌더 변환과 Canvas의 클라이언트 사각형을 기준으로 한다. CSS 크기·위치 변경과 줌을 반영하며 `worldToScreen`의 결과는 DPR 좌표가 아닌 클라이언트 CSS 좌표다.

`focusId`는 녹아웃에서 로컬 플레이어가 사망했고 선택 대상이 살아 있는 같은 팀 액터일 때만 카메라 초점에 사용한다. 플레이어가 살아 있거나 다른 모드이면 플레이어를 추적한다. 탈락한 녹아웃 플레이어에게 사망한 아군·적·존재하지 않는 ID를 요청하면 첫 생존 아군으로 대체하며, 생존 아군 자체가 없으면 전체 보기로 돌아간다. 초점 선택은 로컬 팀·숨김 상태를 바꾸지 않는다. 라운드 결과와 관전 배지는 DOM UI가 담당한다.

추적 미니맵은 지형·고정 목표와 자신·아군을 표시한다. 적이나 자유 공·공 운반 위치를 별도 마커로 노출하지 않는다. 숨은 적과 그 적이 든 공은 전체 화면에도 표시하지 않는다. 핫 존은 두 팀의 진척 링을 독립적으로 그리며 같은 구역의 상대 존재를 점령 정지로 표현하지 않는다. 금고는 체력, 보호막 시간·단계 상태를 표시한다.

바운티는 보이는 액터의 현상금과 소유 배지를 표시한다. 땅에 떨어진 블루 스타는 공개 목표로 그릴 수 있지만 보이지 않는 소유자의 좌표를 별도 바닥 아이콘·미니맵 마커로 노출하지 않는다. 공개 소유 팀 정보와 소유 캐릭터의 숨겨진 위치 정보는 구분한다.

`reducedEffects`는 장식 회전·펄스·입자·잔상과 강한 피격 효과를 줄인다. 위험 범위·독구역·체력·조준·보호막·감속 표시는 유지한다. 선택 필드가 빠져도 기본 렌더링을 유지하도록 처리한다.

| 터치 왼쪽 / 오른쪽 스틱 | 이동 / 조준 사격 |
| 빈 전장의 왼쪽 / 오른쪽 드래그 | 해당 위치에 스틱을 띄워 이동 / 조준 사격 |
| 오른쪽 스틱 짧은 탭 | 자동 조준 사격 |

터치 포인터마다 입력 소유권을 분리한다. 한 손가락의 취소가 다른 스틱의 입력을 지우지 않는다. 특수 공격과 가젯은 전용 버튼을 제공한다. 터치에서 별도 조준을 하지 않은 스킬은 현재 자동 조준 결과를 사용한다. 조준 중에는 스틱 방향을 따른다.

도움말에는 추적 카메라, 조준 가이드, 효과 줄이기, 터치 진동, 전투 팁 옵션이 있다. 카메라 미저장 기본값은 데스크톱 `overview`, 터치 기기 `follow`다. 사용자가 저장한 카메라·효과 설정을 우선한다. 효과 설정이 없을 때만 운영체제의 동작 줄이기 설정을 기본값으로 사용한다. 전투 팁은 ×로 숨길 수 있고 도움말에서 다시 켤 수 있다.

마우스 입력은 화면상의 클라이언트 좌표를 보관하고 프레임·엔진 입력 시점마다 `screenToWorld`를 다시 호출한다. 카메라가 움직였다는 이유로 이전 절대 월드 조준점에 고정되지 않는다. 터치 조준은 계속 플레이어 기준 상대 방향을 사용한다. 목표 HUD는 핫 존의 A·B 독립 진척과 하이스트의 체력·보호막을 표시하며 전황표에서 전투 피해와 목표 기여를 분리한다.

앱은 엔진과 별도로 `spectatorId`를 보관한다. 녹아웃 사망 시 살아 있는 아군을 선택하고 매 프레임 대상의 생존·팀을 재확인한다. Tab의 반복 keydown은 대상을 연속 전환하지 않는다. 선택한 아군 사망 시 다른 생존 아군으로, 모두 탈락하면 `null`로, 플레이어 부활 시 직접 조작으로 복귀한다. 렌더러에는 `options.focusId`로 전달한다.

플레이어의 생존 상태, 라운드 번호 또는 `phase`가 바뀌면 이동·발사·슈퍼·가젯의 유지/대기 입력과 터치 스틱을 해제한다. 탈락·휴식 중 엔진 입력은 중립이며 스킬 버튼과 조준 가이드는 조작 가능 상태로 제시하지 않는다. 라운드 결과 패널은 `playing`이면서 `break`일 때만 보인다. 최종 결과·전적 기록은 `state.status === 'ended'`에서 한 번 처리한다.

녹아웃 시계는 라운드 또는 휴식의 남은 시간과 전체 240초까지 남은 시간 중 짧은 값을 보여 준다. 전체 한도가 먼저 오면 라운드 승수로 판정한다는 목표 문구를 표시한다. 생존 인원·라운드 번호·경기 승수와 최근 라운드 이유를 구분한다. 바운티 HUD는 누적 팀 점수, 공개 블루 스타 소유 팀, 개인 현상금을 표시하고 전황에서는 획득/허용 별을 분리한다.

저장 키 `brawl-lab-settings-v1`, `brawl-lab-records-v1`은 기존 전적과 환경 설정을 이어받기 위해 유지한다. 저장소 접근이 실패해도 플레이를 막지 않는다. `globalThis.BrawlLab.version`은 `4.0.0`이다. `snapshot()`은 진단용 읽기 API이며 게임 상태를 조작하는 명령은 제공하지 않는다. v4 진단에는 `spectatorId`, 라운드와 이력의 복사, 바운티/블루 스타의 복사, 플레이어의 현상금·획득 별·허용 별·승리 생존 수가 포함된다.

## 7. 검증과 확장 경계

현재 `node --test tests/*.cjs`에서 **엔진 82개·앱 24개, 총 106개 사례가 통과**했다. 실패·취소·스킵은 0개이며 기존 80개를 보존했다. v4 엔진 20개는 라운드 생존·자원 보존/초기화·동시 전멸·시간과 독·아군 시야, 바운티의 스텝 시작 값·블루 소유권·동점·실제 전체 경기의 결정성과 유한 상태를 검증한다. 앱 6개는 새 모드 시작, 관전·라운드 HUD·입력 해제·최종 경기 기록·바운티 통계 연결을 추가한다. 자세한 사례는 `tests/`와 README를 참조한다.

테스트용 `game.aiEnabled = false`는 봇의 입력 결정만 멈춘다. 물리·타이머·피해·목표 판정은 계속 진행한다. 공개 상태 fixture로 경계를 구성할 수 있지만 UI 실행 코드는 내부 상태를 직접 수정하지 않는다.

앱의 Node VM·DOM 어댑터 검증과 실제 브라우저·모바일 실기 검증을 구분한다. 앱의 카메라·관전 검증은 초점과 좌표 변환 API를 올바르게 연결하는지 확인한다. 렌더러는 v4의 녹아웃·바운티 × 세 영웅 × 두 카메라 **12조합**을 네이티브 Canvas에서 별도 확인했다. 생존 아군 초점과 잘못된 대상의 대체·전멸 시 전체 보기·부활/로비 복귀, 로컬 팀 유지, 화면/월드 좌표 왕복·CSS 크기 변경·DPR 2, 상태 비변경과 효과 축소를 검사했다.

숨었거나 죽은 블루 스타 소유자의 위치·현상금과 소유 별 좌표를 바꾸어도 전체 이미지 픽셀이 동일하며, 미니맵에는 적과 보유한 별의 위치를 노출하지 않는다. 지상 별의 표시와 실제 관전·소유·모바일 이미지도 따로 확인했다. 이 12조합은 106개의 Node 테스트에 합산하지 않으며, 실제 브라우저 레이아웃·포인터 캡처·실음원·터치 기기 확인을 포함하지 않는다.

온라인 동기화·서버 권위 판정·매치메이킹·계정·상점·원작의 전체 캐릭터 및 모든 모드는 이 실행 코어의 범위에 포함되지 않는다. 이를 추가하려면 엔진 입력/상태 규약은 재사용할 수 있지만 네트워크·영속 데이터·서버 검증 계층은 별도 설계가 필요하다.
