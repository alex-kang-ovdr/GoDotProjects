# Godot 포팅: 지형 시야와 마지막 관측 상태

대상: **Nexus Front Godot v11**, Godot **4.6.3**, 2026-11-20. 웹 v10의 `terrain-memory-v1` 규칙을 네이티브 GDScript로 옮겼다. 이 지형 높이·공격 원점 규칙은 프로젝트에서 설계한 전투 규칙이며, 원작 League of Legends 엔진의 내부 시야 알고리즘을 복제했다고 주장하지 않는다.

구현: [vision_system.gd](../scripts/vision_system.gd) · 검증: [test_vision.gd](../tests/test_vision.gd) · 공통 인터페이스: [PORT_CONTRACT.md](PORT_CONTRACT.md)

## 1. 서로 다른 세 가지 정보를 분리한다

| 정보 | 보관 대상 | 갱신 조건 | 화면·전투에서의 용도 |
|---|---|---|---|
| 현재 시야 | 팀별 `visible` 바이트 격자, 정확한 시야원 검사 | 게임 시간 0.1초마다 격자 갱신. Actor 질의는 현재 위치로 검사 | 안개 마스크, 적 선택·공격 허용 |
| 탐색 기록 | 팀별 `explored` 바이트 격자 | 실제 시야로 관측된 셀을 1로 기록 | 미탐색과 탐색했으나 현재 가려진 지형 구분 |
| 마지막 건물 관측 | 팀별 구조물 스냅샷 | 해당 건물이 실제로 보이는 동안만 복사 | 가려진 건물의 마지막 체력·생존·보호 상태 표시 |

공격 원점 힌트는 이 세 정보와 별도로 관리한다. 힌트가 생겼다고 `visible`, `explored`, 적 Actor의 선택 가능 상태가 바뀌지 않는다.

격자는 **40 프로젝트 단위** 간격이다. 1배 맵은 1,600×1,600 단위와 40×40셀, 1.5배 맵은 2,400×2,400 단위와 60×60셀, 2배 맵은 3,200×3,200 단위와 80×80셀이다. 웹 v10의 20단위 격자보다 해상도를 낮춰 GDScript의 반복 비용을 줄였으며, 실제 적 선택·공격 허용은 거친 셀 값이 아니라 정확한 원·선분 검사로 판단한다. 경계의 시각 표현과 판정 사이에 최대 한 셀 정도의 차이가 생길 수 있다.

## 2. 시야원과 가림 판정

### 시야원

| 시야원 | 기본 반경 | 지형 차단 | 수풀 |
|---|---:|---|---|
| 영웅·포탑 | 420 | 적용 | 같은 관측자의 수풀 접근 조건 적용 |
| 넥서스·기지 | 450 | 적용 | 적용 |
| 억제기 | 270 | 적용 | 적용 |
| 미니언 | 250 | 적용 | 적용 |
| 와드 | 480 | 적용 | 적용 |
| 애쉬 정찰 매 | 효과의 `radius` (기본 220) | 비행 정찰 예외 | 수풀 노출 허용 |

영웅·미니언·건물의 `vision_range`가 있으면 해당 값이 우선한다. 맵 크기를 늘려도 기본 시야 반경은 함께 확대하지 않는다. 넓은 맵에서는 같은 시야원을 더 멀리 배치해야 한다.

일반 판정 순서는 다음과 같다.

1. 시야원이 살아 있는지, 상대 위치가 시야 반경 안인지 확인한다.
2. 관측자보다 높은 지형의 점은 볼 수 없다.
3. 선분이 벽 원의 내부를 통과하면 볼 수 없다. 수학적 접선만 닿는 경우는 통과로 취급한다.
4. 낮은 지형 사이에 높은 언덕이 끼어 있어도 언덕 내부를 통과하는 선분을 차단한다.
5. 적 영웅이 수풀에 있으면 **같은 시야원**이 거리·LOS·수풀 조건을 모두 만족해야 한다.

수풀 조건은 관측자가 같은 수풀 안에 있거나 대상과 95단위 미만으로 가까울 때 만족한다. 벽 뒤의 아군이 수풀 안에 있다는 이유만으로, 수풀 밖의 다른 아군에게 탐지 권한을 빌려주지 않는다. 스킬의 `revealed_until`은 수풀 제한만 완화하며, 정상적인 거리와 LOS 조건은 유지한다.

언덕은 이동할 수 있다. 벽은 이동도 막는다. 즉, 높이와 이동 불가 영역을 하나의 속성으로 합치지 않는다.

## 3. 벽 이동 충돌

`safe_move(from, to, radius)`는 캐릭터 반지름만큼 확대한 원형 벽에 대해 선분 충돌을 검사한다. 프레임당 이동량이 커도 벽을 통과하지 않도록 첫 충돌 지점 직전에 멈추고, 남은 이동량을 접선 방향으로 투영하여 벽을 따라 미끄러지게 한다. 이후 다른 벽에 다시 부딪히는 경우도 한 번 더 제한한다.

`navigation_target()`은 직선 이동을 막는 첫 바위 주변에서 이동 가능한 짧은 우회 지점을 선택한다. `navigate_direction()`은 그 지점을 향한 정규화된 방향을 반환한다. 이는 원형 정적 장애물에 맞춘 가벼운 우회 처리다. 복잡한 임의 메시 지형을 위한 범용 NavMesh 경로 탐색기는 아니다.

점멸·순간이동처럼 벽 횡단이 허용되는 스킬은 월드의 `teleport(..., allow_wall_cross=true)` 경로를 사용하고 도착 지점의 `is_walkable()`을 검사한다. 일반 이동과 순간이동이 실수로 같은 충돌 예외를 공유하지 않도록 API를 나눴다.

## 4. 언덕 위에서 공격받았을 때

숨겨진 적 또는 중립 몬스터가 아군에게 피해를 주면 피해가 발생한 **공격 원점 좌표**를 1.5초 동안 반경 76단위의 힌트로 표시한다.

- 공격자 Actor ID나 현재 이동 위치를 렌더러에 전달하지 않는다.
- 원점은 생성 시 좌표로 고정된다. 공격자가 이동해도 힌트는 이동하지 않는다.
- 같은 좌표에서 반복 피해가 발생하면 만료 시간만 연장한다.
- 다른 좌표의 후속 공격은 별도의 힌트가 될 수 있다.
- 힌트는 적을 대상으로 선택하거나 추적할 권한을 주지 않는다.
- 해당 위치가 이미 정상 시야 안이면 추가 힌트를 만들지 않는다.
- 최대 128개의 힌트를 보관하며 만료 항목은 제거한다.

웹 v10은 중립 몬스터의 공격을 이 힌트에서 제외했으나, Godot v11은 “언덕 위에서 공격받으면 해당 위치가 잠시 보인다”는 요청을 모든 적대적 피해 원점에 적용하여 중립 팀 2의 공격도 지원한다. 피해를 받은 팀은 플레이어 팀 0 또는 1이어야 한다.

표시용 반환값은 `id`, `team`, `pos`, `radius`, `created_at`, `expires_at`만 가진다. 미래에 네트워크 멀티플레이를 추가할 경우에도 이 자료만 클라이언트에 보내면 숨겨진 공격자의 실시간 위치를 전달할 필요가 없다. 현재 프로젝트는 로컬 싱글플레이 시뮬레이션이며 서버 권한 검증을 구현한 것은 아니다.

## 5. 고정 건물의 상태 기억

렌더러는 숨겨진 건물의 실제 Entity를 직접 읽지 않고 `structure_observations(team)`의 복사본을 사용해야 한다. 스냅샷에는 위치, 종류, 팀, 체력, 최대 체력, 생존 여부, 보호 여부, 관측 시각이 들어간다.

예를 들어 마지막 관측이 `체력 1,000 / 살아 있음`이었다면, 이후 안개 속에서 실제 건물이 파괴돼도 화면은 이전 관측 상태를 유지한다. 플레이어가 다시 그 위치를 보았을 때에만 `체력 0 / 파괴됨`으로 바뀐다. 보호 상태 변경도 같은 규칙을 따른다.

실제 Entity가 배열에서 제거돼도 기억을 지우지 않는다. 과거 위치를 다시 보았는데 해당 ID가 없다면 그제야 파괴 상태로 기록한다. 같은 ID의 건물이 재건된 경우에도 현재 관측될 때 새 상태를 복사한다. 한 번도 본 적이 없는 적 건물에는 기억 실루엣을 만들지 않는다.

아군 건물의 상태는 항상 아군에게 공개된다. 반환되는 Dictionary와 격자 배열은 내부 자료와 분리되어, UI가 값을 바꾸더라도 시야 시스템의 지식 상태가 바뀌지 않는다.

## 6. 중립 오브젝트

캠프·드래곤·보스에도 별도의 마지막 관측 자료를 제공한다.

| 상태 | 의미 | 노출 가능한 정보 |
|---|---|---|
| `present` | 실제로 살아 있는 오브젝트를 관측함 | 당시 위치와 체력 |
| `dead` | 처치 팀이거나 죽는 위치를 실제로 목격함 | 해당 시점에 설정된 재생성 시간 |
| `absent` | 캠프 자리는 보지만 오브젝트가 보이지 않음 | 비어 있다는 사실만 공개 |
| 기록 없음 | 관측한 적 없음 | 상태를 추측해 만들지 않음 |

빈 캠프는 죽었다는 증거가 아니다. 몬스터가 다른 위치로 유인됐을 수 있으므로, 숨겨진 실제 Entity의 생존 상태나 재생성 타이머를 복사하지 않는다. `absent`는 `alive=false`로 반환하여 렌더러가 빈 캠프에 몬스터를 그리지 않게 한다.

월드는 처치 시 `respawn_at`을 먼저 결정한 다음 `record_objective_death()`를 호출한다. 숨겨진 적의 처치가 아군의 마지막 관측 상태를 자동 갱신하지 않는다.

## 7. 성능 구조

- 격자는 게임 시간 기준 10Hz로 갱신한다. 게임 속도를 0.5배로 낮추면 현실 시간 기준 약 5Hz, 1.5배로 높이면 약 15Hz가 된다.
- 맵 전체 × 모든 시야원 × 모든 장애물을 매번 검사하지 않는다. 시야원의 반경을 둘러싼 사각형만 순회하고, 앞선 아군 시야원이 이미 밝힌 셀은 건너뛴다.
- 셀 중심의 지형 높이와 벽 내부 여부를 초기화 때 사전 계산한다.
- 각 시야원은 자신의 시야 원과 겹치는 벽·상위 언덕만 후보로 잡는다. 관측자의 높이도 시야원마다 한 번만 계산한다.
- Actor 판정은 최신 위치를 직접 확인한다. 움직이지 않는 격자·건물 표시 자료와 매 프레임 필요한 공격 판정을 분리한다.
- `mask().revision`이 바뀔 때만 안개 텍스처를 다시 만들 수 있도록 변경 번호를 제공한다.

2배 맵의 두 팀 `visible`·`explored` 원시 배열은 총 **25,600바이트**다. 셀 높이·벽 점유 사전 계산은 32,000바이트다. 이는 Dictionary, 시야원, 관측 스냅샷, 렌더링 텍스처, 엔진 관리 비용을 제외한 원시 배열 크기다.

### 측정 범위

Godot 4.6.3 Linux headless에서 실제 맵의 벽 12개·언덕 4개를 사용하고, 영웅 10개와 미니언 140개를 시드 619로 배치했다. 두 기지를 포함해 시야원 152개다. 초기 1회를 제외하고 15회 갱신을 측정한 진단 실행 결과는 아래와 같다.

| 맵 | 팀당 셀 | 시야 격자 갱신 평균 | 해당 실행의 최대 |
|---|---:|---:|---:|
| 1배 | 1,600 | 8.77ms | 9.19ms |
| 1.5배 | 3,600 | 10.72ms | 15.78ms |
| 2배 | 6,400 | 11.04ms | 15.22ms |

이는 클라우드 Linux 컨테이너의 CPU 진단 수치다. 다른 작업과 자원을 공유하며 GPU 렌더링·전체 전투 루프·디스플레이를 측정하지 않았으므로 실제 기기의 FPS 보장으로 해석하면 안 된다.

### 실제 월드의 2배 맵 최종 진단

최종 통합 버전에서 2배 맵, 영웅 AI와 정상 미니언 웨이브를 사용하고 `SimWorld.step(1.0 / 60.0)`을 3,600회 호출하여 게임 시간 60초를 진행했다. 종료 시 Entity 수는 85개였다. 상세 시나리오와 계측 방법은 [PERFORMANCE.md](PERFORMANCE.md)를 따른다.

| 측정 항목 | 최종 통합 실행 결과 |
|---|---:|
| 전체 3,600 step의 CPU 경과 시간 | **10.338초** |
| 전체 step당 평균 CPU 경과 | **2.872ms** |
| 시야 단계 누적 시간 | 6.042초 |
| 이동 함수 누적 시간 | 1.065초 |
| 표적 탐색 함수 누적 시간 | 0.849초 |

함수별 계측에는 호출 관계가 중첩되므로 각 항목을 더해서 전체 시간을 만들면 안 된다. 초기 통합 버전의 같은 길이 진단은 139.98초였으며, 이후 거리 범위 밖의 후보를 시야 검사 전에 제외하고 시뮬레이션 step 안에서 중복 시야 판정을 캐시하여 비용을 줄였다. 최종 측정에는 D/F 소환사 주문 등 추가된 게임 로직도 들어 있다.

이는 클라우드 Linux 컨테이너에서 측정한 headless 처리량이다. GPU 렌더링·디스플레이를 포함한 실제 기기의 FPS 보장이 아니다. 원시 검증 자료와 최종 소스 해시는 통합 검증 보고서 및 native export manifest에서 확인할 수 있다.

## 8. 저장과 검증

`export_state()`는 탐색 비트, 건물·오브젝트 스냅샷, 공격 원점과 만료 시각을 저장한다. 현재 시야는 저장된 실제 월드 상태로 다시 계산한다. `import_state()`는 프로필, 맵 크기, 셀 크기, 배열 길이, 수치 범위와 위치를 검사한 뒤 적용한다. 잘못된 자료는 기존 관측 상태를 부분 변경하지 않고 거부한다. Godot의 Vector2와 PackedByteArray를 보존하는 네이티브 저장 형식이며 웹 v10 JSON 체크포인트의 직접 불러오기는 별도 변환 기능이 필요하다.

전용 테스트는 **56개 통과**다. 벽·접선·언덕 방향성, 수풀과 동일 시야원 제약, 비행 정찰의 예외와 만료, 이동 연속 충돌, 건물의 미관측·파괴·제거·재건·보호 상태, 공격 원점의 비추적·비노출, 중립 사망 타이머, 저장 복원과 잘못된 상태 거부, 갱신 주기, 1배·2배의 모든 셀 중심에서 최적화 격자와 정확한 LOS 판정의 일치를 검사한다.
