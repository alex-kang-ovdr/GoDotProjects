# Godot v11 검증 보고서

작성 기준일: **2026-11-20 (Asia/Seoul)**. 검증 엔진: **Godot 4.6.3 stable official**. 기준 웹 소스: v10 `d53d9e1df6525719f0d791010235090119451d45`.

## 1. 실제 엔진 자동 검증

`python3 tools/test.py`가 실제 Godot 헤드리스 프로세스를 실행했다. 종료 코드뿐 아니라 로그의 `SCRIPT ERROR`와 `ERROR`도 실패로 처리했다.

| 검증 모음 | 통과 | 실패 | 주요 범위 |
|---|---:|---:|---|
| 월드 | **103** | 0 | 3맵·5대5·피해·선딜레이·취소·레벨·R 조건·25아이템 조합·승리 구조·귀환·D/F·와드·저장 |
| 영웅·스킬 | **160** | 0 | 40개 스킬·공식 랭크 배열·시전자별 표식·재시전·패시브·CC·자원·활성 효과 저장 |
| 시야 | **56** | 0 | 벽·높이·수풀·공격 원점·고정 건물 기억·중립 정보·스케일·저장·관측 복사본 |
| **합계** | **319** | **0** | 최종 실행 약 **5.886초** |

원시 결과: `validation_results.json`, 실제 로그: `validation.log`.

조건이 잘못된 소라카 W의 체력·마나·재사용·시전 횟수가 변하지 않는지, 레오나 햇빛을 본인이 소비하지 않는지, 이즈리얼 W 폭발과 Q 적중의 자원·쿨다운 상호작용, 다리우스 Q의 안쪽·바깥쪽과 출혈 중첩 등 구체적 전투 위험을 검사했다. 저장에서는 비유한 좌표·중복 ID·잘못된 영웅 상태·효과·팀 버프를 거부하고 현재 경기를 유지하는지도 확인했다.

## 2. 지속 진행 검증

시드 `2601120`, 일반 모드, Ezreal 선택 후 플레이어를 AI로 바꾸어 10명 모두 봇으로 진행했다. 각 맵에 `dt=0.1`로 1,800step, 게임 시간 180초를 적용했다. 이 검증은 **진행 안정성 검사**이며 아래 처리 시간은 실제 60Hz 렌더링 FPS가 아니다.

| 맵 | 웨이브 | 킬 | 피해 구조물 | 파괴 구조물 | 상태 |
|---|---:|---:|---:|---:|---|
| 1× | 10 | 6 : 7 | 7 | 2 | 좌표·체력 범위와 유한값 정상 |
| 1.5× | 10 | 4 : 7 | 4 | 3 | 정상 |
| 2× | 10 | 3 : 4 | 5 | 2 | 정상 |

180초 동안 넥서스까지 파괴된 자연 경기를 확인한 것은 아니다. 전체 보호 해제와 넥서스 파괴 승리는 별도 월드 테스트에서 실제 피해·파괴 함수로 검증했다. 원시 결과는 `sustained_simulation.json`이다.

## 3. 성능 확인

2배 맵에서 `dt=1/60`, 3,600step으로 게임 60초를 계산한 최종 헤드리스 측정은 **10.338초**, 평균 **2.872ms/step**, 최종 개체 **85개**였다. GPU 렌더링·OS 입력·화면 합성은 이 수치에 포함하지 않는다. 공유 실행 환경이므로 사용자 PC 성능 보장치로 사용하지 않는다.

거리 우선 검사, 스텝 내 시야 캐시, 대상 탐색 주기, 경유점 캐시, 시야 지형 사전 계산을 적용했다. 초기 139.98초와의 차이는 AI 동작·부하가 완전히 같은 통제 실험이 아닌 개발 중 참고 비교다. 상세 방법과 재현 명령은 `PERFORMANCE.md`, 원시 수치는 `performance.json`을 참조한다.

## 4. 네이티브 GUI 확인

Godot 에디터 F5 실행과 별도 Godot 실행 창에서 실제 입력을 확인했다.

- 한글 로비, 10영웅 선택, 소라카 표시, 1.5배 맵·0.75배 속도 선택
- 경기 진입, 5대5 AI·미니언·포탑·미니맵·체력·자원·스킬 UI 표시
- Shift+Q 조준 후 지정 위치 시전: 영역 표시, 자원 감소, 재사용 대기 확인
- F 회복: 실제 체력 증가와 28초 대기 표시
- B 귀환 후 기지 상점에서 구매 가능 상태 확인
- 장화 구매: 3,382G → 3,082G, 인벤토리 반영, 판매가 210G 표시
- 저장 버튼 및 F5: 저장 완료 표시
- F9: 1분 30초의 경기가 저장된 1분 시점으로 복원, 체력·골드·스킬·시야 표시 복원
- 구매 후 저장, 체크포인트 다시 사용
- 투명 SubViewport의 원형 스킬 효과와 안개 합성 표시

데스크톱 GUI 환경에는 실제 사운드 장치가 없어 초기 ALSA 폴백 메시지가 발생했다. 최종 화면 검증은 `--audio-driver Dummy`로 실행했다. GUI 드라이버는 V-Sync 변경을 지원하지 않는다는 경고를 출력했으나 게임 GDScript 오류는 발생하지 않았다. 오디오·특정 GPU별 프레임 성능을 검증한 것으로 해석하지 않는다.

## 5. 내보내기

- Godot 4.6.3 공식 release template로 Linux x86_64 및 Windows x86_64 생성
- 최종 import와 세 export 작업 종료 코드 0, 경고 0, 오류 0
- runtime 입력 97개 파일의 내보내기 전후 SHA-256 동일
- 프로젝트용 PCK와 Linux·Windows PCK의 바이트 동일성 확인
- 최종 Linux 실행본 로비·전투 헤드리스 시동 성공
- 이전 동일 전투 코드 빌드는 로비·전투 각각 100 process frame 검사 통과
- 최종 Linux 실행본의 GUI 확인 내용은 `gui_validation.json`에 기록
- **Windows는 교차 내보내기·파일 형식 확인이며, 실제 Windows OS 실행은 미검증**

내보내기 입력·출력 해시는 `exports/native-export-manifest.json` 및 `exports/runtime-inputs-before-export.json`, `exports/runtime-inputs-after-export.json`에 있다. 상세 안내는 `EXPORT.md`를 참조한다.

## 6. 데이터·기존 산출물 동일성

`docs/data_identity.json` 기준:

- 웹 v10에서 내보낸 객체와 Godot JSON의 모든 값·배열이 동일
- 기존 PNG **35개** 모두 원본과 바이트 동일
- 동봉 v10 소스 ZIP과 기존 다운로드 ZIP의 SHA-256 동일
- 기존 v10 단일 HTML SHA-256 유지
- 기존 웹 Git 작업 트리에 변경 없음

## 7. 배포 ZIP

최종 포장 도구가 압축 후 `ZipFile.testzip()`으로 모든 항목의 CRC를 검사하고, 압축을 읽어 각 원본 파일의 SHA-256·크기와 다시 비교한다. 소스 ZIP 안의 `FILE_MANIFEST.json`은 검증 대상 파일별 크기·해시를 담는다. ZIP 자체 크기·SHA-256·검증 결과는 별도 `delivery_manifest.json` 및 최종 전달 메시지가 기준이다.

## 8. 검증 범위의 한계

원작 LoL과의 모든 판정 동일성, 온라인 멀티플레이, 브라우저 저장 자동 변환, 웹의 레거시 프로필·코치·전적 UI, 모바일 가상 조이스틱 전체, Windows OS 실행, 상용 장시간 부하·모든 GPU 조합은 이번 검증에 포함하지 않는다. 구체적 이식 차이는 README·WORLD·ABILITIES·FOG에 기록했다.
