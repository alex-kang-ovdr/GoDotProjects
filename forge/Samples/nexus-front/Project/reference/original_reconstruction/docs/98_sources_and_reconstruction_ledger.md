# 98. 출처·버전·복원 장부

**열람·재구축 기준일: 2026-11-17 KST.** 이 장부는 확인한 근거의 종류와 적용 범위를 설명한다. 문서의 구조 설계·이벤트명·JSON 스키마·의사 코드는 별도 표시가 없는 한 복원 구현을 위한 제안이며 Riot의 비공개 내부 구조가 아니다.

출처 13개와 24개에는 같은 패치 노트를 서로 다른 시스템에서 참조한 중복이 있다. 두 값을 더해 고유한 웹페이지 수라고 주장하지 않는다. 정적 응답 194개 역시 194개의 독립 게임 규칙을 의미하지 않는다.

`current_patch_certified=true`는 수치 CSV에서 26.22 본문에 직접 적힌 멜 관련 단일 값 7행에만 붙어 있다. 이름과 달리 엔진·챔피언 전체·실전 예외를 인증했다는 의미가 아니다. 정확한 열 의미는 `rules_sources.json`의 `parameter_field_semantics`에 있다.

## 5. 패치 복원 시의 적용 순서

1. 대상 제품·모드·맵·큐·지역을 고정한다. 같은 노트의 Classic 항목을 현대 협곡 규칙으로 옮기지 않는다.
2. 도입 시점 값을 기준선으로 남긴다. 이후 변경 행이 이전 값을 대체하는지, 별도 조건을 추가하는지 구분한다.
3. 구조화 JSON 비교는 해당 필드의 관측값으로 취급한다. 본문에만 있는 동작 변경은 별도 규칙 명세로 기록한다.
4. 공식 자료끼리 충돌하면 양쪽 위치와 값을 보관한다. “공식이므로 항상 한 값”이라고 가정하지 않는다.
5. 미확정 값을 실행용 데이터로 승격하기 전에 공식 정정 또는 통제된 클라이언트 관찰을 확보한다.
6. 적용한 정의에 빌드·해시를 붙여 새 경기와 저장 복원의 규칙을 고정한다.

2026 역할 퀘스트는 26.1 도입값을 그대로 현행으로 쓰기 어려운 사례다. 이번에는 26.3·26.9·26.11·26.12·26.16·26.19 및 26.22의 관련 변경을 검토했으며, 이 목록 밖의 모든 중간 패치·핫픽스가 무변경이라고 전수 인증한 것은 아니다. 구체적인 행은 [경제·역할 퀘스트](systems/02_economy_experience_items.md)에서 확인한다.

## 6. 과거 파일과 원천 바이트 보존

기존 문서 25개는 [보존본 인덱스](../baseline_2026-11-13/00_README.md)로 접근한다. [baseline_integrity.json](baseline_integrity.json)의 해시로 내용 보존을 확인한다. 날짜가 오래된 문서를 현재 규칙으로 덮어쓰기보다 후속 문서에서 수정과 근거를 연결했다.

`raw/`의 JSON은 긴 설명·툴팁 본문을 제외한 선택 필드 projection이다. 원본 응답과 projection의 해시를 각각 기록했다. 보존한 projection의 바이트 일치는 검증하지만, 원본 응답 전체를 동봉했다고 말하지 않는다. 원본 전체가 필요한 후속 작업은 같은 URL을 다시 수집하고 새 수집 시점·해시를 기록해야 한다.

패키지의 각 파일은 `PACKAGE_MANIFEST.json`으로 확인한다. 매니페스트는 자기 자신과 검사 결과 파일을 해시 대상에서 제외하여 순환 의존을 피한다. 파일을 수정한 뒤에는 이전 패키지 해시가 맞지 않는 것이 정상이며, 새 배포 매니페스트가 필요하다.

## 7. 결론을 제한하는 미확보 영역

- 실행 가능한 전 챔피언 스킬 그래프·피해 공식·대체 폼·재시전·예외.
- 서버의 내부 틱 순서, 원작의 현재 시야 격자·최적화·네트워크 복제 구현.
- 비공개 MMR 계수·매치 품질 점수·탐지 모델·지급 백엔드 구조.
- 클라이언트 관측이 필요한 지형 높이·충돌 폭·투사체·캐스팅·반올림 세부.
- 이번에 직접 실행하지 않은 Unreal 및 원작 클라이언트의 성능·정확성 측정.

이 영역의 제안 스키마와 QA는 구현을 준비하는 자료다. 실제 확보한 데이터와 계획을 분리하는 것이 후속 복원에서 잘못된 확신을 줄이고 결함의 원인을 추적하는 기준이 된다.
