# 11. 복원 품질 검증과 실측 계획

**기준일: 2026-11-17 KST · 문서 성격: 수행한 데이터 검증 + 아직 수행하지 않은 게임 검증 계획**

이 문서는 데이터 복원 성공과 원작 동작 일치의 증거를 나눈다. 동봉한 데이터의 해시·참조·수치 일치를 검사했다고 해서 원작 클라이언트의 전투·시야·서비스 동작까지 재현했다고 판단하지 않는다.

## 1. 이번에 수행한 검증

[validation_report.json](../data/validation_report.json)에 다음 8종의 검사를 기록했다. 동봉 projection으로 수행한 오프라인 재생성이 성공했고, 해당 보고서의 경고는 0건이다.

| 번호 | 수행한 검사 | 통과가 의미하는 것 | 통과가 보장하지 않는 것 |
|---|---|---|---|
| D1 | 보존 projection 존재·해시·빌드 | 배포 입력 파일을 추적하고 검증 가능 | 원본 HTTP 바이트 전체의 동봉 |
| D2 | 챔피언·아이템 스탯 원본 포인터 비교 | 정규화 수치가 보존 원천과 같음 | 필드에 없는 패시브·예외 공식 |
| D3 | 스킬 랭크별 비용·쿨다운·사거리 비교 | 해당 배열 원소와 출력 값 일치 | 시전·충돌·온힛 전체 의미 |
| D4 | 챔피언 ID 유일성, 전원 QWER 네 항목 | 카탈로그 중복·누락 관계 검사 | 내부 변신·재시전 스킬 전수 |
| D5 | 미해결 템플릿 null 유지 | 근거 없는 수치를 만들어 넣지 않음 | 모든 식별자의 의미 해결 |
| D6 | 아이템 ID·조합 관계·수량 | 재료 관계를 추적 가능한 형태로 보존 | 실제 상점 노출·구매 제한·핫픽스 |
| D7 | 룬 ID·경로·슬롯 참조 | 룬 선택 구조의 참조 유효성 | 발동 조건·효과 수치·내부 쿨다운 |
| D8 | CSV 파싱과 JSON 행 수 대응 | 배포한 두 형식을 읽고 수량 비교 가능 | 임의 프로그램에서의 의미 해석 |

전체 챔피언 173명·최상위 QWER 692개·아이템 863개라는 집계는 이 자료의 범위다. QWER 템플릿 3,308개 중 3,274개가 미해결이며, 공통 append 토큰 692개를 제외해도 682개 스킬에 2,582개 미해결 참조가 남는다. 이 값은 [coverage_report.json](../data/coverage_report.json)에 있으며 “복원율 100%” 같은 단일 숫자로 대체하지 않는다.

이번 작업에서 원작 클라이언트 플레이, 네트워크 패킷 분석, 전체 챔피언 자동 대전, Unreal 구현 실행, 새 웹 게임 FPS 측정은 수행하지 않았다. 아래 사례의 기본 상태는 `planned_not_executed`다. 기존 v7 게임의 과거 회귀 테스트 기록은 별도의 구현 검증 이력이며 이번 원작 데이터 검증 건수에 합치지 않는다.

## 2. 관측 기록에 반드시 필요한 값

실측은 표본 자체보다 재현 조건이 중요하다. 캡처마다 다음 메타데이터를 기록한다.

| 묶음 | 필요한 값 |
|---|---|
| 버전 | 공개 패치, 실제 클라이언트 빌드, 서버 지역, 기록 시각, 핫픽스 확인 여부 |
| 경기 | 모드, 맵, 연습/사용자 설정 여부, 팀, 게임 시각, 난이도 |
| 공격자 | 챔피언·폼·레벨·스킬 랭크·아이템·룬·버프·HP·자원·전투 스탯 |
| 대상 | 종류·챔피언·레벨·현재/최대 HP·방어·보호막·피해 면역·버프 |
| 공간 | 공격자·대상 위치, 거리 측정 방식, 지형·수풀·고도, 충돌 반경의 근거 |
| 입력 | 명령 시각·대상·좌표·취소·연속 입력, 실제 시전 시작·발사·적중 시각 |
| 결과 | 비용, 쿨다운, 피해 전후 HP, 보호막 변화, 상태 효과, 보상·시야 변화 |
| 증거 | 영상/스크린샷/로그 경로, 프레임률·시간 해상도, 측정자, 반복 번호 |

목적이 다른 두 시험을 합치지 않는다. “화면에 적이 보인다”는 증거는 “정확한 공격 대상으로 지정 가능하다”는 증거와 다르다. “위치에 효과가 표시된다”는 증거는 “그 주변 지형의 시야가 열린다”는 증거와 다르다.

## 3. 원작 비교와 프로젝트 수용 시험

| 시험 종류 | 비교 대상 | 판정 |
|---|---|---|
| 정적 일치 | 선택 버전 JSON의 특정 포인터 | 값·형식·ID 일치 |
| 문헌 일치 | 같은 모드·패치의 공식 설명 | 요구 조건·결과·예외 일치 |
| 원작 실측 일치 | 통제한 원작 클라이언트 장면 | 측정 오차 안에서 사건 순서·수치 일치 |
| 프로젝트 규칙 준수 | 승인된 사용자 요구와 설계 | 요구사항의 불변 조건 충족 |
| 성능 목표 | 명시한 기기·맵·개체·프레임 설정 | 계측한 분포가 목표 이내 |

벽·고저차·공격 위치 공개·건물 기억은 이 프로젝트의 별도 확장 정책으로도 검증한다. 원작 비교 시험과 섞으면 사용자에게 필요한 기능을 “원작과 다르다”는 이유로 제거하거나, 커스텀 동작을 원작 사실로 잘못 기록하게 된다.

## 5. 시야와 기억의 핵심 수용 사례

### V01 — 벽에 의한 차단

한 시야원과 적 사이에 시야 차단 벽을 둔다. 직선 시야가 차단된 동안 대상은 관측 뷰·미니맵·타깃 후보에서 숨는다. 벽을 우회해 직선이 열리면 같은 업데이트 주기 안에서 관측이 갱신되어야 한다. 이동 가능한 얇은 영역과 시야 차단 영역이 다른 경우 각각의 레이어를 기준으로 판단한다.

### V02 — 고저차와 시야 원점

낮은 위치와 높은 위치에 각각 시야원을 배치하고 두 방향을 독립 검증한다. 언덕의 단순 Z 좌표만으로 판정하지 않으며, 가려지는 높이 구간·시야원 눈높이·목표 가시 지점의 계약을 따른다. 한쪽 가시성이 다른 쪽의 가시성을 자동 의미하지 않는다.

### V03 — 고지대 공격의 위치 공개

관측되지 않는 고지대 공격자가 낮은 지역의 적에게 공격한다. 공개 이벤트에는 **공격 시점의 원점과 만료 시각**을 기록한다. 공격자가 이동해도 공개 위치가 따라가지 않아야 한다. 정상 시야·별도 탐지·다음 공격이 없다면 이동 뒤 위치를 새로 제공하지 않는다. 위치 공개가 적 식별·타깃 지정·주변 시야까지 허용하는지는 선택한 정책에서 각각 명시한다.

### V04 — 건물 상태 유지

팀 A가 고정 건물을 HP 80% 상태로 관측한 뒤 시야를 잃는다. 실제 건물이 HP 20%가 되더라도 팀 A의 기억은 HP 80%와 당시 외형을 유지해야 한다. UI에 표시되는 “마지막 관측” 시간도 유지한다. 상태가 보이지 않는 동안 무조건 최신 체력바를 끄는 식의 부분 처리만으로 통과시키지 않는다.

### V05 — 보이지 않는 파괴와 재관측

V04의 건물이 파괴되더라도 팀 A의 기억은 계속 기존 건물 상태다. 팀 A가 **건물이 있던 슬롯·영역을 다시 관측**하면 파괴 상태로 갱신한다. 파괴된 Actor 자체를 재관측 조건으로 삼으면 객체가 제거된 뒤 갱신 기회를 잃으므로 슬롯 ID와 공간 범위를 별도로 보존한다. 전역 공지 예외가 있는 규칙은 별도 채널로 명시한다.

### V06 — 팀별 기억 격리

팀 A는 파괴 전, 팀 B는 파괴 후 상태를 본다. 같은 실제 구조물을 참조하더라도 두 관측 스냅샷은 다르다. 관전자·디버그·리플레이의 전지 시점 데이터가 플레이어 HUD·AI의 입력으로 유입되지 않도록 별도 뷰를 검사한다.

### V07 — 저장·복원과 만료

임시 위치 공개와 건물 기억이 존재하는 상태에서 저장한다. 재개 후 공개의 남은 시간이 배속과 일시정지를 따라 일관되게 흐르고, 오래된 건물 기억이 로드 시 실제 상태로 갱신되지 않아야 한다. 저장 포맷에서 현재 시야와 과거 탐색을 하나의 배열로 합치지 않는다.

### V08 — 간접 정보 누출

비관측 대상에 대해 마우스 커서, 클릭 반응, 자동 조준, 미니맵, 피해 숫자, 음향, 전술 조언, 경로 미리보기, AI 추적을 각각 검사한다. 공개가 허용된 사건과 숨겨야 하는 원본 좌표를 구분한다. 접근 자체가 불가능한 원본 뷰를 제공하는 구조가 조건문을 화면마다 추가하는 방식보다 검증하기 쉽다.

## 6. 기존 선택 기능의 회귀 범위

| ID | 설정 | 확인 |
|---|---|---|
| U01 | 새 경기 맵 1 / 1.5 / 2배 | 생성 좌표·벽·캠프·시야 격자·미니맵·저장 범위 |
| U02 | 경기 시작 후 맵 변경 시도 | 기존 경기 크기 불변, 새 경기 선택으로만 적용 |
| U03 | 속도 0.5 / 0.75 / 1 / 1.5배 | 이동·예약 사건·쿨다운·와드·시야 공개의 시뮬레이션 시간 일치 |
| U04 | 과거 속도 2 저장·손상 설정 | 현재 정규화 규칙과 안내, 지원 목록에 2배 재노출 없음 |
| U05 | 일시정지·탭 숨김·저장·재개 | 동일 사건 중복 발사 없음, 눌린 입력 해제, 기억 보존 |

원작 참고 프로필을 추가하더라도 이 선택 기능은 사용자 프로젝트의 기능으로 유지한다. 맵 면적은 변 길이 배율의 제곱이므로 2배 맵은 4배 면적이다. 이를 “개체나 성능 비용도 항상 4배”라고 단정하지 않고 실제 자료구조별 계측으로 확인한다.

## 7. 성능 계측 설계

성능 수치는 **제안 목표**와 **측정 결과**를 별도 열로 저장한다. 본 문서에서는 측정되지 않은 FPS·메모리를 실적처럼 제시하지 않는다.

### 브라우저

맵 1 / 1.5 / 2배, 동일 시드, 동일 입력 로그, 동일 개체 수를 기본 비교로 사용한다. 이후 시야원·미니언·투사체·효과 수를 각각 늘린다. 목표 기기·브라우저 버전·해상도·DPR·전원 상태를 기록한다. 초기 로딩·지형 캐시 생성과 안정 상태를 구분하며 여러 구간의 중앙값·p95·최댓값을 보고한다.

| 비용 | 계측 지점 | 개선 판단에 필요한 정보 |
|---|---|---|
| 시뮬레이션 | `Game.step` 세부 단계 | 전투·AI·길찾기·시야 각 시간 |
| 시야 | LOS 질의·갱신 셀 수 | 전체 원 갱신과 변경 영역 갱신의 비용 차 |
| 렌더링 | 지형·개체·안개·HUD | 픽셀 수·캐시 재생성·숨은 개체 처리 |
| 메모리 | 격자·스냅샷·개체·캐시 | 맵 배율 및 팀 수에 따른 증가 |
| 저장 | 직렬화·검증·쓰기 | 본 경기 프레임 정체와 저장 크기 |

시야 계산을 렌더 프레임보다 낮은 주기로 수행하는 정책은 관측 지연과 함께 평가한다. 셀 크기를 키우면 계산량은 줄지만 벽 모서리·좁은 통로·건물 재관측 판정이 거칠어진다. 먼저 올바른 관측 경계를 만든 뒤 해상도·업데이트 주기를 조절한다.

### Unreal

Unreal은 논리 시야와 표시용 텍스처를 별도 계측한다. 서버/로직 측에서는 시야원 수, LOS 방문 셀 수, 더티 타일 수, 팀별 기억 갱신, 복제 대상 수를 기록한다. 렌더 측에서는 텍스처 업데이트 바이트, 업로드 빈도, 블러 패스 비용, GPU 프레임 시간을 기록한다. 비동기 계산 결과가 이전 경기·이전 맵의 데이터에 덮어쓰지 않도록 generation ID를 검사한다.

고정 건물 기억은 전체 Actor를 복제하는 대신 표시가 허용된 필드와 관측 시각만 저장하는 구조를 우선 비교한다. 가시성의 논리 판정에 블러된 텍스처를 역으로 읽지 않는다. 블러는 경계를 보기 좋게 만드는 표시 단계이며 타깃 가능 여부는 논리 비트/셀 또는 정확한 판정 결과를 따른다.

## 8. 결함 분류와 승인

| 등급 | 예 | 승인 처리 |
|---|---|---|
| 정보 권한 결함 | 숨은 적 좌표·시야 밖 건물 변화 누출 | 해당 프로필 출고 차단 |
| 상태 무결성 결함 | 중복 보상·아이템 복제·중복 발사·저장 훼손 | 출고 차단 |
| 원작 규칙 차이 | 공식 또는 실측과 비용·효과 조건 불일치 | 일치 목표 콘텐츠의 완료 상태 해제 |
| 근거 공백 | 미측정 투사체 속도·공식 충돌 | 미해결 상태와 조사 계획 유지 |
| 표현 차이 | 논리 일치하나 이펙트·색·보간 차이 | 플레이 판단 영향에 따라 우선순위 결정 |
| 성능 결함 | 특정 조건의 p95 증가·업로드 정체 | 재현 환경과 원인 지점 기록 후 예산 조정 |

검증 완료 콘텐츠에는 **적용 버전, 검증 조건, 통과 사례, 남은 예외**를 함께 제공한다. 데이터 카탈로그 행 수, 테스트 개수, 문서 분량을 게임 복원 완성도의 대용 지표로 사용하지 않는다.
