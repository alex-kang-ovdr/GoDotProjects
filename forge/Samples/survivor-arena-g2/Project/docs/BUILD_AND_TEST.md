- v14의 무기 피해 85개, 기본 간격 17개, 보조 누적값 60개와 런타임 계산의 연결을 유지했습니다.

- 68개 무기 성장 비교의 피해·간격을 실제 런타임과 대조했습니다. 카드 표시·레이더·월드는 시뮬레이션과 RNG를 변경하지 않습니다.
- 설정에서 M/N 단축키를 사용해도 기존 토글 표시가 실제 값과 맞고 음량 슬라이더의 포커스·노드를 유지합니다.
- 대각선 예고의 양 끝점·폭·직교성, 임의 3D 선분, 회전된 적 부품의 치수를 실제 MultiMesh 업로드 변환으로 검사했습니다.

G1의 일정 테스트는 이전 중간 보스를 살려 둔 채 시각을 건너뛰는 준비 단계를 사용했습니다. G2의 단일 교전 규칙에 맞춰 이전 보스 처치와 회복 시간을 추가했으며, 원래 결과 검증문은 유지했습니다. 중첩 일정 자체는 별도의 G2 검사에서 다룹니다.

## 2. 실제 G1 다중 보스 저장 이관

`tests/fixtures/g1_900s_two_midbosses.json`은 **수정하지 않은 G1 프로젝트의 시뮬레이션과 snapshot()**으로 생성했습니다. 두 중간 보스, 일반 적, 공격 예고, 적 탄환, 이미 부여된 처치·피해·피격 통계를 포함합니다. 생성 소스와 픽스처 해시는 같은 폴더의 provenance 파일에 기록했습니다.

처음 복원할 때 기존 주요 컬렉션·통계·RNG·시계가 유지되는지 비교했습니다. 두 가지 보스 처치 순서 모두에서 추적 소유권이 같은 호출 안에 이동하고, 최초 복원 직후·첫 보스 처치 직후·마지막 기존 보스 처치 직후·최종 승리 후의 G2 저장/재복원이 성공합니다.

일반 G2 전투에서는 새 보스를 겹쳐 생성하지 않습니다. 이 예외는 이미 유효하게 저장된 G1 교전의 진행을 보존하기 위한 이관 정책입니다. 저장 후 재현 비교는 Godot JSON 십진수 변환 오차를 고려해 숫자에 절대 오차 `1e-8`을 허용하며, RNG 문자열과 배열 순서는 정확히 일치해야 합니다.

## 4. 실제 OpenGL 화면 검수

Godot Compatibility를 **Mesa llvmpipe**에서 실행해 **19개 네이티브 화면**을 저장했습니다. 로비 및 사막/빙결 미리보기, 설정, 세 전장 전투, 성장 카드, 빌드, 보스 준비/패턴, 정지 설정, 세로 로비·설정·전투·카드·기록, 결과, 데스크톱 기록 화면입니다. 근거는 `tests/captures/`와 `tests/capture_report.json`입니다.

| 확인 항목 | 결과 |
|---|---|
| 1280×800 데스크톱 UI | 로비·전투·비교 카드·설정·기록 검수 |
| 390×844 세로 UI | 버튼·설정·HUD·스크롤 카드·기록 검수 |

| 경고 도형 | 대각선 돌진 예고가 실제 충돌 경로와 일치하도록 수정 후 재캡처 |
| 음량 조절 | 사라진 트랙을 6px 두께로 수정하고 대비 있는 손잡이로 재캡처 |

화면 검수에서 회전 후 전역 스케일을 적용하던 오류를 발견했습니다. 로컬 스케일로 수정하기 전에는 새 기하 검사 23개가 실패했고, 수정 뒤 모두 통과했습니다. 이 변경은 효과 모양뿐 아니라 공격 예고의 방향·폭을 실제 판정에 맞추는 수정입니다.

캡처는 UI와 효과를 확인하려고 레벨·스킬·적·패턴을 직접 구성한 **시각 검사 장면**입니다. 자연 전투 플레이 영상이나 성능 벤치마크로 제시하지 않습니다. 기록 화면에는 자동 플레이 결과를 가져왔지만 크레딧 등 UI 검사용 프로필을 사용합니다. 이미지 생성 모델로 만든 화면이 아닙니다.

## 5. 내보내기와 실행 범위

`python tools/verify_exports.py`로 Linux·Windows·Web·PCK를 새로 내보냈습니다. 네 작업 모두 **종료 코드 0, 내보내기 오류·경고 0**이었고, 내보내기 중 소스 변경은 없었습니다. `tests/export_report.json`에 실제 산출 파일의 크기·SHA-256·런타임 로그·구조 검사를 기록했습니다.

| 대상 | 산출물 | 검증한 범위 |
|---|---|---|
| Godot 프로젝트 | 씬·GDScript·데이터·폰트·음원·문서·검사 | 764개 검사 및 네이티브 GL 화면 |
| Linux x86_64 | 리소스 내장 Release 실행 파일 | 소스 폴더 밖 headless 기동, 별도 OpenGL 창 60프레임 실행 성공 |
| Windows x86_64 | 리소스 내장 Release EXE | PE/AMD64·내장 PCK 확인. **Windows 실기동 미검증** |
| Web | 단일 스레드 HTML/JS/WASM/PCK | 파일 생성·WASM magic·필수 파일 확인. **브라우저 실기동 미검증** |
| PCK | 외부 리소스 팩 | Godot 엔진으로 소스 폴더 밖 headless 기동 성공 |

같은 검증 환경에서 G1의 브라우저 실행을 시도했을 때 Chromium이 UNIX socket 생성 거부로 페이지 생성 전에 종료됐습니다. G2에서는 같은 브라우저 시도를 반복하지 않았으며 로딩 성공으로 처리하지 않았습니다. `tests/web_runtime_report.json`에 이 구분을 명시했습니다. Android/iOS/Safari 실기기, 실제 모바일 발열·배터리·GPU 성능은 검증 범위에 없습니다.

Linux 실제 GL 실행은 CPU 렌더러의 V-Sync 변경 미지원 경고 1종을 출력했습니다. 스크립트 오류나 렌더러 초기화 실패는 없었습니다. 이 환경의 실행 결과를 GPU 프레임 성능으로 해석하지 않습니다.

## 6. 재현 및 배포 검증

```bash
python tools/run_tests.py --godot /path/to/godot
python tools/run_tests.py --godot /path/to/godot --balance
python tools/verify_exports.py --godot /path/to/godot
godot --path . -- --qa --capture
python tools/package_release.py --output /path/to/releases
```

시각 캡처는 디스플레이와 GL 렌더러가 있는 환경에서 실행합니다. `--headless`만으로는 실제 화면을 검증할 수 없습니다. `--qa` 실행은 일반 사용자 프로필 쓰기·정산을 분리하며 디스크 검사는 일회용 디렉터리를 사용합니다.

프로젝트 ZIP에는 `.godot` 캐시·내보내기 템플릿·빌드 바이너리·원본 웹 ZIP을 넣지 않습니다. 처음 열면 Godot이 포함된 소스 에셋을 임포트합니다. 별도 플랫폼 ZIP에는 필요한 실행 파일과 라이선스·실행 안내를 포함합니다. 최종 패키징에서 ZIP CRC·경로 안전성·SHA-256과 프로젝트 파일별 `MANIFEST.sha256`을 검증합니다.
