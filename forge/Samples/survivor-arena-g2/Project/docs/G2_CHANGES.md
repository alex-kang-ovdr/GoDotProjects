# G2 변경 명세

작성일: **2026-11-20**. 기준 프로젝트: 사용자의 v14 웹 프로토타입을 포팅한 Godot G1. G2는 이 프로젝트의 전투 흐름·표현·조작·저장 경험을 개선한 버전입니다.

## 1. 보스전의 구분과 회피 기회

G1은 중간 보스가 살아 있는 동안 일반 웨이브가 계속 누적됐고, 다음 보스 시각까지 처치하지 못하면 보스가 겹칠 수 있었습니다. G2는 보스 진입·교전·회복을 `encounter` 메타데이터로 관리합니다. UI 상태를 별도로 늘리지 않아 선택·정지·이어하기와 같은 기존 전투 상태 흐름을 유지합니다.

| 구간 | G2 동작 |
|---|---|
| 사전 안내 | 예정 등장 8초 전 보스 접근 안내 |
| 등장 | 기존 일반 몬스터와 적 탄환·공격 예고 정리. 정리만으로 처치·XP·골드 지급 안 함 |
| 준비 | 1.6초 동안 적 AI와 예고 공격이 멈춤. 플레이어는 이동·공격 가능, 받는 피해 차단 |
| 교전 | 일반 웨이브·엘리트·보급 이벤트 대기. 보스의 소환 패턴은 실행 |
| 중간 보스 처치 | 잔여 소환수·적 공격 정리 후 2초 동안 일반 디렉터 재개 대기 |
| 일정 중첩 | 이전 보스가 살아 있거나 회복 중이면 다음 이벤트를 대기시키며 순서 보존 |
| 최종 보스 처치 | 승리·정산으로 전환 |

무기 피해량·적 능력치·기본 쿨다운 배열을 이 변경의 수단으로 바꾸지 않았습니다. 준비·회복·이벤트 지연은 G2가 새로 선택한 플레이 규칙입니다. 원작 클라이언트에서 복구한 값이라는 의미가 아닙니다.

HUD는 보스 등장 준비 시간, 현재 페이즈, 패턴별 회피 안내를 표시합니다. `last_damage`는 실제 적용된 피해만 기록해 패배 화면과 최근 전투 기록에서 마지막 피해 원인을 확인할 수 있게 합니다.

## 2. 선택을 이해할 수 있는 성장 카드

카드는 현재 전투의 보조 능력치와 부품 설정을 반영한 값을 표시합니다. 피해는 단일 타격 기준이며 여러 적을 맞히는 범위 공격의 총 DPS로 표현하지 않습니다.

- 무기: 전후 타격 피해, 공격 간격, 투사체·칼날·화염 지대·낙뢰 대상 수, 필요한 경우 탄창·재장전·범위·지속시간.
- 보조: 누적 효과의 전후 비율, 주무기 피해 또는 간격, 실제 최대 HP·회복량·이동 속도·흡수 반경 등의 변화.
- 진화: 주무기 5레벨과 대응 보조 1레벨의 진행도. A/B 드론은 두 액티브의 5레벨 조건을 따로 표시.
- 조건을 만족하는 카드는 다음 진화 후보가 될 수 있음을 안내합니다. 일반 성장 카드를 고르는 것만으로 자동 진화하지 않습니다.
- 파괴자 합체는 액티브 두 칸을 한 칸으로 바꾸는 효과를 명시합니다.

카탈로그의 `preview_upgrade()`는 RNG·슬롯·실제 전투 값을 수정하지 않습니다. 수호자의 타격 간격처럼 일반 발사 쿨다운과 다른 규칙은 별도 문구를 사용합니다. 원래 약어로 표시하던 스킬은 코드로 그린 아이콘과 레벨 표시를 함께 사용합니다.

## 3. 3D 그래픽과 전투 피드백

블록형 캐릭터를 유지하면서 주무기 반동·총구 섬광·발사체 잔상·처치 블록 파편을 추가했습니다. 진화한 무기의 장착 모델과 투사체 색을 구별하며, 보스 등장과 2페이즈도 별도 링·표식으로 표시합니다.

| 전장 | 배경 형상 |
|---|---|
| 도시 | 상점·차양·화단·도로 주변 장식 |
| 사막 | 메사형 바위·태양광 전초기지·선인장·모래결 |
| 빙결 | 수정 군집·연구동·통신 마스트·얼음결 |

세 전장은 색만 바꾸지 않고 장식물 형상도 구분합니다. 건물·수정·식생은 장식이며 충돌·엄폐물로 작동하지 않습니다. 원작이나 Roblox의 모델·텍스처를 사용하지 않았습니다.

반복 효과는 정해진 크기의 MultiMesh를 사용합니다. 공격 예고를 선택적 전투 효과보다 먼저 배치해 예산이 찬 상황에서 위협 정보를 우선합니다. 렌더러는 시뮬레이션과 난수를 수정하지 않습니다.

실제 GL 화면 검수에서 대각선 돌진 예고가 좁은 쐐기처럼 변형되는 문제를 발견했습니다. 회전된 형상에 전역 축 스케일을 적용하던 다섯 경로를 로컬 축 스케일로 고쳐 예고 폭·양 끝점이 실제 충돌 선분과 일치하도록 했습니다. 적 부품·파편·장식의 비균일 크기도 회전 방향에 맞게 보존합니다. 여섯 방향의 예고와 수직선을 포함한 3D 선분을 렌더러 업로드 행렬로 검사합니다. 엔진의 축 스케일 의미는 [Godot 4.6 Basis 문서](https://docs.godotengine.org/en/4.6/classes/class_basis.html)를 기준으로 확인했습니다.

## 4. 설정·레이더·조작

로비와 일시정지 화면에 설정 창을 추가했습니다. 효과음 켜기/끄기, 음량, 그림자와 MSAA 품질, 피격 화면 흔들림, 피해 숫자, 전술 레이더를 조절합니다. 변경은 즉시 적용하고 0.35초 지연 후 저장해 음량 드래그 때 파일을 과도하게 쓰지 않습니다. 종료·로비 전환에서는 저장 대기 값을 먼저 확정합니다.

설정에서 Esc를 누르면 원래 로비 또는 정지 화면으로 돌아옵니다. 정지 중 설정을 닫았다는 이유로 전투가 재개되지 않습니다. 설정 창에서 M/N 단축키를 사용해도 기존 토글 표시가 실제 값과 동기화되며 음량 슬라이더 포커스를 유지합니다.

레이더는 플레이어 중심의 주변 적·보스·보급·회복 아이템을 보여 줍니다. **N**으로 즉시 전환할 수 있습니다. 적과 픽업 표시량을 제한하며 전투 데이터의 읽기만 수행합니다.

터치 조이스틱은 네이티브 GUI가 먼저 처리한 입력을 가져가지 않습니다. 화면 버튼을 누를 때 이동이 시작되는 문제를 막고, 터치 해제·정지·포커스 손실에서 이동 벡터를 비웁니다. W는 화면 위, S는 화면 아래인 좌표 규칙을 유지했습니다.

## 5. 전투 기록과 저장 호환

프로필 스키마 2는 G1의 전투 횟수·승리·최고 처치·크레딧·중복 정산 방지 ID·효과음/품질 설정을 이어받습니다. 새 항목이 없을 때만 G2 기본값을 넣습니다. G1에 저장하지 않았던 과거 개별 전투 기록은 만들어 내지 않습니다.

새로 완료한 전투는 최근 12개를 최신순으로 남깁니다. 승패, 전장, 무기, 모드, 생존 시간, 처치, 레벨, 진화, 실제 누적 피해, 획득 크레딧과 패배 원인을 보존합니다. 전장별로 승리 수·최고 처치·최고 레벨·최단 승리 시간을 기록합니다.

중복 정산은 크레딧·승리·히스토리를 다시 추가하지 않습니다. 저장 실패 시 프로필의 메모리 값도 확정하지 않으며, 로비·재시작·창 닫기에서 저장을 재시도합니다. 이미 정산된 화면에서 설정을 바꾼 직후 이동하는 경우에도 대기 중인 설정 쓰기를 누락하지 않습니다.

G2 전투 저장에는 보스 준비·회복·패턴 표시 시계와 마지막 피해 기록이 추가됩니다. G1의 기존 전투 저장은 새 메타데이터가 없어도 복원하도록 처리합니다. JSON 체크섬·백업·필드 검증·난수 상태·무기 처리 순서 보존을 유지합니다.

G1의 15분 모드에서 두 중간 보스가 함께 저장된 실제 사례 형식도 검증했습니다. 기존 엔티티·통계·진행 중 공격을 보존하고, 추적하던 보스 처치 즉시 다른 보스로 소유권을 옮겨 같은 프레임의 재저장도 유효하게 만듭니다. 마지막 기존 보스가 죽은 뒤 회복 구간을 시작합니다. 해당 픽스처는 수정하지 않은 G1 코드로 생성했으며, 파일과 생성 소스 해시를 `tests/fixtures/`에 함께 보관합니다.

## 6. 검증 자료

최종 수치와 플랫폼 실행 범위는 [`BUILD_AND_TEST.md`](BUILD_AND_TEST.md)에 기록합니다. 각 기능은 저장된 테스트 코드와 JSON 결과로 재현할 수 있습니다. 실제 GL 캡처는 `tests/captures/`, 기본 능력치 자동 전투는 `tests/balance_probe_report.json`에 있으며 두 자료의 목적을 구분합니다.
