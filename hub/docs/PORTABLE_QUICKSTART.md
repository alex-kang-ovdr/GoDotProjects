# PlayHub Portable 빠른 시작

PlayHub Portable은 경량 게임 8종, 사용자 사이트, 관리자 사이트, 저장·이용 지표 API를 한 번의 실행으로 시작하는 Windows용 로컬 PoC다. 사용자는 **SQL 서버·Node.js·IIS를 설치하지 않는다.** SQLite와 Node 런타임은 PlayHub 쪽에 포함하며, 사용자 사이트의 정적 파일 서버는 사용자가 이미 보유한 Rebex Tiny Web Server를 연결한다.

이 문서의 실행 진입점은 `PlayHub.exe`다. 소스 저장소의 기존 `Install.cmd`, IIS 설치 스크립트, `npm` 명령은 이 포터블 사용 절차에 포함되지 않는다. 기존 IIS 버전과 동시에 같은 포트를 사용할 수 없으므로 먼저 해당 실행을 종료하거나 포트 충돌 안내를 해결한다.

## 1. 처음 실행하기

1. 기존 `RebexTinyWebServer.exe`가 있는 폴더에 `PlayHub.exe`를 복사한다.
2. 배포 담당자가 서비스를 종료한 상태에서 PowerShell에서 `.\PlayHub.exe --prepare`를 실행해 정적 사이트와 초기 설정을 배포한다.
3. `PlayHub.exe`를 더블클릭한다. 기존 Rebex 파일을 찾지 못하면 처음 한 번 표시되는 파일 선택 창에서 해당 EXE를 선택한다.
4. 서버가 준비되면 사용자 사이트가 브라우저에서 열린다. 관리자 사이트 주소도 실행 안내에서 확인할 수 있다.

일반 실행은 저장한 경로 설정과 배포된 정적 사이트를 사용한다. 사이트가 없거나 포트 등 사이트용 설정이 배포와 다르면 `PORTABLE_DEPLOYMENT_REQUIRED`가 표시되며, 배포 담당자가 `--prepare`를 실행해 반영한다. 실행 데이터는 기본적으로 **`%LOCALAPPDATA%\PlayHub`** 아래에 생성된다.

최초 준비 때 관리자 이름 `admin`과 무작위 초기 비밀번호를 실행 창에 표시한다. 비밀번호는 평문 파일이나 시작 보고서에 저장하지 않으므로 안전하게 보관한다. 재실행할 때 기존 비밀번호를 다시 표시하지 않는다. 잊었다면 실행 창에서 `Q`로 종료한 뒤 `PlayHub.exe --reset-admin-password`로 새 비밀번호를 만들 수 있다. 이 작업은 기존 관리자 세션을 폐기한다.

Windows의 실행 파일 보안 확인이나 방화벽 확인은 사용자의 시스템 정책에 따라 표시될 수 있다. 실패한 실행을 성공으로 표시하지 않으며, 포트 충돌·Rebex 파일 부재·데이터 폴더 쓰기 실패는 실행 안내와 보고서에서 확인해야 한다. Windows 로그인 없이 부팅 시 자동 서비스로 동작시키는 구성은 이번 포터블 범위가 아니다.

## 2. 실제로 무엇이 실행되는가

| 구성 | 역할 | 접근 범위 |
|---|---|---|
| PlayHub 실행기 | 배포 자산 검증, 프로세스 시작·종료, 상태 확인 | 현재 Windows 사용자 |
| 사용자 사이트 / Rebex | 게임 목록·소개·HTML/CSS/JS·게임 파일 | 로컬 PC, 허용된 LAN |
| 관리자 사이트 / 별도 Node worker | 관리자 화면의 독립 정적 루트 | `127.0.0.1`의 로컬 PC |
| API worker | 게스트·Google 계정·저장·통계·관리자 API | 사용자 API와 loopback 관리자 API 분리 |
| Rebex supervisor | 이번 실행의 Rebex 수명 관리 | 소유한 Rebex 프로세스만 관리 |
| SQLite | 게임 저장, 세션, 이벤트, 관리자 설정 기록 | 서버의 데이터 폴더; 정적 사이트 밖 |

‘EXE 한 번 실행’은 사용자가 여러 서버를 따로 켤 필요가 없다는 의미다. 내부에는 역할별 프로세스와 정적 파일, 데이터 파일이 생성된다. Rebex 실행 파일 하나가 Google 로그인이나 데이터베이스 API까지 처리하는 것은 아니다.

사용자 사이트와 관리자 사이트는 주소만 다른 한 폴더가 아니다. **정적 파일 폴더와 서버 프로세스가 분리되며**, 관리자 사이트와 관리자 API는 loopback으로 제한한다. 기본 사용자 화면 포트는 8080, 관리자 화면은 8081, 사용자 API는 8090, 관리자 API는 8091을 사용하도록 설계되어 있다. 실제 시작 주소는 실행 안내와 `startup-report.json`의 값을 기준으로 확인한다.

일반 실행은 설정에 저장된 포트를 사용한다. 다른 프로그램이 포트를 차지하면 충돌을 해결한 뒤 다시 실행한다. 포트를 변경했다면 정적 사이트를 먼저 수동 배포한다.

## 3. 로그인 없이 게임하기

사용자 사이트를 열고 게임 카드를 누른 뒤 실행한다. Google 로그인은 필수가 아니다. API와 쿠키를 사용할 수 있으면 첫 플레이에서 게스트 기록이 만들어지고 저장이 서버에 연결된다.

| 게임 | 이번 PoC 규칙 |
|---|---|
| 매치 가든 | 8×8 매치3, 25회 이동 안에 목표 점수 |
| 블록 드롭 | 10×18 낙하 블록, 20줄 목표 |
| 버블 스플릿 | 공을 공격해 나누는 액션, 시간·기회 제한 |
| 브릭 브레이크 | 40개 벽돌 제거, 기회 세 번 |
| 슬라이드 나인 | 3×3 숫자 퍼즐 |
| 마인 그리드 | 9×9 보드, 지뢰 10개 |
| 메모리 페어 | 4×4 카드, 여덟 쌍 찾기 |
| 머지 타일 | 4×4 숫자 합치기, 2048 목표 |

게임별 자세한 입력·승패·저장 필드와 미구현 고급 기능은 [POC_GAMES.md](POC_GAMES.md)에 정리되어 있다. 포터블 전환은 이 8종의 규칙을 늘리는 작업이 아니라 실행·배포 방법을 바꾸는 작업이다.

## 4. 저장과 복구

게임 상세의 **저장 기록**에서 서버 이어하기, 현재 탭의 임시 기록, 보관 슬롯, 교체 전 백업을 확인한다. 다른 탭에서 같은 기록이 바뀌면 자동으로 덮어쓰지 않고 충돌을 표시한다. 현재 탭 진행을 먼저 별도 보관한 뒤 이어하기로 적용하거나 서버 기록을 선택할 수 있다.

API가 일시적으로 연결되지 않거나 쿠키를 유지할 수 없는 경우에는 검증된 내장 게임을 로컬 모드로 실행할 수 있다. 이때는 **현재 탭 임시 저장**이며 서버 저장·서버 게임 통계·다른 기기 복구가 제공되지 않는다. 서버가 정상적으로 비활성·접근 거부한 게임을 로컬 모드로 우회하지 않는다.

게스트 저장의 연결 정보는 브라우저 쿠키에 의존한다. 쿠키 삭제·게스트 로그아웃·브라우저 데이터 제거 뒤 동일한 기록으로 자동 복귀하는 기능은 보장하지 않는다. Google 연결은 선택 기능이며, 연결 시 기존 게스트 기록을 어떻게 처리할지 명시적으로 선택한다.

데이터 폴더를 지우면 DB와 설정도 삭제될 수 있다. 프로그램 파일 교체와 데이터 폴더 삭제를 같은 작업으로 취급하지 않는다. 실행 중인 SQLite 파일을 탐색기로 복사하여 정상 백업이 끝났다고 판단하지 않는다. 포터블 데이터 백업·복구는 지원되는 절차와 실제 검증 범위를 확인한 뒤 수행한다.

## 5. 관리자 화면과 지표

관리자 화면은 실행한 PC의 브라우저에서 연다. 일반 게임 사용자의 쿠키로 관리자 로그인이 되지 않는다. 관리자 로그인 정보는 최초 준비 과정의 안내를 따르며, 고정 공용 비밀번호를 사용하지 않는다.

지표 화면에는 다음 세 가지 데이터가 분리되어 있다.

| 보기 | 의미 |
|---|---|
| 실제 | 일반 방문·플레이 기록 |
| QA | 자동 검사에서 명시적으로 생성한 시험 기록 |
| 예제 | UI 확인용 고정 가상 데이터 |

기간 필터는 KST 날짜 기준이며, 게임 필터로 개별 게임을 조회할 수 있다. 노출은 카드의 50% 이상이 문서가 보이는 상태로 1초 유지됐을 때 집계한다. 그 전에 누른 클릭은 별도 조건으로 기록한다. D1·D7·D30은 성숙한 코호트만 확정하며, 아직 시간이 지나지 않은 값은 0% 대신 집계 대기로 표시한다. 기획상의 32개 지표 전체가 이번 화면의 모든 카드로 구현되었다는 의미는 아니다.

## 6. 같은 네트워크에서 사용하기

게임을 제공하는 PC에서 실행한 뒤, 다른 PC·휴대전화는 해당 PC의 LAN 주소와 사용자 사이트 포트로 접근한다. 예를 들어 `http://192.168.0.20:8080/` 같은 형식이다. 실제 IP와 포트는 실행 안내를 사용한다. 다른 기기에서 `localhost`를 열면 서버 PC가 아니라 그 기기 자신을 가리킨다.

사용자 사이트와 사용자 API의 포트가 Windows 방화벽에서 현재 네트워크에 허용되어야 한다. 방화벽 정책 변경이 필요한 환경에서는 관리자 권한이나 조직 정책 승인이 필요할 수 있다. 설치 없는 로컬 실행과 LAN 방화벽 설정이 필요 없는 것은 같은 의미가 아니다.

관리자 사이트와 관리자 API는 LAN에 공개하지 않는다. 사용자 사이트에 관리자 화면 링크를 추가하거나 사용자 포트를 열었다는 이유로 관리자 권한이 생기지 않는다. 인터넷 공개 서비스나 공유기 포트 전달을 이번 PoC의 검증된 운영 방식으로 간주하지 않는다.

## 7. Google 로그인은 별도 설정이 필요하다

게스트 플레이는 외부 인증 설정 없이 사용할 수 있다. 실제 Google 로그인에는 사용자의 Google OAuth client ID·client secret·정확한 redirect URI가 필요하다. 비밀 값은 사용자 사이트의 `config.js`나 정적 폴더에 넣지 않는다.

서버 설정 파일은 `%LOCALAPPDATA%\PlayHub\private\config\local.json`이다. 실행을 종료한 뒤 해당 파일의 `google` 항목을 설정하고 재실행한다. 다른 설정·관리자 해시·데이터 경로는 그대로 유지한다. callback은 현재 선택한 사용자 API 포트의 `http://localhost:<API포트>/api/auth/google/callback`과 Google Console의 등록값을 일치시킨다. 이 localhost 구성은 같은 PC 브라우저의 로컬 검증용이다.

설정이 없으면 화면은 설정이 필요하다고 알리고 게스트 플레이를 유지한다. 시험 계정으로 로그인된 것처럼 표시하지 않는다. HTTP LAN 주소와 `localhost` callback을 섞으면 다른 기기의 브라우저에서 인증 흐름을 완료할 수 없다. 이번 LAN PoC는 게스트 흐름을 기본으로 사용하고, Google은 올바른 호스트·HTTPS·OAuth 설정이 갖춰진 조건에서 별도로 검증한다.

## 8. 종료·재실행·문제 확인

브라우저 탭을 닫는 것과 서버 프로세스를 종료하는 것은 다르다. PlayHub 실행기의 종료 기능을 사용하여 해당 실행이 시작한 자식 프로세스를 정리한다. 사용자가 별도로 실행한 원본 Rebex를 이름만 보고 일괄 종료하는 방식은 사용하지 않는다.

실행 창에서 `U`를 입력하면 사용자 화면, `A`는 관리자 화면을 연다. `Q`는 이번 실행을 종료한다. 시작 보고서는 `%LOCALAPPDATA%\PlayHub\reports\startup-report.json`에 있다. 기본 위치 외에 `--data-dir <폴더>`를 사용한 경우에는 해당 폴더 아래의 같은 구조를 사용한다.

문제가 생기면 다음 순서로 확인한다.

1. PlayHub가 준비 완료를 표시했는지, 시작 보고서에 실패 사유가 있는지 확인한다.
2. 같은 PC의 사용자 사이트와 관리자 사이트가 각각 열리는지 확인한다.
3. 게임에 로컬 모드 표시가 있다면 사용자 API와 쿠키 연결 상태를 확인한다.
4. LAN 접속만 실패하면 서버 PC의 현재 IP·포트·방화벽을 확인한다.
5. 포트가 사용 중이면 기존 PlayHub 또는 IIS 실행 여부를 먼저 확인한다. 다른 프로그램을 임의로 종료하지 않는다.

지원 자료로 보고서를 전달할 때도 관리자 비밀번호·Google secret·쿠키·CSRF 값을 함께 보내지 않는다. 정상 보고서는 이 비밀 값을 기록하지 않도록 구성한다.

## 9. 검증 상태를 읽는 방법

소스 자동 검사, EXE 패키징 검사, 실제 Windows 실행, 브라우저 조작, 다른 기기의 LAN 접속, Google 실인증은 서로 다른 검사다. 하나의 성공을 다른 검사의 성공으로 바꾸지 않는다.

현재 제작 환경에서는 **실제 Windows·Rebex 실행과 브라우저 시험을 수행하지 않았으며 `not_run`**으로 기록한다. `portable/windows-acceptance.ps1`은 사용자 PC에서 이미 실행 중인 인스턴스를 관측하여 실제 응답·프로세스·폴더 분리를 검사하기 위한 도구다. 선택 QA 검사는 별도 시험 방문과 저장 데이터를 만들며 실제 이용 지표와 분리한다. 상세 계약과 체크 목록은 [PORTABLE_DESIGN.md](PORTABLE_DESIGN.md)를 참조한다.

실행 중인 기본 인스턴스를 관리자 인증을 포함해 검사하려면 Windows PowerShell에서 다음을 실행한다. 비밀번호는 숨겨진 입력창에서 받고 명령줄에 넣지 않는다.

```powershell
$playhubRoot = Join-Path $env:LOCALAPPDATA 'PlayHub'
$playhubStartup = Get-Content (Join-Path $playhubRoot 'reports\startup-report.json') -Raw -Encoding UTF8 | ConvertFrom-Json
$playhubCheck = Join-Path $playhubStartup.paths.appRoot 'portable\windows-acceptance.ps1'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $playhubCheck -DataDir $playhubRoot -WithAdmin
```

`-WithAdmin`을 빼면 기본 관측만 수행한다. 관리자 인증 없이 QA HTTP만 확인하려면 `-WithHttpSmoke`를 사용한다. 이 경우 관리자 권한 검사는 미완료로 남을 수 있다. 결과는 `reports\portable-acceptance.json`과 `.html`, 선택 HTTP 상세 결과는 `reports\portable-http.json`에 기록된다. 종료 코드 0은 선택한 자동 검사 범위의 관측 통과이며, 브라우저·다른 기기 LAN·Google 실인증까지 완료했다는 의미는 아니다. 실패는 1, 미완료는 2다.

### 게임 폴더와 목록 변경

편집 가능한 게임 원본은 `%LOCALAPPDATA%\PlayHub\workspace\games`, 중앙 목록은 `workspace\catalog\games.json`이다. 게임을 추가할 때는 `games/<id>/`에 manifest·index.html·자산을 넣고 중앙 목록에 `{ "id": "<id>", "path": "games/<id>", "enabled": true }` 항목을 추가한다. 종료 후 배포 담당자가 `PlayHub.exe --prepare`로 검증과 정적 페이지 생성을 수행한다. 잘못된 manifest나 경로를 고친 다음 다시 배포한다.

이 편집 영역의 게임·카탈로그는 다음 실행에서도 보존된다. `workspace\web`과 `workspace\shared`는 패키지의 앱 코드로 갱신되므로 사용자 콘텐츠의 영구 편집 위치로 사용하지 않는다. 현재 범위는 신뢰된 로컬 파일 카탈로그이며 외부 제작자 업로드·검수 시스템은 포함하지 않는다.

## 10. Rebex 사용 조건

Rebex Tiny Web Server는 상업·비상업 사용이 무료인 정적 서버지만, 공식 EULA는 다른 애플리케이션의 런타임 구성 요소로 재배포할 때 명시적 허가를 요구한다. 따라서 PlayHub 배포 파일에 Rebex 바이너리를 포함하지 않고 사용자가 보유한 파일을 연결한다.

- 제품·설정: https://www.rebex.net/tiny-web-server/
- 공식 EULA: https://www.rebex.net/Content/doc/freeware-eula.txt
- 정적 서버 기능 설명: https://forum.rebex.net/22547/tiny-web-server-can-run-php
- SQLite 설치 없는 동작 설명: https://www.sqlite.org/serverless.html

Rebex 공식 ZIP은 .NET Framework 4.6 이상을 전제로 한다. SQL·Node·IIS 설치를 요구하지 않는다는 설명이 Windows/.NET 자체 요구 사항까지 없다는 뜻은 아니다.
