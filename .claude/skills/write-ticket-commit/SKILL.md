# 전역 커밋 메시지 작성

저장소와 워크트리의 커밋 규칙을 먼저 확인한다. 예를 들어 `PlayHub-Platform`의 영역 태그는 해당 워크트리의 `write-commit` 스킬을 적용한다.

- 전역 기본 제목은 `[티켓번호] 한국어 변경 요약`이다. 사용자 요청이나 확인된 작업 문맥에서 실제 티켓 번호를 가져온다.
- 전역 기본 형식에서 대괄호 안에는 실제 티켓 번호만 쓴다. 작업 영역이나 변경 유형을 대괄호에 넣지 않는다. `feat:`, `fix:`, `docs:`는 필요하면 티켓 태그 뒤에 붙인다.
- 티켓 번호를 확인할 수 없으면 대괄호 태그 없이 제목을 작성한다. 저장소가 티켓 번호를 필수로 요구하면 번호를 확인하기 전에는 커밋하지 않는다.

```text
[OVDR-16146] fix: 공이 바닥을 통과하는 충돌 문제 수정
```

제목 뒤에 빈 줄을 두고, 본문에 `변경 이유`, `요청 내용`, `변경 내용`, `사용 모델 및 작업 시간`을 한국어로 작성한다. 변경 이유에는 기존 문제나 변경의 필요성을, 요청 내용에는 사용자가 요구한 결과를, 변경 내용에는 커밋에 실제로 포함된 차이를 적는다. 모델 ID와 작업 시간은 확인된 값만 기록한다. 알 수 없으면 `모델 ID 확인 불가` 또는 `작업 시간 미측정`으로 적는다.

메시지 작성만 요청받으면 초안을 반환한다. 실제 커밋이 요청된 경우 승인된 변경 범위에 대해 UTF-8 메시지 파일을 `git commit -F`로 전달하고 결과를 확인한다.
