# 커밋 메시지 작성

이 스킬은 `PlayHub-Platform` 워크트리에 적용한다. 커밋할 변경 범위와 해당 저장소의 메시지 규칙을 먼저 확인한다. 요청 내용은 사용자가 원한 결과로, 변경 이유는 기존 동작의 문제나 이번 변경의 필요성으로 구분한다. 변경 내용은 커밋에 실제로 포함된 차이를 기준으로 적는다.

## 형식

제목은 `[분류] 한국어 제목`으로 쓴다. 핵심 변경을 한 줄로 특정하고 제목 뒤에 빈 줄을 둔다. 저장소에 분류 태그가 지정되어 있으면 이를 사용한다. 없으면 `[기능]`, `[수정]`, `[개선]`, `[이관]`, `[문서]`, `[테스트]`, `[빌드]`, `[정리]` 가운데 주된 목적에 맞는 하나를 고른다. 저장소에서 요구하는 공용 또는 티켓 태그가 있으면 해당 규칙도 따른다.

```text
[이관] PlayForge 원본 기록과 로컬 작업 데이터를 통합 워크트리로 이관

변경 이유
- 통합 워크트리에서 기존 작업을 이어가면서 원본 커밋을 복구할 수 있어야 한다.

요청 내용
- PlayForge 개발 경로를 PlayHub-Platform으로 이관하고 검증 후 기존 워크트리를 정리한다.

변경 내용
- 원본 커밋 전체를 담은 Git 번들의 복구 경로와 확인 방법을 기록했다.
- 미커밋 파일과 로컬 저장 데이터의 백업 위치를 문서화했다.

사용 모델 및 작업 시간
- 사용 모델: <확인된 모델 ID. 기여한 서브 에이전트가 있으면 함께 기재>
- 작업 시간: <이 변경을 시작한 시점부터 커밋 직전까지 실제로 잰 경과 시간>
```

본문의 모든 항목을 한글로 작성하되 모델 ID, 파일명, 제품명 등 고유 식별자는 그대로 쓴다. 여러 변경이 있으면 검토자가 동작과 영향을 이해할 수 있는 단위로 나눈다. 검증 결과가 필요하면 변경 내용에 짧게 덧붙이고, 실행한 확인과 생략한 확인을 구분한다. 모델과 시간을 확인할 수 없으면 각각 `모델 ID 확인 불가`, `작업 시간 미측정`이라고 적고 추정치를 사실처럼 쓰지 않는다. 위 예시의 꺾쇠 자리표시자는 실제 메시지에서 제거한다.

AI 에이전트가 커밋하는 경우 본문 마지막에 빈 줄을 두고 `Agent-User-Requests`, `Agent-Elapsed`, `Agent-Permission-Requests`, `Agent-Decision-Requests`, `Agent-Tokens-Total`, `Agent-Tokens-Model` Git trailer를 붙인다. 커밋 메시지 작성 직전에 반드시 샌드박스(`BypassSandbox: false`)에서 아래 집계 스크립트를 실행해 대화 트랜스크립트(`transcript.jsonl`)의 실측값을 추출하고, `사용 모델 및 작업 시간` 및 `Agent-*` trailer에 그대로 반영한다(`N/A`로 남기지 않는다).

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File d:\Github\GoDotProjects-worktrees\PlayHub-Platform\tools\agent-skills\collect-agent-metrics.ps1 -SinceLastCommit
```

트랜스크립트 파일이 아예 존재하지 않는 환경에서만 예외적으로 `N/A`로 적는다. 커밋 전 `npm run gate`(소유권·스킬 동기화·Fast QA) 통과 여부를 변경 내용의 검증 항목에 기록한다.

## PlayHub-Platform 워크트리 규칙

`PlayHub-Platform`에서 커밋할 때는 제목 맨 앞에 변경 영역 태그를 붙인다. 실제 커밋에 포함된 영역에서 하나 이상을 선택한다.

- `[Admin]` 관리자 기능
- `[Hub]` PlayHub 플랫폼
- `[Forge]` PlayForge 서버와 편집기
- `[GD-Ext]` 기본 Godot API 위에서 동작하는 EditorPlugin, 애드온, GDExtension 등 확장 코드
- `[GD-Core]` 기본 Godot 엔진 포크의 코어 소스 변경 또는 해당 변경을 가져오는 서브모듈 갱신
- `[Game]` 게임과 게임 콘텐츠
- `[Script]` 실행, 빌드, 배포, 자동화 스크립트
- `[Tool]` 에디터 보조, 디버깅, 검증 등 내부 개발 도구
- `[QA]` QA 자동화 및 검수 도구

여러 영역을 함께 변경하면 해당 태그를 연달아 붙인다. `feat:`, `fix:`, `docs:` 같은 변경 유형은 영역 태그 뒤에 선택적으로 붙인다. 일반 형식의 `[기능]`, `[이관]` 등은 이 워크트리의 영역 태그를 대신하지 않는다. 본문은 위의 한국어 형식을 그대로 따른다.

엔진 포크를 가리키는 gitlink가 바뀌면 old/new 구간의 실제 엔진 커밋을 확인해 코어 소스 변경을 가져오는 경우에 `[GD-Core]`를 사용한다. 런처나 빌드·배포 스크립트만 바뀌면 `[Script]`를 사용한다.

```text
[Admin][Hub] feat: 관리자 화면에 배포 상태 조회 추가
[Forge] docs: 작업 데이터 백업 및 복구 절차 정리
[Forge][GD-Ext] feat: 에디터 플러그인에 씬 제작 시연 추가
[GD-Core] fix: Godot 포크의 웹 에디터 입력 처리 수정
```

커밋을 실행할 때는 제목과 본문 전체를 UTF-8 임시 파일로 작성해 `git commit -F`로 전달한다. 이때 권한 승인 프롬프트가 매번 재발하지 않도록(Prefix-Match 자동 승인 유지) `$변수`, `$(...)`, `;`, `if ($LASTEXITCODE)` 체인을 섞지 말고 반드시 단일 리터럴 명령(`git -C <워크트리경로> add ...`, `git -C <워크트리경로> commit -F <메시지파일>`, `git -C <워크트리경로> push origin <브랜치>`)으로 각각 실행한다. 커밋 후 실제 메시지의 제목 태그와 본문 항목을 확인한다. 메시지 작성 요청만 받은 경우 초안을 반환한다. 이미 생성된 커밋을 다시 쓰거나 푸시하는 권한은 별도로 판단한다.
