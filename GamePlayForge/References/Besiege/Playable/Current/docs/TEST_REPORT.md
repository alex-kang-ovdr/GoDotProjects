# IRONWOOD 4.0 — 일시정지 점검과 시험 보고서

기준 구현: [report.js](../dist/report.js), [main.js](../dist/main.js), [scene.js](../dist/scene.js).

## 1. 닫힌 제작 루프

기체 제작 → 시험 → 실제 물리 사건 기록 → 점검 → 원본 설계 복원 → 관련 부품 수정의 흐름입니다. 시험 중 부품을 클릭하면 물리를 멈추고 해당 부품을 선택합니다. 물리 엔진의 HP, 코어 연결, 연결 파손, 하중비, 누적 연결 손상을 직접 읽어 표시합니다.

계기판이 숨겨지는 좁은 화면에도 별도의 점검 도구를 둡니다. 코어 점검, 보고서, 한 스텝, 저속, 연결 색상 기준을 사용할 수 있습니다. 피스톤에는 실제 이동·목표·행정·구동 사용률도 표시합니다.

## 2. 일시정지와 한 스텝

일시정지 상태에서는 시간 적분이 진행되지 않습니다. 카메라를 돌리거나 부품을 고르는 UI는 계속 작동합니다. **한 스텝**은 일시정지 중에만 입력을 비우고 1/60초를 요청합니다. 내부 고정 간격은 1/120초이므로 일반적으로 두 물리 스텝에 해당합니다. 입력이 없는 상태에서도 중력, 기존 운동량, 접촉, 적의 시간 조건은 해당 구간만큼 진행됩니다.

종료가 확정된 세계에는 한 스텝을 적용하지 않습니다. 메뉴를 열 때 자동 일시정지했으면 선택 없이 닫을 때 이어가고, 이미 사용자가 멈춘 상태였다면 닫아도 멈춘 상태를 유지합니다. 다른 설계나 작전을 적용하면 새 세션으로 전환합니다.

## 3. 하중과 손상 분리

| 표시 모드 | 데이터 | 해석 |
| --- | --- | --- |
| 순간 하중비 | `connection.stress` | 현재 솔버 제약 하중 / 해당 연결 강도 |
| 누적 연결 손상 | `1-connection.health` | 충격·폭발 등으로 잃은 연결 건강도 |
| 부품 HP | `partStates[id].hp` | 부품 자체의 생존 내구도 |
| 피스톤 구동 사용률 | 구동 축 힘 / 힘 한도 | 액추에이터가 사용 중인 힘의 비율 |

색은 초록→노랑→빨강으로 0→55→100%를 구분합니다. 100%가 넘는 하중도 숫자에는 그대로 표시하며 색의 상한은 빨강입니다. 하중과 손상을 max()로 합쳐 표시하지 않습니다. 높은 순간 하중, 누적된 연결 손상, 부품 HP 소진은 서로 다른 원인입니다.

일반 하중비는 여러 구속 방정식의 multiplier 최대값을 사용한 게임용 비교 지표입니다. 서로 다른 제약 성분을 포함하므로 재료 응력 Pa나 단일 힘 N으로 표현하지 않습니다. 피스톤의 구동 사용률은 별도 축 방정식에서 계산합니다.

## 4. 수집하는 기록

보고서는 출격 당시의 독립 설계 사본과 작전을 보관합니다. 시뮬레이션 시간 기준 최소 1/12초 간격으로 속도·부품 HP·코어 연결·연결 건강도·하중비를 표본 수집합니다. 렌더 프레임에 따라 실제 빈도는 낮아질 수 있습니다. 종료·보고서 열기·조립 복귀 시 추가 표본을 수집합니다.

| 기록 | 수집 방식 |
| --- | --- |
| 시험 시간, 코어 HP, 연결 유지율 | 마지막 표본 |
| 최고 속도, 부품별 최대 하중비 | 관측 표본의 최대값 |
| 부품 피해량, 최초 피해 시점, 피해 원인 | 실제 damage 이벤트 누계 |
| 최초 연결 파손 | 해당 보고서가 유지되는 동안 최초 break 이벤트를 별도 보존 |
| 연결별 파손 시점·원인·직전 하중 | break 이벤트와 상태 표본 |
| 관문 통과·승패 | 실제 terminal/checkpoint 이벤트 |
| 최근 사건 | 최대 100개, 화면에는 최근 24개 |

이벤트를 오래 보관한다고 메모리가 계속 증가하지 않게 제한합니다. 최근 사건 목록에서 사라져도 최초 파손과 연결별 파손 정보, 부품별 피해 누계는 별도로 유지합니다. 보고서의 최고 하중은 모든 120Hz 스텝을 기록한 연속 최대값이 아닙니다. 파단 순간의 이벤트 값은 추가로 반영합니다.

## 5. 파손 원인과 권고

`stress`는 하중 기준 초과, `impact`는 연결 건강도 소진, `part-destroyed`는 부품 HP 0으로 인한 연결 해제를 뜻합니다. 보고서는 실제 원인 코드와 부품 좌표를 보여 줍니다. 기록에 따라 지지 경로·보강·상부 중량·근거리 폭발·코어 보호·부력 등을 점검하도록 권고합니다.

권고는 실패를 완벽하게 설명하는 인과 분석기가 아닙니다. 예를 들어 첫 연결의 하중 파단은 보강 부족일 수도 있고, 의도한 분리 장치의 결과일 수도 있습니다. 원인 코드와 시점을 보고 사용자가 자신의 설계 목적에 맞게 판단할 수 있도록 합니다.

## 6. 이전 설계와의 대응

보고서의 서명은 ID·타입·격자·회전·출력·구동 그룹·각도·피스톤 행정을 포함하며 작전도 비교합니다. 배열 순서는 의미가 없으므로 ID로 정렬해 비교합니다. 시험과 현재 설계가 같을 때만 보고서의 관련 부품을 선택하거나 주황색 윤곽으로 표시합니다.

원본 설계를 수정하거나 다른 작전으로 바꾸면 ‘설계 변경됨’을 표시하고 위치 강조를 해제합니다. 이전 보고서는 읽을 수 있지만 새로운 기체에 과거의 손상 위치를 잘못 투영하지 않습니다. 실행 취소나 원본 불러오기로 동일한 설계를 복원하면 대응이 다시 유효해집니다.

현재 탭에서 최근 시험 한 회를 보관합니다. 보고서 JSON은 원본 설계와 사건을 포함해 내보낼 수 있습니다. 세션 재생, 타임라인 되감기, 물리 상태 복원 기능은 아닙니다. 보고서는 물리 세계를 변경하지 않습니다.
