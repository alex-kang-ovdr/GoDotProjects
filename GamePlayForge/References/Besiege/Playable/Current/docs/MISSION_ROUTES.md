# IRONWOOD 4.0 — 육해공 관문과 진행 시스템

기준 소스는 [physics.js](../dist/physics.js)의 `getMissionLayout()`·`segmentCrossesCheckpoint()`·`_advanceCheckpoints()`, [campaign.js](../dist/campaign.js), [main.js](../dist/main.js)입니다.

## 1. 목표 유형

| 유형 | 진행 수치 | 완수 조건 |
| --- | --- | --- |
| `destroy` | 파괴한 표적 / 전체 표적 | 모든 표적 파괴 |
| `route` | 순서대로 통과한 관문 / 전체 관문 | 마지막 관문까지 통과 |
| `sandbox` | 없음 | 완수 조건 없음 |

`targetCount=0`인 항로를 즉시 승리로 처리하지 않습니다. `objectiveProgress`가 `{kind,completed,total,label,next}`를 반환하여 HUD·결과·장면이 같은 목표 상태를 참조합니다. 파괴 수와 관문 수는 별도 데이터입니다.

## 2. 실제 관문 배치

### 해협 항로

수면 Y=0.45m, 해저 Y=-5m입니다. 모든 관문은 월드 Z에 수직인 평면에 있으며 반경 4m입니다. 강둑 사이에 실제로 열린 물길이 있습니다.

| 관문 | 중심 X | 중심 Y | 중심 Z |
| --- | ---: | ---: | ---: |
| 1 | 0 | 0.45 | -12 |
| 2 | 0 | 0.45 | -26 |
| 3 | 0 | 0.45 | -40 |

### 하늘 회랑

지면은 Y=0m이고 관문 반경은 4m입니다. 지상 차량으로 아래쪽을 통과하는 것을 막기 위해 최소 고도를 둡니다.

| 관문 | 중심 X | 중심 Y | 중심 Z | 코어 최소 Y |
| --- | ---: | ---: | ---: | ---: |
| 1 | 0 | 5 | -22 | 2.5 |
| 2 | 0 | 8 | -38 | 4.5 |
| 3 | 0 | 10 | -54 | 6.5 |

scene은 전체 원을 흐리게 그리고 최소 고도 이상인 유효 원호를 강조합니다. 최소 높이의 가로 점선과 숫자도 표시합니다. HUD에는 다음 관문까지의 거리와 최소 고도를 함께 표시합니다. 두 항로는 새 이동 방식을 익히는 직선 도입 코스입니다.

### 굴곡 주행

V4의 지상 조향 코스입니다. 평평한 지면에 반경 3m의 관문을 좌우로 번갈아 배치하며, 충돌을 강제하는 물리 장애물은 없습니다.

| 관문 | 중심 X | 중심 Y | 중심 Z |
| --- | ---: | ---: | ---: |
| 1 | -5 | 0.7 | -10 |
| 2 | 5 | 0.7 | -23 |
| 3 | -5 | 0.7 | -36 |
| 4 | 5 | 0.7 | -49 |

철갑 충각차를 추천합니다. 관문을 통과하면 B로 감속하고 A/D로 다음 관문을 향한 뒤 전진합니다. W만 유지하면 첫 관문부터 놓칩니다. 지상 프레임과 체크 표시는 동일한 판정 위치를 사용합니다.

## 3. 선분으로 통과 검사

현재 위치가 관문 내부인지 한 번만 검사하면 빠른 기체가 고리 전체를 한 스텝에 지나칠 수 있습니다. 이전 코어 위치 `p0`와 현재 위치 `p1`을 연결한 선분을 사용합니다.

```text
dz = p1.z - p0.z
t = (gate.z - p0.z) / dz
crossing = p0 + t * (p1 - p0)
```

다음 조건을 모두 만족하면 현재 관문 통과입니다.

1. 모든 입력 좌표와 반경이 유한하고 반경이 양수입니다.
2. Z 변화가 거의 0이 아닙니다.
3. `0 <= t <= 1`로 관문 평면과 선분이 만납니다.
4. 교차점의 `(x-gate.x)² + (y-gate.y)² <= radius²`입니다.
5. 최소 고도가 있다면 교차점 Y가 그 이상입니다.

이는 코어 중심선의 통과 판정입니다. 모든 부품이 고리 안으로 들어갔는지 검사하거나 고리 테두리에 물리 충돌을 부여하지는 않습니다. 큰 기체도 코어가 유효 구간을 지나면 통과합니다.

## 4. 순서·중복·고속 이동

다음에 통과해야 할 관문은 `checkpointIndex` 하나로 정합니다. 미래 관문을 먼저 지나도 기록하지 않습니다. 통과한 관문은 `passed=true`가 되고 index를 증가시키며 `checkpoint` 이벤트를 한 번 발생시킵니다.

한 스텝이 여러 관문을 관통하면 동일 선분의 교차 비율 `t`가 증가하는 순서만 인정합니다. 역방향으로 긴 선분을 이동했을 때, 현재 관문보다 먼저 지나친 미래 관문을 뒤늦게 함께 획득하지 않습니다. 개별 현재 관문을 되돌아가 통과하는 것은 허용합니다.

## 5. 시간·손상·완수 우선순위

한 스텝에서 물리·피해·연결·관문을 갱신한 뒤 종료 조건을 검사합니다. 순서는 코어 파괴, 경계 이탈, 시간 초과, 침수 실패, 목표 완수입니다. 마지막 관문을 통과한 틱에 코어를 잃거나 제한 시간이 끝나면 실패합니다.

승패가 확정되면 결과를 고정하고 추가 물리 스텝을 진행하지 않습니다. Route 결과는 기존 `{won,elapsed,shots,integrity,cost}`에 `checkpoints,total`을 추가합니다. UI는 성공 이벤트가 늦게 오거나 메뉴를 열어도 같은 완료를 중복 기록하지 않습니다.

## 6. 임무와 별

| 임무 | 예산 | 탄약 | 제한 시간 | 시간 별 기준 | 세 번째 별 |
| --- | ---: | ---: | ---: | ---: | --- |
| 해협 항로 | 65 | 0 | 150초 | 55초 | 연결된 생존 부품 75% 이상 |
| 하늘 회랑 | 70 | 0 | 150초 | 45초 | 연결된 생존 부품 75% 이상 |
| 굴곡 주행 | 55 | 0 | 150초 | 45초 | 연결된 생존 부품 75% 이상 |

완수하면 첫 번째 별을 받습니다. 항로의 세 번째 별에는 발사 수 조건이 없습니다. 공성 미션의 기존 발사 수 조건은 유지합니다. 캠페인 순서는 돌초소→성문→요새→항로→회랑→굴곡 주행이며 모든 작전은 바로 선택할 수 있습니다.

## 7. 편집·저장 UX

임무만 바꾸면 현재 설계를 유지합니다. 추천 설계 버튼은 현재 설계와 미션을 이전 작업으로 백업하고 새 설계를 적용합니다. 설계 메뉴에서 선박·비행기 프리셋을 누르면 해당 임무도 함께 엽니다. 실제 기체 교체는 명시적인 사용자 행동에만 연결합니다.

환경 권고는 출격 차단 조건이 아닙니다. 부품 수·형식·연결·예산 조건만 강제합니다. 예를 들어 사용자가 직접 만든 다른 형태의 부력 기체로 항로에 도전할 수 있습니다.

기존 설계 형식 1과 진행 기록 버전 1을 유지합니다. 정규화 시 모든 기존 미션 기록을 보존하고 새 미션의 빈 기록만 추가합니다. 최고 별·시간·발사 수는 독립 갱신하며 실패가 이전 최고 기록을 지우지 않습니다.

## 8. 검사 범위

선분 통과, 역순·중복 거부, 단일 틱의 여러 관문, 최소 고도, 지상 차량의 비행 관문 미인정, 일반 입력으로 선박·비행기·굴곡 주행 완주를 검사합니다. WebGL 화면 확인 여부는 별도 [VALIDATION.md](../VALIDATION.md)에 구분합니다.
