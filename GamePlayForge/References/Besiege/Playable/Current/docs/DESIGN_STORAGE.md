# IRONWOOD 4.0 — 이름 있는 설계 보관함

기준 구현: [designs.js](../dist/designs.js), [editor.js](../dist/editor.js), [main.js](../dist/main.js). 서버에 전송하는 저장 기능이 아니라 현재 브라우저의 로컬 저장입니다.

## 1. 사용 흐름

상단 **저장** 또는 Ctrl+S는 설계 보관함을 엽니다. 이름을 입력하고 **새 설계로 저장**을 누르면 빈 칸에 새 항목을 만듭니다. 기존 설계는 **불러오기**, **이름 저장**, **현재 설계로 덮어쓰기**, **삭제**로 관리합니다. 같은 이름을 입력했다고 기존 설계를 덮어쓰지는 않습니다.

최대 8개의 설계를 보관합니다. 꽉 차면 자동으로 오래된 설계를 지우지 않고 저장 실패 메시지를 제공합니다. 원하는 칸의 덮어쓰기 버튼을 누르거나 한 항목을 삭제해 공간을 확보해야 합니다. 미연결 초안도 저장할 수 있으며 실행 가능 여부는 출격 시 검증합니다.

불러오기는 형식을 먼저 검증한 뒤 적용합니다. 이전 작업은 `ironwood.previous.v1`에 보관합니다. 설계 창을 열었다가 닫기만 하면 같은 시험으로 돌아가고, 실제로 다른 설계를 불러오면 이전 시험을 종료합니다.

## 2. 저장 데이터

새 키는 `ironwood.designs.v1`입니다.

```json
{
  "version": 1,
  "legacyMigrated": true,
  "slots": [
    {
      "id": "slot-1",
      "name": "승강 시험대 01",
      "updatedAt": "2026-11-14T00:00:00.000Z",
      "blueprint": {
        "format": "ironwood-design",
        "version": 1,
        "mission": "sandbox",
        "parts": []
      }
    }
  ]
}
```

위 JSON은 필드 설명 예시이며 빈 `parts`는 실제로 불러올 수 있는 설계가 아닙니다. 유효한 설계에는 정확히 하나의 코어와 검증된 1~100개의 부품이 필요합니다.

이름은 공백 제거 후 1~40자이며 제어 문자를 거부합니다. 새 ID는 사용하지 않는 `slot-1`부터 `slot-8` 중 하나입니다. 불러온 저장의 유효한 ID도 정규화하되 중복을 제거합니다. 각 슬롯은 독립적으로 검증하여 한 슬롯이 손상되어도 다른 정상 슬롯을 보존합니다.

`blueprint`는 임의로 신뢰하지 않고 기존 `normalizeBlueprint()`를 거칩니다. 알 수 없는 작전은 돌초소로 정규화합니다. 부품 가격·질량·HP는 가져온 데이터가 아닌 카탈로그가 결정합니다. 입력값의 이름·ID는 UI에 `textContent`와 입력 value로 넣어 HTML로 실행하지 않습니다.

## 3. 이전 버전 호환

| 기존 키 | 역할 / V4 처리 |
| --- | --- |
| `ironwood.design.v1` | 이전 빠른 저장. 최초 빈 보관함에 한 번 복사하고 원본 키 유지 |
| `ironwood.draft.v1` | 현재 작업 자동 저장, 그대로 유지 |
| `ironwood.previous.v1` | 설계 교체 직전 작업, 그대로 유지 |
| `ironwood.campaign.v1` | 기존 별·기록 보존, 새 굴곡 주행 기록 추가 |
| `ironwood.prefs.v1` | 품질·소리·탄도·자세 보조 설정 유지 |

정규화 후 `legacyMigrated:true`를 기록하므로, 사용자가 이전 빠른 저장에서 이관된 슬롯을 삭제해도 다음 실행에서 되살아나지 않습니다. 구버전 빠른 저장은 별도 불러오기 경로를 유지하지만 V4의 상단 저장은 이름 있는 보관함을 사용합니다.

설계 JSON 형식은 계속 버전 1입니다. 피스톤의 선택적 `stroke`가 없으면 1.5m로 읽습니다. 명시한 null, 범위 밖 값은 정상 기본값으로 숨기지 않고 거부합니다. 다른 부품의 기존 설정도 보존합니다.

## 4. API와 불변성

| 함수 | 결과 |
| --- | --- |
| `normalizeDesigns(raw,{legacySaved})` | 버전·슬롯·이관 상태를 갖춘 새 정규 객체 |
| `saveDesignSlot(store,blueprint,{name,replaceId,now})` | 새 슬롯 또는 명시한 슬롯 교체 결과 |
| `renameDesignSlot(store,id,name,{now})` | 설계 본문을 유지한 이름 변경 |
| `deleteDesignSlot(store,id)` | 해당 항목만 제거 |
| `getDesignSlot(store,id)` | 편집해도 저장 원본이 바뀌지 않는 복사본 |

변경 함수는 `{ok,store,slotId,error}`를 반환합니다. `replaceId`를 전달하지 않은 저장은 항상 신규 저장입니다. 시간은 UI가 ISO 문자열로 전달하여 순수 모듈의 동작을 재현할 수 있습니다. 실제 localStorage 저장이 실패하면 UI가 메모리상의 보관함을 성공한 것처럼 교체하지 않습니다.

## 5. 범위와 복구

자동 서버 동기화, 계정 간 보관함 공유, 전체 캠페인 데이터 가져오기는 제공하지 않습니다. 다른 브라우저나 기기로 옮길 때 설계 JSON을 내보내고 가져옵니다. 로컬 HTML에서 저장 공간 접근이 제한되더라도 실행 가능한 설계 JSON 내보내기 경로를 제공합니다.

관련 검증: [designs.test.mjs](../tests/designs.test.mjs). 8칸 한도, 명시 덮어쓰기, 구버전 이관, 손상된 이웃 슬롯, 악성 문자열의 비실행 데이터 처리, 독립 복사와 실패 원자성을 검사합니다.
