# IRONWOOD 4.0 검증 기록

## 1. 판정 요약

실제 cannon-es 물리와 데이터·편집·입력 규칙의 **자동 테스트 88개가 통과했으며 실패·생략은 0개**입니다. 이 결과는 브라우저 GPU 렌더링과 마우스·터치 플레이를 모두 확인했다는 의미는 아닙니다. 물리·모델·패키지 검사와 브라우저 환경 제약을 아래에 구분합니다.

재현 명령:

```bash
node --test tests/*.test.mjs
```

Node.js v24의 통합 실행 결과는 `88 tests / 88 pass / 0 fail / 0 skipped`, 약 **5.538초**였습니다. 테스트 실행 시간은 환경에 따라 달라지며 실제 브라우저 프레임률을 뜻하지 않습니다.

| 영역 | 테스트 수 | 주요 검증 |
| --- | ---: | --- |
| 기존 V1 물리 | 8 | 안정적 정착, 실제 바퀴 주행·선회, 포탑, 발사 에지, 초소·성문 파괴, 연결 파단, 원본 보존 |
| V2 물리 | 13 | 탄약·다중 대포, 고각·탄도, 적 공격·회피, 분리 대포, 종료 우선순위·동결, 브레이크, 요새 완수 |
| V3 물리 | 10 | 부력·침수·파손, 추진 축·역추진·분리, 이륙·날개 손실, 조종 방향, 순차 관문, 선박·비행기 완주 |
| V4 물리 | 10 | 유한 힘 피스톤, 실제 하중·과적·유지·수축, 출력·행정, 분리·기울어진 축·혼합 스택, 굴곡 주행 완주와 직진 실패 |
| 부품·캠페인·편집 | 34 | 10종 카탈로그, 6개 연결 프리셋, 6작전, 구버전 호환, 그룹 원자성·ID·경계·코어 보호 |
| 이름 있는 설계 | 6 | 8칸 한도, 명시 덮어쓰기, 이관, 손상 데이터, 이름 검증과 복사 독립성 |
| 시험 보고서 | 3 | 원본 서명, 최초 파손·누계·이벤트 한도, 손상/하중 구분과 독립 스냅샷 |
| 입력 | 4 | 기존 지상/비행 입력 유지, 피스톤 Z/X·터치 부호·동시 입력 상쇄 |

기존 물리 테스트의 초기화 검사에는 새 임무의 탄약 0을 반영했습니다. 기존 지상 임무의 발사 준비 조건과 다른 동작 기대값은 유지했습니다.

## 2. V4 기계 장치와 조향 완주

기본 승강 시험대에서 Z/X에 대응하는 `actuate` 입력만 주어 상부 6.8kg을 올리고 유지·수축했습니다. 강체 위치·회전·속도를 직접 바꾸어 움직이지 않습니다.

| 검증 | 관측 결과 |
| --- | --- |
| 목표 1.5m의 실제 상승 | 1.499763m |
| 중립 1초의 높이 변화 | 0.000001m 미만 |
| 유지 축력 / 최대 축력 | 66.804N / 120N |
| 수축 후 실제 상대 이동 | −0.000110m, 솔버 오차 |
| 과적 26.8kg, 목표 1.5m | 실제 −0.001243m에서 정지, 구동력 120N·사용률100% |
| 기본 장치 파손 / 코어 HP | 0 / 100 |
| 출력0.3의 36N 구동 | 기본 하중을 올리지 못함 |
| 혼합 piston→hinge→piston | 파손 없이 총 약 3m 상승 |

과적·기울어진 축·전원 단절 검사는 해당 조건을 구성한 단위 시나리오입니다. 일반 프리셋 승강 검증과 목적을 구분합니다. 기계적 가이드가 살아 있을 때 동력이 끊기면 중력으로 자연 수축하고, 가이드 자체를 파단하면 측면 구속도 제거됩니다.

**굴곡 주행**은 기본 철갑 충각차로 실제 위치·방향을 읽으며 W/A/D/B에 대응하는 디지털 명령만 보냈습니다. 관문 뒤 약0.5초 제동하고 다음 관문 쪽으로 회전한 뒤 전진합니다.

| 시나리오 | 결과 |
| --- | --- |
| 순차 조향 | 17.350초, 관문4/4, 승리 |
| 코어 HP / 연결 유지 / 파단 | 100 / 100% / 0 |
| W만 계속 유지하는 대조 | 관문0개, 9.825초에 경계 이탈 실패 |

이는 자동 입력 시나리오의 결과이며 사람의 완주 시간이나 난이도 측정값은 아닙니다. 코스는 평평한 지면 위 좌우 굴곡 경로이며 지형 요철·충돌 장애물은 없습니다.

## 3. 선박·비행기 완주

재현 명령:

```bash
node --test --test-name-pattern 'boat and plane complete' tests/physics_v3.test.mjs
```

완주 테스트는 기본 프리셋으로 시작하여 일반 조작 입력을 사용합니다. 강체 위치·회전·속도·HP·관문 상태를 직접 수정하지 않습니다. 물리 엔진의 적분·제약·접촉·부력·양력이 실제 이동을 만듭니다.

| 지표 | 해협 항로 / Boat | 하늘 회랑 / Plane |
| --- | ---: | ---: |
| 결과 | 승리 | 승리 |
| 관문 | 3 / 3 | 3 / 3 |
| 게임 내 경과 시간 | 9.433초 | 6.183초 |
| 완주까지 최고 표시 고도 | 수면 위 1.270m | 지면 위 8.312m |
| 코어 HP | 100 / 100 | 100 / 100 |
| 연결된 생존 부품 | 100% | 100% |
| 파단된 연결 | 0 | 0 |
| 사용 탄약 | 0 | 0 |

Boat는 W를 유지합니다. 최고 표시 고도 1.270m는 시작 배치 높이이며, 이후 코어는 수면 위 약 0.97m에서 평형을 이룹니다.

Plane는 W를 유지하면서 2.20~2.35초에 `pitch:+1`, 2.50~2.60초에 `roll:+1`을 입력합니다. 관문 통과 시각은 약 3.167초, 4.692초, 6.183초입니다. 자세 보조를 켜고 W만 유지한 별도 모델 연동 확인에서는 6.142초에 완주했습니다. 이 결과들은 자동화된 입력 시나리오이며 사람의 숙련도나 난이도 측정은 아닙니다. 새 항로는 조립·이동 방식을 익히는 직선 도입 코스입니다.

## 4. 실패·파손·통과 판정

- 같은 선박에서 부유체를 제거하면 3.2초에 침수 실패합니다. 온전한 선박은 정지 상태로 5초 동안 손상·파단 없이 떠 있습니다.
- 연결이 끊긴 살아 있는 부유체는 계속 뜨고, HP 0인 부유체는 부력을 잃습니다.
- 프로펠러 장착 방향에 따른 추력 방향, 역추진, B 입력의 추력 차단, 코어 분리 직후 출력 0을 확인했습니다. 기존 운동량은 보존합니다.
- 비행기가 이륙해 모든 바퀴가 지면을 떠난 것을 확인했습니다. 날개 파괴 후 실제 수직 속도가 하강으로 전환됩니다.
- 자세 보조 ON/OFF에서 기수·뱅크 입력 부호를 실제 기체의 자세로 확인했습니다.
- 선분 통과, 관문 반경과 최소 고도, 역순·중복 방지, 고속 이동 시 여러 관문 처리 순서를 검사했습니다.
- 지상 로버로 비행 관문 아래를 지나가도 관문으로 인정하지 않습니다.
- 기존의 단일 종료·실패 우선순위·결과 동결 규칙을 유지했습니다.

특정 파손 조건을 만드는 단위 테스트에는 초기 상태 설정이나 의도적인 부품 파괴가 포함됩니다. 위의 일반 입력 완주 검증과는 목적을 구분합니다.

## 5. 기존 공성 회귀

V1/V2의 21개 물리 테스트를 모두 유지했습니다. 요새 임무는 기존과 동일하게 일반 이동·제동·포탑·고각·발사 입력으로 **목표 15개, 10발, 22.533초, 코어 HP 100, 파단 0**으로 완수했습니다.

적 포탄에 의한 코어 파괴, 공격 예고 후 이동 회피, 포탑 지지부 파괴 후 반격 중단, 살아 있지만 분리된 대포의 발사 차단도 계속 통과합니다.

## 6. Three 객체와 물리 모델의 연동

실제 Three 객체와 `Simulation`을 연결한 CPU 보조 확인을 수행했습니다. 아래 확인은 자동 테스트 88개 집계와 별개이며 GPU 렌더링 검증은 아닙니다.

V4의 실제 Three 객체와 Simulation을 연결한 CPU 보조 확인에서는 다음을 확인했습니다.

- 피스톤의 실제 1.5m 확장·유지·수축, 지지체와 헤드 회전 프레임에서 로드 끝점 일치.
- 가이드 파손 후 로드와 해당 하우징 피킹을 정리.
- 다중 선택·보고서 강조의 독립 수명주기, 실행 중 추가 선택 전달.
- 순간 하중비와 누적 연결 손상 색상 분리.
- 굴곡 주행 지면 관문, 세 화면비의 카메라 투영 범위, 환경 전환 자원 정리.

아래 V3 모델 회귀 규칙도 유지합니다.

- 기존 새 3종 모델이 한 격자 범위에 들어갑니다.
- 날개 기본 6도와 명시 0도를 구분하고 시각 회전이 물리 shape quaternion과 일치합니다.
- 수면·해저·강둑·관문이 공유 레이아웃 좌표와 일치합니다.
- 실제 완주 중 프로펠러·관문 상태·항적·고도·카메라가 물리 상태에 따라 갱신됩니다.
- 물리 시간이 멈추면 프로펠러 회전도 멈춥니다.
- 최소 비행 고도를 밝은 원호·가로 점선·수치로 구분합니다.
- 조립·기존 공성 임무로 돌아가면 관문과 환경을 정리하고 기존 조준·적·HP 표시를 복원합니다.
- 390×684, 700×320, 1440×780의 카메라 투영 계산에서 기체와 다음 관문이 화면 범위 안에 들어옵니다. 실제 UI 패널과 겹치지 않는다는 화면 판정까지 포함하지 않습니다.
- harbor→skyway→outpost 반복 전환에서 임시 자원 수가 계속 증가하지 않고 Sprite texture를 정리합니다.

### CPU UI 상태 통합 검사

별도의 브라우저를 실행하지 않고 실제 main·physics·report·data·Three 장면 메서드를 연결했습니다. HTML 트리·EventTarget·모달 close·RAF/타이머는 제한된 검증용 대체 객체이고 WebGL 렌더러는 사용하지 않습니다. 이 검사는 88개 단위/물리 테스트 집계와 별개입니다.

```bash
npm ci
npm run verify:cpu
```

- 10종 팔레트 초기화, 다중 선택·충돌 거부·그룹 이동/복사·실행 취소/재실행·코어 보호.
- 이름 있는 슬롯 저장·안전한 문자열 표시·이름 변경·삭제·불러오기 후 작전까지 Undo/Redo.
- 실제 Z 키 이벤트로 피스톤 상승, 클릭 점검의 일시정지, 입력 없는 1/60초 진행, 재개.
- 도움말 메뉴의 자동 정지/재개와 하중·손상 표시 전환.
- 손상 사건의 보고서 반영, 부품 선택, 조립 복귀, 설계 수정 후 과거 강조 해제, 새 시험의 HP·기록 초기화.
- 이전 실행의 지연된 종료 창이 새 시험을 중단하지 않음, 종료 후 한 스텝 차단, 결과→보고서→조립 정리.

보고서와 결과 전환 검사는 의도적인 손상 fixture를 사용합니다. 이를 자연 충돌 플레이 완주로 해석하지 않습니다. 이 검사는 CSS 배치, 브라우저 실제 클릭·터치, WebGL 초기화·렌더링을 검증하지 않습니다. 재현 스크립트는 `scripts/check_scene_cpu.mjs`와 `scripts/check_ui_cpu.mjs`에 포함합니다.

## 7. 실행 파일과 소스 검사

구문 검사, HTML ID 참조·중복 검사, 단일 HTML 생성, 외부 스크립트·스타일시트 의존성 검사, ZIP CRC·원본 바이트 일치를 패키징 게이트로 확인합니다. 소스 ZIP에는 Git 상태·호스팅 설정·인증 파일·node_modules를 넣지 않습니다.

단일 HTML에는 게임 코드·CSS·Three.js·cannon-es와 라이선스를 포함합니다. 로컬 실행 중 외부 CDN이나 HTTP 서버를 필요로 하지 않지만, 브라우저의 WebGL 지원은 필요합니다.

## 8. 브라우저 QA의 현재 한계

V4에서 관리형 미리보기 시작은 이미 다른 미리보기가 실행 중이라는 잠금 오류를 반환했습니다. 공식 status가 제공한 주소를 브라우저에서 열어 보니 IRONWOOD가 아닌 다른 프로젝트였습니다. 다른 작업을 중단하거나 별도 서버·브라우저 경로로 우회하지 않았습니다. 따라서 이번 V4의 실제 3D 화면·클릭 플레이·터치 조작 최종 검증은 수행하지 못했습니다.

참고로 이전 V3 검증에서는 올바른 IRONWOOD 미리보기까지 도달했으나 브라우저의 GL vendor/renderer가 Disabled여서 WebGL context를 생성할 수 없었습니다. 이것은 과거 관측이며 V4 화면을 확인했다는 근거로 사용하지 않습니다.

기존 비공개 배포 주소는 이번에도 정상 로그인 게이트를 표시했습니다. 화면 QA를 위해 공개 범위를 바꾸거나 인증을 우회하지 않았습니다. 배포 성공은 별도 Sites 배포 결과로 확인합니다.

현재 판정은 **실제 물리·데이터·입력 규칙·3D 객체 모델·패키지 검사 통과**, **GPU 화면·실기기 조작·프레임률 미검증**입니다. 문서와 채팅에서도 이 구분을 유지합니다.
