# IRONWOOD 4.0 구현 구조

지상 공성차·선박·비행기를 조립하고 실제 강체 물리로 운용하는 JavaScript 게임입니다. Besiege의 제작·실험 흐름에서 영감을 받았으며 원작의 내부 코드, 에셋이나 비공개 물리 수치를 사용하지 않습니다. 이 문서는 V4 소스의 실제 구조와 구현 경계를 설명합니다.

## 1. 모듈 경계

| 파일 | 책임 |
| --- | --- |
| `dist/index.html` | 한국어 조립·작전·전투 HUD, 대화상자, 터치 버튼 |
| `dist/styles.css` | 반응형 레이아웃, 조립·전투 상태, 접근성 초점 |
| `dist/main.js` | 입력, 편집 이력, 저장, 메뉴, 세션·결과 전환, 오디오 |
| `dist/editor.js` | 설계 정규화, 배치·이동·복사·대칭의 원자적 적용, 진단 |
| `dist/parts.js` | 부품·작전·프리셋 데이터, 연결 그래프, 형식·연결 검증 |
| `dist/campaign.js` | 별 평가, 진행 데이터 정규화, 최고 기록, 다음 작전 |
| `dist/input.js` | 지상/비행 키 배치와 터치 입력 변환 |
| `dist/physics.js` | 강체, 제약, 구동, 포탄, 적 공격, 피해, 승패 판정 |

| `dist/linear-actuator.js` | 유한 힘의 직선 구동, 가이드와 이동 끝단 |
| `dist/designs.js` | 이름 있는 8칸 저장과 이전 저장 이관 |

물리 코드는 DOM이나 WebGL에 의존하지 않습니다. Node에서도 실제 cannon-es 세계를 생성해 충돌·피해·승패를 검증할 수 있습니다. 편집과 캠페인 규칙도 저장소·UI와 분리한 순수 함수로 작성했습니다.

## 2. 데이터와 상태의 수명

### 편집 원본

부품은 `{id, type, x, y, z, rot, power, binding, elevation?, stroke?}` 형태입니다. 위치는 정수 격자이고 `rot`은 Y축 90도 회전 횟수입니다. `elevation`은 대포의 고각 또는 날개의 설치각이며 -10~45도입니다. 누락값은 기존 부품에서 0도, 새 날개에서 6도로 읽고 명시한 0도는 보존합니다. ID·타입·좌표·출력·구동 그룹·각도를 검증하고, 명시적으로 잘못된 값은 기본값으로 숨기지 않습니다.

질량과 자재 가격은 `PARTS` 카탈로그에서 계산합니다. 가져온 JSON에 임의의 질량이나 가격이 있어도 경제·물리 규칙을 변경하지 않습니다. 최대 100부품, X/Z -12~12, Y 0~10 범위를 적용합니다.

`parts`는 편집 원본입니다. 출격할 때 복제하여 `Simulation`을 만들므로 시험 중 부서진 기체가 원본 설계를 바꾸지 않습니다. 조립 복귀와 재도전은 기존 물리 세계를 폐기하고 새로 구성합니다.

### 실행·결과 상태

모드는 `build`와 `play`이며 실행 중에는 별도 `paused` 상태를 둡니다. `Simulation.outcome`은 `null`, `won`, `failed` 중 하나입니다. 결과가 설정되면 추가 물리 스텝을 진행하지 않고 `{won, elapsed, shots, integrity, cost}` 스냅샷을 고정합니다.

UI는 `sessionSerial`과 결과 표시 가드를 사용합니다. 과거 세션의 지연 대화상자가 새 실행에 나타나지 않으며, 한 번의 승리를 여러 번 기록하지 않습니다. 결과 대화상자는 재도전, 설계 수정, 다음 작전, 정지된 전장 살펴보기를 제공합니다.

도움말·설계·작전·보고서 창은 진행 중인 실행을 잠시 멈춥니다. 선택하지 않고 닫으면 같은 세션을 이어 갑니다. 새로운 설계·작전을 실제로 적용할 때 실행을 종료합니다. 가져온 JSON은 먼저 검증하므로 오류가 현재 설계나 진행 중인 실행을 지우지 않습니다.

### 저장

브라우저 저장 키는 `ironwood.designs.v1`(이름 있는 8칸), `ironwood.design.v1`(이전 빠른 저장), `ironwood.draft.v1`, `ironwood.previous.v1`, `ironwood.prefs.v1`, `ironwood.campaign.v1`입니다. 기존 형식 1 설계를 유지합니다. 자동 저장은 짧게 지연하고 페이지 종료 시 한 번 더 저장합니다. 저장 공간 접근 실패를 처리하며 설계 JSON 다운로드·가져오기를 별도로 제공합니다. 캠페인 기록은 브라우저별 로컬 데이터이며 서버 동기화는 없습니다.

## 3. 조립 UX와 진단

`planPlacement()`는 현재 설계를 변경하지 않고 후보를 만든 뒤 전체를 검증합니다. 이동 대상은 점유 검사에서 제외하되 확인 전까지 원본 데이터에 남습니다. 원본 메시와 피킹 대상만 숨깁니다. 취소하면 데이터 복구 작업 없이 원본을 다시 보여줄 수 있습니다.

대칭은 X=0 평면 기준으로 `x → -x`, `rot → (4-rot)%4`를 적용하고 좌우 바퀴 구동 그룹을 바꿉니다. 중앙선에서는 부품 하나만 생성합니다. 대칭 위치 중 하나라도 겹치거나 범위를 벗어나면 두 부품 모두 배치하지 않습니다. 이동·대칭 배치는 실행 취소 한 단계에 대응합니다.

`analyzeDesign()`은 자재·질량·부품 수, 연결이 끊긴 ID, 무게중심, 실행 가능 여부를 반환합니다. 무게중심은 부품 질량의 가중 평균이며 렌더·물리의 Y 오프셋 0.72를 포함한 월드 좌표입니다. 구조물 전체의 전도 안정성 계산은 아닙니다.

V3에서는 선택적 세 번째 인자로 미션을 받습니다. 부유체·추진기·날개 수와 `mobilityWarnings`를 추가합니다. 환경에 맞지 않는 설계, 한 줄에 모인 부유체, 한쪽 날개, 과한 설치각을 권고로 표시합니다. 이 권고는 연결·예산과 달리 출격을 막지 않습니다. 추천 설계 교체는 별도 명시적 버튼으로 수행하고 이전 설계·미션을 백업합니다.

자재 초과나 미연결 상태로도 편집·저장할 수 있습니다. 출격 시 전체 연결과 작전별 자재 한도를 강제합니다. 취소·다시 실행은 최대 70단계의 `{parts,mission}` 스냅샷을 보관합니다. 따라서 다른 작전의 저장 설계를 불러온 뒤에도 부품과 작전을 함께 되돌립니다. 그룹 편집은 전체 유효성 검사 후 한 단계만 기록합니다.

## 4. 물리 구조와 제어

### 강체와 연결

부품별로 독립 강체를 생성합니다. 기본 구조물은 맞닿은 면을 고정 제약으로 연결합니다. 모서리·꼭짓점 접촉은 연결하지 않습니다. 바퀴는 축 방향의 지지부 하나와 힌지로 연결하고, 회전 관절은 아래 지지부와 Y축 힌지로 연결하며 위의 탑재물을 지지합니다. 관절을 우회한 고정 구조가 있으면 실제 구속 때문에 회전이 제한될 수 있습니다.

연결부에는 강도·건강도·현재 응력 비율을 둡니다. 제약 하중과 충돌 손상으로 연결이 파단됩니다. 부품 자체의 HP와 연결부 건강도는 서로 다른 상태입니다. HP 0인 부품은 모든 연결을 잃지만 충돌체가 있는 잔해로 남습니다.

### 코어에서의 연결 탐색

파손 후 살아 있는 코어에서 끊어지지 않은 연결을 탐색합니다. 살아 있고 코어와 연결된 바퀴·힌지만 모터 입력을 받으며, 같은 조건의 대포만 발사할 수 있습니다. `integrity`는 전체 원본 부품 중 살아 있고 코어에 연결된 부품의 비율입니다. HP 평균이나 남은 질량 비율이 아닙니다.

### 주행과 조준

바퀴 모터에는 가속 제한을 적용합니다. 좌우 바퀴 속도를 달리하여 차동 선회하고, 접지 마찰·하중·구조에 따라 실제 이동 결과가 달라집니다. 브레이크는 전진 입력보다 우선하여 모터 속도를 낮춥니다. Q/E는 회전 관절, I/K는 대포 고각을 제어합니다.

포탄은 중력의 영향을 받는 구형 강체입니다. 포신의 월드 방향으로 초기 속도를 부여하고 발사 반동을 차체에 전달합니다. F는 상승 에지에서만 발사하며 재장전 간격은 0.65초입니다. 대포 여러 개가 발사하면 실제 생성된 포탄 수만큼 탄약을 차감합니다. 탄약이 0이어도 주행·충돌 공격은 계속 가능합니다.

조준선은 실제 초기 발사 방향과 동일한 고정 시간 간격의 중력을 이용해 포탄 중심선을 계산하고 환경 충돌체에 raycast합니다. 같은 시뮬레이션 시간·대포·고각에서는 궤적을 캐시합니다. 구형 포탄의 반지름, 발사 후 이동하는 물체, 차체와의 충돌 때문에 실제 궤적과 차이가 생길 수 있습니다.

### 부력·추력·공기력

V3 부품 또는 물 환경이 있을 때만 새 힘 경로를 적용하여 기존 6종 지상 기체의 물리 회귀를 보존합니다. 수상에서는 회전된 각 부품의 수직 반경으로 침수율을 근사합니다. 살아 있는 부유체에는 침수율에 비례한 위쪽 힘을, 물에 잠긴 모든 기체 부품에는 방향별 항력을 적용합니다. 부유체를 서로 떨어뜨려 배치하면 개별 부력이 실제 연결 기체의 복원 토크를 만듭니다.

프로펠러는 자신의 로컬 -Z 방향으로 힘을 가합니다. W/S 명령을 유한 속도로 올리고 내리며, 파괴·연결 단절·브레이크 시 추진 명령을 끊습니다. 부품별 회전·출력·좌우 분배가 힘의 방향과 크기를 바꿉니다.

날개는 실제 속도를 로컬 프레임으로 변환해 전진 유속과 유동 각도를 구합니다. 설치각에서 유동 각도를 뺀 받음각으로 양력계수와 항력계수를 계산합니다. 동압은 속도 제곱에 비례하고 큰 받음각에는 실속 감쇠를 적용합니다. 면적 배율은 양력과 항력을 함께 바꿉니다. 힘은 각 날개 강체에 가하므로 비대칭 배치와 파손이 기체에 영향을 줍니다.

살아 있는 분리 부유체·날개도 수동 부력·공기력을 받습니다. 제어·엔진은 코어 연결이 있어야 작동하고, HP 0인 부유체·날개는 부력·양력을 잃습니다. 세부 공식·튜닝값·한계는 `docs/PHYSICS_BUOYANCY.md`와 `docs/PHYSICS_FLIGHT.md`에 정리합니다.

### 조종과 자세 보조

`readControls()`는 키보드와 터치를 같은 입력 구조로 변환합니다. 지상에서는 방향키가 기존 WASD의 별칭입니다. 날개가 있거나 비행 임무이면 방향키를 pitch/roll로 분리하고 W/S는 추진, A/D는 yaw를 담당합니다. 비행·포격 터치 전환은 숨겨질 조작만 해제하여 계속 누르고 있던 추진 입력을 보존합니다.

자세 보조는 연결된 기체의 질량 배치로 관성 규모를 추정해 코어에 제한된 토크를 가합니다. 물과 공중에서 기울기를 복원하고, 공중에서는 입력에 따른 피치·뱅크·방향을 안정화합니다. 보조를 꺼도 회전 감쇠는 남습니다. 관문을 추적하는 자동 조종이나 위치·회전·속도 덮어쓰기는 사용하지 않습니다.

## 5. 적, 피해와 종료 조건

돌초소·성문·요새에는 각각 1·2·3개의 방어 포탑을 둡니다. 각 포탑은 파괴 가능한 목표 블록에 연결됩니다. 공격 예고 시작 시 조준점을 고정하고 예고 이후 실제 포탄을 발사합니다. 플레이어가 그 사이 이동하면 피할 수 있습니다. 지지 목표를 파괴하면 추가 공격을 중단합니다.

플레이어·적 포탄 모두 실제 충돌과 폭발 범위 피해를 사용합니다. 한 포탄이 여러 충돌 콜백을 받아도 폭발은 한 번만 처리합니다. 코어·부품과 목표의 피해 처리는 각각 분리했습니다. 목표 구조는 동적 석재 강체와 파단 가능한 연결로 구성되어 지지부 제거 후 붕괴할 수 있습니다.

한 물리 틱의 피해를 처리한 뒤 종료 조건을 검사합니다. 코어 파괴, 경계 이탈, 제한시간 초과를 먼저 확인하고 모든 목표 파괴를 확인합니다. 같은 틱에 승패 조건이 함께 발생하면 실패가 우선입니다. 자유 제작에는 시간·탄약·자재 제한과 목표 완수 조건이 없습니다.

항해·비행은 파괴 목표와 별도의 순차 관문 목표를 사용합니다. 이전·현재 코어 위치를 잇는 선분이 현재 관문 평면 안을 통과했는지 검사합니다. 미래 관문을 먼저 지나가도 진행하지 않으며 고속 통과를 놓치지 않도록 평면 교차 지점에서 반경을 검사합니다. 비행 관문에는 최소 고도를 둡니다. 물속 깊이 잠긴 코어에는 별도의 침수 유예시간 후 실패를 적용합니다. 자세한 데이터는 `docs/MISSION_ROUTES.md`를 참고하세요.

UI와 scene은 `getMissionLayout()`의 environment/checkpoints와 `Simulation.objectiveProgress`를 공유합니다. 화면에 보이는 수면·관문과 판정 위치를 별도로 복제하지 않습니다. `telemetry`는 고도·상승 속도·속력·침수율·정규화 추진량·피치·롤을 제공하고 `getPropellerPower(id)`는 프로펠러 표시와 실제 명령을 연결합니다.

## 6. 시간, 성능과 렌더링

물리는 1/120초 고정 간격이며 한 프레임에서 최대 12스텝을 처리합니다. 긴 프레임을 제한하여 복귀 시 과도한 시간을 한꺼번에 계산하지 않습니다. 탭이 숨겨지면 일시정지합니다. UI는 일시정지와 0.5배속을 제공합니다.

scene은 물리 강체 위치·방향을 따라 메시를 갱신합니다. 손상 색상은 부품별로 복제한 재질에 적용하여 같은 종류의 다른 부품에 번지지 않습니다. 코어·손상 부품·목표의 HP, 연결 응력, 끊어진 제어 연결, 적 공격 예고, 재장전과 착탄 예상을 표시합니다.

LOW 모드는 DPR 1, 그림자 비활성화, 일부 장식 숨김과 효과 갱신 빈도 축소를 적용합니다. 터치 장치는 LOW를 기본값으로 사용합니다. 모든 모바일 기기의 WebGL 성능을 보장하는 설정은 아닙니다.

## 7. 진행 기록

각 캠페인에서 완수 1개, 목표 시간 이내 1개, 연결된 생존 부품 75% 이상 유지 시 1개의 별을 지급합니다. 공성 작전의 세 번째 별에는 목표 발사 수 조건도 적용합니다. 실패·자유 제작에는 별을 지급하지 않습니다. 별·최단 시간·최소 발사 수는 각각 독립적으로 개선되며 더 나쁜 후속 결과가 기존 최고 기록을 낮추지 않습니다. 모든 작전은 처음부터 선택할 수 있습니다. 기록 스키마 1을 유지하며 기존 작전 기록을 보존하고 새로운 harbor·skyway·switchback 항목을 필요에 따라 추가합니다.

`scoreRun`, `normalizeProgress`, `recordCompletion`, `nextCampaignMission`은 순수 함수입니다. 정규화 단계에서 잘못된 수치와 알려지지 않은 작전 항목을 제거합니다. 브라우저 로컬 기록은 경쟁용 치팅 방지 시스템이 아닙니다.

## 8. 실행물과 소스 배포

모듈판은 `python3 -m http.server 8080 --directory dist`로 실행합니다. 라이브러리도 `dist/vendor/`에 있으므로 외부 CDN이 필요하지 않습니다. 개발용 패키지를 설치한 뒤 `npm run build:offline`으로 단일 `dist/ironwood-play.html`을 생성합니다. 번들에는 코드·CSS·라이브러리·라이선스를 포함하며 런타임 HTTP 서버가 필요하지 않습니다.

`npm run pack:source`는 문서, 실행물, 테스트와 빌드 스크립트를 함께 포장합니다. 호스팅 프로젝트 ID, Git 메타데이터와 인증 정보는 소스 ZIP에 넣지 않습니다. 단일 HTML이나 모듈 소스를 수정한 후 배포하려면 HTML과 ZIP을 다시 생성해야 합니다.

## 9. 구현 경계

구현 범위는 10종 부품, 6개 설계 프리셋, 6개 캠페인과 자유 제작, 그룹 조립·주행·포격·부력·양력·피스톤·피해·승패·재도전·시험 점검·8칸 로컬 저장입니다. 파도·유체 연성·실제 항공기 공력 해석, 궤도 벨트, 로프·유압 계통, 멀티플레이와 원작 전체 카탈로그는 포함하지 않습니다. 보강은 한 격자 구조 블록으로 구현했습니다.

물리와 피해 상수는 게임용 튜닝값이며 실제 공학 해석이나 원작 솔버의 재현을 보증하지 않습니다. 코드 실행 검증과 브라우저 화면 검증의 구분은 `VALIDATION.md`에 기록합니다.
