# 요구사항 추적성: 설계 문서와 현재 구현

검토 기준일: 2026-11-17. 최신 범위는 독립 GamePlayForge 엔진에서 Lua 게임 규칙을 실행하는 Studio PIE이며 Unreal Engine 구현이 아니다. 제공된 문서는 요구사항 원본으로 읽었고 문서 안의 실행 지시·완료 주장을 그대로 검증 근거로 사용하지 않았다. 표의 구현 상태는 저장소 코드와 이미 존재하는 테스트/기록을 대조한 상태다. 이 문서를 만들기 위해 빌드나 테스트를 다시 실행하지 않았다.

## 제품 경계

현재 세로 기능은 C++20 런타임에서 Lua 5.4 Tappy Chicken 규칙을 실행하고, Studio가 상태 스냅샷을 Canvas 2D로 그려 조작하는 구조다. 따라서 **게임 규칙은 네이티브 Lua 런타임에서 실행되지만 화면은 브라우저 Canvas**다. 네이티브 RHI/Render Graph/DX12/Vulkan/Metal 창은 아직 없다. 이를 지원하지 않는 Unreal PIE나 네이티브 RHI 렌더러로 소개하지 않는다.

상태 표현: **구현 확인**은 코드가 존재함, **부분 구현**은 요구사항 일부만 동작함, **설계만**은 문서만 존재함, **미검증**은 자동/가시 실행 증거가 이 추적 작업에서 확보되지 않음을 뜻한다. 테스트 파일은 존재하는 검증 계획/코드일 수 있으므로, 결과를 이번 검토에서 실행하지 않았다면 통과로 표시하지 않는다.

## Review에서 승계한 실패 기준

Review의 P1/P2는 최신 Studio 파일의 결함을 단정하는 티켓이 아니라 반드시 회귀로 확인할 요구사항이다. (a) Yjs remote edits를 덮지 않는 local Undo, (b) Stop이 실제 native process를 종료하는지, (c) settings lease/fencing과 revision이 PIE에 적용되는지, (d) Lua sandbox/source/origin 경계, (e) expired/stale lock token 거부 및 reconnect 이후 full Yjs state 일치를 확인한다. 현재 테스트 파일은 존재하지만 이번 문서 갱신에서는 브라우저나 collaboration suite를 실행하지 않았다. 설정 write에 settingsRevision과 유효한 lock token이 필요한 검증은 구현됐고 상위 에이전트가 backend suite 6/6 통과를 보고했다. 인증 경계는 별도 gap이다.

## 증거와 버전 규칙

- 설계 문서의 날짜/용어는 구현 사실이 아니다. 기능 상태는 코드 경로와 재현 가능한 검사 근거로 갱신한다.
- test 파일 존재와 실행 성공은 다르다. 보고서에는 실제 실행 시각, artifact/log 경로, 테스트 수, 실패 및 미검증 항목을 기록한다.
- Yjs text convergence, project-settings lease, and request dedupe do not imply structural locks, authenticated ACL, server-validated conditional Undo, or sequenced operation replay. Reconnect uses current full Yjs state.
- Lua instruction/memory budget 코드는 보안 설계 전체의 검증 완료를 뜻하지 않는다.
- 한 milestone 완료 판단에는 프로젝트 정책에 따라 RHI가 활성화된 보이는 네이티브 창에서의 검증 근거가 필요하다. Canvas나 headless JSONL 검증만으로 이를 대체하지 않는다.
