# 자체 검토 — 설원 하이라이트와 동굴 밝기

## 변경과 호환성

`WorldLighting`의 `soft-day-v1` 프로필을 실제 게임 환경 생성에 연결했다. 햇빛 에너지는 0.72→0.22, 환경광은 0.38→0.48이다. 기존 하늘/환경광 색상·태양 방향·그림자·Linear 톤매퍼를 유지하고 새 광원이나 후처리 효과를 추가하지 않았다. 전역 노출을 낮춰 동굴까지 어둡게 만드는 대신 직접광과 환경광을 따로 조절했다.

블록 색/텍스처·생성 셀·청크·충돌·저장 형식은 바꾸지 않았다. 생성 버전 5와 기존 v5 체크포인트 호환성을 유지한다. 41/1337 해시 805642358, 185/1337 해시 1937405161이며 비교 전후 layout와 청크 기본 셀 해시/빈 편집 저널도 확인한다. 버전 4 이하 저장 거부 정책은 이전 루프 그대로다.

## 선택 근거와 실험 경계

[Godot 4.7 Environment API](https://docs.godotengine.org/en/4.7/classes/class_environment.html)의 환경광·톤매핑 속성을 확인했다. 문서는 Linear 곡선에서 밝은 값이 잘릴 수 있음을 설명한다. 그러나 다른 톤매퍼를 선택했다는 이유만으로 개선을 가정하지 않고 현재 Compatibility 렌더에서 직접 비교했다.

`tools/lighting_audit.gd`가 같은 월드·정확히 같은 카메라의 지상/동굴 화면을 보존한다. 최초 비교는 `Saved/Verification/lighting-audit`, 추가 조정은 `lighting-tuning`이다. 0.42/0.48 Linear는 기본 지상 근백색 비율이 약 6.02%로 여전히 높았다. 0.30/0.48은 0.56%, 0.22/0.48은 0.10%였다. 0.22 설정을 3개 시드와 동굴의 밝기 조건까지 확인한 뒤 선택했다.

시도한 Filmic/기본 white 설정은 이 장면에서 근백색 영역이 18.57–20.41%로 증가해 채택하지 않았다. 이는 실험한 설정에 대한 결과이지 Filmic 자체나 Compatibility 지원 여부에 대한 일반적인 결론이 아니다. 다른 white/exposure 조합의 최적값을 모두 탐색했다고 주장하지 않는다.

## 측정 정의

실제 1280×720 viewport PNG의 x=20..1259, y=110..569를 측정하고 중앙 조준점 주변은 제외한다. 570,279픽셀로 HUD 대부분을 제외한 장면 영역이다. `near_white_fraction`은 세 표시 RGB 채널 모두 0.98 이상인 픽셀 비율이다. HDR 원본의 실제 클리핑을 직접 측정한 것이 아니며, 눈/모래/윤곽선도 포함할 수 있는 포화에 가까운 표시색의 대리 지표다.

`mean_display_luma`는 표시 RGB의 가중 평균이며 물리 휘도나 선형 광량이 아니다. 암부 비율은 이 값이 0.1보다 낮은 픽셀 비율이다. 밝기 수치 하나만으로 시각 품질 전체를 판정하지 않고 PNG를 함께 검토한다.

## 독립 조명 스모크 결과

`tools/lighting_smoke.gd`는 실제 production 프로필/그림자, 3시드×지상/동굴×기존/현재 화면, PNG 크기/저장, 밝기 조건과 월드 무변경을 41개 단언으로 검사한다. standalone 실행은 모두 통과했다.

- 시드 1337 지상: 근백색 13.8683%→0.0966%, 평균 표시 밝기 0.6478→0.5925.
- 시드 -7 지상: 1.5864%→0%, 평균 표시 밝기 0.6144→0.5638.
- 시드 42 지상: 33.0635%→0.8755%, 평균 표시 밝기 0.7754→0.7350.
- 동굴 3시드 평균 표시 밝기: 0.2053–0.2114→0.2321–0.2387, 각각 10% 이상 증가. 암부 비율은 기존/현재 모두 0으로, 검은 픽셀 복원이라고 표현하지 않는다.

회귀 조건은 지상 근백색 비율 1% 미만/기존보다 악화 없음/평균 밝기 0.25 초과, 동굴 평균 밝기 10% 이상 증가/0.4 미만/암부 1% 미만이다. 이 범위는 3개 고정 카메라의 검증 계약이지 모든 시드/시점/디스플레이의 보편적인 최적 노출은 아니다. 그림자가 있는 실제 게임 경로로 검사하며 헤드리스에서 실행하면 실패로 거부한다.

## 전체 실행과 남은 한계

전체 `Verify.ps1` 증거 `Saved/Verification/20260908-230501-297`는 종료 코드 0으로 완료했다. 새 조명 41개, 기존 단위 48·기후 99·저장 74·메시 502·최적화 동등성 534·랜드마크 데이터 118개, 랜드마크 실제 왕복 41/42·Builder 53/72·웅크리기 24/25·생성 조작 36/44·Dungeon 408/32·조준/CLI 48/50개와 보호 동굴 왕복을 통과했다. 예상한 잘못된 CLI의 exit 2 외 모든 단계는 0이다. 조명 스모크는 4.369초이며 같은 3시점의 지표가 standalone 결과와 일치했다.

Overworld 128시드 행렬은 36.473초, Dungeon 128시드+경계는 2.404초다. 별도 저장 쓰기/읽기 PID 38492/51016(Overworld), 20608/50620(Dungeon)에서 각각 1,000편집과 플레이어·자세·인벤토리·진행도·설정을 복원했다. 최종 `runtime.png`, `cave.png`, `dungeon-exit.png`도 직접 확인했고 HUD/조준과 지상/지하/던전의 읽기 가능 상태를 유지했다. 이중 조명 이미지 12장과 `lighting-metrics.json`을 보존한다.

185맵 3시드 생성은 4.288–5.486초, 255 Overworld 교체는 18.824초/생성 루프 간격 P95 1.265ms/최대 34.283ms, 최대 Dungeon 교체는 1,021.89ms다. 이전 실행과 프레임 간격이 크게 달라졌으며 조명 상수 변경에 따른 성능 향상이라고 해석하지 않는다. 픽셀/밝기 검증과 성능 검증의 범위를 분리한다.

독립 비교 PNG를 직접 검토해 눈 표면의 픽셀 무늬와 면 경계가 더 잘 보이는 것을 확인했다. 동굴은 조금 밝아졌지만 방향 안내·벽/바닥 구분의 전체 해결은 아니다. 건물 외형·자연스러운 연결로·나무 지지/배치·생물군 고도 경계와 자연 동굴 전체 연결은 남아 있다.

이번에는 별도 185맵 렌더 비교를 재실행하지 않는다. 그 벤치마크는 이전부터 독립된 고정 조명/그림자 조건을 사용하며 실제 게임의 새 프로필과 같지 않다. 최신 비교 근거는 여전히 `20260908-224549-629`의 CPU 편집 P95 11.809ms/화면 반영 16.799ms로 16.7ms 목표 미달이다. 조명 개선으로 이 성능 문제나 Unreal 대비 전체 우위가 해결됐다고 주장하지 않는다.
