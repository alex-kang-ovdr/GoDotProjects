# Builder challenge·개발 조작·프로세스 재시작 검토

Unreal README의 채굴 8/설치 4 챌린지, 개발 단축키 계약, R 복귀를 설계 입력으로 삼았다. Unreal C++는 수정하거나 복사하지 않고 Godot 신호·입력·HUD로 독립 구현했다. 이 문서는 구현 에이전트의 자체 검토다.

## 구현과 의미

- 월드가 성공적으로 채굴/설치한 뒤 대상 인벤토리를 포함한 신호를 보낸다. 플레이어는 자신의 인벤토리 이벤트만 집계한다. 물·나뭇잎·가득 찬 스택·빈 스택·막힌 설치 등 실패에는 증가하지 않는다.
- `total_mined`/`total_placed`는 누적 수이며 HUD는 목표 8/4까지 표시한다. 두 조건을 모두 만족하면 COMPLETE가 된다. 정수 최댓값에서는 포화시켜 음수로 넘치지 않게 했다.
- 체크포인트가 두 카운터를 함께 저장한다. 누락 필드는 기존 포맷 2와의 호환을 위해 0으로 읽고, 포함된 잘못된 값은 전체 트랜잭션 전에 거부한다. 생성 버전 3/포맷 버전 2는 그대로다.
- R은 현재 편집 셀에서 입구 주변 반경 2·높이 ±4의 지지 바닥과 2셀 여유를 찾는다. 모두 막혔으면 지형을 강제로 지우거나 플레이어를 옮기지 않는다. 성공해도 진행도/인벤토리는 유지한다.
- 새 월드 생성은 진행도·선택·인벤토리를 새 세션 상태로 초기화한다. 저장 불러오기는 저장 상태를 복원하며 이 초기화 경로와 구별한다.
- 개발 빌드 Ctrl+0 도움말, Ctrl+1 채우기, Ctrl+2 비우기, Ctrl+3 진단, Alt+1 성능 HUD, Alt+3 JSON 프로필을 추가했다. Ctrl+8/9는 저장/복원이다. 수정 키가 붙은 숫자가 일반 핫바 선택으로 흘러가지 않게 분리했고 로드 잠금 중 조작을 거부한다. 개발용 스택 변경 자체는 챌린지를 진행하지 않는다.

## 피드백과 수정

첫 프로세스 재시작 테스트는 공기 위 테스트 블록 1,000개 중 8개 채굴·4개 재설치를 하고도 저널 1,000개가 남는다고 잘못 기대해 실패했다(`20260908-205434-422/restart-write.log`). 기본 공기로 되돌린 4개는 희소 저널에서 제거되는 것이 올바르다. 테스트를 초기 1,004개→최종 1,000개로 수정하고 제거한 4셀의 공기도 별도로 확인한다. 런타임의 정상적인 저널 정규화를 바꾸지 않았다.

첫 Builder PNG에서는 개발 글자가 밝은 설원 위에 겹쳤다. 선택적으로 보이는 어두운 배경을 추가하고 개발/성능 HUD의 높이를 표시 상태에 맞춰 조정했다. 입력 통과와 실제 클릭 회귀를 유지한다.

## 검증 범위

`builder_smoke.gd`는 직접 계약 검사와 실제 렌더 창 입력 검사를 구분한다. 8회 LMB 채굴·4회 RMB 설치, 완료 HUD, 실패 행동 무집계, 다른 인벤토리 무집계, 카운터 손상 거부·레거시 기본값·최댓값, Ctrl/Alt 핫키, Ctrl+8/9 디스크 복원, R 안전 복귀·실제 착지·완전 폐쇄 시 거부, 새 월드 초기화를 포함한다.

`restart_persistence.gd`는 같은 씬 재생성에 그치지 않는다. Verify가 첫 Godot 프로세스의 종료를 확인한 뒤 두 번째 프로세스를 새로 시작한다. 첫 프로세스는 비동기 저장 후 종료하고 두 번째는 무편집/초기 인벤토리에서 파일을 읽는다. 최종 1,000개 저널, 제거한 공기 셀, 수량 `[5,9,9,9,9,9,9,9,8]`, 진행 8/4, 위치·시점·선택·HUD를 고정 기대값과 대조한다. 로그와 process.json은 각 PID를 보존한다.

## 남은 범위

최종 전체 명령은 `pwsh -NoProfile -File MinecraftDungeonGodot/Verify.ps1`이며 `Saved/Verification/20260908-205710-684`에서 종료 코드 0이다. Builder 직접 53개/렌더 입력 72개, 기존 단위 48·저장 74·메시 502·최적화 534개, 128시드 행렬과 동굴 왕복이 통과했다. 재시작 쓰기 PID 77360과 읽기 PID 36408은 모두 종료 코드 0, 저널 1,000개를 기록했다. 최종 `builder.png`와 `runtime.png`를 직접 열어 진행 표시·선택 슬롯·개발 HUD 대비와 화면 배치를 확인했다.

생성 설정 패널, 모드 전환/던전 생성, Alt+2 조준 좌표축과 웅크리기는 아직 없다. 프로필의 엔진 할당 메모리는 OS 최대 작업 집합을 대신하지 않는다. 현재 검증은 개발 빌드이며 릴리스 내보내기는 검증하지 않았다. 정상 종료/재시작 성공은 쓰기 중 강제 종료·정전 복구 증거가 아니다. 기존 편집→프레임 P95 16.948ms의 성능 게이트 미달도 이번 기능 추가로 해결됐다고 보지 않는다.
