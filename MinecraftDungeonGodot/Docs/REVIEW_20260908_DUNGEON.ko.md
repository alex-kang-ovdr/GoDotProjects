# 던전 모드·설정 식별자 자체 검토

기준일: 2026-09-08. 이번 루프는 생성 모드 기능 격차를 줄이며 전체 Unreal 우위 판정은 별도다.

## 계약과 독립 구현

Unreal의 `Public/GenerationOptions.h`, `Public/DungeonLayout.h`, `Private/Tests/DungeonLayoutTests.cpp`를 읽어 UI 크기 11–255/홀수, 방 시도 1–512, 방 비중첩, 전체 바닥 연결, 유효한 입구·출구를 기준으로 삼았다. Unreal C++ 생성 코드는 복사하지 않았다. Godot 제품 UI는 정사각형 크기를 사용하며 Unreal 하위 생성기의 직사각형 Width/Height 조합은 지원하지 않는다.

`DungeonGenerator`는 worker-local 시드 RNG로 사각 방 후보를 만들고 간격을 두고 수락한다. 각 수락 방을 이전 방 중 가까운 중심과 3칸 폭 L 통로로 연결한다. 바닥은 합집합으로 관리하여 중복이 없으며 나중에 높이 3칸의 외곽 벽을 구성하므로 통로가 벽으로 다시 막히지 않는다. 첫 방 중심이 입구, BFS로 가장 먼 바닥이 출구다. 입구 바닥은 잔디, 출구 바닥은 모래이며 선택 POI는 녹색/금색 기둥이다. 지붕 없는 던전이며 적·전리품·클리어 보상은 이번 범위가 아니다.

Tab 패널은 Mode/Seed/Size/Room Attempts/Checks/POI의 여섯 행이다. 모드 변경은 초안만 바꾸며 기본 크기는 Overworld 185/Dungeon 41이다. 방 시도 수는 Overworld에서 N/A이고 숫자 입력/방향키를 무시한다. 방 수가 아니라 배치 시도 수이므로 512를 입력해도 512방을 보장하지 않는다. 기존 생성의 잠금·숨긴 청크 구성·물리 준비·교체·실패 보존 경로를 그대로 사용한다. 패널을 닫은 COMPUTING 단계에서도 경과 시간을 갱신하도록 이전 표시상 한계도 수정했다.

## 저장 계약

포맷 2/생성 버전 3을 유지한다. 기존 Overworld 입력의 셀/해시는 바뀌지 않았다. `generation_options`에 모드, Dungeon이면 방 시도 수를 포함하고 저장 작업자 스냅샷에도 복사한다. 기본 해시가 같아도 옵션이 다르면 복원을 거부한다. 옵션이 없는 기존 저장은 Overworld로만 읽는다. 체크포인트가 자동으로 모드나 월드를 재생성하지는 않으므로 동일 시드·크기·모드·방 설정을 먼저 적용해야 한다.

## 발견한 실패

첫 실행 `Saved/Verification/20260908-213532-707`에서 던전 저장 왕복 2개가 실패했다. 숫자 34가 JSON에서 34.0으로 읽힐 때 중첩 Dictionary 전체 비교가 일치하지 않았다. 모드는 정확히 비교하고 방 시도 수는 유한 정수·정확한 범위로 검증하도록 수정했다. boolean/문자열/소수/범위 밖 값, 같은 기본 해시의 다른 모드·방 옵션과 레거시 옵션 누락 회귀 검사를 추가했다.

두 번째 실행 `20260908-213619-266`에서 실제 던전 경로 왕복·최소/최대 월드 생성은 성공했지만 초기 착지 검사는 실패했다. 스폰은 바닥 위 0.55m에 시작하며 중력 18m/s²이므로 8프레임은 낙하 시간보다 짧았다. 실제 `is_on_floor()`와 바닥 높이를 최대 1초까지 확인하는 제한 대기로 바꿨다. 충돌 검사를 제거하거나 순간이동으로 통과시키지 않았다. 최대 맵 전체 캡처는 하단 HUD가 가리지 않도록 검증 카메라를 멀리 배치했다.

## 검증 범위

`tools/dungeon_smoke.gd`의 데이터 경로는 408개 단언이다. 128시드에서 크기 11/41/65와 다양한 방 시도를 조합해 동일 입력의 셀·방·경로·해시를 재생성한다. 생성기 BFS와 별개로 최종 실제 지지 바닥/2칸 여유 셀을 flood fill해 바닥 전체 도달성을 확인한다. signed int32 양 끝·255맵·512시도, 잘못된 설정 6개, 막힌 입구·겹친 방·범위 밖 바닥·깨진 경로 오류 주입 4개를 포함한다.

실제 렌더 경로는 패널 키 입력·방 수 숫자 오류/수정·모드 변경·POI 교체·최소/최대 크기·Checks OFF/ON·지면 착지·입구↔출구 W 입력 왕복·채굴과 비동기 체크포인트를 검사한다. `restart_persistence.gd --dungeon`은 별도 쓰기/읽기 프로세스로 1,000편집·진행도·인벤토리·시점·웅크린 몸과 설정을 복원한다. `Verify.ps1`의 기존 Overworld 회귀와 함께 실행한다.

## 남은 경계

새 던전 모드는 Overworld의 기후/자연 동굴/구조물 동등성을 대신하지 않는다. 255던전의 셀 수·생성 비용을 255 Overworld나 Unreal의 깊은 지형 수치와 섞어 우위를 주장하지 않는다. Alt+2 좌표축, 모든 기후 축의 생물군 판정·해저 높이맵·전역 접근성, 시각 품질과 편집 화면 반영 P95 16.948ms 미달은 남는다. 일반 게임 시작은 기본 Overworld이며 Unreal의 생성 CLI 플래그 전체를 이식하지 않았다. 실제 보행은 대표 시드 경로 증거이며 128시드의 모든 경로를 물리 왕복한 것은 아니다.

## 최종 전체 검증 근거

프로젝트에서 `pwsh -NoProfile -File .\Verify.ps1` 실행, `Saved/Verification/20260908-213949-627` 종료 코드 0. 단위 48·저장 74·메시 502·최적화 동등성 534, Builder 53/72·웅크리기 24/25·기존 생성 조작 36/44, 던전 데이터 408/렌더 32개 단언이 통과했다. 기존 Overworld 128시드 행렬은 19.820초, 새로운 Dungeon 128시드+경계 검사는 2.202초다.

Dungeon 41×41/시드 1337/34시도는 1,498셀·해시 1360838879, 렌더 생성 요청부터 교체 완료까지 43.13ms였다. 실제 W 입력 63칸 경로를 왕복 877/872 물리 프레임으로 완료했다. 최소 11×11/1시도는 검사 OFF의 READY로 25.62ms, 최대 255×255/512시도는 검사 ON의 PASS로 979.82ms였다. 최대 맵은 62,799셀·해시 2089684311이다. 이 수치는 단일 실행이며 성능 우위 게이트가 아니다.

`dungeon-input.process.json`의 실제 엔진 PID 35152, 전체 단계 32.742초, OS 최대 작업 집합 277,286,912바이트(약 264.44MiB)는 여러 모드 생성·이동·저장·캡처를 포함한다. 순수 생성기 메모리와 구분한다. 별도 쓰기 PID 32472/읽기 PID 65024의 `dungeon-restart-*.log`에서 1,000편집·진행도·자세·충돌체·설정 복원을 검증했다. Overworld의 별도 PID 63840/21064 복원도 통과했다.

같은 전체 실행의 Overworld 185 생성은 2.790–2.829초, 시드 1337 해시 1321744834를 유지했다. 255 Overworld 비동기 교체는 14.789초, 생성 루프 프레임 간격 P95 5.792ms/최대 22.506ms다. 편집 화면 반영 벤치마크는 이번에 재실행하지 않았으며 이전 16.948ms 미달 판정을 유지한다.

최종 화면 검토에서 출구의 자동 보행 방향이 바로 외곽 벽을 향해 캡처가 벽만 담는 문제를 확인했다. 테스트 캡처 시점만 뒤로 돌리고 바닥을 내려다보게 수정한 후 실제 엔진으로 `--script res://tools/dungeon_smoke.gd -- --runtime --output=res://Saved/Verification/20260908-213949-627/dungeon-final-view`를 제한 시간 60초로 재실행했다. 32개 단언·왕복 이동이 다시 통과했고 종료 코드 0, `dungeon-final-view.error.log`는 0바이트였다. 해당 하위 폴더의 PNG가 최신 화면 증거다. 여섯 행과 핫바가 잘리지 않고 최대 맵 전체도 HUD 밖에 들어온다. 출구 바닥은 그림자·핫바 가까이에 있어 표식의 명확성은 후속 시각 개선 대상으로 남긴다.

이 화면 재실행에서는 최대 던전 교체가 1,730.27ms로 앞선 전체 실행의 979.82ms보다 느렸다. 같은 셀·해시는 유지했고, 빠른 값만 골라 성능 통과로 판정하지 않는다. 프로세스 상태·VSync·표시/업로드의 변동을 포함하는 요청→완료 수치이며 아직 반복 성능 게이트가 아니다.
