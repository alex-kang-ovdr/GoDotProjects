# M07 조사 · 마인크래프트식 청크 스트리밍

기준일: 2026-09-11  
범위: Godot 경쟁 구현의 지상 월드 스트리밍. Minecraft 런타임의 비공개 구현 세부를 재현한다고 주장하지 않는다.

## 조사에서 채택한 원칙

[Minecraft Bedrock 공식 월드 생성 개요](https://learn.microsoft.com/en-us/minecraft/creator/documents/world-generation?view=minecraft-bedrock-stable)는 시드에서 출발해 지형, 생물군, 구조물, 특징물 순의 여러 패스로 월드를 구성하며, 높이 노이즈가 청크 경계를 넘어 부드럽게 변한다고 설명한다. 따라서 이번 구현은 **청크 로드 순서가 아니라 전역 시드·X/Z 좌표**만으로 열을 만들도록 했다. 동일 좌표를 어느 방향에서 먼저 방문해도 같은 블록이 생긴다는 것이 첫 계약이다.

공식 문서는 나무·광석·샘을 `feature` 패스의 자연 특징물로 구분한다. 이에 맞춰 지형/생물군/연속 동굴/광석을 열 생성에 넣고, 나무는 이웃 한 칸까지 전역 원점을 검사해 경계 잎이 끊어지지 않게 했다. 반면 월드 전체 후보를 비교해야 하는 랜드마크 선택과 시작 보호 동굴은 M07에서 보류했다. 이는 기능 누락을 숨기지 않고 이후의 지역 구조물 인덱스 과제로 분리하기 위함이다.

[Minecraft 공식 Chunker 세계 설정](https://learn.microsoft.com/en-us/minecraft/creator/documents/chunkerworldsettings?view=minecraft-bedrock-stable)은 월드 시드와 스폰 좌표를 별도로 보존하고, 플레이어 주변에서 서버 청크가 틱되는 범위가 성능에 영향을 준다고 명시한다. 이 프로젝트도 **생성/렌더/시뮬레이션/저장 범위가 같은 값일 필요는 없다**는 원칙을 채택한다. M07은 우선 생성·렌더 상주 범위를 3×3 열로 고정했으며, 엔티티 틱 거리와 장거리 저장은 후속 마일스톤이다.

## 이번 구현 계약

- 실행: `RunGame.bat --mode=overworld --seed=1337 --streaming=on`
- 단위: 수평 16×16 열, y=0~지형/장식 최고점. 기존 16³ 메시 청크로 자동 분할한다.
- 상주: 플레이어 중심 3×3 열. 청크 경계가 바뀌면 가장 먼 비수정 열을 먼저 하나씩 해제하고, 새 열을 하나씩 적재한다.
- 결정성: `generate_stream_column(seed, chunk_x, chunk_z)`는 외부 상태·방문 순서를 읽지 않는다. 인접 열의 나무 잎은 전역 나무 원점을 재검사한다.
- 안전: 블록 편집 또는 상자/화로가 있는 열은 세션 중 해제하지 않는다. 그래서 사용자 변경을 조용히 잃지 않는다.
- 기존 경로: 기본 유한 Overworld/Dungeon, v7 저장, 비동기 유한 월드 교체는 변경하지 않는다.

## 의도적으로 보류한 것

M07은 저장 가능한 무한 월드가 아니다. 스트리밍 세션에서 Ctrl+8/9는 명시적으로 거부되며, 수정 열은 메모리에 고정된다. 해제 가능한 탐험 면적은 넓어졌지만 장시간 세션의 메모리 상한·재시작 복원은 아직 해결되지 않았다.

전역 랜드마크, 시작 보호 동굴, 동굴 길찾기 Atlas, 생물군별 구조물/샘의 지역 인덱스도 아직 유한 생성 경로에만 있다. 이 상태에서 “Minecraft 수준의 무한 월드” 또는 Unreal 대비 우위라고 판정하지 않는다.

## 검증·피드백 루프

1. `RunTests.bat`: 63개 단언. 같은 열 결정성, 반환 좌표 경계, 3×3 부트스트랩, 경계 이동의 증분 적재/해제, 수정 열 고정을 포함한다.
2. `tools/streaming_smoke.gd`: 실제 `VoxelWorld` 경로에서 스트리밍 모드·상주 열·새 열/먼 열 전환·기존 메시/충돌 렌더러 연결 4개 단언을 확인한다.
3. 최신 헤드리스 스모크: 상주 9열, 적재 12열, 해제 3열, 마지막 열 작업 41.070ms. 이는 전체 화면 프레임 시간이나 GPU 측정이 아니다.

### 리뷰 결과와 계획 수정

단일 16×16 열의 GDScript 생성+희소 인덱싱이 약 40ms라서 60Hz 16.7ms 예산을 넘는다. 처음에는 해제 때 전체 `base_cells`를 순회해 더 큰 스파이크가 있었고, M07에서 열→셀 역인덱스를 추가해 전체 월드 스캔은 제거했다. 그러나 생성 자체는 여전히 메인 스레드다.

다음 M08 종료 게이트는 (a) worker에서 순수 열 데이터를 만들고, (b) 메인 스레드에서는 제한된 셀/메시 업로드 예산으로 커밋하며, (c) 30회 경계 왕복에서 P95 CPU 작업과 표시 반영을 분리해 측정하고, (d) 편집 저널·스테이션의 디스크 저장/재시작 복원을 증명하는 것이다. M07 결과만으로 성능 목표 통과를 선언하지 않는다.
