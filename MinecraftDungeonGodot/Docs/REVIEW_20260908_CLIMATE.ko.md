# 자체 검토 — 독립 기후 6축과 최종 높이맵

## 결과와 범위

2026-09-08 전체 `Verify.ps1 -RenderComparison`은 종료 코드 0이다. 증거는 `Saved/Verification/20260908-221350-016`에 보존했다. 독립 Depth 기후장과 실제 높이 shaping, Weirdness의 고지 판정, 고지의 돌 표면, 최종 표면/고체 바닥 높이맵을 추가했다. 생성 결과 변경을 인정해 생성 버전을 3→4로 올렸다. 전체 경쟁 목표는 아직 미달이며 다음은 자연 동굴/랜드마크 전역 접근성과 시각 품질이다.

## 원본에서 확인한 계약과 독립 구현

읽기 전용 Unreal `Private/VoxelWorldLayout.cpp`의 `SampleClimate`, `ChooseBiome`, `TerrainHeight`를 확인했다. Depth는 Y로부터 계산한 상대 깊이가 아니라 별도 수평 기후 노이즈이며 높이 생성에 실제 사용된다. Unreal도 모든 축을 생물군 분기에서 직접 사용하지 않는다. 따라서 예전 문서의 “모든 축의 생물군 판정 반영”은 지나치게 강한 표현이다. 기후장 생성·높이 shaping·생물군 판정의 역할로 나눠 판단한다.

Godot `sample_climate()`는 온도·습도·대륙성·침식·기이도·깊이를 각기 다른 시드 오프셋으로 생성하고 열당 PackedFloat32 6개를 보존한다. 기이도는 고지와 높이에, 깊이는 높이에 기여한다. 다른 축을 고정하고 하나만 바꿀 때 각 축이 생물군 또는 높이를 바꾸는지 검사한다. 깊이 -0.75→0.75만 변경한 비클램프 사례는 정확히 6블록 높이 차이를 만든다. 같은 X/Z의 기후는 Y가 달라도 같고, 기존 상대 깊이 질의는 `density_depth_at()`으로 분리했다. 같은 값 6개나 이름만 바꾼 축으로 완료 판정하지 않는다.

## 높이맵 의미 — 같은 이름을 같은 계약으로 오인하지 않기

최종 생성 이후 모든 셀에서 세 맵을 별도로 만든다. 각 값은 inclusive voxel Y이며 빈 열은 -1이다.

- `surface_heights`: 최상단 비공기 셀, 물 포함.
- `ocean_floor_heights`: 물을 제외한 최상단 고체, 지붕/나뭇잎 포함. 지질학적 지면이라는 뜻은 아니다.
- `heights`: 최상단 충돌 고체. 현재 레지스트리에서는 고체 바닥과 같은 값이다.
- `terrain_heights`: 초기 shaping 높이. 동굴·스폰·건물·코어 보정 이전의 기준이며 최종 지면이라고 부르지 않는다.

Unreal의 Surface/OceanFloor는 장식 전 지면(기초 보정 포함)을 나타내며 MotionBlocking만 최종 고체를 반영한다. Godot의 새 최종 맵과 의미가 다르다. 이 차이를 기록하고 정확한 API 동등성으로 포장하지 않는다. 맵들은 생성 layout 스냅샷이며 플레이 중 편집의 실시간 높이 캐시는 아니다.

`WorldLayoutValidator`가 맵 타입·길이와 기후의 6배 크기/유한 범위를 검사하고 최종 셀에서 높이를 재계산한다. 별도 테스트는 생성기의 맵 함수를 호출하지 않고 매 열을 위→아래로 스캔한다. 물 위 표면/바닥 차이, 높은 나뭇잎, 빈 열, 배열 비공유를 작은 합성 사례로 검사한다. 차원이 맞는 복사 배열만 통과시키는 검사가 아니다.

## 검증과 실패에서 배운 것

새 `tools/climate_smoke.gd`는 99개 단언이다. 시드 1337/-7/42/int32 양끝의 41맵과 1337/185맵을 검사한다. 6축의 공간 변화·시드 반응·Y 독립, 독립 높이 스캔·기준 정렬 해시, 표면/바닥/기후 차원·NaN·범위 오류 주입, 버전 3 저장 무변경 거부를 포함한다.

첫 실행 `20260908-221222-747`은 새 테스트의 `_expect` 보조 함수 누락으로 파싱 실패했다. 함수를 추가했다. 다음 `20260908-221237-337`은 기후 98개는 통과했지만 기존 게임플레이 광선이 정확히 네 열의 모서리에 걸리는 문제를 드러냈다. 새 높이에서는 옆 열의 경계 면과 충돌했다. 시작 X/Z를 대상 열 중앙(+0.5)으로 바꾸고, 단순 충돌 존재보다 강한 정확한 대상 셀 일치를 요구했다. 게임플레이의 실제 물리 검사를 제거하지 않았다.

버전 변경과 독립 높이/기준 해시 오라클을 검토한 뒤 골든을 갱신하고 99번째 단언을 추가했다. v4 시드 1337은 41맵 48,488셀/1774796063, 185맵 1,065,192셀/976838873이다. 최적화 동등성과 Dungeon→Overworld 왕복 테스트의 v3 골든도 의도적으로 갱신했다. Dungeon 자체 41맵 1,498셀/1360838879와 255맵 62,799셀/2089684311은 그대로다.

저장 포맷은 2지만 전역 생성 버전은 4다. 이전 버전 3 체크포인트는 Dungeon도 거부하며 자동 변환/삭제하지 않는다. 같은 시드·크기·기본 해시를 넣고 SHA-256을 다시 계산한 버전 3 페이로드도 월드 변경 없이 거부하는지 검사했다. 보수적 전역 버전 정책의 비용을 숨기지 않는다.

최종 전체 실행에서 단위 48·기후 99·저장 74·메시 502·최적화 534, Builder 53/72·웅크리기 24/25·생성 조작 36/44·Dungeon 408/32·조준/CLI 48/50검사를 통과했다. Overworld 128시드 22.983초, Dungeon 128시드+경계 2.192초, 실제 3시드 동굴 왕복과 두 모드 새 OS 프로세스 1,000편집 복원도 통과했다. `launch-invalid` exit 2만 예상된 입력 거부이고 전체 실행은 0이다.

## 새 지형으로 다시 측정한 성능

185×185/1337/해시 976838873의 동일 셀·카메라·경계 편집 64회, VSync 1로 내부 비교했다. 청크는 준비 6.701823초, OS 최대 작업 집합 523.0625MiB다. 434청크, 250,357단위면을 89,316쿼드로 병합했다. CPU 편집 P95 7.449ms, 다음 `frame_post_draw`까지 P95 11.148ms, 갱신 최대 2청크다. GridMap은 준비 49.741732초/1,132.6171875MiB/화면 반영 P95 26.973ms였다. 같은 Godot 데이터에서 준비 약 86.5%, 메모리 약 53.8% 감소다. GridMap의 CPU 제출 0.006ms는 지연된 렌더/충돌 갱신 비용을 포함하지 않으므로 그 수치만 비교하지 않는다.

이번 단일 실행의 편집 응답성은 16.7ms 아래다. 이전 버전 3 마지막 16.948ms 초과의 원인을 해결했다고 주장하지 않으며 반복 안정성은 남는다. 생성 버전과 지형이 달라 과거 셀 데이터와 최적화 전후 동등 비교도 아니다. 현재 Unreal 1,185,740솔리드셀/약 3초와 기능·계측 범위가 달라 엔진 간 우위 판정은 보류한다. 모든 원시 샘플·PNG·프로세스 지표를 보존했다.
