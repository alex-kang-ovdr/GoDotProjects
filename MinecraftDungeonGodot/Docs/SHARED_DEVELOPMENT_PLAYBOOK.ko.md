# Unreal ↔ Godot 공유 개발 플레이북

기준일: 2026-09-08

## 공유하는 것

- 제품 방향: 결정적 복셀 월드에서 채굴 → 수집 → 배치 → 제작 → 생존으로 이어지는 수직 조각
- 안정 계약: 12개 블록 ID, 9개 핫바 슬롯, 블록당 최대 64개, 돌→조약돌 드롭, 물·나뭇잎 회수 거부
- 생성 계약: 정수 시드와 설정을 명시 입력으로 사용하고 같은 입력은 같은 월드 해시를 생성
- 데이터 흐름: 레지스트리 → 청크·저장 → 생성 → 채굴·도구 → 인벤토리·제작 → 생존 → 상태 블록 → 탐험 → AI → 릴리스
- 품질 루프: 계약 고정 → 최소 종단 구현 → 자동 테스트 → 실제 엔진 스모크 → 화면 검사 → 리뷰 → 문서·인수인계
- 근거 정책: 실패 결과를 숨기지 않고 테스트 수, 실행 명령, 측정값, 남은 위험을 마일스톤 문서에 기록

## 공유하지 않는 것

- Unreal C++ 또는 Godot GDScript 런타임 코드를 서로 복사하지 않는다.
- 엔진별 오브젝트 수명, 물리, 렌더링, 입력, 저장 API를 억지로 같은 추상화에 맞추지 않는다.
- Minecraft, Luanti, Minetest Game의 코드·에셋·명칭을 제품 구현에 무단 복제하지 않는다.

## 엔진별 구현 대응

- Unreal HISM/PCG ↔ Godot 청크별 ArrayMesh/greedy 표면·ConcavePolygonShape3D(현재), GridMap은 비교 기준
- Unreal Character Movement ↔ Godot CharacterBody3D와 Jolt Physics
- Unreal Canvas HUD ↔ Godot Control/CanvasLayer
- Unreal Automation Framework ↔ Godot 헤드리스 SceneTree 테스트 러너
- Unreal SaveGame ↔ Godot 버전형 JSON 희소 편집 저널·SHA-256·백그라운드 파일 작업

185 × 185 동일 셀 비교에서 청크 렌더러를 채택했다. 결과는 `Docs/REVIEW_20260908_CHUNKS.ko.md`에 기록했다. 동일 데이터·시점·편집 시퀀스로 기존 GridMap을 다시 실행할 수 있으며, 깊은 M03 월드로 바뀌면 동일 조건 비교를 반복한다.

## 생성 심화에서 공유할 피드백

Unreal M03 완료 보고서의 높이맵·기후 코어·동굴 보호 회귀 항목을 Godot 최종 셀 검증에 적용했다. Godot에서도 개수만 검사하면 건물로 다시 채워진 공동, 겹친 구조물, 샘이 막은 출입구를 놓쳤다. `WorldLayoutValidator`는 모든 생성 단계가 끝난 셀을 다시 조사한다. 128시드에 작은 해안의 샘 누락 회귀를 포함하며 보호 동굴은 실제 캐릭터 입력으로 별도 검사한다. 이 교훈과 원인·수정은 `Docs/REVIEW_20260908_DEEP_GENERATION.ko.md`에 기록한다. Unreal 원본에 변경을 강제로 적용하지 않는다.

## 초기 준비 최적화에서 공유할 피드백

전체 시간만 측정하면 생성 정렬·노출면 판정·GPU 업로드를 구분하지 못한다. 단계 계측 후 기존 출력과 동등한 최적화부터 적용한다. Godot에서는 정수 키의 네이티브 정렬과 임시 이웃 배열/재질 판정표가 효과적이었다. 단, 밀집 청크에 빠른 방법이 희소 청크에는 더 느렸으므로 멤버 수별 측정 후 적응형 경로를 사용했다. 기준 구현을 보존하고 해시·전체 마스크·충돌 오라클을 대조한 방법론을 공유한다. 엔진마다 비용 구조는 다르므로 Godot의 임계값 64를 Unreal에 그대로 적용하지 않는다.

## 게임플레이와 영속 검증에서 공유할 피드백

Builder 8/4 진행도는 입력 횟수가 아닌 성공한 인벤토리/월드 트랜잭션에 연결한다. 실패 행동과 개발 스택 조작을 분리하며 저장 검증에 카운터 범위를 포함한다. 같은 씬을 새로 만드는 검사와 OS 프로세스를 종료하고 새로 시작하는 검사는 서로 다른 근거로 구분한다. 희소 저널의 테스트 기대값은 기본 셀로 되돌린 편집이 제거되는 정규화 계약을 반영해야 한다. Godot의 구현·실패 사례는 `Docs/REVIEW_20260908_BUILDER.ko.md`에 남겼다.

이동 계약도 카메라 연출만으로 완료하지 않는다. 웅크리기는 실제 몸 높이·천장 겹침·발 위치·대각 가장자리와 점프/바닥 제거 예외를 실제 물리 입력으로 검사한다. 30/60/120Hz 검사는 시간 간격 의존적인 구멍을 찾는 회귀 기준이며 모든 움직이는 지형에 대한 보장은 아니다. 자세 복원은 boolean 데이터 외에 충돌체·눈높이도 확인한다(`Docs/REVIEW_20260908_CROUCH.ko.md`).

## 생성 조작에서 공유할 피드백

생성 설정은 초안과 적용된 월드를 분리한다. 옵션을 변경했다는 이유로 현재 월드를 바꾸지 않으며, 적용·중복 요청·저장과의 경합·실패 복구를 명시적으로 검사한다. 패널 표시 여부와 생성 중 게임플레이 잠금은 별도 상태다. PASS는 실제 수행한 검사에만 부여하며 검사 미실행은 READY로 구분한다.

Godot은 작업 스레드에서 독립 생성 데이터와 청크 인덱스를 만들고, 활성 노드·GPU/충돌 작업은 메인 스레드로 제한했다. 작은 월드 성공만으로 UI 최대값을 보장하지 않으며 255 × 255를 실제 렌더 경로로 실행한다. 평균 생성 시간·생성 중 프레임 간격·편집 화면 반영 시간은 각각 다른 지표다. 단일 청크가 배치 예산을 넘을 수 있다는 한계와 오류 주입 결과를 `Docs/REVIEW_20260908_GENERATION_CONTROLS.ko.md`에 남긴다. 이 상태/검증 계약은 공유하되 Unreal의 스레드/오브젝트 API에 Godot 구현을 직접 이식하지 않는다.

## 던전 모드에서 공유할 피드백

Unreal `Public/GenerationOptions.h`, `Public/DungeonLayout.h`, `Private/Tests/DungeonLayoutTests.cpp`에서 모드별 크기 하한·1–512 방 시도·방 비중첩·바닥 전체 연결·입출구 계약을 확인했다. 생성 알고리즘은 별도로 구현했다. 바닥 목록의 그래프 연결성과 실제 캐릭터가 회전하며 통로를 걷는 것은 다른 검사이므로 둘 다 수행한다. Godot은 최종 셀의 지지 바닥·여유 공간으로 독립 flood fill을 만들고 생성기의 경로 자료와 따로 대조한다.

모드가 늘어나면 저장의 월드 식별자는 시드·크기·해시뿐 아니라 생성 옵션도 포함해야 한다. 방 시도 수가 달라도 우연히 같은 지형이 나올 수 있어 설정을 명시적으로 검사한다. JSON에서 숫자가 부동소수로 복원되는 경우 중첩 Dictionary 동등 비교는 실패할 수 있으므로 유한 정수/정확한 범위 검증으로 정규화한다. 기존 저장의 옵션 누락은 당시 모드로만 해석하고 다른 모드로 자동 승격하지 않는다.

## 조준 표시·실행 옵션에서 공유할 피드백

Unreal `DungeonPlayer::UpdateBlockTarget`의 기본 윤곽/개발 좌표축과 `GenerationOptions::FromCommandLine`의 생성 옵션 의미를 공유한다. 엔진 좌표계는 동일하지 않으므로 Godot은 Y-up을 표시한다. 표시 메시가 조준 충돌을 가로채지 않는지, 블록 삭제·월드 교체·UI 잠금 뒤 잔상이 남지 않는지 검사한다. 물리 갱신 순서는 플레이어 이동 뒤 조준 광선이 오도록 명시하고, 디버그 도형은 매 프레임 다시 만들지 않는다.

실행 인수는 순수 파서 검사만으로 끝내지 않는다. 새 OS 프로세스로 실제 첫 월드·생성 횟수·검사 상태·POI·플레이어 착지를 확인하고 잘못된 입력은 예상 종료 코드도 검사한다. Godot 사용자 인수는 엔진 인수와 `--`로 분리한다. 서로 다른 엔진의 구문을 공유하더라도 기본 실행 경험과 오류 처리의 차이는 명시한다. 이번 Godot은 인수 없는 빠른 41맵 시작을 유지하고 잘못된 범위를 조용히 잘라내지 않고 거부한다.

## 기후·높이맵에서 공유할 피드백

필드 개수만 맞추지 말고 각 신호의 원천과 소비 경로를 확인한다. Unreal의 Depth는 독립 수평 기후장이고 높이 생성에 기여한다. 표면 아래 상대 깊이를 여섯 번째 값으로 붙이는 것은 같은 계약이 아니다. 반대로 모든 축을 생물군 분기에 직접 넣는 것도 원본 계약보다 강한 요구다. Godot은 축 하나만 교란하는 인과 검사와 공간 변화/시드 반응/Y 독립성 검사를 추가했다.

높이맵은 이름보다 셀 포함 조건·생성 단계·빈 열 값이 중요하다. Godot의 최종 물 포함 표면/유체 제외 고체 바닥(지붕·나뭇잎 포함)은 Unreal의 장식 전 지면 맵과 다르다고 명시한다. 독립적인 위→아래 스캔, 물/나뭇잎/빈 열 합성 사례와 오류 주입으로 검사하며 생성 함수가 만든 배열을 그대로 정답으로 쓰지 않는다. 현재 두 맵 값이 같아도 서로 다른 의미를 문서화한다.

생성 결과를 의도적으로 바꾸면 버전을 먼저 구분하고 독립 해시/최종 셀 오라클을 확인한 뒤 골든을 갱신한다. 오래된 저장을 조용히 새 지형에 적용하지 않으며 모드 전체 버전 정책의 호환 비용도 알린다. 물리 테스트 광선은 열 중심을 사용하고 정확한 대상 셀을 요구한다. 정수 모서리 광선은 인접 열 높이에 따라 불확정 면을 맞힐 수 있다. 변경된 지형으로 렌더러 비교를 다시 실행하고 이전 버전의 좋은 P95만 재사용하지 않는다. 근거는 `Docs/REVIEW_20260908_CLIMATE.ko.md`에 있다.

## 전역 접근성에서 공유할 피드백

열린 문과 안전 스폰을 각각 검사해도 둘 사이를 막는 절벽은 놓친다. Godot 버전 4의 기본 시드에서는 6개 문 중 3개만 보행으로 연결돼 있었다. 최종 셀에서 지지 바닥·몸 공간·단차/점프 여유를 가진 연결 그래프를 만들고, 별도 고체 표면 열거/DFS 및 실제 캐릭터 왕복으로 검증한다. 생성기의 경로 목록을 최종 연결성의 정답으로 삼지 않는다.

수정 도로의 바닥/몸 공간만 보존하면 기존 길의 점프 머리 공간을 막을 수 있다. 새 길이 기존 연결 영역에 붙는 지점에서 스폰까지의 경로도 함께 보존해야 한다. 반대로 연결 영역 전체를 고정하면 필요한 절개도 불가능해진다. 필요한 경로·건물·샘·보호 동굴의 구체적 보존 조건을 검사한다. 작은 맵 성공과 255맵 탐색 비용은 따로 측정하며, 전체 스폰까지 새 도로를 만드는 것보다 가까운 연결 영역에 붙이는 방식의 비용을 비교한다.

회귀 이동 테스트 시간을 줄일 때는 이동/충돌을 건너뛰지 않는다. 이번 Godot은 테스트 프로세스에서만 시간 배율과 physics ticks를 함께 조절하고 시뮬레이션 dt=1/60초를 단언한다. 가속된 기능 검증을 플레이 FPS나 편집 P95로 보고하지 않는다. 원래 속도의 중간 검증, 최신 가속/렌더 검증과 별도 기본 타이밍 성능 지표를 구분한다. 구현과 실패 로그는 `Docs/REVIEW_20260908_ROUTES.ko.md`에서 공유하며 Unreal 원본은 직접 변경하지 않는다.

## 조명에서 공유할 피드백

설원의 밝은 부분만 줄이려고 전체 노출을 낮추면 동굴도 어두워질 수 있다. 직접광과 환경광을 구분하고 같은 지형/카메라에서 지상과 동굴을 함께 비교한다. 톤매퍼 이름만으로 품질을 판단하지 않고 실제 사용하는 렌더러에서 확인한다. 선택한 프로필은 한 곳에 정의하고 production 연결 여부를 테스트한다.

밝기 측정은 HUD/조준점과 분석 영역, 표시 RGB인지 선형 광량인지, 근백색 픽셀이 실제 HDR 클리핑의 대리 지표인지 명시한다. 수치가 좋아도 화면을 직접 확인하고 눈 텍스처/면 경계, 동굴의 밝기·안내를 따로 판단한다. 고정 시드의 임계값을 모든 시점의 최적 노출로 일반화하지 않는다. Godot의 비교 근거는 `Docs/REVIEW_20260908_LIGHTING.ko.md`이며 Unreal 원본의 조명을 강제로 변경하지 않는다.

## 국소 메시 캐시에서 공유할 피드백

편집 셀/이웃 청크만 dirty 처리해도 청크 내부의 변경되지 않은 면을 매번 병합하면 CPU 낭비가 남는다. 평면별 실제 마스크 변경 revision과 객체 identity로 geometry를 재사용하되 재질·UV·법선·삼각형/충돌 순서를 기준 구현과 정확 비교한다. 반환 배열 변경이 캐시를 오염시키지 않는지, 마지막 블록 삭제·물로 재생성·전체 rebuild·비동기 월드 publication에서 수명과 인계가 올바른지도 검사한다.

캐시는 초기 시간과 상주 메모리를 소비한다. 한 청크 반복 편집뿐 아니라 여러 청크의 첫 편집도 별도 측정하고 실제 프로세스에서 A/B와 B/A 순서를 바꾸어 반복한다. 조명/그림자·시드/크기·해시·카메라·VSync·focus를 기록하고 같은 조건 PNG를 대조한다. CPU submit 감소를 화면 응답성 게이트 통과로 바꾸어 쓰지 않는다. 새로운 벤치마크가 게임 조명을 공유하더라도 플레이어/HUD 없는 장면이면 그 범위를 명시한다. 이번 절충과 미달 결과는 `Docs/REVIEW_20260908_PLANE_CACHE.ko.md`에서 공유한다.

## 월드 교체와 해제에서 공유할 피드백

새 지형을 작업 스레드에서 만들고 청크 구성을 나누어도 마지막 참조를 메인에서 내리면 이전 수백만 셀의 해제가 한 프레임을 막는다. 작은→큰 전환뿐 아니라 큰→작은 전환을 반복하고, 생성/검사/인덱싱·메시·데이터 인계/해제·노드 해제·완료 수신자를 따로 계측한다. 과거 큰 지연 하나가 재현되지 않으면 원인을 해결했다고 단정하지 말고 새로 재현한 병목의 범위를 분리한다.

Godot 구현은 순수 데이터 참조만 전용 작업 스레드로 넘겨 해제하고 Node/GPU/충돌 객체는 메인에서 배치 제거한다. 중첩 공유 스냅샷 자체를 clear하지 않는다. 이전 충돌이 없어지고 물리가 안정화되며 스레드 join까지 끝날 때 잠금을 해제한다. 스레드 시작 실패와 종료 중 정리도 테스트한다. 이 소유권·수명·증거 기준을 공유하며 Unreal의 UObject/GC에 Godot 방식을 그대로 적용하지 않는다. 최대 끊김 감소와 P95·완료 대기·메모리의 절충은 `Docs/REVIEW_20260908_RETIREMENT.ko.md`에 기록한다.

## 보호 동굴망에서 공유할 피드백

“모든 동굴 연결”은 먼저 대상 집합을 확인한다. Unreal의 CavesConnectedAndReachable는 CaveCells 보호 터널/방을 검사하며 모든 자연 공동을 포함하지 않는다. Godot도 보호 공기의 6방향 연결, 최종 셀의 캐릭터 보행/점프 경로, 실제 왕복 입력을 서로 다른 검사로 둔다. 공기가 연결돼 있어도 단차·천장·지지 바닥 때문에 플레이어는 이동하지 못할 수 있다.

내리막과 넓힌 통로/방을 즉시 조각하면 교차점 바닥이 다른 통로의 머리 공간을 덮는다. X/Z별 중심 발 높이를 먼저 계획하고 충돌이 없는 경우만 적용한다. 보호 대상은 건물 본체뿐 아니라 진입로·나무 수관까지 포함한다. 고도 범위와 분기 방식/길이 상한의 크기 경계를 검사하고, 실제 월드와 독립 합성 지형에서 각각 도달성을 대조한다. 자세한 실패와 복구 기준은 `Docs/REVIEW_20260909_CAVE_NETWORK.ko.md`에 있다.

생성 변경 전에 이전 실행 소스를 보관하고 별도 폴더에서 실제 import/기존 골든 재현을 확인한다. 소스 보관은 저장 파일 백업이나 자동 변환과 다르다. 공통 생성 버전 증가가 변하지 않은 다른 모드의 저장까지 거부할 수 있다는 비용과 동일 기본 저장 경로의 덮어쓰기 위험을 사용자 문서에 명시한다. 과거 성능 결과는 변경된 생성기에 자동 적용하지 않는다.

## 출력 조건과 지연 의미에서 공유할 피드백

OS 비디오 어댑터 목록과 실제 엔진 활성 화면 목록은 다를 수 있다. 이번 Windows 장치 조회는 165/60Hz를 보고했지만 Godot 활성 화면은 60Hz 한 개였다. 화면 번호·실제 창 위치/client 크기·주사율·DPI·VSync 요청값·엔진 FPS 상한·focus를 기록하고 회차/편집 중 변경을 거부한다. 조회 실패를 60Hz로 가정하지 않는다. 화면만 고정해도 드라이버/컴포지터 상태까지 통제되는 것은 아니다.

VSync 설정값과 실제 유휴 프레임 간격을 구분한다. ON/OFF 순서를 교대한 반복, 명시 소프트웨어 FPS 상한 대조, 동일 월드/카메라/PNG 검사를 수행한다. 프레임 제한을 껐을 때 좋은 지연이 나온다고 기존 ON 조건의 문제를 해결한 것이 아니다. CPU 메시 비용과 다음 프레임 대기가 포함된 지연을 각각 남기며 목표를 낮추거나 느린 표본을 버리지 않는다.

엔진 viewport 갱신 신호는 실제 모니터 표시/입력→광자 완료 측정과 같지 않다. 첫 신호 이후 실제 픽셀 변화는 별도 GPU readback 검사로 확인하되 동기화 비용을 성능 표본에 섞지 않는다. 물리 presentation을 주장하려면 OS present 추적/외부 측정이 필요하다. Unreal에도 같은 지연 정의와 측정 범위를 적용해야 비교가 된다. 구현·공식 API 참고·24회 대조와 미달 결과는 `REVIEW_20260909_DISPLAY_TIMING.ko.md`에 기록한다.

## 플레이 안내에서 공유할 피드백

생성 당시 연결됐던 길도 플레이어 편집 이후에는 막힐 수 있다. 출구의 직선 방위와 실제 보행 가능한 다음 방향을 구분하고, 안내 그래프는 현재 지지 바닥·몸 공간·단차 점프 여유를 검사한다. 생성 경로를 그대로 테스트 정답으로 쓰지 말고 안내가 선택한 다른 길도 실제 캐릭터로 걷는다. 일부 통로 봉쇄의 우회, 전체 봉쇄 경고, 지지 바닥 제거, 체크포인트 복원과 월드 교체의 캐시 무효화를 함께 검증한다.

작은 지도는 매 프레임 전체 월드를 복사하지 않는다. 실효 변경 revision과 store identity를 사용하되 이전 대형 월드를 UI 캐시가 붙잡지 않도록 소유권을 검토한다. 방 판정에 X/Z만 쓰면 지표 위에서도 지하 방으로 표시되므로 높이/지도 공기를 함께 본다. 지도 밖 새 터널, 웅크린 통로와 자연 공동의 미지원 범위를 명시하고 “검증된 출구 없음”을 “출구가 절대로 없음”으로 과장하지 않는다. Godot 구현/실제 이동/화면 근거는 `REVIEW_20260909_WAYFINDING.ko.md`에 공유한다.

나침반을 너무 거칠게 반올림하면 “남쪽을 보며 남쪽으로 좌회전”처럼 혼란스러운 안내가 된다. 시선과 경로 방위의 정밀도를 구분하고 실제 카메라 각도로 검증한다. 새 UI가 조명 분석 영역에 들어가면 어두운 패널을 어두운 지형으로 집계할 수도 있다. 실패를 보존하고 밝기 기준을 낮추지 않은 채 HUD 포함 사용자 화면과 UI 없는 조명 분석용 렌더를 따로 기록한다. 고정 픽셀 마스크만으로 모든 후속 UI를 제외했다고 가정하지 않는다.

## 시간 기반 채굴·물리 아이템에서 공유할 피드백

헤드리스의 캡처 마우스 모드와 실제 렌더 창은 다를 수 있다. 게임의 커서 안전 조건을 테스트 때문에 우회하지 말고 순수 도구×블록 행렬과 실제 viewport 버튼 유지/해제·이동 검사를 분리한다. 즉시 회수 API의 통과는 시간 기반 채굴의 증거가 아니다. 완료 전 해제/시선·지형·도구 변경 취소와 정확히 한 번의 내구도·카운터 갱신을 확인한다.

물리 드롭은 조준 광선/플레이어 충돌과 지형 충돌을 분리한다. 지연·거리·차폐·용량 조건을 모두 확인하고 인벤토리가 가득 찼을 때 삭제하지 않는다. 인벤토리 변경 이벤트 전에 드롭 소유권을 제거해 콜백 시점 중복 상태를 피한다. 저장/월드 교체 잠금 중 물리도 멈추고, 실패한 교체에는 기존 소유권을 보존한다. 개수 상한·낙하 구조 정책은 숨기지 않는다.

저장 버전을 올릴 때 이전 포맷의 누락 필드 기본값과 새 포맷의 필수 필드를 구분한다. 새 프로세스 복원에 사용 중/소진 도구와 격자 밖 드롭의 수량·위치·속도·지연을 추가하고 완료 콜백 직후 상태를 기록해 다음 물리 틱과 혼동하지 않는다. JSON 정수 정규화, full_precision과 필드별 수치 오차 기준을 명시하고 모든 실수의 비트 동일성을 가정하지 않는다. 초기 실패와 Godot의 현재 범위는 `REVIEW_20260909_MINING.ko.md`에 남긴다.

실제 입력을 쓰는 가속 테스트도 렌더 프레임과 물리 틱 사이의 전달 시점 영향을 받는다. 경로당 물리 틱 수와 제한 시간 실패를 보존하고, 테스트에서 요청한 키 전환은 다음 물리 틱 전에 명시적으로 전달한다. 속도·충돌·이동 허용 오차를 바꿔 통과시키지 않는다. 실제 OS 입력→표시 성능과 이 합성 입력 하네스를 구분한다. 직접 인벤토리를 세팅하는 fixture는 변경 신호도 보내야 캡처 HUD와 실제 수량이 일치한다.

## 방향 상태·렌더 데이터 경계에서 공유할 피드백

재질 편집과 상태 편집은 다른 사전이다. 기본 생성 재질 그대로라도 방향만 있는 셀을 저장할 수 있어야 하며, 복원 dirty 후보는 이전/새 재질과 이전/새 상태의 합집합이다. 블록 제거/재질 교체·구버전 저장·재생성 뒤 상태 잔존을 검사한다. 중복/셀 존재 검증은 사전 조회로 처리해 행마다 전체 저널을 검색하지 않는다. 이미 사용 가능한 저장 포맷에 필수 상태를 추가하면 버전 번호와 구버전 기본값을 명시한다.

24가지 상태 ID가 다르다는 것과 24가지 실제 회전이 다른 것은 별개다. 각 Basis의 정확 직교/양의 determinant/고유성, 로컬 축과 설치 면, yaw 경계/음수 각을 검증한다. 통나무 단면과 옆면을 구분하고 비대칭 무늬로 분기 회전도 관찰한다. greedy 병합 키·증분 면 갱신·캐시·fresh rebuild·이웃 변경·저장 복원 전체에서 방향을 유지해야 한다. 축/면 순서가 다른 엔진 간 상태 바이트를 직접 공유하는 것으로 오해하지 않는다.

메시 배열의 순서는 시각적 의미와 다를 수 있다. 실제 업로드 메시와 fresh rebuild를 비교할 때 위치·법선·UV·삼각형 winding을 묶고 삼각형 순서만 정규화한다. UV를 별도로 정렬하면 잘못된 면의 텍스처도 통과할 수 있다. 엔진의 법선 압축 경계를 통제하되 비교기에 UV 손상/뒤집힌 winding을 주입해 결함 검출 능력을 유지한다. 자세한 실패와 비교 수정은 `REVIEW_20260909_ORIENTATION.ko.md`에 남긴다.

소유권 보존은 결과 스택만이 아니라 이벤트 콜백에서도 감사한다. Godot 반복 검사는 실제 물리 줍기 경로로 10,000개 아이템을 옮기며 월드+인벤토리 수량을 생성−소비와 대조한다. 반복 fixture의 0초 지연, 일반 게임 지연 검사, 실제 최대 개수의 짧은 물리 실행, 장시간 FPS 검증을 서로 구분한다. 콜백 전에 기존 소유권을 제거해야 같은 아이템이 양쪽에 잠깐 나타나지 않는다.

설치도 같은 원칙을 적용한다. 인벤토리 소비 알림이 블록/방향/진행 기록보다 먼저 나가면 콜백 저장이 소비만 기록할 수 있다. 실제로 그 콜백에서 체크포인트를 만들고 복원해 검증한다. 내부 변경은 알림 없이 먼저 완료한 뒤 정상 알림을 한 번 보내며, 거부 경로는 소비·월드 변경·알림 모두 없어야 한다. 현재 단일 플레이어 계약과 임의 재진입/멀티플레이 권위까지의 보장은 구분한다.

## 동적 인벤토리·작은 창에서 공유할 피드백

아이템 ID와 슬롯 위치를 분리한다. 같은 슬롯에 다른 아이템이 들어갈 수 있으므로 설치·핫바 표시·줍기·저장 전체를 바꾸고, 원래 조약돌 슬롯에 옮긴 통나무를 실제 우클릭으로 설치해 검사한다. 수량 배열만 36칸으로 늘리는 것은 동적 인벤토리가 아니다. 가방이 생기면 한 스택이 가득 찬 상태와 전체 수용량이 없는 상태도 다르다. 기존 용량 거부 fixture는 실제 전체 가방을 채우되 빈 칸이 있을 때 성공하는 검사를 없애지 않는다.

커서는 장식이 아니라 별도 아이템 소유자다. 전체/절반/한 개·병합 잔량·교환·배경 클릭·패널 닫기·저장 중·재생성에서 수량을 확인한다. 종류별 합계와 독립 참조 모형을 고정 시드로 대조하고 changed 콜백에서도 중간 상태가 드러나지 않는지 검사한다. 새 스키마는 전체 구조를 필수 검증하고 구버전은 명시적으로 새 빈 가방/커서로 변환해 잔존을 지운다.

물리 창 크기·논리 UI 좌표·stretch·레터박스·실제 캡처 영역을 구분한다. 이미지 파일명에 요청 창 크기를 넣었다고 PNG가 그 해상도라는 뜻은 아니다. 테스트는 캡처 크기와 좌표 변환을 기록하고 작은 창에서 실제 클릭으로 아이템 수량까지 확인한다. 테스트가 레이아웃 갱신 함수를 직접 호출해야만 통과하면 정상 창 크기 변경 경로를 증명하지 못한다. 키보드 선택은 이전 마우스 위치와 분리한다.

숨은 인벤토리는 매 줍기마다 모든 슬롯의 문구/스타일을 새로 만들 필요가 없다. 닫힌 UI의 변경 콜백 경로를 검사하고 다시 열 때 최신 상태를 그린다. 비용 전후의 같은 workload를 남기되 단일 측정·합성 입력·viewport 캡처를 일반 프레임 성능이나 엔진 간 승리로 과장하지 않는다. 이번 구현/실패/수정은 `REVIEW_20260909_INVENTORY.ko.md`에 보존한다.

## 제작·개별 도구·장비에서 공유할 피드백

아이템 정의의 최대 내구도와 실제 도구 한 개의 남은 내구도를 분리한다. 같은 종류 도구를 합치거나 빈 칸을 탐색할 때 기존 도구를 수리하지 않는다. 가방·커서·장비 간 모든 교환에서 수량과 내구도 서명을 함께 보존한다. Godot은 고정 시드 2,500회 혼합 이동으로 이 불변식을 검사하고, 실제 제작한 도구의 좌클릭 유지 채굴에서 정확히 한 번 마모되는지도 검증한다. 활성 장비와 예비 장비/개발 프리뷰 우선순위 및 소진 시 정책을 명시한다.

제작은 재료 소모 후 생기는 빈 칸까지 포함한 독립 후보 상태에서 사전 검사한다. 결과 전체를 담지 못하면 원본 재료·커서·장비를 그대로 보존하며 성공 때만 한 번 공개한다. 정형 레시피의 외곽 공백/평행 이동/허용된 좌우 반전과 내부 빈 칸, 비정형 레시피의 정확한 수량을 각각 검사한다. 목록 선택→정규 격자 검증과 사용자가 직접 배치하는 제작 격자는 다른 UI 범위다. 작업대 소지 해금과 월드에 설치된 작업대 상호작용도 같다고 주장하지 않는다.

저장 포맷 6은 일반 스택 2튜플/도구 3튜플(아이템·수량·남은 내구도)과 4장비를 필수 검증한다. 이전 포맷 5에서 미래 아이템 ID를 허용하면 불완전한 메타데이터가 우회 유입될 수 있으므로 이전 계약 그대로 검사한 뒤 장비를 비운다. 실제 OS 재시작은 사용 중 활성/가방 도구와 소진 예비 도구를 함께 복원한다. 콜백 검사에서 RefCounted 객체를 캡처하면 자기 참조 순환이 생길 수 있으므로 테스트 종료 시 연결도 정리하고 종료 코드뿐 아니라 리소스 경고까지 검사한다. Godot 구현 근거는 `REVIEW_20260909_CRAFTING.ko.md`에 기록한다.

## 스테이션·피처 상태에서 공유할 피드백

블록의 외형 재질과 월드 상태를 같은 값으로 취급하지 않는다. Godot의 상자/화로는 판자/벽돌 외형을 쓰되 셀 좌표별 별도 상태를 저장하고, 내용물이 있는 상태의 저수준 블록 삭제도 거부한다. 저장은 편집·스테이션·고갈 광맥·고정 틱 잔여 시간을 한 번에 검증한 뒤 공개해야 반쯤 적용된 월드를 남기지 않는다. UI 패널은 이 상태의 소유자가 아니라 전송 창구여야 한다.

생성 원석은 재질 이름이 아니라 생성기의 실제 표식/원천 좌표로 판정한다. 같은 조약돌·이끼 블록을 플레이어가 다시 설치했다고 광석을 되살리면 자원 무한 복제가 된다. 원천 고갈을 별도로 저장하고, 구버전이 해당 정보를 갖지 않을 때는 보수적으로 고갈 처리하거나 명시적으로 거부한다. 이 원칙은 Unreal의 한 스테이션 저장 제한을 그대로 이식하는 것이 아니라 엔진별 저장 범위를 넓히되 의미를 보존하는 방법이다.
