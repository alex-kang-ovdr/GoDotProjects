# 자체 검토 — 변경된 평면만 다시 메시화

## 변경과 보존 계약

청크 마스크의 각 평면에 변경 revision을 두고 `PlaneGeometry`에 병합 결과를 보존한다. 블록 편집 시 해당 셀과 6축 이웃의 마스크를 갱신하되 실제 마스크 값이 달라진 평면만 greedy 병합·정점/충돌 생성을 다시 한다. 변경되지 않은 평면의 packed 배열은 원래 순서로 합치고 재질별 인덱스 offset을 적용한다. 최종 ArrayMesh/ConcavePolygonShape3D 업로드는 여전히 청크 전체 단위다.

원본 `VoxelChunkMesher.build()`는 기준 경로로 유지한다. `build_cached()`는 평면 객체 identity와 revision을 함께 확인하며 반환 데이터와 캐시 데이터를 분리한다. 초기 생성 시 모든 평면을 구성하므로 첫 편집 비용을 숨기기 위한 벤치마크 전용 예열은 없다. 사라진 평면/청크, 전체 재생성, clear에서 캐시를 정리하고 비동기 월드 publication 시 새 마스크와 geometry 캐시를 함께 인계한다.

생성 버전 5, 저장 포맷 2, 기본 셀·재질·UV·법선·삼각형 순서·충돌 규칙은 바꾸지 않는다. 185/1337은 1,065,190셀/해시 1937405161이다. 단위면 250,395개/89,347쿼드/434청크도 기존과 같다. 가시 표면과 충돌 표면의 포함 조건은 각각 유지한다.

## 계측 조건을 먼저 고정

기존 `render_benchmark.gd`의 조명은 실제 게임과 달랐다. 현재 기본은 `--lighting=game`이며 `WorldLighting soft-day-v1` 환경광·햇빛과 그림자를 적용한다. `--lighting=legacy`로 이전 고정 조명을 재현할 수 있다. 따라서 새 값과 과거 `20260908-224549-629`의 16.799ms를 완전히 동일한 조건의 A/B로 보지 않는다.

새 옵션 `--geometry=reference|cached`, `--workload=boundary|scattered`, `--vsync=on|off`를 추가했다. 이 도구는 최소 크기 131, 기본 185/1337의 독립 전경 카메라 장면이다. 게임 조명은 공유하지만 플레이어/HUD/실제 입력 전체 게임 루프의 벤치마크는 아니다. CPU submit과 다음 `frame_post_draw`까지 시간을 별도로 보고하며 후자는 디스플레이에 실제로 나타난 시각의 하드웨어 계측이 아니다.

`tools/Benchmark-PlaneCache.ps1`은 실제 엔진 실행 파일의 OS 프로세스를 각 사례마다 새로 띄워 100ms 간격 PeakWorkingSet64, 종료 코드, 로그, 조건, PNG SHA-256을 기록한다. 기준/캐시 순서를 홀수 회차 AB, 짝수 BA로 바꾸며 두 작업 패턴을 각각 3회 실행한다. 모든 최종 사례는 VSync=1, 64개 편집 후 focus=true, 1280×720 렌더다. 동시 엔진 벤치마크를 실행하지 않았다. 환경에 의한 표시 시간 변동은 제거됐다고 주장하지 않는다.

## 동일 조건 A/B 결과

최종 12회 근거는 `Saved/Verification/plane-ab-20260908-232805-601/summary.json`과 각 하위 디렉터리다.

- 경계 반복: 주 편집 청크 1개/갱신 최대 2개, 64회. 기준 CPU P95 6.728–7.344ms, 캐시 2.613–3.062ms. 대응 회차에서 54.8–64.1% 감소했다. 각 편집의 새 평면은 6개, 재사용은 111–115개다.
- 분산 최초 편집: 서로 다른 주 청크 64개, 갱신 최대 4개. 기준 CPU P95 13.162–14.186ms, 캐시 4.511–5.308ms. 대응 회차에서 61.8–68.2% 감소했다. 새 평면 6–7개/재사용 72–302개다. X/Z 경계와 경우에 따라 Y 경계의 필요한 이웃도 갱신하므로 최대 4개는 과잉 전체 월드 갱신이 아니다.
- 경계 화면 반영 P95: 기준 16.874–16.990ms, 캐시 16.930–17.092ms. 분산은 기준 21.765–33.215ms, 캐시 17.053–17.163ms다. **CPU 개선은 입증했지만 16.7ms 표시 응답성 게이트는 여전히 미달**이다. VSync 포함 변동을 CPU 문제 하나로 단정하거나 VSync OFF 결과로 ON 결과를 대체하지 않는다.
- 최대 OS 작업 집합: 기준 525.29–526.01MiB, 캐시 637.07–637.76MiB. 대응 실행에서 약 111.5–112.0MiB(약 21%) 증가했다. 초기 준비는 기준 6.931–7.368초, 캐시 7.362–7.848초로 대응 회차 4.4–8.4% 증가했다. CPU 편집 개선의 명시적 비용으로 수용하되 메모리/초기 준비 최적화 완료로 표시하지 않는다.
- 모든 대응 PNG의 SHA-256이 같다. 경계 `089CC7AB…C2ABC17`, 분산 `609F4D4A…095F703E`. 실제 전경도 확인했다. 따라서 이번 변경에 새 지형 외형/조명 개선 효과를 주장하지 않는다.

초기 측정은 `plane-baseline`(새 게임 조명/캐시 이전), `plane-cache`(첫 캐시), `plane-ab-20260908-232537-329`(중첩 Dictionary 캐시 12회)에 보존했다. 초기 약 642MiB 캐시를 타입이 있는 `PlaneGeometry`로 바꿔 약 637MiB로 낮췄지만 여전히 기준보다 크다. 이전 좋은 단일 화면 P95 5.726ms 또는 일부 6ms 결과만 선택하지 않고 최종 3회 결과를 사용한다. 초기 standalone에는 OS 최대 메모리 측정이 없으므로 엔진 `MEMORY_STATIC`을 OS 작업 집합으로 바꾸어 표시하지 않는다.

## 정확성·수명 검토

`plane_cache_smoke.gd`는 캐시 유무의 ordered 정점/법선/UV/인덱스/재질/충돌을 정확 비교하고 별도 전체 셀 마스크 재생성과도 대조한다. 고정 RNG의 혼합 재질·물·나뭇잎·음수/경계 좌표 128회 편집, cold/warm cache, 동일 revision의 다른 객체, 평면 제거, no-op, 반환 배열 변조, 마지막 블록 제거 후 물로 재생성, 전체 rebuild/clear를 포함한다. 기존 독립 면 계산/실제 물리 광선 검증은 `meshing_smoke.gd`에서 유지한다. 생성 조작 검사에는 두 번의 비동기 publication 후 새 청크 수와 캐시 수의 일치 검사를 추가했다.

최종 전체 회귀는 `Saved/Verification/20260908-233012-624`, `Verify.ps1 -RenderComparison` 종료 코드 0이다. 38개 엔진 프로세스 단계가 완료됐으며 의도한 CLI 거부만 exit 2이고 나머지는 exit 0/오류 로그 없음이다.

- 신규 평면 캐시 1,005개, 메시 502개, 마스크/해시 최적화 534개, 생성 조작 38/46개(헤드리스/렌더)를 통과했다. 단위 48·기후 99·저장 74·Builder 53/72·웅크리기 24/25·Dungeon 408/32·인터페이스 48/50·조명 41도 통과했다.
- 독립 랜드마크 118개/실제 왕복 41/42개, 보호 동굴 3시드 왕복, Overworld 128시드 31.073초/Dungeon 128시드+경계 2.100초를 통과했다. 실제 프로세스 Overworld 쓰기/읽기 PID 79272/18484, Dungeon 3128/20872에서 각각 1,000편집과 플레이어/인벤토리/자세/옵션을 복원했다.
- 185맵 3시드 생성 단독은 3.781–4.333초다. 생성기 코드는 바꾸지 않았으므로 과거 실행보다 빠른 값을 캐시의 생성 알고리즘 개선으로 해석하지 않는다.
- 별도 게임 조명 렌더: 청크 준비 8.022초/637.75MiB, CPU P95 2.722ms/화면 반영 16.999ms. 같은 셀의 GridMap은 48.895초/1,139.48MiB/화면 반영 28.081ms다. Godot 내부 준비 약 83.6%·메모리 약 44.0% 감소이며 엔진 간 비교가 아니다. GridMap의 작은 CPU submit 값에는 다음 프레임의 지연 실행 작업이 포함되지 않는다.
- 255 Overworld 비동기 교체는 24.285초, 생성 루프 간격 P95 16.799ms/**최대 451.332ms**다. 해당 controls-input 프로세스 최대 작업 집합은 1,100.54MiB다. 이전 루프의 최대 34.283ms보다 큰 지연을 숨기지 않는다. 현재 간격 로그만으로 캐시/단일 청크/최종 publication/OS 스케줄링 중 어느 원인인지 분리할 수 없으므로 단계 계측과 반복 재현을 다음 우선 조사로 둔다. 4ms 배치 목표는 엄격한 프레임 상한이 아니다.
- 255 Dungeon 교체 1,882.22ms, 62,799셀/해시 2089684311이며 정상 전체 연결/입출구 왕복을 유지했다. 지표 크기만 같은 Overworld와 성능을 섞지 않는다.

최신 `runtime.png`, `cave.png`, `dungeon-exit.png`와 A/B 전경을 직접 확인했다. 기존 지형/텍스처/HUD/조준을 보존했으며 자연 동굴 안내나 건물 다양성 등 새 시각 개선을 주장하지 않는다.

## 남은 위험과 다음 작업

캐시는 모든 청크의 모든 구성 평면에 상주하므로 스트리밍/LRU 한도는 없다. 큰 월드의 교체 중에는 기존 월드와 새 캐시가 동시에 존재한다. greedy 병합 외에도 packed 배열 합치기·전체 청크 GPU/충돌 재업로드 비용이 남는다. 분산 테스트는 64개 지표 편집이지 모든 깊이의 복잡한 동굴·유체 패턴 또는 모든 하드웨어의 응답성 보장은 아니다.

표시 응답성 게이트, 자연 동굴 전역 접근성, 시각 품질, 동등 기능/동일 계측의 Unreal 비교는 미완료다. 이번 결과는 Godot 내부 편집 CPU 개선 근거이며 Unreal보다 낫다는 최종 판정이 아니다. Unreal 원본과 `CharacterMovementExample`은 변경하지 않았다.
