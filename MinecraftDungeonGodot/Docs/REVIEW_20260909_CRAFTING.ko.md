# M05 제작·개별 도구·장비 피드백 루프 — 2026-09-09

전체 목표는 진행 중이다. Unreal을 수정하지 않고 현행 M05 보고서/인벤토리 소스의 슬롯·제작 방법론을 참고해 Godot에 독립 구현했다. Unreal 문서상 M06 완료는 이 회차에서 하네스를 재실행한 결과가 아니며, 현재 Godot의 전체 기능/품질 우위를 의미하지 않는다.

## 구현 범위

`ItemRegistry`는 기존 블록/드롭 아이템 ID 0–8을 유지하고 막대·석탄·원철·철괴·작업대·상자·화로 9–15와 나무/돌/철 곡괭이·도끼·삽 16–24를 추가한다. 블록 재질 레지스트리는 여전히 12개다. 새 재료/도구가 새 월드 블록 재질이나 실제 광석 드롭이라는 뜻은 아니다.

일반 스택은 `[item, amount]`, 도구는 `[item, 1, remaining_durability]`다. 도구별 초기/최대 내구도는 59/131/250이며 최대 스택은 1이다. 같은 종류끼리도 내구도가 다른 인스턴스를 합치지 않는다. 36슬롯·커서·4장비의 이동/교환·저장에 메타데이터를 유지한다. 장비 0만 실제 채굴에 적용되고 나머지 3칸은 예비다. 소진 장비는 손 성능이고 자동으로 예비/프리뷰 도구로 대체하지 않는다. 장비를 비우면 이전 T 프리뷰 툴킷이 다시 적용되므로 아직 완성된 생존 성장 시스템은 아니다.

14개 제작 레시피는 통나무→판자×4, 판자→막대×4, 작업대·상자·화로와 9종 도구다. 정형은 외곽 공백/평행 이동/좌우 반전을 허용하고 회전은 허용하지 않으며 내부 빈 칸을 보존한다. 비정형은 종류·수량 다중집합을 비교한다. 3×3은 가방/핫바의 작업대 소지가 필요하며 커서는 제외한다. 별도 후보 인벤토리에서 재료와 소비 후 결과 공간을 검사하고 원본에는 성공 상태만 한 번 알린다. 가득 찬 출력·재료 부족·미해금·알 수 없는 레시피는 원본을 변경하지 않는다.

C 제작 UI는 목록/격자 미리보기/재료 수량/실패 이유/제작 버튼을 제공한다. 위/아래·Enter·실제 마우스, Ctrl+8/9를 사용한다. 사용자가 재료를 드래그하는 격자가 아니라 목록에서 선택한 레시피의 정규 격자를 실제 매처로 검증하는 방식이다. E→F는 장비 화면, 가방 Q는 선택 도구를 활성 장비로 교환, 장비 방향키/Enter/마우스는 커서와 교환한다. 모달 중 이동·채굴을 중단하고 다른 모달과 중첩하지 않는다.

저장 포맷은 6, 생성 버전은 6을 유지한다. 새 포맷은 36스택·커서·4장비와 유효한 도구 메타데이터를 필수 검증한다. 같은 생성 버전의 v5는 원래 0–8 아이템/2튜플 계약을 검사하고 가방·커서를 유지한 채 장비만 비운다. v2–v4는 이전 9수량 배열을 기존 의미로 변환하고 가방·커서·장비를 비운다. v2/3 방향 초기화, v4/5 방향 유지, v3–5 프리뷰 도구/드롭 유지 정책은 그대로다. 구 실행기 v2–v5는 새 저장을 읽을 수 없다. 사용자 저장 파일은 수정하지 않았으며 새 버전으로 직접 저장하기 전에 별도 백업이 필요하다.

## 실패 → 수정 → 재검사

원시 탐색 증거는 `Saved/Verification/crafting-dev`에 보존한다. `import-v2`/`data`의 Variant 타입 추론 오류와 `GDScript.is_tool()` 기본 메서드 이름 충돌을 명시 타입/`is_tool_item`으로 고쳤다. `data-v2`는 논리 163개가 통과했지만 ObjectDB 18개/리소스 2개 잔존으로 깨끗한 성공이 아니었다. verbose에서 레시피별 인벤토리를 캡처한 콜백 14개가 자기 참조 순환을 만든 것을 확인하고 테스트 종료 시 연결을 해제했다.

`render-v1`은 169개 중 작은 장비창 경계 검사 1개가 실패했다. 640×480 요청 창의 실제 렌더 영역은 640×360인데 4행 장비의 최소 높이가 안내문까지 밀어냈다. 작은 창 행 높이/글자 크기를 줄이고 장비 전용 제목/안내·독립 키보드 선택을 넣었다. `render-v2` 178개, 추가 2,500회 혼합 이동·잘못된 도구 메타데이터 검사까지 포함한 `render-v3` 2,695개가 통과했다. 현재 실패 로그는 삭제하지 않았다.

최종 탐색 렌더는 1280×720/640×480 요청 창에서 실제 마우스 레시피 선택·제작 수량을 검증하고, 작은 장비창에서 마우스 해제→키보드 예비 이동→마우스 재장착으로 내구도 58을 보존한다. 실제 좌클릭 유지 0.25초에는 블록/내구도가 유지되고 진행만 늘며, 완료 후 도구는 59→58/드롭 1개다. headless는 캡처 포인터를 흉내내지 않고 production 완료 경로를 별도 검사한다.

## 전체 회귀

`Saved/Verification/20260909-043812-774`에서 `Verify.ps1 -RenderComparison -BenchmarkScreen 0` 전체 59단계/상위 종료 0을 확인했다. 55개 exit 0/의도한 옵션 거부 4개 exit 2, 단계 시간 합계 795.474초, 엔진 ERROR/WARNING/SCRIPT ERROR 0행, 소유 엔진 프로세스 잔존 0개다. 전체 실행 시작 이후 게임/검사 소스는 변경하지 않고 문서만 갱신했다. 프로젝트는 부모 저장소에서 아직 untracked이며 commit/reset/삭제를 하지 않았다. 수정 대상 소스의 별도 공백 검사에도 일치가 없었고 `git diff --check`를 untracked 검증 근거로 쓰지 않았다.

제작 headless 2,683개/실제 렌더 2,695개, 기존 인벤토리 10,059/10,188개(각 10,000회 참조 모델), 채굴 294/360·방향 878/900·물리 보존 1,085개(10,000개 전달/10,749콜백/루프 6.467초)가 통과했다. 단위 48·저장 74·메시 502·캐시 1,005·정리 25·동등성 534, Builder 53/72·생성 조작 40/49·Dungeon 408/32·웅크리기 24/25·인터페이스 48/50·조명 53 및 기존 전체 회귀도 유지한다. 동굴 실제 경로 113/121은 131.817/131.646초로 기존 180초 제한 이내다.

새 OS 프로세스 Overworld 5968→53224/Dungeon 18824→87344에서 각각 1,000편집·방향·프리뷰 도구·드롭·마지막 가방/커서와 새 장비를 복원했다. 활성 나무 곡괭이 `[16,1,17]`, 소진 예비 철 삽 `[24,1,0]`, 가방 돌 곡괭이 `[19,1,83]`, 작업대와 커서 통나무 `[8,3]`가 디스크 및 독립 reader 검사에 일치한다. 새 저장 버전은 실제 envelope에서 6/생성 6이다. 도구의 수량 2·누락/음수/분수/bool/등급별 초과 내구도를 가방/커서/장비에 넣은 잘못된 저장은 적용 전에 거부하고 플레이어 상태를 보존한다. v5 전체 envelope 호환 읽기도 실행했다.

최종 `crafting-1280x720.png`, `crafting-640x480.png`, `equipment-small.png`를 직접 확인했다. PNG 실제 렌더 영역은 각각 1280×720/640×360/640×360이며 OS 레터박스는 캡처하지 않는다. 작은 창에서도 제작 버튼/안내와 네 장비/커서가 영역 안에 있다. 실제 마우스 수량 검사와 경계 단언을 함께 통과했으나 거친 작은 글자·텍스트만의 UI는 별도 시각 후속이다.

## 남은 범위 / 다음 루프

상자·화로는 제작 결과 아이템만 있고 설치/월드 셀 결합/보관/제련이 없다. 석탄·원철·철괴 ID는 있어도 실제 채굴→제련 획득 경로가 없으므로 철 도구는 준비된 테스트 재료로만 제작 검증했다. 프리뷰 도구 9개가 남아 있으며 실제 생존 진행과 M06 체력·허기·시간·날씨·사망/리스폰도 후속이다. 다음은 월드 결합 보관/화로와 광석 획득, 저장·실제 입력·오류 주입까지 같은 루프로 구현한다.

작은 창의 잘림은 고쳤지만 글자 래스터화가 거칠고 아이콘/장비 비주얼이 없는 텍스트 UI다. 전반적인 시각 품질·자연 동굴 탐험성·초기 준비/메모리·반복 VSync ON 16.772–17.069ms 미달·native presentation 미계측·동등 Unreal 비교는 해결되지 않았다. 레시피 개수나 일부 빠른 벤치마크 값만으로 우위를 선언하지 않는다.

## 공유 참고 자료

- Godot 4.7 [Script.is_tool](https://docs.godotengine.org/en/4.7/classes/class_script.html#class-script-method-is-tool)은 인수 없는 에디터 실행 여부 조회다. 이번 아이템 분류 함수 이름 충돌은 실제 실패 로그와 대조한 것으로, 별도 `is_tool_item` 이름을 사용한다.
- Godot 4.7 [RefCounted](https://docs.godotengine.org/en/4.7/classes/class_refcounted.html)는 참조 순환이 자동 해제되지 않는 경계를 설명한다. 이 회차의 verbose 잔존 로그와 콜백 연결 해제 전후를 별도로 검증했다.
- Unreal 로컬 M05 완료 문서/`VoxelInventory.h/.cpp`의 36슬롯·4장비·정형/비정형 제작과 작업대 소지 해금은 읽기 전용 참고다. 엔진 소스/바이너리/미완성 변경을 Godot에 복사하지 않았으며 추가 아이템 ID/축별 상태 바이트의 직접 호환도 주장하지 않는다.
