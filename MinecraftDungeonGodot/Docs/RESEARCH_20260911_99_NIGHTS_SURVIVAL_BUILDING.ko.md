# 99 Nights in the Forest 참고: 생존·채집·건축 루프 분석

기준일: 2026-09-11. 이 문서는 Roblox 게임 **99 Nights in the Forest**에서 관찰·공개 설명된 생존 제작 패턴을 분석해 Voxel Frontier에 독립 적용하기 위한 설계 기록이다. 레퍼런스의 코드, 아트, 명칭, 정확한 밸런스 수치, 레시피는 사용하지 않는다.

## 자료 신뢰도와 사용 범위

- [Roblox 게임 페이지](https://www.roblox.com/games/105853769231245/99-Nights-in-The-Forest-Survival)는 게임의 존재·공개 설명을 확인하는 출발점으로만 사용했다.
- [Fandom 제작 문서](https://99-nights-in-the-forest.fandom.com/wiki/Crafting), [커뮤니티 제작 안내](https://99nights.wiki/crafting/), [PC Gamer의 플레이 가이드](https://www.pcgamer.com/games/roblox/99-nights-in-the-forest-tips/)는 제작대 진행, 낮 채집, 야간 기지 방어, 모닥불 중심 회복이라는 반복 패턴을 교차 확인하는 2차 자료다.
- 라이브 서비스는 갱신될 수 있으므로 위 커뮤니티 자료의 정확한 아이템·비용·패치 사실은 고정 사양으로 삼지 않는다. 아래는 **설계 가설**이며 Voxel Frontier 플레이테스트로만 판정한다.

## 레퍼런스에서 추출한 설계 가설

| 관찰된 패턴 | 플레이어가 받는 압박/보상 | Voxel Frontier 독립 번역 |
|---|---|---|
| 낮에 나무·고철 등 자원 채집 | 멀리 갈수록 보상이 커지지만 귀환 시간이 줄어든다 | 기존 블록 채굴·물리 드롭·가방 용량을 ‘탐험 시간’의 비용으로 사용한다 |
| 야간 위협과 불빛/거점 | 안전한 귀환 장소가 단순 장식이 아니라 전략 자산이 된다 | 낮/밤·허기·보온을 도입하되, S01에서는 피해·적·죽음을 강제하지 않는다 |
| 제작대 단계 및 처리 설비 | 원재료가 도구·저장·방어·탐사력으로 전환된다 | 기존 제작·상자·화로를 식량/연료/방어 설비의 확장 지점으로 유지한다 |
| 배치 가능한 방어·생활 구조물 | 자원 지출이 생존 확률과 동선의 질을 바꾼다 | 기존 면 기반 블록 설치를 보호 반경·침대·화톳불·방어 구조물의 기반으로 쓴다 |

핵심 루프는 **낮의 채집 → 야간 위험 대비 → 기지·제작 투자 → 더 먼 탐험**이다. 현재 프로젝트에 이미 존재하는 채굴, 배치, 인벤토리, 제작, 상자·화로, 안전 입구 복귀는 이 루프의 재사용 가능한 기반이다.

## S01: 생존 샌드박스와 디버그 워크벤치

### 의도와 범위

첫 반복은 밸런스가 아니라 관찰 가능한 상태 모델을 만드는 것이다. `SurvivalState`는 0–100의 체력·허기·보온과 120초 낮/60초 밤 시계를 0.25초 고정 스텝으로 갱신한다. 밤은 보온을 더 빨리 소모하고, 허기 또는 보온이 0이면 체력이 줄어든다.

고정 스텝의 목적은 프레임률 차이 때문에 같은 시간 경과가 다른 결과를 내지 않게 하는 것이다. 값은 임시 제안값이며 실제 플레이테스트 전에는 재미나 난이도를 주장하지 않는다.

| 항목 | S01 제안값 | 목적 |
|---|---:|---|
| 낮/밤 | 120초 / 60초 | 짧은 개발 반복에서 귀환 압박을 관찰 |
| 갱신 | 0.25초 | 결정성·낮은 UI 갱신 빈도 |
| 낮 허기 감소 | 초당 0.045 | 장기 탐험 비용의 기준점 |
| 밤 허기 감소 | 초당 0.075 | 야간 지연에 작은 추가 비용 |
| 낮/밤 보온 감소 | 초당 0.012 / 0.22 | 밤을 명확한 안전·불빛 설계 대상으로 만듦 |
| 0 허기/보온 피해 | 초당 0.18 / 0.32 | 실패 경고를 위한 가시적 변화 |

### 의도적으로 제외한 것

- 식품 아이템, 모닥불·침대·날씨, 적 AI, 전투, 사망·리스폰, 멀티플레이 권위
- S01 생존 상태의 저장/복원. 현 저장 포맷 v7 계약을 바꾸지 않는다.
- 건축물의 내구도·적 경로 차단·보호 반경. 블록 설치 자체는 기존 구현을 사용한다.

이 제외 항목은 미구현을 감추기 위한 것이 아니라, 먼저 생존 압박과 회복 수치를 빠르게 실험하기 위한 경계다.

## 수동 테스트·디버그 워크벤치

디버그 빌드에서 `F4`를 누르면 **SURVIVAL DEBUG WORKBENCH**가 열린다. 열려 있는 동안 플레이어 조작을 잠그고 마우스를 해제하며, 닫으면 조작과 포인터를 복원한다. HUD는 현재 DAY/NIGHT, HP, Hunger, Warmth를 표시한다.

| 기능 | 수동 조작 | 자동 검증 |
|---|---|---|
| 생존 속성 편집 | SpinBox로 HP/Hunger/Warmth 설정 후 Apply | 경계값 0–100 clamp |
| 시계·시뮬레이션 | Set DAY, Set NIGHT, Advance 60s, Reset | 밤 보온 감소, 음수 시간 거부 |
| 채집/건축 준비 | Item ID·수량 지급, Fill/Clear selected | 인벤토리 용량·알 수 없는 ID 거부 |
| 월드 디버그 | Safe return, Save, Load, Profile | 기존 월드 함수 직접 호출 |
| 시각화 | Performance HUD, voxel axes | 기존 HUD/축 상태 전환 |
| 명령어 | `help`, `set hunger 40`, `night`, `advance 60`, `give 10 8` | 알 수 없는 명령 거부 |

개발 치트는 Builder 채굴·배치 카운터를 증가시키지 않는다. 배포 빌드에서는 워크벤치가 열리지 않는다.

## 테스트 케이스와 성능 지표

### 자동 테스트

- `tests/test_runner.gd`: 생존 초기 상태, 낮/밤 소모, 0값 피해, 범위 clamp, 음수 시간 거부, 리셋을 검사한다.
- `tools/survival_debug_smoke.gd`: 실제 Main 씬에서 워크벤치 열기/닫기, 속성 명령, 시간 진행, 아이템 지급·거부, Fill/Clear, 성능 HUD/축 시각화, 알 수 없는 명령 거부를 검사한다.
- `Verify.ps1`: `survival-debug`, `survival-benchmark` 단계를 전체 회귀에 포함한다.

### 이번 실행 결과

- 2026-09-11: 단위 테스트 **57개 단언 통과**.
- 2026-09-11: 헤드리스 및 실제 렌더 런타임에서 `SURVIVAL DEBUG SMOKE: 14 assertions, 0 failures`.
- 2026-09-11: 최신 `benchmark_survival.gd` 실행에서 1,200초/4,800 스텝을 9회 시뮬레이션: 평균 **3,343.2µs**, P95 **4,091µs**. 초기 실행의 P95 7,176µs도 기록했으며, 짧은 CPU 마이크로벤치의 변동성을 보여 준다.

이 성능 수치는 생존 상태만의 CPU 마이크로벤치이며, 실제 게임 프레임·HUD·AI·날씨 또는 최저 사양 PC 성능을 대표하지 않는다. S02부터는 실제 장면에서 HUD 갱신, 화톳불 반경, 다수 배치물을 함께 계측한다.

## 리뷰와 다음 반복 결정

### S01 판정

**구현·자동 검증 완료, 플레이 밸런스 미검증.** 상태 모델과 디버그 루프는 작동하지만, 현재는 회복 행동이 없으므로 생존 게임으로서의 재미·공정성·난이도를 주장할 근거가 없다.

### S02 제안: 화톳불과 회복/위험의 첫 연결

1. `Campfire`를 별도 스테이션으로 추가하고 연료·점화·반경을 저장 계약 v8에 명시한다.
2. 반경 안에서 보온 회복, 밤 조도/안전 피드백을 적용한다. 적 AI는 계속 제외한다.
3. 나무·석탄·음식 후보의 수집량과 화톳불 연료 소모를 5/10/15분 시나리오에서 계측한다.
4. 건축물은 ‘벽’보다 먼저 안전 반경 내 배치·접근성·저장/복원을 검증한다.
5. S02 종료 전 최소 3명의 내부 수동 플레이테스트로 귀환 시점, 혼란, 막힘, 편법을 기록한다. 그 전에는 수치 조정을 완료로 부르지 않는다.

## 운영 명령

```powershell
.\RunTests.bat
.\RunGame.bat # 게임 실행 후 F4
.\Verify.ps1 -SkipCapture
```

게임 실행 중에는 `F4`를 누르고 `help`를 입력해 지원 명령을 확인한다. 실제 렌더 검증은 프로젝트 루트의 Godot 콘솔 실행기에서 `tools/survival_debug_smoke.gd`를 실행해 재현할 수 있다.
