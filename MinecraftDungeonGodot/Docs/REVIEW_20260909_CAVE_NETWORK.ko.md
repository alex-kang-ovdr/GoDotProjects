# 보호 동굴 탐험망 — 구현·검증 기록

## 판정과 비교 범위

Unreal 대비 최종 우위는 아직 미달이다. 이번 루프는 기존 입구 계단/전실 하나를 깊은 중앙 방과 네 갈래 탐험 구역으로 확장한다. `Saved/Verification/20260909-003207-293`의 `Verify.ps1 -RenderComparison`은 종료 코드 0, 전체 42개 엔진 단계 완료다. 이번 편집 화면 반영 P95 8.002ms는 단일 실행 목표를 충족했지만 이전 약 17ms와 표시 조건 차이를 아직 분리하지 못했으므로 안정화 완료로 판정하지 않는다.

Unreal 원본 `Source/MinecraftDungeonExample/Private/Tests/VoxelWorldTests.cpp`의 `MinecraftDungeon.Overworld.CavesConnectedAndReachable`는 `Layout.CaveCells`만 입구에서 6방향으로 flood fill한다. Cheese/Spaghetti/Ravine 자연 공동 전체가 아니라 보호 터널/방의 연결 계약이다. `Private/VoxelWorldLayout.cpp`의 중앙 계단·허브·네 분기와 방을 참고했으며 원본 파일은 변경하지 않았다. 모든 자연 공동 연결을 원본보다 강한 필수 동등성 조건으로 오인하지 않는다.

Godot 방은 중앙 반경 2/말단 반경 3의 모서리를 깎은 형태이며 Unreal의 반경 6 방과 크기·형상이 같지 않다. 연결된 탐험 구역을 추가한 것이고 정확한 기하 동등성이나 전체 M03 완료는 아니다.

## 구현

`CaveNetwork`는 기존 17개 계단 중심 경로와 전실을 보존한 뒤, 별도 내리막 접근로를 통해 Y=4 중앙 방으로 연결한다. 평평한 네 분기는 서쪽/동쪽/북쪽/남쪽 방까지 이어진다. 큰 월드에서는 분기가 최대 35블록으로 늘어나며 남쪽은 상부 내리막을 피하도록 우회한다. 세로 접근로와 가로 터널이 같은 X/Z에서 서로의 바닥을 막지 않도록 중심 열의 발 높이를 먼저 계획한다. 계획 오류 시 입력 셀/보호 공기를 부분 수정하지 않는다.

통로는 기본 3칸 폭/3칸 여유, 방은 4–5칸 여유이며 내리막 코너의 전 구간 3칸 폭을 보장하지 않는다. 말단 방 바닥 테두리는 이끼·조약돌·벽돌·판자로 구분한다. 전투·보상·미니맵·발견 UI는 아직 없다.

보호 공기와 바닥은 후속 랜드마크 연결로에서 유지한다. 나무의 수관, 건물 5×5 바닥뿐 아니라 문 앞 3·4번째 열도 보호 천장과 겹치지 않게 후보를 걸러낸다. 시드 -7의 초기 구현에서는 건물 진입로가 `(14,31,9)` 보호 공기를 덮었고, 이 추가 조건으로 수정했다. 기존 자연 공동 전체를 인공 바닥으로 채우거나 별도 연결 계약으로 바꾸지 않는다.

최종 셀 검사는 스폰→6개 랜드마크 문 및 5개 동굴 방의 지지 바닥·몸 공간·점프 여유를 포함한 보행 그래프, 방 바닥 재질 보존, 보호 공기 비점유 및 입구와의 6방향 연결을 함께 확인한다. 생성 경로 metadata만으로 통과시키지 않는다.

## 검증과 발견한 실패

- `Saved/Verification/cave-network-prototype/data3.log`: 124개 크기/고도 조합과 8개 실제 월드, 독립 전체 셀 해시/보호 공기 DFS 및 오류 주입 522개 단언 통과. 이후 분기/길이 상한의 크기 경계 109/111/173/175와 고립 공기·바닥 재질·실패 시 무변경 검사를 추가했다.
- 같은 폴더 `walk.log`: 1337/41, -7/41, int32 최대/41, 1337/185에서 실제 W/Space로 원래 계단→내리막→각 방 왕복→지상 복귀 57개 단언 통과. fixture 시작 위치 설정 외에는 순간이동하지 않고, 편집 저널이 비어 있는지도 검사한다. 기능 검사만 시간 배율 8/physics ticks 480을 사용하며 dt=1/60초다. 성능 지표로 쓰지 않는다.
- `matrix.log`의 시드 -7 진입로 충돌은 실패 기록으로 보존했다. 수정 후 `matrix2.log`는 128시드 통과(병행 테스트 실행 중 43.712초, 단독 성능 수치가 아님).
- `20260909-002945-170` 첫 전체 실행은 `landmark-data`의 오류 문구 일치 검사에서 중단됐다. 실질적인 도달 불가 오류는 발생했으나 동굴 방을 추가한 새 문구와 과거 문자열이 달랐다. 오류 주입 검사를 제거하지 않고 새 명시 메시지로 갱신했다.
- 초기 프로토타입은 Variant 유래 `shoulder`의 타입 추론 오류가 있어 Vector3i를 명시했다. 해당 실패 로그/종료도 보존했다.

## 전체 회귀와 렌더 계측

최종 전체 실행에서 새 동굴 데이터 1,021개, 실제 왕복 57/61개(헤드리스/렌더), 단위 48·기후 99·랜드마크 데이터 118·저장 74·메시 502·캐시 1,005·정리 수명 25·최적화 동등성 534개가 통과했다. 랜드마크 왕복 41/42, Builder 53/72, 웅크리기 24/25, 생성 조작 40/49, Dungeon 408/32, 조준/CLI 48/50, 조명 41개도 통과했다. 오류 로그는 없으며 `launch-invalid` exit 2는 의도한 거부다.

Overworld 128시드 행렬은 33.813초, Dungeon 128+경계는 2.140초다. 별도 OS 쓰기/읽기 PID 31516/71464(Overworld), 67444/69788(Dungeon)에서 각각 1,000편집·인벤토리·자세·위치/시점·생성 설정을 복원했다. 185맵 생성 단독 3시드는 3.576–4.272초이며 시드 1337은 3.656초다.

같은 v6 185/1337·게임 조명/그림자·64경계 편집의 내부 렌더 비교는 청크 준비 **7.853초/639.17MiB**, GridMap **49.349초/1,131.38MiB**다. 준비 약 84.1%, 최대 작업 집합 약 43.5% 감소는 Godot 내부 비교이지 Unreal 비교가 아니다. 청크 434개, 253,339단위면→89,764쿼드이며 편집은 최대 2청크를 갱신했다. 편집 CPU P95 2.950ms, 다음 frame_post_draw P95 **8.002ms**다. GridMap 화면 반영은 26.860ms이며 deferred 작업이므로 CPU submit 0.006ms와 청크 전체 갱신 비용을 직접 비교하지 않는다.

모든 편집 focus 표본은 true/VSync mode 1이지만 벤치마크는 창의 실제 화면 번호·주사율을 아직 기록하지 않는다. 이번 실행 후 Win32_VideoController 조회는 Intel UHD 출력 2560×1600/165Hz와 RTX 4070 출력 3840×2160/60Hz를 함께 보고했다. 어떤 출력에 해당 창이 있었는지, 이것이 과거 지연 변동의 원인인지까지 증명한 것은 아니다. 다음 루프는 화면 번호·주사율·창 위치를 명시/기록한 반복 측정이다. 단일 8.002ms만 선택해 기존 약 17ms 미달을 해결했다고 선언하지 않는다.

255 Overworld 비동기 교체는 19.931초/P95 1.411ms/최대 20.249ms다. `controls-input` 최대 메모리 1,167.54MiB에는 진단 trace 16,033프레임과 두 월드 교체가 포함된다. 이전 23.864초/P95 17.022ms와 표시 간격 양상이 달라 생성 코드 개선으로 단정하지 않는다. 255 Dungeon은 1.056초이며 다른 콘텐츠라 Overworld 성능과 섞지 않는다.

네 방의 outward PNG를 직접 확인했다. HUD/조준 윤곽은 정상이고 깊은 방도 어둠에 묻히지 않는다. 다만 조약돌/돌벽돌 방의 색 차이는 약하며, 벽을 향한 시점만으로 출입구와 길 찾기 품질을 판단할 수 없어 복귀 방향/바닥을 보는 추가 캡처를 넣었다. 밝기·이동 통과는 탐험 미감·안내 완료가 아니다.

추가 캡처 후 동일 네 월드를 다시 실제 왕복한 `cave-return-views.log`는 종료 코드 0/65개 단언 통과다. `cave-return-views/`의 네 복귀 방향 PNG도 직접 검토했다. 이끼/판자 링은 쉽게 보이고 돌벽돌 무늬는 가까이서 구분되지만 먼 거리 방향 표지는 없다. 일부 통로의 밝은 직사광 패치는 다음 조명 검토에서 지표 개구부와 그림자 동작을 대조할 항목이다. 시점만 추가했으며 런타임 지형/플레이 코드는 전체 실행 이후 변경하지 않았다. 현재 Verify의 렌더 동굴 단계는 이 65개 검사를 실행한다.

## 생성 버전과 이전 저장

저장 포맷은 2, 전역 생성 버전은 **6**이다. 독립 정렬 기준 해시를 대조한 뒤 테스트 골든을 갱신했다. 시드 1337은 41맵 47,146셀/2029358965, 185맵 1,062,829셀/392942167, 255맵 2,068,749셀/546771480이다. Dungeon 셀 알고리즘은 바꾸지 않았으나 전역 정책상 버전 5 이하 저장은 두 모드 모두 거부한다. 사용자 저장을 삭제하거나 자동 변환하지 않았다.

변경 전에 `Saved/GenerationArchives/voxel-frontier-v5-runtime.zip`에 v5 `scripts/`, `scenes/`, `project.godot`을 보관했다. SHA-256은 `4FF53B00931F9208842F5D4DE02105F1A2A46A96B55087674757ED9452397617`이다. `.godot`·엔진 실행 파일·사용자 저장은 포함하지 않는다. 사용하지 않는 초기 CaveNetwork 스크립트가 포함됐지만 v5 생성기는 호출하지 않는다.

별도 `Saved/Verification/archive-v5-check`에 압축을 풀어 Godot 4.7.2로 import한 뒤 외부 `tools/archive_v5_smoke.gd`를 실행했다. import/test 모두 종료 코드 0, 게임 씬·v5 48,493셀/805642358·편집 없음·생성 1회를 확인했다. 이 도구는 사용자 체크포인트를 읽거나 쓰지 않는다. 오래된 저장을 이용하려면 아카이브를 별도 폴더에 풀고 동일 엔진으로 열어 저장 당시 설정을 생성해야 한다. 새 버전에서 저장하면 기본 저장 경로가 같으므로 이전 파일을 별도로 복사해 보존하는 것이 필요하다. 기존 저장의 실제 로드/마이그레이션 시험까지 수행했다고 주장하지 않는다.

## 남은 게이트

자연 공동의 모든 셀 보행 가능성, 방 크기/다양성·길 찾기·보상, 기후 코어 고도·나무 지지·구조물/연결로 시각 품질, 전체 프레임 지연, 같은 콘텐츠/계측 범위의 Unreal 비교는 여전히 남아 있다. v5의 캐시 A/B/정리 프로파일은 당시 기록이고 v6 성능 증거로 자동 승계하지 않는다.
