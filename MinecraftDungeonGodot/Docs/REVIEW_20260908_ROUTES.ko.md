# 자체 검토 — 스폰에서 랜드마크까지 연결

## 발견한 결함

기존 검증은 스폰·문 주변의 지지 바닥과 빈 공간만 검사했다. 최종 셀의 보행 그래프를 조사하자 버전 4 기본 시드 1337/41은 6개 랜드마크 중 3개, int32 양끝은 각각 2개만 연결됐다. -7/42는 모두 연결돼 있었다. 기준 로그는 `Saved/Verification/landmark-baseline/audit.log`다. 열린 출입구는 전역 접근성의 증거가 아니다.

## 독립 구현과 보존 경계

`VoxelTraversal`은 최종 셀만 읽어 발 위치의 고체 지지·두 칸 몸 공간·4방향 이동·최대 1블록 단차를 검사한다. 높이 차가 있으면 낮은 쪽에 추가 한 칸 머리 공간이 필요하다. 양방향으로 가능한 보수적인 보행/점프 그래프이며 비행·채굴·설치·긴 공중 점프는 허용하지 않는다. 지하를 지나갈 수도 있으므로 모든 경로가 지표면에만 있다는 뜻은 아니다.

`LandmarkRoutes`는 연결되지 않은 문의 바깥 접근 지점에서 이미 스폰과 연결된 영역까지 비용 기반 탐색으로 연결로를 만든다. 기존 지형 고도에서 벗어나는 정도, 제거할 블록과 새 바닥 비용을 반영한다. 동률은 고정 이웃 순서와 삽입 순번으로 결정한다. 전체 경로 길이의 수학적 최적성이나 모든 가능한 설정에 대한 성공을 주장하지 않는다.

수정 가능한 바닥은 조약돌로 만들고 세 칸 머리 공간을 확보한다. 안전한 곳은 양옆을 넓히지만 급한 굽이/문 주변은 한 칸 길로 남을 수 있다. 지형을 깎는 통로나 협곡 위 연결 바닥이 생길 수 있으며 자연스러운 교량/옹벽 외형은 후속 시각 작업이다. 이미 연결된 월드에는 새 길을 추가하지 않는다.

건물 footprint 전체·문 앞 두 칸·보호 동굴 공기/바닥·샘과 그 위 열린 열은 고정한다. 기존 성공한 경로와 새 연결 지점→스폰 경로도 고정하며 단차의 점프 공간까지 포함한다. 연결 지점의 원래 접근 경로를 새 길이 침범하면 이를 고정한 뒤 다시 탐색한다. 연결로 자신이 같은 X/Z를 다른 높이로 돌아와 통로를 막지 않도록 조상 경로 검사를 한다. 최종 셀에 맞게 동굴/광맥 metadata를 정리한 뒤 높이맵과 해시를 계산한다. `timings.routes_us`로 추가 비용을 분리한다.

`WorldLayoutValidator`는 저장된 생성 경로를 정답으로 삼지 않고 최종 셀에서 다시 모든 문까지의 연결을 검사한다. 접근성은 생성 시점의 계약이며 플레이어가 이후 길을 파괴하면 그대로 변경된다. 런타임 자동 수리나 순간이동으로 테스트를 통과시키지 않는다.

## 실패·수정 기록

- 처음 정적 함수 이름을 Object의 `connect`와 충돌시켜 파싱 실패했다. `build`로 바꿨다.
- 문 자체에 3칸 여유를 요구하니 보존해야 할 2칸 높이 문틀 때문에 탐색할 수 없었다. 문/지붕은 유지하고 열린 접근 지점에 연결했다.
- 월드 가장자리의 합법적인 접근 지점을 탐색 범위에서 제외한 off-by-one을 수정했다.
- 128시드 검사에서 9개 시드의 경로가 자신의 다른 높이 구간을 막았다. X/Z 재방문을 막고 자체 바닥/공기 충돌도 사전 검사한다.
- 최초 스폰까지의 전체 길 생성은 185맵 3.333초/255맵 4.731초의 경로 비용이 들었다. 가까운 기존 연결 영역에 이어 붙이도록 바꿨다.
- 최적화 과정에서 기존 점프 공간이나 연결 지점의 원래 접근 경로가 가로 확장에 의해 막혔다. 점프 여유와 연결 지점→스폰 경로를 함께 보존하도록 수정했다. 전체 연결 영역을 무조건 고정하는 실험은 필요한 절개까지 막아 시드 -48이 실패했으므로 채택하지 않았다.
- 새 데이터 테스트의 `_expect` 보조 함수 누락도 파싱 검사에서 발견해 수정했다. 테스트 로그의 도달 수는 기대값 6을 찍지 않고 독립 그래프에서 실제 센 값으로 출력한다.

위 진단 로그는 `Saved/Verification/landmark-baseline`에 남겼다. 중간 구현의 해시·성능·통과 결과를 최종 버전 근거로 대신 쓰지 않는다.

## 검증 설계

`tools/landmark_data.gd`는 모든 고체 셀에서 가능한 지지 표면을 먼저 열거하고 별도 DFS 그래프를 만든다. 생성기의 경로 metadata나 runtime BFS를 정답으로 쓰지 않는다. 기본/회귀/극단 시드, 185/255맵, 모든 지붕 보존, 기준 정렬 해시와 결정론을 확인한다. 고립된 문·벽을 연 경우·대각 접촉·문 봉쇄 오류 주입도 검사한다.

`tools/landmark_smoke.gd`는 1337/-48/int32 최대 시드의 모든 6개 문까지 실제 CharacterBody3D W/Space 입력으로 왕복한다. 각 시드 시작 외에는 위치를 쓰지 않고, 왕복 중에는 순간이동·채굴·설치가 없다. 일반 60Hz 중간 구현도 36회 편도 이동/40개 단언을 통과했다(`walk.log`). 최신 전체 러너는 시간 배율 8/physics ticks 480으로 벽시계 시간을 줄이되 각 시뮬레이션 dt=1/60초임을 단언한다. 렌더 실행에서도 같은 물리 이동과 도착 PNG를 검사한다. 이는 플레이 성능 계측이 아니며 별도 렌더 비교는 기본 엔진 타이밍을 쓴다.

## 저장 호환 경계

생성 결과가 바뀌어 전역 생성 버전은 5, 저장 포맷은 2다. 버전 4 이하 저장은 Dungeon도 자동 변환 없이 거부하며 파일을 삭제하지 않는다. 같은 시드·크기·기본 해시를 제공해도 이전 생성 버전은 적용하지 않는 검사를 유지한다. 새 골든은 독립 최종 높이/연결 그래프/기준 정렬 해시 검토 후 갱신한다.

## 최종 실행 결과

전체 `Verify.ps1 -RenderComparison` 실행 `Saved/Verification/20260908-224549-629`는 종료 코드 0으로 완료했다. 예상한 `launch-invalid`의 exit 2 외 모든 계측 단계가 0이다. 신규 데이터 118개·랜드마크 왕복 41/42개(헤드리스/렌더), 기존 단위 48·기후 99·저장 74·메시 502·최적화 동등성 534개, Builder 53/72·웅크리기 24/25·생성 조작 36/44·Dungeon 408/32·조준/CLI 48/50개를 통과했다. Overworld 128시드 행렬 38.906초, Dungeon 128시드+경계 2.313초, 보호 동굴 왕복도 통과했다.

별도 저장 쓰기/읽기 PID는 78232/59168(Overworld), 42308/10000(Dungeon)이며 각각 1,000편집·플레이어/자세·인벤토리·진행도·옵션을 복원했다. 최신 랜드마크 이동 단계는 58.578초(헤드리스), 72.784초(렌더)다. 두 실행 모두 3시드×6문×왕복을 통과하고 시뮬레이션 dt를 확인했다. 입력 전달은 렌더 프레임 묶음의 영향을 받으므로 가속 전후의 걸린 물리 프레임 수가 동일하다고 주장하지 않는다.

v5 시드 1337은 41맵 48,493셀/해시 805642358, 185맵 1,065,190셀/1937405161, 255맵 2,071,110셀/575395598이다. 독립 데이터 검사의 연결로 비용은 185맵 506.674ms, 255맵 1,749.101ms다. 기본/회귀/극단/185/255의 독립 그래프가 모든 문에 도달했다. 같은 41맵이라도 이미 연결된 -7/42 시드는 셀/해시 변경이 없다.

185맵 3시드 생성 단독은 4.304–5.234초로 이전 v4의 3.182–3.187초보다 느리다. 최신 청크 렌더 준비 8.264296초/OS 최대 작업 집합 522.8671875MiB, 동일 GridMap 51.839149초/1,131.36328125MiB다. 내부 준비 시간 약 84.1%, 메모리 약 53.8% 감소다. 434청크/250,395단위면→89,347쿼드이며 편집당 갱신 최대 2청크를 유지했다. 생성 버전이 달라 v4와 출력 동등 최적화 비교로 취급하지 않는다.

경계 64편집 CPU P95는 11.809ms, 화면 반영 P95는 **16.799ms로 16.7ms 게이트 미달**이다. 같은 GridMap의 화면 반영 P95는 26.911ms다. 청크 원시 화면 반영 샘플 대부분은 16.6ms 부근이며 VSync 1이다. 화면 동기화와 CPU 변동의 영향을 더 조사해야 하고 원인을 확정하지 않는다. 이전 v4의 좋은 11.148ms를 현재 통과 근거로 쓰지 않는다. `Verify.ps1` 성공은 정확성 검사와 계측 완료이지 모든 성능 게이트 달성을 뜻하지 않는다.

최대 255 Overworld 실제 렌더 교체는 24.114초, 생성 루프 간격 P95 16.969ms/최대 45.223ms다. 이전 17.771초보다 느리며 이 역시 기록한다. Dungeon 255는 1,899.25ms다. 이 생성 루프 지표와 185맵 단일 편집 지표를 섞지 않는다.

## 실제 화면과 다음 게이트

실제 도착 `landmark-arrival.png`, 기본 `runtime.png`, 보호 동굴 `cave.png`를 직접 검토했다. HUD/조준 윤곽은 읽히고 실내로 도달했지만 설원은 과도하게 밝으며 건물 내부는 단조롭다. 별도 `tools/capture_routes.gd`로 생성한 `landmark-route-overview.png`와 `landmark-route-interior.png`도 확인했다. 연결 바닥은 구분되지만 난간/교각·표지 같은 자연스러운 안내와 외형이 부족하다.

첫 별도 카메라가 지형에 가려진 결과(`landmark-route.png`)를 남기고, 월드 최고 높이 위 전경과 실제 경로 눈높이 두 시점으로 보정했다. 보정 도구의 PackedInt32Array `max()` 오용은 런타임 오류로 발견해 명시적 높이 순회로 수정했다. 실패한 캡처 프로세스만 확인 후 종료했으며, 최종 별도 실행은 `route-reviewed-capture.log`의 error 0/종료 코드 0이다. 게임 코드나 전체 테스트 결과를 바꾸지 않는 캡처 보정이다.

현재 전체 판정은 계속 미달이다. 자연 동굴 전체 연결, 기후 코어의 고도 일관성, 조명/구조물/길 찾기, 생성 준비 비용과 편집 응답성 안정화, 동일 기능·동일 계측의 Unreal 비교를 다음 루프로 이어간다. 임의 시드 전체와 185/255의 모든 길을 실제 캐릭터로 왕복했다는 주장은 하지 않는다. Unreal 작업트리와 기존 프로젝트는 수정하지 않았다.
