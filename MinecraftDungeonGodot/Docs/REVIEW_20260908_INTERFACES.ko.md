# 조준 좌표축·생성 CLI 자체 검토

기준일: 2026-09-08. M01 인터페이스 격차를 줄이는 루프이며 전체 Unreal 우위 판정은 아니다.

## 구현 경계

`TargetIndicator`는 실제 플레이어 카메라의 6m 충돌 광선으로 선택한 블록에 기본 흰색 윤곽을 표시한다. Alt+2는 청록색 강조 박스와 0.8m 길이 XYZ 축으로 전환한다. Godot은 X 빨강·Y 초록(위)·Z 파랑이며 Unreal Z-up과 구분한다. 비충돌 메시 두 개를 한 번 만들고 위치/표시만 갱신한다. 매 프레임 복잡한 지형을 다시 만들지 않는 작은 도형 용도로 [ImmediateMesh 공식 문서](https://docs.godotengine.org/en/4.7/classes/class_immediatemesh.html)를 참고했다. 기본 윤곽은 일반 플레이에도 제공하고 개발 좌표축 토글만 개발 빌드로 제한한다.

광선은 플레이어 이동 뒤에 갱신하도록 물리 우선순위를 정했다. 순서는 트리 위치가 아니라 [Node의 process_physics_priority 규칙](https://docs.godotengine.org/en/4.5/classes/class_node.html#class-node-property-process-physics-priority)에 따른다. 메시에는 충돌체가 없고 그림자를 만들지 않으며 선택 블록의 전체 윤곽이 보이도록 깊이 검사를 끈다. 이것은 실제 벽 투시 탐지 기능이 아니라 이미 광선으로 선택된 블록의 표시다. 패널·생성·불러오기 중, 조준 실패·블록 삭제 시 표시를 지운다. 월드 교체 후에도 같은 표시 노드가 새 청크 충돌을 따른다.

`LaunchOptions`는 네이티브 모드/시드/크기/방 시도/Checks/POI와 공유 Unreal 형식 플래그를 파싱한다. 사용자 인수는 [OS.get_cmdline_user_args 공식 문서](https://docs.godotengine.org/en/stable/classes/class_os.html?highlight=OS+execute)에 따라 엔진 인수 뒤 `--` 이후만 사용한다. `RunGame.bat`은 구분자와 인수를 전달한다. main이 노드를 만들기 전에 유효성을 확인하고 첫 VoxelWorld의 설정으로 넣으므로 기본 월드를 먼저 생성하는 중복 작업이 없다.

인수 없는 Overworld 41/1337/검사 OFF는 기존 동작이다. 명시적 생성 옵션은 검사 ON, 모드별 기본 크기 Overworld 185/Dungeon 41이다. 방 시도는 1–512, 시드는 signed int32, 크기는 모드별 41/11–255이며 짝수만 다음 홀수로 정규화한다. 범위/타입/중복/모순은 실행 전에 종료 코드 2로 거부한다. 이 오류 처리는 Unreal의 clamp 정책과 다르다. 다른 테스트 러너 인수는 무시하며 생성 옵션 오타까지 자동으로 추론하지 않는다. 시작 생성은 동기식으로 남아 있고 플레이 중 교체만 비동기식이다. 직사각형 던전 API는 여전히 이식하지 않았다.

## 실패와 수정

- 첫 실행 `Saved/Verification/20260908-215335-299`은 launch_smoke의 Dictionary 값 비교에서 bool 형식을 추론하지 못했다. 테스트 변수를 명시적 bool로 고쳤다. 파싱 오류가 exit 0으로 숨지 않고 검증을 멈췄다.
- 다음 실행 `20260908-215353-973`의 헤드리스 조준 검사는 통과했지만 렌더 검사에서 축 픽셀 수가 모두 0이었다. 캡처와 실제 광선을 확인하니 테스트 카메라만 look_at으로 향하게 하고 pitch 상태는 그대로 둔 상황에서 호스트 커서 재중앙화 이벤트가 pitch를 다시 적용해 조준이 빗나갔다. Alt+2 자체는 활성화되어 있었다.
- 키보드/표시 픽스처는 커서를 visible로 두어 호스트 마우스 입력을 분리하고 카메라 pitch도 동기화했다. 사용자 카메라 처리를 꺼서 전체 게임 테스트를 통과시킨 것이 아니라 해당 픽스처의 외부 입력만 고정했다. 기존 렌더 창 마우스 채굴/설치 검사는 계속 별도로 실행한다.
- 코드 검토에서 조준 갱신이 트리 순서상 플레이어보다 먼저 실행될 수 있음을 확인해 물리 우선순위를 플레이어 이후로 지정했다.
- 전체 통과 후 accepted option을 다시 점검하면서 Overworld 시작의 RoomAttempts가 현재 지형에는 쓰이지 않더라도 UI 초안에는 보존돼야 함을 확인했다. 초기 설정을 초안에 복사하고 새 프로세스의 Overworld CLI 검증에 `-RoomAttempts=34`를 추가했다. 이후 모드 전환에서 사용자의 명시 입력이 24로 되돌아가지 않는다.

## 검증 범위

파서와 조준 인터페이스를 `tools/interface_smoke.gd`에서 검사한다. 정상/최대·최소/음수 입력, 중복·모순·범위·타입 오류, 기본 시작 보존, 음수/청크 경계 대상, 기본/개발 표시 전환, 슬롯/저널/플레이어 비변경, 광선 비간섭, 메시 재사용, 패널·로드·생성 잠금, 빗나감·채굴·던전 교체 후 대상 갱신을 포함한다. 실제 PNG 중앙 영역의 빨강/초록/파랑/청록 픽셀도 세어 노드 visible 플래그만으로 렌더 성공을 주장하지 않는다.

`launch-native`와 `launch-legacy`는 새 OS 프로세스에서 main 씬을 생성해 첫 월드 모드/시드/크기/옵션·생성 횟수 1·POI·검사 상태·물리 착지를 확인한다. `launch-invalid`는 실제 일반 게임 시작 경로에 잘못된 시드를 전달하며 종료 코드 2와 거부 메시지를 성공 조건으로 사용한다. 이 단계의 비영 종료는 예상된 입력 거부이지 전체 검증 실패가 아니다.

## 남은 게이트

좌표축과 지원 생성 CLI가 연결됐어도 M03 기후 판정·해저 높이맵·자연 동굴 연결/전역 구조물 접근성은 남는다. 설원 과노출·구조물 외형·출구 표식의 시각 품질도 후속 대상이다. 기존 화면 반영 편집 P95 16.948ms 미달은 이번 기능 검사로 해결됐다고 주장하지 않는다. 조준 메시 재사용은 할당 회귀 근거이지 새 성능 우위 계측이 아니다.
