# Godot 마일스톤 계획

Unreal 프로젝트의 의존 순서와 종료 기준을 공유하되 각 마일스톤은 Godot 증거로 독립 완료한다.

- M00/M01 (`구현, 검증 중`): 프로젝트 부트스트랩, 12블록 레지스트리, 9슬롯 인벤토리, 이동·채굴·배치·HUD, Builder 8/4·R 안전 복귀·개발 단축키·웅크리기. Builder 53/72검사, 낮은 통로/천장/30·60·120Hz 가장자리/저장 자세 24/25검사 통과. 생성 패널과 비동기 교체·255맵을 40/49검사로 검증. 연결 던전·모드별 저장 데이터 408/렌더 32검사와 새 프로세스 1,000편집 복원 통과. 기본 윤곽·Alt+2와 지원 생성 CLI를 48/50검사 및 새 프로세스 시작/거부 검사로 추가 검증. 직사각형 하위 API·CLI 기본값/오류 정책 차이는 남음
- M02 (`구현 중`): 청크 인덱스·희소 편집/방향 상태·경계 dirty·greedy 메시/충돌·평면 geometry 캐시·일괄 복원·비동기 I/O와 월드 데이터/노드 분리 정리 구현. 정리 수명 25·캐시 1,005·메시 502·동등성 534검사와 OS 재시작 복원 유지. 출력 조건 21·첫 viewport 픽셀 40검사, 24회 화면 고정/FPS 상한/VSync 대조 유지. 무제한 ON의 viewport P95 16.772–17.069ms는 반복 미달. 최신 단일 준비 8.226초/653.875MiB/CPU 2.940ms/viewport 6.048ms는 짧은 유휴 간격을 보여 완료 근거로 쓰지 않음. viewport 신호를 physical presentation으로 표현하지 않는다. 이번 255맵 교체 최대 119.668ms/COMPUTING은 원인 미확정이며 이전 91.373ms의 해결도 뜻하지 않는다. native 창/OS present 경로·초기 준비/상주 메모리·비정상 종료/정전 복구는 후속이며 전체 실행 59개 단계 통과
- M03 (`구현 중`): 독립 기후 6축·고지 돌·최종 높이맵·자연 공동/협곡/광맥/샘·랜드마크 접근로에 더해 보호 중앙 방+네 갈래 동굴 탐험망 구현. 128시드·기후 99·랜드마크 그래프 118·동굴 데이터 1,021개와 실제 이동 회귀를 유지한다. 다음은 공식 레이어드 생성 조사에 따른 M03.2 지형-생물군 일관성, M03.3 지하 생물군, M03.4 구조물/피처 예약이며 완료 계약은 `PROCEDURAL_WORLDGEN_PLAN.ko.md`에 기록한다.
- M04 (`핵심 구현·검증, 품질 개선 중`): 실제 LMB 유지/해제·대상/도구/패널 변경 취소, 종류·등급·내구도, 물리 드롭/지연 줍기/가득 찬 인벤토리 보존에 24가지 설치 방향·통나무 단면/옆면·이웃 갱신/영속 복원·10단계 3D 균열을 추가했다. 방향 도입 시 저장 v4(현재 M05 v6)/생성 v6이며 포맷 2/3은 방향을 초기화하고 v3 도구/드롭을 유지한다. 채굴 294/360(120개 도구×블록 조합 포함), 방향 878/900, 실제 물리 아이템 10,000개/변경 콜백 10,189회 보존 525개, 두 모드 새 OS 프로세스 복원을 통과했다. 설치 콜백 중 저장의 소비 전용 결함도 수정·복원 검증했다. 2,048드롭 검사는 짧은 수량/용량 검사이지 장시간 FPS 보장이 아니며 초기 도구 9개는 프리뷰로 남아 있다. 큰 채굴 HUD의 대상 가림 등 시각/게임 품질 개선은 유지한다. 상세 근거는 `REVIEW_20260909_MINING.ko.md`, `REVIEW_20260909_ORIENTATION.ko.md`
- M05 (`완료 기록`): 36슬롯·커서, 개별 내구도 도구/4장비, 14개 제작, 셀 결합 상자 27칸·화로 20Hz(철 원석 200틱/석탄 1,600틱), 광석 고갈 보존과 최대 128개 스테이션을 저장 v7에 연결했다. `20260909-093733-788` 전체 61단계가 종료 0이며 스테이션 2,565/2,584개·제작 2,683/2,695개 단언, 두 모드 1,002편집 OS 재시작 복원을 통과했다. 범위/호환성과 실패 기록은 `REVIEW_20260909_STATIONS.ko.md`를 따른다. 생존·시간·날씨는 M06이다.
- M06 (`S01 구현·자동 검증, 밸런스 미검증`): 99 Nights in the Forest의 낮 채집→야간 위험 대비→기지 투자 패턴을 독립 분석한 뒤, 4Hz 결정적 체력·허기·보온·낮/밤 상태와 F4 생존 디버그 워크벤치를 추가했다. 수치 편집·시계 진행·아이템 지급·채집/건축 준비·저장/복귀·프로파일·성능/축 시각화를 직접 호출하며, 단위 57개와 런타임 14개 단언을 통과했다. 최신 1,200초/4,800스텝 상태 마이크로벤치 P95는 4.091ms이지만 전체 게임 성능이 아니다. 상태는 v7 저장에 아직 포함하지 않으며, 적·사망·음식·화톳불·날씨·리스폰도 제외한다. 다음 S02는 화톳불/연료/보온 반경과 저장 v8 계약이다. 상세는 `RESEARCH_20260911_99_NIGHTS_SURVIVAL_BUILDING.ko.md`.
- M07 (`구현·성능 미달 기록`): `--streaming=on`에서 전역 시드/XZ만으로 결정적인 16×16 열을 만들고, 플레이어 경계 이동에 맞춰 3×3 상주 링의 비수정 열을 하나씩 해제/새 열을 하나씩 적재한다. 수정/스테이션 열은 세션 중 고정하며 기존 16³ 메시·충돌을 재사용한다. 단위 65개와 실제 월드 스모크 4개 단언은 통과했지만 최신 헤드리스 마지막 열 작업 41.070ms는 16.7ms 목표를 초과한다. 스트리밍 저장·전역 랜드마크/스폰 동굴/Atlas는 미지원이다. 상세: `RESEARCH_20260911_MINECRAFT_CHUNK_STREAMING.ko.md`.
- M08 (`구현·성능 미달 기록`): 열 생성 계산을 단일 워커로 옮기고, 라이브 저장소/노드/물리 변경은 메인에 남겼다. 초기 3×3도 중심 열부터 점진 적재하며, 목표 밖으로 밀린 워커 결과는 커밋하지 않는다. `streaming_smoke.gd` 6개와 `streaming_profile.gd` 5개 단언을 통과했다. 시드 1337 초기 링+X 네 번 이동의 헤드리스 CPU P95는 틱 23.230ms/워커 26.084ms/커밋 24.616ms로 16.7ms를 넘는다. M09에서 커밋·메시·충돌 예산화를 구현한다. 증거: `Saved/Verification/streaming-m08-profile.json`, `StatusReport/milestones/M08.html`.
- M09 (`계획`): 채널별 커밋 버퍼링(메시·충돌)과 렌더 재생성 비용 상한 테스트.
- M10 (`계획`): 편집 저널 재시작 복원, 스트리밍 세션 저장 계약(편집 델타/스탬프).
- M11 (`계획`): 전역 구조물·랜드마크·보상 포인트 예약 규칙 정형화.
- M12 (`계획`): 플레이어 왕복 이동 30회 P95 측정 루프(헤드리스/렌더 분리 지표).
- M13 (`계획`): 시드 다변성 20배치(지형·지하·바이옴 구성) 자동 비교표 작성.
- M14 (`계획`): 청크 경계 다단계 프리패치(거리·고도·방향 기반)와 스폰 안정성.
- M15 (`계획`): 스트리밍 상주 풀 메모리 LRU 정책 및 예산 초과 거부.
- M16 (`계획`): 동굴 동선·협곡 연계성 강화, 경로 불연속 케이스 수동 회귀.
- M17 (`계획`): 피처 패스(나무/연못/균열/자원군) 배치 간섭 및 충돌 정합성 테스트.
- M18 (`계획`): 99 Nights in the Forest 참조 기반 야간 생존 리스크 이벤트 통합.
- M19 (`계획`): 생존/채집/건축 루프를 스트리밍 편집 히트맵으로 계측.
- M20 (`계획`): HUD/치트 디버그 패널에서 열 단위 강제 재생성·고정·해제 직접 호출.
- M21 (`계획`): 멀티플레이 권위 모형 프리뷰(명령 반영 우선순위/동시 편집 충돌).
- M22 (`계획`): 적/사망/리스폰 모형 연결 테스트 하네스.
- M23 (`계획`): 날씨/보온/음식/불 번짐 이벤트를 월드 상태와 결합.
- M24 (`계획`): 마이크로프로파일을 루프 단위로 자동 수집하고 게이트 임계치 갱신.
- M25 (`계획`): 생성 다양성 점검표(색/지형/피처/탐험 동선) 기준 충족 보고.
- M26 (`계획`): 시뮬레이션/렌더 분리 리포트 자동화, 웹 문서 업데이트 자동화.
- M27 (`계획`): 20회 루프 리뷰, Unreal 대비 성능·플레이성 비교, 다음 시즌 목표 확정.

시각 후속: `WorldLighting` soft-day-v1로 3개 고정 지상 시점의 근백색 면적을 1% 아래로 낮추고 동굴 표시 밝기를 10% 이상 높였다. 새 안내판의 ROI 유입 실패를 고쳐 HUD 포함 PNG/지형만의 측정 프레임을 분리한 A/B 실제 렌더 53개 검사를 통과했다. 기존 밝기 기준은 유지한다. 설원 개선과 방 이름/출구 안내는 전체 시각 품질 완료가 아니다. 나무/구조물·방 형태/보상·지도 밖 탐험성, 작은 제작/장비 UI의 글자·아이콘, 편집 지연 안정화는 후속이다. 최신 생성 패널 40/49개, 동굴 안내 경로 이동 113/121개, 제작 2,683/2,695개, 전체 실행 `20260909-043812-774` 59개 단계 완료다. Unreal은 현재 문서상 M06 완료이므로 M01–M03 게이트를 전체 목표 완료로 대신하지 않는다.

M00/M01 종료에는 헤드리스 테스트, 실제 렌더 스모크, 화면 확인, 문서화가 모두 필요하다. 이후 마일스톤도 같은 루프를 사용한다.
