# 생성 초안·비동기 교체 자체 검토

기준일: 2026-09-08. 판정: 이번 기능 회귀 통과, Unreal 대비 전체 우위는 미달.

## 구현과 설계 경계

`GenerationControls`가 Seed/Size/Generation Checks/Show POI 네 행을 제공한다. Tab 열기/닫기, 방향키·PageUp/Down, N 숫자 입력·Enter 확정·Escape 취소, J 무작위 시드 초안, G 적용을 연결했다. G 이전에는 월드와 POI를 변경하지 않는다. Size는 41–255 홀수이며 숫자로 넣은 짝수는 다음 홀수로 정규화한다. 기존 지원 크기의 생성 결과를 바꾸지 않아 생성 버전은 3이다.

`VoxelWorld.request_generation()`은 저장/로드/생성과의 경합을 거부한다. COMPUTING에서 작업 스레드가 독립 layout·선택 검사·VoxelChunkStore를 만든다. MESHING에서 메인 스레드가 숨긴 청크 렌더러를 약 4ms 배치 예산으로 구성한다. 준비 완료 후 기존 렌더 노드를 교체하고 물리 2프레임 SETTLING 뒤 완료를 발행한다. 생성 중 패널을 닫아도 이동·편집·저장/로드를 잠근다. 성공 시 플레이어/인벤토리/진행도는 새 월드 계약에 맞게 초기화한다.

활성 SceneTree와 렌더/물리 조작을 작업 스레드에서 수행하지 않는 경계는 [Godot 4.7 thread-safe APIs](https://docs.godotengine.org/en/4.7/tutorials/performance/thread_safe_apis.html)를 참고했다. 엔진 API가 모두 스레드 안전하다는 전제를 두지 않고 작업자별 생성 데이터와 노이즈 리소스만 사용한다.

Checks ON의 PASS는 WorldLayoutValidator 불변식 검사와 청크 교체 완료를 뜻한다. Checks OFF 또는 초기 동기 생성은 READY다. POI는 비충돌 금색 기둥 6개이며 모든 동굴/관심 지점의 주석 시스템은 아니다. DungeonMode/RoomAttempts는 이번 범위에 포함하지 않았고 구현되지 않았다.

## 발견한 실패와 수정

- 첫 탐색 실행에서 Checks OFF 분기의 비형식 빈 배열이 `Array[String]` 반환 계약과 충돌했다. 명시적 형식의 빈 배열과 조건부 검사로 수정했다. 작업자 반환 Dictionary의 필수 키·값 형식도 검사하여 잘못된 결과가 잠금 고착으로 이어지지 않게 했다.
- 헤드리스에서 마우스가 반드시 CAPTURED일 것이라는 테스트 전제가 틀렸다. 패널 열기 전 모드를 보존/복원하는 계약으로 바꾸고 실제 렌더 입력 경로를 별도로 실행했다.
- 초기 동기 생성에 검사를 수행하지 않고 검사 완료처럼 표시하던 메타데이터를 READY/Checks OFF로 수정했다. FAIL도 요청 당시 안내문 대신 실제 실패 메시지를 보여준다.
- 빈 작업 결과를 주입하여 FAIL 후 기존 월드/플레이어 보존과 잠금 해제를 검증했다. 같은 실행에서 이후 최대 월드 생성이 성공하여 실패 후 재시도도 확인했다.

## 재현 명령과 최종 증거

프로젝트 디렉터리에서 `pwsh -NoProfile -File .\Verify.ps1` 실행. 최종 종료 코드 0, 증거 디렉터리 `Saved/Verification/20260908-212251-978`.

- 단위 48, 저장 74, 메시 502, 최적화 동등성 534개 단언 통과.
- Builder 헤드리스 53/렌더 72, 웅크리기 24/25, 생성 조작 36/44개 단언 통과.
- 생성 조작 검사는 초안 입력/취소·짝수 정규화·검사/POI 독립성·게임 입력 차단·중복 요청·저장 경합·기존 월드 유지·실패 복구·교체된 청크 충돌을 포함한다. 패널을 닫고 W를 눌러도 생성 중에는 이동하지 않음을 검사했다.
- 128시드 행렬 19.443초, 극단 시드 포함 생성 감사 및 오류 주입 5개, 실제 W/Space 입력으로 3시드 동굴 왕복 통과.
- 서로 다른 OS 프로세스 PID 21384/30052에서 편집 1,000개와 자세·충돌체·인벤토리·진행도를 저장/복원했다.
- `controls.png`, `generating.png`, `controls-large.png`와 런타임/동굴/Builder/웅크리기 PNG를 보존했다. 최대 크기의 1280 × 720 화면에서 네 행과 상태/도움말·핫바가 잘리지 않음을 직접 확인했다. 설원 과노출은 여전히 남는다.

실제 렌더의 최대 255 × 255 시드 1337: 2,061,001셀, 해시 1834750467, 요청부터 완료까지 14,866.38ms. 12,420회 생성 루프 프레임 간격 P95 5.622ms, 최대 22.404ms. 같은 프로세스의 작은 43/41맵 요청은 각각 407.71/398.04ms였다. `controls-input.log`에 원시 실행 요약, `controls-input.process.json`에 실제 엔진 PID 24792와 최대 작업 집합 925,421,568바이트(약 882.55MiB)를 남겼다. 이 프로세스 메모리는 여러 교체·검사를 포함하며 단일 255맵 초기 메모리와 같지 않다.

## 남은 위험과 다음 루프

4ms는 청크 간 배치 예산이며 한 청크 메시/업로드와 마지막 전체 노드 이동이 이를 넘을 수 있다. 현재 최대 22.404ms가 관찰됐으므로 모든 생성 프레임이 16.7ms 이하라고 주장하지 않는다. 또한 생성 루프 프레임 간격은 입력-화면 지연이 아니다. 이번에는 렌더 비교를 재실행하지 않아 이전 편집 화면 반영 P95 16.948ms 미달도 유지한다.

기존 월드와 준비 중인 새 월드를 동시에 보유하므로 일시 메모리 비용이 있다. 청크 스트리밍, 강제 종료 중 생성/저장 복구, 모든 시드의 255맵 물리 왕복은 보장하지 않는다. 닫힌 패널의 COMPUTING 단계에서는 상시 상태가 표시되지만 경과 시간은 다음 상태 신호까지 갱신되지 않는 표시상 한계도 남는다.

다음 기능 게이트는 DungeonMode/RoomAttempts와 Alt+2, 생성 계약의 모든 기후 축·해저 높이맵·전역 접근성이다. 그 뒤 시각 품질과 동일 조건 성능을 다시 평가한다. Unreal 원본은 변경하지 않았으며 공유 가능한 초안/상태/검증 방법론은 플레이북에 반영했다.
