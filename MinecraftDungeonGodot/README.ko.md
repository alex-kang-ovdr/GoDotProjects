# Voxel Frontier — Godot 경쟁 구현

Godot 4.7.2로 만드는 마인크래프트풍 1인칭 복셀 게임입니다. 사내 Unreal 샘플과 개발 방법론·블록 의미·검증 기준을 공유하지만 런타임 코드는 GDScript와 Godot 노드로 독립 구현합니다.

## 현재 플레이 가능한 범위 (M01–M05, M05 스테이션 완료 기록)

- 시드 1337의 결정적 41 × 41 복셀 지형과 평원·숲·사막·설원·해안·고지 생물군
- Unreal 기준과 동일한 안정 ID의 12개 블록 정의, 36슬롯 가방과 9개 핫바 슬롯
- E 인벤토리: 전체/절반 집기·한 개 놓기·병합·교환, 방향키/Enter와 실제 마우스, 닫아도 보존되는 커서 스택
- C 제작: 통나무→판자→막대/작업대와 나무·돌·철 도구를 포함한 14개 정형/비정형 레시피. 작업대 소지 시 3×3 해금
- 월드 셀 결합 상자(27칸)·화로(원료/연료/결과), X 열기·B 가방 전환, 최대 128개 상태 저장
- 조약돌 광맥의 석탄·이끼 광맥의 철 원석, 20Hz 화로(200틱 제련/석탄 1,600틱)와 재설치에도 재생성되지 않는 고갈 광맥
- E→F 장비: 활성 도구 1칸/예비 3칸, Q로 선택 도구 장착. 도구는 한 칸에 한 개이며 개별 내구도가 이동·저장·채굴에 연결됨
- WASD 이동, Space 점프, Ctrl 달리기, Shift 웅크리기(가장자리 보호), 마우스 시점
- S01 생존 샌드박스: HUD의 DAY/NIGHT·HP·Hunger·Warmth. 현재는 디버그 실험용 상태이며 식품·화톳불·적·사망·저장은 다음 S02 범위
- 왼쪽 버튼 유지로 시간 기반 채굴, 오른쪽 클릭 설치, 숫자 1–9 블록 선택
- 손과 나무·돌·철 곡괭이/도끼/삽, `T` 다음 도구/`Shift+T` 이전 도구, 내구도와 채굴 진행 HUD
- 실제 대상 블록의 10단계 3D 균열, 면/시선 방향으로 정해지는 24가지 설치 상태와 통나무 단면/옆면 회전
- 채굴 아이템은 물리 드롭으로 떨어지며 0.35초 뒤 1.5m 안에서 줍기. 가득 찬 인벤토리는 드롭을 보존
- 6m 조준 블록의 흰색 윤곽, Alt+2 개발용 청록색 강조/XYZ 좌표축
- 초기 핫바 9칸에 블록 8개씩, 나머지 27칸은 빈 가방으로 시작하며 최대 스택은 64개
- 돌은 사용 가능한 곡괭이로 채굴해야 조약돌로 회수되며 물·나뭇잎은 회수할 수 없음
- Builder challenge: 성공한 채굴 8회·설치 4회, 진행 HUD와 저장/복원
- R로 현재 편집을 고려한 안전한 입구 복귀(진행도·인벤토리 유지)
- 시드·월드 크기·블록 수·결정론 해시와 행동 피드백 HUD
- 보호 동굴의 CAVE ATLAS: 방 이름·현재 방위·실제 출구 다음 방향/점프 안내. 채굴·설치·체크포인트 복원에 따라 재탐색하며 막힌 길은 경고합니다. 지도 밖 자연 공동/새 터널은 안내하지 않습니다.
- 16 × 16 청크 좌표와 희소 편집 저널, SHA-256 검증이 있는 버전형 저장(`Ctrl+8`)·불러오기(`Ctrl+9`)
- 백그라운드 저장·읽기, 저장 시점 스냅샷, 이전 저장 `.bak` 보존, 검증 후 월드·인벤토리·시점 일괄 복원
- 16³ 청크별 노출면·greedy 메시, 정적 삼각형 충돌, 편집 셀 주변 면 캐시 갱신
- 6개 독립 수평 기후장(Depth 포함)의 생물군/높이 생성, 약 30블록 깊이 지층, 연속 밀도 동굴·곡선 터널·협곡
- 최종 셀의 표면(물 포함)·유체 제외 고체 바닥·충돌 높이맵과 생성 전 shaping 높이 분리
- 스폰 보호 계단·전실에서 깊은 중앙 방과 네 갈래 탐험 구역으로 이어지는 동굴망, 비중첩 랜드마크 6개와 해안 샘
- 스폰에서 접근할 수 없는 랜드마크의 연결로 보정, 최종 지형의 보행/점프 연결성 검사
- 설원 하이라이트를 낮추고 동굴 밝기를 보완한 `soft-day-v1` 조명, 3시드 고정 시점의 실제 화면 회귀 검사
- Tab 생성 초안 패널: Overworld/Dungeon·시드·홀수 크기·방 배치 시도·생성 검사·POI, 작업 스레드 생성과 단계별 청크 교체
- Dungeon: 11–255 크기, 방 배치 시도 1–512, 비중첩 방·3칸 폭 통로·연결된 입구/출구와 실제 채굴·설치·체크포인트

## 실행

`RunGame.bat`을 실행합니다. 첫 실행 시 Godot가 리소스를 임포트하느라 잠시 걸릴 수 있습니다. 마우스 커서는 Escape로 해제하거나 다시 잡습니다.

M04의 기본 도구 9개 프리뷰는 아직 유지합니다. M05 제작 도구를 활성 장비에 넣으면 프리뷰 선택보다 우선하며, 소진 장비는 다른 프리뷰/예비 도구로 자동 대체하지 않고 손 성능이 됩니다. 버튼 해제·대상 변경·도구 교체·패널 열기·저장/로드는 채굴과 균열을 취소합니다. 설치 시 조준한 면과 현재 수평 시선으로 방향을 정하며, 통나무의 나이테/결이 회전하고 이웃 편집이나 저장 복원 뒤에도 유지됩니다. [채굴·드롭 기반 검토](Docs/REVIEW_20260909_MINING.ko.md)와 [방향·균열·보존 반복 검토](Docs/REVIEW_20260909_ORIENTATION.ko.md)에 실제 입력·물리·저장 검증과 제한을 기록합니다.

현재 저장 포맷은 7/생성 버전은 6입니다. 새 저장에는 36개 스택·커서·4장비·도구 내구도·방향·드롭과 셀 결합 상자/화로·고갈 광맥·화로 틱 잔여 시간이 포함됩니다. v2–v6은 스테이션 없는 상태로 읽으며 v6의 새 재료 드롭은 모호한 복원을 막기 위해 거부합니다. 포맷 2–6 실행기는 새 저장을 읽을 수 없으므로 돌아갈 가능성이 있다면 새 체크포인트 전에 별도 백업하세요.

E로 인벤토리를 열고 E/Escape로 닫습니다. 왼쪽 클릭/Enter는 전체 집기·병합·교환, 오른쪽 클릭/Shift+Enter는 절반(올림) 집기·한 개 놓기입니다. 방향키로 36칸을 선택하며 첫 줄이 핫바입니다. 아이템을 옮기면 핫바 표시와 실제 설치 종류도 따라 바뀝니다. 주운 블록은 같은 종류의 기존 스택부터 채운 뒤 빈 칸에 들어갑니다. 전체 수량이 들어갈 공간이 없으면 드롭은 남습니다. 커서를 들고 닫아도 아이템은 보존되며 패널 내부 Ctrl+8/9로 저장·복원할 수 있습니다. 패널 중 이동·채굴은 멈추고 Tab/C 모달과 겹쳐 열리지 않습니다. E 안에서 Q는 선택 도구를 활성 장비로 교환하고 F는 장비 화면을 엽니다. 장비의 방향키/Enter 또는 마우스는 커서와 교환하며 예비 3칸은 자동 사용하지 않습니다.

C로 제작 목록을 열고 위/아래 또는 마우스로 레시피를 고른 뒤 Enter/Craft를 누릅니다. 목록형 제작으로 실제 드래그 격자는 아니며 정형/비정형 격자 매칭을 통과한 레시피만 실행합니다. X는 조준한 상자/화로를 열고 B는 가방/스테이션을 오갑니다. 화로는 철 원석+석탄을 20Hz로 처리합니다. 내용물이 있는 스테이션은 채굴할 수 없고, 결과가 가득 차면 새 연료를 점화하지 않습니다. [제작·장비 검토](Docs/REVIEW_20260909_CRAFTING.ko.md)와 [스테이션 완료 기록](Docs/REVIEW_20260909_STATIONS.ko.md)에 검증과 제한을 기록합니다.

개발 빌드에서는 `F4`로 **Survival Debug Workbench**를 엽니다. HP/Hunger/Warmth 속성을 편집하고 낮/밤·시간 진행·아이템 지급·선택 스택 채우기/비우기·안전 복귀·저장/불러오기·프로파일·성능 HUD·축 시각화를 직접 호출할 수 있습니다. 명령줄에는 `help`, `set hunger 40`, `night`, `advance 60`, `give 10 8` 같은 명령을 입력합니다. 워크벤치는 플레이 조작을 잠그며 닫으면 복원하고, 이 조작은 챌린지 진행도를 올리지 않습니다. `Ctrl+0`으로 개발 도움말, `Ctrl+1`로 선택 스택 채우기, `Ctrl+2`로 비우기, `Ctrl+3`으로 레지스트리/플레이어 진단을 실행합니다. `Alt+1`은 FPS·엔진 할당 메모리·청크/편집 수와 마지막 재생성 비용, `Alt+2`는 조준 강조 박스/좌표축, `Alt+3`은 `user://Profiles`에 JSON 프로필을 저장합니다. 엔진 할당 메모리는 OS 전체 프로세스 메모리와 다릅니다. 축 색상은 X 빨강·Y 초록(위)·Z 파랑이며 Unreal의 Z-up 표기와 구분합니다. 조준 표시는 충돌이나 저장 데이터를 만들지 않고, 패널·생성·로드 중과 조준 실패 시 숨깁니다.

실행 옵션은 `RunGame.bat` 뒤에 전달할 수 있습니다.

```powershell
.\RunGame.bat --mode=dungeon --seed=-7 --size=41 --room-attempts=34 --checks=on --poi=on
.\RunGame.bat -Overworld -DungeonSeed=1337 -WorldSize=185 -DungeonPOI
```

직접 엔진을 실행할 때는 엔진 인수 뒤에 `--` 구분자를 두고 위 게임 옵션을 전달합니다. 배치 파일은 이미 구분자를 넣습니다. 네이티브 옵션은 `--mode=overworld|dungeon`, `--seed=정수`, `--size=정수`, `--room-attempts=1..512`, `--checks=on|off`, `--poi=on|off`입니다. 공유 검증용 `-Overworld`, `-DungeonSeed=`, `-WorldSize=`, `-DungeonSize=`, `-RoomAttempts=`, `-NoGenerationChecks`, `-DungeonPOI`도 지원합니다.

인수가 없으면 기존 41맵/시드 1337/Checks OFF로 시작합니다. 생성 옵션을 명시하면 Checks ON이 기본이고, Overworld 기본 크기는 185/Dungeon은 41입니다. 언리얼 형식의 던전 옵션만 쓰면 Dungeon을 선택하므로 지상 월드는 `-Overworld`를 명시합니다. 짝수 크기는 다음 홀수로 맞추지만 범위 밖 값·타입 오류·중복/모순 옵션은 월드 생성 전에 오류 메시지와 종료 코드 2로 거부합니다. 생성과 무관한 다른 인수는 테스트 러너와의 공존을 위해 무시합니다. 시작 옵션은 첫 월드에 적용하며 기본 월드를 한 번 더 생성하지 않습니다. 시작 생성 자체는 동기식이고, 플레이 중 G 재생성은 비동기식입니다.

`Tab`으로 생성 설정을 엽니다. 위/아래는 항목 선택, 좌/우는 값 변경, PageUp/PageDown은 큰 단위 변경입니다. Seed/Size/Room Attempts에서 `N`으로 숫자를 입력하고 Enter로 초안을 확정하거나 Escape로 취소합니다. 시드는 signed int32, 크기는 Overworld 41–255/Dungeon 11–255이며 짝수 입력은 다음 홀수로 맞춥니다. 모드를 바꾸면 크기 초안은 Overworld 185/Dungeon 41로 돌아갑니다. Room Attempts는 Dungeon에서만 조작되며 1–512입니다. 배치 시도 수이지 보장된 방 수는 아닙니다. `J`는 무작위 시드 초안, `G`는 적용입니다. Tab/Escape로 패널을 닫으며 **G를 실행하면 저장하지 않은 편집이 새 월드로 대체됩니다**. Checks는 모드별 최종 지형 불변식 검사, POI는 Overworld 랜드마크 6곳/Dungeon 입구(녹색)·출구(금색)의 기둥 표시이며 서로 독립적입니다. 초안만 바꾸어서는 현재 월드/POI가 바뀌지 않습니다.

생성은 COMPUTING → MESHING → SETTLING 순서로 진행하며 패널을 닫아도 이동·편집·저장/불러오기와 중복 생성은 잠깁니다. 준비 완료 후 월드와 충돌을 교체하고 플레이어를 새로 시작합니다. 작업 결과 검증 실패는 기존 월드를 보존합니다. 검사한 생성만 PASS, 검사하지 않은 생성은 READY로 표시합니다. PASS는 전체 품질 게이트나 Unreal 대비 우위의 의미가 아닙니다.

Shift를 누르면 몸 높이 1.5m·눈높이 1.27m·이동 속도 1.295m/s로 웅크립니다. 발 위치는 유지하며 Ctrl 달리기보다 웅크리기가 우선합니다. 천장이 있으면 Shift를 놓아도 몸을 펼치지 않고, 통로를 벗어나 공간이 확보되면 다시 섭니다. 지상 가장자리에서는 보행 추락을 막지만 의도적인 점프나 발밑 블록 제거까지 막지는 않습니다. 현재 1m 블록 한 칸 통로는 몸보다 낮아서 통과할 수 없습니다.

빠른 검증은 `RunTests.bat`으로 실행합니다. 전체 게이트는 PowerShell 7에서 `./Verify.ps1`로 실행합니다. 단위 검사 48개, 저장 통합 검사 74개(편집 1,000개 디스크 저장·새 씬 복원 포함), 메시 검사 502개, 게임플레이 스모크, 128시드 행렬, 185 × 185 생성 측정, 실제 렌더 창의 LMB·숫자·RMB 입력 검사와 화면 캡처를 수행합니다. 결과는 `Saved/Verification/<timestamp>/`에 남기며 오류 로그·완료 표식 누락·제한 시간 초과도 실패로 처리합니다. `-SkipCapture`는 렌더 입력 검사도 생략합니다.

생성 감사는 최종 셀의 높이·공동·샘·구조물 출입구와 보호 경로를 확인하며 극단 시드, 185/255맵, 오류 주입도 포함합니다. 원래 계단 왕복 외에 4개 월드(185맵 포함)에서 실제 W/Space로 다섯 방을 탐험하고 지상으로 복귀하는 회귀 검사와 방별 PNG를 남깁니다. 보호 공기의 연결과 실제 보행 가능성을 구분해 검사합니다.

Builder 검사는 실제 렌더 창의 채굴·설치·개발 단축키·키보드 저장/복원·R 착지와 완료 HUD를 검사합니다. 별도의 쓰기/읽기 Godot 프로세스가 편집 1,000개·진행도·인벤토리·시점을 복원하며 각 단계 PID와 디스크 체크포인트를 증거 폴더에 보존합니다. 이 재시작 검증은 강제 종료 중 쓰기나 정전 복구 보장과는 다릅니다.

초기 준비 최적화는 정수 정렬·적응형 노출면 마스크를 사용하며, 기준 구현과 해시/음수 좌표/전체 마스크를 대조하는 동등성 검사와 밀도별 마이크로벤치마크를 전체 검증에 포함합니다. 자세한 계측은 [`Docs/REVIEW_20260908_STARTUP.ko.md`](Docs/REVIEW_20260908_STARTUP.ko.md)에 기록합니다.

블록 편집에는 평면별 geometry 캐시를 사용합니다. 마스크가 달라진 평면만 다시 병합하고 나머지 정점/충돌은 재사용합니다. `tools/Benchmark-PlaneCache.ps1`은 동일 185맵·게임 조명·VSync ON에서 기준/캐시를 경계 반복·64청크 분산 편집 각각 3회 비교하고 프로세스 메모리와 동일 PNG를 검사합니다. CPU P95는 대응 회차에서 54.8–68.2% 감소했지만 캐시 메모리가 약 112MiB 늘고 화면 반영 P95 16.7ms 목표는 아직 미달입니다. 원시 지표와 비용은 [평면 캐시 검토](Docs/REVIEW_20260908_PLANE_CACHE.ko.md)에 기록합니다. `render_benchmark.gd`의 기본 조명은 이제 실제 게임 프로필/그림자이며 이전 조건은 `--lighting=legacy`로 재현합니다. 이 독립 카메라 계측을 플레이어/HUD 전체 게임 루프 또는 Unreal 비교로 일반화하지 않습니다.

비동기 월드 교체는 기존 순수 데이터 참조를 작업 스레드에서 해제하고, 이전 렌더·충돌 노드는 메인에서 약 2ms 예산으로 나눠 제거합니다. 노드 정리·물리 안정화·스레드 회수가 끝나기 전에는 조작/저장 잠금이 유지됩니다. 스레드 시작 실패 시 동기 대체 처리로 완료하지만 지연이 생길 수 있습니다. `tools/generation_profile.gd`는 실제 게임 씬의 41→255→41 왕복을 반복해 프레임별 생성/메시/교체/정리 증거를 남깁니다. 큰→작은 전환의 최대 간격을 323–366ms에서 27–34ms로 줄였으나 전체 대기 시간이나 모든 프레임 지연의 개선을 보장하지 않습니다. [월드 정리 검토](Docs/REVIEW_20260908_RETIREMENT.ko.md)에 안전 경계와 측정 한계를 기록합니다.

`./Verify.ps1 -RenderComparison`은 동일한 185 × 185 지형·시점·64개 편집을 새 청크 렌더러와 기존 GridMap에서 별도 프로세스로 실행해 JSON 지표, 전경 PNG, OS 최대 작업 집합을 추가 기록합니다. 현재 [청크 전환 보고서](Docs/REVIEW_20260908_CHUNKS.ko.md)의 비교는 Godot 내부 기준이며 Unreal 우위 달성 판정과 구분합니다.

렌더 비교는 이제 `-BenchmarkScreen 0`(기본값)으로 실제 화면을 고정합니다. 직접 `render_benchmark.gd`에는 `--screen=N`, `--max-fps=0..1000`을 전달합니다. 창은 해당 화면의 1280×720 중앙으로 배치하고 화면 번호·주사율·위치·크기·VSync 요청·엔진 FPS 상한·포커스를 기록합니다. 조건이 바뀌면 원시 JSON/PNG를 보존하되 측정을 실패로 처리합니다. 헤드리스와 잘못된 화면 번호는 거부합니다. 화면 번호는 `tools/display_probe.gd`로 조회하며 OS 비디오 어댑터 목록과 같다고 가정하지 않습니다.

```powershell
.\tools\Benchmark-Display.ps1 -Screen 0 -Rounds 3 -MaxFps 0
.\tools\Benchmark-Display.ps1 -Screen 0 -Rounds 3 -MaxFps 60
```

각 명령은 경계/64청크 분산 편집에서 VSync ON/OFF를 교대해 12회 실행합니다. `MaxFps`는 벤치마크 전용 대조 조건으로 게임 설정이나 모니터 주사율을 바꾸지 않습니다. 최종 무제한/VSync ON 6회 P95는 16.772–17.069ms로 16.7ms 목표에 미달했습니다. OFF의 낮은 수치를 ON 안정화로 대체하지 않습니다. 여기서 과거 “화면 반영”이라고 부른 수치는 **엔진의 viewport 갱신 신호까지**이며 GPU 완료·물리 화면 표시·입력→광자 지연의 직접 측정이 아닙니다. 40개 별도 GPU 읽기 검사는 다음 관측 viewport의 실제 블록 추가/삭제 픽셀을 확인합니다. [표시 계측 검토](Docs/REVIEW_20260909_DISPLAY_TIMING.ko.md)에 공식 신호 정의, 유휴 간격·FPS 대조·미달 결과를 기록했습니다.

저장은 `user://voxel_frontier_save.json`에 기록합니다. 현재 포맷 버전은 6, 생성 버전은 **6**입니다. 같은 생성 버전의 포맷 2–5 호환 읽기는 지원하지만 보호 동굴망 확장 이전 생성 버전은 자동 변환 없이 거부합니다. 전역 정책이라 지형 알고리즘이 그대로인 Dungeon의 생성 버전 5 이하 저장도 거부하며, 거부 시 파일 삭제나 월드 변경은 없습니다. 변경 전 생성 v5 실행 소스는 `Saved/GenerationArchives/voxel-frontier-v5-runtime.zip`에 보관하고 별도 폴더에서 기존 해시 재현을 확인했습니다. 소스 아카이브에 사용자 저장은 포함되지 않으므로 이전 저장은 새 버전에서 저장하기 전에 별도로 복사해 보존하세요. [동굴망 검토](Docs/REVIEW_20260909_CAVE_NETWORK.ko.md)에 아카이브 해시와 복구 범위를 기록했습니다. 저장 중 플레이를 계속할 수 있고 불러오는 동안 이동·편집·드롭 물리는 잠시 정지합니다. 전체 검증 후 반영하며 `.pending` 읽기 재검증과 `.bak` 후 교체하지만 정전·파일시스템 수준 원자성까지 보장하지 않습니다.

같은 포맷/생성 버전에서 챌린지 필드가 없던 저장은 진행도 0으로 읽습니다. 포함된 진행도는 0–2,147,483,647 범위 정수만 허용하고 잘못된 값은 월드나 플레이어를 변경하기 전에 거부합니다. 새 월드 생성은 인벤토리 8개·선택 슬롯 1·진행도 0으로 새 세션을 시작하며 R 복귀는 초기화하지 않습니다.

저장에는 생성 모드와 Dungeon 방 시도 수를 포함합니다. 모드/설정이 다르면 기본 셀 해시가 우연히 같아도 거부합니다. 이전 포맷-2 저장에서 생성 옵션이 없으면 Overworld로만 해석합니다. 다른 모드로 이동한 후 체크포인트를 불러오려면 먼저 저장 당시 시드·크기·모드·방 시도 설정으로 월드를 생성해야 합니다. 파일이 자동으로 모드를 전환하지 않습니다.

웅크린 자세도 저장되며 이전 저장의 누락 자세는 서 있는 상태로 읽습니다. 자세 필드는 boolean만 허용합니다. 1.55m 통로·천장 여유·30/60/120Hz 대각 가장자리·점프·지지 블록 제거를 실제 캐릭터 입력/충돌로 검사하며 새 OS 프로세스의 자세·충돌체·눈높이 복원도 검증합니다.

최신 전체 근거는 `Saved/Verification/20260909-093733-788`, `Verify.ps1 -RenderComparison -BenchmarkScreen 0` 종료 코드 0/61개 단계 완료입니다. 헤드리스/실제 렌더 스테이션은 2,565/2,584개, 제작은 2,683/2,695개 단언을 통과했습니다. 두 모드 새 OS 프로세스는 1,002개 편집과 스테이션 상태를 복원합니다. 생성 v6/기본 해시는 유지하고 저장만 v7로 올렸습니다. [스테이션 완료 기록](Docs/REVIEW_20260909_STATIONS.ko.md)과 [절차 생성 루프](Docs/PROCEDURAL_WORLDGEN_PLAN.ko.md)에 범위·실패·다음 게이트를 남겼습니다.

실제 255맵 교체 P95는 17.344ms로 16.7ms 목표에 미달합니다. 이 수치는 engine `frame_post_draw`까지의 CPU wall time이며 물리 표시/입력→광자 지연이 아닙니다. Unreal 현행 로컬 보고서는 M06 완료를 기술하므로 Godot M05 완료 기록만으로 전체 우위를 선언하지 않습니다. 다음 기능 루프는 [절차 생성 M03.2](Docs/PROCEDURAL_WORLDGEN_PLAN.ko.md)의 지형-생물군 일관성입니다.

`climate_at()`의 6번째 값은 시드와 X/Z에 따른 독립 Depth 기후장이며 높이 shaping에 쓰입니다. Y에 따른 표면 아래 상대 깊이는 별도의 `density_depth_at()`입니다. 높이맵은 모든 장식/동굴 생성 이후의 스냅샷이며 플레이 중 편집은 청크 저장소에서 조회합니다. `ocean_floor_heights`는 지질학적 지면이 아니라 물을 제외한 최상단 고체(지붕/나뭇잎 포함)입니다. Unreal의 장식 전 지면 높이맵과 정확히 같은 API 의미라고 주장하지 않습니다.

랜드마크 연결 검사는 문 주변만 확인하지 않고 스폰에서 모든 문까지 지지 바닥·몸 공간·1블록 단차의 보행/점프 경로를 확인합니다. 연결되지 않은 곳에는 기존 동굴/건물/샘과 성공한 경로를 보존하는 조약돌 연결로를 생성합니다. 일부 구간은 한 칸 너비이며 지하 통로나 협곡 위 바닥을 포함할 수 있습니다. 플레이 후 길을 파괴하면 자동 복구하지 않습니다. 자연 동굴 전체 연결이나 최단 경로·모든 임의 시드의 성공 보장을 뜻하지 않습니다. [접근성 검토](Docs/REVIEW_20260908_ROUTES.ko.md)에 독립 그래프와 실제 왕복 검사·실패 수정·성능 비용을 기록합니다.

조명은 `WorldLighting`에서 관리하며 햇빛 0.22/환경광 0.48, 기존 그림자와 Linear 톤매퍼를 사용합니다. `lighting-input`은 같은 월드/카메라의 기존·현재 지상/동굴 PNG와 표시 밝기 지표를 남깁니다. 3개 고정 시점의 근백색 면적·동굴 밝기를 개선했지만 모든 시점의 노출이나 동굴 길 찾기 전체를 해결한 것은 아닙니다. 당시 조명 변경은 v5 지형을 유지했으며 이번 동굴망 변경은 v6입니다. [조명 검토](Docs/REVIEW_20260908_LIGHTING.ko.md)에 당시 측정 정의와 범위를 기록했습니다.
