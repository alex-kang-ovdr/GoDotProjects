# 변방의 기록 — Frontier Colony 4.0

세 명의 정착민으로 시작하는 JavaScript 정착지 생존 게임입니다. **채집 → 운반 → 거처 완성 → 제작·장비 → 교역·연구 → 발전·축전 → 냉장 보관 → 습격 방어 → 구조 신호 전송**이 하나의 플레이로 이어집니다. 주민은 스스로 작업하고, 플레이어는 공간·분업·연구와 하루 일정을 정합니다. 화재와 습격을 막은 뒤에는 부상자를 구조하고 치료해 일상으로 복귀시킵니다.

**플레이 주소:** https://frontier-colony-0e03a8.taru00.chatgpt.site

림월드 역기획에서 핵심 관계를 가져와 독립적으로 구현했습니다. 수치·시간·규칙은 이 프로토타입을 위해 조정했으며 원작 코드, 이미지, 음악은 사용하지 않았습니다. 모든 장면은 Canvas 2D와 CSS로 그립니다.

## 실행

배포 주소를 브라우저에서 열면 설치 없이 플레이할 수 있습니다. 소스를 실행하려면 Node.js 20 이상에서 프로젝트 폴더를 열고 다음 명령을 실행합니다. 외부 패키지를 설치할 필요가 없습니다.

```sh
npm start
```

브라우저에서 [http://127.0.0.1:8080](http://127.0.0.1:8080)을 엽니다. ES Modules를 사용하므로 HTML 파일을 직접 더블클릭하는 대신 HTTP 서버로 실행하세요.

```sh
npm test
```

Node.js 내장 테스트 러너로 엔진·환경·저장·기본 시나리오를 검증합니다. 개발 검증 환경은 Node.js 24.22.1입니다.

### 제작·교역을 시작하는 순서

1. 거처와 식량을 준비한 뒤 **제작 → 제작대 건설**을 선택합니다. 비용은 목재 20·강철 8이며 전기나 연구 없이 사용할 수 있습니다.
2. **제작 담당 배치**로 가능한 주민 중 제작 기술이 높은 사람의 우선순위를 1로 올립니다. 운반 담당도 남겨 둡니다.
3. 제품을 고르고 횟수를 올리거나 보유량 유지 목표를 정합니다. 예를 들어 작업 도구 1개는 강철 8·목재 4를 사용합니다. 주문만으로 즉시 생산되지 않습니다.
4. 완성품이 창고에 들어오면 주민 선택 → **장비와 도구 → 장착**을 누릅니다. 비징집 주민이 창고까지 가서 장비를 받습니다.
5. 시작 80초 이후 상인이 지도에 들어옵니다. 도착 후 **교역** 탭에서 품목·방향·수량을 고릅니다. 새 게임은 은화 60개로 시작하며, 이전 저장에는 무료 은화를 추가하지 않습니다.
6. 구매품과 판매 대금을 운반합니다. 판매한 은화가 아직 상인 발밑에 있다면 상단 은화는 늘지 않습니다. 상인은 도착 후 100초 머무르고, 퇴장 완료 220초 후 다음 방문을 예약합니다.

| 제품 | 제작 비용 | 효과 |
| --- | --- | --- |
| 작업 도구 | 강철 8·목재 4 | 건설·수리·농사·채집·채광·제작 속도 +25% |
| 방탄 조끼 | 강철 16 | 총탄 피해와 총상 출혈 증가량 −35% |
| 개량 소총 | 강철 18·목재 8 | 징집 사거리 9칸, 피해 +35%, 명중률 +4%p, 징집 사격 간격 1.2초 |

보유량 유지 주문은 창고·바닥·운반·장착 제품과 제작 중 산출 예정량을 포함합니다. 주문 설정을 바꾸면 해당 제작을 중단하고 수령한 재료를 바닥에 돌려놓으며, 미완성 진행도는 초기화합니다. 상인은 음식 재판매를 받지 않습니다.

## 첫 정착지를 진행하는 방법

1. **거처를 닫습니다.** 시작 거처의 동쪽 `(27,16)`, 남쪽 `(23,19)` 빈틈에 문이나 벽을 건설합니다. 북쪽에는 기존 출입문이 있습니다. 세 번째 침대는 실내 빈칸, 예를 들어 `(25,13)`에 배치할 수 있습니다.
2. **물자와 식량을 확보합니다.** 채집 지정으로 나무와 광맥을 표시하세요. 초기 지정 외에도 설비에 쓸 강철을 더 채광해야 합니다. 농사 구역을 드래그하면 사각형 영역으로 지정되며 주민이 파종·수확합니다.
3. **연구를 맡깁니다.** 처음부터 연구대와 전기 공학 연구가 준비되어 있습니다. 연구 탭에서 진행을 확인하고 작업 탭에서 연구 담당의 우선순위를 올리세요. 연구에도 주민의 시간이 들어갑니다.
4. **전기를 연결합니다.** 태양광과 축전지를 상하좌우로 붙이거나 전력선으로 연결합니다. 소비 설비는 연결망에서 3칸 이내에 둡니다. 낮에 충전하고 밤에는 저장 전력을 사용합니다.
5. **식량을 오래 보관합니다.** 냉장 보관 연구 후 창고가 있는 닫힌 방에 냉각기를 둡니다. 전력과 실내 온도를 확인하세요. 침실과 냉장실을 나누면 주민이 추운 곳에서 자지 않아도 됩니다.
6. **습격을 방어합니다.** 기본 설정에서는 습격 발견 시 시간을 멈춥니다. 전원 징집하면 전원이 선택되고, 빈 땅을 누르면 서로 다른 칸으로 이동합니다. 적을 누르면 집중 공격합니다. 전투 후 징집을 해제하면 치료·수리·생활을 재개합니다.
7. **통신을 연구하고 신호기를 지킵니다.** 장거리 통신 연구 후 구조 신호기를 건설하고 전력을 공급합니다. 신호가 절반에 이르면 최종 습격이 찾아옵니다. 방어 후 조건을 유지하면 구조에 성공합니다.

의료·소방 탭에서 여분의 침대를 의료용으로 지정하고, 작업 탭의 구조·치료·소방을 켜 두세요. 고리 던지기를 건설하고 일정에 여가를 마련하면 기분 유지에 도움이 됩니다. 전투가 끝나면 징집을 해제해야 주민이 구조·치료·진화를 시작합니다.

이 좌표 안내는 v4 새 게임의 시작 거처에 해당합니다. 이전 저장을 불러오면 기존 지도를 보존하므로 그 정착지에 맞게 거처와 설비를 배치하세요.

## 작업과 자원

작업 우선순위는 **1이 가장 높고 4가 가장 낮습니다.** `—`는 작업 비활성입니다. 우선순위가 같으면 작업 목록 순서와 대상 거리·예약·접근 가능성을 기준으로 선택합니다. 허기, 휴식, 전투, 치료 필요에 따라 생활 행동이 달라집니다.

채집·생산 결과는 바닥 물품으로 생성됩니다. 주민이 운반해 창고에 넣어야 상단 재고에 반영됩니다. 조리는 식재료 2개를 소비해 식사 1개를 만들며 결과물도 운반해야 합니다. 창고 재고는 정착지 전체의 공용 재고이고, 음식 보존은 입고 위치가 기록된 배치별로 계산합니다.

건설 계획은 자재를 한 번 예약·차감하고 주민이 실제로 운반해 시공합니다. 취소하면 자재를 한 번 반환합니다. 완성 건물 철거는 재료별 절반을 내림해 바닥에 돌려놓습니다. 수리는 재료 1개와 4 작업량으로 최대 40 내구도를 회복하며, 도중에 중단하면 사용 전 운반 자재를 내려놓습니다.

## 의료·소방·일정 사용법

**쓰러진 주민:** 의료·소방 탭의 구조 지시를 누릅니다. 건강한 비징집 주민이 빈 침상을 찾아 실제로 운반합니다. 출혈이 심하면 치료를 먼저 준비하세요. 의료 침상은 환자를 위해 비워 두므로 건강한 주민이 잘 일반 침대도 필요합니다.

**불이 난 곳:** 소방 작업을 켜고 담당 주민의 징집을 해제합니다. 자동 진화 외에도 의료·소방 탭의 진화 지시, 또는 주민 선택 → 우선 작업 → 불을 누르는 방법을 사용할 수 있습니다. 불을 끈 뒤 파손 건물, 전력 연결과 냉장실 온도를 확인하세요.

**하루 일정:** 일정 탭에서 주민 → 활동 → 시간칸 순서로 편집합니다. 한 칸은 게임 시간 1시간입니다. 생존에 긴급한 욕구와 위기 대응은 일정보다 우선합니다. 작업 우선순위를 비활성화하면 작업 시간에도 그 업무를 수행하지 않습니다.

## 실내·전력·온도

완성된 벽과 문으로 둘러싸인 **120칸 이하**의 육지 공간에 자동으로 지붕이 생깁니다. 물은 벽으로 인정되지 않습니다. 벽을 철거하거나 적이 파괴하면 공간이 열리고, 외기 온도에 가까워집니다. 방을 다시 닫아도 온도를 임의로 초기화하지 않습니다.

발전기·축전지·전력선은 상하좌우로 이어져 전력망을 형성합니다. 냉각기·난방기·신호기는 가장 가까운 연결망의 도체에서 **맨해튼 거리 3칸 이내**일 때 연결됩니다. 소비 설비는 다른 설비에 전력을 중계하지 않습니다.

| 항목 | 구현 수치·규칙 |
| --- | --- |
| 태양광 | 한 기당 최대 600 W, 06~18시에 일조량에 비례, 밤에는 0 W |
| 날씨 영향 | 비는 발전량 45%, 폭염은 90% |
| 축전지 | 한 기당 18,000 W·s, 실제 공급·소비 차이로 충방전 |
| 냉각기 | 120 W, 실내 목표 0°C |
| 난방기 | 100 W, 실내 목표 21°C |
| 구조 신호기 | 240 W |
| 공급 순서 | 냉각기 → 난방기 → 구조 신호기; 같은 종류는 안정적인 타일 순서 |
| 공급 부족 | 소비 설비가 필요한 전력을 전부 받지 못하면 꺼짐 |

방 크기와 외기에 대한 열손실 때문에 목표 온도까지는 시간이 걸립니다. 정전되면 냉각이 멈추고 실내가 다시 따뜻해집니다. 난방과 냉각을 한 방에서 동시에 사용하면 서로 영향을 줍니다. 설비 탭에서 발전량·필요 전력·축전 비율과 각 방 온도를 확인할 수 있습니다.

### 음식 보존

식재료와 식사는 창고, 바닥, 운반 중 상태를 옮겨도 신선도를 유지합니다. 재입고하거나 작업을 취소해 신선도가 새것으로 초기화되지 않습니다. 오래된 재고부터 소비합니다.

- 20°C 기준 기본 보존량: 식재료 360초, 식사 240초.
- 0°C 이하: 부패하지 않음.
- 0°C 초과~8°C: 기본 부패 속도의 15%.
- 8~20°C: 온도에 따라 부패 속도 증가.
- 20°C 초과: 더 빨리 부패.
- 신선도 소진: 실제 물품·재고를 제거하고 부패 통계를 기록.

상단 비축 식량의 ‘일분’은 현재 영양량에 기반한 추정이며, 향후 부패 손실까지 보장하는 기간은 아닙니다.

## 구조 성공과 계속 플레이

다음 조건을 유지하는 동안 신호가 총 **90 시뮬레이션 초**에 걸쳐 충전됩니다.

- 생존 주민이 있음.
- 실내 침대 3개가 완성됨.
- 식사 6개 이상 보유: 창고·바닥·운반 중 식사를 포함.
- 장거리 통신 연구를 완료함.
- 완성된 구조 신호기에 전력이 공급됨.
- 정착지가 이전 습격을 한 번 이상 방어했으며 현재 전투 중이 아님.
- 지도에 남은 화재가 없음.

50%에서 최종 습격이 한 번 발생합니다. 전투·화재 또는 조건 미충족 중에는 충전이 멈추며 진행도는 유지합니다. 최종 습격을 막고 완충하면 구조에 성공하고, 그 뒤에도 계속 운영할 수 있습니다. 전원 사망하면 새 정착지를 시작할 수 있습니다.

시간은 게임 내 하루 120초, 첫날 08:00부터 시작합니다. 표준 첫 습격은 시작 210초, 여유 모드는 340초입니다. 정기 후속 습격은 직전 시작으로부터 표준 270초·여유 모드 370초 후에 예약되며 이전 전투가 끝나야 발생합니다. 구조 최종 습격은 별도의 진행 조건을 사용합니다.

## 저장과 이전 버전 호환

20초마다, 그리고 페이지를 떠날 때 이 브라우저에 자동 저장합니다. 메뉴가 열려 있거나 탭이 숨겨져 있으면 게임 시간은 진행되지 않습니다. 위기 자동 정지 설정도 이 브라우저에 기억합니다.

메뉴의 JSON 내보내기·가져오기로 다른 기기에 정착지를 옮길 수 있습니다. 자동 저장은 브라우저·사이트 주소별로 구분되며 기기 간 자동 동기화는 하지 않습니다. 새 정착지를 확정하면 현재 자동 저장을 바꿉니다.

- 파일 포맷: `frontier-colony-save`, 바깥쪽 포맷 버전은 1 유지.
- 엔진 상태 버전: 4.
- 가져오기: 4MB 이하, 버전·지도·자원·작업·예약·연구·전력·음식 장부를 검증.
- 실제 v1·v2·v3 저장의 지도, 자원, 주민 위치, 진행 작업은 보존하고 새 시스템 기본값을 추가.
- 기존 주민은 자율 일정으로 이관. 새로운 의료·여가·화재 상태와 소방·구조 작업 기본값을 추가.
- v3의 환자 운반·침상 예약·일정·화재와 v4의 제작 재료·장비·상인 상태를 검사하고 진행 중 저장도 복원.
- 이전 저장의 새 자원은 모두 0으로 시작하고, 장비 슬롯은 비어 있으며 생산 주문은 0개. 상인 첫 방문을 현재 시각 +80초에 예약. 기존 엔진 난수는 소비하지 않음.
- 기존 신호기 계획·완공본은 필요한 전기·통신 연구를 승계. 이미 달성한 승리도 유지.
- 불러오기에 실패한 원본은 자동 저장으로 덮어쓰지 않으며 메뉴에서 복구용 원본을 내보낼 수 있음.

## 검증과 범위

수용 테스트는 자원 보존, 예약 경합, 취소와 징집, 식사·수면·치료, 연구 노동·해금, 자재 수리, 우선 작업, 대형 이동, 방 개폐, 정전과 냉각, 식품 부패, v1·v2 저장 이관과 v3 결정성을 검증합니다. 추가로 구조·환자 운반·급식·침상 예약·화재·소방·일정·여가와 방향 엄폐를 확인합니다.

기본 UI와 같은 `seed=314159`, `standard` 난도에서 지도·자원·능력치·적·시계를 직접 수정하지 않고 공개 명령과 시간 진행만으로 전체 플레이를 완주하는 테스트가 있습니다. 연구·운반·신호 충전 도중 저장한 복원본의 미래 상태도 원본과 비교합니다. 자동 테스트의 진행은 한 가지 재현 가능한 전략이며 모든 플레이 방식의 승리를 보장하지는 않습니다.

v4 수용 테스트는 **88개 모두 통과**, 실패·건너뜀은 0개입니다. 기존 61개 회귀에 새 제작·장비·교역·v4 저장 23개와 실제 앱 UI 이벤트 4개를 더했습니다. 복수 제작자의 재료 경쟁, 모든 제작 중단의 반환, 장비 소유권과 실제 효과, 거래 실패의 무변경, 구버전 신규 필드 주입 방어를 검증했습니다.

기본 구조선 시나리오는 **1239.3 시뮬레이션 초**, 주민 **3명 생존**, 습격 **5회 방어**로 통과했습니다. v3의 채집 330·조리 50·부패 75·낙뢰 3·직접 진화 4도 유지됐습니다. 별도의 기본 맵 시나리오는 공개 명령만으로 **제작대 건설 → 도구 제작·운반 → 판매 → 대금 운반 → 소총 구매·운반 → 장착**을 첫 자연 방문 안인 180초 이전에 완료했습니다.

실제 `app.js`를 Node VM과 DOM 대역으로 실행해 **10개 패널**, 생산 주문, 장비 지급·취소·해제, 구매·판매와 수량 입력을 확인했습니다. 입력 포커스를 유지하면서 패널을 전환할 수 있고, 지난 방문 ID의 거래는 자원을 변경하지 않습니다. 기존 손상 저장 보호와 위기 자동 정지도 통과했습니다. 렌더러는 새 물품·장비·상인을 3개 레이어에서 실행하고 게임 상태 불변을 확인했습니다.
