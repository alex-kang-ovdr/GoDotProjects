# 변방의 기록 — Godot 핸드오프

- 작성일은 2026-11-27이다.
- 대상 프로젝트는 `FrontierColonyGodot`이다.
- 네이티브 Godot UI를 만들고 기존 JavaScript 정착지 시뮬레이션 규칙을 유지한다. 시뮬레이션은 로컬 Node.js 20+ 프로세스에서 실행한다.

## 기준선과 출처

기준 문서는 `docs/web-v4/README.md`, `docs/web-v4/ARCHITECTURE.md`, `docs/web-v4/docs/*.md`에 원문 그대로 옮겼다. 원본은 `D:\Github\GoDotProjects-worktrees\Forge-Games-brawlLabs\references\hub-original\WebProjects\RimWorld\Playable\Current`에 있던 변방의 기록 4.0 웹 플레이어블 기준 문서다. 상대 링크 구조인 루트 README·ARCHITECTURE와 `docs/`를 그대로 보존했다. 문서 안의 웹 배포 주소와 `../tests/...` 등 원본 웹 프로젝트 파일 경로는 역사적 출처를 가리키며 현재 Godot 프로젝트의 파일을 뜻하지 않는다.

시뮬레이션 모듈 7개는 `Forge-Games-brawlLabs/games/rimworld/Web`에서 이관했다. 원본과 SHA-256이 모두 일치한다. `main.tscn`은 네이티브 지도와 관리 화면을 띄우고, `scripts/colony_runtime.gd`가 `engine/runtime.mjs`를 로컬 Node 프로세스로 실행한다. Node가 시뮬레이션과 저장을 담당하고 Godot이 입력, 화면, 진행 배속을 담당한다.

## 런타임 동작

- 로컬 표준 입출력으로 새 게임, 시간 진행, 명령, 저장, 불러오기를 직렬 처리한다. 전체 지도 응답은 압축하고 구역 명령은 한 요청으로 묶는다. 종료할 때 자식 프로세스와 임시 파일을 정리한다.
- Node 실행 실패나 응답 오류는 진행을 멈추고 상태 표시줄에 알린다. 정착지 메뉴에서 새 게임이나 저장을 다시 열 수 있다. 저장 파일은 가져오기에 성공했을 때만 활성 상태를 교체한다.
- 새 게임은 표준 또는 여유 난도에서 기본 시드 314159로 시작한다. 고정 시뮬레이션 단계는 배속과 관계없이 기존 규칙을 따른다.

## 보존할 코어 규칙

### 시계·재현성·좌표

- 엔진 단계는 0.1 시뮬레이션 초, 환경 갱신은 0.5초다. 하루는 120 시뮬레이션 초이며 시작 시각은 08:00이다. UI 배속은 실시간 입력만 변환하고 엔진 단계 자체를 바꾸지 않는다.
- 난수 상태와 고정 단계 잔여분을 저장한다. 저장/복원, UI 상태 조회, 상인 계산은 기존 RNG 순서를 바꾸지 않아야 한다. 복원 시 새 지도 생성·시간 진행·파생 상태 갱신 없이 저장된 진행 상태를 복구한다.
- 타일·바닥 물품·경로는 정수 셀 좌표이며 렌더 중심은 `(x+0.5,y+0.5)`다. 주민·적·효과 좌표는 이미 중심을 나타내는 실수다.

### 작업·물류·환경

- 작업 흐름은 후보 선정 → 접근성 확인 → 예약 → 이동 → 준비/운반/작업 → 완료다. 취소·실패·징집·사망은 작업과 예약을 정리한다. 창고·바닥·운반 중 물품을 중복 계상하지 않는다.
- 완성 벽은 이동을 막고 문은 통과시킨다. 경로는 4방향 BFS이며 변화 시 재계획한다. 비징집 주민은 불을 피하는 안전 경로를 우선한다.
- 닫힌 방과 지붕, 실내 온도, 전력 연결망 및 발전·소비·충방전, 음식 배치의 신선도/부패는 실제 운영 상태다. 연구는 주민 작업으로 진행한다. 손상 건물은 재료를 운반해 수리한다.
- 일정은 주민별 시간대 작업/수면/여가를 결정한다. 허기·피로·통증·온도·여가가 기분에 반영된다. 고리 던지기 등 여가 시설, 의료 구조·치료·급식, 화재 번짐·소방, 방향에 따른 방벽 엄폐를 유지한다.

### 생산·장비·교역

- 작업대 건설은 목재 20·강철 8이며 전기/연구가 필요 없다. 제작은 자재를 실제로 수령·운반하고 진행 후 완제품을 작업대 바닥에 생성한다. 횟수 주문과 보유량 유지 주문을 지원한다. 작업 중 취소·징집·파괴·사망 시 전달 자재와 운반 중 자재를 각각 한 번만 반환한다.
- 보유량 유지 목표는 창고·바닥·일반 운반·장착·진행 중 산출 예정품을 포함한다. 제품은 작업 도구(강철 8·목재 4), 방탄 조끼(강철 16), 개량 소총(강철 18·목재 8)이다.
- 장비는 주민이 창고에서 실물 수령 후 장착한다. 도구는 건설·수리·농사·채집·채광·제작 속도 +25%, 조끼는 총탄 피해와 총상 출혈 증가 −35%, 소총은 사거리 9칸·피해 +35%·명중 +4%p·사격 간격 1.2초다. 중단/해제/사망 시 소유권은 한 번만 반환한다.
- 상인은 새 게임 시뮬레이션 80초에 방문을 예약하고, 도착 후 100초 체류한다. 퇴장 완료 220초 후 다음 방문을 예약한다. 거래는 재고·은화·거리/접근·상태를 원자적으로 검증한다. 구매 물품과 판매 대금은 상인 위치 바닥에 생성되므로 운반 전 창고에서 사용할 수 없다. 판매는 창고 수량만 허용한다. 방문 RNG는 기존 엔진 RNG를 소비하지 않는다.

### 저장·위기 종료 조건

- v1·v2·v3 저장을 가져오며 기존 지도·RNG·작업·운반·시간을 유지한다. 신규 자원인 은화는 새 게임 60, 이전 저장 0부터다.
- 연구·전력·냉장·식량·의료·화재·징집 방어를 유지하며, 장거리 통신 연구 후 구조 신호를 충전한다. 50% 충전 시 최종 습격이 발생한다. 방어를 마치고 화재가 없는 조건 등 신호 충전 규칙을 유지해 전송을 완료한다.

## 검증 범위

- 보관본 `PlayHub-Platform/references/hub-original/WebProjects/RimWorld/Playable/Latest_Playable.zip`의 모듈 7개를 이 프로젝트의 이관본으로 교체한 임시 복사본에서 기존 테스트 88개가 모두 통과했다. 기본 지도에서 냉장 창고·연구·최종 습격·구조 전송 완주, 교역과 제작, 의료와 소방, 구버전 저장 마이그레이션을 포함한다.
- `tests/play_smoke.gd`를 Godot 4.7.2와 Node 22.16에서 실행했다. 지도에서 문·침대 건설과 경작지 지정을 시작하고, 실내 침대 완공, 전기 공학 해금, 10개 관리 탭, 징집과 대형 이동, 저장 복원을 확인했다.
- Godot 화면의 연속 완주와 Windows 이외 환경의 실행은 별도 검증 범위다. 기준 웹의 조작과 화면은 Godot 입력과 화면 배치에 맞춰 변경했다.
