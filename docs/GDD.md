# Captain Salvage — Game Design Document

## 제품 정의

`Captain Salvage`는 Godot GDScript 하나로 PC, Android, Web에 내보내는 탑다운 2D 물리·모듈형 우주 전투 프로토타입이다. 플레이어는 취약한 지휘 코어를 조종하고, 전투·충돌·회수·재조립으로 즉석 함선을 만든다. 우주선과 부유 부품은 마인크래프트풍 박스·도트 텍스처로 보이도록 렌더링하지만, 이동·투사체·충돌은 모두 2D다. 장거리 잔해 항로를 지나 세 정거장과 두 중간 보스를 돌파한 뒤 최종 보스를 격파하는 것이 한 번의 목표다. 원작의 코드, 이름, 아트, 음향이나 콘텐츠는 포함하지 않는다.

## 문서 상태

- **이식 기준**: 아래 규칙은 GDScript 이식의 수락 기준이다. M20에서 검증한 기본 조립·방어막·탄약 규칙 외 항목은 아직 이식 완료가 아니다. 정확한 상태는 [GDScript SSOT 이식 계획](GDSCRIPT_SSOT_MIGRATION.md)을 우선한다.
- **배포 구성**: PC/Android/Web용 Godot export preset은 존재한다. 실제 Android 설치·Web HTTPS·성능은 아직 기기와 호스트에서 확인하지 않았다.
- **출처 확인됨**: 원작·리메이크의 고수준 노획 및 조립 루프는 [References](../References/CAPTAIN_FOREVER_RESEARCH.md)에 기록한 출처로 확인했다.
- **설계 후보, 미플레이테스트**: 30분 세션 길이, 난이도, 재미, 최소 사양 60fps는 실제 플레이어나 최소 사양 기기에서 검증하지 않았다.

## 플레이어 판타지와 성공 조건

플레이어는 이동 중인 정비사 함장이다. 작은 리그로 출발해 충돌을 버티고, 온전한 부품을 골라 붙이고, 손상된 장착 부품도 떼어 최적 위치에 다시 연결한다. 성공은 두 중간 보스를 격파해 `VOID WARDEN`을 활성화하고 그 지휘 코어를 파괴하는 것이다. 플레이어 지휘 코어가 0 HP가 되면 즉시 패배한다.

## 30분 항로 가설

출발점 `(9,000, 10,000)`에서 최종 목표 `(166,000, 83,000)`까지 경로상 시설을 따르는 거리는 약 17만 월드 단위다. 시작 함선의 추진·감속 계수로 계산한 순항 후보에 보스전·회수·정거장 정비 시간을 더해 약 30분을 목표로 삼는다. 이는 런타임 계측이나 플레이테스트 증거가 아닌 설계 가설이며, [월드 항로 설계](WORLD_ROUTE.md)가 보정 절차를 정의한다.

## 핵심 루프

1. `W/S`, `A/D`로 관성을 가진 리그를 조종하거나, 빈 공간 클릭/터치로 자동 항법을 지정해 다음 표식으로 이동한다.
2. 랜덤 적을 상대해 코어를 우선 파괴하고, 보존된 부품을 회수한다.
3. 필드 중립 부품을 좌클릭으로 들어 올린 뒤 원하는 빈 연결 격자에서 릴리스해 장착한다.
4. 이미 붙은 비코어 부품은 `Shift` + 클릭으로 들어 올리고 다른 빈 연결점에 클릭해 재장착한다.
5. 손상·열·질량을 정거장에서 회복하거나 업그레이드로 한 축을 강화한다.
6. 두 중간 보스를 순서대로 격파하고 최종 보스를 처치한다.

## 조작과 상태

- `W/S`: 장착된 메인/후진 추진기의 힘으로 전진/후진한다. `A/D`는 RCS 추진기의 접선 힘으로 회전한다. 속도·가속도·각속도는 질량, CoM, 관성모멘트와 감쇠로 시뮬레이션한다. 메인 추진기 둘 이상은 CoM 기준 전진 토크를 최소화하도록 출력을 자동 보정한다.
- 적 함선 클릭/터치: 적 전체 바운드 반경을 클릭하면 적 함선을 표적으로 지정한다. 적 함선 파트는 중립 부품이 아니므로 회수 대상이 될 수 없다. 표적이 살아 있는 동안 `Space`, `F`, 우측 하단 HUD 무기 카드는 표적 중심을 자동 조준한다.
- `Space`: 레이저와 장착한 머신건·레일건을 발사한다. 레이저는 에너지 무기이고, 머신건은 `BULLET BAY` 1발, 레일건은 `BULLET BAY` 4발을 소모한다.
- 우클릭 짧은 클릭: 적을 누르면 표적 지정 뒤 장착된 `MISSILE` 발사기로 유도탄을 쏜다. 빈 공간을 누르면 자동 항법 목적지를 지정한다. `MISSILE BAY` 2발이 필요하다. 우클릭 드래그는 종전대로 Top-View 수평 회전이다.
- 빈 공간 클릭/터치: 회전 RCS와 실제 메인 추진기로 목적지를 향하는 자동 항법을 시작한다. `W/S/A/D`의 수동 추력은 자동 항법을 해제한다.
- 중립·회수 부품: 부품 중심 72px 안에서 좌클릭을 누르면 커서 운반 상태가 된다. 유효한 연결 격자에서 마우스/터치를 놓으면 해당 위치에 장착되며, 유효하지 않은 위치에서는 원래 자리로 돌아간다. 플레이어는 최대 18개 모듈을 가진다.
- `Shift` + 장착 부품 클릭: 그 부품을 운반 상태로 만든다. 강조된 인접 빈 소켓을 클릭하면 같은 내구도와 균열 상태로 재장착한다. 코어는 이동할 수 없다.
- `E`: 정거장 반경 220px 안에서 사용한다. 최초 한 번은 업그레이드와 전면 수리, 이후에는 전면 수리만 한다.
- `R`: 새 항해. PC는 키보드·마우스·휠을 사용한다. 우클릭 드래그는 카메라의 수평 방향만 회전한다.
- Android의 가로 화면에서는 화면 좌측 전진·후진·회전과 우측 `FIRE`·`MSL`·정거장·`MOVE`·줌 조종계를 제공한다. 누르는 동안만 가상 키가 유지된다. `MOVE` 뒤 장착 모듈 탭은 `Shift` + 클릭과 같은 재장착 시작 동작이다.
- Android 핀치 줌, 게임패드와 키보드 전용 부품 선택은 아직 없다.

## 시점과 블록형 메시

- 기본값은 회전 0의 **직교 Top-View**다. 카메라는 원근·피치·롤·기울어진 뷰를 사용하지 않으며, 플레이어를 따라 2D 월드 중심만 이동한다.
- PC의 우클릭 드래그는 카메라의 수평 방향(yaw)만 바꾼다. 월드·배경·운석은 함께 회전하고 HUD·표식 텍스트는 읽기 쉬운 화면 방향을 유지한다. 이 회전은 물리 좌표·충돌 반경·사격 거리·함선 조종 방향을 바꾸지 않는다.
- 마우스 휠 또는 `+`/`-`로 0.7×~1.5× 범위에서 확대·축소할 수 있다. 줌은 직교 화면 범위만 바꾼다.
- 모듈은 위에서 내려다본 마인크래프트풍 박스다. 상단 베벨, 모듈별 결정적 도트 텍스처, 특수 장치 상단 패턴으로 재질을 구분한다. 맞닿은 점유 격자 사이에는 9-slice 외곽선·밝은/어두운 베벨을 생략하고, 함선 외곽 윤곽에만 남긴다.
- 이 표현은 외부 3D 엔진·WebGL·3D 충돌체를 사용하지 않는다. 시각 박스와 모든 이동·투사체·충돌은 2D다.

## 부품·전투·파괴

- 플레이어 `core`는 시작 시 200 HP(기본의 2배), 질량 2다. 지휘 코어가 파괴되면 해당 리그가 종료된다. 적 코어 수치는 난이도별로 별도다.
- 파트별 표시명·설명·Hull·Shield·Power·무기 유형·전진/후진/RCS 추진력·탄약은 [파트 튜닝 CSV](PART_TUNING.md)에서 조정한다. `thruster`는 메인 추력 4,750(기존의 5배), `reverse_thruster`는 약한 후진 추력 220, `rcs_thruster`는 회전용 접선 추력 1,800(기존의 5배)을 제공한다. 후진 추진력은 이번 조정 범위에 포함하지 않았다. 색·질량·형태·격자 점유 같은 구조 데이터는 [balance](../Godot/scripts/balance.gd)에 남긴다.
- 초기 주무장은 레이저 2개다. 최신 사양의 좌·우 `MINI MSL` 보조 런처는 근거리 적을 자동 지정해 2초간 유도하고 급가속한다. 이는 `MISSILE BAY` 재고를 1발씩 소비하는 자동 보조 무장이며, 수동 `MISSILE` 주무장과는 다르다.
- `MACHINE GUN`·`RAILGUN`은 `BULLET BAY`만, `MISSILE`·`MINI MSL`은 `MISSILE BAY`만 쓴다. 같은 종류의 부유 탄약고는 드래그 릴리스로 병합할 수 있다. 더 높은 현재 내구도의 쪽이 남아 다른 탄약고의 탄약·용량·질량을 합치고 최대/현재 HP의 일부를 강화하며, 병합 결과는 계속 커서에 든다.
- 구조 파트는 `BLOCK` 1칸, `BEAM-2/3/4` 길이 2·3·4칸, `PLATE-4` 2×2 정사각기둥, `WEDGE` 1칸·`LONG WEDGE` 2칸 삼각 기둥이다. 다칸 파트는 모든 점유 격자가 비어야 장착되며, 회수·재장착 때 사용 가능한 2D 방향을 자동 선택한다.
- 플레이어 레이저는 기본 7 피해, 0.28초 쿨다운이다. Lyra 업그레이드는 피해를 +2 한다. 열이 100을 넘으면 발사할 수 없다. 기본 냉각은 초당 18이다.
- 각 모듈은 원형 접촉 반경을 갖는다. 함선 대 함선의 모듈 충돌은 겹침 해소와 충격량 반발을 적용하며, 상대 속도 115 초과 충격은 양쪽 접촉 부품에 1–7 피해를 준다. 부유 부품은 함선 모듈 및 서로와 충돌한다.
- 운석은 별도 2D 원형 물리체다. 소형(반경 14, 질량 1.4)은 충돌·반발·스파크만 발생시키며 피해를 주지 않는다. 중형(반경 27, 질량 7.5)은 충격량 350 초과부터, 대형(반경 46, 질량 18)은 430 초과부터 가장 가까운 함선 모듈에 피해를 준다. 피해는 감산 질량과 접근 상대속도를 곱한 충격량에 비례하며, 중형은 1–8, 대형은 1–15로 제한한다.
- 운석의 외곽선·회전은 2D 다각형 렌더링이고, 운석-함선·운석-운석 모두 원형 2D 충돌만 쓴다. 블록형 3D 표현은 우주선과 부유 부품의 시각 메시로 한정한다.
- 피해를 받은 모듈에는 체력 비율에 따라 최대 다섯 개의 균열이 누적된다. 일반 모듈 파괴 시 금 간 비회수 파편으로 분리되고, 코어가 먼저 파괴된 적 리그의 살아 있는 모듈은 회수 가능 부품으로 분리된다. 피격·충돌·파괴에는 스파크 파티클을 사용한다.
- 함선·운석 충격으로 파트가 실제 제거되면 해당 함선의 **렌더 본체만** 0.16초 동안 흔들린다. 일반 파트는 최대 3.2px, `laser` 무기는 최대 5.2px이다. 카메라, 배경, HUD, 표식, 물리 충돌체는 흔들리지 않는다. 투사체만으로 파트가 파괴되는 경우에는 이 충격 흔들림을 쓰지 않는다.
- `SHIELD GEN`은 층당 피해를 한 번 흡수하고, 비어 있는 층을 주기적으로 복구한다. 실제 최대 레이어는 `min(5, 생성기 수 + 업그레이드, 모든 생성기 커버 질량 ÷ 현재 함선 질량)`이다. 기본 함선은 1 레이어로 시작한다. Perseus 업그레이드는 레이어 상한과 복구 시간을 강화한다. 좌측 상단의 파란 채움 사각형은 현재 레이어 수를, 함선을 감싼 방어막의 고정 푸른 불투명도는 현재 레이어 수를 나타낸다. 그 불투명도는 게임 밸런스가 아닌 [visual tuning](../Godot/scripts/visual_tuning.gd)에서만 조정한다.
- 피격으로 모듈이 제거될 때는 지휘 코어(컨트롤 타워)를 루트로 4방향 점유 격자 연결 그래프를 다시 계산한다. 코어와 끊긴 덩어리는 내구도·탄약·질량을 보존한 회수 가능한 중립 부품으로 흩어진다. 수동 재장착 중의 임시 분리, 관절 물리, 부품별 충돌 회전 토크는 아직 구현하지 않았다.

## 배경과 가독성

배경은 CC0 성운·별 텍스처 두 장을 낮은 알파와 서로 다른 패럴랙스로 겹치고, 화면 인접 격자만 해시로 계산하는 결정적 2D 별 레이어를 월드 좌표에 그린다. 전투·인터랙션 요소는 전경의 색·라벨·체력 바로 구분한다. 절차적 3D 은하 생성기는 이 2D 전투 화면의 현재 범위 밖이다. 생성기 조사와 자산 라이선스는 [space references](../References/SPACE_BACKGROUND_REFERENCES.md)를 참조한다.

## 랜덤 스폰과 난이도

- 일반 적은 플레이어에서 760–1,150px 떨어진 위치에 나타난다. 레벨은 `항로 구역 + 플레이어 부품/업그레이드 파워`로 1–10 범위에서 계산한다.
- 일반 적은 레벨 3에 추가 레이저, 레벨 5에 배터리, 레벨 7에 추가 장갑을 받는다. 레벨은 코어 HP, 사격 피해에도 반영된다.
- 일반 적 동시 상한은 진행도와 플레이어 파워에 따라 2–5척이다. 스폰 간격은 5–12초다. 필드 중립 부품은 8–14초마다, 회수 가능한 중립 부품 10개 미만일 때만 생성한다.
- 이것은 성장에 대응해 위협을 올리는 디렉터 규칙이다. 위협이 너무 빨리 누적되거나, 강한 장비가 약한 적만 소환하는지 여부는 플레이테스트에서 관찰해야 한다.

## 정거장·보스·경로

- Kepler Repair Dock: 코어 최대 HP +30과 전면 수리.
- Lyra Control Tower: 레이저 피해 +2, 유도탄 유도 성능·사정거리 +1과 전면 수리.
- Perseus Reactor Bay: 기본 냉각 +12/s, 방어막 레이어 상한 +1, 복구 시간 -1초와 전면 수리.
- Rift Breaker(구역 3)와 Crown Eater(구역 5)는 순서대로 활성화되는 중간 보스다. 보스의 코어 파괴 시 보존된 모듈과 근처 중립 보상 부품 세 개가 분리된다.
- Void Warden(구역 7)은 두 중간 보스가 모두 격파되기 전에는 활성화되지 않는다. 세 정거장은 선택적 회복·성장 지점이며, 보스 해금에는 중간 보스 격파가 필수다.

## 성능·접근성 예산

- 동시 일반 적 5, 보스 1, 플레이어 파트 18(최대 점유 격자 72), 투사체 160, 부유 부품 60, 운석 48, 파티클 220이 구현 상한이다. 오래된 투사체·부품·운석·파티클부터 제거한다.
- 배경 별은 화면 인접 72px 격자만 계산해, 월드 크기에 비례한 별 배열을 보관하지 않는다. 다칸 파트도 실제 점유 셀로 피격·충돌을 검사하되, 함선 쌍마다 프레임당 충돌 해소는 4회로 제한한다. 부유 부품 상호 충돌은 상한 60개에서 최대 1,770쌍, 운석 상호 충돌은 상한 48개에서 최대 1,128쌍만 검사한다.
- `aria-live="polite"` HUD와 색 이외의 텍스트 라벨을 제공한다. `prefers-reduced-motion`의 UI 전환 최소화는 유지하지만, 화면 리더 전투 서술·키보드 전용 부품 선택은 아직 없다.
- Web 내보내기는 WebAssembly/WebGL 2를 사용한다. 이 예산은 저사양 PC·Android 적합성 증명이 아니다. 대표 전투 구간을 최소 지원 기기에서 프로파일링하기 전에는 60fps·오프라인 동작을 주장하지 않는다.

## RPG 이벤트·퀘스트·튜토리얼

- 출항 시 `CONTROL TOWER` RPG 대화가 열리고, “비행 절차 시작/안내 건너뛰기”를 선택한다. 비행 절차는 실제 기동 → 중립 부품 회수 → 빈 소켓 릴리스 순서로 동작하며, 퀘스트 HUD가 현재 단계를 표시한다.
- 첫 적대 신호/격파와 세 정거장 접근·정비, 보스 스폰은 기능 아이콘과 나레이션을 가진 비차단형 대화 이벤트를 큐에 추가한다. 보스 디렉터가 `boss_name`을 전달하면 중간/최종 보스용 이벤트를 재사용한다. 전투와 물리는 대화 중에도 계속된다.
- 대화 UI는 정보·퀘스트 안내를 위한 것이며 스토리 분기, 영구 퀘스트 보상, 음성 연기는 아직 범위 밖이다.

## NPC 우주선 행동

- 일반 NPC는 로밍이 기본이며, 플레이어에게 피격되면 공격한다. 일부 레이더형 NPC만 근거리 진입을 선제 공격으로 간주한다.
- 일부 대화형 NPC는 무기 사거리 근처에서 회수 의뢰 또는 사격 통제 구역 이탈 요구를 제시한다. 회수 의뢰는 표식 중립 부품 장착으로 완료하며, 이탈 요구를 무시하면 적대 전환한다.
- 행동 비율과 거리 값은 `Balance.NPC_AI`의 공용 밸런스 데이터로 관리한다. NPC의 전진·후진·RCS 입력은 플레이어의 50%로 제한해, 5배 강화된 플레이어 추진력과 구분한다. 구현 초기값이며 플레이테스트 밸런스 확정값은 아니다.

## 물리 갈고리

- `G`로 마우스가 가리키는 다른 우주선에 갈고리를 발사한다. 명중 뒤 `PinJoint2D` 링크 체인이 실제 2D 물리 견인력을 전달하며, 다시 `G`를 누르거나 과신장되면 해제된다.
- 함선↔함선 충돌은 유지한다. 체인 링크는 충돌 레이어/마스크가 없어 함선↔체인의 충돌·일반 상호작용은 없고, 연결 대상에 대한 견인 제약만 남긴다.
- 갈고리에는 HP가 있어 레이저·총알·미사일이 비행 머리 또는 체인 선분을 맞히면 피해를 주며, HP가 0이면 연결이 끊어진다.

## 수락 시나리오

1. 플레이어가 적 또는 부유 부품에 충돌했을 때 겹침이 해소되고 큰 충격은 피해·스파크를 낸다.
2. 피격 모듈에 균열이 보이고, 파괴된 비코어 모듈은 금 간 파편으로 분리된다.
3. 중립·적 유래 회수 부품을 클릭해 붙이고, 장착 부품 하나를 떼어 다른 빈 소켓으로 재장착할 수 있다.
4. 각 정거장은 최초 접근 시 지정 업그레이드와 수리를, 재방문 시 수리만 제공한다.
5. 플레이어 파워 또는 항로 구역 상승 뒤 생성되는 일반 적의 레벨·구성이 강해진다.
6. 두 중간 보스를 격파하기 전 최종 보스 게이트는 잠기며, 이후 최종 보스를 격파하면 승리 오버레이가 표시된다.
7. 운석 지대에서 소형 운석은 함선을 밀어내도 부품 체력을 바꾸지 않고, 충분히 빠른 중·대형 운석은 접촉 위치와 가장 가까운 모듈에 제한된 피해·균열·스파크를 낸다.
8. PC 키보드·마우스 조작을 유지하고, Android 가로 화면의 터치 조종계로 추진·회전·사격·정거장·줌·재장착 시작을 수행할 수 있다. Web은 같은 GDScript를 WebAssembly/WebGL 2로 내보낸다.
9. 기본 직교 Top-View에서 우클릭 드래그로 수평 방향만 회전하고, 기울임·원근 없이 클릭·소켓 좌표가 정확히 역변환된다. 연결된 박스는 외곽만 베벨을 보이며, 충격 파트 파괴에는 해당 함선 본체만 짧게 흔들린다. 무기 파괴 흔들림은 일반 파트보다 크다.
10. 중립 부품은 커서 드래그·릴리스로 원하는 유효 소켓에 붙고, 같은 종류 탄약고는 병합 뒤 더 튼튼한 결과가 커서에 남는다. 총알·미사일 재고는 서로 섞이지 않는다. 연결 파트가 파괴되면 지휘 코어와 끊긴 덩어리는 중립 부품으로 분리된다.
11. 기본 방어막은 첫 피해를 흡수하고, 현재 함선 질량이 생성기 커버 용량을 넘으면 생성 가능한 레이어가 줄어든다. HUD 채움 사각형과 레이어별 고정 방어막 불투명도가 같은 현재 레이어를 표현한다.
12. 출항 튜토리얼 선택, 정거장·보스 이벤트 대화, Lyra 컨트롤 타워의 유도·사거리 향상이 동작한다.
13. 적 함선을 클릭하면 회수하지 않고 표적만 지정하며, 표적 생존 중 주무장·유도 미사일·미니 미사일이 표적을 자동 조준한다. 빈 공간 클릭/터치는 실제 RCS·메인 추력을 쓰는 자동 항법을 시작하고 수동 추력은 이를 해제한다. 우측 하단 무기 카드에는 무기 타입·준비 상태·재고가 표시되고 클릭/터치로 발사한다.

세부 수동 절차와 계측 기록 양식은 [TEST_PLAN](TEST_PLAN.md)을 따른다.
