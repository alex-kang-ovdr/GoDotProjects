## 0. 핵심 용어 구분 (혼동 방지)

문서·DB·API·운영 대시보드 전반에서 **인프라 원가 측 크레딧**과 **플랫폼 과금 재화**를 엄격히 구분한다.

| 용어 | 표기 | 주체 · 성격 | 용도 및 정산 원칙 |
|---|---|---|---|
| **구글 크레딧 (GCP Credit)** | `GCP Credit` | **플랫폼 운영자 → Google Cloud** (인프라 원가 측) | GCP 무료 체험·스타트업 크레딧 등 클라우드 청구서 상계용. 초기 운영비 완충 수단일 뿐이며, **본 문서의 원가·마진 시뮬레이션은 구글 크레딧 소진 이후의 실현금 원가 기준**으로 산정한다. |
| **허브 포인트 (Hub Point)** | `P` (Point) | **제작자 ↔ PlayHub 플랫폼** (매출 · 과금 재화 측) | 제작자가 멀티플레이 서버 이용료로 충전·차감하는 플랫폼 내부 포인트 (`1 P = \$0.01`, 약 14원). **24시간·전 요일 단일 고정 단가**를 적용하며 **피크 할증 및 비피크 할인 없음**. |

## 1. 설계 목표와 핵심 원칙

1. **배포 모드 선택 단순화**: 제작자가 배포 시 `SinglePlay` / `MO` / `MMO` 중 하나를 선택하면, 해당 모드에 맞는 호스팅·스케일링·과금 정책이 자동 적용된다.
2. **동접 상한 없음 (유료 기준)**: 바이럴·인기 급상승 시 트래픽 손실이 없도록 인위적 동접 상한(Max CCU Cap)을 두지 않고 자동 확장한다. 대신 **허브 포인트 잔액 + 소진 속도(Burn Rate) 이중 트리거 메일 노티**와 **소진 시 안전 슬립**으로 예기치 않은 중단·과금 사고를 방지한다.
3. **허브 포인트 단일 고정 요율**: 시간대·요일에 따른 피크/비피크 차등 할인·할증을 두지 않아 제작자 비용 예측과 정산을 단순화한다. 시간대별 마진 방어는 인프라 측(Warm 풀 동적 축소, Spot 혼합, 글로벌 분산)으로만 처리한다.
4. **비인기 게임(롱테일) 유지비 ≈ ₩0**: Scale-to-Zero, 공용 Warm 런타임 풀, 멀티테넌트 컨테이너 팩킹, MMO 자동 슬립·복원으로 동접이 적은 게임의 대기 비용을 사실상 제거한다.
5. **로비 무비용화 (Lazy Connect)**: 동기화가 필요 없는 로비·상점·랭킹·매칭 대기 트래픽은 게임 서버에 절대 연결하지 않고 Hub 무상태 API와 공용 경량 Lobby Gateway로 처리한다.
6. **Egress 역마진 차단**: 제어면(Hub/Forge/DB/GCS)은 기존 GCP 3단계-Lite 스택을 유지하되, 실시간 게임 서버 실행 풀은 **저Egress 전용 노드 풀(하이브리드)**로 분리해 단위 마진 58~63%를 확보한다.

## 2. 배포 분류(`deployMode`) 선택 모델 및 Manifest 계약

### 2.1 3대 배포 분류 비교

| 분류 | 대표 장르 / 예시 | 서버 실행 토폴로지 | 스케일링 · 수명주기 |
|---|---|---|---|
| **SinglePlay** | 퍼즐, 아케이드, 1인 액션 | **게임 서버 없음** — GCS + Cloudflare CDN 정적 서빙 (쿠키 없는 게임 전용 origin) | 트래픽 무관 상시 서빙 (허브 포인트 0 P) |
| **MO** (Multi-Online · 룸/매치형) | BrawlLabs(3v3), Fortress War, 배틀로얄, 협동 룸 | **온디맨드 세션 워커 풀** + WSS Gateway (`JoinTicket` 인증). `node-wss-v1` / `godot-linux-wss-v1` 공용 수용 | **Scale-to-Zero 기본**: 매칭·방 생성 시 2~4초 기동 → 전원 퇴장 후 유휴 TTL(2~3분) 경과 시 자동 종료 |
| **MMO** (지속 월드 · 대규모 동접) | Tappy Chicken MMO, 오픈필드, 광장, 지속형 서바이벌 | **전용 Linux VM / GKE(Agones) 실행 풀** + **자동 채널(Shard) 분할** + Turso/PostgreSQL 상태 영속화 및 주기 스냅샷 | **기본 자동 슬립 + 상태 복원**(유저 0명 10~15분 경과 시 스냅샷 후 종료), 필요 시 제작자 옵션(`alwaysOn: true`)으로 24시간 상시 유지 |

## 3. 멀티플레이 서버 운영 아키텍처

### 3.1 전체 토폴로지 (GCP 제어면 + 저Egress 게임 실행 풀 하이브리드)

```text
[클라이언트 (Web WASM / Native)]
  │
  ├─ 1) 정적 에셋 · SinglePlay 게임
  │     └─► Cloudflare CDN ─► GCS (us-west1, 쿠키 없는 게임 origin)
  │
  ├─ 2) 타이틀 · 프로필 · 인벤토리 · 상점 · 랭킹 (동기화 불필요)
  │     └─► Hub 무상태 HTTP API (GCP Cloud Run) ─► Turso (libSQL)
  │
  ├─ 3) 방 목록 · 매칭 큐 · 파티 초대 · 로비 채팅 (동기화 불필요)
  │     └─► 플랫폼 공용 Lobby / Matchmaking Gateway (멀티테넌트, 1대로 수만 명 처리)
  │
  └─ 4) "게임 시작 / 매칭 완료 / 월드 입장" 시에만 (Lazy Connect)
        └─► WSS Gateway (JoinTicket 60초 검증 · DDoS/패킷 Rate Limit · 1분 단위 계량)
              └─► [게임 서버 실행 풀 (저Egress 전용 노드 / Spot + On-Demand 혼합)]
                    ├─ Warm 공용 런타임 대기 풀 (2~4초 패키지 마운트 기동)
                    ├─ 멀티테넌트 격리 컨테이너 (1 월드 = 1 프로세스, 비인기 게임 10~20개 팩킹)
                    └─ 전용 고성능 노드 (인기 MO/MMO 자동 승격 · 채널 자동 증설)
```

### 3.2 비인기 게임(롱테일) 0원 근접 운영 전략

UGC 플랫폼은 전체 게임의 90~95%가 동접 0~2명 구간에 머문다. 게임별 전용 서버를 사전 할당하지 않고 다음 3계층으로 운영한다.

1. **공용 Warm 런타임 풀 + Scale-to-Zero**:
   - 게임별 전용 컨테이너를 미리 띄우지 않고, 빈 공용 런타임(Godot 4.7.2 Headless / Node 24)만 소수 대기시킨다.
   - 첫 유저 접속 시 해당 게임의 `.pck` 또는 서버 번들을 로컬 캐시/GCS에서 마운트해 **2~4초 내 기동**한다.
   - 전원 퇴장 후 유휴 TTL(MO 2~3분, 슬립형 MMO 10~15분) 경과 시 즉시 회수한다.
2. **1서버 다중 월드 팩킹 (1 월드 = 1 격리 프로세스)**:
   - 물리 호스트(예: 4~8 vCPU) 1대에 서로 다른 비인기 게임월드 10~20개를 **OS 컨테이너(cgroups/gVisor) 단위로 격리 배치**한다.
   - **주의**: 1개 Godot 프로세스 안에 여러 월드를 혼합하지 않는다. 1월드 = 1프로세스 격리를 유지해야 ① 크래시·무한루프 전파 차단, ② CPU/RAM 상한 및 허브 포인트 계량 정확성, ③ UGC 보안 격리가 보장된다.
   - 특정 게임이 인기 급상승으로 임계치(예: 50~100 CCU)를 넘기면 자동으로 **전용 노드로 승격**한다.
3. **MMO 자동 슬립 + 상태 복원 (On-Demand Persistent World)**:
   - 마지막 플레이어 퇴장 후 10~15분 경과 시 월드 상태를 Turso/GCS 스냅샷으로 저장하고 프로세스를 종료한다(스토리지 소액 외 유지비 ≈ ₩0).
   - 다음 유저 접속 시 3~5초 로딩("월드를 깨우는 중...") 동안 마지막 스냅샷을 복원해 이어서 플레이한다.
   - 24시간 무인 시뮬레이션이 꼭 필요한 게임만 `alwaysOn: true` 옵션으로 상시 허브 포인트를 지불한다.

### 3.3 채널(Channel / Shard) 자동 분할 전략

동접 상한 없이 확장하려면 단일 프로세스의 동기화 한계(Godot 4 Headless 20Hz 기준 전투/물리 게임 50~150명, 경량 이동 게임 150~300명)를 넘는 시점에 **자동 채널 분할**이 필수다.

- **단일 채널 구간 (동접 < 채널 정원)**: 채널 선택 UI를 숨기고 1채널로 운영해 유저 분산(텅 빈 맵)을 방지한다.
- **자동 증설 (Scale-out)**: 채널 정원(예: 80~150명) 도달 시 새 채널 프로세스를 자동 기동한다. 신규 입장자는 ① 친구/파티 소재 채널 → ② 60~80% 채워진 채널 순으로 자동 배정한다.
- **자동 축소 (Drain → Scale-in)**: 새벽 등 동접 감소 시 신규 입장을 1번 채널로 유도하고, 빈 채널은 자연 소멸시켜 허브 포인트 낭비를 막는다.
- **MO 게임**: 방(Room/Match) 자체가 분할 단위이므로 별도 채널을 두지 않는다.

### 3.4 동기화 없는 로비 화면 처리 (`Lazy Connect`)

접속자의 30~50%가 머무는 타이틀·커스터마이징·상점·랭킹·매칭 대기 화면이 게임 서버를 점유하지 않도록 분리한다.

| 화면 / 기능 | 처리 계층 | 허브 포인트 차감 |
|---|---|---|
| 타이틀 · 설정 · 튜토리얼 · 로컬 커스터마이징 | 클라이언트 로컬 | **0 P** |
| 프로필 · 인벤토리 · 상점 · 랭킹 · 업적 | Hub 무상태 HTTP API + Turso | **0 P** |
| 방 목록 · 매치메이킹 큐 · 파티 초대 · 로비 텍스트 채팅 | 플랫폼 공용 경량 Lobby/Matchmaking Gateway | **0 P** |
| 실제 게임 플레이 (MO 매치 / MMO 월드) | WSS Gateway → 게임 서버 실행 풀 | **1분 단위 고정 요율 차감** |
| *(선택)* 실시간 3D 광장형 로비 (`realtime_3d_lobby`) | 저주파(5~10Hz) 소셜 채널 서버 | **선택 시 차감** |

- **AFK 자동 퇴장**: MMO 월드에서 일정 시간(기본 20분) 무입력 시 캐릭터 선택/로비 화면으로 자동 이동해 유휴 포인트 소모를 차단한다.
- **보안 경계**: 게임 서버 컨테이너는 외부 임의 아웃바운드 네트워크를 차단(암호화폐 채굴·프록시 악용 방지)하며, Hub API 통신만 내부 프록시로 허용한다.

## 4. 허브 포인트 과금 모델 및 Free 티어 제약

### 4.1 서버 스펙 프리셋 및 허브 포인트 단가 (하이브리드 · 단일 고정 요율)

- **기준 단가**: **`1 P (Hub Point) = \$0.01` (약 14원)** — 소수점 없는 정수 원장 계산
- **요율 원칙**: **24시간·평일/주말 구분 없이 단일 고정 요율 적용 (피크 할증 · 비피크 할인 없음)**
- 제작자는 인프라 상세 대신 **프리셋**만 선택하며, 동접 증가 시 해당 프리셋 인스턴스가 자동 증설된다.

| 프리셋 | 스펙 (vCPU / RAM) | 권장 용도 | 인스턴스당 권장 동접 (20Hz) | 시간당 차감 (고정) | 포함 Egress | 월 24×7 상시(720h) |
|---|---|---|---:|---:|---:|---:|
| **Free-Nano** | 0.25 vCPU / 512 MB | Free MO 체험 전용 | 최대 8~10 CCU | 무료 쿼터 | 공정 한도 | 월 무료 한도 제한 |
| **Nano** | 0.25 vCPU / 512 MB | 비인기 MO / 초소형 룸 | ~10 CCU | **3 P / hr** (~42원) | 0.2 GB/h | 2,160 P (~3.0만원) |
| **Micro (S)** | 0.5 vCPU / 1 GB | 소규모 MO 룸 | ~30 CCU | **6 P / hr** (~84원) | 0.5 GB/h | 4,320 P (~6.0만원) |
| **Small (M)** | 1 vCPU / 2 GB | 중형 MO / 소형 MMO | ~80 CCU | **12 P / hr** (~168원) | 1.2 GB/h | 8,640 P (~12.1만원) |
| **Medium (L)** | 2 vCPU / 4 GB | MMO 기본 채널 | ~200 CCU | **24 P / hr** (~336원) | 3.0 GB/h | 17,280 P (~24.2만원) |
| **Large (XL)** | 4 vCPU / 8 GB | MMO 대형 채널 · 물리 | ~400 CCU | **48 P / hr** (~672원) | 6.0 GB/h | 34,560 P (~48.4만원) |

- **계량 단위**: 실제 가동 시간 **1분 단위 올림** 정산 (`활성 인스턴스 수 × 프리셋 단가 × 가동 분 / 60`).
- **초과 Egress 보호**: 정상 게임 패킷(1 CCU당 평균 4~5 KB/s)은 프리셋에 포함되며, 비정상 패킷 폭주·대용량 바이너리 재전송으로 포함 한도를 초과하는 경우만 **`10 P / GB`** 별도 차감한다.

### 4.2 Free 티어 제약 정책

| 항목 | Free 티어 제약 | 유료 (허브 포인트 충전) |
|---|---|---|
| **SinglePlay 배포** | **무료** (빌드당 100 MB, 공정 사용 트래픽 한도) | 용량 확장 · 커스텀 도메인 |

### 4.3 허브 포인트 원장(`hub_point_ledger`) 및 소진 시 메일 노티 체계

#### Append-Only 원장 구조 (Turso / libSQL 호환)
- 잔액은 항상 `SUM(delta_points)`로 산출하며, 모든 차감·충전에 `idempotency_key`를 강제해 중복 차감을 원천 차단한다.
- **차감 우선순위**: `① 월간 무료 지급 포인트(이월 불가) → ② 이벤트/프로모션 포인트 → ③ 유료 충전 포인트`.
- **예약–정산 (Reserve → Settle)**: 인스턴스 기동 시 최소 10분치를 선점(`reserved_points`) → WSS Gateway의 1분 하트비트로 실사용량 확정 차감 → 조기 종료 시 미사용분 즉시 반환.

```sql
CREATE TABLE hub_point_accounts (
  account_key         TEXT PRIMARY KEY,
  free_balance        INTEGER NOT NULL DEFAULT 0,
  promo_balance       INTEGER NOT NULL DEFAULT 0,
  paid_balance        INTEGER NOT NULL DEFAULT 0,
  reserved_points     INTEGER NOT NULL DEFAULT 0,
  burn_rate_per_hour  INTEGER NOT NULL DEFAULT 0,
  notify_email        TEXT,
  auto_topup_enabled  INTEGER NOT NULL DEFAULT 0,
  updated_at          TEXT NOT NULL
);

CREATE TABLE hub_point_ledger (
  id                  TEXT PRIMARY KEY,
  account_key         TEXT NOT NULL,
  game_id             TEXT,
  instance_id         TEXT,
  bucket              TEXT NOT NULL, -- 'free' | 'promo' | 'paid'
  event_type          TEXT NOT NULL, -- 'grant' | 'topup' | 'reserve' | 'settle' | 'refund' | 'egress_overage'
  delta_points        INTEGER NOT NULL,
  idempotency_key     TEXT NOT NULL UNIQUE,
  metadata_json       TEXT,
  created_at          TEXT NOT NULL
);
```

#### 잔액 + 소진 속도(Burn Rate) 이중 트리거 메일 노티

갑작스러운 바이럴로 동접이 폭증할 때 "잔액 %"만 보면 메일 확인 전에 서버가 멈출 수 있으므로, **현재 시간당 소진 속도 기준 남은 예상 시간**을 함께 감시한다.

| 알림 단계 | 트리거 조건 | 발송 채널 및 시스템 동작 |
|---|---|---|
| **1차 경고** | 잔액 20% 이하 **또는** 현재 Burn Rate 기준 **72시간 내 소진 예상** | 이메일 + 대시보드 알림 (현재 동접, 시간당 차감 P, 원클릭 충전 링크) |
| **2차 긴급** | 잔액 5% 이하 **또는** **24시간 내 소진 예상** | 긴급 이메일 + 자동 충전(Auto Top-up) 활성화 안내 |
| **3차 임박** | **2시간 내 소진 예상** | 긴급 이메일 + (선택) 인게임 점검 예고 배너 훅 발송 |
| **잔액 0 도달** | 유료 허브 포인트 소진 | **즉시 셧다운 금지** → 15~30분 유예 버퍼(소액 마이너스 허용) 동안 **신규 입장만 차단** → MO 진행 매치 정상 종료 / MMO 월드 스냅샷 저장 후 슬립 전환 → "충전 시 원클릭 재개" 메일 발송 |
