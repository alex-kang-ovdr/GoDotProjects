# 시나리오 모드 — 월드맵 FTL 항로

상태: 2026-09-23 사용자 요구 확정 / 설계 초안 v1. **월드맵 UI와 목표 시스템은 아직 런타임 미구현이다.** 기존 자유 항로 검증과 시나리오 구현을 혼동하지 않는다.

## 확정 요구

- 월드맵에서 FTL 점프 경로를 선택해 목표 행성계까지 이동한다.
- 한 번의 점프는 인접한 행성계 하나로의 이동이다.
- 갈림길이 있으나 모든 제시 경로는 최종 목표로 이어진다.
- 임무 목표는 섬멸, 탈출, 보호, 아이템 획득이다.
- 시나리오마다 다른 AI 패턴, 등장인물, 대화가 나타난다.
- 기존 직교 탑뷰, 2D 물리, 3D 파트 렌더링, 회수·조립 조작을 유지한다.

‘벨트 스크롤’은 전투 카메라 강제 스크롤이 아니다. 월드맵을 가로로 펼쳐 항로를 탐색하는 표현에만 사용한다. 전투 공간은 행성계별 독립 구역이다.

## 플레이 경험과 코어 루프

플레이어는 손상된 함선을 회수 부품으로 개조하면서 다음 항로의 위험과 필요한 보급을 판단하는 선장이다. 루프는 ‘행성계 도착 → 상황 대화 → 목표 확인 → 조작·전투·회수 → 결과·정비 → 연결된 다음 행성계 선택 → FTL 점프’다.

월드맵의 경로 선택은 여행 의사결정이고, 전투 화면의 빈 공간 클릭은 해당 행성계 안의 자동 항법이다. 두 기능은 이름·버튼·상태를 분리한다.

## 그래프 규칙

1. 각 노드는 행성계이며 `system_id`는 유일하다. 표시명과 ID는 분리한다.
2. 출발 노드 1개, 목표 노드 1개를 가진다. 초기안은 깊이가 증가하는 방향 그래프로 한정한다. 후퇴·재방문은 별도 기능으로 보류한다.
3. 현재 노드의 outgoing edge만 다음 점프로 선택할 수 있다. 선을 건너뛰거나 임의 목적지로 바로 이동할 수 없다.
4. 분기는 2–3개 후보를 제공하고 이후 합류할 수 있다. 가지마다 임무·보상·적 성향이 달라야 한다.
5. 생성 후 출발에서 도달 가능한 노드인지, 모든 노드에서 목표로 도달 가능한지 양방향 탐색으로 검증한다. 목표 외 막다른 노드·자기 연결·중복 ID·없는 노드 참조를 거부한다.
6. 자원 조건까지 경로 보장을 깨지 않도록 첫 구현에는 소모성 점프 연료를 넣지 않는다. 충전 시간과 임무 상태만 점프를 제한한다. 이후 연료를 도입하려면 보급 하한·구제 경로 검증이 선행되어야 한다.
7. 선택하지 않은 가지에만 있는 필수 아이템/보스 때문에 최종 목적지가 잠기지 않도록 한다. 필수 관문은 모든 경로가 통과하는 합류 노드에 놓는다.

초기 수제 예시: 출발 → 구조물 섬멸 또는 데이터 회수 → 첫 보스 합류 → 호위 또는 봉쇄 탈출 → 정비 합류 → 두 번째 보스 → 고난도 전투 또는 위험 회수 → 최종 목표 행성계. 이는 콘텐츠 초안이며 아직 게임에서 선택할 수 있는 맵은 아니다.

## 목표별 성공·실패 계약

### 섬멸

- 성공: 시나리오가 지정한 필수 적 ID 집합이 전부 격파됨. 일반 로밍·중립 NPC는 카운트에서 제외한다.
- 증원: wave manifest에 예정된 필수 적이 남아 있으면 현재 화면의 적이 0이어도 성공하지 않는다.
- 실패: 플레이어 코어 상실 또는 명시한 제한시간 초과. 무기만 파괴된 적을 격파로 처리할지는 별도 설정이며 기본은 코어 파괴다.
- HUD: 필수 적 잔여 수 / 현재 웨이브. 마지막 격파 후 목표 완료 알림.

### 탈출

- 성공: 출구 구역에 플레이어가 도착하고 FTL 충전이 완료됨. 적 섬멸은 요구하지 않는다.
- 충전은 구역 안에서만 진행하고, 이탈하면 중단·보존 또는 초기화를 시나리오에서 명시한다. 첫안은 중단·보존이다.
- 실패: 코어 상실. 시간제 탈출만 제한시간을 적용한다.
- HUD: 출구 방향, 거리, 충전 진행, 방해 원인. 뒤쫓는 적을 모두 잡도록 자동 유도하지 않는다.

### 보호

- 성공: 지정 대상이 생존한 채 지정 시간 또는 목적지 도착 조건을 충족함.
- 실패: 보호 대상 코어 상실. 플레이어 코어 상실도 공통 실패다.
- 보호 대상은 고정 시설/이동 호위 중 하나로 정의한다. 적은 보호 대상 우선 공격, 우회 침투, 플레이어 견제 같은 역할을 분리한다.
- HUD: 대상 HP, 남은 시간 또는 호위 진행률. 대상 화면 밖 표식·피격 경고를 제공한다.

### 아이템 획득

- 성공: 지정 `item_id` 수량을 실제 인벤토리에 확보하고 필요시 출구까지 보유함.
- 커서에 들기만 한 상태, 다른 파트의 같은 표시명, 단순 잔해 수거는 획득으로 세지 않는다.
- 필수 아이템이 파괴되면 즉시 실패 또는 복구 가능한 드롭으로 처리한다. 임무가 끝없이 지속되는 상태는 금지한다.
- HUD: 아이템 아이콘·이름·확보 수·회수 지점. 탈출 결합 여부를 사전에 표시한다.

각 임무는 우선 주 목표 하나로 시작한다. 복합 목표는 `all / any` 명시 조건으로만 구성한다. 성공·실패는 한 번만 확정되고 결과·보상도 한 번만 지급한다. 동시 프레임에는 공통 실패(플레이어/보호 대상 파괴)를 먼저 확정한다.

## 적 AI·등장인물·대화

- AI 상태 전환 66ms 정책을 유지한다. 물리력 적용은 고정 물리 스텝에 남긴다.
- 패턴 후보: 근접 돌격, 사거리 유지, 측후면 선회, 저격/후퇴, 호위대 우선 공격, 매복, 도주·지원 요청. 기존 로밍·반격·선제 공격·대화 AI와 조합한다.
- 스폰은 임무 예산 안에서 난이도 곡선·역할·편대·증원 시점으로 정의한다. 임의로 무한 강화하지 않는다.
- `character_id`와 함선 인스턴스 ID를 분리하여 재등장 인물이 같은 인물로 인식되게 한다.
- 입장·첫 접촉·목표 갱신·성공·실패·다음 항로 선택에 대화 트리거를 배치한다. 대화로 스폰 함수를 직접 호출하지 않고 명시적 임무 이벤트를 발생시킨다.
- 평화 NPC를 표적으로 선택한 것만으로 자동 무기가 발포하지 않는다. 선제 공격은 수동 발사 또는 명시적 선택으로만 한다.
- 싱글플레이 대화/월드맵은 정지. 멀티플레이에서는 로컬 대화로 전 서버를 정지시키지 않으며 호스트의 임무·점프 결정과 합의 정책을 별도 구현한다.

## 화면·입력

월드맵은 현재 노드, 방문 경로, 선택 가능한 다음 노드, 잠긴 노드, 최종 목표를 시각적으로 구분한다. 노드 선택은 우측 정보 카드 미리보기이고, ‘FTL 점프’ 확인 버튼으로 출발한다. PC 클릭과 Android 터치에 같은 계약을 사용한다. 단일 클릭으로 비용 소비·화면 전환을 즉시 실행하지 않는다.

정보 카드: 행성계명, 주 목표 아이콘·문장, 예상 적 패턴/위험도, 정거장 유무, 알려진 보상, 캐릭터 신호. 미확인 정보는 추정/미확인으로 표시한다. 버튼이 비활성화되면 ‘임무 미완료’, ‘회수 중인 부품 있음’, ‘보호 대상 미도착’처럼 이유를 표시한다.

FTL 전환 중 추진·발사·조립 입력을 차단한다. 함선 구성·개별 HP·탄약·업그레이드·퀘스트 상태를 보존하고, 이전 구역의 투사체·체인·잔해·NPC는 정리한다. 새 구역은 한 번만 생성하며 안전한 스폰 위치에서 시작한다. 카메라는 탑뷰·사용자 줌을 유지하고 과한 화면 흔들림을 넣지 않는다.

## 데이터·소프트웨어 경계

- `ScenarioDefinition`: 그래프 노드·간선·출발·목표·시드·버전.
- `SystemDefinition`: 배경 테마·시드·입장 위치·정거장·임무 ID·등장인물·대화 목록.
- `MissionDefinition`: 목표 유형/대상 ID/웨이브/실패 규칙/보상/AI 프로필.
- `CampaignState`: 현재 노드·방문 노드·결과·시나리오 플래그·플레이어 함선 스냅샷.
- `MissionController`: 적 파괴·구역 진입·아이템 획득·보호 대상 이벤트를 받아 목표를 평가한다. 문자열 UI는 판정의 근거가 아니다.
- `JumpController`: 선택 검증 → 함선 스냅샷 → 구역 종료 → 새 구역 준비 → 상태 커밋 → 조작 복귀. 실패 시 기존 노드로 복구하고 중복 보상을 막는다.
- `WorldMapOverlay`: 상태를 표시하고 선택/확인 의도만 전달한다. 밸런스 또는 진행 상태를 직접 수정하지 않는다.

임무 문장·대화·이름은 내러티브 데이터, 목표·스폰·보상 수치는 밸런스 데이터, FTL 연출은 시각 튜닝으로 분리한다. 물리 수치는 `physics_tuning.gd`에 유지한다. 태그는 `Objective.Eliminate`, `Objective.Escape`, `Objective.Protect`, `Objective.Acquire`, `Travel.Jumping`, `Mission.Completed` 같은 분류에 사용할 수 있으나 현재 미구현 태그 시스템을 전제로 완료 처리하지 않는다.

## 30분 목표 재해석

기존의 거대한 월드 직선 이동 거리로 30분을 만드는 방식은 시나리오 모드에서 폐기한다. 경로별 행성계 체류·전투·대화·정비·선택 시간을 합해 25–35분을 목표로 한다. 후보는 실제 방문 7–9개 행성계, 주요 임무 2–4분, 점프·선택·정비를 합한 별도 예산이다. 모두 미검증 목표다.

중간 보스 2개·최종 보스 1개는 필수 합류 관문으로 배치하고 정거장 3개 접근 기회를 각 구간에서 보장하는 안을 우선한다. 정거장 선택이 필수인지 선택인지 콘텐츠 검증 후 확정한다. 섬멸만 가장 수익성 높은 유일한 선택이 되지 않게 보호/탈출/획득도 동급 진행 보상을 준다.

## 10단계 구현·검증 게이트

1. 그래프/행성계/임무 데이터 스키마와 검증기. 출발·목표 도달, 분기 합류, 잘못된 참조 테스트.
2. 가로 월드맵 UI. 노드 미리보기, PC/터치 선택, 경로 제한, 정보 카드.
3. FTL 한 점프 한 행성계 전환. 구성·HP·탄약 보존, 입력 잠금, 중복 전환 방지.
4. 섬멸 목표와 웨이브. 중립 제외, 마지막 적·예정 증원·승패 동시 프레임 테스트.
5. 탈출 목표. 구역 판정, 충전 중단·복귀, 적 생존 상태 클리어.
6. 보호 목표. 대상 우선 AI, HP HUD, 호위 완료·대상 사망 판정.
7. 아이템 획득 목표. 고유 ID, 인벤토리·보유 상태, 파괴/복구와 중복 회수 방지.
8. 캐릭터·대화·분기 결과 연결. 플래그 보존, 안전한 대화 큐, 재등장 일관성.
9. 정거장 3개·중간 보스 2개·최종 보스의 수제 시나리오. 모든 경로 규칙 워크스루.
10. PC/웹 자동화·수동 25–35분 완주 평가. 동일 시드 반복, 중도 재개, 보상 중복·막힌 경로·유령 투사체 회귀 테스트.

각 게이트는 구현 → 재현 테스트 → 플레이 피드백 → 수정 → 통과 기록 → `[Cap]` 한글 커밋·push 순서다. Android는 공통 입력 설계를 유지하되 이번 플랫폼 합격 판정은 PC·웹으로 한정한다.

## 규칙 워크스루와 남은 질문

섬멸 경로와 획득 경로가 첫 보스에 합류하는 경우, 어느 경로를 택해도 필수 진행 플래그가 준비돼야 한다. 보호 실패 후 탈출 분기로 계속하게 하려면 실패가 ‘임무 실패지만 항해 지속’인지 ‘항해 종료’인지 데이터에 명시해야 한다. 목표 아이템을 FTL 직전에 소비하는 경우에는 점프 확인 시 다시 검증한다.

확정 전 후보: 실패 시 재도전 단위(행성계/항해), 구역 재방문, 연료 비용, 멀티플레이 경로 투표. 첫 구현은 행성계 재시작을 제공하고 나머지는 보류하는 안이다. 실제 플레이테스트 전 재미·난이도·완주 시간을 검증됐다고 표시하지 않는다.
