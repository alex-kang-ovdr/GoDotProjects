# 10-Milestone Delivery Plan

각 마일스톤은 실행 가능한 상태와 하나의 검증 질문을 남긴다.

## 현재 상태 (2026-09-15)

1–10은 브랜치의 순차 커밋으로 구현됐다. 다만 “완료”는 코드·문서 전달 상태를 뜻하며, 재미·밸런스·최소 사양 성능의 플레이테스트 완료를 뜻하지 않는다. 세부 출처와 구현 차이는 [GDD](GDD.md) 및 [References](../References/CAPTAIN_FOREVER_RESEARCH.md)에 기록한다.

1. **Flight deck** — 무의존성 HTML Canvas 셸, 반응형 HUD, 출항·재시작 진입점을 만든다.
2. **Flight model** — 코어, 방향, 관성, 키보드 추진을 구현해 함선을 조종 가능하게 만든다.
3. **Ship assembly** — 격자형 모듈 데이터와 부품별 렌더링을 추가해 구성의 차이를 보이게 한다.
4. **Fire control** — 0.28초 쿨다운 레이저, 열 냉각, 원형 투사체 피격 판정, 모듈 체력을 추가했다. 첫 모듈 레이캐스트는 범위 밖이다.
5. **Hostile rigs** — 거리 유지·조준 AI와 웨이브별 추가 무기를 구현했다. AI는 플레이어와 완전히 동일한 조종 규칙이나 웨이브별 조준 정확도 변화는 사용하지 않는다.
6. **Break and drift** — 개별 모듈 파괴, 적 코어 사망 시 살아 있는 비코어 모듈의 잔해 분리, 화면 효과를 구현했다. 구조 연결 연쇄 파괴는 범위 밖이다.
7. **Salvage rig** — 클릭 회수, 연결점 탐색, 자동 스냅, 함선 능력치 재계산을 구현한다.
8. **Sector run** — 5웨이브 난이도 곡선, 휴식 시간, 승패 상태를 추가한다.
9. **Readable combat** — HUD·색 외 텍스트 라벨·회수 포인터·모션 감소·객체 상한을 구현했다. 저사양 프로파일링은 아직 없다.
10. **Release candidate** — 수동 테스트 체크리스트와 실행 문서를 작성했다. 밸런스 패스·브라우저 시각 QA·호스팅 배포는 아직 검증 또는 수행되지 않았다.

## 후속 범위 확장 (2026-09-15)

10개 초기 마일스톤 이후, 웨이브형 짧은 프로토타입을 장거리 회수 항로로 확장했다. 이 항목은 새 10개 마일스톤을 완료했다는 주장이 아니라 다음 플레이테스트에 넘길 수 있는 통합 세로 슬라이스다.

- **Physics and breakage** — 함선 모듈끼리, 부유 부품과 모듈·부유 부품끼리의 2D 충돌, 충격 피해, 균열·파편·스파크를 추가했다.
- **Field assembly** — 중립 부품 생성·클릭 장착, `Shift` + 클릭 장착 부품 이동·재장착을 추가했다.
- **Route director** — 플레이어 파워와 구역 진행도에 따라 1–10 레벨 일반 적을 2–5척 범위로 스폰한다.
- **Long route** — 7구역, 3개 수리·업그레이드 정거장, 순차 중간 보스 2개, 잠금 해제형 최종 보스 1개를 구현했다.
- **Time hypothesis** — 약 17만 월드 단위 항로로 전투·정비를 포함한 약 30분 세션을 의도했다. 실제 완주 시간, 재미, 저사양 성능은 아직 검증되지 않았다.

구현 규칙·상한·검증 항목은 [GDD](GDD.md), [월드 항로 설계](WORLD_ROUTE.md), [TEST_PLAN](TEST_PLAN.md)에서 관리한다.

## M11 · 직교 블록 메시 전환

- **범위**: 우주선·부유 부품의 2D 사각형 표현을 상단·측면·전면을 가진 블록 메시로 바꾼다. 2D 물리, 충돌체, 카메라 추적 규칙은 바꾸지 않되 0.7×~1.5× 직교 줌을 제공한다.
- **수락 기준**: 원근 축소 없는 직교 투영, 고정 탑다운 카메라 방향, 줌 입력, 선회 시 메시의 작은 보정, 블록 표면 위의 모듈 체력·균열 표현이 모두 존재한다.
- **검증**: JavaScript 문법, Canvas 모의 런타임의 출항·추진·사격 경로, 정적 소스 확인. 실제 브라우저 시각 QA는 별도 수동 테스트가 필요하다.

## M12 · 2D 운석 지대와 충격 피해

- **범위**: 6개 항로 운석 지대를 접근 시 생성한다. 소·중·대형 운석은 2D 원형 물리체와 2D 다각형 외형을 사용한다. 우주선의 블록형 3D 메시와 분리해, 어떤 운석에도 3D 충돌·질량·회전 물리를 추가하지 않는다.
- **수락 기준**: 소형은 반발하지만 피해가 없고, 중·대형은 감산 질량과 상대속도에 비례한 충격량이 각 임계값을 넘을 때만 가장 가까운 모듈에 제한 피해를 준다. 운석 수는 48개 이하다.
- **검증**: JavaScript 문법, Canvas 모의 런타임의 운석 생성·렌더·충돌 갱신 경로, 충격 규칙 정적 확인, 수동 운석 시나리오. 실제 모바일·브라우저 시각 및 충돌 감각은 별도 수동 테스트가 필요하다.

## M13 · PC · Android · 웹 PWA 타겟

- **범위**: PC 키보드·마우스 조작을 유지하고, Android 가로 화면에 가상 비행·사격·정거장·줌·`MOVE` 재장착 조종계를 추가한다. 정적 웹 빌드에 Manifest·서비스 워커·아이콘을 넣어 HTTPS에서 설치·오프라인 앱 셸을 제공한다.
- **수락 기준**: 터치 버튼은 누르는 동안만 같은 가상 키를 유지하고, `MOVE` 탭은 기존 `Shift` + 클릭 재장착 시작과 같은 동작을 한다. Manifest·서비스 워커는 상대 경로 정적 배포를 보존한다. 네이티브 APK/AAB·EXE는 만들지 않는다.
- **검증**: JavaScript와 서비스 워커 문법, Canvas 모의 런타임의 터치 입력·재장착 모드·줌 경로, 정적 PWA 파일·링크 확인, PC/Android/HTTPS 수동 시나리오. 실제 Android 설치·오프라인·성능은 별도 기기·호스트 테스트가 필요하다.

## M14 · 공용 테스트 프레임워크 웹 어댑터

- **범위**: 공용 `game-test-framework`에 `target: web` 설정과 Node 명령 기반 자동화, 보이는 Chromium ANGLE RHI 수동 실행을 추가한다. 프로젝트 루트 BAT는 공용 메뉴에 `syntax`, `runtime`, `platform`, `manual-rhi`를 연결한다.
- **수락 기준**: 선택한 각 스위트는 절대 경로 로그를 남기고 성공·실패 패턴으로 판정한다. `runtime`은 운석 소형 무피해·대형 고충격 피해를, `platform`은 터치·PWA 구성을 확인한다. 수동 경로는 GPU 비활성·헤드리스 인자를 거부하고 `--use-angle=d3d11`을 보이는 브라우저에 전달한다.
- **검증**: 공용 프레임워크 단위 테스트, 프로젝트 스위트 직접 실행, 공용 CLI의 `--suite all` 통합 실행, 수동 RHI 명령 `--dry-run`. 실제 브라우저 시각·Android 기기·GPU 성능은 수동 검증으로 남긴다.

## M15 · Top-View 박스 조립과 충격 본체 흔들림

- **범위**: 기본 기울임 없는 직교 Top-View와 우클릭 수평 회전을 제공한다. 도트 텍스처·9-slice 외곽 베벨을 가진 박스, 1·2·3·4칸 구조 파트와 1·2칸 삼각 기둥을 2D 점유 격자로 구현한다. 충격으로 제거된 파트에는 해당 함선 본체 전용 흔들림을 준다.
- **수락 기준**: 카메라 피치·원근·화면 흔들림 없이 회전·클릭 역변환이 정확하고, 인접 박스 내부에는 베벨이 없다. 다칸 파트는 모든 셀을 점유하며, 무기 파괴 흔들림은 일반 파트보다 크다.
- **검증**: JavaScript·공백 검사, 공용 `runtime`·`platform` 스위트의 운석·다칸 점유·소켓·Top-View 역변환·흔들림 강도 확인, 수동 Top-View 시나리오. 실제 브라우저 시각과 충격 감각은 별도 수동 테스트가 필요하다.

## M16 · 질량 물리·무장·방어막·RPG 인터랙션

- **범위**: 중립 부품 드래그 릴리스 장착과 탄약고 병합, CoM 자동 메인 추력 보정, 메인·후진·RCS 실제 추력, 레이저/탄도/미사일 분리 탄약, 우클릭 표적 유도탄, 좌·우 자동 미니 유도탄, 질량 제한 방어막, 컨트롤 타워 연결 분리, RPG 대화형 튜토리얼·이벤트를 구현한다. 밸런스와 시각 튜닝은 분리된 단일 소스 파일로 관리한다.
- **수락 기준**: 드래그 부품은 유효 소켓에서만 놓이고, 같은 탄약고 병합 결과는 탄약·용량·질량을 합친 더 튼튼한 커서 부품이다. CoM 불균형에서도 전진 메인 추력은 자동 보정된다. `BULLET BAY`와 `MISSILE BAY` 재고는 섞이지 않는다. 방어막 레이어·질량 용량·HUD·고정 불투명도가 일치하고, 연결부 파괴 뒤 코어와 끊긴 덩어리는 중립 부품으로 분리된다. 대화 선택과 정거장/보스 이벤트가 비차단으로 동작한다.
- **검증**: 공용 `runtime` 스위트에서 드래그 장착, 탄약고 병합, 수동/자동 미사일 소비, 방어막 흡수·질량 제한, 컨트롤 타워 연결 분리, 튜토리얼 대화 상태를 확인한다. `platform`은 밸런스·시각 튜닝·PWA 캐시 연결을 확인한다. 실제 브라우저의 시각 대비, 게임패드 외 입력, 난이도는 수동 테스트로 남긴다.
