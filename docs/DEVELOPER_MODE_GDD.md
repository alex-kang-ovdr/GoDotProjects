# 개발자 모드 GDD

## 목적

실행 인자 `--edit-mode`로 개발자 전용 진입점을 열고, 플레이 씬을 변경하지 않은 상태에서 네 가지 검증 흐름을 빠르게 선택한다.

## 첫 화면 메뉴

| 모드 | 플레이어/개발자 목표 | 완료 조건 |
|---|---|---|
| 파트 편집 | CSV 파트의 표시명·질량·Hull·재질·무기 스펙을 확인 | 파트 목록과 튜닝 값 표시 |
| 우주선 조립 | 배치·clearance·CoM·bound sphere·추력 작용점 확인 | 조립 검증 항목 표시 |
| 이벤트 및 퀘스트 편집 | 튜토리얼·대화·정거장·보스·NPC 접점 확인 | 내러티브 키 목록 표시 |
| 테스트 파일럿 | 실제 조작·물리·전투 플레이 | 메뉴 제거 후 일반 플레이 재개 |

메뉴가 열린 동안 게임 물리·AI 틱은 정지한다. 편집 화면의 `테스트 파일럿으로 실행` 또는 첫 화면의 테스트 파일럿 버튼을 누르면 메뉴가 닫히고 플레이가 시작된다. 이는 현재 1차 회색상자이며, 값 저장·씬 편집은 후속 마일스톤에서 추가한다.

## 플랫폼/입력

PC·웹·Android에서 동일한 GDScript를 사용한다. PC/웹은 마우스, Android는 터치 가능한 `Button`을 사용한다. 인자 전달은 Godot 실행 파일 뒤 `-- --edit-mode` 형식을 권장한다.

## 검증 시나리오

1. 인자로 실행하면 네 버튼이 첫 화면에 보인다.
2. 각 편집 버튼은 해당 모드 제목·설명·목록을 표시한다.
3. 뒤로 가기로 첫 화면으로 돌아온다.
4. 테스트 파일럿 선택 시 오버레이가 제거되고 기존 플레이 씬이 재개된다.
5. 인자 없이 실행하면 기존 플레이 시작 동작이 변하지 않는다.

## 파트 편집 모드 · 마일스톤 1

파트 목록에서 하나를 선택하면 `display_name`, `description`, `hull`, `mass`, `material`, `power`, 전진/후진/RCS 추력, `weapon_type`을 수정할 수 있다. 저장 전 Hull·질량은 양수, 추진력은 0 이상, 필수 텍스트는 비어 있지 않은지 검사한다.

저장 값은 패키지 원본을 덮어쓰지 않고 `user://part_tuning_overrides.csv`에 전체 CSV 행으로 기록된다. 다음 파트 생성과 테스트 파일럿은 기본 `part_tuning.csv` 위에 이 오버라이드를 적용한다. 원본 CSV 반영과 일괄 import/export UI는 다음 마일스톤 범위다.

## 파트 편집 모드 · 마일스톤 2

파트 목록을 엑셀형 그리드로 확장했다. 검색어는 ID·이름·설명·재질·무기 타입에 대해 부분 일치하며, 전체·무기·추진·방어·탄약/기타 필터를 조합할 수 있다. ID·Hull·Mass·Type 정렬 버튼은 같은 열을 다시 누를 때 방향을 전환한다.

그리드 행을 선택하면 우측 테스트 파일럿 미리보기에 파트 박스와 스펙 debug string이 표시된다. `정지`, `추진 반복`, `공격 반복` 모드로 추진 화살표, RCS 방향 화살표, 무기 빔을 확인할 수 있으며, 미리보기는 실제 월드/저장 상태와 격리된다.
