# 독자적 2D 경량 우주 배경 생성기 구현 계획

> **GDScript 이식 기준:** 이 계획의 알고리즘·예산은 유지하되 구현 위치는 `Godot/scripts/background.gd`와 후속 GDScript 모듈이다. Canvas/Node/WebGL/JavaScript 언급은 제거된 웹 프로토타입의 역사적 설계안으로만 읽는다.

## 문서 상태

- **계획**: 아직 이 문서가 정의하는 성운·은하수 렌더러는 구현하지 않았다.
- **M20 구현됨**: `Godot/scripts/background.gd`는 고정 시드 별밭과 저알파 은하수 띠를 `CanvasItem._draw()`로 그린다.
- **목표**: 외부 이미지, WebGL, 라이브러리, 네트워크 요청 없이 Godot 2D 드로우 호출만으로 재현 가능한 우주 배경을 만든다.
- **검증 상태**: 성능·가독성·재미 효과는 실제 PC/Android/Web 최소 사양 기기에서 아직 검증되지 않았다.

## 의도와 범위

배경의 역할은 항로의 거리감과 구역 정체성을 주되, 적 코어·레이저·회수 부품·정거장 표식을 가리지 않는 것이다. 플레이어의 조작이나 전투 규칙은 바꾸지 않는다. 같은 `seed`와 월드 좌표는 매번 같은 별·은하수·성운 배치를 만들어야 하며, 새로운 이미지 파일을 내려받거나 배포물에 추가하지 않아야 한다.

다음은 이번 계획의 범위 밖이다.

- 3D 은하, 행성 탐험, WebGL, three.js, Web Worker 의존 렌더러
- 현실 천문 데이터의 재현이나 실사 이미지 사용
- 전투 중 동적으로 변하는 대형 유체·파티클 시뮬레이션
- 고해상도 스크린샷용 포토리얼 성운

## 플레이어가 보는 결과

1. 먼 검푸른 바탕 위에 밀도가 다른 작은 별이 보인다.
2. 화면을 가로지르는 옅은 은하수 띠가 구역마다 방향·폭·색이 달라진다.
3. 낮은 대비의 성운 구름이 천천히 패럴랙스 이동한다.
4. 보스·정거장 구역은 같은 시드 규칙 안에서 색조만 달라져 위치 기억을 돕는다.
5. 레이저, 코어 체력 바, 황금 회수 부품보다 배경이 밝아지는 경우에는 배경 품질보다 가독성을 우선해 자동으로 밀도를 낮춘다.

## 고정 규칙과 조정 변수

### 고정 규칙

- `seed + tileX + tileY + layer`로 모든 난수를 도출한다. `Math.random()`은 생성기 내부에서 쓰지 않는다.
- 전역 별 배열을 만들지 않는다. 현재 화면과 한 타일 여유분만 계산하거나 캐시한다.
- 일반 전투 프레임에서 성운 픽셀을 다시 생성하지 않는다. 생성된 타일은 오프스크린 캔버스에 보관하고 합성만 한다.
- Canvas 2D API와 프로젝트 내 JavaScript만 사용한다. 새 런타임 의존성은 0개다.
- 배경은 월드 카메라보다 느리게 움직이며, UI·모듈·투사체는 항상 배경 위에 그린다.

### 첫 구현 후보값

- 마스터 시드: `CAPTAIN-SALVAGE-01`을 32비트 정수로 해시한다.
- 논리 타일: 1,024×1,024 월드 단위. 화면 가장자리에서 보이는 타일을 포함해 최대 3×3 타일만 캐시한다.
- 별 셀: 72px, 생성 확률 0.42. 희귀 밝은 별은 0.055 이하의 해시 구간으로 제한한다.
- 은하수 띠: 폭 260–520px, 화면 대비 알파 0.04–0.11, 구역별 색조는 청록·보라·적갈색 중 하나다.
- 성운 타일: 256×256 저해상도 오프스크린 캔버스에 3옥타브 값 노이즈를 굽고, 화면에서는 2–4배 확대·낮은 알파로 합성한다.
- 캐시: 성운 타일 최대 6개. 새 타일을 만들 때 가장 오래 사용하지 않은 타일을 제거한다.
- 패럴랙스: 먼 별 0.04–0.07, 은하수 0.09–0.14, 성운 0.16–0.22. 후보값이며 플레이테스트로 확정하지 않는다.

## 설계 구조

새 `ProceduralSpaceBackground` 모듈은 게임 상태와 분리한다. 입력은 `seed`, 카메라 좌표, 캔버스 크기, 시간, 구역 ID뿐이며, 출력은 현재 프레임의 Canvas 2D 드로우 호출이다. 적 AI, 물리, 회수, HUD를 읽거나 수정하지 않는다.

### 1. 결정론 도구

- 문자열 시드를 32비트 정수로 변환하는 `hashString`을 둔다.
- 정수 좌표 해시 `noise2D(x, y, layer, seed)`는 0 이상 1 미만을 반환한다.
- `valueNoise`는 네 인접 격자 해시를 smoothstep 보간한다. `fbm`은 이를 3옥타브 합산하되, 성운 타일을 만들 때만 호출한다.
- 테스트를 위해 같은 인수에는 같은 수치가, 다른 시드에는 다른 수치가 나오는 순수 함수를 유지한다.

### 2. 먼 별 레이어

- 현재 보이는 셀만 순회해 별의 위치, 크기, 색온도, 반짝임 위상을 계산한다.
- 1px 미만 별은 밝기를 낮추고 크기를 억지로 키우지 않는다. 멀리 갈수록 화면 전체가 밝아지는 현상을 피한다.
- 밝은 별은 최대 1.8px, 일반 별은 0.35–1.2px 범위에 둔다. 큰 렌즈 플레어와 반복 애니메이션은 쓰지 않는다.

### 3. 은하수 띠 레이어

- 월드 좌표를 기울어진 띠 축으로 투영한다. 중심선과의 거리가 폭보다 작을 때만 색을 더한다.
- 중심부에는 작은 규모의 `valueNoise`를 곱해 먼지대와 빈 공간을 만든다.
- 구역 ID에서 색조와 띠 방향을 파생해 7개 구역이 같은 우주 안에 있으면서도 구별되도록 한다.
- 이 레이어는 타일 사전 생성 없이 수십 개의 넓은 반투명 도형 또는 낮은 해상도 캔버스 한 장으로 합성한다.

### 4. 성운 캐시 레이어

- 카메라의 성운 타일 좌표가 바뀔 때만 256×256 오프스크린 캔버스를 생성한다.
- 각 픽셀 또는 2×2 블록에서 3옥타브 `fbm`과 거리 감쇠를 계산하고, 임계값을 넘은 영역에만 저채도 색을 준다.
- 생성은 한 프레임에 최대 한 타일만 허용한다. 아직 없는 타일은 단색의 아주 옅은 폴백으로 그려 입력 지연을 피한다.
- `OffscreenCanvas`가 없으면 일반 메모리 캔버스를 사용한다. 어느 쪽도 없으면 성운 레이어만 생략한다.

### 5. 합성·대비 보호

렌더 순서는 단색 바탕 → 성운 → 은하수 → 먼 별 → 기존 전투 월드 요소다. 배경은 UI 아래가 아니라 캔버스의 월드 요소 뒤에만 그린다. 보스·정거장·회수 부품 근처에는 반경 기반의 어두운 비네트를 선택적으로 적용한다. `prefers-reduced-motion`에서는 별 반짝임과 성운 드리프트를 정지한다.

## 구현 마일스톤

각 항목은 독립 커밋 하나로 끝내며, 명시한 검증을 통과하기 전에는 다음 단계로 넘어가지 않는다.

### PBG-1 · 결정론 코어

- 구현: `hashString`, 정수 좌표 해시, 값 노이즈, 시드 설정 API를 별도 모듈로 만든다.
- 수락: 같은 시드·좌표가 100회 같은 값을, 다른 시드가 다른 표본값을 반환한다. 전투 상태를 바꾸지 않는다.
- 검증: Node 단위 테스트와 `node --check`.
- 커밋: `feat(background): add deterministic space seed core`.

### PBG-2 · 텍스처 없는 별밭

- 구현: 현재 셀-해시 별 레이어를 시드 지원 모듈로 옮기고, CC0 별 타일을 기능 플래그 뒤의 비교 폴백으로 둔다.
- 수락: 같은 카메라·시드에서 재시작 후 별 위치가 같고, 월드 크기 증가에 비례하는 별 배열이 없다.
- 검증: 고정 카메라 캔버스 픽셀 샘플 또는 드로우 명령 스냅샷, 1280×720 수동 확인.
- 커밋: `feat(background): render seeded procedural starfield`.

### PBG-3 · 은하수 띠

- 구현: 구역별 색조·방향을 갖는 낮은 알파 은하수 띠와 먼지대 노이즈를 추가한다.
- 수락: 7개 구역에서 띠가 구별되지만 적·정거장 라벨보다 밝지 않다.
- 검증: 각 구역의 스크린샷 검토, 흰색·노란색·보라색 전경 요소와의 대비 수동 점검.
- 커밋: `feat(background): add sector milky-way bands`.

### PBG-4 · 성운 타일 캐시

- 구현: 저해상도 `fbm` 성운 타일, LRU 캐시, OffscreenCanvas 폴백을 추가한다.
- 수락: 타일 경계가 보이지 않고, 새 구역 진입 시 입력 멈춤이 없다. 캐시가 6개를 넘지 않는다.
- 검증: 타일 경계 왕복, 캐시 크기 단위 테스트, 10분 이동 프레임 시간 기록.
- 커밋: `feat(background): cache procedural nebula tiles`.

### PBG-5 · 가독성·접근성 패스

- 구현: 보스·정거장·회수 부품 주변 대비 보호, reduced-motion 정지, 배경 품질 프리셋을 추가한다.
- 수락: 전경 색만으로 의존하지 않고 라벨·체력 바가 읽히며, reduced-motion에서는 시간 기반 배경 이동이 없다.
- 검증: 수동 대비 체크, `matchMedia` 모의 테스트, 390px와 1280×720 확인.
- 커밋: `feat(background): protect combat readability`.

### PBG-6 · 측정·기본 전환 판단

- 구현: `performance.now()` 기반의 배경 프레임 비용 계측과 개발용 프리셋 전환을 추가한다.
- 수락: 대표 전투 구간의 백그라운드 평균 비용과 최악 비용을 기록하고, 기준을 통과하면 CC0 기본 이미지를 절차 레이어로 대체한다. 미달이면 CC0/별 전용 폴백을 기본으로 유지한다.
- 검증: 최소 지원 기기 또는 합의된 보수적 프록시에서 10분 이동·전투 프로파일. 플레이어 가독성 관찰도 함께 기록한다.
- 커밋: `perf(background): validate procedural renderer`.

## 성능 예산과 폴백

다음은 구현 목표이며, 최소 사양 실측 전까지 보장 수치가 아니다.

- 1280×720, 일반 전투 오브젝트 상한에서 배경 CPU 비용 평균 2ms 이하, 최악 4ms 이하를 목표로 한다.
- 매 프레임 별 셀은 화면과 여유 한 칸만 순회한다. 성운 픽셀 노이즈는 타일 재생성 때만 계산한다.
- 캐시 메모리는 256×256 RGBA 타일 6개 기준 약 1.5MiB이며, 실제 브라우저 구현·백버퍼 비용은 별도로 계측한다.
- 성능이 미달이면 순서대로 별 밀도 감소 → 은하수 알파/샘플 감소 → 성운 해상도 128×128 → 성운 레이어 비활성화로 품질을 낮춘다.
- 성운을 비활성화해도 결정론 별·은하수 띠와 전투 기능은 유지한다.
