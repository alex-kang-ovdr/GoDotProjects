# 물리 백엔드 계약

## 현재 상태

- 현재 백엔드: Godot 내장 2D 물리. 프로젝트는 PC·Web·Android에서 오류 없이 실행·내보내기 가능한 상태를 유지한다.
- 물리 상수 SSOT: `Godot/scripts/physics_tuning.gd`. 엔진 기본 감쇠를 대체하고, 웹 기준본과 같은 초당 유지 비율을 `_integrate_forces`에서 적용한다.
- 후보: `Pizzaandy/godot-box2d-v3` 릴리스 `0.1.0`의 Box2D v3 GDExtension.
- 게임 규칙과 조립·질량·추진 계산은 GDScript SSOT로 유지한다. Box2D가 채택될 경우 `RigidBody2D`의 힘 적용, 질량, 관성, 감쇠, 접촉 해석만 교체한다.

## 결정

- 2026-09-15: 프로젝트는 Godot 내장 2D 물리를 계속 사용한다.
- `Pizzaandy/godot-box2d-v3` 전환은 Godot 4.7 호환 확장과 해당 플랫폼별 바이너리가 검증될 때까지 보류한다.

## Pizzaandy/godot-box2d-v3 호환성 게이트

- Godot 4.7.2에서 Windows·Web·Android 바이너리 포함 내보내기는 가능하다.
- 그러나 `RigidBody2D` 충돌체를 등록하면 `Box2DPhysicsServer2D::_body_set_shape_as_one_way_collision` 필수 가상 메서드 미구현 오류가 발생한다.
- 이는 업스트림의 열린 [Godot 4.7 호환성 이슈 #6](https://github.com/Pizzaandy/godot-box2d-v3/issues/6)와 일치한다. 따라서 현재 프로젝트에는 이 확장을 활성화하지 않는다.
- 활성화하려면 Godot 4.7 API에 맞춘 확장 소스 수정·재빌드 또는 검증된 호환 엔진 버전 선택이 필요하다.

## 위험과 운영 원칙

이 확장은 Box2D v3를 제공하지만, 업스트림이 단위 변환 및 메모리 안전성 이슈를 이유로 유지보수 중단·비권장을 명시한다. 따라서 호환성 수정 뒤에도 실기기 장시간 플레이, 조립·파괴 반복, 운석 대량 충돌은 각 릴리스 후보에서 별도 소크 테스트로 통과해야 한다. 크래시·단위 불일치가 확인되면 이 확장은 즉시 격리하고, 검증된 대체 백엔드를 선택한다.

## 웹 기준본과의 비교 기준

웹 기준본은 자체 적분과 수동 반발·임펄스 처리다. Box2D 전환이 웹과 같은 숫자를 자동으로 보장하지는 않는다. 다음 비교에서는 60 Hz에서 다음을 측정한다.

1. 초기 함선의 1초 전진 속도와 1초 제동 거리
2. 90도 회전에 걸리는 시간과 입력 해제 뒤의 각속도 감쇠
3. 비대칭 질량에서 CoM 보정 전·후의 선회량
4. 중·대형 운석 충돌 뒤 속도 변화와 접촉 부품 피해
