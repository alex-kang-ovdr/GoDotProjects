# 숨 4.0 검증 기록

검증일: 2026-11-14. 대상은 이 저장소의 Vanilla JavaScript 게임 4.0입니다. 이 검증은 새 게임에서 생산·생활·탐사·성장이 실제로 연결되고 최종 목표를 달성할 수 있는지를 확인합니다. 원작 Oxygen Not Included 전체의 물리 정확도를 재현했다는 의미는 아닙니다.

## 1. 최종 결과

- 최신 엔진의 **Node 회귀·통합 테스트 71/71 통과**. 실패·취소·건너뜀 0개. 최종 실행 시간 약 57.43초.
- **새 Game(73)에서 공개 명령만 사용해 2,188.5게임 초에 20/20 목표 달성**. 자원·연구·욕구·경험·산소·지형을 주입하지 않았습니다.
- 승리 저장의 정확한 저장/불러오기 왕복 후 **추가 10주기, 1,200초**를 운영했습니다. 대원 3명 모두 생존하고 최저 건강 100을 유지했습니다.
- 최종 예제 JSON을 실제 브라우저의 파일 선택기로 가져와 **20/20**, 방 판정, 충전소 잔량, 기술 배분과 중단·복구를 확인했습니다.
- **390×844 세로**, **844×390 가로**에서 일곱 정보 탭, 구역 카드, 평균 산소와 스크롤 패널을 확인했습니다. 두 화면 모두 문서 폭과 화면 폭이 같았습니다.
- **6개 모듈을 합친 단일 HTML**에서도 저장된 완성 기지와 20/20 목표, 방별 평균 산소, 충전소 상태가 정상 표시되고 시뮬레이션이 진행됐습니다.

## 2. 재현 방법

```sh
npm test
npm run test:renderer
npm run build:standalone
```

외부 패키지 설치가 필요하지 않습니다. Node 내장 테스트 러너와 기본 모듈을 사용합니다.

정상 진행은 [tests/scenarios.mjs](tests/scenarios.mjs)의 `establishFrontierColony()`에 있습니다. 최종 예제와 장기 운영 기록은 다음 명령으로 다시 생성합니다.

```sh
node examples/generate-example.mjs
```

[examples/validation-report.json](examples/validation-report.json)은 첫 승리·추가 10주기 후의 수치, 최저 건강·식량과 농장 관찰 값을 담습니다. 배포용 [examples/self-sustaining-colony.json](examples/self-sustaining-colony.json)은 첫 승리 시점의 기지입니다.

## 3. 자동 회귀 범위

총 71개는 기존 48개와 새 23개입니다. 기존 검증은 버전·목표 개수 가정을 갱신하되 자원·생존·작업·저장 검증을 유지했습니다. 일부 독립 경계 검사는 환경·욕구·연구·기술을 명시적으로 통제하여 해당 규칙을 분리합니다. 이와 달리 전체 정상 진행 시나리오는 시작 자원과 공개 플레이 명령만 사용합니다.

## 4. 첫 승리와 추가 10주기

| 지표 | 첫 승리 | 추가 10주기 뒤 |
|---|---:|---:|
| 게임 시간 | 2,188.5초 | 3,388.5초 |
| 사이클 표시 | 19 | 29 |
| 완료 목표 | 20/20 | 20/20 |
| 생존 대원 | 3명 | 3명 |
| 건강 | 전원 100 | 전원 100 |
| 전체 식품 | 약 96.8끼 | 약 130.3끼 |
| 수확 누계 | 91.5끼 | 145.5끼 |
| 조리 누계 | 51끼 | 75끼 |
| 식탁 식사 | 36회 | 60회 |
| 계획 수면 | 32회 | 57회 |
| 실제 침실 수면 | 199.7초 | 534.7초 |
| 실제 유효 식당 식사 | 15회 | 39회 |
| 실제 휴대 산소 호흡 | 617.9초 | 617.9초 |

추가 10주기 동안 최저 식품은 약 **96.65끼**, 최저 건강은 **100**이었습니다. 하층 세 농장은 각각 **9회 수확**했고, 그 지면의 최대 물은 약 **13.32%**로 침수 정지 기준 아래였습니다.

첫 승리 시점에는 정착 240초와 확장 180초를 채웠습니다. 추가 10주기 끝의 현재 유지 시간은 각각 약 **140.8초**입니다. 이미 완료한 목표와 승리는 이력이고, 현재 생활 조건과 연속 유지 시간은 계속 다시 평가합니다. 따라서 장기 검사 결과는 생존·건강·생산이 이어졌다는 뜻이며, 모든 세부 생활 조건이 1,200초 내내 한 번도 끊기지 않았다는 뜻은 아닙니다.

승리 후 새 저산소 탐사를 지정하지 않았으므로 휴대 산소 호흡 누계가 그대로인 것도 정상입니다. 호흡 가능한 생활권에서는 휴대통을 소비하지 않습니다.

## 5. 검사 중 발견하고 처리한 문제

### 밀폐한 생활 공간의 산소 공급

기존 기지를 침실 8칸과 식당 10칸으로 나누자 원거리 확산기의 산소가 충분히 전달되지 않았습니다. 자동문 상태 600초 관찰에서 확장 유지의 최장 구간은 113.5초였고, 실내 일부 셀 산소가 호흡 가능 경계까지 떨어졌습니다. 대원은 휴대통으로 버텼지만 생활 구역 산소 조건 때문에 유지 시간이 초기화됐습니다.

문을 열기만 하는 비교에서도 부족한 공급이 해결되지 않았습니다. 최종 정상 경로는 구리 광맥과 연결 통로를 추가로 채굴·수거해 **침실 `(18,11)`과 식당 `(19,16)`에 확산기를 실제 설치**하고 문을 열어 환기합니다. 목표 조건을 낮추지 않았습니다.

이 경험을 반영해 구역 카드에 **방별 평균 산소와 온도**를 추가했고, 게임 도움말과 실행 안내에도 밀폐한 방의 내부 산소 생산을 확인하도록 명시했습니다. 방의 구조적 분류와 실제 호흡 환경은 별개입니다.

### 막힌 철거에서 경험치가 반복 지급되는 문제

철거를 예약한 후 재고가 증가해 반환 공간이 부족해지면 기존의 95% 재시도 동작이 새 경험치 규칙과 결합해 같은 노동에 XP를 반복 지급할 수 있었습니다. 고체 보관·물 탱크·산소 충전소의 반환 공간을 **작업 시작 전에 재확인**하도록 고쳤습니다.

재현 검사에서 45초간 막힌 상태의 추가 진척·XP는 모두 0이었고, 공간을 확보한 뒤 실제 남은 철거 작업만 완료·보상했습니다. 영구 회귀 테스트에도 포함했습니다.

### 세부 경계

- 같은 충전소 칸의 중앙에서 벗어난 대원이 멈추지 않고 실제 중앙으로 이동한 뒤 충전합니다.
- 한 틱보다 적은 마지막 휴대 산소도 실제 분량만 소비·보호 시간에 반영합니다.
- 사망·추락 등에서 이전 틱의 휴대 산소 사용 표시가 남지 않게 했습니다.
- 문·충전소 청사진은 완공 전에 실제 차단·압축이 작동 중인 것처럼 표시하지 않습니다.
- 방 목록의 위치 이동은 외곽 상자 중심 대신 실제 방 셀을 선택합니다.
- 반복 UI 갱신에서 조작 버튼과 입력의 불필요한 재생성을 줄여 포커스를 보존합니다.

## 6. 이전 저장과 원자적 불러오기

실제 v1·v2·v3의 진행/승리 저장 **6개**를 사용합니다. v1/v2 원본 4개는 기존 커밋과 바이트 단위로 같으며, v3 승리 fixture는 원래 v3 커밋의 예제 `.game`과 완전 동일합니다. v3 진행 fixture도 v3 엔진에서 실제 공개 명령을 실행해 보존했습니다.

이행 시 기존 자원·설비·대원·완료 목표를 보존하고 새 경험·기술·휴대 산소는 0에서 시작합니다. 이전 승리 이력에 새 목표를 자동 완료하지 않습니다. 이행 후 UI는 시간을 멈추고 새 기능을 안내합니다.

v4 승리 저장에서는 충전소 끄기, 침상 끄기, 문 잠금, 마스크 끄기, 추가 기술 배분 등 일시정지 중 제어 직후에도 저장 왕복이 정확히 일치했습니다. 잘못된 저장은 원본 기지와 호출자의 입력 객체를 바꾸지 않고 거부합니다.

## 7. 실제 브라우저 검증

미리보기의 실제 UI로 다음 동작을 확인했습니다. 개발자 콘솔에서 게임 자원이나 결과를 주입하지 않았습니다.

1. 기존 v3 브라우저 저장의 4.0 이행, 새 목표 표시와 초기 경험·휴대 산소 0을 확인했습니다.
2. 기밀문을 `(19,11)`에 건설 예약하고 대원이 실제 완공하는 것을 확인했습니다. 정보 패널에서 자동·열림 유지·잠금을 바꾸자 실제 상태 문구와 문 표현이 바뀌었습니다.
3. 대원의 휴대 산소를 자동 → 꺼짐 → 자동으로 바꾸고 상태를 확인했습니다.
4. 최종 예제 JSON을 **조작법 → 세이브 가져오기**의 파일 선택기로 가져왔습니다. **20/20**, 확장 180초, 침실 8칸·식당 10칸, 충전소 18/18이 표시됐습니다.
5. 실제 작업으로 얻은 포인트를 사용해 나루의 굴착을 1→2로 올렸습니다. 미배분 포인트가 5→4로 정확히 감소하고 저장됐습니다.
6. 충전소를 수동 정지하자 현재 확장 시간이 0으로 바뀌고 필요한 충전소 조건이 표시됐습니다. 복구하면 현재 조건이 회복됐으며 과거 **20/20 달성 이력**은 유지됐습니다.
7. 방별 평균 산소·온도, 실제 산소 압축·휴대 잔량과 방 사용 누계를 확인했습니다.
8. 단일 HTML에서도 동일한 저장 기지를 읽고 20/20, 방별 공기 수치와 충전소 상태를 표시했습니다. 해당 최종 페이지의 게임 JavaScript 오류는 관찰되지 않았습니다.

브라우저 확장 자체의 메타데이터 경고는 게임 오류 집계에서 제외했습니다. 일시적인 미리보기 제공 상태 변경 시에는 프로젝트 미리보기를 다시 시작하고 페이지 제목·실제 UI를 확인한 뒤 계속했습니다.

## 8. Canvas 검증

[scripts/check-renderer.mjs](scripts/check-renderer.mjs)는 실제 신규/저장 상태와 통제된 표현 상태를 사용합니다. 7개 오버레이, 네 가지 크기·픽셀 비율 조합, 총 **168개 렌더 조합과 57개 상태 검사**를 수행합니다.

실제 `room.cells` 모양, L자 방의 오목 경계, 미탐사 셀 제외, 문 개폐·모드, 압축·방문 충전의 구분, 휴대통 잔량·실사용 마스크, 기술 단계와 선택 방을 검사합니다. 비정상 좌표·음수 도형 크기·Canvas 상태 불균형과 렌더에 의한 게임 상태 변경도 거부합니다. 장식 배경을 제외한 게임플레이 표현은 `game.time`이 고정되면 동일합니다.

이 검사는 픽셀 기반 실기 화면 검사를 대신하지 않습니다. 실제 화면 확인은 앞의 브라우저 절차로 별도 수행했습니다.

## 9. 구현 범위

- 기체 확산·물 흐름·열은 게임용 근사 모델입니다. 원작의 전체 원소·압력·상변화·배관 화학량론을 재현하지 않습니다.
- 새 산소 장비의 저장·전달·소비 수지는 검증하지만, 기존 지형 타일 건설·채굴을 포함한 세계 전체가 정밀 물질 보존 모델인 것은 아닙니다.
- 운반은 채굴품의 실제 줍기와 수거 거점 입고까지이며 공용 비축에서 개별 시설로 가는 마지막 배송은 추상화했습니다.
- 냉장고는 공용 식품의 실제 부패율에 영향을 주며 개별 용기 저장을 구현하지 않습니다.
- 휴대 산소는 산소통과 자동 마스크입니다. 방열복·시체 장비 회수·기체 배관과 복잡한 기압 설계는 현재 범위에 포함하지 않습니다.
- 멀티플레이·서버 세이브 동기화는 없습니다. 브라우저 자동 저장과 JSON 내보내기·가져오기를 사용합니다.
- 단일 HTML은 외부 코드·글꼴·이미지 요청 없이 만들어졌고 HTTP 미리보기에서 실행을 확인했습니다. 모든 운영체제·브라우저의 로컬 파일 저장 정책까지 확인하지는 않았습니다.
