# 21. 밸런스 분석과 검증 계획

> 대상: PC Final Cut 클래식 생존 모드 · 작성일: 2026-11-13  
> **이 문서는 [분석] 및 [재구성안]이다. 아래 실험·게임 플레이 테스트를 실행했다는 보고가 아니다.**  
> 문서의 링크·형식 검증과 실제 게임 규칙의 실행 검증을 구별한다.

## 1. 검증 목표

역기획의 품질은 규칙을 많이 적는 것만으로 결정되지 않는다. 어떤 규칙이 직접 확인되었고, 어떤 설명이 추정인지 구별할 수 있어야 한다. 또한 인물이 적고 선택지가 제한된 상황에서도 여러 대응이 의미 있게 경쟁하는지 설명할 수 있어야 한다.

검증은 세 층으로 나눈다.

| 층 | 질문 | 산출물 |
|---|---|---|
| 사실 확인 | 실제 게임이 문서대로 작동하는가 | 관찰 기록, 버전별 차이 |
| 구조 분석 | 왜 그 규칙이 선택과 결과를 바꾸는가 | 인과 관계, 대안별 비용 |
| 재현 검증 | 제안 데이터·코드가 의도한 규칙을 유지하는가 | 불변식·오류·회귀 시험 |

공개 자료만으로 수행한 이번 문서는 첫 층의 일부와 두 번째 층을 제공한다. 세 번째 층의 실제 실행은 구현물이 생긴 뒤 수행한다.

## 2. 밸런스를 읽는 핵심 지표

아래는 설계 분석을 위한 제안 지표다. 개발사가 실제 사용한 지표나 숨은 게임 수치가 아니다.

| 지표 | 산정 개념 | 의미 | 오해하기 쉬운 점 |
|---|---|---|---|
| 필수재 여유 | 현재 재고 / 예상 순소비 | 추가 조달 없이 버틸 여유 | 인물·날씨 변화로 소비가 달라짐 |
| 가용 노동력 | 역할 가능한 인물과 시간 | 다음 선택을 실행할 능력 | 생존 인원수와 동일하지 않음 |
| 운반 수익 | 이번 방문의 목적 기여 / 사용 슬롯 | 가방 선택의 적합성 | 시장 가격만 높다고 좋은 물자가 아님 |
| 위험 노출 | 위험 구간 시간·행동·불확실성 | 수색의 부담 | 원작의 확률 공식으로 사용 불가 |
| 복구 여력 | 치료품·휴식·대체 인원·비축 | 손실 후 다시 운영할 능력 | 잔여 재고 총합으로 대체 불가 |
| 대안 수 | 현재 실행 가능한 의미 있는 계획 | 선택의 폭 | UI 항목 개수와 다름 |
| 위기 인지 | 예고 이해와 대응 선택 | 정보 전달의 유효성 | 방송을 읽은 횟수만으로 판단 불가 |
| 선택 기억 | 사건의 원인·대상을 회상하는 정도 | 서사적 영향 | 도덕적 정답 여부를 측정하지 않음 |

예상 순소비가 0 이하인 자원은 단순 나눗셈으로 생존 일수를 계산하지 않는다. 생산 중단, 도구 소모, 계절 변화, 재료 고갈 같은 조건을 함께 기록한다.

## 3. 대표적인 피드백 고리

### 3.1 손실이 손실을 부르는 구조

**[분석]**

부상이나 질병으로 필요한 회복 시간이 늘면 낮의 생산과 밤의 역할 배분이 어려워진다. 조달 여유가 줄어들면 더 위험한 선택을 고려하게 되고, 그 선택의 손실이 다시 회복 부담을 늘릴 수 있다.

검증할 질문은 “연쇄가 있는가”만이 아니다. 그 연쇄를 끊을 작은 회복 기회가 존재하는지, 사용자가 그 기회를 인지하는지, 특정 조합에서는 사실상 대안이 없는지도 확인해야 한다.

### 3.2 안정이 더 큰 안정을 만드는 구조

시설과 건강한 역할 분담이 안정되면 같은 시간에 더 많은 준비를 할 수 있다. 그 준비가 위험한 방문을 줄여 다시 안정성을 높일 수 있다.

숙련자에게 이 흐름이 너무 빨리 완성되면 후반의 선택이 사라질 수 있다. 반대로 성공적인 준비를 매번 무효화하면 계획의 의미가 사라진다. 세계 사건은 이 균형을 바꾸는 요소로 평가한다.

## 4. 한 가지 전략이 항상 유리해지는 문제

| 후보 전략 | 강점 | 검사할 반대 조건 | 설계 판단 |
|---|---|---|---|
| 특정 인물만 계속 수색 | 능력 활용·운영 단순화 | 부상·피로·지역 요구·거래 | 대체 인물의 가치가 있는가 |
| 모든 자원을 시설에 투자 | 장기 효율 | 즉시 소비·겨울·캠페인 잔여 | 단기 비용이 실제로 존재하는가 |
| 매번 전투로 해결 | 자원·장애물 제거 | 건강·탄약·심리·적대 반응 | 회피·거래가 의미를 갖는가 |
| 도움을 전부 거절 | 물자·시간 보존 | 인물 반응·미래 사건 | 자체 필요와 타인 필요가 충돌하는가 |
| 거래품 생산만 반복 | 조달 경로 안정 | 투입재 부족·상인 부재·가격 | 생산 사슬에 다른 쓰임이 있는가 |
| 최소 식량만 배급 | 물자 절약 | 상태·역할·회복·도움 선택 | 단일 배급표가 모든 상황을 지배하는가 |
| 밤 외출을 계속 생략 | 외부 위험 감소 | 재고 감소·시설 재료 | 장기적으로 감수할 비용이 있는가 |

이 표는 해당 전략을 “나쁜 플레이”로 규정하지 않는다. 조건에 따라 강점이 바뀌는지 확인하기 위한 비교다.

## 5. 사실 확인 우선순위

| 우선순위 | 미확정 항목 | 먼저 검증하는 이유 |
|---|---|---|
| P0 | 모드·플랫폼·정확한 빌드 | 다른 버전의 규칙 혼합 방지 |
| P0 | 낮 종료·밤 시작·귀환·저장 경계 | 모든 실험의 기준 |
| P0 | 음식·물·연료 생산 경로와 비용 | 경제 분석의 기반 |
| P0 | 수색 반출 장비와 은신처 방어 관계 | 중복 계산 여부 |
| P1 | 허기·피로·질병·부상 단계 전이 | 회복·노동 모델 |
| P1 | 인물 특성과 시설 등급의 비용 차이 | 분업과 투자 평가 |
| P1 | 지역별 상황 변형·소유권·경고 | 탐색·도덕 반응 모델 |
| P1 | 거래 상대·인물·상황에 따른 가치 | 교환경제 평가 |
| P2 | 습격 확률·감정 가중치·NPC 임계값 | 숨은 수치 정밀화 |
| P2 | 모든 엔딩 조건과 방문 체인 | 콘텐츠 전수 검증 |

정밀한 확률을 먼저 추정하느라 기본 규칙을 놓치지 않는다. 가방에서 반출한 도구가 어디에 남는지 같은 확정 동작부터 확인하는 편이 효과적이다.


## 7. 구체적 관찰 실험

### 실험 A. 인물 특성이 제작 비용에 미치는 영향

**목적:** 기본 인물과 특성 보유 인물의 비용 차이, 시설 등급과의 상호작용을 확인한다.

1. 같은 시설·등급·레시피·수량을 준비한다.
2. 선택 인물만 바꾸어 UI 비용을 기록한다.
3. 각 인물이 실제 제작했을 때의 재고 전후를 기록한다.
4. 인물 특성 적용이 UI 미리보기와 실행에서 일치하는지 확인한다.
5. 제작 수량과 시설 등급을 바꿀 때는 별도 실험으로 취급한다.

**오염 요인:** 다른 레시피 선택, 이미 예약된 재료, DLC·모드 효과, 화면 갱신 지연.  
**판정:** 고정 할인율을 가정하지 않고 레시피별 관찰값을 보관한다.

### 실험 B. 시간 경계와 주간 조기 종료

**목적:** 진행 중 작업·수면·방문자와 End Day의 관계를 확인한다.

1. 어떤 작업도 없는 상태에서 자연 종료 결과를 기록한다.
2. 같은 종류의 작업을 서로 다른 시작 시각에 지시한다.
3. 조기 종료와 자연 종료에서 작업 결과·소비 재고·상태를 비교한다.
4. 수동 작업과 대기형 생산을 분리한다.
5. 저장 재개가 어느 시점으로 돌아오는지 따로 기록한다.

**오염 요인:** 서로 다른 인물 능력, 이동 시간, 실제 일시정지 여부.  
**판정:** 모든 작업을 하나의 “종료 시 즉시 완료” 규칙으로 일반화하지 않는다.

### 실험 C. 소음·시야·적대 반응

**목적:** 목격과 청각 조사, 경고와 공격을 구분한다.

1. 같은 지역 변형과 NPC 상태를 기록한다.
2. 걷기·뛰기·도구 사용 등 한 행동만 바꾼다.
3. NPC가 시야를 확보하기 전후의 반응을 분리해 관찰한다.
4. 무기 노출과 사유 구역 진입은 별도 변수로 다룬다.
5. 소음 표시가 사라진 뒤에도 NPC가 조사하는지 기록한다.

**오염 요인:** NPC 순찰 위치, 이미 발생한 경계 상태, 인물 특성.  
**판정:** 한 번 들키지 않았다고 완전 무소음이나 시야 면역으로 결론 내리지 않는다.

### 실험 D. 심리 반응과 회복

**목적:** 사건 맥락, 인물 차이, 시간 경과를 분리한다.

1. 동일 사건 전의 인물 상태와 최근 주요 사건을 기록한다.
2. 수락·거절·미응답을 구분한다.
3. 행위자와 나머지 동료의 반응을 따로 기록한다.
4. 즉시 대사와 다음 날의 상태 변화를 구분한다.
5. 음식·휴식·대화 등 다른 회복 조치를 통제한다.

**오염 요인:** 여러 사건의 누적, 세계 사건, 가족·관계 조건, 숨은 상태.  
**판정:** 관찰한 반응 방향과 숨은 점수식을 구분한다. 완전한 내부 점수 복원이 불가능하면 상태 수준의 규칙으로 남긴다.

## 8. 확률을 추정할 때의 원칙

같은 저장을 불러와 반복한 결과는 독립 표본이 아닐 수 있다. 난수 상태가 저장되어 있거나 이미 결과가 결정되었다면 반복 횟수를 늘려도 새로운 정보를 얻지 못한다.

| 상황 | 잘못된 결론 | 적절한 기록 |
|---|---|---|
| 한 번 습격 없음 | 방어가 완벽하다 | 해당 조건에서 습격이 관찰되지 않음 |
| 동일 저장 10회 같은 결과 | 발생 확률 100% | 결과 또는 난수 고정 가능성 |
| 다른 시나리오에서 결과 차이 | 특정 인물의 효과 | 시나리오 차이 통제 필요 |
| 여러 조건 동시 변경 | 어느 한 변수가 원인 | 변화 요인 분리 필요 |
| 추위 중 건강 유지 | 임계온도 이상이면 질병 0 | 관찰 기간·회복 조치 함께 기록 |

표본 수와 조건이 부족하면 정밀한 퍼센트를 출력하지 않는다. 구조를 설명하는 데 필요하지 않은 숨은 상수는 무리해서 추정하지 않아도 된다.

## 9. 시스템별 통합 시험

아래 기대 결과는 **재구성 구현의 일관성 요구**다. 실제 원작에서 동일하게 동작한다고 확인한 결과표가 아니다.

| ID | 통합 상황 | 기대하는 일관성 |
|---|---|---|
| INT-01 | 음식 제작 중 같은 재료 거래 | 예약 재고가 이중 사용되지 않음 |
| INT-02 | 시설 업그레이드 중 낮 종료 | 시설·작업·재료 상태가 연결됨 |
| INT-03 | 반출 무기 전량과 은신처 습격 | 집에 남지 않은 무기를 계산하지 않음 |
| INT-04 | 수색자 사망·가방 보유 | 인물·물자·이력 결과가 일치 |
| INT-05 | 수색자 지연 귀환 | 부재와 영구 사망 구분 |
| INT-06 | 부상자 치료와 아침 상태 판정 | 치료·경과를 한 번만 반영 |
| INT-07 | 방문 도움으로 밤 인원 감소 | 역할 배정 후보 갱신 |
| INT-08 | 사건 종료와 가격 수정 | 다른 사건의 가격 효과 유지 |
| INT-09 | 지역 재방문과 루팅 변경 | 지속 상태 적용 |
| INT-10 | 사유 물자 이동과 NPC 목격 | 경제·인지·서사 사건 맥락 일치 |
| INT-11 | 사건 반응 중 저장·재개 | 정서 반응 중복 없음 |
| INT-12 | 종전과 미완료 생산 | 종결 정책에 맞게 정리 |
| INT-13 | Stories 전용 목표 아이템 | 일반 판매·분해 가능 정책 명확 |
| INT-14 | The Little Ones 인물 역할 | 성인 역할 규칙 무조건 적용 금지 |
| INT-15 | 모드 변경과 저장 로드 | 호환성 검사 |
| INT-16 | 일시정지 중 모든 시간 시스템 | 의도한 정지 정책 유지 |

## 10. 콘텐츠 회귀 시험

| 축 | 대표 조합 | 확인하는 문제 |
|---|---|---|
| 인물 | 적은 인원, 특성 편중, 부상 시작 | 필수 역할 공백 |
| 지역 | 무인, 거래, 민간인, 적대, 변형 지역 | 상호작용·소유권·위험 차이 |
| 환경 | 온화, 추위, 범죄 증가, 복합 상태 | 자원·방어·접근성 결합 |
| 재고 | 필수재 최소, 가방 가득 참, 도구 없음 | 소프트락·오류 설명 |
| 서사 | 도움·거절·상실·폭력 이력 | 맥락에 맞는 반응 |
| 시간 | 첫날, 중반, 종전 직전, 마감 경계 | 수명과 처리 순서 |
| 저장 | 새 회차, 중간 재개, 업데이트 후 로드 | 지속성·버전 |

모든 조합을 전수 실행하기 어렵다면 위험이 높은 교차점부터 고른다. 예를 들어 인원 부족과 외출 요청, 추위와 연료 부족, 종전과 지연 귀환은 둘을 함께 볼 때 의미 있는 문제를 드러낸다.

## 11. 플레이테스트 질문

평가자가 “좋은 선택을 했는가” 대신 다음을 묻는다.

1. 오늘 가장 부족했던 것은 무엇이었는가.
2. 왜 그 사람을 밖으로 보냈는가.
3. 가져오지 못한 물건 중 가장 아쉬운 것은 무엇인가.
4. 도움 요청에서 어떤 비용을 고려했는가.
5. 예상과 달랐던 결과를 설명할 수 있는가.
6. 다음 날 계획을 가장 크게 바꾼 사건은 무엇인가.
7. 한 인물을 잃었을 때 무엇이 가장 달라졌는가.
8. 다시 플레이한다면 어떤 선택을 바꾸고 싶은가.

이 답변은 성공률만으로 드러나지 않는 의사결정의 질과 기억을 보여 준다. 같은 실패율이라도 원인을 이해한 실패와 조작을 오해한 실패는 다른 문제다.

## 12. 프로토타입 검증 순서

**[확인·개발자 개인 회고]** 참여 디자이너는 욕구 시스템을 스프레드시트로, 전투·제작을 작은 C# 응용으로 먼저 시험한 경험을 설명한다. 이는 원작의 당시 프로토타입 이력이며 현행 런타임 구현 언어에 대한 근거가 아니다. [P06](https://www.gamedeveloper.com/design/7-things-i-ve-learnt-from-designing-this-war-of-mine)

**[재구성안]** 같은 목적의 검증이라면 다음 순서가 적절하다.

| 단계 | 가장 작은 실험 | 종료 기준 |
|---|---|---|
| 경제 | 하루 소비·생산·가방 선택 표 | 물자 간 선택이 생김 |
| 인물 | 역할·피로·회복 모형 | 오늘과 다음 밤이 연결됨 |
| 외부 탐색 | 작은 지역과 한 위험 | 수익·시간·귀환 판단이 생김 |
| 도덕 반응 | 소수 사건과 서로 다른 인물 | 맥락이 선택의 이유를 바꿈 |
| 캠페인 | 몇 가지 사건을 포함한 짧은 회차 | 위기와 회복의 흐름을 설명 가능 |
| 확장 | 인물·지역·레시피 추가 | 핵심 관계가 유지되고 새 선택 추가 |

## 13. 이번 문서 세트의 검증 범위

이번 산출물의 근거는 개발사 공개 자료, 참여 개발자의 설명, 커뮤니티 문서의 공개된 내용이다. 실제 게임 실행이나 모딩 도구 설치, 저장 파일 추출, 숨은 확률 실험은 하지 않았다.

따라서 이 문서 세트는 시스템 구조와 설계 의도를 검토하고 구현 계획을 세우는 기준 문서로 사용할 수 있다. **특정 패치의 수치가 정확히 일치하는 복제 구현용 데이터베이스**로 사용하려면 위 실험을 통해 세부 규칙을 보완해야 한다.

모든 불확실성을 해소할 때까지 설계 작업을 멈출 필요는 없다. 구현 결과에 큰 영향을 주는 항목을 먼저 검증하고, 불확실성이 남는 값은 조정 가능한 데이터로 분리하면 된다.
