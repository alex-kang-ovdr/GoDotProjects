# LAST LIGHT · 마지막 불빛 — Campaign Edition 4.0

JavaScript와 Canvas 2D로 구현한 한국어 싱글플레이 생존 전략 게임입니다. 《This War of Mine》 역기획서에서 분석한 **낮의 은신처 운영 → 밤의 수색과 방어 → 상태 정산 → 다음 날** 구조를, 12일 캠페인으로 구현했습니다. 게임의 이름·인물·그림·문장·지도·밸런스는 이 프로젝트를 위한 독립 구성입니다.

## 이번 버전에서 완성한 흐름

기존의 낮 운영·밤 수색·습격·회복·12일 결말에 **구호 연락망과 대피 준비**, **부품을 던지는 소음 유인**, **탐험 기억을 사용하는 미니맵과 귀환 안내**를 연결했습니다. 생존자의 상태에 따라 오늘 필요한 행동을 안내하고, 무전기와 대피 꾸러미의 준비 상태도 은신처 장면에 표시합니다.

- 무전기 복구 → 4일째부터 구호 교신 → 다음 아침의 한정 보급 → 9일째부터 대피 물자 봉인 → 준비 여부가 남는 결말.
- 부품 1개를 챙겨 출발 → T 또는 유인 버튼으로 조준 → 보이는 같은 층에 투척 → 경비의 시선을 돌리고 은밀히 이동.
- 현재 시야의 사람과 이미 발견한 장소만 지도에 표시. 닫힌 문과 아직 확인하지 않은 귀환 구간은 그대로 구분합니다.
- 기존 저장은 없는 필드만 보완하여 이어갑니다. 서버나 외부 패키지 없이 실행합니다.

## 가장 간단한 실행

`dist/last-light.html`을 브라우저로 열면 됩니다. CSS와 모든 JavaScript가 한 파일에 들어 있으며 네트워크 연결이나 게임 서버가 필요하지 않습니다. 로컬 파일에서 저장소를 제한하는 브라우저에서는 JSON 저장 파일 내보내기를 사용하세요.

단일 파일을 다시 만들려면 Node.js에서 다음 명령을 실행합니다. 외부 npm 패키지는 필요하지 않습니다.

```bash
npm run offline
```

## 모듈 소스로 실행

별도 빌드나 npm 의존성 설치가 필요하지 않습니다. 소스 ZIP을 풀고 해당 디렉터리에서 다음 명령을 실행합니다.

```bash
python3 -m http.server 8080 --directory dist
```

브라우저에서 <http://localhost:8080>을 엽니다. ES 모듈을 사용하므로 `index.html`을 파일 탐색기에서 직접 열기보다 HTTP 서버로 실행하세요. `dist` 폴더는 그대로 정적 호스팅에 배포할 수 있습니다.

## 게임의 목표

민간인 세 명을 돌보며 **12번째 밤까지 한 명 이상 생존**하면 구호 통로가 열립니다. 모두 사망하면 캠페인이 끝납니다. 플레이 시간은 낮의 진행 속도와 수색·일시정지 시간에 따라 달라집니다. 처음에는 시간이 멈춰 있으며, 작업을 맡기거나 재생을 누르면 흐릅니다.

### 세 사람

| 인물 | 역할 | 특성 | 수색 가방 |
|---|---|---|---:|
| 미라 | 간호사 | 자신과 동료를 치료할 때 회복 보너스 | 10칸 |
| 윤 | 정비공 | 제작·시설 건설 시간 20% 단축 | 12칸 |
| 레오 | 배달원 | 가장 넓은 가방 | 15칸 |

화면의 건강·포만·기력·사기는 높을수록 좋습니다. 내부 데이터의 `hunger`와 `fatigue`는 높을수록 나쁜 값이므로 화면에는 `100 - 값`으로 표시합니다.

## 권장 첫날

1. 미라에게 조리를 맡깁니다. 조리 완료 후 식사는 자동으로 먹지 않으므로 배고픈 사람을 선택해 배급합니다.
2. 윤에게 시설 탭의 집수기 건설을 맡깁니다. 재료가 부족하면 제작 탭에서 잔해를 정리합니다.
3. 레오는 휴식으로 기력을 준비한 뒤 밤의 수색을 담당합니다.
4. 첫 수색에서는 폐가의 상자를 조사해 식재료·목재·부품을 가져옵니다.
5. 4일째부터 오는 추위에 대비해 난로와 연료를 준비합니다.
6. 다음 날 보고서에서 문 손상과 재고 변화를 확인하고 필요하면 시설 탭에서 은신처를 수리합니다.
7. 진료소·정비소·아파트로 갈 때는 주민에게 건넬 물자도 고려하세요. 출입 허락과 사유 물품을 가져갈 허락은 구분됩니다.

`밤을 준비하기`는 낮의 남은 시간을 진행시킵니다. 완료할 수 있는 진행 중 작업은 마치고, 남은 시간보다 긴 작업은 취소하여 예약 재료를 반환합니다. 버튼을 누른 뒤에는 낮으로 돌아가지 않습니다.

## 새로운 생존 환경

표준은 기존 출발 물자와 밤 허기 +18을 사용합니다. 봉쇄는 시작 물자가 줄고, 밤 허기 +21·습격 확률 ×1.35·강도 +4·문 마모 ×1.6이 적용됩니다. 두 난이도 모두 12일 캠페인입니다. 새 게임 화면에서 난이도와 선택적인 생존기 번호를 정하고 시작합니다. 같은 번호·난이도·행동 흐름으로 결과를 재현할 수 있습니다.

문 보강의 방어 기여는 `단계 × 11 × 내구도 / 100`입니다. 습격이 발생하면 방어 성공 후에도 문이 손상됩니다. **은신처 수리**는 목재 2·부품 1, 기본 70분으로 내구도를 최대 35 회복합니다. 윤은 기본 수리 시간이 56분입니다.

적이 근접하면 0.55초의 공격 예고가 보입니다. 실제 타격 시점에 거리를 벌리거나 회피·문으로 대응할 수 있습니다. 회피는 0.26초, 그중 회피 판정은 0.18초이고 재사용 대기는 2.4초입니다. 스태미나는 별도의 현장 행동 자원으로, 낮 화면의 기력과 다릅니다.

## 구호 연락망과 대피 준비

구호 연락망 화면에서 담당자와 비용·시간을 확인하고 작업을 맡길 수 있습니다. 일반 행동 목록에서도 같은 작업을 수행합니다.

| 준비 | 가능한 날짜·조건 | 비용 | 기본 시간 | 결과 |
|---|---|---|---:|---|
| 무전기 복구 | 첫날부터 | 목재 2·부품 5 | 100분, 윤 80분 | 모두의 사기 +3, 교신 준비 |
| 구호팀과 교신 | 4일 이후·무전기 복구 | 부품 2·연료 1 | 80분 | 사기 +5, 다음 아침 보급 예약 |
| 대피 물자 봉인 | 9일 이후·교신 완료 | 식사 3·물 4·붕대 1 | 100분 | 사기 +8, 준비된 대피 결말 |

질병·사기 상태에 따른 작업 시간 가감은 일반 작업과 같습니다. 각 단계는 한 번만 완료하며 예약과 중단 환급을 지원합니다. 교신 보급품은 **식재료 2·약품 1·붕대 1·연료 2**입니다. 지난밤의 난방·습격 뒤에 도착하므로 해당 밤의 비용을 대신 내주지 않습니다.

장기 목표는 선택 사항입니다. 준비를 마치지 않아도 12번째 밤에 한 명 이상 살아 있으면 승리합니다. 봉쇄에서는 무전기에 쓸 재료와 문 보강·난방의 우선순위를 함께 결정해야 합니다. 검증 정책은 3일에 무전기를 복구하고, 부족해진 문 보강 재료를 다음 수색으로 보완합니다.

## 소음 유인과 길 찾기

부품은 건설·나눔뿐 아니라 야간 유인에도 사용할 수 있습니다. 가방에 부품을 넣고 T 또는 유인 버튼을 누른 뒤 밝게 보이는 같은 층을 클릭·탭하세요. 조준하는 동안 시간은 멈추며, 잘못된 위치를 누르거나 취소하면 부품을 소모하지 않습니다. 성공하면 시간을 재개하고 기존 이동 경로를 멈춥니다.

- 비용 부품 1개, 재사용 8초. 너무 가깝거나 먼 곳, 다른 층, 닫힌 문 너머는 불가능합니다.
- 플레이어를 보지 못한 사람이 착지점의 소리를 들으면 그곳까지 걸어가 조사합니다. 이미 공격 중이거나 나를 보고 있는 적의 추격을 지워 주지는 않습니다.
- 은신처 안에서 던져도 숨은 상태를 유지하며, 주민을 소리로 유인한 사실만으로 적대 관계를 만들지 않습니다.
- 미니맵은 탐험한 구간·발견한 물자·문과 현재 보이는 NPC만 보여 줍니다. 사라진 NPC의 위치나 조사하지 않은 상자의 내용은 공개하지 않습니다.
- 귀환선은 실제로 알고 있는 계단과 길을 따라 이어지고, 첫 닫힌 문 앞에서 멈춥니다. 문은 E 또는 클릭으로 여세요.

설정에서 탐색 지도와 화면 움직임 줄이기를 선택할 수 있습니다. 화면 움직임 설정은 시각 효과만 바꾸며 게임 시간·행동 판정은 같습니다.

## 구현 시스템

- 3명의 건강·허기·피로·사기·질병과 인물별 특성.
- 동시 작업, 인물당 최대 3개 대기열, 미래 시설·재료를 반영한 예약, 실제 시작 시 재료 차감, 중단 환급.
- 동료 대상 약품·붕대 치료와 미라의 치료 보너스.
- 출발 전 방어력·습격 확률·난방 연료·침대 배정 예측.
- 식사, 조리, 식수, 연료, 휴식, 치료, 대화, 유한 잔해 수거.
- 침대·집수기·난로·문 보강·덫·스토브 개선, 지렛대·칼 제작.
- 추운 날의 난방과 연료 소비, 질병·허기·피로에 따른 생존 압박.
- 매일 수색 0~1명, 경계·수면 역할 배분, 반출 장비와 남은 방어 장비 구분.
- 날짜에 따라 열리는 5개 장소와 3층 이동, 조사·잠금·사유 물품.
- 3곳 주민에게 통행 요청 또는 유한한 도움·교환, 사유 물자 허락, 공격 후 관계 악화와 재방문 지속.
- 품목별 묶음과 가방 칸, 물건 내려놓기·회수, 반복 방문의 잔여 물자 유지.
- 주민의 경고·순찰·소음 반응·추적·공격·도주, 은신과 근접전.
- NPC 공격 예고와 거리·문·회피 재판정, 스태미나 비용·회복, 충돌을 지키는 유한 회피.
- 실제 충돌과 시야를 막는 문, 미탐험 구역, 발견한 물품 기억, 현재 시야의 NPC만 표시.
- 3초 응급처치, 이동·피격 시 취소, 완료 시 붕대 소비와 건강 회복, 12초 재사용 대기.
- 약탈, 낮의 상인·방문자 선택, 도움·절도·사망에 따른 기록과 사기.
- 직접 품목과 수량을 고르는 물물교환, 판매·구매 가격 차이, 꾸러미와 공유하는 유한 상인 재고.
- 습격에 따른 문 마모와 유료 수리, 예측과 실제 판정의 공통 공식.
- 재고 순증감과 세 인물의 상태 전후 보고, 12일 승리·전원 사망 패배·인물별 직업과 선택이 남는 후일담.
- 브라우저 자동 저장과 정상 백업 복구, 하루 시작 기록 복구, JSON 내보내기·불러오기, 구 버전 저장 호환.

`engine.js`와 `expedition.js`는 DOM 의존성이 없는 ES 모듈입니다. `scene.js`는 상태를 읽어서 그릴 뿐 게임 수치를 바꾸지 않습니다. `saves.js`는 진행 상태와 현장 상태의 일치를 검증한 뒤 저장합니다. 별도 백엔드·로그인·외부 CDN·분석 스크립트가 없습니다. 자동 저장은 현재 사이트 주소의 브라우저 저장소에만 남습니다. 주소나 기기를 바꿀 때는 JSON 저장 파일을 옮기세요.

## 검증

Node.js가 설치되어 있으면 아래 명령으로 게임 규칙 테스트를 실행합니다.

```bash
npm test
npm run check
npm run test:offline
```

테스트는 두 난이도의 여러 시드에서 12일 캠페인 완주, 전원 사망, 재료 예약과 환급, 반출과 귀환의 중복 적용 방지, 남은 장비로만 방어하기, 무리한 가방 적재 거부, 이동·계단·소음·주민 경고, 클릭한 대상 정확히 상호작용하기, 장소 고갈 유지, JSON 저장 후 수색 재개를 검사합니다. 4.0에서는 구호 단계와 지연 보급의 중복 방지, 준비된 대피 완주, 합법적인 창고 은신·유인·귀환, 조준 취소와 비용 원자성, 미니맵 정보 제한도 검증합니다. 전체 자동 테스트 158개와 단일 HTML UI 검증이 통과했습니다. 실제 결과와 브라우저 검증 범위는 [VALIDATION.md](VALIDATION.md)에 정리했습니다.

## 범위

이 프로젝트는 핵심 시스템이 연결된 플레이 가능한 프로토타입입니다. 원작의 정확한 수치·상용 분량·콘텐츠·그래픽을 복제한 완제품은 아닙니다. 고정 3인과 고정 지도 5곳, 12일 압축 캠페인, 간소화된 근접전·NPC·이벤트를 사용합니다. 멀티플레이·서버 동기화·DLC·어린이 시스템·원작 스토리 캠페인은 포함하지 않습니다.
