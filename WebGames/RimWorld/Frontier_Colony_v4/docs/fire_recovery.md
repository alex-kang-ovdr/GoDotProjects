# 화재와 복구 시스템

이 문서는 Frontier Colony v3의 실제 JavaScript 구현을 설명한다. 수치는 이 프로젝트의 게임 규칙이며 림월드의 내부 수치나 공식 규칙을 재현한 것이 아니다. 시간 단위는 일시정지·배속을 반영한 **시뮬레이션 초**다.

구현 근거는 [hazards.js](../dist/hazards.js), [colony-systems.js](../dist/colony-systems.js), [engine.js](../dist/engine.js), [renderer.js](../dist/renderer.js)다. 의료·구조·일정의 전체 규칙은 해당 시스템 문서를 함께 참고한다.

## 1. 시스템의 역할과 실행 순서

화재는 타일에 저장된 화력과 연료를 소비하며 주변에 번지고, 구조물·식물·인물에게 실제 피해를 준다. 소방 담당자는 불 옆까지 이동한 뒤 작업 시간에 비례해 화력을 낮춘다. 화재 때문에 침상이나 벽, 전력선이 파괴되면 작업·환자 예약을 정리하고 방과 전력망을 다시 계산한다.

엔진의 환경 주기는 0.5초다. 환경·온도·식량 갱신 `updateSystems(game, dt)` 다음에 `updateHazards(game, dt)`를 호출하고, 이후 습격 종료와 구조 신호 조건을 확인한다. 큰 `dt`를 직접 전달하면 화재 모듈은 최대 0.5초 단위로 나누어 연소를 계산한다. 모듈 자체는 `state.time`을 증가시키지 않는다. 낙뢰 예정 시각은 호출 시점의 엔진 시각으로 판단한다.

열 계산은 현재 저장된 화력을 읽고, 이어서 화재 모듈이 다음 화력을 갱신한다. 새 점화의 온도 영향은 다음 환경 주기부터 나타난다. 건물 파괴 뒤 실행되는 `refreshSystems()`는 방·전력의 연결을 즉시 갱신하지만 추가 시간, 부패, 충방전을 발생시키지 않는다.

## 2. 공개 API와 저장 상태

| API | 동작 |
|---|---|
| `initializeHazards(game, {migration=false}={})` | 없는 필드만 기본화한다. 기존 화력·연료·예정 시각·난수·시계를 바꾸지 않는다. |
| `igniteTile(game, x, y, strength=.35)` | 점화 가능 여부를 먼저 검사하고 `{ok, message}`를 반환한다. 실패하면 상태를 변경하지 않는다. |
| `updateHazards(game, dt)` | 낙뢰, 연소, 피해, 확산, 파괴 후 연결망 갱신을 처리한다. |
| `validateHazards(data, bad)` | 잘못된 화재 저장 상태를 `bad(reason)`으로 거부한다. |

시나리오·검증용 엔진 명령은 `game.command('ignite', {x, y, strength})`다. 일반 플레이 화면에는 점화 도구가 없다. 플레이어의 소방 명령은 `prioritize`를 사용하며, 명령 자체가 화력을 즉시 없애지는 않는다.

```js
tile.fire = 0;       // 현재 화력: 0~1
tile.fireFuel = 0;   // 남은 연료: 연속량
tile.burned = false; // 탄자리 여부

state.hazards = {
  nextIncidentAt: 360,
  spreadTimer: 0,
  incidentCount: 0,
  extinguished: 0,
  burnedBuildings: 0,
  burnedPlants: 0
};
```

`incidentCount`는 실제 점화에 성공한 낙뢰 사건 수다. `extinguished`는 주민의 소방 작업이 불을 끝까지 끈 횟수이며, 비나 연료 소진으로 꺼진 불에는 증가하지 않는다. `burnedBuildings`는 불로 삭제된 완성 건물 수, `burnedPlants`는 제거된 나무·딸기나무·작물 수다. 식량 부패 통계는 별도의 `systemStats.spoiled`가 계속 담당한다.

## 3. 낙뢰 발생 규칙

| 항목 | 보통 | 여유롭게 |
|---|---:|---:|
| 새 게임 첫 예정 시각 | 360초 | 480초 |
| 구버전 저장 이동 후 첫 대기 | 저장된 현재 시각 + 360초 | 저장된 현재 시각 + 480초 |
| 이후 사건 간격 | 300~390초 | 360~450초 |
| 최초 화력 | 0.35 | 0.28 |

이후 간격에는 `floor(game._rand() * 91)`을 더한다. 예정 시각에 습격이 진행 중이거나 현재 불이 8칸 이상이면 사건을 **현재 시각 + 45초**로 미룬다. 낙뢰 하나는 한 칸만 점화한다.

낙뢰 위치는 아래 조건을 충족하는 타일에서 선택한다.

- 완성 건물들의 평균 위치에서 직선거리 6~12칸이다. 건물이 없으면 생존 주민의 평균 위치, 주민도 없으면 지도 중심을 사용한다.
- 지붕·건물·작물이 없고, 아직 불이 붙지 않았으며 연료가 있다.
- 모든 완성 건물과의 맨해튼 거리가 3칸 이상이다.
- 살아 있는 주민으로부터 타일 중심까지 2칸 이상 떨어져 있다.

후보 중 나무·딸기나무가 있는 곳을 먼저 선택하고, 없으면 다른 연료 후보를 사용한다. 후보가 없으면 점화와 사건 통계 증가는 생략하고 다음 예정 시각만 정한다. 낙뢰는 기지의 완성 건물이나 주민 위를 곧바로 점화하지 않도록 설계되어 있다. 다만 이후 실제 확산으로 기지에 도달할 수 있다.

## 4. 점화와 연료

점화 좌표는 지도 안의 정수 셀이어야 하며 화력은 유한한 수 **`0 < strength <= 1`**이어야 한다. 물, 연료 없는 빈 돌바닥, 건설 계획이 있는 타일은 점화할 수 없다. 이미 불이 난 타일을 다시 점화해 연료나 화력을 초기화할 수도 없다. 건설 계획이 있는 타일은 그 아래 자연 연료가 있더라도 대상에서 제외한다.

잔여 연료가 있으면 새 점화도 그 연료를 사용한다. 잔여 연료가 0이면 현재 타일의 연료를 다음 표대로 합산한다.

| 연료 요소 | 연료량 |
|---|---:|
| 아직 타지 않은 잔디 | 10 |
| 나무 | `48 + min(24, amount)` |
| 딸기나무 | 25 |
| 작물 | 18 |
| 나무 벽 / 문 | 100 / 85 |
| 침대 / 조리대 / 방벽 | 70 / 65 / 105 |
| 연구대 / 고리 던지기 | 80 / 60 |
| 구조 신호기 | 130 |
| 태양광 / 축전지 | 75 / 65 |
| 냉각기 / 난방기 / 전력선 | 65 / 65 / 20 |

건물 연료는 완성되었고 내구도가 남은 구조물에만 적용한다. 표에 없는 완성 건물의 방어적 기본값은 45다. 건물과 잔디처럼 같은 칸에 있는 요소의 연료는 합산한다. 이미 탄 잔디는 자동으로 다시 연료를 생성하지 않는다. 그 위에 새 작물이나 건물을 두면 해당 요소는 연료가 될 수 있다.

연소 중 연료 소비량은 **`(0.35 + 0.95 × 현재 화력) × dt`**다. 연료가 0이면 불이 꺼진다. 연소가 한 번 진행되면 `burned=true`가 되며, 진화 후에도 탄자리 표시가 남는다. 이 표의 연료 단위는 게임 균형용 연속량으로, 목재 아이템의 개수와 같지 않다.

## 5. 화력 변화, 비, 번짐

화력은 다음 변화를 적용한 뒤 0~1로 제한한다.

| 조건 | 초당 화력 변화 |
|---|---:|
| 잔여 연료가 4보다 많음 | +0.045 |
| 잔여 연료가 4 이하 | −0.20 |
| 비가 오며 지붕 없음 | 위 변화에 추가로 −0.30 |

비는 `tile.roofed === false`인 칸에만 적용된다. 비에 노출된 불은 이웃으로 퍼뜨리지 않는다. 지붕이 유지되는 실내의 불은 비만으로 꺼지지 않는다. 벽 파괴로 방이 열리고 지붕이 해제되면 다음 화재 갱신부터 비의 영향을 받는다.

확산은 **3초마다** 실행하며, 타일 배열 순서와 상·우·하·좌 이웃 순서를 고정한다. 각 기존 화재는 점화 가능한 직교 이웃이 있을 때 **`0.45 × 현재 화력`** 확률로 이웃 하나를 선택한다. 새 불의 화력은 **0.22**다. 확산 직전에 수집한 기존 불만 이번 주기의 출발점이므로, 새 불이 같은 주기에 다시 연쇄 확산하지 않는다.

균형과 처리량을 위해 한 확산 주기에 새 불은 최대 **4칸**, 지도 전체 동시 화재는 최대 **32칸**이다. 직접 `igniteTile`을 호출해도 32칸 제한을 적용한다. 이 제한은 구현상 게임 규칙이다. 불을 끄거나 자연 소진되면 빈 화재 슬롯을 다시 사용할 수 있다.

## 6. 피해와 실내 열

완성 건물은 **`6 × 화력` HP/초**, 같은 타일을 차지하는 주민과 약탈자는 **`5 × 화력` HP/초**의 직접 피해를 받는다. 인물의 실수 좌표를 내림해 점유 칸을 찾는다. 운반 중인 환자도 실제 위치에 따라 피해를 받을 수 있다. 화재 피해는 총격용 `_hitPawn`을 사용하지 않으며 **출혈을 새로 만들지 않는다**.

주민이 체력 15 이상에서 15 미만으로 내려가면 `_downPawn`을 호출하고, 체력이 0이면 `_killPawn`을 호출한다. 기존 엔진의 자원·작업·환자 운반 정리 절차를 그대로 사용한다. 약탈자는 체력 0에서 사망 상태로 바뀌고 제압 통계가 한 번 증가한다.

식물은 소수 개수의 수확물을 만들지 않도록 처리한다. 나무·딸기나무는 연소 중 남은 연료가 **`max(6, 현재 fuelFor(tile) × 0.5)` 이하**가 되면 개체와 지정 작업을 제거하고 수확량을 0으로 만든다. `fuelFor(tile)`는 현재 요소로 다시 계산하며 이미 탄 잔디는 포함하지 않는다. 작물은 성장량을 **`0.06 × 화력`/초**씩 잃고, 성장량 0에서 제거된다. 성장 감소와 별개로 엔진의 통상 작물 성장도 실행된다. 식물이 사라지면 그 타일의 채집·농사 작업 예약을 해제한다.

온도 시스템에도 불이 연결되어 있다.

- 실외 불타는 칸은 통상 외기 수렴 계산 뒤 **`7 × 화력 × dt` °C**를 더한다. 실외는 3초 시정수로 외기 온도를 향해 변하므로 불이 꺼져도 온도를 즉시 초기화하지 않는다.
- 실내는 각 불에서 **`1400 × 화력`**의 모델 열량/초를 더한다. 방의 열용량은 `12 × 면적 + 120`이며, 실내 온도 증가는 `합산 열량 × dt / 열용량`이다.
- 이 열을 반영한 뒤 냉각기·난방기의 기존 온도 조절을 적용한다. 온도는 저장 검증과 일치하도록 −100~150°C로 제한한다.

따라서 화재는 직접 화상뿐 아니라 기존 온도 부담과 식량 부패 경로에도 영향을 준다. 냉각기를 켜 놓았다는 이유만으로 실내 화재가 무효화되지는 않는다. 벽 자체의 불은 방 타일에 포함되지 않으므로 실내 열원 합계에 직접 더하지 않지만, 벽이 무너지면 방이 열리고 그 결과가 반영된다.

## 7. 진화, 파괴와 복구

소방은 별도의 `firefight` 작업이다. 실제 작업 예약키는 `fire:x,y`이며 주민은 접근 가능한 인접 칸까지 이동한다. 작업 중 초당 **`0.25 + 소방 기술 × 0.025`**만큼 화력을 낮춘다. 소방에 별도 물품은 소비하지 않는다. 화력이 0.001 이하에 도달하면 정확히 0으로 만들고 탄자리를 유지하며, `hazards.extinguished`를 한 번 증가시킨다. 자연적인 화력 증가는 환경 주기에서 별도로 계산한다.

완성 건물의 내구도가 0이 되면 다음 순서로 처리한다.

1. `game._onBuildingDestroyed(building, tile, 'fire')`로 해당 구조물을 목표·목적 침상으로 삼던 작업, 운반 환자, 환자의 침상 참조를 안전하게 정리한다.
2. `tile.building=null`로 구조물을 삭제하고 파괴 통계를 증가시킨다.
3. 해당 갱신의 파괴 처리가 끝난 뒤 `refreshSystems()`로 방·지붕·전력망을 갱신한다.

화재는 철거·건설 취소 명령을 호출하지 않으며 **자재 환불이나 철거 잔해를 생성하지 않는다**. 운반 중이던 수리 자재 등은 엔진의 정상 작업 해제 규칙에 따라 한 번만 내려놓는다. 불타는 칸에 새 건설 계획을 두거나 불타는 건물을 철거해 소방을 우회하는 행위는 엔진 명령에서 차단한다.

벽이 소실되면 실내·지붕 판정이 바뀌고, 전력선이나 발전·저장 장치가 소실되면 공급이 끊길 수 있다. 의료침상이 소실되면 환자는 해당 침상을 계속 참조하지 않고 다시 구조·간호가 필요한 상태가 된다. 불이 남아 있으면 구조 신호 전송은 멈추며, 누적 신호 진행률은 유지된다. 화재가 끝나고 다른 승리 조건도 충족하면 기존 진행률에서 이어진다.

복구 흐름은 **진화 → 부상자 구조·치료 → 방 경계와 침상 복구 → 전력망 확인 → 냉장·식량 확인 → 신호 재개**다. 지도에서 불을 우선 작업 대상으로 선택하거나 의료·소방 화면의 진화 지시를 사용한다. 명령을 내린 주민은 이동과 작업을 실제로 수행해야 한다.

## 8. 저장, 결정성, 화면 표현

화력·연료·탄자리·확산 타이머·다음 사건 시각·통계는 모두 직렬화 가능한 상태 안에 있다. 확산과 낙뢰의 난수는 실제 엔진의 `game._rand()`를 사용하고, 엔진의 `rngState`와 함께 저장된다. 초기화·렌더링은 난수를 소비하지 않는다. 모듈에 저장되지 않는 확산 이력이나 벽시계 타이머를 두지 않는다.

화재 저장 검증은 화력 0~1, 연료 0~1,000,000, 참/거짓 탄자리, 0 이상 정수 통계, `0 <= spreadTimer < 3`, 동시 불 32칸 이하를 검사한다. 연료 없는 불, 물 위의 불, 건설 계획 위의 불도 거부한다. 시간·통계 상한은 10,000,000,000이다. v1·v2 이동은 기존 지도·자원·작업·시각·난수를 보존하고 없는 화재 필드만 추가한다. 완전한 v3 저장은 초기화로 예정 시각이나 타이머를 재설정하지 않는다.

렌더러는 현재 상태에서 불꽃·연기·탄자리, 소방 물줄기, 낙뢰와 진화 효과를 그린다. 의료침상에는 의료 표식을 표시하고 쓰러진 주민은 누운 자세로 그린다. 운반 중인 환자는 별도 위치에 중복 렌더하지 않고 운반자에게 부착해 표시한다. 이러한 애니메이션은 게임 상태를 수정하지 않는다.

검증 코드는 [hazards.test.mjs](../tests/hazards.test.mjs)에 있으며 다음 명령으로 실행한다.

```bash
node --test tests/hazards.test.mjs
node --test tests/*.test.mjs
```

주요 확인 대상은 실패한 점화의 무변경, 실제 연료·번짐·비·피해, 환불 없는 건물 파괴, 방·전력의 단절, 소방 작업의 이동·시간·예약, 신호 중단·재개, 화재 중 저장 이후 동일한 미래다. 렌더의 숫자 인수와 상태 불변성도 Node Canvas 대역으로 별도 확인한다.

## 9. 범위

이 구현은 독립적인 소규모 정착 게임에 맞춘 화재 규칙이다. 풍향별 확산, 재료별 열전도, 산소·유독가스, 옷이나 신체 부위별 연소, 소화기 탄약, 방화 구역, 잔해 회수, 불에 의한 개별 아이템 직접 소실은 포함하지 않는다. 연기는 시각 효과이며 별도의 질식 피해를 만들지 않는다. 식량은 기존 온도·신선도 시스템을 통해 영향을 받는다. 의료침상·구조·소방·전력·방 판정은 실제 게임 상태와 연결되어 있다.
