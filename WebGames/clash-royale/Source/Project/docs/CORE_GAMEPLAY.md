# Crownfall Arena 4.0 — 코어 게임플레이 구현 명세

기준일: 2026-11-14 · 전투 규칙 3 · 저장/리플레이 데이터 형식 2

이 문서는 현재 JavaScript 구현의 계약을 설명합니다. 원작의 최신 수치를 그대로 재현한 사양이 아니라, 원작 역기획을 바탕으로 작성한 독립적인 싱글 플레이 전투 모델입니다. 카드별 정확한 현재 수치는 `dist/js/engine.js`의 `CARDS`가 기준입니다.

## 1. 완료 범위

하나의 게임 루프는 `도전 단계 또는 자유 대전 선택 → 덱 준비 → 카운트다운 → 카드 배치와 자동 전투 → 승패 → 기록·복기·다음 도전`입니다. 실전과 같은 비용 및 피해 규칙을 사용하는 세 훈련, 제한 없는 자원 충전이 가능한 자유 연습, 진행 중 전투의 저장·복원도 포함합니다. 단계 진행과 메달의 상세 계약은 [SINGLE_PLAYER.md](SINGLE_PLAYER.md)를 참고하세요.

| 시스템 | 담당 파일 | 완료 기준 |
|---|---|---|
| 카드와 자원 | engine.js | 중복 없는 8장 덱, 손패 4장, 대기 4장, 원자적 비용 차감·순환 |
| 배치 | engine.js | 진영·비용·몸체 검사, 같은 계획으로 미리보기와 실제 생성 |
| 이동 | engine.js | 지상 다리 경유, 공중 직행, 구조물 회피, 막힌 다리 대체 경로 |
| 교전 | engine.js | 대상 종류·사거리·공격 간격·투사체·범위·상태 효과 |
| 승패 | engine.js | 킹 파괴, 정규전 크라운, 연장 서든 데스, 최종 체력 비교 |
| 상대 | ai.js, decks.js | 숨은 정보 미조회, 정상 자원·배치 API, 세 성향과 세 난이도 |
| 조작·화면 | app.js, renderer.js | 클릭·터치·드래그·키보드, 고정 스텝과 독립 렌더 |
| 훈련 | training.js | 재현 가능한 적 스케줄, 실제 전장 조건 평가, 성공/실패/재시도 |
| 세션 | engine.js, ai.js, app.js | 전체 진행 상태·난수·AI 타이머·훈련 목표 저장과 복원 |
| 복기 | session.js | 명령 재생·속도·탐색·종료 결과 비교·JSON 파일 |
| 도전 진행 | campaign.js | 6단계 순차 해금, 승리 메달·최고 기록, 실제 전투 인스턴스와 시도 바인딩 |
| 경기 목록 | history.js | 완료한 최근 8경기, bounded ID 중복 방지, 구버전 마지막 기록 이관 |

네트워크 대전, 서버 권위 판정, 랭크·상점·카드 성장·클랜·시즌 운영은 이 코어의 범위에 포함하지 않습니다.

## 2. 시간과 승패

렌더 루프는 `requestAnimationFrame`, 실제 시뮬레이션은 `1/60초` 고정 스텝입니다. 한 프레임의 경과를 최대 0.12초로 제한해 긴 정지 후 갑작스러운 대량 진행을 방지합니다. 숨겨진 탭에서는 게임을 멈추고 저장하며, 모달 전환도 같은 게임일 때만 원래 재생 상태로 돌아갑니다.

자유 대전과 도전은 3초 준비 카운트다운 뒤에 시작합니다. 준비 중 엔진 tick·자원·AI는 정지하고, 화면 카운트다운만 진행합니다. 카운트다운도 일시정지·모달·화면 숨김을 따르며 남은 시간을 저장합니다. ‘바로 시작’은 이 준비 시간만 생략합니다. 훈련·자유 연습·리플레이는 자체 진행 규칙을 사용합니다.

| 항목 | 규칙 |
|---|---|
| 정규전 | 180초 |
| 연장전 | 최대 120초, 동률일 때 진입 |
| 킹 타워 | 파괴 즉시 상대 3크라운, 경기 종료 |
| 정규전 종료 | 크라운 수가 다르면 높은 진영 승리 |
| 연장전 | 타워 파괴로 크라운 수가 달라지면 즉시 종료 |
| 최종 동률 | 살아 있는 타워 중 최저 절대 HP 비교; 더 높은 쪽 승리 |
| 완전 동률 | 무승부 |
| 같은 틱 양쪽 킹 파괴 | 3:3 무승부 |
| 연장 중 같은 틱 양쪽 타워 파괴 | 여전히 동률이면 계속 진행 |
| 항복 | 해당 진영 패배, 상대 승리; 현재 tick·크라운·피해 유지 |

한 스텝은 상태 효과 시간 감소, 죽음 정리, 지속 영역, 주문, 병력 행동, 몸체 분리, 타워 공격, 투사체, 죽음 정리, 승패 판정 순으로 진행합니다. 모든 가능한 상용 게임의 동시 처리 규칙을 복제한 것은 아니며, 위에 명시한 동시 파괴 상황은 회귀 테스트로 고정합니다.

`game.concede(team)`은 정상 진영이며 아직 종료하지 않은 경기에서만 성공합니다. 실행 중·일시정지·0틱 모두 지원하며 `{ok:true,winner,reason:'concede'}`를 반환합니다. `endAction:{type:'concede',team,tick}`을 기록하고 `phase='finished'`, `running=false`로 전환합니다. 잘못된 진영이나 중복 항복은 상태를 바꾸지 않습니다. 앱은 실제 시작한 일반 대전·도전의 일시정지 화면에서 확인을 받은 뒤 호출합니다.

## 3. 카드와 배치 트랜잭션

엘릭서는 5에서 시작하고 10까지 생성됩니다. 0~120초에는 2.8초당 1, 120~240초에는 2배, 240초부터는 3배입니다. 경계를 가로지르는 스텝은 구간별 시간을 나눠 적분합니다.

배치 요청은 `{team, handIndex, x, y}`입니다. 다음 조건을 모두 확인한 뒤 한 동기 실행 안에서 명령 기록, 비용 차감, 손패 교체, 생성 또는 주문 예약을 처리합니다.

1. 경기 진행 중이며 진영과 슬롯이 올바른가.
2. 좌표가 유한하고 논리 아레나 480×640 안에 있는가.
3. 필요한 자원이 있는가.
4. 병력·건물은 아군 구역 또는 이미 열린 전진 구역인가.
5. 타워와 겹치지 않으며 무리의 모든 개체가 설 공간이 있는가.

실패하면 자원·손패·대기열·명령·개체를 바꾸지 않습니다. 주문은 진영 배치 제한을 받지 않습니다.

규칙 3의 병력 배치 계획은 기본 진형에서 시작해 최대 48 논리 픽셀 반경의 후보를 결정적으로 탐색합니다. 각 몸체의 크기, 벽, 강, 기존 개체와 이미 계획한 개체를 검사합니다. 전진 배치 탐색도 사용자가 선택한 영역 안에 머뭅니다. 같은 초기 상태와 좌표는 같은 계획을 만듭니다.

```js
const preview = game.previewDeployment('player', cardId, x, y);
// preview.ok, reason, positions[], affectedTargets[]
const result = game.playCard('player', slot, x, y);
// result.ok, reason?, cardId?
```

`previewDeployment()`는 상태를 변경하지 않습니다. 주문의 대상 목록은 현재 위치의 검사 결과이며, 타워 피해 감소와 현재 체력을 반영한 1회 피해를 반환합니다. 독은 1틱 기준입니다. 시전까지의 이동을 예언하거나 총 지속 피해를 확정하지 않습니다.

## 4. 이동·타기팅·효과

지상 유닛은 x=120 또는 x=360 다리를 경유하고, 공중 유닛은 강을 직선으로 통과합니다. 고정 구조물 앞에서는 두 경유점을 사용하며, 다리 입구를 구조물이 막으면 다른 다리를 평가합니다. 경계 보정은 몸체 반경을 포함하고 밀치기와 분리에도 적용합니다.

타깃은 생존 여부, 적 진영, 지상/공중/건물 조건을 만족해야 합니다. 보통 병력은 주변 유효 대상을 찾고, 없으면 살아 있는 적 타워로 이동합니다. 거인과 돌격 기수는 건물만 공격합니다. 자기 중심 광역은 목표의 뒤가 아니라 공격자 주변을 판정합니다.

| 효과 | 현재 동작 |
|---|---|
| 배치 지연 | 카드별 시간 이후 행동; 무리 개체는 0.06초씩 순차 준비 |
| 투사체 | 발사 후 이동, 도착 때 피해; 적절한 공중/지상 필터 유지 |
| 화염구 | 지연 후 범위 피해·병력 밀치기; 타워 피해 감소 |
| 감전 | 피해와 0.5초 기절 |
| 얼음 정령 | 자기 위치 광역 피해·1.1초 동결 후 희생 |
| 독 | 8초, 최초 1초 후부터 총 8틱; 안에 있는 적만 피해 |
| 독 감속 | 규칙 3에서는 이동 20% 감소; 공격 주기 유지 |
| 대포 수명 | 35초 동안 자연 체력 감소; 기절 중에도 수명 진행 |
| 킹 활성화 | 직접 피격 또는 자기 프린세스 타워 파괴 |

v4의 새 규칙 3 병력은 초기 개별 배치 대기 시간을 `deployDuration`으로 보관합니다. 이 값과 `deployRemaining`으로 렌더러가 준비 원형 표시를 그립니다. 기존 저장에 초기 대기 시간이 없어도 복원되며, 렌더러는 남은 초를 표시합니다. 이 표시 메타데이터는 비용이나 행동 대기 시간을 바꾸지 않습니다.

## 5. AI 판단

AI는 자기 손패와 자원, 공개 병력·타워만 사용합니다. 세 상대는 거인 중심 전열, 빠른 순환 압박, 방어 후 역공 성향을 가지며 능력치 보정은 없습니다.

방어 기여는 적을 실제로 공격할 수 있는 아군만 계산합니다. 타워를 때리는 거인이 있다고 해서 고블린 수비가 충분하다고 판단하지 않습니다. 건물 후보는 여러 레인의 접근을 함께 고려하고, 배치가 타워와 겹치면 대체 좌표를 탐색합니다.

치명적인 킹 위협이 있으면 즉시 처치·기절 가능한 주문을 검토합니다. 상대 킹을 확정 파괴할 수 있으면 승리 행동을 유지하고, 단순한 측면 타워 마무리는 생존 행동보다 낮게 평가합니다. 공격에서는 이미 배치된 아군의 레인별 비용을 비교해 과도한 집중을 줄입니다.

난이도는 생각 주기, 반응 지연, 조준 오차, 선택의 차이입니다. 같은 수비 fixture에서 실제 첫 반응이 쉬움 2.433초, 보통 1.417초, 도전 0.733초였지만, 모든 덱·seed에서 난이도별 승률이 단조 증가함을 뜻하지 않습니다.

## 6. 훈련과 일반 전적의 경계

`TrainingRun`은 같은 `Game`을 사용합니다. 정해진 시각에 적 카드 슬롯을 찾아 정상 `playCard()`를 호출하며 자원을 추가하지 않습니다. 루프는 `training.step(1/60)`을 호출하고, 별도의 AI는 실행하지 않습니다.

| ID | 관찰하는 사실 | 완료 처리 |
|---|---|---|
| defend | 기수의 targetId가 중앙 대포를 가리켰는지, 기수 제거, 아군 타워 HP | 세 조건을 만족하면 성공 |
| spell | 해당 화살비의 실제 적중·처치 기록에 지정 미니언 3기 모두 포함, 타워 HP | 다른 병력·주문의 처치는 인정하지 않음 |
| push | 살아 있는 거인 뒤에 궁수 배치, 적 왼쪽 타워 실제 HP 감소 | 925 이상 피해와 지원 배치 모두 필요 |

훈련 완료는 게임을 일시정지하고 전용 결과를 보여줍니다. 일반 `finishBattle()`에 진입하지 않아 대전 수·승수·최근 대전 리플레이를 바꾸지 않습니다. 훈련 달성 목록은 브라우저 설정에 남깁니다. 자유 연습도 일반 전적과 리플레이에서 제외합니다.

`game.getSpellResolutions()`는 가장 최근 `update()`에서 발동한 주문의 복사본을 반환합니다. 항목은 `commandIndex`, `team`, `cardId`, `x`, `y`, `tick`, `persistent`, `hits:[{id,team,damage,killed}]`를 가집니다. 훈련은 명령 인덱스로 화살비 시전과 실제 처치를 연결하며, 과거 저장에 인덱스가 없으면 위치·시전 시간 구간을 사용합니다. 독 같은 지속 효과는 생성 시점에 총 피해를 준 것으로 기록하지 않습니다. 이 진단 정보는 시뮬레이션 상태·난수·개체 ID·이벤트 순서를 변경하지 않습니다.

적 웨이브의 지정 지점이 막히면 같은 레인의 가까운 후보를 검사합니다. 배치할 수 없으면 비용·명령을 추가하지 않고 0.25초 간격, 최대 3초 재시도합니다. 계속 실패하면 예외를 던지는 대신 사유가 있는 훈련 실패로 종료합니다. 재시도 횟수와 대기 시간은 훈련 snapshot에 포함합니다.

## 7. 저장과 리플레이 버전

| 구분 | 포함 데이터 |
|---|---|
| 엔진 snapshot | 초기 설정, 전체 state, RNG 값, ID 순서, 대기 주문, 승인 명령 |
| AI snapshot | 난수, 판단 타이머, 스타일·난이도, 관찰 상태 |
| 앱 세션 | 상대, 연습 모드·속도·AI 설정, 훈련 snapshot, 도전 시도 context, matchId, 테마, 준비 잔여 시간 |
| 훈련 snapshot | 과제 ID, 적 배치 진행, 적 개체 ID, 목표 플래그, 명령 관찰 위치 |
| replay | 초기 설정, 고정 step, 명령, finalTick, 승자, 종료 결과, 선택적 endAction |
| 프로필 | 덱·설정·전적, 훈련 완료, 도전 진행, 최근 8경기와 중복 검사 ID |

형식 버전 2를 유지하면서 `config.rulesVersion`을 분리합니다. 신규 게임은 3, 필드가 없는 과거 기록은 2입니다. 과거 규칙의 배치·독·이동 분기를 보존해 기존 리플레이에 새 규칙을 덮어쓰지 않습니다.

리플레이는 같은 tick의 명령을 기록 순서대로 실행한 뒤 1/60초 진행합니다. 마지막 tick에 명령이 남아 있으면 그 명령까지 적용하고 추가 스텝 없이 끝냅니다. 항복 기록은 마지막 명령 뒤 `endAction`을 적용합니다. 0틱 항복도 생성·초기화 시점에 처리합니다. AI 판단은 다시 실행하지 않습니다. 재생 종료 시 tick·소모한 명령 수·승자를 검사하고, 새 기록은 종료 이유·크라운·타워 체력·누적 피해도 대조합니다. 다른 결과는 오류로 표시합니다.

파일 입출력 형식은 다음과 같습니다. UI 보고서나 브라우저 설정은 포함하지 않습니다.

```json
{
  "format": "crownfall-replay",
  "version": 1,
  "opponentId": "bran",
  "arenaTheme": "grove",
  "stageId": "stage-1",
  "replay": {
    "version": 2,
    "step": 0.016666666666666666,
    "config": { "rulesVersion": 3 },
    "commands": [],
    "finalTick": 0,
    "winner": null
  }
}
```

위 JSON은 구조 설명용이며 실제 파일의 config에는 덱·상대 덱·난이도·seed·연습 여부가 포함됩니다. 파일을 읽을 때 크기·형식·카드·좌표·tick 순서·결과 범위를 확인합니다. `arenaTheme`은 `grove/dusk/frost`, `stageId`는 `stage-1`~`stage-6`만 보존하며, 잘못된 선택 항목은 각각 누락합니다. 과거 파일에 없는 항목은 강제로 추가하지 않습니다. 이 메타데이터는 화면 재현용이고 도전 결과 반영 권한을 주지 않습니다.

최근 목록은 최대 8경기를 보관하고, 별도의 최근 ID 최대 128개로 오래된 목록 항목을 지운 뒤에도 제한된 범위에서 중복 저장을 막습니다. 전적·도전 진행·목록은 한 프로필 쓰기에 함께 넣습니다. 전투 체크포인트는 별도 저장이므로 여러 키에 걸친 데이터베이스 트랜잭션을 제공하는 것은 아닙니다. 도전은 활성 시도·완료 시퀀스와 실제 `Game` 바인딩을 별도로 검사하여 리플레이나 다른 전투가 해금과 메달을 갱신하지 못하게 합니다.

## 8. 검증의 실제 범위

114개 자동 테스트, 그 안의 기존 18경기 완주 검사, 별도 도전 18경기 표본, 전체 스냅샷 복원·재생 비교, 과거 규칙 SHA-256 비교, 실제 Canvas 400px 출력 및 정적 DOM 연결 검사를 수행했습니다. 단일 HTML 빌드에서는 순수 모듈 조합도 실행하여 도전·훈련·기록의 의존성 누락을 검사합니다. 브라우저 접근 정책으로 최신 전체 UI 클릭 검증은 수행하지 않았습니다. 모바일 실기기 조작·오디오·파일 다운로드는 추가 검증 대상입니다.

경로와 충돌은 이 크기의 로컬 아레나를 위한 휴리스틱입니다. 자동 검사에서 확인한 상황과 표본을 넘어 모든 배치 조합이나 장기 군집 상태가 완벽하다고 보장하지 않습니다.
