# 실행 구조와 확장 지점

## 1. 파일 의존성

```text
data/game-data.json ── tools/build.mjs ── js/data.js
                                             │
                                    js/engine.js
                                             │
                          ┌──────────────────┴───────────────────┐
                    js/renderer.js                           js/ui.js
                          │                                      │
                     Canvas / minimap                 DOM / input / save
                          └──────────────────┬───────────────────┘
                                        index.html
                                             │
                                     tools/build.mjs
                                             │
                                         PLAY.html
```

실행 시 네트워크 요청, fetch, ES module 로더, 외부 폰트, 이미지, 프레임워크, CDN, npm 패키지는 필요하지 않습니다. 일반 script 태그의 순서로 데이터 → 엔진 → 렌더러 → UI를 초기화합니다. 이 때문에 `file://` 실행에 필요한 동일 출처 fetch 문제를 피하도록 설계했습니다. 보안 정책상 로컬 HTML 실행 자체가 금지된 브라우저까지 실행을 보장하는 것은 아닙니다.

## 2. 게임 상태

`Engine.s`는 JSON으로 직렬화 가능한 순수 상태입니다.

```javascript
{
  schema: 1, version: '1.0.0', turn: 0,
  player: 'cao', difficulty: 'normal', goal: 8,
  rng: 1101200, nextId: 1,
  factions: {}, cities: [], officers: [], units: [],
  fires: [], shipments: [], logs: [],
  eventQueue: [], eventDone: [], missions: {}, stats: {}, outcome: null
}
```

행동 후 UI가 `render()`를 호출합니다. 렌더러는 게임 규칙을 변경하지 않습니다. `effects`는 이동 보간·피해 숫자용 일시적 출력이며 저장하지 않습니다.

도시·무장·부대·수송대는 문자열 ID를 사용합니다. 정적 지도는 데이터와 해시로 재생성하며 저장하지 않습니다. 원작의 바이너리 ID나 지도 포맷은 아닙니다.

## 3. 주요 명령

```javascript
const e = Engine.fresh({ faction: 'cao', difficulty: 'normal', goal: 8 });
e.recruit(cityId);
e.build(cityId, 'market', 6);
e.deploy(cityId, {
  leader: officerId, deputies: [],
  type: 'spear', troops: 5000, food: 10000
});
e.move(unitId, {q: 24, r: 17});
e.attack(unitId, targetId, 'attack');
e.attack(unitId, targetId, 'tactic', 'spiral');
e.attack(unitId, targetId, 'confuse');
e.fire(unitId, {q: 24, r: 16});
e.nextTurn();
const saved = e.serialize();
const restored = Engine.load(saved);
```

좌표·ID·자원·적성이 유효하지 않으면 `RuleError`를 발생시킵니다. UI는 사용자 메시지로 처리하고, 성공한 명령만 저장합니다. 명령 입력은 먼저 검사하고 자원을 차감하도록 구성했습니다. 저장 파일에 명령 코드·스크립트를 넣거나 eval로 실행하지 않습니다.

## 4. 헥스·길찾기

지도 저장 좌표는 odd-r offset입니다. 거리와 이웃 계산 때 axial 좌표로 변환합니다. 이동 범위는 이동 비용을 사용하는 Dijkstra 탐색, 장거리 AI 목표 접근은 A* 탐색입니다.

지형은 43×35 고정 범위에 결정적 해시로 생성합니다. 원작과 다른 손배치 도시 좌표를 넣고, 각 도시의 가까운 세 도시 사이에 도로와 여울을 만들어 연결합니다. 개발지는 인접 1~4칸에서 다른 개발지와 겹치지 않는 통행 가능 헥스를 배정합니다. 통행 가능 지형으로 42도시가 연결되는지는 자동 테스트합니다.

적 부대 인접 헥스로 들어오면 남은 이동력을 0으로 만듭니다. 원작의 정확한 ZOC와 같은 규칙이라는 의미는 아닙니다. 병력 부대끼리 겹칠 수 없으며 산악·수면은 통행할 수 없습니다. 아군 도시 헥스는 통행 가능하지만 적 도시는 점령 전 통행할 수 없습니다.

## 5. AI

각 비플레이 세력은 도시 운영, 출진, 야전 행동, 연구 순서로 명령합니다. 중립 도시 수비대는 출진하지 않습니다. 산적 부대는 야전 AI만 실행합니다.

도시는 전선 접근·보유 병력·턴 주기에 따라 부대를 출진시키고, 수리 → 순찰 → 징병 → 훈련 → 시장/농장 순으로 현재 상태에 맞는 명령을 택합니다. 병장을 추가 생산하거나 도시 간 물자를 옮기는 AI는 없습니다. 초기 비축 병장이 부족하면 검병을 사용합니다.

야전은 보급·입성 판단 후 근접 적 또는 도시를 공격합니다. 사거리 밖이면 가까운 목표로 이동합니다. 적성·기력·지형에 맞는 전법, 지력 우위의 교란을 선택할 수 있습니다. 공동 공격 계획·전선 사령부·포위망·장거리 물류 최적화는 없습니다.

## 6. 렌더링

Canvas 2D로 헥스, 지형, 도로, 성벽, 건물, 깃발, 부대와 전투 숫자를 직접 그립니다. 정적 지형은 별도 캔버스에 캐시합니다. 변경이 없으면 프레임 그리기를 생략합니다. 뷰포트 밖 도시·부대 장식은 생략합니다.

도시·부대 라벨은 화면 좌표계에서 그려 확대/축소 중에도 가독성을 유지합니다. 작은 화면은 정보 패널을 슬라이드형으로 전환합니다. 확대 버튼과 포인터 드래그를 지원하며 멀티터치 핀치 확대는 구현하지 않았습니다.

## 7. 저장 검증

저장 봉투 형식은 `{magic: 'RTK11_WEB_SAVE', schema: 1, state: ...}`입니다. 최대 4MB 텍스트를 허용합니다. 버전, 개체 수, ID, 정적 도시 위치, 숫자 범위, 병과·시설·기교 키, 부대 좌표 중복, 무장-부대 양방향 참조, 이벤트 중복, 수송 경로를 검사합니다.

브라우저 저장 키는 `rtk11-web-v1-save`입니다. 자동 저장 실패는 게임 실행을 중단시키지 않습니다. 수동 저장 실패 시 JSON 내보내기를 안내합니다. 개발자 도구를 통한 치트나 변조를 막는 온라인 보안 기능은 아닙니다.

## 8. 데이터 교체·추가 시 주의

`game-data.json`을 고친 뒤 `node tools/build.mjs`를 실행하세요. 정적 데이터는 게임 생성 시 복사되므로 기존 저장 상태가 자동으로 새 밸런스에 이행되지는 않습니다. 무장 수, 도시 ID, 시나리오 시작 위치를 바꾸면 기존 저장 검증이 실패할 수 있습니다. 신규 상태를 테스트하거나 저장 스키마 마이그레이션을 별도로 작성해야 합니다.

특기의 이름을 추가한다고 효과가 자동 실행되지는 않습니다. `hasSkill` 호출 지점에 로직을 추가하고, 무장록의 적용 표시 및 규칙 테스트를 함께 변경하세요. 원작 수치를 편입할 때 출처·플랫폼·버전·검증 수준을 `provenance`와 문서에 남깁니다.

## 9. 플랫폼에 넣기

프로젝트 폴더 전체를 게임 하위 디렉터리에 두고 `index.html`을 진입점으로 사용하면 됩니다. `game.json`은 목록 생성용 최소 메타데이터 예시이며, 현재 특정 플랫폼의 SDK·계정·통계 수집과 연결되지는 않았습니다. 수집·추적 코드는 포함하지 않았습니다. 원작 상표를 쓰는 공개 배포의 권리 문제는 별도 검토 대상입니다.
