# 20. Advanced Edition 변경점과 버전 경계

[전체 목차](00_README_문서안내.md)

> 기준: 2022년 Advanced Edition 출시 공지와 이후 확인 가능한 공개 자료 / 조사일: 2026-11-13.
> [확인]은 해당 자료가 설명한 사실, [분석]은 설계 영향, [제안]은 구현·검증 방식, [미확인]은 후속 확인 항목이다. '출시 당시 추가 수'를 '2026년 최신 전체 수'로 바꾸어 해석하지 않는다.

## 1. 분석 기준

**[확인]** Advanced Edition은 2022-07-19 공개된 무료 확장 업데이트다. 추가 콘텐츠를 끌 수 있지만 밸런스 변경까지 출시 이전 상태로 되돌리는 옵션은 아니다. [E01]

[분석] 따라서 '기본 콘텐츠만 사용'과 '2018년 출시 빌드'는 별개의 규칙 집합이다. 무기 비용, 업그레이드 전력, 버그 수정이 누적되기 때문에 역기획 문서에는 콘텐츠 선택과 룰 버전을 따로 기록해야 한다.

## 3. 기존 시스템의 변경

다음은 **[확인·공식 발표 요약]**이다. [E01]

- 여러 무기의 기본 사용 전력을 줄여 새 장비를 즉시 시험하기 쉽게 했다.
- 무기 상점 가격은 평판 1만큼 올렸고 첫 두 섬의 상점 선택지를 제한했다.
- 스쿼드 해금 코인 비용을 조정했다.
- KO 후속 효과, 균열 지형, 다음 공격 피해를 1 높이는 Boost를 추가했다.
- Unfair에서는 전력 획득이 두 배이며 손실을 전략적으로 감수하는 운용을 안내한다. 적 출현에도 상한이 있다.

**[미확인·범위 제한]** 위 '두 배'는 공식 발표의 전력 보상 운용 설명이다. Grid Charger 같은 특수 장비가 만드는 전력 증가까지 모든 획득 이벤트에 일괄 적용되는지는 별도로 확인해야 한다.

정확한 현행 가격표는 [12 경제](12_경제_보상_상점.md), 해금은 [15 메타 진행](15_메타진행_업적_콘텐츠해금.md)에 모았다.

## 4. 확장의 설계 방향

[분석] AE는 같은 공격에 큰 숫자를 붙이는 방식 외에 기존 규칙을 연결하는 경로를 늘렸다. 처치가 생성과 지형 변화로 이어지고, 연기·화염이 아군 회복과 강화의 자원이 된다. 기본판에서 배운 위치·피해·상태의 의미를 다른 조합으로 사용한다.

| 연결 | 기본 요소 | AE에서 분석할 새로운 질문 |
| --- | --- | --- |
| 처치 → 객체 | 피해·HP·사망 | 누가 마무리해야 다음 수단이 생기는가? |
| 처치 → 지형 | 공격·바닥·밀기 | 지금 죽인 칸이 다음 적의 제거 경로가 되는가? |
| 연기 → 회복 | 공격 차단·상태 | 차단 영역을 소모해도 되는가? |
| 화염 → 강화 | 지속 피해·지형 | 불을 적에게 남길지 아군이 소비할지? |
| 적 이동 → 다중 해결 | 예고·위치 | 이동 경로 끝에서 몇 개의 위협이 바뀌는가? |

이 표는 원작 개발자의 발언을 재현한 것이 아니라 공개 콘텐츠에서 도출한 설계 해석이다.

## 6. 신규 적 7종의 기능

아래 '확인 동작'은 각 커뮤니티 적 문서의 요약이다. 수치표 전체를 재현하지 않는다.

| 적 | [확인] 대표 동작 | [분석] 추가되는 문제 | 근거 |
| --- | --- | --- | --- |
| Bouncer | 앞 대상과 자신을 반대쪽으로 밀며 공격 | 공격자 뒤의 칸까지 계산 | E32 |
| Gastropod | 갈고리로 대상 또는 자신을 끌어당김 | 고정물과 이동체의 차이 | E34 |
| Mosquito | 비행하며 표적 칸에 연기를 부여하고 공격 준비 | 공격 행동을 제한하는 지형 | E02 |
| Moth | 자신과 표적을 미는 포격 | 원격 피해와 양끝 반동 | E35 |
| Plasmodia | 별도 포자를 생성 | 생성물의 공격 순서·수명 | E36 |
| Starfish | 주변 대각 네 칸 공격 | 정면 한 방향으로 설명할 수 없는 범위 | E42 |
| Tumblebug | 폭발성 바위를 생성하고 이를 공격 | 본체 제거와 위험물 제거의 분리 | E37 |

**[확인]** 일반 Mosquito와 Alpha의 연기 부여를 보스의 연기+거미줄+즉사 공격과 혼동하면 안 된다. 보스는 별도 능력을 가진다. [E41·E43]

[분석] 신규 적은 플레이어가 밀기 결과를 더 멀리까지 생각하게 만든다. '표적이 안전해졌다' 이후에도 공격자의 반동, 생성물, 폭발 바위, 주변 대각선이 다른 위협을 만들 수 있다.

## 8. KO 후속 효과의 판정 설계

[분석] KO 효과가 있는 공격은 '피해를 줬다'와 '내 공격으로 제거했다'를 구분해야 한다. 밀기·충돌·반동·폭발 등 여러 사건이 한 행동에서 일어날 수 있기 때문이다.

### 8.1 재구현 시 필요한 정보

다음은 **[제안]**이다.

| 정보 | 목적 |
| --- | --- |
| 행동 ID | 한 공격에서 발생한 사건을 묶음 |
| 원인 무기 ID | 어떤 KO 효과를 적용할지 결정 |
| 피해 원인 종류 | 직접 피해·충돌·환경·연쇄를 구분 |
| 최종 사망 위치 | 생성물·균열을 어디에 둘지 결정 |
| 처치 귀속 | 경험치·회복·업적과 연결 |
| 이미 발생한 KO 효과 | 중복 실행 방지 |

**[미확인]** 원작 모든 KO 무기가 간접 사망까지 같은 방식으로 인정하는지는 이 문서에서 일반화하지 않는다. 각 무기의 설명과 프리뷰를 개별 확인해야 한다.

### 8.2 경계 사례

- [제안] 직접 피해로 사망한 뒤 밀리는 시각 연출이 남는 경우.
- [제안] 직접 피해는 생존하지만 충돌로 사망하는 경우.
- [제안] 공격이 균열을 깨고 대상이 떨어지는 경우.
- [제안] 죽은 대상의 폭발이 다른 적을 제거하는 경우.
- [제안] 소환해야 할 칸에 다른 유닛이나 특수 지형이 있는 경우.

이 항목의 기대 결과를 먼저 추측해 코딩하지 말고 무기별 관찰 표로 채우는 것이 필요하다.

## 9. Boost의 시스템 영향

[분석] 고정 피해가 작은 전투에서는 피해 1 증가가 연속적인 강도 상승보다 이산적인 처치 가능성 변화로 나타난다. 특히 여러 칸에 같은 증가가 적용되는 공격에서는 총 피해 증가가 커진다.

**[제안]** Boost를 단순한 무기 기본 피해 수정으로 저장하지 않고 행동 시점의 상태 수정자로 다룬다. 다음과 같은 사항을 별도 규칙으로 정의한다.

| 질문 | 검증 이유 |
| --- | --- |
| 여러 번 타격하는 무기에 어디까지 적용되는가? | 1회 사용과 개별 피해 사건의 차이 |
| 자해에도 적용되는가? | 공격 후 생존 예측 |
| 피해 없는 능력·수리에 적용되는가? | 소비 시점과 UI 설명 |
| 반동·충돌 피해까지 증가하는가? | 원인별 피해 계산 |
| 지속 공급하는 파일럿·Psion이 있는가? | 일회성 상태와 지속 원천의 구분 |
| 행동을 되돌렸을 때 복구되는가? | 스냅샷 범위 |

구체적 원작 상호작용은 [05 상태·지형](05_상태이상_지형_환경.md)와 [09 파일럿](09_파일럿_경험치_시간여행.md)을 따른다.

## 10. 균열의 시스템 영향

[분석] 균열은 위험을 한 단계 예약하는 지형이다. 바로 구덩이로 만드는 효과와 달리, 후속 공격과 이동 순서를 고민할 여지가 있다. 다만 한 번 만든 구덩이는 적 제거 수단이면서 아군 이동을 막는 영구적 제약이 될 수 있다.

**[제안]** 균열 판정은 유닛 HP와 지형 상태를 따로 갱신하도록 설계한다. 공격 피해가 어느 칸에 적용되는지, 자해가 현재 칸을 손상시키는지, 비행 특성이 추락을 막는지 등을 사건 순서로 검증한다.

**[제안] 예시 상태 모델:** 정상 바닥 → 균열 표시 → 지형 피해 → 구덩이. 지형이 바뀌면 해당 칸 유닛의 지형 반응을 별도 사건으로 처리한다.

이 표현은 상태 변화 관계만 나타낸다. 얼음·물·산·건물·미션 시설에 모두 같은 균열 규칙이 적용된다는 의미는 아니다.

## 11. 콘텐츠 옵션과 저장 데이터

[분석] 추가 콘텐츠를 끄더라도 기본 규칙의 수정은 남을 수 있다. 따라서 저장 데이터가 단일 `advancedEnabled`만 가진다고 가정하면 상태를 정확히 재현하기 어렵다.

다음은 **[제안] 저장 메타데이터 예시**다. 실제 원작 필드 이름이 아니다.

```yaml
ruleset:
  semanticVersion: research_reference
  contentOptions:
    additionalEnemies: true
    additionalEquipment: true
    additionalPilotAbilities: true
    additionalMissions: true
  difficulty: normal
  selectedSquadId: custom_example
  balanceRevision: post_ae_reference
```

추가 스쿼드의 초기 장비와 무작위 보상 풀은 같은 허용 조건을 사용할지 별도로 검사한다. 옵션 이름과 UI 세부는 실제 실행 버전에서 확인해야 하므로 위 예시를 원작 설정 파일로 사용하지 않는다.

## 14. 후속 검증 우선순위

1. KO·자해·회복·지형 붕괴가 한 행동에 겹치는 판정.
2. 동일 무기의 프리뷰와 실제 범위·밀기 순서.
3. 신규 적·미션의 배타 조합과 최종전 등장 풀.
4. 업적이 세는 객체 범주와 처치 귀속.
5. 옵션별 무작위 보상·초기 장비·파일럿 능력의 허용 범위.

패치 노트에서 수정한 현상을 영구적인 정상 규칙으로 옮겨 적지 않는다. 상세한 공식 수정 이력과 남은 미확인 항목은 [18 검증](18_검증체크리스트_미확인항목.md) 및 [19 근거대장](19_출처_버전_근거대장.md)을 참조한다.
