# 04. AI 항해·사격 판단·접촉 복구 시스템

## 1. 목적과 적용 범위

IRON TIDE V3의 수상함 전투에서 **주어진 행동을 끝까지 수행하는 것**을 목표로 개선한 시스템이다. 섬 앞에서 전진·후진만 반복하는 AI, 사격할 수 없는 적을 고집하는 AI, 점령 지시를 받고 거점을 이탈하는 AI를 재현하고 수정했다.

구현 근거는 [전투 시뮬레이션](../dist/sim.js), [자동 검증](../tests/simulation.test.cjs), [수정 전에 확보한 실제 V2 저장 상태](../tests/fixtures/v2-active-bastion.json)다. 아래 수치와 모델은 이 웹 게임의 플레이를 위해 정한 값이며, 원작의 물리·서버 구현을 의미하지 않는다.

## 2. 이동 상태와 접촉 상태

| 필드 | 의미 | 사용처 |
|---|---|---|
| `driveSpeed` | 가감속과 추진 관성을 유지하는 내부 속도 | 추진·후진 전환·접촉 중 조타 |
| `speed` | 충돌을 해결한 뒤의 실제 이동 속력. 후진은 음수 | 속도계·AI 거리 판단 |
| `vx`, `vy` | 접촉으로 차단된 성분을 제외한 실제 이동 벡터 | 선행 조준·어뢰 접근 예측 |
| `contact.kind` | `none`, `island`, `boundary` | 접촉 표시·항해 복구 판단 |
| `contact.normalX/Y` | 장애물 밖 또는 전장 안쪽을 향하는 단위 법선 | 이동 성분 제거·탈출 방향 |
| `contact.until` | 접촉 상태 표시·조타 보정을 유지할 시각 | 마지막 접촉 후 0.7초 유지 |
| `recovery` | AI의 임시 탈출 목표. 평상시 `null` | 복구 완료 후 일반 항해 복귀 |

```js
ship.contact = {
  kind: 'island',
  normalX: -1,
  normalY: 0,
  until: game.time + 0.7
};

ship.recovery = {
  x: escapeX,
  y: escapeY,
  until: recoveryDeadline,
  reverse: true
};
```

플레이어에게 자동 항해나 자동 후진을 적용하지 않는다. 플레이어는 추진 단계·후진·조타로 빠져나가고, AI만 `recovery`를 사용한다.

## 3. 접촉 시 이동 처리

추진 속도로 이동 후보를 계산한 뒤 섬의 타원 충돌과 전장 경계를 해결한다. 섬은 함체 길이·폭·방향을 반영해 확장한 타원으로 접촉을 검사한다. 겹침은 표면 밖으로 보정하고, 속도가 법선의 반대 방향으로 들어가는 경우 그 성분을 제거한다. 해안선과 나란한 이동 성분은 남긴다.

전장 경계에서는 밖으로 향하는 `vx` 또는 `vy`를 0으로 만든다. 이후 `speed`를 실제 벡터 크기와 후진 부호로 다시 계산한다. 따라서 경계에 막힌 함선이 이전 전진 속도를 계속 보고해 선행 조준을 왜곡하지 않는다.

접촉 중에는 실제 이동이 멈추어도 추진 상태의 일부를 조타에 반영한다. 반대 방향 추진을 선택했고 실제 이동이 크게 제한된 경우에는 차단된 관성을 그대로 후진 전환 대기 시간으로 사용하지 않는다. 이 처리로 경계에서 방향을 바꾸거나 섬에서 후진할 수 있다.

## 4. AI의 접촉 복구와 항로 재개

AI가 접촉하면 법선 방향에 임시 탈출 지점을 하나 생성한다. 접촉이 계속되는 매 프레임마다 목적지를 새로 만들지 않는다.

| 항목 | 규칙 |
|---|---|
| 탈출 거리 | `70 + 함체 길이 × 0.45` |
| 방향 | 접촉 법선 방향. 목표는 전장 안쪽으로 제한 |
| 전진·후진 선택 | 법선이 선수 뒤쪽을 향하면 후진, 앞쪽이면 낮은 전진 단계 |
| 완료 | 목표와의 거리 22 이하 또는 제한 시간 종료 |
| 제한 시간 | 거리와 함종 속도에 따라 계산하며 최대 16초 |
| 후속 행동 | 임시 상태를 해제하고 원래 거점·전술 목표로 복귀 |

후진 중에는 선체 회전 반응이 반대이므로 AI 조타 명령의 부호도 반전한다. 장애물 회피용 확장 타원 안에서 출발한 경우에는 **바깥쪽으로 나가는 경로를 유효한 후보**로 취급한다. 이 예외가 없으면 모든 후보가 시작점 충돌로 평가되어 섬을 향한 기존 경로를 계속 고르게 된다.

일반 항해는 현재 목표 방향 주변의 여러 후보를 검사한다. 장애물·경계·주변 함선에 대한 비용을 더해 안전한 진행 방향을 선택한다. 접촉 복구 상태가 있으면 짧은 탈출 행동을 먼저 끝낸다.

## 5. 교전 가능한 표적 선택

AI는 팀이 탐지한 생존 적함만 후보로 사용한다. 후보마다 현재 함선에서의 사선과 사거리를 평가한다.

| 평가 항목 | 점수에 반영하는 값 |
|---|---:|
| 목표까지 거리 | 실제 거리 |
| 사선이 열려 있고 사거리 안 | 추가 비용 0 |
| 사선은 열려 있으나 사거리 밖 | +1,300 |
| 섬에 가려진 사선 | +2,600 |
| 직전부터 조준하던 표적 | −140 |
| 집중 공격 지시 표적이며 현재 교전 가능 | −320 |
| 지시 표적이나 현재 교전 불가 | −40 |

낮은 점수의 표적을 선택한다. 기존 표적에 주는 작은 우대는 거리가 조금 바뀔 때마다 표적을 바꾸는 현상을 줄인다. 집중 공격 지시는 유지하지만, 지시 표적이 섬 뒤에 있는 동안에는 당장 공격할 수 있는 다른 적함을 사격할 수 있다.

탐지를 잃은 적함은 새 교전 후보에서 빠진다. 집중 공격 지시에 ID가 남아 있다는 이유로 미탐지 적의 현재 위치를 따라가지 않는다.

## 6. 거점 점령 지시의 유지 조건

명시적인 점령 지시는 보통의 전투 선회보다 우선한다. 다음 조건이면 거점으로 접근하고, 반경의 80% 안에 들어온 뒤 추진을 중립으로 내려 감속·대기한다. 포탑은 별도로 회전하므로 정지한 상태에서도 사격할 수 있다.

- 거점이 현재 경합 상태가 아니다.
- 최근 2.8초 이내 직접 피해를 받지 않았다.
- 가까운 적함과 충돌할 수준의 즉각적인 위협이 없다.
- HP가 최대치의 24%보다 높다.

실제로 접근하는 탐지된 어뢰에 대한 회피와 접촉 복구는 점령 대기보다 먼저 처리한다. 따라서 단지 적이 보인다는 이유로 거점을 떠나지 않으면서, 위험이 발생하면 회피할 수 있다.

## 7. 교전 여부와 독립적인 피해 대응

AI의 수리반·피해 복구 판단은 표적 존재 여부와 분리한다. 시야를 잃거나 섬 뒤로 물러났다는 이유로 사용 가능한 수리반을 방치하지 않는다.

HP가 68% 아래이고 회복 가능한 피해가 있으면 수리반 사용을 시도한다. 침수, 복수 화재, 특정 조건의 지속 화재 또는 일반 모듈 손상에 피해 복구를 사용한다. 실제 사용 가능 여부·회복 장부·재사용 대기 시간은 플레이어와 같은 소모품 함수가 검사한다. 치명적 모듈 손상은 기존 규칙대로 자동 복구 시간을 따른다.

## 8. 포탑 정렬과 발사 준비

주포 발사 정렬 허용 오차는 **0.025라디안, 약 1.43도**다. 기존의 큰 각도 오차에서 발사 방향이 조준점으로 급히 바뀌는 현상을 줄였다. 포탄의 최종 산포는 기존 분산 모델을 계속 사용한다.

`getWeaponSolution()`은 모든 준비 상태에서 숫자형 `alignmentTime`을 반환한다.

```text
alignmentTime = max(0, 조준 방향과 포탑 방향의 각도 차이 - 0.025) / 포탑 회전 속도
```

어뢰의 `alignmentTime`은 0이다. 어뢰는 포탑 회전 대신 실제 발사각 범위를 검사한다. HUD와 클릭 발사 대기는 이 값으로 대기 이유와 예상 정렬 시간을 표현할 수 있다. 주포가 고장 난 경우에는 별도의 `disabled` 사유가 우선한다.

## 9. 저장 호환성과 훈련 경계

새 저장 형식은 버전 3이다. 버전 2를 복구할 때는 먼저 **기존 버전 2의 전체 스키마**를 검증하고, 그 뒤 새 항해 상태만 추가한다.

- `driveSpeed`는 기존 `speed`로 초기화한다.
- `contact`는 접촉 없음, `recovery`는 `null`로 초기화한다.
- 이미 발사된 투사체, RNG 상태, `matchId`, HP, 회복 장부, 소모품과 장전 시간은 유지한다.
- 새 필드를 구버전 입력에 임의로 섞거나 필수 새 필드가 없는 데이터를 버전 3으로 표시하면 거부한다.
- 범위를 벗어난 수치, 잘못된 열거형, 중복 식별자, 접근자와 프로토타입 오염 입력에 대한 검증을 유지한다.

훈련용 게임은 `trainingMode=true`이며 일반 점수·시간·적 전멸 승리로 종료하지 않는다. 플레이어의 실제 격침은 패배로 처리하고, 단계 완료는 훈련 시스템이 결정한다. 훈련은 일반 전투 스냅샷을 생성하지 않는다.

실제 플레이어 주포·어뢰 명중 이벤트에는 `ammo`, `ownerId`, `secondary:false`, `result`, 실제 적용 `damage`를 포함한다. 훈련과 UI는 현재 선택한 무장이 아니라 해당 명중 이벤트의 무장 정보를 사용한다. 미탐지 표적의 위치를 새 이벤트 필드로 노출하지 않는다.

## 10. 검증 결과

전투 시뮬레이션 자동 검증 **63개가 통과**했다. 기능별 초기화만 확인하는 검증 외에 행동의 완료까지 진행하는 회귀 검증을 추가했다.

| 재현 문제 | V3 검증 |
|---|---|
| AI가 섬 앞에서 60초 동안 전·후진 반복 | 섬에서 이탈하고 반대편 목표로 이동해 실제 점령 완료 |
| 경계에서 속도가 매우 낮아져 조타가 느려짐 | 10초 내 안쪽으로 방향을 바꾸고 실제 이동 재개 |
| 경계 처리 이후 속도 벡터가 이전 값 유지 | 실제 속력과 `vx/vy` 크기 일치 확인 |
| 가까운 가림 표적을 고집해 발사하지 않음 | 사선이 열린 다른 탐지 표적 선택 |
| 점령 지시가 전투 선회에 덮임 | 외부의 비위협 적함이 보여도 실제 거점 점령 완료 |
| 퇴각 중 화재·손상 방치 | 표적이 없어도 수리·피해 복구 실행 |
| 큰 포탑 오차에서 발사 | 오차가 허용치 안으로 들어온 뒤 발사 |
| 구버전 진행 상태 손실 우려 | 실제 V2 투사체·수리 진행·RNG·신원을 유지해 V3 복구 |
| 복구 도중 저장·재개 시 AI가 달라짐 | 활성 탈출 상태를 저장한 뒤 동일 입력으로 같은 결과 도달 |

이 검증 결과는 지정한 시나리오와 입력에 대한 결과다. 모든 지형 배치·전술 상황에서 최적 항로를 보장하는 전역 경로 탐색기는 아니며, 현재 세 작전의 짧은 수상 전투에 맞춘 항해·판단 시스템이다.
