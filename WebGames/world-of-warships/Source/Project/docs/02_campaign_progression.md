# 원정·함장 경력 시스템 명세

이 문서는 IRON TIDE V3의 원정 진행, 전투 평가, 함종·난이도별 기록과 저장 규칙을 설명합니다. 기준 코드는 `dist/operations.js`이며, 실제 전투 종료는 `dist/sim.js`, 전투 문맥·화면·저장은 `dist/game.js`와 `dist/interaction.js`에서 연결합니다.

## 1. 목적과 플레이 흐름

자유 작전은 원하는 해역을 바로 선택하는 반복 전투입니다. 군도 원정은 같은 세 해역을 정해진 순서로 승리하는 목표를 제공합니다. 함장 경력은 두 방식의 종료 결과를 공통으로 기록합니다.

훈련 → 자유 작전 또는 원정 → 전투 종료 → 평가·경력 갱신 → 다음 출격이 기본 흐름입니다. 함종·장비는 처음부터 모두 사용할 수 있으며 계급, 별 평가, 원정 완주가 전투 능력을 올리지 않습니다.

| 단계 | 고정 ID | 작전 | 기존 전투 규칙 |
|---|---|---|---|
| 1 | `northern` | 북쪽 군도 | A·B·C 거점, 800점 목표, 8분 |
| 2 | `bastion` | 해협의 보루 | 중앙 B 거점, 640점 목표, 7분 |
| 3 | `openwater` | 외해 교전 | 거점 없는 함대전, 5분 종료 시 팀 잔존 HP 비율 비교 |

순서는 불변 배열 `IronTide.CAMPAIGN_STAGES`로 내보냅니다. 원정은 자유 작전과 동일한 맵·함선·승패 판정을 사용합니다. 기함 격침은 패배이며, 세 번째 해역도 반드시 `won` 결과를 얻어야 완주합니다.

원정 시작 시 선택한 난이도는 해당 원정 동안 고정합니다. 함종과 장비는 매 출격 전에 바꿀 수 있습니다. 항구의 자유 작전 선택은 원정 단계를 바꾸지 않습니다.

## 2. 원정 상태 전이

| 현재 상태 | 입력·결과 | 처리 |
|---|---|---|
| `idle` | 유효한 새 `runId`로 시작 | `active`, 단계 0, 선택 난이도, 누적 값 0 |
| `active` | 원정 시작·계속 버튼 | 기존 원정 ID·단계·난이도를 유지하고 현재 단계의 새 전투 시작 |
| `active` | 현재 원정의 유효한 패배·무승부 | 시도·피해·XP 누적, 단계 유지 |
| `active` | 현재 원정의 유효한 승리 | 승리 요약 저장, 단계 1 증가 |
| `active`, 단계 2 | 세 번째 유효한 승리 | 단계 3, `completed`, 완주 횟수 1 증가 |
| `completed` | 다른 유효한 `runId`로 시작 | 새 원정의 단계 0; 기존 경력·완주 횟수 유지 |
| 임의 | 중복 전투 결과 | 모든 경력·원정 수치 변경 없음 |

진행 중 원정이 있으면 `startCampaign()`에 새 난이도나 ID를 전달해도 현재 원정을 덮어쓰지 않습니다. 완료된 원정에 같은 ID를 재사용해도 새 원정을 만들지 않습니다. 정상 컨트롤러는 새 원정에 새로운 ID를 생성합니다.

항구의 **진행 중 작전 계속하기**는 저장된 전투 중간부터 재개합니다. **원정 단계 계속하기**는 현재 원정 단계의 새 전투를 시작합니다. 새 출격은 활성 전투 저장을 대체하며, 전투 결과가 없는 중도 재시작은 원정 시도 횟수에 더하지 않습니다.

## 3. 경력 데이터 계약

저장 키는 V2와 동일한 `iron-tide.career.v2`를 사용하고 객체의 `version`을 3으로 올립니다. `Career.empty()`의 주요 구조는 다음과 같습니다.

```js
{
  version: 3,
  xp: 0, battles: 0, wins: 0, bestDamage: 0,
  history: [], operations: {}, classes: {}, recordedMatchIds: [],
  campaign: {
    runId: null, status: 'idle', stage: 0, difficulty: 'normal',
    attempts: 0, totalDamage: 0, totalXp: 0, results: []
  },
  campaignCompletions: 0
}
```

| 필드 | 의미와 범위 |
|---|---|
| `history` | 최신 종료 전투 최대 20개, 최근 순서 |
| `recordedMatchIds` | 이미 정산한 전투 ID 장부; 화면 기록에서 사라진 전투도 중복 지급 방지 |
| `operations[id]` | 작전별 출격·승리·최고 별·최고 피해·최단 승리 시간 및 난이도별 최고 별 |
| `operations[id].bestByDifficulty` | `{easy, normal, hard}`, 각 0~3 |
| `classes[classId]` | `{battles, wins, bestDamage}`, 함종별 기록 |
| `campaign.stage` | 다음 출격 단계 0~2; 세 해역 완주 후 3 |
| `campaign.results` | 순서대로 통과한 승리 요약과 `matchId`, 최대 3개 |
| `campaign.attempts` | 현재 원정·단계 조건에 맞아 정산된 승리·패배·무승부 수 |
| `campaign.totalDamage`, `totalXp` | 유효한 원정 시도의 합계; 패배·무승부도 포함 |
| `campaignCompletions` | 완주 횟수 |

작전·함종 기록은 실제 기록이나 가져온 데이터가 있을 때 생성합니다. XP·피해 누적 상한은 각각 10,000,000이며, 출격·승리·원정 횟수 같은 집계는 유한한 범위로 제한합니다. 정규화 시 잘못된 타입, 비유한 숫자, 알 수 없는 키를 안전하게 처리합니다.

## 4. 종료 요약과 세션 구분

`Career.summarize(game, context={})`는 실제 게임의 통계, 함종, 장비, 난이도, HP 비율, 결과를 바탕으로 종료 요약을 만듭니다.

```js
{
  operationId, shipClass, loadoutId, difficulty,
  sessionType, campaignRunId, campaignStage,
  won, phase, damage, kills, hits, shots, caps, time,
  hpRatio, accuracy, xp, stars, score,
  damageBreakdown, ribbons, achievements
}
```

| 문맥 필드 | 값·기본값 |
|---|---|
| `sessionType` | `free`, `campaign`, `training`; 기본 `free` |
| `campaignRunId` | 원정 세션의 유효한 문자열 ID; 그 외 `null` |
| `campaignStage` | 원정 세션의 정수 0~2; 그 외 `null` |
| `loadoutId` | 실제 `game.loadoutId` 우선, 문맥 값은 대체값; 유효하지 않으면 `balanced` |

게임의 `trainingMode=true`는 전달된 문맥보다 우선합니다. 문맥을 원정으로 잘못 넘겨도 훈련 요약이 되며 XP·별·달성 항목은 0 또는 빈 배열입니다. `Career.record()`는 훈련 결과에 전투 ID조차 추가하지 않습니다.

명중률은 `hits / shots`를 0~1로 제한합니다. 피해 종류별 합계가 총 실제 피해보다 크게 들어오면 정규화 과정에서 비례 조정합니다. 호출자가 넘긴 XP·별·달성 항목을 그대로 믿지 않고 정리한 결과 필드에서 다시 계산합니다.

## 5. 한 번의 결과 정산

`Career.record(career, summary, matchId)`는 기존 입력을 직접 바꾸지 않고 정규화된 새 경력을 반환합니다.

1. 유효한 전투 ID인지, 결과가 `won/lost/draw`인지, 훈련이 아닌지 검사합니다.
2. 이미 `recordedMatchIds`에 있으면 그대로 반환합니다.
3. 새 전투 ID를 장부에 추가하고 경력 XP·출격·승리·최고 피해를 한 번 갱신합니다.
4. 작전별 통계, 해당 난이도 최고 별, 실제 플레이한 함종의 통계를 갱신합니다.
5. 원정 조건에 맞으면 같은 객체 안에서 원정 시도·누적 값·단계를 갱신합니다.
6. 최신 기록을 앞에 추가하고 표시 기록은 20개로 제한합니다.

원정 진행에는 아래 조건을 **모두** 요구합니다.

- 세션 유형이 `campaign`이며 현재 원정이 `active`입니다.
- 요약의 `campaignRunId`가 현재 `runId`와 같습니다.
- 요약의 `campaignStage`가 현재 단계와 같습니다.
- 실제 작전 ID가 현재 단계의 고정 작전과 같습니다.
- 실제 난이도가 원정 난이도와 같습니다.

자유 전투 승리, 다른 원정 ID, 이전·미래 단계, 다른 작전·난이도의 결과는 원정을 진행시키지 않습니다. 새롭고 유효한 일반 종료 결과라면 경력에는 기록할 수 있지만 현재 원정의 시도·누적 값에는 포함하지 않습니다. 중복 결과는 경력과 원정 모두에서 무시합니다.

원정 결과는 `career.campaign` 내부에 있어 경력과 같은 `localStorage.setItem`에서 저장됩니다. 따라서 일반 보상과 원정 단계에 별도의 중복 정산 경로가 없습니다. 활성 전투 스냅샷은 별도 키로 관리하므로 두 키 전체를 하나의 데이터베이스 트랜잭션으로 다루지는 않습니다.

## 6. 보상·별·계급

자유 작전과 원정은 동일한 보상을 사용합니다. 원정 완주 보너스 XP나 능력치 해금은 없습니다.

```text
피해 보상 = min(480, 피해 / 기본 함종 HP × 160)
결과 보상 = 승리 150, 무승부 60, 패배 0
점령 보상 = min(120, 점령 수 × 40)
격침 보상 = min(105, 격침 수 × 35)
XP = round((30 + 피해 보상 + 결과 보상 + 점령 보상 + 격침 보상)
           × 난이도 배율)
```

최종 XP는 0~1,200으로 제한합니다. 난이도 배율은 입문 `0.85`, 표준 `1`, 베테랑 `1.15`입니다. 피해 보상과 별의 기준 HP는 장비를 적용하기 전 함종 기본 HP이므로 생존 장비를 선택했다고 피해 평가 기준이 높아지지 않습니다.

별은 승리 1개, 기본 함종 HP의 절반 이상 피해 1개, 남은 HP 35% 이상 또는 점령 1회 이상에 1개입니다. 승리 시 최대 3개이며 패배·무승부는 최대 1개입니다. 미종료 전투와 훈련은 평가를 받지 않습니다.

| 계급 | 누적 XP |
|---|---:|
| 소위 | 0 |
| 중위 | 350 |
| 대위 | 900 |
| 소령 | 1,800 |
| 중령 | 3,200 |
| 대령 | 5,200 |

`Career.rank(xp)`는 계급명·레벨·현재 구간 XP·다음 구간 필요량·진행률을 반환합니다. 최고 계급의 `next`는 0, `progress`는 1입니다. 결과 화면은 계산상 보상과 별도로 경력에서 실제 증가한 XP를 표시하므로 중복 정산 결과를 새 보상처럼 표시하지 않습니다.

## 7. 저장·이행·복원

`Career.normalize()`는 기존 V2 경력의 총 XP·전적·기록·전투 ID를 보존하고 V3 기본 필드를 추가합니다. V2의 종합 최고 별만으로 어떤 난이도에서 달성했는지 추정하지 않습니다. 남아 있는 전투 기록에서 실제 난이도를 확인할 수 있을 때만 해당 난이도의 최고 별을 채웁니다. 함종 집계가 없는 과거 데이터는 남아 있는 기록으로 확인 가능한 표본만 생성합니다.

기록의 장비 필드가 없으면 표준 장비, 세션 유형이 없으면 자유 전투로 처리합니다. 난이도·장비·원정 여부는 V3 전투 기록에 유지되어 화면에서 함께 확인할 수 있습니다.

원정을 복원할 때는 저장된 `stage`나 `completed`만 믿지 않습니다. 결과 배열에서 같은 원정·난이도의 0→1→2단계 승리 사슬을 검증하고 유효한 순서의 길이로 단계를 다시 계산합니다. 중복 전투 ID, 틀린 작전, 누락된 앞 단계가 나오면 그 지점에서 결과 채택을 멈춥니다. 검증된 승리 세 개가 있어야 완료 상태가 됩니다.

일반 전투 키 `iron-tide.active.v2`에는 시뮬레이션 스냅샷과 UI `control`을 저장합니다. 원정 문맥인 `sessionType/campaignRunId/campaignStage`는 `control` 안에 있으며 엔진 스냅샷과 분리됩니다. UI 저장이 없던 V2 전투는 기본 자유 전투로 재개합니다. 훈련은 이 키를 쓰지 않습니다.

경력 저장 실패는 결과 화면에 표시합니다. 같은 페이지에서는 갱신된 메모리 상태로 계속할 수 있지만 다시 열었을 때의 유지 여부는 성공한 브라우저 저장을 기준으로 합니다. 저장 도우미 `Career.read/write`도 손상 JSON과 접근 거부를 예외로 중단하지 않고 처리합니다.

## 8. API 요약과 검증 범위

| API | 책임 |
|---|---|
| `Career.empty()` | 독립 초기 경력 생성 |
| `Career.normalize(value)` | V2/V3 경력 정규화, 안전한 원정 상태 복원 |
| `Career.startCampaign(career, {runId, difficulty})` | 기존 활성 원정 유지 또는 새 원정 시작 |
| `Career.summarize(game, context)` | 실제 전투 통계와 세션 문맥에서 평가 생성 |
| `Career.record(career, summary, matchId)` | 중복 없이 경력·원정을 함께 갱신 |
| `Career.rank(xp)` | 계급 및 구간 진행률 |
| `Career.read(storage)`, `Career.write(storage, career)` | 오류를 처리하는 선택적 저장 도우미 |

실행 명령:

```bash
node tests/operations.test.cjs
```

V3 구현 검증에서 **42/42 검사 통과**를 확인했습니다. 검증은 다음을 포함합니다.

| 영역 | 검증 내용 |
|---|---|
| 작전·장비 | 세 작전의 다른 목표 구조, 좌표 유효성, 전함 크기를 고려한 출발 안전성과 거점까지의 경로, 데이터 불변성, 네 장비의 성능 교환 |
| 경력·평가 | 계급 경계, 보상 상한, 장비와 기본 HP 평가 기준 분리, 정규화, 기록 20개 제한, 저장소 오류 |
| 중복 지급 | 화면에서 사라진 과거 전투도 재정산하지 않음; JSON 저장·복원 뒤 ID 장부 유지 |
| V2 이행 | 기존 합계·ID 보존, 난이도 추정 금지, 확인 가능한 기록의 난이도·함종 표본 복원 |
| 원정 | 자유 승리 배제, 패배·무승부의 시도만 누적, 일치하는 세 승리로 완료, 완주 중복 방지, 이전 단계·다른 원정·다른 작전·난이도 거부 |
| 훈련 제외 | 보상·전적·ID·원정 갱신 없음 |

원정 테스트는 종료 요약 자료를 사용해 정산·전이 규칙을 검증합니다. 브라우저에서 원정 세 경기를 수동 완주했다는 의미는 아닙니다. 실제 전투 판정과 훈련의 정상 조작 완료는 각각 전투·훈련 테스트에서 검증합니다.
