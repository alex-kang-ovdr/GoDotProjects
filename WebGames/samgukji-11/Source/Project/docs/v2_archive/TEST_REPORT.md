## 환경과 중요한 제한

Node.js v22.16.0, Linux Chromium 144, Python Playwright, Xvfb, SwiftShader 소프트웨어 WebGL2.
브라우저 검사는 네트워크를 차단한 상태에서 **빌드된 PLAY.html 전체 내용**을 `set_content`로 로드했습니다.
작업 환경의 관리 정책이 `file://` 및 로컬 URL 직접 탐색을 제한하여, 사용자의 PC에서
더블클릭하는 실행 경로 자체는 직접 검증하지 못했습니다. 정책을 해제하거나 우회하지 않았습니다.

실제 GLSL 컴파일, WebGL2 컨텍스트, 그림자 프레임버퍼, GPU draw, 캔버스 클릭과 DOM 명령을 검사했습니다.
이는 Windows Chrome/Edge 또는 물리 GPU·모바일 실기기에서의 성능 보증이 아닙니다.
소프트웨어 GPU 검사에서 화면 크기·품질에 따라 약 1–2 FPS가 관찰되었으며, 이를 하드웨어 성능으로
해석하면 안 됩니다. 고정 프레임 속도 목표를 달성했다고 주장하지 않습니다.

## 77개 규칙·서버 테스트

기존 엔진 60개, 확장 지도·저장 변환 12개, HTTP 서버 5개입니다.
도시·무장 데이터, 내정·편성 비용, 이동·공격·12전법, 상태이상, 보급, 공성, 이벤트,
정전·연구·수송, 저장 검증, 3개 플레이 세력의 각 40턴 AI 진행 등 기존 규칙을 재검사했습니다.

추가 검증은 6,020개 헥스, 홀수 행 오프셋을 반영한 도시 좌표, 이동 경로의 연속성·통과 가능성,
훈련의 유효한 7부대 배치, 전투 효과 기록, schema 2 round-trip, v1 자원·턴·난수 보존 변환,
잘못된 지도·좌표 거부, 시작 부대의 접근 가능 경로, 시각 효과의 저장 상태 분리입니다.
전체 원작 게임과 결과가 동일하다는 검증은 아닙니다.

## 31개 브라우저 검사

실제 화면 버튼과 3D 캔버스를 통해 캠페인 시작, 시장 건설, 징병, 기병 출진, 이동과 공격을 수행했습니다.
공격 후 실제 병력이 감소하는지 확인했고 전투 효과 기록도 확인했습니다.
카메라 회전·확대·전략/전투 프리셋·패널 접기, 지형 좌표 투영/역피킹, 42개 도시 전체 보기,
JSON 파일 입력 round-trip과 v1 변환, 적 AI 턴 진행, WebGL 오류와 JavaScript 오류를 검사했습니다.

390×844 브라우저 뷰포트에서 가로 넘침과 주요 버튼 표시를 검사했습니다. 물리 휴대전화 검사는 아닙니다.
별도 페이지에서 WebGL2 미지원 상황을 모사하여, 명시적인 2D 호환 표시와 플레이 가능 상태를 검사했습니다.

## 8개 전투 렌더링 검사

실제 근접 공격 명령을 실행한 뒤 높은 품질·그림자 프레임버퍼로 렌더링했습니다.
노병은 유효한 한 칸 이동 후 사거리 내 적을 실제 공격했습니다. 이동·공격을 순간이동으로 대체하지 않았습니다.
화살이 떠 있는 애니메이션 시점에서 3D 투사체 인스턴스 생성을 확인했습니다.
렌더링 전후 직렬화 문자열을 비교해 게임 상태·난수 상태가 변하지 않는지 확인했습니다.
낮음/보통/높음 각각의 렌더링 경로와 WebGL 오류를 검사했습니다.

## 스크린샷

`tests/artifacts/`의 PNG는 위 실행 과정에서 캡처한 **실제 코드 렌더링 화면**입니다.

## 재실행

```sh
npm test
npm run build
xvfb-run -a python tests/browser_3d.py
xvfb-run -a python tests/render_effects.py
```

기본 게임 플레이에는 Python·Playwright·Xvfb가 필요 없습니다. 위 두 브라우저 QA 스크립트는
Linux의 `/usr/bin/chromium`을 사용하며, 테스트 환경에서 Playwright 설치가 필요합니다.

## 아직 확인하지 않은 것

실기기별 성능, Safari/Firefox, 장기 수백~수천 턴 전쟁, 모든 GPU 드라이버,
브라우저 GPU 컨텍스트 상실 후 자동 복구, 원작의 전체 수치·행동 동일성은 검증하지 않았습니다.
GPU 컨텍스트 상실은 안내 후 새로고침이 필요합니다. WebGL2 초기화 실패 때의 2D 모드는 검사했지만,
실행 도중 GPU 상실을 무중단으로 복구하는 기능은 없습니다.
