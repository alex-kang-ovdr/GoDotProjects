# 17. 동작 검증 실험과 미확정 규칙 목록

> **이 문서는 미실행 검증 계획이다.** 현재 게임을 직접 실행하거나 프레임·힘·메모리·패킷을 계측한 결과가 아니다. ‘예상’은 가설이며 통과 결과로 읽지 않는다.
> 조사 기준: 2026-11-13 Steam PC. 실제 시험 시 실행 화면의 버전·빌드·DLC·모드를 기록한다.

## 1. 왜 실험을 별도 문서로 두는가

공식 패치 노트는 기능 도입과 변경을 알려 주지만 모든 접점·자유도·비교 연산·타이밍을 정의하지 않는다. 특히 물리 게임은 같은 외형이라도 저장본의 레거시 설정, 배치 순서, 초기 관통, 시간 배율에 따라 결과가 달라질 수 있다. 검증하지 않은 규칙을 구현 확정값으로 바꾸지 않기 위해 실험을 분리했다.

## 2. 공통 시험 조건

| 항목 | 기록·통제 방법 |
|---|---|
| 버전 | 버전 문자열과 빌드 번호를 그대로 적는다 |
| 플랫폼 | OS, 단독/호스트/클라이언트 구분 |

| 시간 | 수동 배율, 자동 배율 여부, 실제·시뮬레이션 시간 분리 |
| 환경 | 평지·경사·공기·물·중력·바람 조건 |
| 입력 | 누른 시점·지속시간·반복, 기본키 대신 실제 설정 기록 |

| 저장본 | 새로 만든 기체/과거 저장본/Workshop 기체 구분 |

**규모 표현:** 아래 `L`은 시험에서 선택한 기준 구조 블록의 길이이다. 원작 1블록이 현실 1m라는 뜻이 아니다. UI가 물리 단위를 제공하지 않는 값은 표시값 그대로 기록한다.

## 5. 연결·기초 물리 시험

### PHY-01: 접촉과 연결 분리

두 구조 블록을 눈으로 보기에 붙인 경우와 작은 간격을 둔 경우를 만든다. 접합 가능한 면·옆면·장식 외형을 달리한다. 실행 후 한쪽에만 작은 하중을 걸고 함께 움직이는지 확인한다.

- **기록:** 배치 순서, 상대 위치, 접점 시각화, 중력만 켠 결과, 외력 후 결과.
- **가설 구분:** 외형 접촉만으로 연결 / 별도 접점 필요 / 시작 시 공간 탐색.
- **주의:** 함께 떨어졌다는 사실만으로 영구 연결을 증명할 수 없다. 서로 분리시키는 상대 운동을 시험한다.

### PHY-02: 배치 순서

좌우 대칭 구조를 A→B와 B→A 순서로 만든다. 저장 후 재로드한 경우도 비교한다. 강도·상대 운동·연결 대상이 바뀌면 생성 순서 또는 저장 변환이 영향을 줄 수 있다.

### PHY-03: 단일 관절 자유도

T1에 외력을 서로 독립적인 방향으로 적용하고 병진 3축·회전 3축을 확인한다. 각 시험에서 한 자유도만 자극한다. 구동 입력 없이 관절이 움직이는지 먼저 확인한다.

### PHY-04: 초기 관통

가동측이 차체에 겹치지 않는 구성과 아주 조금 겹치는 구성을 비교한다. 실행 첫 순간 튀는 현상, 연결 파단, 큰 가속이 생기는지 기록한다. 관통을 해결한 뒤에도 문제가 남는지 확인한다.

### PHY-05: 보강과 과구속

회전 가능한 팔에 Brace를 추가한다. 팔 내부 보강과 팔→기준대 보강을 비교한다. 후자가 회전을 막는다면 보강 위치가 자유도를 없앤 것이다. 파단되어 다시 움직이는 경우도 별도 기록한다.

### PHY-06: 질량과 관성

같은 총 추가 하중을 중심 가까이 또는 팔 끝에 배치한다. 동일한 입력으로 초기 각가속과 정지 시간을 비교한다. 현실 공식의 수치를 맞추는 것보다 방향성·일관성부터 확인한다.

### PHY-07: 시간 배율

자동 배율을 끄고 같은 기체를 두 수동 배율에서 시험한다. 게임 내 같은 경과시간에서 위치·연료·타이머를 비교한다. 벽시계 시간만 비교하지 않는다.

### PHY-08: 파단과 부품 파괴

무적 옵션·보강·하중을 하나씩 바꾸며 먼저 끊어지는 대상이 부품인지 연결인지 기록한다. 기능을 잃은 시점과 시각적 파편이 생긴 시점을 분리한다.

|---|---|---|
| 최상 | 연결 탐색·가동측 접합·배치 순서 | 기체 구조 자체가 달라짐 |
| 최상 | Build/Sim 전환과 복구 | 반복 실험·저장 신뢰성 붕괴 |
| 최상 | 모터 목표·한계·반력 | 차량과 기구 동작이 달라짐 |
| 높음 | 키 유지·에지·토글·자동화 순서 | 연속발사·반복제어 오작동 |
| 높음 | 파단과 부품 손상 | 보강·장갑 설계 효과 왜곡 |
| 높음 | 항공·수중 부품의 실제 힘 방향 | 비행·부력 설계 실패 |
| 중간 | 레거시 설정·DLC 로드와 편집 | 기체 호환성 문제 |
| 중간 | 클러스터 분할·네트워크 사건 | 멀티플레이 표시 불일치 |

## 12. 문서 신뢰도를 올리는 규칙

한 번 움직였다는 결과를 보편 규칙으로 올리지 않는다. 원인을 분리하는 대조군을 만들고 재현성을 확인한다. 부품 정의에 ‘확정’을 붙일 때는 대상 버전·설정·시험 범위를 함께 남긴다. 확인된 범위를 넘어 원작 내부 구현으로 일반화하지 않는다.
