# IRONWOOD 3.0 — 양력·추진·비행 조종 시스템

기준 소스는 [physics.js](../dist/physics.js)의 `_applyFluidForces()`·`_applyControlTorques()`·`telemetry`, [parts.js](../dist/parts.js)의 `wing`·`propeller`·`plane`, [input.js](../dist/input.js)입니다. 원작 또는 실기체의 비공개 수치를 사용하지 않은 게임용 구현입니다.

## 1. 강체 단위의 비행

날개·추진기·차체·바퀴는 각각 독립 강체입니다. 양력과 추력은 해당 부품에 가하고 기존 고정 연결과 힌지 제약을 통해 기체로 전달합니다. 비행 모드라고 기체의 위치·회전·속도를 목표값으로 덮어쓰지 않습니다. 따라서 속도 부족, 비대칭 배치, 파손과 충돌이 비행에 영향을 줍니다.

## 2. 좌표와 설치각

| 로컬 축 | 의미 |
| --- | --- |
| -Z | 부품의 전방 |
| +X | 오른쪽 / 날개 폭 방향 |
| +Y | 위쪽 |

격자 회전 `rot`은 Y축 90도 단위입니다. 날개의 `elevation`은 **설치각(incidence)**이며 실제 유동에 대한 받음각과 다릅니다. 새 날개는 기본 6도, 항공 프리셋 꼬리 날개는 0도입니다. 저장된 명시적 0도를 기본 6도로 바꾸지 않습니다.

실제 속도를 부품의 로컬 프레임으로 바꾼 뒤 다음 값을 사용합니다.

```text
forwardSpeed = max(0, -localVelocity.z)
alpha = incidence - atan2(localVelocity.y, forwardSpeed)
q = 0.5 * 1.225 * forwardSpeed²
```

전진 유속이 0.1m/s 이하이면 이 날개의 양력 계산을 생략합니다. 여기서 바람은 0으로 가정합니다. 강체 질량중심 속도를 사용하며, 날개 면 여러 지점의 유속을 따로 적분하지 않습니다.

수상 환경에서는 동압에 공기 노출 비율 `1-submerged`를 곱합니다. 완전히 잠긴 날개에 공중과 같은 양력을 주지 않습니다. 별도의 수중익 해석은 구현하지 않습니다.

## 3. 양력·실속·항력

받음각은 라디안으로 계산합니다. 정상 구간은 절댓값 18도 이내입니다.

```text
abs(alpha) <= 18°:
  CL = clamp(5.4 * alpha, -1.35, 1.35)

abs(alpha) > 18°:
  excess = abs(alpha) - 18°
  CL = sign(alpha) * 1.35 * clamp(1 - excess / 40°, 0.12, 1)

CD = 0.035 + 0.065 * CL² + min(0.65, excess * 0.6)
```

정상 구간에서는 `excess=0`입니다. 코드의 `excess`는 라디안입니다. 이는 실제 에어포일 곡선을 보간한 결과가 아니라 튜닝된 단순 곡선이며 실속 시작점에서 정확한 연속성을 보장하지 않습니다.

양력 방향은 월드 날개 폭 축과 실제 속도의 외적으로 정합니다. 양력 크기는 `q * power * CL`, 항력 크기는 `q * power * CD`이며 각각 최대 크기를 제한합니다. UI의 **날개 면적 배율**은 `power`로 양력과 항력에 함께 적용됩니다. 메시 크기·질량·구속 위치를 바꾸는 값은 아닙니다.

날개에는 로컬 X 방향 속도에 비례하는 옆미끄럼 감쇠도 추가합니다. 동체·수직 꼬리날개를 별도 공력 패널로 해석하지 않는 것을 보완하는 게임용 항력입니다. 새 공력 부품이 있는 기체에는 약한 전체 공기 저항을 적용합니다. 기존 6종 지상 기체의 기존 힘 경로는 유지합니다.

## 4. 프로펠러

공중·지상 환경의 기본 추력은 `80 * power * throttle` N이며 물 환경은 55N 계수를 사용합니다. 실제 방향은 프로펠러의 월드 -Z입니다. 뒤집어 조립하면 반대 방향으로 힘이 작용합니다.

정규화 추진량은 -1~1이고 목표값까지 초당 1.8의 변화율을 적용합니다. W는 전진, S는 역추진, B는 추진 차단입니다. 브레이크는 바퀴에도 작용하지만 별도의 공중 에어브레이크 면적을 생성하지 않습니다. 연결이 끊기거나 파괴된 프로펠러는 즉시 제어를 잃습니다.

## 5. 조종 입력과 보조

| 입력 | 물리 명령 |
| --- | --- |
| W/S | 전후 추진, 바퀴 모터 |
| A/D | 좌우 yaw |
| ↑/↓ | 양수/음수 pitch, 양수는 기수 상승 |
| ←/→ | 양수/음수 roll, 양수는 왼쪽 뱅크 |
| I/K · Q/E · F | 대포 고각 · 관절 회전 · 발사 |

조종은 코어와 연결된 살아 있는 날개가 2개 이상일 때 기체 제어 토크를 만듭니다. 속도가 낮아도 최소 제어 권한을 주는 게임용 보정이 있으며, 실제 조종면에 작용하는 공력만으로 조종하는 순수 항공 해석은 아닙니다.

자세 보조 ON은 입력에 따라 제한된 피치·롤 목표를 만들고 현재 자세·각속도와의 차이로 토크를 가합니다. 충분한 속도에서는 기본 기수 목표를 약간 올려 이륙을 돕고 뱅크 입력에는 선회를 보조합니다. 초기 진행 방향과 사용자의 yaw/roll 입력을 기준으로 방향을 안정화합니다. 관문 위치나 다음 목표를 따라가는 자동 경로 추적은 없습니다.

자세 보조 OFF는 입력에 따른 목표 각속도와 현재 각속도의 차이로 제한된 토크를 만듭니다. 수평 자세 목표는 사용하지 않습니다. 질량 배치에서 구한 관성 추정치는 제어 게인 규모에만 쓰며, 최종 운동은 각 강체의 실제 관성과 제약을 cannon-es가 계산합니다. 모든 토크는 제한됩니다.

## 6. 파손과 수동 힘

살아 있는 분리 날개는 계속 공기력을 받습니다. 다만 그 날개는 코어의 조종 가능한 날개 수에서 빠지고 연결 기체에 힘을 전달하지 않습니다. HP 0인 날개는 양력을 잃습니다. 따라서 날개를 잃은 기체는 기존 관성으로 움직이다가 중력·항력·잔존 날개의 힘에 따라 떨어집니다.

프로펠러의 생존 여부·코어 연결은 엔진에, 날개의 생존 여부는 수동 양력에, 코어 연결된 날개 수는 조종에 각각 영향을 줍니다. 이 세 조건을 혼동하지 않습니다.

## 7. 기본 비행기와 HUD

`plane`은 19부품, 19.9kg, 자재 51입니다. 주날개 6개는 좌우로 펼치고 설치각 6도를 사용합니다. 꼬리 날개 2개는 설치각 0도입니다. 바퀴 4개는 출력 2, 앞쪽 추진기는 출력 1.2입니다. 코어는 지상 바퀴보다 한 격자 높습니다.

고도는 코어 중심의 지면/수면 기준 높이입니다. 속력은 현재 코어 속도의 크기이고 상승 속도는 월드 Y 속도입니다. 무풍을 가정하므로 이 구현의 airspeed는 별도 바람을 뺀 속도가 아닙니다. 추진량은 연결된 프로펠러의 정규화 명령 평균입니다. 피치·롤은 실제 코어 자세에서 계산합니다.

공중 관문에는 최소 고도가 있습니다. 표시된 유효 원호와 최소 고도 기준선을 따라 통과하세요. 거리는 현재 코어에서 다음 관문 중심까지의 3D 거리이며 실제 비행 경로 길이는 아닙니다.

## 8. 검증과 한계

기본 비행기의 실제 활주·이륙·관문 완주, pitch/roll 부호, 추진 축 방향·역추진·분리, 날개 파괴 후 하강을 테스트합니다. 완주 테스트는 일반 입력을 사용하며 위치·HP·관문 상태를 강제로 변경하지 않습니다.

바람·프로펠러 회전 유동·개별 조종면 힌지·지면 효과·압축성·실제 항공기 안정 미계수는 포함하지 않습니다. 세부 검증 결과는 [VALIDATION.md](../VALIDATION.md)에 기록합니다.
