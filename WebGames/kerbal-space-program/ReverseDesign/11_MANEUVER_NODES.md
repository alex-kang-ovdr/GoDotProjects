# 기동 노드와 Δv — KSP 1 역기획서

> 분석 기준: Kerbal Space Program 1 (1.12.x 계열). 공개 플레이 관찰 및 일반적인 물리/게임 개발 지식을 바탕으로 재구성. 원본 내부 구현과 완전히 동일하다는 뜻은 아니다.

## 1. 시스템 목적
Prograde, Normal, Radial, Burn Time, 전이 계획를 통해 로켓 설계·실험·탐사라는 핵심 경험을 제공한다.

## 2. 플레이어 관점 동작
- 플레이어는 이 시스템의 입력과 결과를 UI 또는 비행 상태에서 확인한다.
- 설계 선택은 질량, 비용, 안정성, 추진 성능 또는 임무 성공률에 영향을 준다.
- 실패 결과를 분석해 설계를 수정하고 재시도하는 반복 학습 구조를 만든다.

## 3. 주요 기능 및 규칙
- Prograde
- Normal
- Radial
- Burn Time
- 전이 계획
- 상태 전환과 실패 조건은 모드/난이도 및 기체 상태에 따라 다를 수 있다.
- 실측 수치가 없는 경우 임의의 '원작 정확 수치'를 제시하지 않고 데이터 테이블로 조정 가능하게 한다.

## 4. 처리 흐름
**노드 생성→Δv 편집→예측 궤도 갱신**

```mermaid
flowchart LR
 A[플레이어 입력] --> B[조건 및 데이터 검증]
 B --> C[상태/시뮬레이션 갱신]
 C --> D[결과 계산]
 D --> E[UI 및 피드백]
 E --> A
```

## 5. 데이터 설계
- `definitionId`: 부품·규칙·환경 정의를 참조하는 안정적인 식별자
- `entityId`: 런타임 인스턴스 식별자
- `enabled`, `state`: 활성화와 단계 상태
- `parameters`: 조정 가능한 밸런스 값
- `events`: 저장 및 리플레이 가능한 상태 변경 이벤트

## 6. 재구현 권장 구조
궤도 좌표기저에서 속도 변화 적용. 물리/규칙/표현을 분리하고 테스트 가능한 순수 함수로 핵심 계산을 구성한다.

## 7. 경계 사례
- 저장/로드 또는 씬 전환 도중 상태가 바뀌는 경우
- 부품 파손·분리·자원 고갈이 같은 시뮬레이션 스텝에서 발생하는 경우
- 프레임 저하와 시간 가속 상태에서 결과가 달라지는 경우
- UI에 표시된 예측치와 실제 시뮬레이션이 차이 나는 경우

## 8. 검증 시나리오
| 테스트 | 입력 | 기대 결과 |
|---|---|---|
| 정상 흐름 | 유효한 기본 기체와 정상 입력 | 시스템 결과가 일관되게 반영됨 |
| 경계값 | 자원 0, 입력 0, 극한 자세 | NaN·무한 루프 없이 안전하게 처리 |
| 분리/전환 | 연결 변경 또는 모드 전환 | 참조와 물리 상태의 무결성 유지 |
| 저장/복원 | 동작 중 저장 후 복원 | 중요한 상태와 결과가 보존됨 |

## 9. 원작과 재구현의 구분
- **관찰 가능한 원작 기능:** 위 기능 목록 및 플레이어 경험.
- **재구현 제안:** 데이터 구조, 이벤트 파이프라인, 수치해석, 테스트 아키텍처.
- **추가 실측 필요:** 정확한 수치 상수, UI 제한, 버전별 세부 예외 및 내부 계산 순서.

### Δv 좌표 변환
Prograde = normalize(v), Normal = normalize(r × v), Radial = Normal × Prograde(부호 정의를 명시). \(\Delta\mathbf v=\Delta v_p\hat p+\Delta v_n\hat n+\Delta v_r\hat r\). 기동 후 새 상태벡터를 생성하여 예상 궤도를 다시 계산한다. 유한 시간 연소의 실제 궤도는 순간 임펄스 예측과 다를 수 있다.

## 10. 다른 시스템과의 연결
부품/자원/물리/비행 UI/저장 시스템과 통합한다. 시스템 간 변경은 이벤트를 통해 전파하고, 주기적 계산은 명시적인 업데이트 순서를 따른다.
