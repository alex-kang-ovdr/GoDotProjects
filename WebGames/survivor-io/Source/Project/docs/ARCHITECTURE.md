# v13 구현 구조

## 빌드와 의존성

Python 표준 라이브러리 `build.py`가 template의 자리에 CSS/JS를 삽입합니다. 실행 파일에는 외부 스크립트, 이미지, 폰트, 오디오 링크가 없습니다. 절차적 3D 메시와 합성 오디오를 사용합니다. 로딩 순서는 data → gameplay → tactics → doctrine → persistence → legacy2d → render3d → enhancements → input입니다. 초기화와 루프 시작은 모든 정의를 결합한 뒤 실행합니다.

## 시뮬레이션

+X는 화면 오른쪽, +Y는 화면 아래입니다. 렌더러가 이 좌표를 직교 쿼터뷰로 투영하고 입력은 같은 기준을 사용합니다. 실시간 루프는 60Hz 고정 스텝, 프레임당 최대 6스텝입니다. 시뮬레이션을 실행할 수 있는 상태는 playing뿐입니다. perk 상태를 추가해 선택 중 이동·전투·쿨다운·위험 예고가 정지하도록 했습니다.

일반 레벨업 큐인 pendingLevels는 특성 선택으로 소모하지 않습니다. resumePlay에서 미선택 특성 단계를 먼저 제시하고, 모두 처리한 후 남은 일반 레벨업을 처리합니다. 선택 직후 저장하므로 새로고침으로 선택을 중복 적용하지 않습니다.

## 피해 경로

기존 무기 피해 → 무기 오버클럭 배율 → damage 대상 검증 → 거물 사냥꾼 대상 보정/냉각 부여 → 정예 ward 흡수 → 실제 HP 감소/무기 통계 → 처치 보상/특성 처치 카운터 순서입니다.

연쇄 폭발은 처리 대기 배열에 저장하고 다음 tickDoctrine에서 snapshot 방식으로 배출합니다. 자기 원인 perk_blast 처치는 폭발 카운터를 충전하지 않습니다. 최대 32개로 제한합니다. 기존 explosion/범위 피해 경로를 재사용하므로 통계·보상과 분리된 가짜 시각 효과가 아닙니다.

hurt는 기존 방어력 완화 후 방벽을 확인하고, 실제 HP 손실만 기록합니다. 최근 피해의 원인은 알려진 ID 목록으로 제한하며 HTML에 저장 원문을 직접 삽입하지 않습니다. 피격 이력은 8건으로 제한합니다.

## 정예와 시각화

정예는 type=elite를 유지하고 affix 필드로 추가 행동을 구분합니다. 기본 AI, 접촉, 드랍, 공간 해시가 같은 경로를 사용합니다. 파동은 기존 threats의 ring 판정과 동일한 시각화 데이터를 사용합니다. 소유 적이 죽으면 위협을 취소합니다. 둔화는 기본 speed 값을 변형하지 않고 이동 계산에 임시 배율을 적용합니다. 돌진의 목표 경로를 뒤늦게 줄이지 않아 예고와 판정이 어긋나지 않습니다.

3D 장식은 기존 ring/gem/box 인스턴스 배치를 재사용합니다. 2D 대체 모드도 동일한 게임 상태와 둔화·방벽·정예를 표시합니다. 주변 배경 프롭은 여전히 충돌 없는 장식입니다.

## 저장

영구 스키마 12 및 키는 유지하며 체크포인트 내용 버전만 13으로 증가합니다. version 12는 newDoctrine 초기값으로 읽습니다. version 13은 선택된 특성, draft, 방벽, 카운터, 폭발 대기열, 피격 기록을 검증한 후 게임 상태를 변경합니다. 복원된 shot.hit는 Set으로, threat.owner는 enemy ID로 다시 연결합니다. RNG 상태는 저장하지 않으므로 결정론적 리플레이가 아닙니다.

정산 ID와 영구 보상을 같은 localStorage 레코드에 기록한 뒤 체크포인트를 삭제하는 기존 방식을 유지합니다. 단일 활성 창·단일 원점을 가정합니다. 다중 탭 트랜잭션, 서버 검증, 강제 종료 시 이탈 이벤트 보장은 없습니다.
