# 07. 바퀴·조향·현가·지상 이동 역기획

> 조사 기준: 2026-11-13, Steam PC. **[공식 확인]**과 **[설계 해석]**, **[재구성 제안]**, **[검증 필요]**를 구분한다. 수식과 시험 절차는 구현·분석용이며 게임의 공개 내부 공식이나 실제 측정값이 아니다. 우주 DLC의 Metal Wheel은 본편 바퀴와 별도 취급한다.

## 1. 지상 이동의 설계 구조

**[설계 해석]** 차체를 만들고 바퀴를 붙이는 행동 안에는 네 가지 서로 다른 문제가 들어 있다.

| 문제 | 물리적인 질문 | 조립에서 조정할 것 |
| --- | --- | --- |
| 추진 | 구동 회전을 지면과의 접촉을 통해 전진으로 바꾸는가 | 바퀴 방향·속도·가속·하중 배분 |
| 조향 | 어느 접점의 이동 방향을 바꾸는가 | 조향축 방향·앞뒤 배치·좌우 회전 부호 |
| 접지 유지 | 굴곡진 지면에서도 필요한 접점이 남는가 | 현가 이동량·강성·감쇠·지상고 |
| 차체 생존 | 접촉력과 모터 반력을 구조가 버티는가 | 지지 길이·보강·질량·가속 |

이 문제를 한꺼번에 조정하면 원인을 찾기 어렵다. 평지 직진 → 저속 선회 → 단일 장애물 → 비대칭 장애물 → 무기 탑재 순서로 비교하는 편이 분석에 적합하다.

## 3. 부품별 동작 규칙 카드

### 3.1 Powered Wheel / Large Powered Wheel

**[설계 해석]** 구동 바퀴는 “이동 속도를 차량에 직접 지정하는 부품”과 구별해서 읽어야 한다. 접점이 충분하지 않거나 차체가 지면에 걸리면 회전 의도가 전진으로 이어지지 않을 수 있다. 바퀴가 차체에 붙은 기준축, 회전 화살표, 입력의 정·역방향을 하나의 묶음으로 설정한다.

| 항목 | 규칙 분석 |
| --- | --- |
| 입력 | 회전 방향, 동작 키 또는 자동화 입력, 속도·가속 관련 매개변수 |
| 출력 | 접촉 조건을 거친 추진과 차체에 전달되는 반력 |
| 연결 검토 | 차체 쪽 고정부와 바퀴 회전체를 혼동하지 않음 |
| 조립 순서 | 축 방향 확인 → 좌우 회전 부호 확인 → 저속 직진 → 속도 상승 |
| 실패 후보 | 공회전, 전복, 축 파단, 바퀴끼리 충돌, 차체 바닥 걸림 |
| 미확정 | 목표 각속도형·토크형 등 실제 모터 제어식, 정지 입력의 제동 방식, 마찰 수치 |

**[공식 확인]** V1.26의 가속 개편은 감속에도 영향을 준다고 명시한다. 따라서 속도 설정과 가속 설정을 같은 기능으로 설명하면 안 된다. [공식 변경 내역](https://store.steampowered.com/news/posts/?appids=346010&enddate=1715361118&feed=steam_community_announcements)

### 3.2 Unpowered Wheel / Large Unpowered Wheel

**[설계 해석]** 무동력 바퀴는 지지와 구름을 담당하는 수동 요소로 분류한다. 다른 구동부로 밀리거나 당겨질 때의 저항, 축 방향, 관절 상태가 중요하다. “무동력”이라는 이름만으로 마찰과 회전 저항이 0이라고 판단하지 않는다.

활용 예는 후방 지지, 트레일러, 회전축의 받침, 외부 구동 전달 실험이다. 구동 바퀴와 크기·접지 높이를 맞추지 않으면 일부 바퀴가 떠서 기대한 하중 배분이 사라질 수 있다.

### 3.3 Small Wheel

**[공식 확인]** V1.75는 Small Wheel이 구형 충돌체를 사용하고 자유롭게 구르도록 바뀌었다고 밝힌다. [V1.75](https://store.steampowered.com/news/posts/?appgroupname=Besiege&appids=346010&enddate=1772123201&feed=steam_community_announcements)

**[설계 해석]** 따라서 보조 접점이나 방향 구속을 적게 두고 싶은 지지부 후보로 비교한다. 그러나 구형 충돌체라는 사실만으로 완전한 무방향 마찰, 항상 안정적인 캐스터, 부품 전체의 3축 자유회전을 보증하지 않는다. 실제 회전 자유도와 측방 저항은 분리해서 측정해야 한다.

### 3.4 Roller Wheel

**[공식 확인]** 개발자는 Roller Wheel을 무동력, 축이 고정된 바퀴 묶음으로 설명하며 강성 설정을 제공한다고 밝혔다. [V1.65](https://steamcommunity.com/games/346010/announcements/detail/4441207205094492419)

**[설계 해석]** Small Wheel과의 핵심 비교축은 “작은 보조 바퀴”라는 외관이 아니라 허용 이동 방향이다. 방향을 정해 주는 지지와 자유롭게 미끄러질 수 있는 지지는 선회 방식에 다른 영향을 준다. Roller Wheel의 강성을 바꾸는 실험에서는 차체 질량과 바퀴 축 방향을 고정한다.

### 3.5 Steering Block / Steering Hinge

**[공식 확인]** V1.26은 두 조향 부품에 tension 매개변수를 추가했고, V1.65는 Steering Block의 선택적 회전 한계를 추가했다. [V1.26](https://store.steampowered.com/news/posts/?appids=346010&enddate=1715361118&feed=steam_community_announcements), [V1.65](https://steamcommunity.com/games/346010/announcements/detail/4441207205094492419)

**[설계 해석]** 조향 블록은 바퀴의 굴림축과 다른 회전축을 만드는 장치로 읽는다. 설치 방향이 틀리면 좌우 조향 대신 바퀴의 캠버를 바꾸거나 바퀴를 들어 올리는 동작이 된다. 조향 목표, 회전 한계, 입력 해제 후 복귀, 외부 힘에 대한 버팀을 각각 구분한다.

**[검증 필요]** 각 부품의 정확한 초당 회전각, tension의 단위, 자동복귀 기본값과 구동 방식, 제한각 경계에서의 힘 처리는 실행 버전의 UI·실험으로 확인한다. 과거 위키의 수치를 현행 절대값으로 옮기지 않는다.

### 3.6 Suspension

**[공식 확인]** V1.25는 Suspension의 damper 설정 추가를 명시한다. [V1.25](https://steamcommunity.com/games/346010/announcements/detail/3702564861056742651)

**[설계 해석]** 현가는 바퀴와 차체 사이에 변위를 허용하면서 힘을 전달하는 장치다. 강성은 눌림에 대한 버팀, 감쇠는 진동의 소멸과 관련된 서로 다른 조정축으로 분석한다. 단순히 강성을 최대로 올리는 방식은 충격을 차체로 전달하거나 접지 변화를 키울 수 있다.

### 3.7 Bounce Pad

**[공식 확인]** 개발자는 힘을 받으면 반대 방향으로 강하게 밀어내는 도약용 부품으로 설명한다. [V1.65](https://steamcommunity.com/games/346010/announcements/detail/4441207205094492419)

**[설계 해석]** 일반 Suspension과 같은 수동 감쇠 요소로 간주하지 않는다. 이동을 안정시키는 현가와 에너지를 증폭하거나 적극 반발시키는 게임 장치는 목적이 다르다. 반복 접촉 시 도약 높이가 유지·증가·감소하는지와 방향별 응답을 우선 확인한다.

### 3.8 Metal Wheel — The Broken Beyond

**[공식 확인]** 우주 확장의 구동 Metal Wheel은 거친 지형의 접지 확보를 목표로 소개되었다. 기존 바퀴도 우주 환경에서 사용할 수 있다는 설명이 함께 있다. [공식 Space Blocks 개발 게시물](https://steamcommunity.com/app/346010/announcements/)

**[설계 해석]** 낮은 중력에서 마찰에 쓸 수 있는 수직 하중이 줄어드는 문제와 휠 형상의 장애물 통과 문제를 나눠 비교한다. “우주용이므로 모든 지상 바퀴보다 우수하다”는 결론은 자료에 없다.

## 4. 좌우 미러와 회전 방향

**[재구성 제안]** 바퀴의 회전은 로컬 축과 월드 축을 구별한다. 좌우 배치가 거울상일 때 동일한 키가 동일한 수치 부호를 준다고 반드시 전진 방향이 일치하는 것은 아니다.

검증 순서는 다음과 같다.

1. 차체를 대칭으로 만들고 좌우 바퀴를 동일 높이에 둔다.
2. 입력을 짧게 넣고 두 바퀴의 접점이 뒤로 지면을 미는지 확인한다.
3. 반대쪽이 역방향이면 해당 바퀴의 방향 설정을 변경한다.
4. 직진이 성립한 뒤 조향 입력을 추가한다.
5. 미러·복제 후 키맵과 방향 값이 어떻게 복제되는지 별도 기록한다.

**[설계 해석]** 방향 화살표는 장식이 아니라 좌우 조립 오류를 미리 줄이는 피드백이다. 화면에서 보이는 시계·반시계만 비교하면 카메라 방향 때문에 혼동한다. 최종 판정 기준은 지면 접점의 이동 방향이다.

## 5. 조향 방식 비교

| 구성 | 조립 목적 | 물리 분석 포인트 | 대표 제약 |
| --- | --- | --- | --- |
| 앞바퀴 조향 | 보통 차량의 직관적 운전 | 휠베이스, 앞뒤 하중, 좌우 회전각 | 급선회 시 전복·측방 미끄럼 |
| 후륜 조향 | 후방이 크게 움직이는 기계 | 조종 기준점과 궤적 | 플레이어 기대와 반대되는 후방 흔들림 |
| 좌우 차동 구동 | 전차형 방향 전환 | 좌우 속도차, 측방 접촉 저항 | 바퀴가 많을수록 제자리 선회가 쉽게 되리라는 보장 없음 |
| 중앙 관절 굴절 | 두 차체를 서로 꺾음 | 중앙 관절의 하중과 조향력 | 부하가 중앙에 집중 |
| 다관절 보행 | 다리의 주기 접촉으로 이동 | 위상·지지 다각형·충격 | 조립·제어·접촉 계산 비용 증가 |

이 표는 **[설계 해석]**이며 해당 구성이 게임에서 특정 성능을 낸다는 실측표가 아니다. 궤도 차량은 범용 부품으로 궤도를 구성하는 분석 예로 취급하며, 내장 Track 블록의 존재를 전제하지 않는다.

## 6. 접지와 구동의 참고 모델

다음은 **[재구성 제안]**이다. 실제 Besiege 마찰 모델이나 휠 모터 구현을 뜻하지 않는다.

\[
v_{rim}=\omega r,\qquad |F_{traction}|\lesssim \mu N
\]

바퀴 가장자리 속도와 차량 속도가 크게 다르면 미끄럼을 의심할 수 있다. 다만 이 두 식만으로 게임 차량의 가속을 예측할 수는 없다. 구동 제한, 횡방향 마찰, 충돌 형상, 다중 접점과 관절 손실이 함께 작용할 수 있기 때문이다.

| 관찰 | 가능한 원인 | 우선 바꿀 변수 |
| --- | --- | --- |
| 바퀴 회전은 빠르나 차체 정지 | 접지 부족, 바닥 걸림, 구동 방향 상쇄 | 지상고·접점·좌우 방향 |
| 전진 입력 때 앞부분이 들림 | 추진선·질량 중심 높이·급가속 | 가속·질량 배치 |
| 저속에서도 한쪽으로 감 | 비대칭 하중, 바퀴 축 또는 설정 불일치 | 좌우 부품과 파라미터 비교 |
| 선회할 때만 바퀴가 떨어짐 | 횡방향 하중, 긴 지지대, 과도한 조향각 | 조향각·지지 경로 |
| 요철 이후 계속 출렁임 | 감쇠 부족 또는 구동 피드백 진동 | 현가 감쇠와 제어를 따로 점검 |
| 현가를 넣었는데 더 불안정 | 축 방향 오류, 과도한 변위, 질량 불균형 | 설치축·정적 눌림·간섭 |

## 7. 현가의 강성과 감쇠를 구별하는 방법

**[재구성 제안]** 기준 모델은 스프링과 댐퍼의 합으로 시작할 수 있다.

\[
F=-k(x-x_0)-c\dot x
\]

여기서 `k`는 위치 편차에 따른 복원, `c`는 상대 속도에 따른 감쇠다. 실제 게임 슬라이더 값과 이 계수를 직접 등치하지 않는다.

### 분석용 비교 시나리오

- **정적 눌림:** 시뮬레이션 시작 후 입력 없이 멈춘 높이를 비교한다. 하중 지지 여부를 본다.
- **한 번의 충격:** 같은 높이의 장애물을 같은 속도로 지나게 한다. 최대 눌림, 튀어 오름, 안정화 시간을 본다.
- **좌우 비대칭 충격:** 한쪽 바퀴만 올라가게 한다. 차체 롤과 반대편 접지 상실을 본다.
- **반복 충격:** 일정 간격의 요철을 지난다. 공진처럼 보이는 현상이 구동 주기와 결합되는지 본다.

**[검증 필요]** Suspension이 인장·압축에서 같은 계수를 쓰는지, 이동 끝단에 별도 강성이 있는지, 모드 스케일이 travel·mass·strength를 어떻게 바꾸는지는 확인되지 않았다.

## 8. 조립 UX에 요구되는 피드백

**[재구성 제안]** 유사 게임을 만든다면 설정 창에 숫자만 나열하지 말고 다음 피드백을 함께 제공한다.

| 상황 | 필요한 표시 | 학습 효과 |
| --- | --- | --- |
| 바퀴를 선택함 | 구동축·회전 방향·지지 연결 | 잘못된 부착 방향 수정 |
| 좌우 바퀴 동시 선택 | 값이 같음/다름, 서로 반대 방향 관계 | 미러 후 오류 발견 |
| 조향 부품 선택 | 허용 각도 부채꼴과 중립 위치 | 회전 범위와 충돌 간섭 예측 |
| 현가 선택 | 변위축·시작 길이·허용 이동 구간 | 위아래가 아닌 방향으로 설치한 오류 확인 |
| 테스트 정지 | 최초 파단 지점·입력 시점·접지 상태 | 마지막 파편 위치에서 원인을 추측하는 비용 감소 |

현재 게임에 이 표의 모든 표시가 존재한다고 주장하지 않는다. 공식적으로 확인된 시각화 도구와 별도로 제시하는 제품 설계안이다.

## 9. 최소 실험 세트

| ID | 조립물 | 통제 조건 | 검증 목표 |

| GD-01 | 4륜 평판 차체 | 대칭 질량·저속·평지 | 좌우 회전 방향과 직진 |
