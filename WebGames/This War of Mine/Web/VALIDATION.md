## 4.0에서 추가한 검증

### 구호 연락망을 포함한 실제 캠페인

표준·봉쇄 각각 시드 31·247에서 다음 단계를 실제 API로 진행했습니다. 재고·건강·날짜·좌표·RNG를 시험용 수치로 덮어쓰지 않습니다.

| 단계 | 진행 날짜 | 확인한 결과 |
|---|---:|---|
| 무전기 복구 | 3일 | 실제 목재·부품 비용과 윤의 작업 시간 지불 |
| 구호팀 교신 | 4일 | 실제 부품·연료 지불, 5일 아침 보급 예약 |
| 구호 보급 | 5일 아침 | 한 번만 수령, 보고서·재고 증감 일치 |
| 대피 물자 봉인 | 9일 | 식사 3·물 4·붕대 1 실제 소비 |
| 준비된 대피 결말 | 12일 밤 이후 | 3명 생존·건강 100/100/100·절도 0·살해 0 |

봉쇄에서는 3일 무전기 지출 때문에 4일의 문 보강 재료가 부족해집니다. 실제 정책은 경계를 늘리고 3단계 보강을 5일로 미룹니다. 비용을 무시하거나 물자를 추가하지 않았습니다. 이 네 실행과 아래 기본 여섯 실행을 합해 캠페인 테스트 파일에서 **10회 완주**를 검사합니다. 모든 임의의 선택이나 모든 시드의 성공을 보장한다는 뜻은 아닙니다.

### 실제 은신·투척·귀환

야간 테스트는 시드 31의 캠페인을 정상적으로 5일째까지 진행하고, 부품 2개를 든 레오를 보급 창고로 보냅니다. 조용히 문 앞까지 이동하여 실제 상호작용으로 문을 열고, 숨을 곳에 들어간 뒤 착지점으로 부품을 던집니다. 경비가 그 위치까지 걸어가 조사하며 발각·피격·절도·살해 없이 17초 이내 정상 귀환합니다. 남은 부품 1개와 유인 사용 1회를 실제 `finishNight`로 정산하고 저장 검증까지 통과합니다. 이 시나리오에도 직접 상태 주입을 사용하지 않습니다.

나머지 경계 테스트는 각 상황을 분리하기 위한 fixture를 사용합니다. 사거리·닫힌 문·다른 층·가방 부족·행동 중·공격 시야 우선·중립 주민·8초 재사용·입력 상승 에지·시간 만료·JSON 복원을 검사합니다. 잘못된 투척은 가방·소리·경로를 일부 변경하지 않습니다.

### 조준과 표시 경계

실제 컨트롤러로 조준 중 시간 정지, 너무 가까운 위치의 미소비, Esc 취소와 원래 재생 상태 복원, 성공한 투척의 비용과 시간 재개를 검사합니다. 미니맵 설정은 저장됩니다. 구호 모달의 담당자 변경과 윤의 80분, 작업 착수와 완료도 검사합니다.

미니맵은 현재 보이지 않는 NPC를 기억하지 않으며 상자 내용을 공개하지 않습니다. 닫힌 문과 미탐험 구간을 넘어가는 경로를 그리지 않습니다. 지도 영역 전체를 클릭·투척 좌표에서 제외하는 경계도 검사했습니다.

### 브라우저에서 확인한 흐름

1. 기존 저장을 읽고 구호 연락망 모달을 열었습니다.
2. 담당자를 미라에서 윤으로 바꿔 무전기 복구 시간이 100분에서 80분으로 바뀌는 것을 확인했습니다.
3. 실제 복구 작업을 맡기고 낮을 마쳐 부품 5·목재 2가 차감되며 준비가 1/3로 바뀌는 것을 확인했습니다.
4. 부품 1개를 반출해 연립주택에 들어갔습니다.
5. 조준 모드를 열고 장면을 클릭해 투척했습니다. 가방의 부품이 소모되고 사용 안내가 표시되었습니다.
6. 현관 상자를 조사하고 목재 6·부품 4를 가방에 담았습니다.
7. 출입구로 정상 귀환한 보고서에서 유인 사용 1회와 재고 변화 목재 +6·부품 +3을 확인했습니다.
8. 다음 아침으로 진행한 뒤 무전기 완료와 구호 교신 날짜 제한이 유지되는 것을 확인했습니다.

브라우저 콘솔 조회에서 확인한 오류는 브라우저 확장의 메타데이터 전송 오류였으며, 게임 경로의 JavaScript 오류는 관찰하지 않았습니다. 이 관찰을 전체 브라우저 환경의 무오류 보장으로 확대하지 않습니다.

## 전투와 주민의 경계 조건

- 첫 근접 공격은 0.55초의 예고를 거치며, 예고 중 거리 이탈·문 닫기·회피가 실제 피해를 바꿉니다.
- 유효한 공격에만 스태미나를 사용하고, 부족한 스태미나나 공격 회복 중에는 연속 행동을 거부합니다.
- 회피는 한 번의 입력에 한 번 시작하고, 문·세계 경계·계단을 지킵니다. 보호 구간이 끝난 뒤에는 피격될 수 있습니다.
- 치료와 회피, 물자 이동, 협상을 동시에 실행하여 비용을 중복 사용하거나 결과를 중복 적용하지 않습니다.
- 붕대 완료 프레임에 공격 예고가 끝나 피격되면 회복·소비 전에 치료를 취소합니다.
- 현재 보이지 않는 주민의 대화를 노출하지 않고, 요청만 받은 사유물과 나눔 허락을 받은 물품을 구분합니다.
- 도움·교환의 최종 가방 용량을 검사하며, 부족하면 비용과 권한을 모두 유지합니다.
- 재방문·JSON 복원·아파트의 다른 주민을 이용해 보상을 다시 받지 못합니다.
- 주민 공격 시 허락을 철회하고 다음 방문의 적대 관계를 유지합니다.

## UI와 저장 경계 조건

UI 테스트는 브라우저 대신 DOM·Canvas 인터페이스를 모사하여 실제 `app.js`를 실행합니다. 모듈과 단일 HTML에 같은 검증을 수행합니다.

- 조리 예약과 동시 건설 → 밤 예측 → 실제 클릭 경로 수색·일괄 획득 → 귀환 보고 → 다음 아침.
- 직접 물물교환과 아침 복구, 저장 가져오기에서 문자열 이스케이프.
- 난이도 선택과 시드 범위 검사, 봉쇄 출발 물자, 아침 기록의 난이도 유지.
- 회피 버튼의 스태미나 소비와 대화 중 시간 정지.
- 복수 터치 중 한 포인터만 해제할 때 나머지 이동 유지, 마지막 해제 후 정지, 누르는 동안 야간 HUD 갱신.
- 실제 경로로 진료소 주민에게 접근한 현장 기록에서 통행 요청 → 도움 → 사유 보관함 허락 → 귀환 정산.
- 일시정지한 상태에서 Canvas NPC를 눌러 대화하고 닫아도 정지 상태 유지.
- 합법적인 밤 정산으로 만든 결말에서 새 게임 설정을 열고 취소하여 결말로 복귀, 다시 새 게임 실행.
- 저장소 쓰기 실패를 모사하여 매 프레임 재시도하지 않고 5초 간격 유지.

무전기와 구호 진행, 투척 직후의 소리·가방·재사용 시간을 같은 envelope로 저장한 뒤 실제 귀환 정산까지 검사합니다. 날짜가 맞지 않는 준비 완료나 허용 범위를 벗어난 현장 유인 횟수는 현재 저장을 덮어쓰기 전에 거부합니다.

새 생존기를 시작하면 같은 번호를 다시 사용하더라도 기본·백업·아침 기록을 첫날 상태로 갱신합니다. 다른 난이도의 같은 번호로 아침 복구를 시도하면 거부합니다. 가져온 기록의 잘못된 현장 ID·인물·가방 크기·새 전투 필드와 권한 데이터도 검사합니다.

## Canvas 확인

별도 native 래스터 검증에서 실제 수리·회피·공격 예고·주민 합의 API로 만든 상태를 렌더링했습니다. 깊게 동결한 상태를 넘겨도 상태는 변하지 않습니다. 문 뒤 공격 준비 NPC와 주민을 제거한 PNG와 원본 PNG의 바이트가 같아, 숨은 경고·공격 예고·말풍선 누출이 없음을 확인했습니다.

동적 내구도·행동 변화는 배경 캐시를 다시 만들지 않고, 일반 프레임에서 DOM 크기를 다시 읽지 않습니다. 360×225 CSS 크기와 DPR 2에서도 주민 클릭이 일치하고, destroy 시 이벤트를 정리합니다.
