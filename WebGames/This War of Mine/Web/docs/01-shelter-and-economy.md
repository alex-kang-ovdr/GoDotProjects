# 01. 은신처·자원·작업 시스템

이 문서는 LAST LIGHT Campaign Edition 4.0의 실제 구현 명세입니다. 상용 원작의 확정 수치가 아니라, 이 프로젝트에서 구현하고 검증하는 규칙을 설명합니다. 규칙의 기준은 [engine.js](../dist/engine.js), 회귀 검증은 [engine.test.js](../tests/engine.test.js)입니다.

## 설계 목적

낮은 세 사람의 시간을 식사·회복·제작·시설 유지에 나누는 단계입니다. 밤에 반출한 도구는 집에서 사용할 수 없고, 밤늦게 가져온 연료는 이미 지나간 밤의 난방에 사용할 수 없습니다. 따라서 출발 전에 동료의 상태와 남겨 둘 물자를 함께 판단해야 합니다.

## 상태와 소유권

| 상태 | 의미 | 변경 시점 |
|---|---|---|
| `inventory` | 은신처 공용 재고 | 작업 착수·완료·취소, 거래, 출발, 밤 정산 |
| `characters[].job` | 진행 중 작업과 예약 재료 | 착수 시 생성, 완료·취소 시 해제 |
| `characters[].queue` | 최대 3개 후속 행동 ID | 예약·삭제, 앞선 작업 종료 |
| `facilities` | 시설 개수 또는 보강 단계 | 건설 완료 |
| `shelterIntegrity` | 방호벽 상태, 0~100 | 습격과 수리 |
| `nightPlan` | 역할·반출량·출발 직전 재고 | 밤 준비 확정 |

아이템은 목재, 부품, 물, 식재료, 식사, 연료, 약품, 붕대, 천, 쇠지레, 칼의 11종입니다. 재고는 알려진 아이템의 0 이상 정수만 허용합니다. 가방 칸은 `ceil(수량 / 묶음 크기)`를 품목별로 더합니다. 품목별 묶음은 `ITEMS`에 선언되어 있습니다.

## 낮의 시간과 동시 작업

하루는 06:00~20:00입니다. 실제 1초가 게임 12분이며 2배속에서는 24분입니다. 아침은 일시정지로 시작하고 작업을 맡기면 시간이 흐릅니다. 각 생존자는 한 작업을 수행하며 여러 생존자가 동시에 움직일 수 있습니다.

예약은 재료를 차감하지 않습니다. 작업이 실제 시작할 때 비용을 한 번 차감하고, 완료 시 결과물을 생성합니다. 중단하면 예약했던 재료를 한 번 돌려줍니다. 후속 작업의 예상 가능 여부는 앞선 작업으로 바뀌는 재료·시설·남은 시간을 반영합니다. 착수 시 재료가 다른 인물에게 사용되었다면 해당 예약을 건너뛰고 기록을 남깁니다.

큰 시간 간격과 작은 시간 간격으로 동일한 총 시간을 진행해도 결과가 같도록, 완료 경계마다 시간을 나누어 처리합니다. 침대 수와 중복 시설 건설, 잔해 동시 정리 제한은 UI가 아닌 엔진에서 검사합니다.

## 인물과 회복

| 인물 | 특성 | 가방 |
|---|---|---:|
| 미라 | 자신·동료에게 붕대와 약품을 사용할 때 추가 회복 | 10칸 |
| 윤 | 제작·건설 작업 시간 20% 감소 | 12칸 |
| 레오 | 넓은 수색 가방 | 15칸 |

건강·사기는 높을수록 좋고, 내부 값 `hunger`, `fatigue`, `illness`는 높을수록 나쁩니다. UI는 허기와 피로를 각각 `100 - 값`인 포만·기력으로 표시합니다. 식사는 자동으로 먹지 않습니다. 충분히 먹고 쉰 인물은 낮과 밤을 더 안정적으로 버팁니다.

동료 치료는 `performCare(state, healerId, targetId, kind)`로 시작합니다. 실제 환자 ID를 작업에 기록하고 시전자의 특성으로 회복량을 정합니다. 치료 중 환자를 잃거나 작업을 중단하면 치료품을 환급합니다. 사망한 인물이 회복하는 경로는 차단합니다.

## 시설·손상·수리

시설은 침대, 스토브, 작업대, 집수기, 난로, 문 보강, 덫, 무전기입니다. 무전기와 교신·대피 준비의 상세 비용 및 작업 규칙은 [구호 연락망 명세](04-relief-and-objectives.md)를 따릅니다. 시설 개선과 기존 시설의 수리는 별개의 비용을 갖습니다. 방호벽을 끝까지 보강해도 손상 관리는 계속 필요합니다.

문 보강의 유효 방어력은 다음과 같습니다.

`문 보강 방어력 = 단계 × 11 × 내구도 / 100`

총 방어력에는 기본 3, 경계 인물의 건강·피로에 따른 기여, 집에 남긴 도구가 추가됩니다. 칼의 방어 보너스는 8, 쇠지레는 4이며 경계 인원이 있을 때만 적용합니다. 반출한 도구는 제외합니다.

| 행동 | 비용 | 기본 시간 | 결과 |
|---|---|---:|---|
| 은신처 수리 | 목재 2 · 부품 1 | 70분 | 내구도 최대 35 회복, 상한 100 |
| 윤의 은신처 수리 | 같은 비용 | 56분 | 인물 특성이 적용된 같은 회복량 |

질병·낮은 사기 때문에 실제 작업 시간은 늘어날 수 있습니다. 수리는 내구도가 100이면 시작할 수 없고, 두 사람이 같은 은신처를 동시에 수리할 수 없습니다. 예약·취소·재료 환급은 다른 작업과 같은 체계를 사용합니다.

습격이 없으면 내구도는 줄지 않습니다. 습격이 발생하면 방어 성공 여부와 관계없이 다음 식으로 마모를 계산합니다.

`예상 마모 = ceil((3 + 습격 강도 / 10 + max(0, 강도 - 방어력) × 0.12) × 난이도 마모 배수)`

계산 결과는 2~18로 제한하고 현재 내구도 이하만 적용합니다. 그날의 방어는 습격 전 내구도로 판정하고, 손상은 다음 방어에 영향을 줍니다. 이번 밤을 이겼다는 이유로 현재 방어력을 다시 낮춰 같은 습격 피해를 중복 계산하지 않습니다.

## 출발 전 예측

`getNightForecast(state, plan)`은 실제 밤 판정과 같은 공식을 사용합니다. 경계 인원, 총 방어력, 습격 확률과 강도 범위, 내구도와 예상 마모, 난방용 연료, 수면 인원과 침대를 표시합니다. 수색 중에는 출발 전 재고에서 반출량을 다시 계산하여 이중 차감을 피합니다.

예측은 가능한 범위를 알려 주며 난수 결과를 미리 노출하지 않습니다. 부족한 연료·침대, 약한 방어, 지친 경비와 손상된 방호벽은 명시적인 경고로 이어집니다.

## 거래

상인의 재고는 자유 교환과 간편 꾸러미가 공유합니다. 플레이어가 제공한 물자의 판매 가치가 받으려는 물자의 구매 가치 이상이어야 합니다. 같은 품목은 양쪽에 동시에 올리지 못하고, 소유 재고와 상인 재고를 먼저 확인한 다음 전체 교환을 반영합니다.

잘못된 교환은 재고를 일부만 변경하지 않습니다. 판매가는 구매가보다 낮으며, 꾸러미와 재판매를 조합해도 전체 판매 가치가 늘어나지 않도록 검증합니다.

## 밤 정산과 피드백

순서는 현장 귀환 상태 반영 → 집의 습격 → 난방·수집·덫 → 건강과 허기·피로·사기 변화 → 귀환 물자 반입 → 보고서입니다. `nightPlan.resolved`와 phase로 밤을 한 번만 정산합니다.

보고서의 `supplyDelta`는 출발 직전 재고와 아침 재고의 차이입니다. `loot`는 실제 귀환 가방이며 둘의 의미가 다릅니다. `characterChanges`는 세 인물의 전후 상태와 변화량을 기록합니다. UI에서는 포만·기력 변화의 부호를 내부 허기·피로와 반대로 표시합니다.

## 검증해야 할 불변 조건

- 취소·귀환·정산은 한 번만 비용이나 결과를 적용한다.
- 예약은 자원을 선점하지 않으며, 시작할 수 없는 예약 때문에 뒤 작업이 영원히 막히지 않는다.
- 손상된 문은 단계가 유지되고 유효 방어력만 낮아진다.
- 수리는 내구도 100을 넘지 않고 같은 비용을 두 번 환급하지 않는다.
- 예측과 실제 판정이 같은 역할·재고·난이도·내구도를 사용한다.
- 귀환 물품이 그날 밤 난방이나 집의 방어에 소급 사용되지 않는다.
