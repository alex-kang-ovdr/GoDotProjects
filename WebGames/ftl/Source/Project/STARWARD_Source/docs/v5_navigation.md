# STARWARD v5 — 문 경유 이동·실제 경로·공간 판정

v5는 같은 시스템 방 사이의 이동도 함선별 실제 문과 거리를 따르게 합니다. 화면에 그린 선만 바꾸는 기능이 아니라 위치 갱신·문 상호작용·물리 방 전환·저장 검증을 같은 규칙으로 연결합니다.

근거: [engine.js](../dist/engine.js)의 경로·이동·문·빔 명령과 저장 검사, [data.js](../dist/data.js)의 레이아웃, [UI](../dist/app.js)의 경로 표시. 정규 데이터는 [v5 레이아웃 명세](v5_layouts.md), 이전 저장은 [v5 검증 명세](v5_validation.md)를 참고합니다.

## 1. 소유 함선과 실제 함선

승무원은 소유자의 `crew` 배열에 남아 있으며 `faction`은 소유 편입니다. `shipId`는 현재 실제 위치입니다. 아군이 적선으로 침투해도 플레이어 소유 배열에서 제거하지 않습니다.

| 판단 | 기준 |
|---|---|
| 지금 위치·방·이동 경로·문 | `state[crew.shipId]`의 레이아웃 |
| 아군 문 자동 통과 여부 | 승무원 편과 현재 함선 편의 일치 |
| 저장 배치 `homeRoomId` | 소유 함선의 유효 방 |
| 전송 도착점 | 목적 함선의 해당 방 중심 |
| 조준·빔·탄의 도착 | 공격 대상 함선의 기하 |

같은 방 ID를 양측이 사용해도 좌표는 다를 수 있습니다. 플레이어 도면에 맞는 좌표를 적선 승무원에게 적용하지 않습니다. 일반 `moveCrew()`는 같은 물리 함선 안의 이동이며 함선 간 이동은 기존 텔레포터 명령입니다.

## 2. 경로 탐색과 실제 이동

연결은 현재 함선의 내부 문 `a ↔ b`에서 유도합니다. 에어록은 외부를 향하므로 내부 방 경로의 노드로 쓰지 않습니다. 닫힌 문도 경로에는 존재하지만 도착했을 때 자동 개방 또는 파괴 규칙을 적용합니다.

탐색은 너비 우선 방식으로 통과 문 수가 적은 경로를 선택합니다. 같은 문 수이면 정의에 기록된 연결 순서를 따릅니다. 문 수가 같은 경로들 사이에서 실제 거리가 가장 짧은 경로를 다시 최적화하거나 화재·적 승무원·저산소를 자동 회피하지는 않습니다. 위험한 길을 피하려면 다른 방을 경유하도록 직접 명령합니다.

명령이 정한 방 ID 큐는 기존 `movePath`로 유지합니다. 좌표는 현재 위치에서 다음 실제 문 중심으로, 문을 넘은 뒤 해당 방 내부로 진행합니다. 문 도달 전까지 전혀 관계없는 방이나 외벽을 가로질러 목적 방 중심으로 직행하지 않습니다. 최종 방에서는 방 중심까지 이동을 마칩니다.

정지 중 명령은 경로만 바꿉니다. 현재 좌표·방·시간·문 파괴량을 즉시 진행시키지 않습니다. 이동 중 다른 목적지를 지정하면 현재 실제 좌표에서 새 문 경로를 구하고, 원래 방 중심으로 순간이동시키지 않습니다.

### 문 통과의 기존 규칙

- 아군은 자기 함선의 정상 닫힌 문을 자동으로 열어 통과합니다. 수동으로 연 문은 그대로 유지합니다.
- 적대 인원은 닫힌 적 함선 문 앞에서 파괴합니다. 문 내구도와 파괴 시간은 기존 규칙을 유지합니다.
- 파괴된 문은 열린 연결로 작동하며 이후 비콘 정비 규칙에 따라 회복합니다.
- 경로가 있다고 해서 즉시 도착하지 않습니다. 이동 속도·문 상태·침입자 파괴·일시정지가 실제 소요 시간을 결정합니다.

틱의 이동 예산은 `종족 이동 속도 × 경과 시간`입니다. 문에 도착하는 데 쓴 시간을 먼저 빼고, 남은 시간만 문 파괴에 사용할 수 있습니다. 닫힌 적 문은 초당 내구도6을 잃습니다. 문 앞에 도착하기 전에 방 중앙에서 원격 파괴를 진행하거나 같은 시간을 이동과 파괴에 두 번 쓰지 않습니다.

## 3. 경로 조회 API

`getCrewRoute(crewId)`는 유효한 활성 경로가 없으면 `null`을 반환합니다. 경로가 있으면 다음 구조를 반환합니다.

```js
{
  shipId: 'player',
  roomIds: [/* 현재 물리 방에서 목적 방까지 */],
  points: [{ x, y }, /* 실제 문 중심 */ { x, y }],
  distance: /* 선분 길이의 합 */
}
```

첫 점은 현재 실제 승무원 좌표, 마지막 점은 목적 방 중심입니다. 중간 점은 남은 실제 경로를 나타냅니다. `distance`는 연속 점 사이의 유클리드 길이 합이며 문 파괴 대기·정지 시간을 포함한 도착 예정 시간이 아닙니다. UI는 이 결과를 그대로 사용해 선택한 승무원의 경로와 대략적인 거리를 표시합니다.

조회는 상태·로그·난수·ID를 변경하지 않습니다. 같은 상태에서 반복해 호출해도 항해 결과가 달라지지 않아야 합니다. 이동하면서 현재 위치와 남은 거리가 바뀌는 것은 정상입니다.

레이스 기관실 중심 `(1,3)`에서 무기실 중심 `(5,1)`으로 가는 경로는 `(1,3) → (2,3) → (3,2) → (4,1) → (5,1)`입니다. 기관→의료→실드→무기의 세 문을 지나며 총 거리는 `2 + 2√2 ≈ 4.83`격자입니다. 화면의 약4.8칸은 이 실제 선분 길이입니다. 방 중심을 곧장 잇는 거리 약4.47과 구분합니다.

## 4. 감압·빔과의 일관성

산소 확산과 감압은 실제 열린 내부 문과 에어록을 따라갑니다. 다른 레이아웃에 있던 전역 인접 목록을 참조해 닫힌 벽 너머로 산소가 이동해서는 안 됩니다. 전원 공급·질식·화재·수리의 기본 공식은 기존 [v3 전투 명세](v3_combat.md)를 유지합니다.

빔 조준은 목표 함선의 시작·끝 방 중심을 구하고 최대 길이 안에서 선분을 정합니다. 통과한 서로 다른 방을 한 번씩 기록합니다. 설치한 함선의 구조로 상대 방 교차를 계산하지 않습니다. 비행 중 탄에는 이미 선택한 도착 방·빔 경로를 보존하므로 적 카드의 다음 표적과 분리합니다.

도면·이동 경로·감압·빔이 서로 다른 기하를 사용하지 않도록 실제 `ship.layoutId`를 공통 기준으로 삼습니다. 렌더링은 이를 화면 좌표로 변환할 뿐 통로를 추가하거나 피해 판정을 다시 만들지 않습니다.

## 5. 저장·재개 경계

이동 중 임의 시점에 저장해도 현재 좌표와 방 ID 큐를 보존합니다. 복원 직후 좌표가 방 중심으로 이동하거나 문을 건너뛰어서는 안 됩니다. 같은 저장에서 두 게임을 복원하고 같은 명령·시간을 적용하면 경로·문·좌표·전투 상태가 일치해야 합니다.

이전 버전은 방 중심 사이의 직선 이동을 사용했습니다. legacy 변환은 해당 저장의 좌표·경로를 그대로 보존해야 하며, 새로운 함선 구조에 강제로 투영하지 않습니다. 현재 v5 정상 저장에는 해당 레이아웃의 실제 문·유효 경로·좌표 규칙을 적용합니다. 확정된 이전 저장의 예외 처리는 [검증 명세](v5_validation.md)에 따로 기록합니다.
