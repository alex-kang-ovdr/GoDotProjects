# STARWARD — 마지막 신호

**EXPEDITION / 05 · 실시간 일시정지 함선 전술 게임**

FTL에서 영감을 받은 전력 배분·시스템 공격·승무원 생존·자원과 경로 선택을 실제 캠페인으로 연결했습니다. v5는 **함선별 실제 격실·문 구조, 문 중심을 지나는 이동, 남은 경로·거리, 상대 도면에 따른 빔 판정**을 추가합니다. 장비·화물·회수품·거래, 네 적 전술·표적 의도, 배치 저장, 숙련·은폐·이온·환경 위험과 기존 침투·드론·수동 사격도 유지합니다.

## 1. 실행

웹 주소: [STARWARD — 마지막 신호](https://starward-last-signal.taru00.chatgpt.site)

**독립 파일:** `artifacts/STARWARD_Offline.html`을 최신 브라우저로 엽니다. CSS·네 스크립트를 포함하므로 별도 설치·외부 라이브러리·네트워크가 필요하지 않습니다. 웹 화면의 **오프라인 버전 / 소스 ZIP**에서 내려받을 수 있습니다. 로컬 파일 실행 중에는 별도 다운로드 버튼을 숨깁니다.

**소스 실행:** `dist/index.html`을 열거나 프로젝트 폴더에서 다음 명령을 실행하고 `http://localhost:8000`에 접속합니다.

```bash
python3 -m http.server 8000 --directory dist
```

Windows는 `py -3 -m http.server 8000 --directory dist`를 사용할 수 있습니다. 게임에는 Node.js·npm이 필요하지 않습니다. Node.js는 개발용 테스트와 오프라인 생성에 사용합니다.

## 2. 격납고와 첫 교전

| 함선 | 실제 시작 구성 |
|---|---|
| 아르고 | 선체30·반응로10, 삼연장 레이저+아르테미스, 인간·엔지·록, 방어 드론. 스크랩60·연료12·미사일10·부품4. |
| 아틀라스 | 선체28·반응로11, 이온+중형 레이저, 인간·엔지·엔지, 공격·방어 드론. 스크랩50·연료12·미사일6·부품6. |
| 레이스 | 선체26·반응로11, 삼연장 레이저+빔, 인간·엔지·인간, 방어 드론·은폐1. 스크랩45·연료12·미사일6·부품3. |

모두 실드 한 층과 같은 여섯 시스템을 사용하지만 실제 방의 위치·크기·문 연결은 다릅니다. 아틀라스의 설치 드론도 **전개 때 부품을 지불**합니다. 레이스는 은폐 전력 1이 배분된 채 시작합니다. 베테랑은 적 선체를 20% 늘려 올림하고 적 무기 충전 시간을 10% 줄입니다. 플레이어 시작 구성과 보상은 표준과 같습니다. 출항 뒤 함선·난이도를 바꾸지는 않습니다.

| 함선 구조 | 방 범위·내부 문 | 이동과 환기 특징 |
|---|---|---|
| 아르고 | 7×4·8개 | 상하 우회로, 기관실·의료실 에어록 |
| 아틀라스 | 6×4·7개 | 중앙 무기·의료실, 후방 기관실·산소실 에어록 |
| 레이스 | 8×4·6개 | 기관실·함교는 단일 진입, 기관→무기 이동에 세 문 |

1. 함선·난이도를 고르고 **선택 함선으로 출항**합니다. 전투는 일시정지로 시작합니다.
2. 무기 카드 또는 `1~4` → 적 방으로 표적을 지정합니다. 빔은 시작 방과 끝 방을 차례로 지정합니다.
3. 아틀라스는 드론 탭에서 공격 드론을 전개하세요. 이온은 실드를 잠그고 레이저·드론이 실제 선체 피해를 줍니다.
4. **Space / 전투 시작**으로 진행합니다. 피격·화재·침입 때 멈추고 전력과 승무원을 재배치합니다.
5. 회수품이 나오면 **화물칸으로 회수 / 분해**를 선택합니다. **장비·화물**에서 정비하고 지도에서 연결 비콘을 고릅니다. 세 섹터와 기함 세 단계를 통과하면 승리합니다.

## 3. 조작

| 기능 | 입력과 동작 |
|---|---|
| 시간 | **Space** 또는 전투 버튼으로 정지·재개, **1× / 2×**로 배속. |
| 무기 | 카드 또는 **1~4** 선택 → 적 방. **ON/OFF**, **자동/수동 사격**, 개별 **발사**. |
| 일제사격 | **F / 일제사격**. 충전·전력·표적·탄약을 갖춘 무기만 발사합니다. 정지 중 예약은 재개 후 실행합니다. |
| 빔 | 빔 선택 → 시작 방 → 끝 방. 최대 4격자 길이 안의 통과 방을 한 번씩 공격합니다. |
| 은폐 | **C / 은폐**. 설치·전력·재사용 대기가 필요합니다. 자기 무기 발사는 은폐를 해제합니다. |
| 승무원 | 목록·도면에서 선택. **Shift / 다중 선택**으로 여러 명, 현재 위치한 함선의 방을 눌러 이동합니다. 선택 인원의 점선은 실제 남은 문 경로이며 거리를 함께 표시합니다. |
| 함선 구조 | 본함·적선 상태 아래 **도면 이름 ↗**를 눌러 실제 방·연결 목록·에어록·전략을 봅니다. 격납고 미니 도면도 실제 시작 구조입니다. |
| 숙련·기록 | **숙련 현황**에서 인원별 XP·효과, **함선 기록**에서 이번 항해 로그를 확인합니다. |
| 승무원 배치 | **배치 저장**으로 본함의 생존·정지 인원 위치를 기억하고 **복귀 ↩**로 돌아갑니다. 정지 중에는 이동만 예약하며 적선 인원은 제외합니다. |
| 장비·화물 | 상단·지도·보상의 **장비·화물**에서 장착·화물 보관·같은 종류 교체·무기 순서·폐기. 교전·사건 중에는 열람만 가능합니다. |
| 회수·거래 | 보상의 **화물칸으로 회수 / 분해**, 상점의 장비 관리에서 **판매**. 회수품을 결정하기 전에는 계속할 수 없습니다. |
| 적 의도 | 적 전술 설명과 각 무기의 **다음 표적**을 확인합니다. 충전 중에는 해당 표적을 유지합니다. |
| 전력 | 주 시스템·드론·텔레포터·은폐의 **＋ / −**. 모두 현재 반응로 예산을 공유합니다. |
| 문·에어록 | 도면 또는 **격실 문** 목록. **통로 개방**은 내부 문, **전체 봉쇄**는 정상 문과 에어록을 닫습니다. |
| 환기 | **전체 환기**로 내부 문·에어록을 엽니다. 연결된 방이 감압되며 아군도 질식합니다. |
| 침투·귀환 | 1~2명 선택 → 텔레포터 전력 → **적선 침투** → 적 방. 충전 후 **귀환**으로 본함 의료실에 회수합니다. |
| 드론 | **드론 탭** → 관제 전력 → **전개**. 같은 교전의 전개 기체는 중지·재가동이 무료입니다. |
| 항해·도주 | 지도에서 연결 비콘 → **FTL 도약**. 전투의 **긴급 도약**은 FTL100·조종사·엔진·연료가 필요합니다. |
| 저장 | **저장 / 불러오기**, **⇅ 저장 파일 관리**의 JSON 내보내기·가져오기. |
| 기타 | **?** 안내, **Esc** 선택·수동 창 취소, **♪** 효과음, **↻** 새 항해. 도면의 방·문과 버튼은 키보드로도 실행합니다. |

## 4. 핵심 규칙

**실격실·이동:** 아르고·아틀라스·레이스, 요격함·기함은 자기 방과 문을 사용합니다. 승무원은 문 중심에 먼저 접근한 뒤 자동 개방·문 파괴·통과를 처리합니다. 적선 위 아군도 적선의 연결을 따릅니다. 경로는 적은 문 수를 우선하며 위험·최단 거리를 자동 최적화하지 않습니다. 표시 거리는 문 파괴 시간을 포함한 도착 예정 시간이 아닙니다. 레이스 기관→의료→실드→무기 경로는 약4.83칸입니다.

**목표 도면과 빔:** 같은 기관실→무기실 조준도 요격함에서는 기관·실드·의료·무기의4방, 기함에서는 기관·실드·무기의3방을 지나갑니다. 최대 길이4와 방별 한 번 타격 규칙은 유지합니다. 닫힌 벽은 이동·산소에 유효하며 장식 선체 외곽이 새 통로를 만들지는 않습니다.

**장비·화물:** 무기 4개·드론 2개를 설치하고 두 종류를 합쳐 화물 6개를 보관합니다. 같은 정의도 서로 다른 개체로 중복 소유할 수 있습니다. 회수는 화물로 들어가며 장착과 전력 확보는 별개입니다. 보관·재장착은 충전·표적·전개를 초기화하고 부품을 환불하지 않습니다. 마지막 무기 보관·판매는 금지하지만 교체는 가능하며, 만석 화물도 같은 종류 교환을 허용합니다. 무기 순서는 실제 전력 우선순위입니다.

**회수·판매:** 첫 일반 승리와 2·4·6…승, 승무원 전멸 승리에 회수품이 나옵니다. 첫 회수품은 아르고·레이스 이온, 아틀라스 빔입니다. 화물로 받거나 표시된 판매가로 분해할 때까지 보상 화면을 유지합니다. 상점 장비 구매는 빈 설치 슬롯부터, 만석이면 화물로 들어갑니다. 상점 판매 수입은 전투 획득 스크랩 통계에 중복 집계하지 않습니다. 폐기는 보상 없이 제거하므로 장비창에서 확인합니다.

**적 전술·배치:** 습격형은 무기, 교란형은 이온과 실드·무기, 강습형은 산소·의료 지원, 포격형은 미사일·엔진을 압박합니다. 수리·전력 우선순위도 실제로 다릅니다. 적은 충전 시작 때 표적을 정해 발사까지 유지하고, 이미 날아가는 탄은 별도 표적을 보존합니다. 승무원을 원하는 담당실로 보낸 뒤 배치를 저장하면 정비·치료 후 한 번에 복귀 명령을 내릴 수 있습니다.

**숙련:** 조종·기관·무기·실드·수리·선내 전투 XP가 각각 40/120에서 1/2단계가 됩니다. 실제 운용·작업·타격으로 성장하며 정지·사망·이동·무전력·유휴 수리로 얻지 않습니다. 운용은 최고 적격 승무원 한 명만 적용합니다. 단계당 조종·기관 회피 +3%p, 무기 충전 +10%, 실드 충전시간 -8%, 수리 +15%, 근접 피해 +10%입니다. 도약·정비는 XP를 유지하고 새 항해는 초기화합니다.

**은폐:** 전력 1/2/3에 지속 6/8/10초, 회피 +60%p(최대95%)와 상대 일반 무기 충전 정지를 제공합니다. 비행 중 탄은 계속 판정합니다. 자기 사격·전력 상실·지속 종료 뒤 재사용 20초이며 전력이 있어야 대기가 줄어듭니다. 드론·환경·기함 특수 타이머는 계속 진행합니다.

**이온:** 전력1·기본충전7초, 선체 피해0입니다. 실드가 남으면 실드에, 없으면 지정 시스템에 잠금1·5초를 적용합니다. 중첩은 시스템 레벨, 잔여시간은15초까지입니다. 물리 손상·승무원 피해·화재·균열은 만들지 않습니다. 함교 잠금은 조종도 멈춥니다. 만료 때 빈 전력 예산만 복원하고 사용자가 다른 곳에 옮긴 전력을 빼앗지 않습니다.

| 환경 | 효과와 선택 |
|---|---|
| 소행성 | 8초 주기·2초 예고, 양측 피해1 파편. 회피·일반 실드가 적용됩니다. |
| 태양 | 22초 주기·5초 예고, 양측 한 방 화재+0.8. 그 순간 실드0이면 선체1 추가 피해. |
| 이온 폭풍 | 현재 가용 반응로만 65% 내림·최소2로 제한합니다. 명목 반응로는 파괴되지 않습니다. |

환경은 선택 가능한 일부 교전 비콘에 배치하고 지도에서 효과와 보너스를 미리 보여 줍니다. 승리 보너스는 스크랩 +8이며 도주·패배에 지급하지 않습니다.

기존 전술도 함께 작동합니다. 닫힌 문은 산소·화재를 격리하고 침입자는 문을 부숩니다. 아군은 자기 문을 자동 통과합니다. 네 종족의 이동·수리·체력·근접 특성, 의료, 실제 대인전과 시스템 파괴 공작을 처리합니다. 드론은 교전당 첫 전개 부품1, 공격 드론은6초마다 레이저1, 방어 드론은3초 주기로 미사일만 요격합니다. **적선 파괴·도주 전에 침투조를 회수해야 합니다.**

세 섹터의 상점·조건 사건·위험 경로를 거쳐 강습/드론 과충전/미사일 일제사격 기함을 상대합니다. 비콘 사이에는 사고·문·임시 효과를 정리하고 생존 본함 인원을 부분 치유합니다. 선체는 별도 수리·보급이 필요하고 전사자는 부활하지 않습니다. 실제 가격·공식·모드 전환은 시스템별 MD에 상세히 정리했습니다.

## 5. 저장 호환과 파일 이동

저장 내부는 **version5**, 기존 브라우저 키 `starward-save-v1`을 유지합니다. 단일 슬롯에 전투 중 주기적·모드 전환·탭 숨김·종료 시 자동 저장을 시도합니다. 새 항해를 실제 시작하면 이전 슬롯을 덮어씁니다.

- v1·v2·v3·v4 저장을 연속 변환합니다. 이전 선체·체력·자원·장비 ID·화물·회수품·위치·문·침투·드론·충전·XP·은폐·이온·환경·캠페인·저장 배치를 보존합니다. 기존 함선은 **기존 항해 배치(legacy)**로 유지하고 새 도면으로 재배치하지 않습니다. 새 항해부터 선택한 함선의 새 구조를 사용합니다.
- 은폐 중, 이온 잠금, 환경 타이머, 숙련, 침투·전개 드론·비행 중 빔·현재 적 표적·화물·미결정 회수품·회수 영수증도 저장합니다.
- JSON 파일을 선택하면 구조·버전 검증과 상태 미리 보기 후 적용합니다. 적용 전 현재 항해의 복구용 사본을 보관하며 백업 저장에 실패하면 교체하지 않습니다.
- 이동 중 실제 문 좌표와 경로를 저장합니다. 구 버전의 문 통과 직후·정지 중 재지시 저장도 원본을 보존하고 현재 위치에서 이어갑니다.
- 손상·미지원 버전·잘못된 참조·전력·자원·변조된 방/문·가짜 이동 경로는 거절하고 현재 항해를 유지합니다. 불러온 전투는 UI에서 일시정지됩니다.
- 웹과 로컬 파일의 저장 공간은 다를 수 있습니다. 파일 내보내기로 옮기거나 저장이 제한되는 브라우저에서는 로컬 서버를 사용하세요.

## 6. 구현 범위와 남은 한계

3함선·2난이도·3섹터·3기함 단계, 4종족·5종 무기·공격/방어 드론·텔레포터·은폐·숙련·3환경·장비 거래·화물·회수품·4적 전술·저장 배치·함선별 공간 구조를 제공합니다. 각 함선은 동일한 여섯 시스템을 다른 위치·문 연결로 배치합니다. 지도 골격·상품은 고정입니다. 일부 사건·적 변형·명중은 시드 난수를 씁니다.

원작 전체 종족·함선별 해금·레이아웃 수집·업적·영구 성장, 폭탄·플랙·해킹·정신 지배·클론실·보조 배터리·강화장치, 성운 센서 차단·펄서·ASB는 없습니다. 빔은 방 중심 사이 경로이며 자유 좌표 조준·칸 점유 경쟁은 없습니다. 장비 희귀도·상점별 재고·영구 창고·화물 중량·레이아웃 편집기·빈 복도·개별 보조 시설실은 없습니다. 드론은 무기실, 텔레포터는 의료실, 은폐는 기관실을 공유합니다. 기함 패턴·경제·비콘 정비는 이 게임의 자체 규칙입니다. 서버·계정·멀티플레이는 사용하지 않습니다.

## 7. 개발·검증

Classic script 순서는 `data.js → engine.js → campaign.js → app.js`입니다. `Starward.Game`이 JSON 상태와 공개 명령을 소유하고 UI는 SVG·HTML, 소리는 Web Audio로 구현합니다. 실행 코드는 `dist/`, 테스트는 `tests/`, 명세·실제 화면은 `docs/`에 있습니다.

Node.js18 이상, 별도 의존성 없이 실행합니다.

```bash
node --test tests/engine.test.cjs tests/corev2.test.cjs tests/corev3.test.cjs tests/corev4.test.cjs tests/corev5.test.cjs
node tests/playthrough.cjs
node tests/playthrough.cjs --loadout atlas --difficulty veteran 42
```

## 8. 다운로드 파일 다시 만들기

소스를 확정한 뒤 실행합니다.

```bash
node scripts/build-offline.cjs
python3 scripts/package-source.py
```

Windows는 `py -3 scripts/package-source.py`를 사용할 수 있습니다. 결과는 `artifacts/STARWARD_Offline.html`, `artifacts/STARWARD_Source.zip`이며 `dist/`에도 복사합니다.

HTML은 로컬 CSS·스크립트를 순서대로 포함하며 외부 URL·module script·누락 입력을 거절합니다. ZIP은 게임 소스·README·변경 이력·v3/v4/v5 명세9개·실제 캡처7개·테스트·fixture·빌드 스크립트·독립 HTML을 포함하고 CRC를 검사합니다. 저장소 내부 정보·환경 메타데이터·이전 ZIP 자체는 포함하지 않습니다. 소스를 바꾸면 두 다운로드 파일도 다시 생성해야 합니다.

v5 최종 오프라인 HTML은358,864바이트입니다. 내장 CSS1개·스크립트4개와 외부 코드 참조0을 확인했고, 포함된 엔진에서 레이스 실제 경로·요격함4방 빔·저장 복원 검사를 통과했습니다.
