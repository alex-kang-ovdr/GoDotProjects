# 17. UI·UX, 입력, 정보 공개와 피드백

> 대상: PC판 FTL: Faster Than Light 및 Advanced Edition. 조사 기준일: 2026-11-13.\
> 이 문서에서 **[확인]**은 공개 자료로 확인한 게임 동작, **[해석]**은 그 동작의 설계적 의미, **[재구성안]**은 같은 경험을 구현하기 위한 제안이다. 화면 좌표·입력 처리 코드·접근성 사양을 원작 내부 구현으로 주장하지 않는다.

관련 문서: [전투](07_combat_timing_and_damage.md), [무기](08_weapons_shields_and_targeting.md), [전력](06_power_systems_and_subsystems.md), [탐험](02_sector_map_navigation_pursuit.md), [QA](21_qa_and_acceptance_tests.md).

## 1. 이 시스템이 해결하는 문제

**[확인]** FTL은 전투 중 일시정지한 상태에서 승무원 명령, 전력 배분, 무기 목표 지정을 할 수 있다. 실시간 압박과 숙고할 시간을 같은 전투 안에 결합한다. [U1]

**[해석]** 플레이어가 해결해야 하는 문제는 버튼을 빨리 누르는 일보다, 여러 위협 중 먼저 해결할 것을 고르는 일이다. UI는 다음 네 질문에 답해야 한다.

1. 지금 무엇 때문에 패배에 가까워지고 있는가?
2. 다음 적 공격까지 어떤 자원을 옮길 수 있는가?
3. 명령을 내렸지만 아직 완료되지 않은 일은 무엇인가?
4. 보이지 않는 정보 때문에 판단을 유보해야 하는 것은 무엇인가?

함선 내부 지도는 장식이 아니라 전투판이다. 방의 연결, 시스템 위치, 승무원 이동, 화재와 진공을 같은 공간에 표현하기 때문에, 긴 상태 목록을 읽는 대신 원인을 공간적으로 추적할 수 있다.

## 2. 화면 정보 구조의 역설계

아래 표는 원작의 대표 화면 요소를 기획 목적에 따라 다시 묶은 **[해석]**이다. 정확한 픽셀 배치나 모든 해상도에서의 위치를 규정하지 않는다.

| 정보 묶음 | 표시해야 할 의미 | 연결되는 명령 | 판단에 미치는 영향 |
|---|---|---|---|
| 선체·자원 | 선체 손상과 연료·미사일·드론 부품·스크랩 잔량 | 수리, 구매, 점프, 소모품 사용 | 이번 전투를 이겨도 다음 구간을 진행할 수 있는가 |
| 아군 함선 내부 | 승무원, 방, 문, 시스템 손상, 위험 | 이동, 문 조작, 수리 대응 | 위험을 격리할지 사람을 투입할지 결정 |
| 시스템 전력 | 설치 용량과 현재 가용 전력, 일시적 제한 | 전력 증감, 능력 발동 | 무기·회피·생명 유지 사이의 교환 |
| 적 함선 | 조준 가능한 방, 실드, 선체, 관측 가능한 내부 | 무기 조준, 해킹, 텔레포트 | 방어를 깎을 순서와 타격 목적 선택 |
| 무기·드론 | 활성 여부, 충전, 발사 예약, 소모 비용 | 선택, 목표 변경, 자동 발사 | 개별 재장전보다 일제사격 타이밍을 관리 |
| 승무원 목록 | 누가 선택됐는지, 체력과 담당 작업 | 선택, 복귀, 능력 | 공간에서 찾기 어려운 개인을 빠르게 제어 |
| FTL·위험 상태 | 이탈 가능 여부와 방해 요인 | 점프 | 계속 교전할지 이탈할지 결정 |
| 이벤트·상점·함선 관리 | 선택지, 비용, 조건과 결과 | 구매, 투자, 선택 | 실시간 전투와 다른 의사결정 맥락 제공 |

**[재구성안]** 선체와 산소를 같은 붉은 경고로만 표현하지 않는다. 선체는 전역 패배 위험, 산소는 방별 생존 위험이다. 산소 평균이 충분해도 특정 방은 치명적일 수 있으므로 전역 수치와 지역 표현을 함께 유지한다.

## 3. 입력은 행동 맥락을 먼저 결정한다

### 3.1 기본 조작 계약

**[재구성안]** 모든 입력은 `행동 → 대상 → 유효성 확인 → 명령 접수 → 진행 결과` 순서로 처리한다. 화면 버튼과 단축키는 같은 명령 API를 호출하며, 단축키만 유효성 검사를 우회하지 않는다.

| 행동 맥락 | 대상 | 접수 시 확인 | 실행이 지연되는 이유 | 사용자에게 남길 표시 |
|---|---|---|---|---|
| 승무원 이동 | 승무원이 현재 있는 함선의 방·타일, 적 함선 탑승 포함 | 선택 승무원 생존, 이동 가능한 선박 | 거리, 문, 전투, 통로 | 목적지 또는 이동 중 상태 |
| 일반 무기 조준 | 적 함선의 방 | 전력·무기 슬롯·표적 유효성 | 무기 충전, 전투 상태 | 예약 표적과 충전 구분 |
| 빔 조준 | 시작점과 끝점 | 길이와 유효 선분 | 충전·발사 조건 | 선분 미리보기 |
| 시스템 능력 | 적 시스템, 승무원, 또는 자기 함선 | 대상 종류, 시야, 재사용 상태 | 능력별 준비·유지 시간 | 대기·활성·재사용 구분 |
| 전력 변경 | 시스템 전력 칸 | 반응로, 시스템 가용 용량 | 즉시 반영 또는 능력별 잠금 | 불가 이유와 최종 가동량 |
| 문 조작 | 내부 문·에어록 | 문 제어 가능 여부 | 해킹·봉쇄 등 예외 | 닫힘·열림·잠김 구분 |
| 이벤트 선택 | 현재 이벤트의 선택지 | 요구 자원과 조건 | 결과 분기 처리 | 선택 확정과 자원 증감 |

### 3.2 일시정지와 강제 정지의 구별

**[확인]** 개발자 설명에 따르면 대화 이벤트가 열려 있으면 게임은 정지 상태를 유지한다. 사용자가 일시정지 키를 눌러도 대화 상자를 닫지 않은 채 전투를 진행시키는 동작은 하지 않는다. [U2]

**[재구성안]** `userPaused`와 `modalBlocked`를 별도 값으로 둔다.

```text
simulationRuns = not userPaused and not modalBlocked and sessionIsPlayable
```

이렇게 하면 일시정지 중 이벤트를 열고 닫았을 때 사용자가 의도하지 않게 시간이 재개되는 문제를 피할 수 있다. 재구현 시 보존할 사용자의 정지 의도와, 원작에서 직접 비교할 세부 복귀 동작은 구분한다.

### 3.3 숫자키 충돌 방지

**[확인]** 개발자는 무기 선택 숫자키가 갑자기 열린 대화의 선택지로 전달되는 문제에 대해, 대화 숫자키 비활성화 또는 활성화 지연 옵션을 안내했다. [U3]

**[해석]** 이는 단순한 편의 옵션이 아니다. 전투에서 누른 키가 이벤트의 영구적 선택으로 해석되면, 플레이어의 전략적 실수와 UI 오작동을 구분할 수 없게 된다.

**[재구성안]** 모달이 열린 프레임의 입력을 이벤트 선택으로 재사용하지 않는다. `pressed`와 `held`를 구별하고 모달 전환 이전부터 눌려 있던 키는 해제 후 재입력할 때 수용한다. 이 보호는 기본 입력 안전장치이며 원작의 정확한 지연 시간은 별도 확인한다.

## 4. 핵심 전투 조작 시나리오

아래 절차는 원작의 조작 요소를 바탕으로 정리한 **[해석]**이며 특정 기본 키 배열에 의존하지 않는다.

### 상황 A. 실드 제거 뒤 빔 공격

1. 일시정지하고 적의 현재 실드와 아군 충전 상태를 읽는다.
2. 실드 제거용 무기의 목표와, 빔이 통과할 방들의 선분을 따로 계획한다.
3. 투사체의 도착 시점을 고려해 발사한다.
4. 실드가 실제로 줄었는지 확인한 뒤 빔 사용을 결정한다.
5. 빗나감으로 전제가 무너졌으면 다음 공격 계획을 바꾼다.

**[재구성안]** UI는 발사 명령 접수와 명중 결과를 같은 성공 효과로 표현하지 않는다. 적 실드 감소, 방 피해, 시스템 제한은 각 결과가 확정된 시점에 표시한다. 원작의 실제 피해 판정 규칙은 [08번 문서](08_weapons_shields_and_targeting.md)를 따른다.

### 상황 B. 화재와 산소 부족의 동시 발생

1. 정지 후 위험 방과 승무원의 위치를 확인한다.
2. 살릴 승무원을 대피시키고, 문을 통해 위험 구역을 격리한다.
3. 진공 소화가 가능한 연결인지 판단한다.
4. 필요한 시스템이 꺼졌다면 수리 인력과 전력을 재배치한다.
5. 화재가 사라진 뒤에도 산소 회복을 기다린다.

**[재구성안]** 화염 효과가 사라지는 순간을 안전 복귀 신호로 사용하지 않는다. 방별 산소 위험 표시가 남아야 한다. 위험 종료와 통행 가능 여부는 서로 다른 상태다.

### 상황 C. 승무원 복귀

**[확인]** AE 출시 당시의 공통 개선에는 승무원 위치 저장·복귀 기능, 실드 재충전 표시, 자원 변화가 드러나는 보상 표시가 포함되었다. 이들 편의 개선을 AE 콘텐츠 토글에서만 켜지는 전투 시스템과 동일하게 취급하면 안 된다. [U4]

**[재구성안]** 저장된 위치를 현재 위치와 별도 보관한다. 사망한 승무원의 목적지, 새로 합류한 승무원, 외부 선박에 있는 승무원을 무리하게 같은 방식으로 복귀시키지 않는다. 복귀 입력은 유효한 승무원에 대한 이동 명령으로 풀어내고 개별 실패를 기록한다.

## 5. 정보 공개와 오인 방지

**[해석]** FTL에서 정보 부족은 전략 자원이다. 관측할 수 없는 적 내부를 평상시와 같은 UI로 표시하면 정보 관련 업그레이드의 의미가 사라진다.

**[재구성안]** 내부 상태와 화면 지식 상태를 분리한다.

| 지식 상태 | 화면 표현 원칙 | 잘못된 구현 예 |
|---|---|---|
| 현재 관측 가능 | 현재 값이나 상태 표시 | 이전 값만 표시해 입력 오도 |
| 현재 관측 불가 | 미상 표시 또는 숨김 | 내부 시뮬레이션의 정확한 HP 노출 |
| 이전 관측 정보만 존재 | 마지막 관측 정보임을 분명히 표시하는 경우에만 사용 | 이전 승무원 위치를 현재 위치로 표시 |
| 대상 자체가 무효 | 선택 취소 또는 불가 이유 | 사라진 적에게 발사 예약 유지 |

정확한 센서 단계별 공개 범위, 성운 영향, 슬러그 감지와 정신 지배 시야 예외는 개별 시스템 문서의 규칙을 연결한다. 이 문서는 미확인 공개 범위를 새로 확정하지 않는다.

## 6. 피드백 우선순위

다음은 소리·색·애니메이션을 실제 원작 에셋과 분리하여 정의한 **[재구성안]**이다.

| 우선순위 | 사건 | 시각 피드백 | 청각 피드백 | 중복 억제 |
|---|---|---|---|---|
| 1 | 게임 종료, 결정적 위험 | 화면의 명확한 상태 전환 | 높은 인지성의 단발 신호 | 같은 사건 ID당 한 번 |
| 2 | 선체 급감, 중요 시스템 불능 | 전역 경고와 해당 방 강조 | 경고 큐 | 짧은 시간 다중 피해 묶기 |
| 3 | 승무원 위급, 화재·균열 | 해당 개인·방의 상태 | 공간 위험 신호 | 같은 방 반복 제한 |
| 4 | 충전 완료, 능력 사용 가능 | 상태 바와 버튼 변화 | 필요 시 짧은 신호 | 자동 반복 작업은 최소화 |
| 5 | 자원 획득, 숙련 향상 | 결과 정리와 증감 | 보상 신호 | 이벤트 묶음 처리 |

화면에 여러 경고가 있을 때 모든 경고를 같은 크기로 점멸시키면 긴급도가 사라진다. 반대로 한 가지 경고만 남기면 지역 위협을 놓친다. 전역 요약과 공간 위치 표시를 함께 둔다.

## 7. UI 상태 모델 예시

**[재구성안]** 다음 객체는 렌더링용 모델이다. 원본 FTL 저장 구조가 아니다.

```json
{
  "inputContext": "combat.weaponTargeting",
  "userPaused": true,
  "modalBlocked": false,
  "selection": { "weaponInstanceId": "wpn_04" },
  "targetPreview": { "shipId": "enemy_01", "roomId": "weapons" },
  "commandAvailability": {
    "canSubmit": true,
    "willExecuteImmediately": false,
    "reason": "CHARGING"
  },
  "visibleKnowledgeVersion": 22
}
```

시뮬레이션은 `SelectWeapon` 같은 순수 UI 명령을 알 필요가 없다. 반대로 UI가 `ApplyHullDamage`를 직접 실행해서는 안 된다. `SetWeaponTarget` 같은 의도를 검증된 명령으로 전달하고, 결과 상태를 읽어 표현한다.

## 8. 재구현 시 접근성 개선 후보

이 절은 모두 **[재구성안]**이며 원작에 이미 있는 옵션이라는 뜻이 아니다.

- 색만으로 전력 부족·손상·이온 제한을 구별하지 않고 패턴이나 아이콘을 함께 사용한다.
- 승무원 체력 경고의 크기, 텍스트 확대, 일시정지 상태 표시를 별도로 조정한다.
- 모든 핵심 명령에 마우스 조작 경로를 남기고 단축키를 재매핑한다.
- 빔 선분 선택 중 시작점을 다시 잡거나 취소하는 명령을 제공한다.
- UI 배율을 올려도 두 함선의 주요 시스템과 발사 제어가 서로 가려지지 않도록 검증한다.
