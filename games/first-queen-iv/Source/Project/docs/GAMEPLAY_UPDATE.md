# v22 Gameplay Integration — 휴식·피로·방어전

## 범위

v21 소스를 기반으로 실제 플레이 중 복원 관측값을 판단·행동·결과에 연결한다. 원시 자료를 새로 복구하거나 원작 규칙을 인증하지 않는다. 데이터 파일 9개의 SHA-256이 v21과 동일하다.

## 데이터 흐름

| 데이터 | 런타임에서 쓰이는 지점 | 플레이어 피드백 |
|---|---|---|
| 관측 fatigue + 전투 중 누적 | 이동 속도·공격 간격·관측 병사 AT 보정 | FT 게이지, 이동 %, 공격 간격 %, 적용 AT |
| 관측 hpRate(HR) | 안전 정지/휴식의 HP 회복량 | HR, 회복 조건, 안전 대기/위협/회복 상태 |
| 관측 hitPoint | 기존 최대 HP 해석 유지 | 현재 HP와 최대 HP |
| 관측 AT/AR/DF/DR 및 장비 | 기존 공격·명중·방어 계산 유지 | 능력치와 원시 기록 비교 |
| 출처 recordId/hash | 저장·복원·편성·전과 | 관측 기록 식별과 지문 검증 |

## 휴식 상태와 우선순위

직접 조작 > 개별/부대 철수 및 자동 부상병 철수 > 행동 진행/구출 보호 > 휴식/전술 AI. 휴식 명령은 새 명령으로 기존 경로·집중 표적을 취소한다.

1. `issue('rest')`는 현재 부대 중심에 anchor를 두고, 미완료 공격 준비를 취소한다. 기존 공격 cool은 유지한다.
2. `recoveryBlock(u)`는 현재 전투 상태만 읽는다. 전사·철수·집중·직접 조작, 근접 위협, 최근 피해, 실제 이동, 진형 집결, 행동 진행을 구분한다.
3. `updateRecovery()`는 공격·투사체 피해·충돌 처리 후 매 틱 실행된다. 부적격이면 recoveryTicks=0, 적격이면 최대180까지 증가한다.
4. 180에 도달하면 FT 감소를 적용하고 개인 ID 위상의 120틱 주기에서 HR 회복을 적용한다.
5. 실제 피해는 `lastHurtTick`과 카운터를 갱신한다. 회피는 피해 시각으로 기록하지 않는다.

시야 차단 여부와 무관하게 180거리 이내의 적은 위협이다. 사거리 밖으로 추격하지 않는 휴식 AI와, 사선이 필요한 자위 공격·치료를 구분한다. 안전 회복은 특정 치료사의 전과로 집계하지 않는다.

`Game.restStatus(u)`는 `{state,label,safeTicks,neededTicks}`를 반환한다. 상태는 inactive, manual, threat, positioning, settling, recovering이다. 표시 함수가 게임 상태를 바꾸지 않는다.

`fatigueEffects(u)`는 기존 전투 공식을 UI와 공유한다. 이동 표시에는 돌격·철수 등 일시적 행동 배율을 포함하지 않는다. 공격 간격 %는 속도의 역수에 해당하는 대기시간 표시다.

## 방어전

신규 전투는 `defenderTeam = !training && ownerBefore==='blue' ? 'blue' : 'red'`로 만든다. 아군 방어일 때 `battlefield(kind,'blue')`는 모든 장애물과 성문의 x좌표를 WIDTH-x로 대칭한다. 진형·철수는 기존 blue-left/red-right 기준을 보존한다.

- 수비병의 siegeAI/beginAttack(gate)/gateDamage 경로에서 자기 성문 공격을 차단한다.
- 아군 수비 중 공성 명령 요청은 상태 변경 없이 거절한다.
- 강 다리는 물 장애물의 실제 x좌표를 사용한다. 수비 깃발은 defenderTeam 색상이다.
- 기존 디버그 gateToggle과 공격자 없는 gateDamage는 테스트·개발 동작으로 유지한다.
- 구버전의 진행 중 전투는 지형을 재배치하지 않고 defenderTeam=red로 이행한다.

## 연습과 이전 저장

관측 캠페인의 전장/평원 주둔군이 모두 비어 있으면 데이터의 기존 필터 조건에서 14명을 안정적으로 선택한다. 연습 ID는 음수로 유지하고 캠페인 nextId/명부/출처 데이터를 변경하지 않는다.

v13 이행의 커스텀 병사 생성은 현재 Game.world.profile에 의존하지 않는 순수 생성기로 변경한다. 입력이 같으면 관측 화면과 커스텀 화면에서 동일한 이행 결과를 얻는다.

## 저장22

`battle.defenderTeam`, `unit.recoveryTicks`, `unit.lastHurtTick`를 보존한다.

- 수비 진영·전장 대칭 관계를 검사한다.
- 카운터는 정수이고 0..min(180,battle.tick) 범위다.
- 마지막 피해는 null 또는 전투 시각 이내의 정수다.
- 최근 피해와 회복 카운터의 모순, 전사·철수 병사의 회복 카운터를 거절한다.
- 입력 복사본 검증 후 전체 상태를 교체한다. 거절하면 기존 상태는 유지한다.
- v21에서 새 회복 필드는 0/null로 초기화하고 기존 전과는 보존한다.

## 의도적 제한

원작 전투 화면·실행 파일과 대조한 휴식 공식이 아니다. 복잡한 병목 진형, 원작 초기 캠페인과 이름 매핑, GPU와 브라우저 실기기 결과는 이 변경에서 해결했다고 주장하지 않는다. 구버전 입력의 모든 의미적 조합을 인증하는 검증기도 아니다.
