# v20에서 유지하는 관측 데이터 통합 규칙

아래는 v19 어댑터 명세 보존본입니다. 수치·관측 참조는 유지하며, 저장 출력 스키마는 20으로 변경했습니다. 새 전술 상태와 AI/회복 사선 변경은 `TACTICAL_UPDATE.md`가 우선합니다.

# v19 데이터→플레이 통합 명세

## 1. 세 계층

1. `data/roster_N.json`: v18의309개 관측 기록을 바이트 동일하게 보존한다. 수치의 출처는 공개 저장소 N의 부분 캡처다. 원작 화면 검증 또는 한국어 새 게임 인증 자료가 아니다.
2. `src/source-data.js`: 관측값, recordId, offset, raw32 해시, 원시 바이트를 불변 카탈로그로 제공한다. `DATA.records` 및 각 raw 객체는 재귀적으로 freeze된다. 버전 지문은 원본 roster_N.json의SHA-256이다.
3. `src/engine.js`: 관측값을 플레이에 사용하는 **명시적 하이브리드 어댑터**다. 원작 미확인 규칙을 ‘복원 완료’로 올리지 않는다. 관측 HP를 최대체력으로 사용하는 가정도 이 계층에 속한다.

엄격한 원작 재현 프로필은 이번 게임에 존재하지 않는다. 관측값을 활용하는 hybrid-repoN-v19와 기존 custom-v15만 제공한다. v18의 `original_playable=false`를 뒤집어 원작 검증이 끝났다고 주장하지 않는다.

## 2. 식별과 저장

런타임 병사의 `id`는 게임 자체의 일련번호다. `origin={recordId,hash}`는 카탈로그 참조다. recordId는 파일+절대위치다. `roleId`, `name`, `job`은 독립된 관측 필드이며 유일 키가 아니다. 역할ID313 두 기록은 별도로 보존한다. 같은 관측기록을 여러번 모집한 것은 새로운 런타임 개체를 만드는 자체 게임 규칙이며 원작의 복제/합류 규칙이라는 의미가 아니다.

저장스키마19는 `world.profile={id,ruleset,datasetRevision}` 및 장비 재고를 가진다. `origin`에 새로운 스탯 필드를 추가해 덮어쓰는 입력은 거부한다. 원본카탈로그 없이 저장의 수치로 대체하지 않는다. 출전명부/런타임/원래 소속 간 origin과 장비가 같은지 검사한다. 실제 데이터 내용이 바뀌면 지문도 바뀌므로 기존 복원 저장은 별도 마이그레이션을 구현하지 않는 한 거부된다.

불러오기는 복사본의 모든 검증이 끝난 후 실제 상태를 교체한다. 오류 발생 시 현재 world, nextId, battle 상태를 유지한다. UI는 유효한 카메라 값만 복원한다. 전투는 정지 상태로 복원된다. 이는 오프라인 치트 방지 서명 시스템이 아니라 손상과 참조오류를 막는 검증이다.

## 3. 수치 연결과 미적용 필드

| 관측 필드 | 실행에서 사용하는 방식 | 상태 |
|---|---|---|
| hitPoint LE | 최대HP로 가정하고 새 개체의 초기현재HP로 설정 | 관측값+CUSTOM 의미 가정 |
| attack | AT의기초값 | 관측값 |
| attackRate | 명중식 입력 AR | 관측값+CUSTOM 공식 |
| defence | DF의기초값 | 관측값+CUSTOM 공식 |
| defenceRate | 명중식 입력 DR | 관측값+CUSTOM 공식 |
| arrowAvoid | 화살 명중 보정 AA | 관측값+CUSTOM 공식 |
| arrowDef / magicDef | 화살/마법 피해 보정 | 원시양수를 감소계수로 쓰는 CUSTOM 해석 |
| hpRate | 비전투 안전거리 회복 | 관측값+CUSTOM 주기·계수 |
| fatigue | 새 개체의0~100 피로로 제한해 사용 | 관측값+CUSTOM 범위 |
| level / grow / exp | 원시값만 표시·보존 | 원작 성장규칙 미적용 |
| name / roleId / job | 출처 검사/표시·가설 역할 분류 | 인물명 자동확정 없음 |
| leadership / element / item | 원시값 표시·보존 | 지휘·속성·장비코드 대응 미적용 |

AD/MD는 이전 복원에서 unsigned 읽기와 음수라는 설명이 충돌했다. 여기서는 그 의미를 확정하지 않는다. 아래 감소식은 게임을 진행시키기 위한 양수 보정 정책이며 원작 해석이 아니다.

## 4. 실행 공식 — 모두 CUSTOM

관측 병사에게 `u.level`은 새 훈련단계이고1부터 시작한다. 원작 raw.level을 정규화하거나 덮어쓴 값이 아니다. `rank = u.level - 1`이다.

```text
HPmax = max(1, observed.hitPoint) + 7 × rank
AT    = observed.attack + rank + overlay.AT
AR    = observed.attackRate + overlay.AR
DF    = observed.defence + overlay.DF
DR    = observed.defenceRate + overlay.DR
AA / AD / MD / HR = 각 관측값
최종 능력치 = max(0, 위 값)

AttackPower = AT × (1 - 0.20 × clamp(FT,0,100)/100)
P(hit) = clamp(0.72 + (attacker.AR - defender.DR)/160
               - (arrow ? defender.AA/300 : 0), 0.20, 0.96)

Extra = arrow ? AD : magic ? MD : 0
Damage = max(1, round(AttackPower × 100/(100+DF)
                     × (1 - clamp(Extra,0,70)/100)))
부대 방패 결속 중 Damage = round(Damage × 0.65)
기록되는 피해는 대상의 현재HP를 넘지 않음
```

`hurt`에 공격자가 없는 개발자 피해는 명중검사를 하지 않는다. 일반 근접·화살·마법은 전투별 시드PRNG로 명중을 판정한다. 기존 순수커스텀 양측에는 기존 명중100%와 빼기식 방어를 유지한다. 커스텀 병사의 장비 DF보정도 기존 빼기식에 적용한다.

HR은 근처 적이180단위보다 멀고 공격행동 중이 아닐 때120틱마다 HR×0.35만큼 회복한다. 갱신 틱은 ID로 분산한다. 이미 있던 치료사/전술회복/구출보호 회복은 별도 커스텀 기능이다.

훈련 경험은 기존 처치 경험 시스템을 사용하며 원작 확률성장으로 주장하지 않는다. 명중/피해/효과 RNG도 기존 한 스트림을 사용하므로 교차엔진·서로 다른 렌더러의 네트워크 결정성을 약속하지 않는다. 같은 엔진에서 같은 입력으로 저장 전후 결과가 같음을 테스트한다.

## 5. 역할 매핑

도감의 원문 클래스에서 기본 역할을 제안한다. 이는 **가설/자체 설계**이며 사용자 모집 시 변경할 수 있다. 데이터 레코드의 원문job은 바꾸지 않는다.

- 護士 / 僧侶 / 修道士 / 尼僧 → 치료사
- 法師 / 魔女 / 學者 / 學士 / 靈媒 / 詩人 → 마법사
- 弓 / 狙擊 → 궁수
- 騎 / 王子 / 國王 / 公爵 / 勇士 → 기사
- 나머지 → 보병 역할(임시 표현)

`data/role_mapping_custom.json`에309개 기록별 기본매핑과CUSTOM 상태를 출력한다. 비인간·소환·고유병종의 원작 특수행동까지 구현한 것이 아니다. 렌더링은 다섯 로우폴리 역할이다.

마법사 기본공격은 magic종류의 투사체다. F 비전파동은 사선 안210범위의 가까운 표적을 중심으로70범위에 AT×1.15 피해를 준다. 보병 방패결속, 기사 회전베기, 궁수 일제사격, 치료파동도 커스텀이다.

## 6. 편성·적군 배치

관측 team0x10의13개기록은 초기주력군에 사용한다. 예비6명은 치료사/마법사/궁수/보병 중심의 자체구성이다. 상대는 관측 team0중 HP150~330, AT20~48의 보병/궁수 기본매핑 기록을 순환해 배치한다. 이는 공략을 복원한 적 초기편성이 아니며 team0 자체가 적진영을 뜻한다는 해석도 아니다.

기존 6개노드·5전장,부대정원40,최대5군단,예비120,지원군대기,고용비용,보상/동맹대체사건은 계속커스텀이다. v16의100개지역명만 보고 지도간선을 만들어 넣지 않는다. 미완성 원작조건식으로 엔딩을 자동발동하지 않는다.

## 7. 장비14종

`items_reported.json`의 normalized_modifiers가 비어있지 않고 AT/AR/DF/DR만 포함하는 보고를 선택한다. 불명확한 DE, 미확인특수효과만있는장비는 제외한다. 전투에 사용하는 숫자보정의 근거는 REPORTED이지 원본화면검증이 아니다.

가격 = 60 + 5×양수보정합계. 단일 추가슬롯,모든역할허용,재고120,금화구매,해제반환은커스텀이다. 슬롯장비는 관측원본장비를 교체하는것이 아니라 숫자를 추가한다. 초기item코드는 원작슬롯으로 매핑하지 않으며 보정이 이미 포함됐을 가능성을 UI에 표시한다. 기존장비 추가효과·숨은상성은 활성화하지 않는다.

사망한 병사의 추가장비는 회수하지 않는 자체정책이며 사망기록에 ID를 남긴다. 생존/철수자는 장비를 유지한다. 장착·해제·구매는 전략단계만 가능하며 재고상한으로 저장불능이 되는 교환은 미리 거부한다.

## 8. 출처·가시성·재현

도감은 원시레벨0/이름코드/역할ID/기록위치/20개필드/raw32/해시를 표시한다. 선택병사 출처는 원시와런타임값을 나란히 표시한다. 코드의 label은 한국어 고유이름이라고 주장하지 않는다.

전투는 최근120개의 hit/miss/heal 이벤트를 보관한다. tick,actor,target,관측참조,수치,종류,명중확률을 저장·내보낸다. 이 로그는 자체시뮬레이터의 판정이며 원작플레이의 실측로그가 아니다.

## 9. 검증 범위

191개 소프트웨어검사는 엔진/데이터참조/UI의 구현을 검사한다. 원작정확도를 입증하는 횟수가 아니다. GPU실행은 환경상 미검증이다. 원작판본확정·한국어이름·실제전후세이브 대조가 다음 데이터승격의 필요조건이다. 본 릴리스는 그 완료를 주장하지 않고 실제 게임에서 관측 데이터를 시험할 수 있게 만든 것이다.
