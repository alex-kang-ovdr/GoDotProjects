# 퍼스트 퀸 IV · Field Command v21

v20 실행본에서 **교전 이동, 집중 표적, 병사별 누적 전과**를 추가한 오프라인 웹 게임입니다. 문서·자료실만 제공하는 버전이 아닙니다.

## 실행

`index.html` 또는 별도 배포한 `FirstQueen4_v21.html`을 다운로드해 Chrome/Edge에서 여세요. 두 파일의 내용은 같습니다. 서버·npm·CDN·인터넷 연결은 게임 실행에 필요하지 않습니다. 채팅 링크는 파일 다운로드이며 공개 웹 호스팅 주소가 아닙니다.

WebGL을 먼저 시도하고, 사용할 수 없으면 CPU 3D 호환 모드로 전환합니다. 2D 전술 화면도 있습니다. 실제 사용 중인 렌더러가 화면에 표시됩니다.

## 바로 확인

1. 평원 연습을 선택해 시작하고 P로 일시정지합니다.
2. 주력군을 선택합니다. **T → 전장 클릭**은 교전 이동, **Shift + 클릭**은 같은 모드의 후속 목적지 예약입니다. 현재 목적지 외에 최대 8개입니다.
3. Esc로 입력 모드를 해제하고, **적 병사 우클릭**으로 우선 공격할 표적을 지정하세요. 터치에서는 **집중 표적 X → 적 탭**을 사용합니다.
4. 표적이 제거·철수하거나 지정 당시 위치에서 너무 멀어지면 기존 명령과 예약 경로를 재개합니다. P로 전투를 진행하고 **부대 전과**에서 피해·치유·공성 기여를 확인하세요.
5. F5 저장 / F9 복원으로 경로·표적·집계의 보존을 확인하세요. 복원 직후에는 일시정지입니다.

예제 `examples/attackmove-focus-v21.json`은 이 명령을 적용한 평원 연습 저장입니다. `examples/live-performance-v21.json`은 실제 시뮬레이션 1,100틱을 진행한 상태입니다. 원작 세이브가 아니라 이 프로토타입의 예제입니다.

## 교전 이동

- 일반 `이동`과 별도 명령입니다. 목적지를 향해 이동하다 주변의 사선 안 적을 발견하면 교전하고, 정리되면 기존 경로를 이어갑니다.
- 최초 접촉 때 부대의 교전 기준점을 고정합니다. 표적은 그 주변에서 선택하며, 비슷한 거리의 표적 사이를 빈번히 바꾸지 않도록 유지 여유를 둡니다.
- 교전 기준에서 표적을 모두 잃으면 2초 동안 경로 복귀를 우선합니다. 이 기간의 재탐색 대기는 저장됩니다.
- 부대 전체의 목적지 도착을 확인한 뒤 다음 예약 지점으로 진행합니다. 교전/집중 표적 때문에 멈춘 동안 목적지를 완료한 것으로 처리하지 않습니다.
- 닫힌 성문을 이동 명령만으로 통과하거나 예약을 건너뛰지 않습니다. 사선이 막혀 적을 탐지하지 못하는 공성 상황에서는 G 공성 명령을 사용하세요.
- 진형 이동은 목표 칸과 충돌 회피 방식입니다. 복잡한 병목에서 항상 완벽한 진형과 도착을 보장하지는 않습니다.

## 집중 표적

- 기본 우클릭은 땅에서 이동, 적 병사 위에서는 집중 공격입니다. Shift를 누르거나 명시적인 이동 지정 모드에서는 이동 예약을 우선합니다.
- X는 적 클릭·탭으로 지정하는 입력 모드입니다. 빈 땅을 누르면 적을 선택하라는 안내만 표시합니다.
- 기본은 선택 부대만 적용합니다. `명령을 전군에 적용`을 켜야 아군 전체에 적용합니다. 미도착 지원군도 별도 명령을 보관합니다.
- 집중 표적은 기존 부대 명령을 덮어쓰지 않는 임시 우선순위입니다. 목적지와 예약 지점은 보존합니다.
- 표적이 전사·철수하거나 지정 당시 표적 위치에서 240단위 넘게 벗어나면 해제합니다. 취소 버튼으로도 기존 명령에 복귀합니다.
- 부대 후퇴 중에는 집중 공격을 거절합니다. 개별 철수와 부상병 자동 철수는 집중 공격보다 우선하며, 치료사는 아군 지원을 유지합니다. 직접 조작 중인 병사까지 강제로 움직이지 않습니다.
- 표적 변경은 아직 타격하지 않은 일반 공격 준비를 취소하지만, 이미 사용한 공격 대기시간을 초기화하지 않습니다. 이미 발사된 투사체는 되돌리지 않습니다.
- 원래 명령이 자유 공격이면 집중 해제 후에도 일반 공격 AI가 적을 추격할 수 있습니다. 해제 자체가 부대 후퇴 명령은 아닙니다.

## 병사별 누적 전과

`부대 전과`와 전투 종료 결과표에서 아군 병사별로 확인합니다.

| 항목 | 집계 |
|---|---|
| 피해 | 실제로 감소시킨 HP. 과잉 피해 제외 |
| 받은 피해 | 실제 HP 감소량 |
| 치유 | 시전자가 회복한 유효 HP. 초과 회복 제외 |
| 성문 | 실제로 감소시킨 성문 내구도 |
| 처치 | 치명 피해를 낸 공격자에게 기록 |
| 명중 / 시도 | 병사 대상 공격 판정. 성문 공격과 치유는 별도 |
| 상태 | 생존 / 전사 / 철수 |

최근120개 판정 로그와 별개로 전체 집계가 계속 누적됩니다. 자동 자연 회복은 특정 치료사에게 가산하지 않습니다. 피해·치유·공성·처치·받은 피해·병사 번호로 정렬하고 JSON으로 내보낼 수 있습니다.

전투 중 저장에는 병사별 집계를 포함합니다. 전투가 끝난 뒤에는 결과창에서 확인하고 파일로 내보낼 수 있지만, 결과창 자체가 캠페인의 영구 통계 이력으로 저장되지는 않습니다. 연습 결과도 통계를 보지만 캠페인 성장·사망에 반영하지 않습니다.

## 주요 조작

| 입력 | 기능 |
|---|---|
| WASD / Space | 카메라 기준 직접 이동 / 기본 공격 |
| 클릭 / Q·E / Tab | 병사 선택 / 병사 변경 / 지휘 부대 변경 |
| 땅 우클릭 | 일반 이동 |
| 적 우클릭 | 지정 표적 우선 공격 |
| T → 클릭/탭 | 교전 이동 목적지 지정 모드 |
| X → 적 클릭/탭 | 집중 표적 지정 모드 |
| Shift + 목적지 클릭 | 현재 입력 모드와 같은 종류의 후속 이동 예약 |
| Esc | 목적지·표적 입력 모드 취소 |
| C / V | 위험 병사 선택 / 개별 철수·취소 |
| 1·2·3·4 / G | 공격·집결·방어·부대 후퇴 / 공성 |
| F / H | 역할별 기술 / 전술 회복 |
| P / F5 / F9 | 일시정지 / 빠른 저장 / 복원 |
| 드래그 / 휠 | 카메라 회전 / 줌 |
| 미니맵 | 카메라 이동 또는 활성 목적지 명령 |

열린 대화창과 글 입력란에서는 게임 단축키를 가로채지 않습니다. 전술 명령은 일시정지 중에도 지정할 수 있습니다.

## 데이터와 원작의 경계

v20의 관측 기록309개, 장비 숫자 보정14종, 역할 매핑과 데이터 지문을 그대로 보존했습니다. `tests/provenance-v21.json`에서 파일별 SHA-256 일치를 확인할 수 있습니다. 이번 업데이트에 새 원작 수치·이름·사건을 임의로 추가하지 않았습니다.

이 게임은 원작 완전 복원판이 아닙니다. 관측 수치를 적용하지만 HP의 의미, 전투·성장 공식, 역할, 지도, 경제, 교전 이동·표적 추격 범위 등 실행 규칙은 자체 설계입니다. 불명확한 원작 한국어 인물명·초기 상태·장비코드를 인증하지 않습니다.

## 저장 호환

출력 스키마 **21**, 로컬키 `fq4_proto_v21` / `fq4_checkpoint_v21`입니다. 기존 v20 슬롯은 덮어쓰지 않으며 빠른 저장 조회의 대체 입력으로 읽습니다. v20 JSON 가져오기도 지원합니다. v19 및 구형 커스텀 저장의 이행 경로도 유지합니다.

v20의 위치·출처·장비·이동 예약·자동/개별 철수는 보존됩니다. 새 집중 표적과 교전 접촉 상태는 비활성으로 시작합니다. 이전 파일에는 개별 기여도가 없어 **복원 시점부터 새로 집계**하며 이를 화면에 표시합니다. 과거120개 로그로 전체 기여도를 지어내지 않습니다.

v21 저장을 v20 프로그램에서 다시 여는 역호환은 없습니다. 같은 엔진/입력의 저장 전후 연속성을 테스트한 것이지, v20과 미래 전투 결과까지 동일하다는 의미는 아닙니다. 브라우저가 localStorage를 차단하면 탭 메모리 저장으로 전환하며, 중요한 진행은 JSON으로 내보내세요.

## 검증과 한계

최종 소스에서 **엔진217 + 브라우저120 = 337개** 검사를 통과했습니다. 이전 버전 보고서의 숫자를 더한 것이 아니라 기존 검사도 실제 재실행했습니다. 상세 결과는 `TEST_REPORT.md`와 `tests/*results.json`에 있습니다.

현재 검사 환경에서 WebGL 컨텍스트를 생성하지 못했습니다. 화면·좌표·조작 검증은 CPU 3D 및2D로 수행했고, GPU 하드웨어와 Android/iOS 실기기 성능은 미검증입니다. file:// 탐색도 관리 정책으로 차단되어 동일 HTML을 Chromium set_content로 주입했습니다. 실제 파일 입력·JSON 다운로드와 Chromium 터치 이벤트는 검사했지만 휴대전화 실기기 테스트라는 뜻은 아닙니다.

## 개발

```text
python build.py
node tests/engine.test.cjs --report
node tests/integration.test.cjs
node tests/tactics.test.cjs
node tests/command.test.cjs
python tests/browser.test.py
python tests/browser.integration.py
python tests/browser.tactics.py
python tests/browser.command.py
node tools/make_v21_examples.cjs
```

게임 실행 자체에는 필요 없으며, 브라우저 검사를 재실행할 때만 Playwright와 Chromium이 필요합니다. `CHROMIUM_PATH`로 실행 경로를 지정할 수 있습니다.
