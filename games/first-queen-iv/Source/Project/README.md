# 퍼스트 퀸 IV · Field Command v22

**복원 자료를 실제 전술 선택으로 연결한 오프라인 게임 업데이트입니다.** v21의 교전 이동·집중 공격·병사별 전과에 **전장 휴식, 피로 효과 표시, 방어전 공수 배치 수정**을 더했습니다.

## 실행과 빠른 체험

`index.html` 또는 별도 배포한 `FirstQueen4_v22.html`을 내려받아 데스크톱 Chrome/Edge에서 여세요. 두 파일은 동일한 내용입니다. 게임 실행에는 서버, npm, CDN, 인터넷 연결이 필요하지 않습니다. 다운로드 링크는 공개 게임 호스팅 주소가 아닙니다.

1. 세계맵에서 **휴식 연습**을 누릅니다.
2. 성채 연습이 일시정지 상태로 열립니다. 아군 주력만 피로 70, 최대 HP에서 70 감소한 자체 훈련 상태입니다.
3. **P**로 진행합니다. 병사들이 실제 이동으로 집결하고, 안전하게 정지한 뒤 3초가 지나면 회복합니다.
4. 선택 병사의 **피로 게이지 / 현재 AT / 이동 % / 공격 간격 % / HR / 휴식 상태**를 확인하세요.
5. **1 공격**이나 **T 교전 이동**으로 다시 전진합니다. 전장 휴식은 이전 이동 경로를 취소하는 새 부대 명령입니다.
6. **F5 저장 / F9 불러오기**로 전투 상태를 이어갈 수 있습니다. 복원 직후에는 일시정지입니다.

휴식 연습은 원작 초기 상황을 재현한 것이 아니라 새 규칙을 확인하는 훈련입니다. 캠페인 병력·원본 관측 기록은 바뀌지 않으며 연습 손실과 성장도 캠페인에 반영되지 않습니다.

## 휴식과 회복 규칙

모든 시간은 **게임 시간** 기준입니다. P 일시정지에서는 누적되지 않고 배속을 변경하면 실제 기다리는 시간이 달라집니다. 다음 수치와 조건은 **자체 설계**이며 원작 공식을 복원했다고 주장하지 않습니다.

- `R` 또는 **전술 휴식**은 기본적으로 선택 부대에 적용됩니다. `명령을 전군에 적용`을 켜면 아군 부대 전체에 적용합니다.
- 휴식은 현재 중심에 진형을 잡습니다. 이동 예약과 집중 표적을 해제하고, 미완료 공격 준비를 취소합니다. 이미 소모한 공격 대기시간은 유지합니다.
- 안전 정지를 180틱, 즉 3초 유지해야 회복합니다. 살아 있고 전장에 남은 병사만 대상입니다.
- 이동·공격/치료 행동·직접 조작·개별/부대 철수·집중 표적 수행 중에는 자연회복하지 않습니다.
- 적이 180거리 이내에 있거나 최근 180틱 동안 실제 피해를 받았으면 안전 시간이 누적되지 않습니다. 벽 너머 적도 거리 조건에 포함합니다.
- 피해 직후에는 3초의 위협 유지 뒤 안전 정지 3초가 필요하므로 회복 시작까지 약 6초 이상이 걸릴 수 있습니다. 추가 이동이나 위협이 있으면 더 늦어집니다.
- 휴식 중에도 적을 추격하지 않고 사거리 안에서 공격합니다. 치료사는 사선·사거리 안의 부상 아군을 치료하며, 먼 환자를 쫓지 않습니다. 해당 행동 중에는 그 병사의 자연회복이 멈춥니다.

| 조건 | 피로 FT 감소 | 관측 병사의 자연 HP 회복 |
|---|---:|---:|
| 일반 안전 정지 | 초당 0.1 | 2초 주기마다 HR × 0.35 |
| 휴식 명령 + 안전 정지 | 초당 4 | 2초 주기마다 HR × 0.7 |
| 이동·교전·직접 조작·철수·위협 | 없음 | 없음 |

HP 회복은 병사 ID별로 분산된 120틱 주기에서 적용되므로 회복 가능 상태가 된 바로 그 틱에 HP가 오르지 않을 수 있습니다. 최대 HP를 넘지 않습니다. 원시 HR이 없는 기존 커스텀 병사에게 관측 HR이나 추가 HP 자연회복을 부여하지 않습니다. 기존 치료사·전술 회복 스킬은 별도 행동입니다. 기존 구출 보호 회복도 안전 조건을 만족하고 보호 시간이 남아 있을 때만 적용됩니다.

### 피로가 전투에 주는 영향

기존 공식은 유지하고 화면에서 확인할 수 있게 했습니다.

| 항목 | 현재 계산 |
|---|---|
| 관측 병사 적용 AT | 능력치 AT × (1 − 0.2 × FT / 100) |
| 기본 이동 속도 | 병종 속도 × (1 − 0.2 × FT / 100) |
| 공격 대기 간격 | 병종 기본 간격 × (1 + FT / 230), 틱 단위 반올림 |

이동 표시는 피로로 인한 기본 배율입니다. 직접 조작·돌격·철수 등 행동별 이동 배율은 별도로 적용됩니다. 공격 간격 135%는 대기시간이 기본의 1.35배라는 뜻입니다. 기존 커스텀 병사에는 피로에 따른 AT 감소를 새로 추가하지 않았습니다.

예를 들어 FT80, 능력치 AT35인 관측 병사는 적용 AT29.4, 이동84%, 공격 간격 약135%가 표시됩니다.

## 방어전과 성문

새로 시작하는 실제 아군 거점 방어전에서는 지형을 좌우 대칭해 아군이 성문 안쪽 왼편, 적이 바깥 오른편에서 시작합니다. 강변의 두 다리와 충돌 지형, 성채 깃발도 수비 방향에 맞춥니다.

수비 진영은 자기 성문에 일반 공격·공성 피해를 줄 수 없습니다. 아군이 수비 중일 때 공성 명령은 거절됩니다. 적 공격군은 문을 공격하고 파괴 뒤 전투를 계속합니다. 개발자 옵션의 성문 개폐는 기존 디버그 기능입니다.

**기존 v21 이하의 진행 중 전투**는 좌표·지형을 바꾸지 않고 이어받습니다. 이전 배치의 수비 진영을 유지하므로 새로운 방어 배치를 보려면 v22에서 새 전투를 시작하거나 새 예제를 여세요.

## 유지한 플레이 기능

- 관측 기록 기반 병력과 장비, 병사별 원시값·런타임 비교
- 교전 이동 T, Shift 예약 최대 8곳, 집중 표적 X
- 부대별 진형·지원군, 위험 병사 C와 개별 철수 V
- 실제 유효 피해·치유·성문 피해·처치의 병사별 누적 전과
- 지형 충돌·경로 탐색, 성문 공성, 원래 군단으로 생존자 귀속
- 전략 맵, 편성·모집·장비, 거점 보상, 전투 중 JSON 저장
- WebGL 3D, 사용할 수 없을 때 CPU 3D, 2D 전술 화면

## 원본 자료와 실행 규칙의 구분

v21의 **관측 기록 309개, 장비 숫자 보정 14종**을 유지했습니다. `data/*`와 `src/source-data.js` 총 9개 파일을 원본 v21과 바이트 해시로 비교했습니다. 결과는 `tests/provenance-v22.json`에 있습니다.

관측 수치의 실행 반영을 개선한 버전이며 새 원작 데이터 복구를 수행한 버전은 아닙니다. HP를 최대체력으로 보는 해석, 명중·피해·성장 공식, 전장 지형, 역할 매핑, 편성, 경제, 휴식·위협 조건은 자체 구현입니다. 이름코드와 원시 레벨을 한국어 인물명이나 원작 초기 능력치로 단정하지 않습니다.

## 저장 호환

출력 스키마는 **22**, 빠른 저장과 체크포인트 키는 `fq4_proto_v22` / `fq4_checkpoint_v22`입니다. v21 키는 읽기 대체 입력으로 사용하며 덮어쓰지 않습니다. 구형 JSON의 기존 이행 경로도 유지합니다.

v21 전투의 위치·장비·출처·예약·표적·전과를 보존하고 안전 회복 카운터는 0에서 시작합니다. v13 저장은 현재 화면이 관측 프로필이어도 커스텀 저장으로 일관되게 복원합니다. 저장된 상태의 전투 연속성은 같은 v22 엔진 안에서 검사했으며 v21과 미래 전투 결과까지 동일하다는 의미는 아닙니다. v22 저장을 이전 프로그램에서 여는 역호환은 제공하지 않습니다.

localStorage가 차단되면 탭 메모리 저장으로 전환합니다. 중요한 진행은 JSON으로 내보내세요.

## 검증과 실행 범위

최종 결과는 `TEST_REPORT.md` 및 `tests/*-results.json`에 기록했습니다. 엔진 회귀, 새 회복·방어 규칙, 입력 수학, 실제 UI 스크립트의 이벤트 연결, 실제 CPU 렌더러를 각각 구분해 검사했습니다.

**이번 환경에서는 브라우저 검사를 실행하지 못했습니다.** 로컬 Chromium은 시작 단계의 소켓 권한 제한, 연결 브라우저는 세션 부재, 원격 브라우저는 로컬 파일 URL 정책 때문에 사용할 수 없었습니다. 제한을 우회하지 않았습니다. Node UI 검사는 제한 DOM 모의 환경이며 실제 레이아웃·모바일 터치·브라우저 다운로드 검증이 아닙니다. CPU Canvas 검사는 WebGL GPU 검증이 아닙니다.

`docs/history/v21/`의 보고서와 이미지들은 이전 버전의 역사 자료입니다. 그 브라우저 통과 수를 v22 결과에 합산하지 않았습니다. 다수 병력이 좁은 통로에서 항상 완벽한 진형을 유지하는 것과 모든 기기의 프레임률은 보장하지 않습니다.

## 개발 및 재실행

게임 실행에는 아래 도구가 필요하지 않습니다.

```text
python3 build.py
node tests/engine.test.cjs --report
node tests/integration.test.cjs
node tests/tactics.test.cjs
node tests/command.test.cjs
node tests/recovery.test.cjs
node tests/input.test.cjs
node tests/ui.test.cjs
node tests/render.test.cjs
node tools/make_v22_examples.cjs
```

`render.test.cjs`만 선택 의존성 `@napi-rs/canvas`를 사용합니다. UI 이벤트 모의 검사는 추가 패키지를 요구하지 않습니다. `tests/browser*.py`는 Playwright/Chromium이 설치된 허용 환경에서 실제 화면·입력을 재검사하기 위한 스크립트이며 이번 환경에서는 미실행입니다. `CHROMIUM_PATH`로 경로를 지정할 수 있습니다.
