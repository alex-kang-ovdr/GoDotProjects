## 검사 수준과 해석

**엔진**: 실제 JavaScript 게임 엔진을 실행한다. 전투 틱, 명중/피해/치유, 성문, 이동과 경로 예약, 원래 명부 귀속, 구버전 이행, JSON 왕복 등을 검사한다. 통제된 배치가 포함되며 모든 검사가 자연 캠페인 전체를 진행했다는 뜻은 아니다.

**입력 수학**: 실제 renderer의 movement/project/ground를 호출한다. 2D 및 3D 6개 yaw × 3개 pitch × 3개 zoom에서 화면 방향을 확인한다. 이는 실제 브라우저 키보드나 터치 장치 검사가 아니다.

**UI 이벤트 통합**: 실제 layout.html과 source-data/engine/renderer/ui 스크립트를 Node VM에 로드한다. 필요한 일부 DOM·이벤트·canvas는 tests/ui-fixture.cjs에서 모의한다. R, T, Shift 예약, 방어/선택 변경, 입력란·대화창 단축키 보호, 저장 키, 회복 상태 표시를 실행한다. CSS 레이아웃과 브라우저 자체 API의 완전한 대체물이 아니다.

**CPU 렌더러**: 실제 renderer.js의 3D 장면 생성·소프트웨어 면 렌더링·2D/HUD를 @napi-rs/canvas에서 실행한다. 3D 공격/방어 지형의 강 다리 정렬, 회복 중 표시, 상세/간소화 렌더링, 렌더링의 게임 상태 불변을 검사했다. tests/software-renders/*.png는 이 실행에서 생성했다. 브라우저 캡처나 GPU 프레임이 아니다. CJK 글꼴을 네이티브 테스트 환경에 등록해 이미지를 확인했다.

## 주요 확인 사례

- 179틱까지 회복 없음 → 180틱에서 회복 가능 상태. FT4/초와 관측 HR 회복 적용.
- 이동, 직접 조작, 개별 철수, 집중 표적, 행동 진행, 180거리 위협 중 자연회복 차단.
- 실제 피격 후 최근 피해 위협과 안전 대기 재시작. 회피로 가짜 피해 시각을 만들지 않음.
- 휴식 중 추격 없이 사거리 내 자위 공격, 치료사는 사선 안 가까운 환자만 치료.
- 휴식 시작이 기존 큐·집중을 해제하되 공격 대기시간을 초기화하지 않음.
- 회복 중 저장/복원 후 동일 입력480틱의 전체 전투 상태 일치.
- 회복 카운터·피해 시각·수비 진영의 손상된 저장 거절과 현재 상태 보존.
- 실제 v21 예제의 출처·명령·전과·기존 지형 유지. v13 이행의 현재 프로필 독립성.
- 신규 아군 방어전의 성문 안쪽 배치, 자기 성문 타격 차단, 강변 다리/깃발의 수비 방향.
- 관측 캠페인의 주둔군 고갈 후에도14명의 연습 적군 생성, nextId/캠페인/관측 불변.
- 새 휴식 연습 버튼의 FT70/부상은 전투 런타임에만 적용. 초기 좌표, 출전 명부, 캠페인, 원본 데이터 유지.
- FT80의 관측 AT35 → 적용 AT29.4, 이동84%, 공격 간격 약135% 표시.
- T 또는 X 뒤 방어/R/부대 선택이 남아 있던 지정 모드를 해제. Shift 이동 예약은 유지.
- v22 저장·v21 빠른 저장/체크포인트 대체 읽기, 복원 후 일시정지.

## 이번 환경에서 실행하지 못한 항목

- 로컬 Chromium은 페이지를 열기 전에 ProcessSingleton의 socket 권한 제한으로 종료됐다.
- 연결 브라우저 확장은 현재 세션이 제공되지 않았다.
- 원격 브라우저는 file:// 프로토콜을 정책으로 거절했다. 해당 제한을 우회하지 않았다.
- 따라서 실제 브라우저 렌더링, 반응형 CSS, 브라우저 파일 입력/다운로드, localStorage의 file:// 차이, 실기기 터치, WebGL GPU, 프레임률은 이번 결과에 포함하지 않았다.
- 브라우저의 pageerror/console/network 0건 같은 결과도 이번 실행 결과로 주장하지 않는다.

상세 차단 근거는 tests/browser-validation-status-v22.json에 있다. 브라우저 검사 스크립트의 출력 기대값은22로 갱신했지만 재실행 통과라고 표시하지 않는다. docs/history/v21에는 이전 보고서와 이미지가 별도로 보존된다.
