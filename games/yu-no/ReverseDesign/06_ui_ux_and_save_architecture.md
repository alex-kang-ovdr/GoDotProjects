## 2. A.D.M.S. 병렬 분기 맵 UI 명세 `[확인]` `[재구성안]`
1. **줌·패닝 트리 캔버스**: 좌→우(시간 흐름) 또는 상→하(분기 전개) 방향의 계층형 DAG/트리 렌더링. 미탐색 분기는 안개(미개방 점선) 처리한다. `[재구성안]`
2. **시각 범례 (5종 아이콘)**:
   - 🔵 **보옥 배치 노드**: 현재 보옥 세이브가 꽂혀 있어 원클릭 점프 가능.
   - ✨ **광점(Shining Point)**: 미수집 보옥이 숨겨진 구역 표시(수집 완료 시 체크 전환).
   - 🌀 **소용돌이(Whirlpool)**: 배드엔드·순서 함정 종단 표시.
   - 🔒 **관문(Lock Gate)**: 마우스 호버 시 미충족 조건 힌트 표시 (예: "필요 계승 아이템: 블루 카드 — 미보유" `[재구성안]`).
   - ⭐ **루트 완료 배지**: 히로인 엔딩 달성 노드 표시.
3. **점프 확인 다이얼로그 (역계승 프리뷰)** `[재구성안]`:
   - 보옥 로드 실행 직전, **"회수될 보옥(+1)", "복원될 과거 시간대", "그대로 들고 갈 현재 소지품 목록"**을 3열 프리뷰로 보여 주어 초보 플레이어가 비대칭 역계승 규칙을 직관적으로 이해하도록 돕는다.

## 3. 이중 세이브 아키텍처 (System Save vs Jewel Save) `[확인]` `[재구성안]`
『YU-NO』 구현에서 가장 흔한 실수는 **OS/디스크 세이브(System Save)**와 **인게임 보옥 세이브(Jewel Save)**를 혼동하는 것이다. 두 계층은 역할이 완전히 다르다.

| 구분 | 시스템 세이브 (System / Slot Save) | 보옥 세이브 (A.D.M.S. Jewel Save) |
|---|---|---|
| **성격** | 플레이 세션 전체를 디스크/로컬스토리지에 저장·복원하는 메타 세이브 | 세계관 내부 장치(리플렉터)로 시간축 앵커를 심는 인게임 메커니즘 |
| **저장 범위** | `GlobalState` + `CurrentLocalState` + `PlacedJewelSnapshots` 전체 | 해당 노드 시점의 `LocalStateSnapshot` 1건만 저장 |
| **로드 시 글로벌 상태** | 세이브 당시의 글로벌 상태로 **완전 롤백** | **롤백하지 않고 현재 글로벌 상태를 유지(역계승)** `[확인]` |
| **자원 제한** | 슬롯 수(예: 20슬롯 + 퀵세이브)만 존재, 인게임 자원 미소모 | 보유 중인 보옥 1개 소비, 점프 시 보옥 반환 `[확인]` |
| **이세계편 사용 여부** | 사용 가능 (단일 시간축 저장) | **비활성화** (A.D.M.S. 봉인) `[확인]` |

### 3.1 직렬화 버전 정책 (`save_schema_version`) `[재구성안]`
- PlayHub 저장 파일은 `localStorage` 및 클라우드 동기화 규격을 고려해 단일 JSON 문서(`yuno_save_v1`)로 직렬화한다.
- 버전 모드(`"pc98_8_jewels"` | `"ss_remake_10_jewels"`)를 세이브 헤더에 영구 기록하여, 중도 난이도 전환 시 보옥 수량 불변식이 깨지지 않도록 차단한다.
