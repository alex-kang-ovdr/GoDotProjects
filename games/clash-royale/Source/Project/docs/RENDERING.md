# 렌더링 기술 명세

이 문서는 Crownfall의 Canvas 2D·WebGL 3D 표시 계층과 입력 좌표 계약을 설명한다. 렌더링 방식은 같은 전투를 보는 설정이다. 모드 전환은 `Game`을 다시 만들거나 전투 시간을 진행시키지 않으며, 카드 비용·타깃·피해·승패 계산은 엔진이 담당한다.

## 1. 구성과 책임

| 구성 | 역할 |
| --- | --- |
| [`ArenaView`](../dist/js/view.js) | 현재 렌더러 선택, 방향 동기화, 3D 지연 생성, 오류 시 2D 복귀 |
| [`ArenaRenderer`](../dist/js/renderer.js) | 기존 Canvas 2D 전장과 개체·표시 그리기 |
| [`ArenaRenderer3D`](../dist/js/renderer3d.js) | WebGL1 지형·모델과 투명 Canvas 2D HUD, 3D 좌표·모델 선택 계산 |
| [`app.js`](../dist/js/app.js) | 모드 설정과 저장, 입력 전달, 애니메이션 루프, 현재 게임 소유 |
| [`engine.js`](../dist/js/engine.js) | 전투 상태와 합법적인 배치 계획 제공 |

`#arena`는 두 모드가 공유하는 Canvas 2D 및 포인터·키보드 입력 표면이다. 3D 모드에서는 그 뒤의 `#arena-3d`가 입체 전장을 그린다. WebGL 캔버스는 `pointer-events: none`과 `aria-hidden`으로 입력과 접근성 표면을 중복하지 않는다. 2D 모드에서는 숨긴다.

### 반드시 지킬 alpha 계약

`ArenaView`는 **어떤 렌더러보다 먼저** 아래 호출을 수행한다.

```js
canvas.getContext('2d', { alpha: true });
```

Canvas 2D 컨텍스트의 alpha 설정은 최초 생성 요청에서 정해진다. 기존 2D 렌더러의 이후 `alpha: false` 요청으로 이미 생성된 설정을 바꿀 수 없다. 최초 컨텍스트가 불투명하면 3D HUD의 `clearRect()`가 뒤쪽 WebGL 전장을 드러내지 못한다. 따라서 새 3D 렌더러는 확인 가능한 HUD 컨텍스트의 `alpha`가 `false`일 때 생성 오류를 발생시킨다.

2D 렌더러는 전장 배경을 채워 그리므로 투명 컨텍스트를 공유해도 기존 배경 표시를 유지한다. 3D HUD는 매 프레임 변환·알파·합성 방식·선 스타일을 초기화하고 투명하게 지운 후 표시를 그린다.

## 2. 표시 모드와 실제 3D 구현

| 항목 | 2D | 3D |
| --- | --- | --- |
| 전장 | Canvas 2D 지형과 스프라이트 | 높이가 있는 저폴리 지형·모델을 WebGL1 삼각형으로 제출 |
| 광원·가림 | 2D 색과 그리기 순서 | 면 법선에 의한 방향광·환경광, 깊이 버퍼 |
| 카메라 | 정면 탑뷰 | 고도각 58도의 직교 카메라 |
| HP·이름·피해·타이머 | Canvas 2D | 투명 Canvas 2D HUD에 정방향 표시 |
| 배치·사거리·훈련·선택 | 전투 좌표 기반 표시 | 같은 카메라로 지면에 투영한 표시와 3D 배치 모델 |

3D 정점은 `[worldX - 240, altitude, worldY - 320]` 좌표를 사용한다. 정점 하나는 위치 3개, 평면 법선 3개, 색상 RGBA 4개의 총 10개 float로 구성된다. 셰이더의 `u_viewProjection`이 방향·카메라·화면 여백을 반영한다. 텍스처나 외부 모델 파일을 다운로드하지 않는다.

지형은 초원·황혼·설원 테마를 지원하며 강·다리·성벽·깃발을 입체 메시로 그린다. 타워와 파괴 잔해, 지상·비행 병력, 방어 건물, 투사체, 주문 효과도 높이를 가진 모델이다. 불투명 메시 이후 반투명 메시를 그리며, 반투명 단계에는 깊이 기록을 끈다. 선택·사거리 같은 HUD 표시는 가독성을 위해 모델 가림과 별도로 보인다.

밀집보병은 `cardId: 'phalanx'` 모델에 투구·팀 색 방패·창을 사용한다. `formationProtected`는 전면 방패와 보호 표시, `formationState`·`chargeRemaining`은 돌격 자세·흔적과 상태 라벨에 사용한다. 렌더러가 방어 효과나 돌격 가능 여부를 결정하지 않는다. 해당 선택 필드가 없어도 기본 모델을 그릴 수 있다.

## 3. 진영 방향과 좌표

엔진 월드는 항상 **480 × 640**이며, 적 진영은 낮은 `y`, 아군 진영은 높은 `y`에 있다. 화면 방향을 바꾸어도 엔진의 타워·강·다리·병력 좌표는 그대로다.

| 화면 | 표시 크기 | 진영 | 직교 투영 이전의 평면 방향 변환 |
| --- | --- | --- | --- |
| 세로 | 480 × 640 | 적 위 / 아군 아래 | `(u, v) = (x, y)` |
| 가로 | 640 × 480 | **적 왼쪽 / 아군 오른쪽** | `(u, v) = (y, 480 - x)` |

2D는 위 평면 좌표를 직접 사용한다. 3D는 같은 방향 변환에 카메라 기울기와 모델 높이를 반영한다. 개념적으로 지면의 세로 길이는 `sin(58°)` 비율로 보이고, 높이가 있는 점은 화면 위쪽으로 이동한다. 실제 GPU와 HUD는 동일한 카메라 행렬을 사용하므로 이 개념식을 별도로 입력 처리에 복제하지 않는다.

`worldToScreen(x, y)`는 **캔버스 내부 CSS 픽셀 좌표**를 반환한다. `screenToWorld(clientX, clientY)`는 `PointerEvent.clientX/Y`와 같은 **브라우저 클라이언트 좌표**를 받는다. 두 값을 왕복할 때는 캔버스의 `rect.left/top`을 더하거나 빼야 한다.

렌더러는 현재 `getBoundingClientRect()`를 읽어 `ResizeObserver` 알림 이전의 레이아웃 변화도 반영한다. 화면 비율이 다르면 전장을 가운데 맞추고 여백을 남긴다. DPR은 실제 그리기 버퍼 해상도에만 적용하며 1~3 범위로 제한한다. 입력에 DPR을 다시 곱하지 않는다.

## 4. 배치와 대상 선택은 서로 다른 검사

### 카드 배치: 지면 광선 교차

3D의 `screenToWorld()`는 클라이언트 좌표를 화면 정규 좌표로 바꾸고, 역 카메라 행렬로 가까운 점과 먼 점을 얻는다. 두 점을 잇는 광선과 **높이 0인 엔진 지면 평면**의 교점을 전투 좌표로 반환한다. 시각적인 다리 높이나 모델 머리를 배치 지면으로 사용하지 않는다.

여백이나 경기장 밖 입력을 경기장 가장자리로 강제 보정하지 않는다. 계산된 바깥 좌표의 배치 가능 여부도 엔진이 판정한다. 표시 단계는 `game.previewDeployment('player', cardId, x, y)` 결과의 `ok`, `positions`, `affectedTargets`를 읽는다.

- 여러 병력의 고스트는 엔진이 반환한 개별 생성 위치를 사용한다.
- 주문 대상 강조와 예상 피해는 반환된 현재 대상 정보를 사용한다.
- 독 피해 라벨의 `/초`는 현재 위치 기준 틱 피해이며, 전체 지속 피해를 보장하는 표시가 아니다.
- 오래된 `pointer.valid`가 실제 엔진의 합법성 판정을 덮어쓰지 않는다.
- 훈련 목표 표시는 안내이며 불법 배치를 허가하지 않는다.

### 검사 도구: 보이는 모델 표면 선택

```js
renderer.pickEntity(clientX, clientY, entities); // 원본 entity 또는 null
```

타워 머리나 비행 병력을 클릭한 점을 지면으로 투영하면 개체의 발밑 좌표에서 벗어날 수 있다. 따라서 3D 대상 검사는 배치 좌표를 이용한 반경 검사 대신 실제 모델을 사용한다.

먼저 화면 경계와 대략적인 투영 범위로 후보를 줄인 뒤, 모델의 삼각형을 화면에 투영해 클릭 점이 포함되는지 검사한다. 포함된 삼각형의 깊이를 보간하여 가장 앞쪽 개체를 반환한다. 겹친 대상은 입력 배열 순서로 결정되지 않는다. 마지막으로 그린 프레임의 시간과 움직임 감소 설정을 사용해 비행 높이도 맞춘다.

살아 있는 타워·병력만 선택한다. 캔버스 밖, 여백, 빈 공간, 사망·파괴 대상은 `null`이다. 반환값은 전달받은 **원본 엔티티 참조**이므로 호출자는 검사 결과를 읽는 용도로 사용해야 한다. 선택이 게임 상태를 변경하지는 않는다.

`ArenaView.pickEntity()`는 3D에서 위 검사를 전달한다. 2D 모드의 기존 대상 검사는 애플리케이션이 유지하며, facade의 2D `pickEntity()`는 `null`을 반환한다.

## 5. 공개 인터페이스와 전환

```js
const view = new ArenaView(hudCanvas, glCanvas, { onFallback });
view.setMode('3d');                   // 실제 적용된 '2d' 또는 '3d' 반환
view.setOrientation('landscape');
view.draw(game, options);
view.worldToScreen(x, y);
view.screenToWorld(clientX, clientY);
view.pickEntity(clientX, clientY, entities);
```

3D를 직접 생성할 때는 `new ArenaRenderer3D(hudCanvas, glCanvas, { onContextLost })`를 사용한다. 기존 렌더러와 동일한 `draw`, `resize`, `setOrientation`, 좌표 변환과 `destroy`를 제공한다. 카메라 보조 함수 `createCamera`, `projectGround`, `unprojectGround`는 HUD·선택 계산과 수학 검증에 사용된다.

공통 `draw()` 옵션은 `selectedCard`, `pointer`, `showRanges`, `reducedMotion`, `hoveredEntityId`, `selectedEntityId`, `trainingTarget`, `arenaTheme`이다. 렌더러가 애니메이션 루프를 시작하거나 게임 시간을 소유하지 않는다. 장식 동작도 게임 시간과 안정적인 ID 기반 값으로 계산한다.

`ArenaView`는 2D로 시작하고, 처음 3D를 선택할 때 WebGL 렌더러를 생성한다. 정상적인 2D 복귀에서는 3D 인스턴스를 보관해 다음 전환에 재사용한다. 방향은 두 렌더러에 동기화한다. 애플리케이션의 모드 전환은 진행 중인 카드 조준을 해제하고 같은 게임을 계속 표시한다.

`renderMode`와 `orientation`은 애플리케이션의 로컬 설정으로 저장한다. 렌더링 선호를 전투 명령·난수 상태·스냅샷·리플레이 규칙에 추가하지 않는다. 따라서 화면 전환 자체는 전투 결정성이나 결과를 바꾸지 않는다.

## 6. 미지원·오류·컨텍스트 손실

| 상황 | 동작 |
| --- | --- |
| WebGL 컨텍스트를 얻지 못함 | 생성 오류 → facade가 2D 유지, 안내 콜백 |
| 셰이더·프로그램·버퍼 생성 또는 초기 크기 설정 실패 | 부분 생성 자원 정리 → 생성 오류 → 2D 복귀 |
| 3D `draw()` 오류 | 3D 정리·숨김 → 같은 게임을 그 프레임에 2D로 다시 그림 |
| `webglcontextlost` | 기본 이벤트 처리 중단, 손실 상태 표시·콜백 → facade가 2D로 복귀 |

3D 렌더러를 단독 사용하는 경우에는 손실 상태의 `draw()`가 오류를 발생시킨다. 인스턴스를 유지한 채 복원 이벤트를 받으면 셰이더·버퍼를 다시 만든다. 앱의 facade 경로는 손실 시 해당 인스턴스를 `destroy()`하고 참조를 비우므로, 자동으로 같은 인스턴스의 3D 화면으로 돌아가지는 않는다. 이후 사용자가 3D를 다시 선택하면 생성을 시도할 수 있다.

`destroy()`는 해당 렌더러의 observer·resize/context 이벤트·GL 버퍼·셰이더·프로그램·지형 캐시를 정리한다. 공유 HUD 캔버스나 게임 객체를 삭제하지 않는다. 화면 전체를 제거하는 별도 호스트가 있다면 보관 중인 각 렌더러에도 정리를 호출해야 한다.

앱은 fallback 안내를 표시하고 실제 적용 모드를 `2d`로 저장한다. 이 과정에서 전투를 새로 시작하거나 결과를 생성하지 않는다.

## 7. 오프라인 번들

[`scripts/build-offline.mjs`](../scripts/build-offline.mjs)는 2D·3D 렌더러와 facade를 게임 모듈들과 함께 `dist/crownfall-offline.html` 안에 포함한다. CSS·아이콘·셰이더·모델 생성 코드도 파일 안에서 제공하므로 3D용 CDN, 모델 서버, 외부 패키지가 필요 없다.

번들은 알려진 ES 모듈의 import/export 경계를 묶는 프로젝트 전용 스크립트다. 문법 검사와 순수 모듈 연결 검사는 수행하지만, 빌드 과정에서 브라우저 WebGL 컨텍스트를 실행하는 것은 아니다. 오프라인 파일에서도 브라우저의 WebGL 가용성과 동일한 2D fallback 정책을 사용한다.

## 8. 자동화 검증의 의미

현재 [`renderer3d.test.mjs`](../tests/renderer3d.test.mjs)는 **3D 8개와 밀집보병 2D 1개**로 구성된다.

| 3D 검증 | 확인하는 위험 |
| --- | --- |
| 양 방향 카메라와 지면 왕복 | 적·아군 방향 및 역투영 교점 오류 |
| 실제 제출 행렬·viewport와 CSS 좌표 비교 | DPR, 여백, 실시간 크기 변화로 생기는 표시·입력 불일치 |
| 메시·깊이·HUD | 유효한 정점, 실제 높이, 법선·행렬 사용, 깊이 테스트 제출, 정방향 텍스트 |
| 동결된 상태·배치 계획을 사용한 그리기 | 규칙 버전 2·3의 배치 계획과 상태·명령·난수 변경 여부 |
| 높은 모델·비행 병력 선택 | 머리·몸통 선택, 바깥·빈 곳·사망 대상 제외 |
| 겹친 모델 선택 | 배열 순서와 무관한 가까운 표면 선택 |
| 미지원·컴파일·링크 실패 주입 | 명시적인 실패와 부분 생성 자원 정리 |
| 컨텍스트 손실·복원·해제 | 손실 보고, 복원 경로와 자원 정리 |

밀집보병 2D 검증 1개는 구별 가능한 카드 그림, 실제 방어·돌격 필드에 맞는 분대 표시, 다수 병력 미리보기를 다룬다. 이것을 별도의 3D GPU 검증으로 세지 않는다.

[`view.test.mjs`](../tests/view.test.mjs)의 **3개**는 다음 통합 계약을 확인한다.

1. 투명 HUD의 최초 생성, 방향을 유지한 반복 모드 전환, 같은 전투 상태 유지.
2. WebGL 미지원 시 보이는 2D 화면, 한 번의 안내, 게임 불변.

## 9. 지원·성능 범위와 남은 검증

WebGL1 및 Canvas 2D를 사용할 수 있는 브라우저 환경을 대상으로 한다. 3D 가용성은 실제 컨텍스트 생성 결과로 판단한다. 특정 브라우저·운영체제·GPU 조합의 지원을 이 문서나 자동화 결과만으로 보장하지 않는다.

성능을 위해 정적 지형 메시를 세 테마별로 캐시하고, 불투명 지형·동적 불투명·동적 반투명 메시를 최대 세 번의 배치로 제출한다. 모델은 단순한 상자·원기둥·다각형이며, DPR은 최대 3이다. 다만 동적 메시를 CPU에서 매 프레임 만들고, 모델 선택은 범위를 통과한 후보의 삼각형을 검사하므로 개체 수가 증가하면 비용도 증가한다. 현재 수치로 FPS·최대 병력 수·배터리 소모를 보장하지 않는다.

**GL recorder는 실제 GPU나 브라우저가 아니다.** [`webgl-recorder.mjs`](../tests/fixtures/webgl-recorder.mjs)는 호출·정점·행렬·자원 상태를 기록하고 성공·실패·손실을 주입하는 테스트 도구다. 위 검증은 실제 드라이버의 GLSL 컴파일, 래스터화 결과, 글꼴·안티앨리어싱, 투명 효과의 최종 모양, GPU 메모리 사용량과 실시간 프레임 속도를 측정하지 않는다.

이번 구현에서는 브라우저/GPU 실기 QA를 수행하지 않았다. 따라서 자동화 결과는 좌표·상태 격리·렌더링 제출·실패 처리의 근거로 사용하며, 실제 시각 품질과 장치별 성능은 허용된 실행 환경에서 별도로 확인해야 한다.

## 4.4 추가: 진영별 테스트 미리보기

앱은 `deploymentTeam`과 `game.getCard(cardId,deploymentTeam)`을 매 프레임 전달한다. 양 렌더러는 선택 진영의 합법 배치 영역, 상대 타워 파괴에 따른 전진 구역, 주문·무리 미리보기와 고스트 색을 같은 진영으로 계산한다. 전장 카메라는 제어 진영 변경으로 뒤집히지 않는다.

개발자 자유 배치에서는 양쪽 영역을 표시하되 실제 엔진의 자리 탐색과 충돌 판정을 사용한다. 현재 진영의 조절된 주문 반경·병력 수치로 표시하고, 렌더러가 카드 정의나 시뮬레이션 상태를 직접 바꾸지 않는다. 최신 검증 범위는 [RELEASE_NOTES.md](RELEASE_NOTES.md)에 정리한다.
