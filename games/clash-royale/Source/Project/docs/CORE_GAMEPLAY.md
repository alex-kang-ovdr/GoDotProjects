# Crownfall Arena 4.4 — 코어 게임플레이 구현 명세

기준일: 2026-11-16 · 전투 규칙 4 · 저장/리플레이 데이터 형식 2

이 문서는 현재 JavaScript 구현의 계약을 설명합니다. 원작의 최신 수치를 그대로 재현한 사양이 아니라, 원작 역기획을 바탕으로 작성한 독립적인 싱글 플레이 전투 모델입니다. 카드별 정확한 현재 수치는 `dist/js/engine.js`의 `CARDS`가 기준입니다.

## 1. 완료 범위

하나의 게임 루프는 `도전 단계 또는 자유 대전 선택 → 덱 준비 → 카운트다운 → 카드 배치와 자동 전투 → 승패 → 기록·복기·다음 도전`입니다. 실전과 같은 비용 및 피해 규칙을 사용하는 세 훈련, 제한 없는 자원 충전이 가능한 자유 연습, 진행 중 전투의 저장·복원도 포함합니다. 단계 진행과 메달의 상세 계약은 [SINGLE_PLAYER.md](SINGLE_PLAYER.md)를 참고하세요.

## 2. 시간과 승패

렌더 루프는 `requestAnimationFrame`, 실제 시뮬레이션은 `1/60초` 고정 스텝입니다. 한 프레임의 경과를 최대 0.12초로 제한해 긴 정지 후 갑작스러운 대량 진행을 방지합니다. 숨겨진 탭에서는 게임을 멈추고 저장하며, 도움말·덱 등의 모달 전환도 같은 게임일 때만 원래 재생 상태로 돌아갑니다. 외부 설정 서랍은 열었다는 이유만으로 전투를 멈추지 않으며 별도의 일시정지 제어를 제공합니다.

자유 대전과 도전은 3초 준비 카운트다운 뒤에 시작합니다. 준비 중 엔진 tick·자원·AI는 정지하고, 화면 카운트다운만 진행합니다. 카운트다운도 일시정지·모달·화면 숨김을 따르며 남은 시간을 저장합니다. ‘바로 시작’은 이 준비 시간만 생략합니다. 훈련·자유 연습·리플레이는 자체 진행 규칙을 사용합니다.

| 항목 | 규칙 |
|---|---|
| 정규전 | 180초 |
| 연장전 | 최대 120초, 동률일 때 진입 |
| 킹 타워 | 파괴 즉시 상대 3크라운, 경기 종료 |
| 정규전 종료 | 크라운 수가 다르면 높은 진영 승리 |
| 연장전 | 타워 파괴로 크라운 수가 달라지면 즉시 종료 |
| 최종 동률 | 살아 있는 타워 중 최저 절대 HP 비교; 더 높은 쪽 승리 |
| 완전 동률 | 무승부 |
| 같은 틱 양쪽 킹 파괴 | 3:3 무승부 |
| 연장 중 같은 틱 양쪽 타워 파괴 | 여전히 동률이면 계속 진행 |
| 항복 | 해당 진영 패배, 상대 승리; 현재 tick·크라운·피해 유지 |

한 스텝은 상태 효과 시간 감소, 죽음 정리, 지속 영역, 주문, 병력 행동, 몸체 분리, 타워 공격, 투사체, 죽음 정리, 승패 판정 순으로 진행합니다. 모든 가능한 상용 게임의 동시 처리 규칙을 복제한 것은 아니며, 위에 명시한 동시 파괴 상황은 회귀 테스트로 고정합니다.

`game.concede(team)`은 정상 진영이며 아직 종료하지 않은 경기에서만 성공합니다. 실행 중·일시정지·0틱 모두 지원하며 `{ok:true,winner,reason:'concede'}`를 반환합니다. `endAction:{type:'concede',team,tick}`을 기록하고 `phase='finished'`, `running=false`로 전환합니다. 잘못된 진영이나 중복 항복은 상태를 바꾸지 않습니다. 앱은 실제 시작한 일반 대전·도전의 일시정지 화면에서 확인을 받은 뒤 호출합니다.

## 3. 카드와 배치 트랜잭션

엘릭서는 5에서 시작하고 10까지 생성됩니다. 0~120초에는 2.8초당 1, 120~240초에는 2배, 240초부터는 3배입니다. 경계를 가로지르는 스텝은 구간별 시간을 나눠 적분합니다.

배치 요청은 `{team, handIndex, x, y}`입니다. 다음 조건을 모두 확인한 뒤 한 동기 실행 안에서 명령 기록, 비용 차감, 손패 교체, 생성 또는 주문 예약을 처리합니다.

1. 경기 진행 중이며 진영과 슬롯이 올바른가.
2. 좌표가 유한하고 논리 아레나 480×640 안에 있는가.
3. 필요한 자원이 있는가.
4. 병력·건물은 아군 구역 또는 이미 열린 전진 구역인가.
5. 타워와 겹치지 않으며 무리의 모든 개체가 설 공간이 있는가.

실패하면 자원·손패·대기열·명령·개체를 바꾸지 않습니다. 주문은 진영 배치 제한을 받지 않습니다.

규칙 3 이상의 병력 배치 계획은 기본 진형에서 시작해 최대 48 논리 픽셀 반경의 후보를 결정적으로 탐색합니다. 각 몸체의 크기, 벽, 강, 기존 개체와 이미 계획한 개체를 검사합니다. 전진 배치 탐색도 사용자가 선택한 영역 안에 머뭅니다. 같은 초기 상태와 좌표는 같은 계획을 만듭니다.

```js
const preview = game.previewDeployment('player', cardId, x, y);
// preview.ok, reason, positions[], affectedTargets[]
const result = game.playCard('player', slot, x, y);
// result.ok, reason?, cardId?
```

`previewDeployment()`는 상태를 변경하지 않습니다. 주문의 대상 목록은 현재 위치의 검사 결과이며, 타워 피해 감소와 현재 체력을 반영한 1회 피해를 반환합니다. 독은 1틱 기준입니다. 시전까지의 이동을 예언하거나 총 지속 피해를 확정하지 않습니다.

## 4. 이동·타기팅·효과

지상 유닛은 x=120 또는 x=360 다리를 경유하고, 공중 유닛은 강을 직선으로 통과합니다. 고정 구조물 앞에서는 두 경유점을 사용하며, 다리 입구를 구조물이 막으면 다른 다리를 평가합니다. 경계 보정은 몸체 반경을 포함하고 밀치기와 분리에도 적용합니다.

타깃은 생존 여부, 적 진영, 지상/공중/건물 조건을 만족해야 합니다. 보통 병력은 주변 유효 대상을 찾고, 없으면 살아 있는 적 타워로 이동합니다. 거인과 돌격 기수는 건물만 공격합니다. 자기 중심 광역은 목표의 뒤가 아니라 공격자 주변을 판정합니다.

| 효과 | 현재 동작 |
|---|---|
| 배치 지연 | 카드별 시간 이후 행동; 무리 개체는 0.06초씩 순차 준비 |
| 투사체 | 발사 후 이동, 도착 때 피해; 적절한 공중/지상 필터 유지 |
| 화염구 | 지연 후 범위 피해·병력 밀치기; 타워 피해 감소 |
| 감전 | 피해와 0.5초 기절 |
| 얼음 정령 | 자기 위치 광역 피해·1.1초 동결 후 희생 |
| 독 | 8초, 최초 1초 후부터 총 8틱; 안에 있는 적만 피해 |
| 독 감속 | 규칙 3 이상에서는 이동 20% 감소; 공격 주기 유지 |
| 대포 수명 | 35초 동안 자연 체력 감소; 기절 중에도 수명 진행 |
| 킹 활성화 | 직접 피격 또는 자기 프린세스 타워 파괴 |

규칙 3 이상의 병력은 초기 개별 배치 대기 시간을 `deployDuration`으로 보관합니다. 이 값과 `deployRemaining`으로 렌더러가 준비 원형 표시를 그립니다. 기존 저장에 초기 대기 시간이 없어도 복원되며, 렌더러는 남은 초를 표시합니다. 이 표시 메타데이터는 비용이나 행동 대기 시간을 바꾸지 않습니다.

### 4.1. 밀집보병의 분대와 스킬

`phalanx`는 엘릭서 5로 6명을 소환합니다. 개별 체력 340·공격력 65·공격 간격 1.15초·사거리 32·몸체 반경 8을 사용합니다. 3열 × 2행의 분대 앵커와 개별 슬롯을 유지하고, 방진 이동 속도는 24입니다. 실제 정렬되어 보호받는 병사만 받는 피해를 70% 줄이며, 생존 병사 3명 이상 등의 보호 조건을 검사합니다.

규칙 4의 `forming/guard/regroup`은 공격하지 않습니다. `charge`에서만 실제 공격을 수행합니다. 기존 규칙 3의 35% 방어·방진 공격은 과거 저장과 리플레이에서 유지합니다.

`방패 돌격`은 엘릭서 1을 소모하고 5초 동안 대형을 풀어 속도 68의 개별 추적으로 전환합니다. 돌격 중 방진 방어는 해제됩니다. 분대별 쿨다운은 발동 시점부터 14초이며, 종료 후 생존 병사는 다시 모여 대형을 복구합니다. 대형 유지·다리 통과·사상자 슬롯 정리·보호 범위와 피해 적용 순서는 [PHALANX.md](PHALANX.md)의 현재 엔진 계약을 따릅니다.

```js
const abilities = game.getAbilities('player'); // 상태 복사본
const result = game.activateAbility('player', abilities[0].groupId);
// 비용·진영·생성 명령·진행·생존·배치·기절·쿨다운·모드 검증
```

실패한 능력은 비용·명령·타이머를 바꾸지 않습니다. 일시정지와 종료 상태에서는 발동하지 않으며, 분대 타이머는 시뮬레이션 시간으로만 감소합니다. 훈련과 리플레이 관전자 입력은 엔진에서도 차단합니다. 실제 연습 치트의 명시적인 피해·제거는 보호 효과를 우회하여 요청한 HP 조작의 의미를 유지합니다.

## 5. AI 판단

AI는 자기 손패와 자원, 공개 병력·타워만 사용합니다. 세 상대는 거인 중심 전열, 빠른 순환 압박, 방어 후 역공 성향을 가지며 능력치 보정은 없습니다. 밀집보병이 포함된 덱에서는 자기 분대와 공개된 대상의 위치로 돌격 가치를 계산하고, 플레이어와 같은 능력 비용·쿨다운을 적용합니다. 기존 세 상대의 기본 덱은 유지하며 추천 덱에는 네 번째 방패의 진군을 추가합니다.

방어 기여는 적을 실제로 공격할 수 있는 아군만 계산합니다. 타워를 때리는 거인이 있다고 해서 고블린 수비가 충분하다고 판단하지 않습니다. 건물 후보는 여러 레인의 접근을 함께 고려하고, 배치가 타워와 겹치면 대체 좌표를 탐색합니다.

치명적인 킹 위협이 있으면 즉시 처치·기절 가능한 주문을 검토합니다. 상대 킹을 확정 파괴할 수 있으면 승리 행동을 유지하고, 단순한 측면 타워 마무리는 생존 행동보다 낮게 평가합니다. 공격에서는 이미 배치된 아군의 레인별 비용을 비교해 과도한 집중을 줄입니다.

난이도는 생각 주기, 반응 지연, 조준 오차, 선택의 차이입니다. 같은 수비 fixture에서 실제 첫 반응이 쉬움 2.433초, 보통 1.417초, 도전 0.733초였지만, 모든 덱·seed에서 난이도별 승률이 단조 증가함을 뜻하지 않습니다.

## 6. 훈련과 일반 전적의 경계

`TrainingRun`은 같은 `Game`을 사용합니다. `abilityMode: "training"`으로 생성하고, 정해진 시각에 적 카드 슬롯을 찾아 정상 `playCard()`를 호출하며 자원을 추가하지 않습니다. 루프는 `training.step(1/60)`을 호출하고, 별도의 AI는 실행하지 않습니다.

| ID | 관찰하는 사실 | 완료 처리 |
|---|---|---|
| defend | 기수의 targetId가 중앙 대포를 가리켰는지, 기수 제거, 아군 타워 HP | 세 조건을 만족하면 성공 |
| spell | 해당 화살비의 실제 적중·처치 기록에 지정 미니언 3기 모두 포함, 타워 HP | 다른 병력·주문의 처치는 인정하지 않음 |
| push | 살아 있는 거인 뒤에 궁수 배치, 적 레인 A 타워 실제 HP 감소 | 925 이상 피해와 지원 배치 모두 필요 |

훈련 완료는 게임을 일시정지하고 전용 결과를 보여줍니다. 일반 `finishBattle()`에 진입하지 않아 대전 수·승수·최근 대전 리플레이를 바꾸지 않습니다. 훈련 달성 목록은 브라우저 설정에 남깁니다. 자유 연습도 일반 전적과 리플레이에서 제외합니다.

`game.getSpellResolutions()`는 가장 최근 `update()`에서 발동한 주문의 복사본을 반환합니다. 항목은 `commandIndex`, `team`, `cardId`, `x`, `y`, `tick`, `persistent`, `hits:[{id,team,damage,killed}]`를 가집니다. 훈련은 명령 인덱스로 화살비 시전과 실제 처치를 연결하며, 과거 저장에 인덱스가 없으면 위치·시전 시간 구간을 사용합니다. 독 같은 지속 효과는 생성 시점에 총 피해를 준 것으로 기록하지 않습니다. 이 진단 정보는 시뮬레이션 상태·난수·개체 ID·이벤트 순서를 변경하지 않습니다.

적 웨이브의 지정 지점이 막히면 같은 레인의 가까운 후보를 검사합니다. 배치할 수 없으면 비용·명령을 추가하지 않고 0.25초 간격, 최대 3초 재시도합니다. 계속 실패하면 예외를 던지는 대신 사유가 있는 훈련 실패로 종료합니다. 재시도 횟수와 대기 시간은 훈련 snapshot에 포함합니다.

## 7. 저장과 리플레이 버전

| 구분 | 포함 데이터 |
|---|---|
| 엔진 snapshot | 초기 설정, 전체 state, RNG 값, ID 순서, 대기 주문, 승인 명령 |
| AI snapshot | 난수, 판단 타이머, 스타일·난이도, 관찰 상태 |
| 앱 세션 | 상대, 연습 모드·속도·AI 설정, 훈련 snapshot, 도전 시도 context, matchId, 테마, 준비 잔여 시간 |
| 훈련 snapshot | 과제 ID, 적 배치 진행, 적 개체 ID, 목표 플래그, 명령 관찰 위치 |
| replay | 초기 설정, 고정 step, 명령, finalTick, 승자, 종료 결과, 선택적 endAction |
| 프로필 | 덱·설정·전적, 훈련 완료, 도전 진행, 최근 8경기와 중복 검사 ID |

형식 버전 2를 유지하면서 `config.rulesVersion`을 분리합니다. 신규 게임은 4, 필드가 없는 과거 기록은 2입니다. 규칙 3 기록은 그대로 3으로 복원합니다. 과거 규칙의 배치·독·이동 분기를 보존해 기존 리플레이에 새 규칙을 덮어쓰지 않습니다. 밀집보병은 규칙 3 이상에서 허용합니다. 분대가 필요한 덱에만 선택 필드 `state.formations`를 추가하여 기존 덱의 직렬화 모양을 유지합니다. 분대 앵커·생존 멤버·슬롯·보호 상태·돌격·쿨다운을 검증하고 복원합니다. 화면 방향과 렌더링 방식은 프로필 설정이며 엔진 snapshot에는 들어가지 않습니다.

배치 명령은 기존 형태를 유지하며 밀집보병 소환에만 `groupId`를 덧붙입니다. 능력은 `{type:"ability", tick, team, cardId:"phalanx", abilityId:"shield_charge", groupId}`로 같은 명령열에 기록합니다. 분대의 생성 명령과 진영을 연결하여 남의 분대·존재하지 않는 분대·너무 이른 발동·재사용 대기 중 반복 명령을 거절합니다. 뷰어의 직접 능력 API는 차단하고 검증된 재생 경로만 기록을 실행합니다.

리플레이는 같은 tick의 명령을 기록 순서대로 실행한 뒤 1/60초 진행합니다. 마지막 tick에 명령이 남아 있으면 그 명령까지 적용하고 추가 스텝 없이 끝냅니다. 항복 기록은 마지막 명령 뒤 `endAction`을 적용합니다. 0틱 항복도 생성·초기화 시점에 처리합니다. AI 판단은 다시 실행하지 않습니다. 재생 종료 시 tick·소모한 명령 수·승자를 검사하고, 새 기록은 종료 이유·크라운·타워 체력·누적 피해도 대조합니다. 다른 결과는 오류로 표시합니다.

파일 입출력 형식은 다음과 같습니다. UI 보고서나 브라우저 설정은 포함하지 않습니다.

```json
{
  "format": "crownfall-replay",
  "version": 1,
  "opponentId": "bran",
  "arenaTheme": "grove",
  "stageId": "stage-1",
  "replay": {
    "version": 2,
    "step": 0.016666666666666666,
    "config": { "rulesVersion": 4 },
    "commands": [],
    "finalTick": 0,
    "winner": null
  }
}
```

위 JSON은 구조 설명용이며 실제 파일의 config에는 덱·상대 덱·난이도·seed·연습 여부가 포함됩니다. 파일을 읽을 때 크기·형식·카드·좌표·tick 순서·결과 범위를 확인합니다. `arenaTheme`은 `grove/dusk/frost`, `stageId`는 `stage-1`~`stage-6`만 보존하며, 잘못된 선택 항목은 각각 누락합니다. 과거 파일에 없는 항목은 강제로 추가하지 않습니다. 이 메타데이터는 화면 재현용이고 도전 결과 반영 권한을 주지 않습니다.

최근 목록은 최대 8경기를 보관하고, 별도의 최근 ID 최대 128개로 오래된 목록 항목을 지운 뒤에도 제한된 범위에서 중복 저장을 막습니다. 전적·도전 진행·목록은 한 프로필 쓰기에 함께 넣습니다. 전투 체크포인트는 별도 저장이므로 여러 키에 걸친 데이터베이스 트랜잭션을 제공하는 것은 아닙니다. 도전은 활성 시도·완료 시퀀스와 실제 `Game` 바인딩을 별도로 검사하여 리플레이나 다른 전투가 해금과 메달을 갱신하지 못하게 합니다.

능력 횟수와 소비 엘릭서는 전투 분석에서 카드 사용량과 분리합니다. 총 엘릭서에는 둘 다 포함하며, 카드 평균 비용과 레인·주문 비중에는 능력 명령을 넣지 않습니다.

## 8. 검증의 실제 범위

4.4 전체 자동 검사 **190개가 모두 통과**했습니다. 상세 범위는 [RELEASE_NOTES.md](RELEASE_NOTES.md)에 기록했습니다. 신규 검사에는 양 진영의 분대 다리 통과, 후방 타워·막힌 다리 우회, 피해 감소·대형 붕괴, 능력 비용과 원자적 거절, 돌격 후 재집결, 사상자, AI, 저장·재생 전체 상태 일치를 포함합니다. 기존 덱은 이전 소스와 같은 입력으로 1,800틱을 진행하여 규칙 2·3의 전체 스냅샷 SHA가 일치함을 확인했습니다.

렌더러 검사는 좌표·메시·실제 모델 선택·시뮬레이션 불변·2D 복구를 다룹니다. WebGL은 호출 기록기 기반이므로 실제 GPU 영상·기기 성능 검사는 아닙니다. 밀집보병 상태별 독립 Canvas 이미지와 실제 HTML 구조·DOM 바인딩도 확인했습니다. 단일 HTML 빌드에서는 순수 모듈 조합을 실행하여 의존성 누락을 검사합니다. 브라우저 접근 제한으로 최신 전체 페이지 클릭·터치·모바일 다운로드 검증은 수행하지 않았습니다.

경로와 충돌은 이 크기의 로컬 아레나를 위한 휴리스틱입니다. 자동 검사에서 확인한 상황과 표본을 넘어 모든 배치 조합이나 장기 군집 상태가 완벽하다고 보장하지 않습니다.

## 9. PC 도구와 화면 방향

PC에서는 외부 좌측 설정·전역 치트, 가운데 모바일 게임 화면, 외부 우측 선택 대상·통계·대상 치트를 표시합니다. 좁은 화면에서는 게임 바깥 제목줄의 설정 버튼으로 같은 좌측 패널을 엽니다. 일시정지·음향·방향·렌더링·상대·난이도·덱·도움말 등 일반 설정은 인게임에 놓지 않습니다.

가로 화면은 상대 왼쪽·아군 오른쪽입니다. 2D는 월드 `(x,y)`를 `(y,480-x)`로 투영하고, 3D는 같은 진영 관계의 기울어진 정사영 카메라를 사용합니다. 지면 입력은 각 카메라의 역변환을 거쳐 기존 배치 API로 전달하고, 3D 개체 선택은 실제 모델 삼각형과 깊이를 검사합니다. 전투 중 방향·렌더러를 바꾸어도 엔진 상태는 유지합니다.

인게임 왼쪽은 시간·점수·세로 엘릭서만 남깁니다. 다음 카드 미리보기는 오른쪽 맨 위, 그 아래는 손패 4장의 단일 세로 열입니다. 승리 조건과 플레이 방법 등 상시 설명은 제거하고 외부 도움말로 제공합니다. 카드 정보·취소는 카드 선택 중에만, 밀집보병 스킬은 해당 분대가 있는 동안에만 표시합니다. 훈련·리플레이의 설정과 상세 상태 역시 외부 좌측 패널에서 제공합니다.

치트는 `practice`인 미종료 실제 Game에서만 작동하고, 앱과 `applyCheat()`가 훈련·리플레이를 추가로 제외합니다. `applyPracticeEffect()`는 연습 피해·기절을 기존 피해·상태·죽음·종료 처리에 연결하는 공개 API입니다. 치트는 시간을 전진시키거나 카드 명령을 추가하지 않습니다. 자세한 화면·입력·API는 [LAYOUT_AND_TOOLS.md](LAYOUT_AND_TOOLS.md), 3D와 실패 복구는 [RENDERING.md](RENDERING.md)에 정리했습니다.

## 10. 개발자 테스트와 수치 해석

`Game({practice:true, developerMode:true})`는 규칙 4 전용 테스트를 만듭니다. 전역 `CARDS`는 바꾸지 않고 `getCard(cardId,team)`이 해당 Game·진영에 적용할 정의를 반환합니다. 소환·주문·능력·AI·배치 미리보기·UI가 같은 정의를 사용합니다. 개발자 변경은 일반 대전·도전·훈련·리플레이에 적용하지 않습니다.

개발자 snapshot에는 선택 필드 `developer`로 진영별 수치와 치트가 들어갑니다. 일반 snapshot의 모양은 유지합니다. 개발자 전투는 리플레이로 내보내거나 불러오지 않으며 진행 상태 전체를 저장하여 이어갑니다. 개발자 명령에만 실제 지불한 `cost`를 기록하여 전투 중 비용 변경도 정확히 합산합니다.

현재 병력을 갱신할 때는 남은 HP 비율과 공격 대기 진행률을 유지합니다. 기존 투사체·예약 주문은 발사·시전 때의 값을 갖고, 이후 공격부터 새 값을 사용합니다. 팀별 엘릭서 무한, 능력 대기 해제, 진영 제한 해제도 개발자 상태로 관리하며 엔진에서 다시 모드와 입력을 검증합니다.

공개 API, 조절 항목, 배치·복원 경계는 [DEVELOPER_MODE.md](DEVELOPER_MODE.md)에 정리했습니다.
