# Crownfall Arena 4.0 — 변경 기록과 검증

2026-11-14 · 왕관의 길과 반복 플레이 흐름 완성

4.0은 기존 18종 카드 전투를 6단계 도전·전투 준비·결과·해금·복기로 연결합니다. 실시간 전투 규칙은 3을 유지하고, 진행 데이터와 화면 흐름을 확장했습니다. 기존 배치·강 경계·AI 개선의 상세 이력은 [3.0 변경 기록](RELEASE_NOTES_V3.md)에 보존했습니다.

## 이번 버전의 플레이 흐름

| 추가한 흐름 | 실제 동작 |
|---|---|
| 왕관의 길 | 숲 2단계 → 황혼 2단계 → 설원 2단계, 총 6관문 |
| 단계 선택 | 첫 단계 기본 해금, 승리하면 다음 단계 개방, 완료 단계 재도전 |
| 준비 화면 | 상대 실제 덱·난이도·내 덱·평균 비용·공략 힌트 확인 |
| 덱 편집 연결 | 준비 중 덱을 저장하거나 취소하면 같은 단계 준비 화면으로 복귀 |
| 출전 | 3초 카운트다운, 바로 시작, 준비 중 일시정지·모달·화면 숨김·저장 복원 |
| 메달 | 승리 1개 + 아군 타워 무손실 1개 + 180초 내 승리 1개, 단계별 최대 3개 |
| 최고 기록 | 시도·승리·최고 메달·최단 승리 시간; 다음 단계 또는 같은 단계 재도전 |
| 경기 목록 | 완료한 자유 대전과 도전 최근 8경기, 개별 재생·JSON 내보내기 |
| 항복 | 일시정지에서 확인 후 상대 승리로 종료, 점수·시간·피해를 유지하며 기록 |
| 전장 표시 | 숲·황혼·설원, 병력 배치 대기, 25% 이하 타워 경고, 피해 숫자 간격 조정 |

단계와 메달은 카드 능력치·시작 자원·피해량을 올리지 않습니다. 도전 단계는 고정 상대·난이도·seed와 사용자가 선택한 8장 덱을 사용합니다. 전적과 도전 결과는 일반 리플레이·훈련·자유 연습으로 늘어나지 않습니다.

## 실제 결함과 경계 처리

| 문제 | 변경 | 검증 |
|---|---|---|
| 마지막 tick의 입력을 처리하기 위해 리플레이가 한 틱 더 진행할 수 있음 | 마지막 명령 적용 후 추가 스텝 없이 종료 | 완료·미완료 기록의 같은 tick 입력과 전체 상태 비교 |
| 0틱·일시정지·시전 직후 항복을 재현할 종료 명령이 없음 | 선택적 endAction을 기록하고 최종 입력 뒤 적용 | 양 팀 항복, 같은 tick 배치, 진행 중 주문, 저장 후 항복 |
| 화염구가 먼저 죽인 미니언을 화살비 훈련 성공으로 인정 | 해당 화살비의 실제 적중·처치 기록으로 세 개체 확인 | 화염구가 먼저 처치하고 화살비 발동까지 약 0.037초 남은 기존 오판 재현 |
| 훈련 웨이브 배치가 막히면 예외로 프레임 루프를 중단할 수 있음 | 가까운 합법 위치, 0.25초 간격 최대 3초 재시도, 계속 불가하면 정상 실패 종료 | 재시도 시간·중복 생성·비용 보존·저장 복원 검사 |
| 도전 리플레이 파일에서 테마·단계 메타데이터 손실 | 허용 목록의 선택 메타데이터를 직렬화·역직렬화 | 세 테마·여섯 단계 왕복, 구버전 파일, 잘못된 값의 독립적 누락 |
| 동일 결과의 재반영 가능성 | 도전 시도와 실제 Game 바인딩, 완료 시퀀스 및 기록 ID 확인 | 다른 Game·리플레이·재적용·저장 후 중복 거절 |

## 데이터와 호환성

- 신규 전투 규칙은 `3`, 과거 기록의 누락된 `rulesVersion`은 `2`입니다.
- 엔진 저장·리플레이 형식은 `2`, 파일 래퍼는 `1`을 유지합니다. 새 필드는 선택 항목입니다.
- 항복 기록에만 `endAction:{type:'concede',team,tick}`을 추가합니다. 기존 정상 종료 기록을 임의로 변경하지 않습니다.
- 신규 규칙 3 병력에 초기 배치 대기 시간 `deployDuration`을 보관합니다. 기존 저장에 없어도 복원하며 규칙 2 상태에는 추가하지 않습니다.
- 규칙 2의 수정 전 두 경기 전체 snapshot SHA-256가 기존 값과 일치합니다.
- 도전 진행 snapshot은 버전 1입니다. 활성 시도·완료 시퀀스·단계 기록을 보관하며, 반복 도전 때마다 전체 과거 시도를 누적하지 않습니다.
- 최근 목록은 8개, 중복 방지용 ID는 128개로 제한합니다. 기록 객체는 복사하여 외부 변경이 내부 저장에 반영되지 않게 합니다.
- 설정·전적·도전 진행·최근 목록은 `crownfall.v1`에 함께 기록합니다. 진행 중 전투는 별도 `crownfall.match.v2` 체크포인트입니다. 저장소가 제한되면 현재 세션은 플레이할 수 있으나 새로고침 후 보존은 보장할 수 없습니다.
- 이전 버전의 `crownfall.replay.v2` 마지막 경기를 새 목록으로 이관합니다. 파일 불러오기는 프로필이나 도전 진행을 변경하지 않습니다.

기존 스트레스 테스트는 상대 3종 × 난이도 3종 × seed 2개, 총 18경기를 정상 비용과 합법 API로 진행합니다. NaN·불법 배치·음수/초과 자원·예외가 없고 대표 경기의 리플레이 전체 상태가 일치합니다. 이는 위 자동 테스트의 한 항목에 포함됩니다.

추가 도전 점검은 단계 6개 × 추천 덱 3개, 총 18경기입니다. 플레이어는 hard AI와 프리셋별 성향, 단계마다 고정 seed를 사용했고 상대는 실제 단계 설정을 사용했습니다. 모두 종료되었으며 단계마다 최소 한 추천 덱의 승리 사례가 있었습니다. 첫 단계 결과도 추천 덱에 따라 달랐으므로 이 작은 AI 표본을 사람의 승률이나 단계별 단조로운 난이도 상승으로 해석하지 않습니다. 각 단계 결과는 [싱글 플레이 명세](SINGLE_PLAYER.md)에 기록했습니다.

## 빌드와 화면 확인

- 모듈 JavaScript 문법, HTML ID 중복, 정적 DOM 연결, 필요한 산출물을 검사했습니다.
- 단일 파일 빌드는 9개 모듈을 연결하고 순수 모듈 조합을 실행해 도전·기록·훈련 의존성 누락을 검사합니다.
- 실제 Canvas 2D에서 CSS 폭 400px·2배 해상도로 세 테마, 배치 대기 표시, 낮은 타워 HP 경고, 겹친 피해 숫자를 렌더했습니다.
- 브라우저 접근 정책 차단으로 이번 버전의 전체 화면 클릭 검증은 수행하지 않았습니다. 독립 Canvas 출력은 브라우저 전체 화면 캡처가 아닙니다. 모바일 실기기의 터치·오디오·파일 저장과 전체 UI 흐름은 추가 확인이 필요합니다.
