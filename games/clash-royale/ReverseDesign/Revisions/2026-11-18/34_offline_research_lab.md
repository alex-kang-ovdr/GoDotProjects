# 34. 오프라인 데이터 연구 도구

> **v4 추가 조사 안내:** 아래 본문과 개수는 해당 v2/v3 작성 당시의 범위를 설명한다. 현재 통합 자료, 추가 복원, 레벨 미기재 값의 처리와 실행 명령은 [39번 개요](39_research_reconstruction_v4_overview.md), [44번 근거 조정](44_sources_and_level_reconciliation.md), [최신 검증 보고서](reports/validation_report.md)를 기준으로 한다.

> v3.0.0 · 기준일 2026-11-17 · 실행 파일: [ROYALE_DATA_LAB.html](ROYALE_DATA_LAB.html) · 데이터와 계산 코드를 한 HTML에 포함했다. 원작 실측 도구나 실제 전투 게임으로 표시하지 않는다.

## 1. 이번 고도화의 목적

v2는 원작 규칙의 근거와 역사 데이터를 재구축했다. v3는 이 자료를 검토하고 계산하는 과정을 실제로 실행할 수 있도록 확장한다. 문서에서 수치를 찾은 뒤 JSON을 열고 별도 계산기로 옮기던 작업을 카드 사전, 규칙 탐색, 성장·확률 계산, 전투 참조 계약, 검증 과제로 연결했다.

핵심은 조회 결과의 많고 적음보다 **어떤 시점·조건의 값이며, 어떤 값이 아직 없는지**를 확인하는 것이다. 같은 카드의 2023 체력과 2026 피해량이 각각 알려져 있다고 해서 두 값을 합친 현재 프로필이 성립하지는 않는다. 화면과 내보내기 모두 이 경계를 유지한다.

이 도구는 기존 자료를 더 쉽게 다루는 인터페이스다. 원표는 16종·7,128행으로 유지한다. 카드별 범위 분석, 출처 참조 수, 작업 목록은 추가 분석 뷰이며 원작 수치가 새로 발견된 것으로 집계하지 않는다. [품질 보고서](reports/quality_report.md)와 [37번 문서](37_coverage_and_implementation_gates.md)에서 집계 기준을 확인할 수 있다.

## 2. 실행과 파일 구성

ZIP을 압축 해제한 뒤 루트의 `ROYALE_DATA_LAB.html`을 더블 클릭한다. 브라우저가 HTML을 열면 바로 계산과 조회를 할 수 있다. 인터넷 연결, 서버 기동, Node 설치, 계정 로그인이 필요하지 않다. 새로고침하면 검색·입력·순환 실험 상태는 초기화된다.

## 3. 카드 사전

### 3.1 세 가지 자료 범위

| 범위 | 조회 대상 | 결측 처리 | 허용하는 해석 |
|---|---|---|---|
| 2026 패치 | 수록 원장의 마지막 공식 개별 필드 | 해당 레벨·형상·구성요소의 필드가 없으면 빈 결과 | 그 문서에서 이 필드가 확인되었다 |
| 2023 아카이브 | 고정 공개 스냅샷, 정확한 key 연결, 도달 개체의 레벨 배열 | 누락된 카드 루트를 유사 이름으로 보충하지 않음 | 그 역사 자료에 이 값과 참조가 있었다 |
| 자체 구현 | Crownfall v4.4 카드 참조 | 원작 카드로 매핑되지 않은 카드의 원작 ID는 null | 자체 프로토타입에 사용한 값이다 |

기본 화면은 2026 패치다. 목록은 자료에 등장하는 식별자 범위를 보여준다. **현재 플레이 가능한 전체 카드 목록**이라는 뜻이 아니다. 선택 범위에서 값이 없는 카드도 남겨 두어 결측을 확인할 수 있게 했다. 검색은 한국어 이름, 영문 이름, 카드 key를 사용한다.

조회 레벨은 수록 필드의 `reference_level`과 비교한다. 레벨 독립 필드는 레벨을 바꿔도 남지만, 레벨 11에서 공개된 피해를 레벨 12로 자동 성장시켜 표시하지 않는다. 자체 구현 수치는 동일한 레벨 체계를 사용한다고 검증되지 않았으므로 레벨 선택을 비활성화한다.

### 3.2 카드 조회를 확인하는 대표 흐름

1. 기사 `knight`를 선택하고 2026 범위를 본다. 현재 수록 패치에 해당 수치가 없으므로 빈 결과가 나온다.
2. 2023 아카이브로 바꾸고 레벨 11을 선택한다. 역사 레벨 배열의 기사 HP를 확인할 수 있다.
3. 두 조회를 내보내 각각의 `scope`, `records`, `fullCurrentProfile`을 확인한다. 현재 조회를 역사 HP로 채우지 않는다.

이 동작은 수치 누락이 UI 오류인지, 자료의 실제 한계인지 구분하기 위한 회귀 검사에도 포함했다. 빈 결과는 숨길 문제가 아니라 구현자가 알아야 할 정보다.

### 3.3 개체 참조

아카이브 화면에서는 카드 루트부터 개체, 투사체, 하위 소환물과 효과까지 명시된 연결을 따라간다. 탐색은 방문 집합을 사용하는 전체 도달 탐색으로 구현했다. 임의의 3단계 제한은 두지 않으며 순환 참조가 있어도 종료한다. 연결 후보가 여러 개이거나 대상이 없으면 추측으로 선택하지 않는다.

도달한 모든 개체가 전투 중 동시에 존재한다는 뜻은 아니다. 이 그래프는 데이터 참조 구조다. 실제 발동 조건, 대상 선정, 수명, 피해 적용은 개별 규칙과 실험에서 확인해야 한다. 이름 없는 6개 개체의 격리 상태도 원본에서 유지한다.

공개 데이터의 원시 사거리·속도를 현재 게임의 타일이나 Crownfall 픽셀로 변환하지 않는다. 개체 기록에서 `provider_raw_units`를 볼 수 있으며, 좌표 보정이 완료되기 전에는 단위가 같다고 가정하면 안 된다.

### 3.4 패치 이력과 변화율

2026 화면은 카드별 수록 패치를 날짜 순서로 나열한다. 형상과 구성요소를 유지하므로 본체·보호막·소환물·능력 피해를 하나로 합치지 않는다. 변화율은 `(after-before)/before`로 계산한 파생 값이다. 이전 값이 0이면 비율을 산출하지 않고 차이만 해석할 수 있게 한다.

변화율의 양수·음수가 카드의 전체 강약을 직접 뜻하지 않는다. 공격 간격 감소와 피해량 감소는 방향이 다르며, 조건부 범위와 소환 수는 상호작용에 따라 효율이 달라진다. 이 도구는 공개 필드의 변경을 비교할 뿐 실전 승률이나 메타 티어를 계산하지 않는다.

## 4. 규칙 탐색과 근거 추적

테이블과 근거 수준을 고른 뒤 key·값·설명·출처 ID 등을 검색할 수 있다. 검색 대상은 선택 테이블 전체이며 화면은 20행씩 표시한다. CSV 내보내기는 현재 페이지가 아닌 **필터에 맞는 전체 결과**를 저장한다.

기록 버튼은 원본 레코드와 관련 출처를 대화상자에 보여준다. 출처에는 제목, 발행자, 발행일, 조회일, 범위와 주의사항을 표시한다. 외부 링크는 HTTP·HTTPS만 허용한다. 로컬 구현 참조는 문서 이름과 메타데이터로 표시한다.

`official_confirmed`는 공식 문서에 기재된 주장이라는 뜻이다. 기록의 적용 시작일이나 현재 유효성을 자동 보증하지 않는다. `effective_to=null`은 종료일을 확보하지 않았음을 나타내며 영구 적용을 의미하지 않는다. 규칙을 구현할 때는 문서 날짜, 시즌, 모드, 레벨 조건을 같이 확인한다.

## 5. 성장·확률 계산

업그레이드는 이미 해당 레벨의 카드를 보유한 상태에서 목표 레벨까지의 추가 복제본·골드를 계산한다. 필요하면 보유 자원을 입력해 부족분을 계산한다. 해금 비용, 상점 구매, 와일드카드 배분, 향후 보상, 유료 패스 가격은 합산하지 않는다.

자료가 없을 때는 확정 합계와 알려진 부분합을 분리한다. 예를 들어 Epic 목표 레벨 7의 골드가 비어 있으면 합계를 0으로 만들지 않는다. 원문에서 비어 있는 값을 다른 버전으로 채우지도 않는다. 상세 계산은 [36번 문서](36_economy_calculators_and_boundaries.md)에 정의했다.

확률은 정확히 같은 그룹 식별자의 조건만 모아 계산한다. 시작 별 수, 상자 계열, 계정 조건이 다른 확률을 섞지 않는다. 99.99%나 100.01% 같은 공개 표시값은 기록된 허용 오차로 검사하고 정규화하지 않는다. 최종 별 수가 명시된 완결 그룹에서만 가중 평균을 보여주며 이를 골드 가치나 성장 기간으로 바꾸지 않는다.

독립 반복 계산은 별도 가정 도구다. 실제 보상 보장·천장·풀 중복 보정·계정 상태가 포함되지 않았다. 매우 작은 양의 확률을 0%, 1 미만의 확률을 100%로 반올림하지 않도록 경계 표시를 둔다. 정확한 원값은 계산 모듈의 결과에 보존된다.

## 6. 전투 계약과 원작 관측

손패 순환은 고정 입력 A~H를 사용해 대기열과 사용 순서를 확인한다. 일반 카드와 Champion을 별도 짧은 순환으로 처리하지 않는다. 4장 손패·초기 순서·원자적 교체는 참조 모델의 설계 범위이며, 실제 드로우 지연이나 랜덤 시드를 검증한 결과가 아니다.

시간 도구는 경기 진행에 따른 배수와 정규·연장 종료까지의 시간을 구분한다. 공식 지원 문서는 일반전에서 첫 두 분은 1배, 다음 두 분은 2배, 마지막 연장 분은 3배라고 안내한다. 단, 이벤트와 2v2는 별도 규칙이 가능하다. [Supercell Elixir](https://support.clashroyale.com/hc/en-us/articles/49484936933403-Elixir)

엘릭서 초기량·최대량·기본 생성 간격은 입력 없이 계산하지 않는다. 현재 수록 근거에서 미확정인 필드를 숨은 기본값으로 채우지 않기 위해서다. 입력값을 정한 뒤 120초·240초 경계를 통과하는 연속 적분을 확인할 수 있다. 서버 틱, UI 표시 지연, 실제 패킷 도착 시점은 계산하지 않는다.

보호막 초과 피해도 미확인 상태를 기본값으로 둔다. 소멸·이월 정책을 직접 선택하면 그 가정에 대한 결과만 계산한다. 어느 선택지를 눌렀다는 사실이 원작 정책의 근거가 되지는 않는다.

밀집보병은 사용자 요구에 따른 자체 카드다. 방진 시 공격하지 않고, 생존·정렬·배치·기절 조건을 충족하면 방어력을 적용한다. 돌격 상태에서는 방진 감면을 해제한다. UI의 공격 준비 상태는 분대 집계이며, 한 병사가 기절했다고 다른 개별 병사의 공격까지 중지된다는 뜻이 아니다. [35번 문서](35_executable_combat_contracts.md)에서 모델의 적용 범위를 확인할 수 있다.

## 7. 검증 과제와 기록 내보내기

검증 과제 화면은 16개 후속 작업의 우선순위, 선행 과제, 완료 기준, 근거 기록을 보여준다. 44개 상호작용 명세에서는 하나를 선택해 관측 기록 양식을 JSON으로 받을 수 있다. 양식의 기본값은 `observed=false`, `test_status=not_run`이며 결과와 측정값은 비워 둔다.

원작 관측을 완료했다면 버전, 플랫폼, 모드, 레벨, 초기 상태, 입력 순서, 측정값, 근거와 오차를 함께 남긴다. 이 화면은 사용자의 관측을 업로드하거나 진위를 자동 판정하지 않는다. 참조 함수 실행이나 JSON 저장만으로 데이터의 공식 확인 상태를 변경하지 않는다.

## 8. 접근성과 화면 범위

넓은 화면은 왼쪽 탐색 메뉴, 중앙 목록·계산, 오른쪽에 이어지는 상세 공간을 사용한다. 작은 화면은 메뉴를 가로로 모으고 카드 목록을 가로 스크롤로 전환하며 계산 패널을 세로로 쌓는다. 입력에는 레이블을 붙이고, 키보드 포커스와 선택 상태를 표시하며, 색 외에 근거 배지 문구를 함께 사용한다.

대화상자는 기본 브라우저 dialog를 사용한다. 닫기 버튼과 Escape로 닫을 수 있으며 결과의 핵심 안내는 live region으로 갱신한다. 감소된 움직임 환경에서는 카드 이동 효과를 제거한다. 이러한 구조·상태 연결은 정적으로 검사했지만 실제 브라우저별 화면 렌더링, 스크린리더, 터치 기기 시험을 수행했다는 뜻은 아니다.

## 9. 재생성과 검증

```bash
python scripts/analyze_quality.py
python scripts/build_lab.py
python scripts/verify_package.py
```

HTML 생성은 JSON 데이터, 분석 뷰, CSS, 세 JavaScript 모듈과 화면 코드를 하나로 합친다. 외부 CDN, 동적 import, fetch 요청을 사용하지 않는다. JSON을 내장할 때 `<` 같은 문자를 이스케이프해 데이터 문자열이 script 태그를 닫지 못하도록 한다. 원본 데이터는 변경하지 않는다.

검증 도구는 자료 정합성, 재생성 일치, 순수 함수의 경계, DOM 입력·출력 흐름과 번들 구조를 구분해 보고한다. 각 검사가 무엇을 보증하는지는 [38. 인계·수용 기준](38_versioned_handoff_and_acceptance.md)에 정리했다.
