# 38. 버전 인계와 구현 수용 기준

> **v4 추가 조사 안내:** 아래 본문과 개수는 해당 v2/v3 작성 당시의 범위를 설명한다. 현재 통합 자료, 추가 복원, 레벨 미기재 값의 처리와 실행 명령은 [39번 개요](39_research_reconstruction_v4_overview.md), [44번 근거 조정](44_sources_and_level_reconciliation.md), [최신 검증 보고서](reports/validation_report.md)를 기준으로 한다.

> v3.0.0 · 산출물은 원작 분석·공개 데이터·오프라인 연구 도구·참조 계약이다. 실제 Crownfall 웹게임은 기존 v4.4.0을 유지한다.

## 1. 세 가지 버전을 분리한다

| 버전 축 | 현재 값 | 바뀌는 이유 | 자동으로 바뀌지 않는 것 |
|---|---|---|---|
| 연구 패키지 | 3.0.0 | 문서·분석·조회 도구·검증 보강 | 원작 현재 빌드 |
| 공개 역사 스냅샷 | 2023-10-18 고정 커밋 | 명시적으로 다른 공개 자료를 채택할 때 | 2026 자료로 승격 |
| 자체 게임 구현 | Crownfall v4.4.0 / rulesVersion 4 | 게임 엔진·저장·배포를 변경할 때 | 연구 도구의 변경만으로 게임 밸런스 갱신 |

원작 패치는 네 번째 시간 축이다. 개별 기록의 적용일·형상·레벨에 속하며 연구 패키지 버전과 같지 않다. 패키지를 v3로 올렸다는 이유로 과거의 수치를 현재 값이라고 해석하지 않는다. 추후 원작 레벨·타워·능력 규칙이 바뀌면 새 근거와 적용 조건을 가진 기록으로 수용한다.

## 2. 기능의 인계 단위

v3에서 바로 사용할 수 있는 범위는 다음과 같다.

| 기능 | 입력 | 출력 | 실패·보류 조건 |
|---|---|---|---|
| 카드 조회 | 카드 key, 자료 범위, 레벨 | 해당 범위의 레코드와 근거 | 누락은 빈 결과, 다른 버전 보충 금지 |
| 개체 탐색 | 역사 카드 루트 | 명시적 참조로 도달한 개체·간선 | 누락·모호 연결 자동 선택 금지 |
| 패치 비교 | 동일 카드의 수록 원장 | 전후 값·날짜·형상·구성요소 | 0 기준 변화율은 null |
| 업그레이드 | 희귀도, 현재·목표 레벨, 선택적 자원 | 레시피·합계·부분합·부족분 | 비용 누락은 확정 합계/충족 판단 보류 |
| 조건부 확률 | 정확한 그룹 식별자 | 공개 합·조건·허용 오차·제한된 기대값 | 조건 충돌, 중복 결과, 결측, 잘못된 합 |
| 손패 계약 | 8개 고유 ID와 슬롯 사용열 | 손패·대기열·사용 이력 | 중복·잘못된 길이·손상 상태 |
| 시간·엘릭서 계약 | 경과 시간, 명시적 프로필, 소비 사건 | 구간 적분·잔량·소실·거절 | 프로필/구간 시작 잔량 누락 |
| 보호막 계약 | HP, 피해, 선택 정책 | 본체·보호막 결과와 가정 | 정책 미확인은 계산 차단 |
| 밀집보병 계약 | 분대 집계 상태 | 방어 활성·감면·전원 공격 준비 | 원작 카드 매핑이나 개별 타격 일치 주장 금지 |
| 관측 양식 | 상호작용 명세 | 실행 전 JSON 기록 | 입력 없이 결과 완료 처리 금지 |

기능의 성공 반환은 입력과 수록 데이터로 계산이 가능하다는 뜻이다. 원작의 실제 작동을 검증했다는 의미로 재사용하면 안 된다. 특히 경제 모듈은 `ok=true, complete=false, blocked=true`를 허용한다. 요청 자체는 유효하지만 결정에 필요한 값이 부족한 경우다.

## 3. 게임 엔진으로 데이터를 옮기는 조건

현재 도구에는 원작 패치 값을 Crownfall에 자동 주입하는 기능이 없다. 이후 어댑터를 구현한다면 카드 한 개의 프로필을 옮기기 전에 다음 조건을 만족해야 한다.

1. **프로필 식별:** 카드, 형상, 구성요소, 레벨, 모드, 유효 시점을 명시한다.
2. **필수 필드:** HP·대상·공격 간격·피해 방식·배치·수명·소환 구조 등 해당 카드가 실제로 요구하는 값이 완비된다. 어떤 카드는 본체 피해 대신 투사체 피해가 필요하다.
3. **단위 변환:** 원시 거리·속도·시간이 런타임 단위로 어떻게 변환되는지 별도 근거와 오차를 가진다.
4. **사건 순서:** 보호막, 넉백, 사망 생성, 다중 파동, 타워 파괴 등 순서 의존 동작을 명시한다.
5. **관측 범위:** 대표 상호작용의 실제 관측과 동일 조건의 재현 결과를 연결한다.
6. **저장 호환:** 수치·규칙 변경이 진행 중 경기, 리플레이, 기존 저장에 미치는 영향을 정한다.

필드가 부족한 상태에서는 부분 프로필 그대로 보관한다. 값을 임의로 보정해 완전한 원작 프로필이라고 내보내면 안 된다. 재현용 가정을 채운 프로필이 필요하다면 별도 식별자와 `reproduction_design` 출처, 선택 이유를 함께 보존해야 한다.

## 4. 사용자 지정 카드의 보존

밀집보병과 강철 검사는 독자 카드다. 원작 데이터셋을 갱신할 때 이름·역할이 비슷하다는 이유로 원작 ID를 부여하지 않는다. 밀집보병의 방진 공격 금지, 강한 방어, 돌격 해제와 가속은 사용자 요구에서 나온 자체 규칙으로 유지한다.

연구 계약에서 보이는 `canAttack`은 전원 준비 상태를 단순화한 값이다. 실제 v4.4 게임은 개별 병사의 기절·배치·타겟·쿨다운을 처리하므로, 한 명이 기절한 돌격 분대에서 다른 병사들이 공격하는 동작까지 이 집계 함수로 대체하지 않는다. 참조 모델은 계약의 좁은 부분을 설명하는 도구이며 기존 엔진 전체의 축약본이 아니다.

## 5. 검증 계층

| 계층 | 실제 검증 내용 | 보증하지 않는 내용 |
|---|---|---|
| 데이터 정합성 | JSON/CSV 동일성, 식별자, 출처 연결, 레벨 배열, 패치 계보, 조건부 확률 | 비공개 원본 DB 또는 현재 클라이언트 전체 수치 |
| 분석 재생성 | 카드 키 합집합, 연결 탐색, 결측·충돌·미실행 집계, 과제 DAG | 연구 완성도 백분율 |
| 순수 계산 | 손패·경계 적분·자원 보존·보호막 정책·비용·확률·불변성 | 실전 승률, 서버 틱, AI·경로·GPU 성능 |
| DOM 흐름 | 실제 화면 코드의 초기화, 요소 연결, 주요 입력·출력·내보내기 요청 | 실제 브라우저의 시각 렌더링·모바일 터치·접근성 적합성 |
| 번들 구조 | HTML 내장 데이터 일치, 외부 로딩 부재, script 경계, 재생성 바이트 동일성 | 브라우저별 파일 다운로드 정책 |
| 배포 패키지 | ZIP CRC, 내부 바이트 동일성, 파일 SHA-256 목록 | 원작 클라이언트 시험 완료 |

DOM 검사는 Python HTMLParser가 읽은 템플릿과 Node의 최소 DOM 환경에서 화면 JavaScript를 실행한다. 실제 브라우저를 시작한 검사가 아니며 결과 보고서도 이를 구분한다. 직접 렌더링·기기별 사용성 시험은 후속 검증 범위다.

## 6. 재현 가능한 실행 순서

일반 사용자는 HTML만 열면 된다. 개발자는 Python과 Node가 설치된 환경에서 다음을 사용할 수 있다. 외부 Python 패키지와 npm 설치는 필요하지 않다.

```bash
python scripts/rebuild.py --check
python scripts/analyze_quality.py --check
python scripts/build_lab.py --check
python scripts/verify_package.py
```

입력 자료나 화면 소스를 변경했다면 먼저 필요한 생성물을 재생성한다.

```bash
python scripts/rebuild.py
python scripts/analyze_quality.py
python scripts/build_lab.py
python scripts/verify_package.py
python scripts/package_release.py
```

검증기는 개별 단계의 종료 코드와 Node/Python 테스트 수를 [릴리스 검증 보고서](reports/release_validation.md)에 기록한다. [기계 판독 보고서](reports/release_validation.json)는 자동화에 사용할 수 있다. 보고서의 원작 관측 실행 수는 별도이며 0으로 유지한다.

ZIP 생성은 패키지 루트의 파일을 포함하되 Python 캐시와 임시 파일을 제외한다. 내부 `SHA256SUMS.txt`는 자신을 제외한 파일의 SHA-256을 기록한다. ZIP은 패키지 바깥에 생성하므로 재압축할 때 이전 ZIP이 내부에 중첩되지 않는다.

## 7. 변경 수용 체크

후속 변경은 아래 기준을 적용한다.

| 변경 종류 | 필수 검토 | 수용 불가 예 |
|---|---|---|
| 공식 패치 추가 | 원문 날짜, 카드·형상·구성요소·레벨, 기존 필드 계보 | 제목 날짜만 보고 URL의 연도를 데이터 적용일로 사용 |
| 역사 스냅샷 변경 | 새 commit·해시·고정 출처, 누락과 행 수 차이 | 저장소 HEAD가 오래되었는데 최신 라이브 자료라고 명명 |
| 비용 변경 | 레시피 목표 레벨, 새/옛 표 구분, 비적용·미확정 분리 | Epic 골드 빈칸을 과거 값이나 0으로 채움 |
| 확률 추가 | 조건, 전체 분포 여부, 반올림 오차, 중복 결과 | 서로 다른 상자·계정 조건을 합쳐 100%로 정규화 |
| 관측 추가 | 실제 입력·빌드·모드·레벨·근거·오차 | 참조 함수의 성공을 원작 관측 supported로 복사 |
| 엔진 수정 | 별도 브랜치/버전·테스트·저장 호환·게임 리뷰 | 연구 자료 생성만으로 기존 자체 밸런스 변경 |
| UI 수정 | 데이터 범위 배지, 결측 표시, 입력 오류, 내려받기 내용 | 역사 수치와 현재 패치 값을 한 통계 카드로 합침 |

## 8. 알려진 경계와 다음 단계

이번 패키지는 현재 전체 카드 프로필을 0개로 보고한다. 이는 자료가 쓸모없다는 뜻이 아니라, 완전한 현재 프로필을 주장하기 위한 조건을 엄격하게 적용한 결과다. 부분 패치가 있는 40개 키와 역사 카탈로그 120행은 서로 다른 목적의 유효한 근거다.

가장 먼저 해결할 후속 작업은 대표 카드의 동일 빌드·레벨 프로필, 거리·속도 단위 보정, 보호막과 동시 사건 순서, 누락된 카드 루트 연결, 경제의 미기재 경계다. 상세 우선순위와 선행 관계는 [재구축 작업 목록](data/analysis/reconstruction_backlog.json)에 있다.

지금 실행 가능한 계산과 아직 필요한 실제 관측을 구분하면, 후속 자료가 들어왔을 때 어떤 기능을 확정할 수 있는지 명확해진다. 이 경계를 유지한 채 근거를 추가하고 재생성·검증을 반복하는 것이 v3의 인계 방식이다.
