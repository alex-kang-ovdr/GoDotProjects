# 32. 데이터 재구축 파이프라인과 검증 도구

> **v4 추가 조사 안내:** 아래 본문과 개수는 해당 v2/v3 작성 당시의 범위를 설명한다. 현재 통합 자료, 추가 복원, 레벨 미기재 값의 처리와 실행 명령은 [39번 개요](39_research_reconstruction_v4_overview.md), [44번 근거 조정](44_sources_and_level_reconciliation.md), [최신 검증 보고서](reports/validation_report.md)를 기준으로 한다.

> Python 표준 라이브러리만 사용하는 오프라인 정규화·검증 도구. 외부 게임 계정, API 토큰, Node 서버가 필요하지 않다. 선택적인 과거 자료 재다운로드에는 인터넷이 필요하다.

## 1. 입력과 출력

| 구분 | 위치 | 관리 방식 |
|---|---|---|
| 과거 원문 식별·해시 | `data/snapshot_manifest.json` | 2023 커밋SHA와 파일별 원문·선별본 해시 |
| 과거 사실 입력4개 | `data/raw/*_2023_facts.json` | 공개 수치·식별자·한국어 이름만 선별 |
| 공식 규칙·경제·모드 입력 | `data/tables/*_rules.json` 등 | 출처를 대조해 정리한 검토 완료 입력 |
| 공식 수치 패치 입력 | `data/tables/balance_patch_ledger_2026.json` | 카드·형상·부위·레벨별 before/after |
| 자체 구현 참고 입력 | `implementation_reference/crownfall_4_4_cards.json` | 게임 코드에서 읽은19개 카드의 자체 수치 |
| 자동 생성 표 | 카드·개체·레벨·연결·최신패치·구현대조 JSON | `rebuild.py`로 생성 |
| CSV | 모든 `data/tables/*.csv` | 동일 JSON의 행·열을 직렬화 |
| 검사 결과 | `reports/validation_report.json`, `.md` | 성공·실패와 알려진 한계를 함께 출력 |

공식 경제표 JSON은 공개 HTML 표를 조사·정리한 입력이다. 이번 배포에는 공식 사이트의 현재 HTML을 전부 다시 크롤링하고 자동 해석하는 도구를 포함하지 않는다. 재생성 도구의 범위는 확보한 입력을 정규화하고 CSV·조회본을 재구축하는 데 있다. 공식 자료가 바뀌면 원문을 다시 확인한 사람이 입력과 출처 버전을 함께 갱신해야 한다.

## 2. 실행 방법

압축을 해제한 최상위 폴더에서 실행한다. 경로에 한글이 있어도 Python3의 UTF-8 파일 처리로 읽도록 작성했다. Windows에서 `python` 명령이 없다면 설치된 Python 런처의 `py -3`로 바꿔 실행한다.

```bash
python scripts/rebuild.py
python scripts/rebuild.py --check
python scripts/validate.py
```

`rebuild.py`는7종의 자동 생성 JSON과 모든 데이터 CSV를 쓴다. `--check`는 내용이 같은지 비교하고 다르면 실패하므로, 입력을 바꾼 뒤 결과물을 갱신하지 않은 상황을 찾을 수 있다. `validate.py`는 검사 결과를 보고서로 남기고 오류가 있으면0이 아닌 종료코드를 반환한다.

### 카드 조회

```bash
python scripts/query_data.py card fireball --level 11
python scripts/query_data.py card minion-giant
python scripts/query_data.py card knight --scope archive-2023 --level 11
python scripts/query_data.py compare phalanx
```

기본 scope는 `verified-2026`이다. 여기서는 선택한 공식 패치에 있는 필드만 반환한다. `archive-2023`은 카탈로그와 명시적 참조를 따라가 해당 레벨 배열을 보여준다. 두 범위를 섞지 않는다. `compare`는 기존 웹게임의 자체 카드와 역할 참조 정보를 반환한다.

## 3. 과거 스냅샷 재확보

```bash
python scripts/fetch_snapshot.py
```

이 명령은 최신 자료를 검색하는 기능이 아니다. `dataset_config.py`에 고정된 SHA의 원문4개를 내려받고, 원문 SHA-256이 일치한 경우에만 선별 사실 입력을 저장한다. 하나라도 다르면 모든 출력 교체 전에 실패한다.

manifest에는 연구 기준일 `analysis_as_of`와 실제 재확보 시각 `retrieved_at_utc`가 분리되어 있다. 나중에 다시 실행해도 자료 자체의 기준 커밋은2023-10-18이며, 다운로드 날짜를 최신 게임 수치의 근거로 사용하지 않는다. 원본 파일 전체를 배포 폴더에 저장하지 않는다.

## 4. 자동 검사에서 확인하는 것

| 검사 | 찾는 실제 오류 |
|---|---|
| JSON·공통 필드·근거 상태 | 파싱 실패, 잘못된 evidence_status, 필수 출처 누락 |
| record_id·source_id 유일성 | 다른 카드나 규칙을 조용히 덮어쓰는 충돌 |
| 출처 외래키 | 존재하지 않는 source_id를 가진 행 |
| 적용일 순서 | 종료가 시작보다 빠른 행, 잘못된 날짜 형식 |
| 선별 입력 해시 | 재구축 중 원본 부분 데이터의 의도하지 않은 변경 |
| 카드·개체·레벨 정합성 | 행 손실, 잘못된 배열 인덱스, 미존재 참조 |
| 희귀도 레벨 회귀 | 일반·희귀·투사체의 표시 레벨 오프셋 오류 |
| 패치 최신 조회 | 9월 값을10월값 위에 덮는 오류, 역사 데이터 폴백 |
| 조건부 확률 | 범위 밖 수, 상호 배타적 그룹의 합계 오류 |
| JSON↔CSV | JSON 수정 뒤 CSV를 갱신하지 않은 상태 |
| 문서 상대 링크 | ZIP을 풀었을 때 존재하지 않는 문서·데이터 참조 |
| 자체·원작 경계 | 밀집보병에 원작 카드ID를 붙이는 오류 |
| 실험 실행 상태 | 미실행 원작 실험을 성공으로 표시하는 오류 |

확률의 원문 표시값은 반올림 때문에100%와 아주 조금 다를 수 있다. 공식 표의 원값을 유지하고 그룹별 허용오차로 검사한다. 총합을 억지로1로 맞추면 공식 표시값과 다른 데이터를 생성하게 된다. null인 미확정 확률도0으로 바꾸지 않는다.

## 5. 실행 확인 사례

단순히 파일이 열리는지 외에도 다음 조회를 실행해 확인했다.

| 조회 | 확인 결과 |
|---|---|
| 최신 Minion Giant | 해당 패치 원장 내 최종 피해153 |
| 최신 Knight | 미확인HP를2023 자료로 채우지 않음 |
| 아카이브 Knight, 레벨11 | 제공자 배열의 HP1766 조회 |
| 아카이브 Super Lava Hound | 4홉 이후 Lava Pup 투사체까지 도달 |
| 구현 Phalanx 대조 | 원작 카드ID null, custom_only 유지 |

그래프 조회의 고정3홉 제한은 독립 검토에서 실제 누락 사례를 찾은 뒤 방문 집합 기반 탐색으로 수정했다. 이 검증은 깊은 사망 소환 체인이 자료 조회에서 잘리는 위험을 해결한다. 실제 게임 내 소환 순서를 직접 검증한 것은 아니다.

## 6. 검사 통과가 보장하지 않는 것

데이터 검사로는 원문의 실수, 공식 공지의 지연, 계정별 실험, 실게임의 숨은 판정, 원시 단위의 의미, 소수점 반올림 시점을 확정할 수 없다. 같은 수치라도 레벨·형상·주문 파동이 달라질 수 있으므로 실제 전투 대조가 필요하다.

현재44개 실험 명세의 `test_status`는 모두 `not_run`이다. 데이터에 출처가 있는 것과 그 규칙이 현재 계정에서 동작하는 것을 분리한다. 원작의 프레임 테스트·승률 표본·네트워크 패킷·클라이언트 코드 분석을 수행한 것으로 표현하지 않는다.

## 7. 입력 갱신 절차

1. 변경 출처의 원문과 적용 범위를 확인한다.
2. 다른 시점의 행을 삭제하지 말고 새 버전 행 또는 새 스냅샷을 만든다.
3. JSON의 값·단위·출처·적용일·조건을 함께 수정한다.
4. `rebuild.py`, `rebuild.py --check`, `validate.py`를 실행한다.
5. 변경된 입력과 영향받는 시스템 문서를 검토한다.
6. 검증 보고서와 산출물 ZIP을 같은 상태에서 생성한다.

이미 있는 표의 열을 추가하면 CSV도 다시 생성해야 한다. 중첩 객체를 CSV의 여러 열로 임의 펼치지 않고 JSON 문자열로 보존한 이유는 희귀도별 비용·조건부 보상처럼 구조가 다른 값을 손실 없이 읽기 위해서다.
