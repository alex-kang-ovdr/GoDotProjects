# 구현 완료 기준·테스트 계획

## 모듈 경계
- `GameClock`: 10세 시작부터 18세 종료까지 달력, 슬롯, 생일
- `ScheduleEngine`: 행동 검증 및 실행, 비용, 결과 집계
- `StatEngine`: 능력치 범위, 상태효과, 질병
- `EconomyLedger`: 거래 idempotency, 수입/지출
- `EventEngine`: 트리거/조건/선택/쿨다운
- `AdventureEngine` 및 `BattleEngine`: 이동/조우/전투/보상
- `EndingResolver`: 후보 조건/우선순위
- `Persistence`: 버전 포함 스냅샷, PRNG 상태, 마이그레이션

## 통합 시나리오
| ID | 시나리오 | 통과 기준 |
|---|---|---|
| IT01 | 10세 시작, 3개 슬롯 편성 | 1개월 종료 후 3개 행동의 효과·비용 정확 |
| IT02 | 0G로 유료 교육 실행 | 사전 거부, 상태 불변 |
| IT03 | 피로 90에서 교육 | 감쇠 적용, 피로 상한 유지 |
| IT04 | 이벤트 선택 대기 중 저장/복원 | 선택 중복 적용 없음 |
| IT05 | 모험 전투 승리 후 귀환 | 보상 한 번만 반영 |
| IT06 | 동일 세이브+PRNG 시드 | 모든 결과 결정적 |
| IT07 | 18세 마지막 달 종료 | 엔딩 한 번만 발생 |
| IT08 | 세이브 스키마 구버전 | 명시적 마이그레이션 또는 오류 |
| IT09 | 교육 1000회 반복 | 수치 오버플로·NaN 없음 |
| IT10 | 이벤트 동시 발동 | 우선순위·독점 그룹 안정적 |

## 데이터 품질 게이트
- 모든 행동·이벤트·엔딩 ID는 유일해야 한다.
- 모든 참조 ID는 존재해야 한다.
- 모든 수치 범위·단위·반올림 정책을 스키마에 기록한다.
- 원작과 비교한 관찰은 `version`, `date`, `saveHash`, `before`, `after`, `confidence`를 남긴다.

## 완료 판정
문서 구현 명세 완성 = 모든 모듈의 입출력과 경계·테스트 정의 완료. **원작 완전 재현**은 원작 데이터 및 판정식 검증과 플레이 비교 테스트가 끝나야 별도로 선언할 수 있다.
