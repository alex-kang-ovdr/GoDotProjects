# Fortress BLUE 플레이 프로토타입 — 데이터 출처와 구현 가정

## 이 데이터가 의미하는 것

이 프로젝트는 공개 자료에서 복구한 일부 수치를 사용하여 만든 독립적인 턴제 포격 프로토타입이다. 원작 실행 파일·서버·물리 엔진을 복제하거나, 포트리스3 BLUE의 현재 라이브 밸런스를 재현한 결과물이 아니다. 출처 수치와 플레이를 위해 정한 값을 `dist/data.js`에 함께 기록하되 서로 다른 상태로 분류한다.

입력 정본은 **Fortress_Recovered_Data.json v1.2.0, 1,208행, 수집일 2026-11-18**이다. 이 파일은 읽기만 했으며 수정하지 않았다. 입력 파일 SHA-256은 다음과 같다.

```text
ae45745e803d403bbe434e7903497ce1d067f5ee063fa71bb2b803b0db0bc384
```

플레이 데이터는 `window.FortData`에 노출된다. 선택한 원문 레코드 61개는 `provenance.sourceSnapshots`에 값 변경 없이 보존하고 재귀적으로 동결했다. 원문 레코드의 `null`은 0으로 바꾸지 않았다. 카탈로그에서 실행에 필요한 값이 비어 있는 경우에는 별도의 구현값을 넣고 그 사실을 표시했다.

## 출처 상태 표시

| 상태 코드 | 뜻 |
|---|---|
| `source_reported` | 일본 서비스 2003년 문헌 수치. 실행 검증은 하지 않음 |
| `community_claim_not_runtime_verified` | 한국 커뮤니티 보고값. 정확한 빌드와 실행 일치 미확인 |
| `source_input` | 문헌 공격값을 프로토타입 피해식의 입력으로 사용 |
| `official_published` | 공식 소개 공지 수치. 표에 없는 성급·레벨·모드 조건은 미상으로 유지 |
| `official_patch_input` | 날짜·모드·성급·레벨이 명시된 공식 패치의 공격값을 입력으로 사용 |
| `simulation_assumption` | 플레이를 위한 수치 조정, 단위 환산, 행동 해석 또는 단순화 |

탱크의 `provenance.statSources`는 필드별 값·상태·출처 URL을 제공한다. `provenance.simulationAssumptions`는 그 탱크의 구현 가정이다. 무기는 `attackStatus`, `sourceSnapshot`, `sourceRefs`, `assumptions`로 구분한다. 화면의 데이터 패널에서 이 정보를 읽을 수 있다. `description`은 플레이할 때 볼 행동 설명이며 출처 판정이나 원문 수치를 대체하지 않는다.

### 원문 입력과 실행 동작의 분리

42개 무기에 다음 실행 필드를 명시한다. 이 필드를 추가하면서 기존 HP·기본 딜레이·이동·카탈로그 사격각·공격 입력·기본 탄수·스킬 딜레이·해금 라운드와 원문 스냅샷 61개는 보존했다.

| 필드 | 의미 | 판정 범위 |
|---|---|---|
| `role` | `attack` 공격 또는 `support` 지원 | 반복 발사와 아이템 호환을 결정하는 실행 분류 |
| `delivery` | `projectile` 발사체 또는 `self` 자기 적용 | 지원탄과 직접 사용하는 방어·증폭을 구별 |
| `behavior.trajectory` | `ballistic` 곡선 또는 `linear` 직선 | 직선 모델은 중력·바람을 적용하지 않음 |
| `behavior.bounces`, `restitution` | 지형 반사 횟수와 반사 속도 계수 | 현재 고유 반사 계수는 0.72 |
| `behavior.lifeSteal` | 적의 실제 HP 감소량을 기준으로 하는 흡혈 비율 | 현재 흡혈박쥐의 비율은 0.25 |
| `behavior.repeatable` | 더블·서든데스 반복 대상 여부 | 모든 지원기는 `false` |
| `behavior.homingTarget` | 유도탄의 추적 대상 | 현재 `enemy`로 제한 |
| `behavior.aimMin`, `aimMax` | 해당 스킬의 별도 사격각 | 펄스레이저 −35~75도. 카탈로그 각도는 유지 |
| `behaviorStatus` | 실행 계수의 출처 상태 | 전부 `simulation_assumption` |

엔진 호환용 `behavior.role`은 최상위 `role`과 같은 값이다. `attackStatus`가 `official_patch_input`이어도 `behavior`까지 공식 상수라는 뜻은 아니다. 예를 들어 통통유도볼의 공격 입력 304는 날짜·성급·레벨 조건을 가진 공식 패치 값이지만, 반사 2회와 계수 0.72는 별도로 정한 실행 모델이다.

`shots`는 한 번의 공격에 사용하는 기본 발사체 입력이다. `delivery=self`인 지원 행동은 기존 필드에 `shots=1`이 있어도 실제 발사체가 0개다. 화면의 현재 행동 안내는 엔진이 계산한 반복 수와 실제 발사체 수를 사용한다. 맹독박쥐는 기본 6발이며 BLUE3 서든데스의 3회 반복에서는 18발이다. 이는 이 프로토타입의 발사체 개수 계산이며, 원작의 확정 총 피해를 산출한 것이 아니다.

### 발사각과 파워의 추가 복원 범위

발사각 30행(JP13·KR13·3BLUE4), 파워 17행을 [별도 JSON](../dist/datasets/Fortress_AnglePower_Recovery.json)으로 제공한다. JP/KR 차이 5종, 한국 캐논의 보고 각폭25/산술 각폭20 모순, 공식 자료에서 확인되지 않은 3BLUE 각도와 모든 탱크의 원작 파워 곡선은 [각도·파워 복원 보고서](ANGLE_POWER_RECOVERY_KO.md)에 정리했다.

원작 파워 하한·상한, 완충 시간, 오버플로 방식, 탄속 곡선, 중력, 풍력, 탄중량은 `sourcePower`에서 모두 null로 유지한다. 현재 실행의 0–100 정규화 입력,72%p/초 왕복 충전과90–1050 속도 선형 변환은 별도 fallback이다. UI·AI·가이드·실제 발사는 같은 파워 범위와 양자화를 사용한다. 탱크별로 근거 없는 탄속 배율을 추가하지 않았다.

구 일본 매뉴얼의 [조작 설명](https://bandaigv.com/html/03_howto003.htm)에 나온 Space 충전, 목표·직전 파워 표식, 지형각과 조준각의 합성은 정성 규칙의 근거다. 정확한 빌드와 내부 좌표계는 별도 미확인 상태다. 구현의 좌우·경사 변환은 수학적 일관성을 검증한 프로토타입 좌표계이며 바이너리 복원치가 아니다. 원문 선택 화면의 POWER1·2는 [무기 공격력](https://www.4gamer.net/specials/fortress2/03.html)을 뜻하므로 발사 게이지 값이나 탄속으로 변환하지 않는다.

### 공격값을 실행에 연결한 방법

단발 무기는 문헌의 공격 숫자를 `attack` 입력으로 유지한다. 이 숫자를 실제 적 HP 감소량으로 단정하지 않는다. 엔진은 거리 감쇠와 전역 `damageScale` 등을 적용한다.

다탄 무기는 원문 공격 숫자의 의미가 발당인지 총합인지 불명확하다. 구현은 **표의 공격값을 구현 탄수로 균등 분배**한다. 예를 들어 캐롯의 두 번째 무기는 원문 570과 별도 기록된 3발을 보존하면서, 이 프로토타입의 발당 입력만 190으로 정한다. 190은 원작의 발당 공격력 복구값이 아니다. 다탄 숫자를 다시 곱해 원작의 확정 총 피해라고 주장하지 않는다.

| 무기 | 원문 공격값 | 사용 탄수 | 구현의 발당 입력 |
|---|---:|---:|---:|
| 캐롯 2번 | 570 | 3 | 190 |
| 멀티미사일 1번 | 650 | 3 | 216.6667 |
| 멀티미사일 2번 | 650 | 9 | 72.2222 |
| 슈퍼탱크 1번 | 900 | 3 | 300 |
| 슈퍼탱크 2번 | 850 | 9 | 94.4444 |
| 레이저 2번 | 270 | 3 | 90 |
| 세크윈드 2번 | 550 | 2 | 275 |

무기별 지형 파괴의 대·소 등급은 자료의 정성 정보이다. 이를 실제 픽셀 반경으로 복구하지 못했으므로 0–72픽셀의 구현 반경을 따로 정했다. 한국어 무기 버튼 이름은 편의 표기이며 원문 표의 공식 명칭으로 취급하지 않는다. 기본·특수 무기 추가 딜레이 100/200은 같은 2003년 딜레이 자료를 참고한다.

이동력은 문헌의 단위가 불명확하다. 카탈로그의 원문값은 유지하지만 엔진의 턴당 이동 예산은 **원문 이동력 × 2 월드 픽셀**이라는 별도 모델이다. 독·화염·지뢰·구속·유도·레이저의 지속시간, 발동 범위, 판정 순서는 구현 수준으로 간소화했다. 내성 글자를 무적이나 특정 피해 배율로 변환하지 않았다.

### 기존 패시브 모델의 명시

기존 엔진에 캐릭터 이름으로 들어 있던 두 동작을 카탈로그의 `passives`로 옮겼다. 새로운 원문 수치를 복구한 것이 아니라 이미 사용하던 구현 가정을 드러낸 변경이다.

| 캐릭터 | 실행 모델 | 출처 처리 |
|---|---|---|
| 세크윈드 | HP가 최대치의 50% 이하이면 공격 입력에 1.5배 적용 | `low_hp_attack_boost`, `simulation_assumption` |
| 레이저탱크·포세이돈 | 매설 지뢰의 접근 기폭을 일으키지 않음 | `mine_trigger_exemption`, `simulation_assumption` |

지뢰 기폭 제외는 지뢰 직격이나 다른 기체가 기폭시킨 폭발 피해까지 무효화하는 면역이 아니다. 세크윈드의 1.5배도 원문 공격 입력 400/275를 덮어쓰지 않고 발사 시 적용하는 모델이다. 포세이돈 물폭탄은 이동 구속을 적용하며 밀쳐내기 효과는 없다.

## BLUE3: 공식 HP가 확인된 4종

캐터펄트는 [2026-09-21 신규 캐릭터 공지](https://3blue.squadground.com/projects/fortress3blue/community/news/updates/1173), 나머지 3종은 [2026-05-27 공지](https://3blue.squadground.com/projects/fortress3blue/community/news/updates/31)의 HP와 딜레이를 사용했다. 소개표에는 기준 성급·레벨·모드가 없으므로 이를 0성·1레벨 수치라고 부르지 않는다.

| 캐릭터 | HP | 딜레이 | 원문 이동속도 | 구현 이동 예산 입력 |
|---|---:|---:|---:|---:|
| 캐터펄트 | 1,725 | 550 | 1.5 | 42 |
| 메카펀치 | 1,834 | 560 | 1.4 | 40 |
| 이블벨라 | 1,528 | 575 | 1.4 | 40 |
| 야구소년 | 1,528 | 555 | 1.4 | 40 |

이동속도 1.4/1.5는 출처 정보에 보존한다. 이를 원작 턴 이동 거리로 환산하는 공식은 없으므로 구현 예산 40/42는 독립적으로 정했다. 발사각도 프로토타입 조정값이다. 평균 AP 4/4.5처럼 폼 대응이 불명한 값을 임의로 해석해 넣지 않았다.

### 공식 공격 입력과 조정 공격 입력

[2026-08-07 패치](https://3blue.squadground.com/projects/fortress3blue/community/news/updates/771) 중 **턴 모드(2BLUE4K·3BLUE), 0성, 1레벨, 변경 후**라는 조건이 확인된 아래 세 값을 그대로 입력에 사용한다.

| 캐릭터·무기 | 변경 전 → 후 | 구현 입력 | 주의점 |
|---|---:|---:|---|
| 이블벨라·피의구슬 | 488 → 580 | 580 | 실제 HP 감소 공식은 별도 모델 |
| 이블벨라·맹독박쥐 | 84 → 73 | 발당 73, 6발 | 발당 수치가 명시됨. 전탄 총 피해는 미확정 |
| 야구소년·통통유도볼 | 363 → 304 | 304 | 원작의 바운스·다중 명중을 동일하게 구현한 값이 아님 |

이 세 입력은 현재 라이브 값이라는 보장이 없다. 소개 HP의 불명 성급과 무기의 0성·1레벨을 하나의 원작 캐릭터 상태로 검증한 것도 아니다. 서로 다른 날짜의 자료를 사용한 플레이 실험이라는 점을 카탈로그에 명시했다.

캐터펄트 3공격, 메카펀치 3공격, 벨라 궁극기·해제탄, 야구소년 기본·특수 공격의 공격값은 **튜닝**이다. 캐터펄트의 10월 패치에 나온 **탄 내구도**를 공격력으로 오인하지 않았다. 포트리스2나 포트리스M의 값을 대신 넣지 않았다.

| 이블벨라 · 흡혈박쥐떼 | 적을 추적하고 자신을 회복 | 적에게 실제로 감소시킨 HP의 25%. 최대 HP까지만 회복 |
| 야구소년 · 퉁퉁안타 | 지형 반사와 명중 시 밀쳐내기 | 반사 1회, 계수 0.72, 밀쳐내기 세기 65 |
| 야구소년 · 통통유도볼 | 적 추적과 지형 반사 | 반사 2회, 계수 0.72. 공식 공격 입력 304는 유지 |
| 이블벨라 · 유틸해제 | 적의 방어·공격 강화 효과를 지우는 지원탄 | 1회 처리, 더블·서든 반복 제외, 공격 입력 110은 모델 |

흡혈은 방어막에 흡수된 피해, 아군에게 준 피해, 지속 피해를 회복량에 포함하지 않는다. 원작의 관통·바운스·흡혈 공식을 재현했다는 뜻은 아니며, 위 효과의 비율과 기하 판정은 모두 `simulation_assumption`이다. 기존에 유도탄으로만 처리하던 흡혈박쥐와 반사 없이 발사하던 야구공에 구별되는 플레이 동작을 추가했다.

바운스는 지형에만 적용하며 탱크 접촉에서는 종료한다. 유도 대상은 적으로 제한하지만 일반 폭발 피해는 아군에게도 적용될 수 있다. 유틸해제의 버프 제거만 적에게 한정한다. 이러한 대상 필터도 별도의 실행 정책이다.

### 지원 스킬 단순화

각 캐릭터에는 네 가지 선택지가 있다. 일반·특수는 1라운드, 지원은 2라운드, 궁극기는 3라운드에 열리는 구현 규칙이다.

- 캐터펄트의 대형 물리방패는 지형 설치물 대신 개인 흡수막 320으로 단순화한다.
- 메카펀치의 플라즈마실드는 반사 계산 대신 개인 흡수막 360으로 단순화한다. 메카킥도 점프 이동 전체를 복원하지 않고 충격탄으로 표현한다.
- 이블벨라의 유틸해제는 착탄 범위 안 적의 지원 효과를 지우는 지원탄으로 표현한다. 추가 공격 입력 110, 해제 가능한 상태 목록과 범위 판정은 모델이다.
- 야구소년의 증폭기어는 범위 구조물 대신 자신에게 공격 1.2배·2턴 효과를 적용한다. 원문 20%는 모드가 명시되지 않은 표이므로 **3BLUE의 확정 효과로 승격하지 않는다**.

직접 적용하는 세 지원기는 `delivery=self`, 유틸해제는 `delivery=projectile`이다. 네 지원기 모두 `role=support`와 `repeatable=false`를 사용하므로 무기의 시각적 `kind`가 레이저인지 방패인지에 따라 반복 여부가 달라지지 않는다. 지원기는 자기 차례를 마친다.

## 공용 아이템 네 가지

| 도구 | 클래식에서 참고한 문헌 | BLUE3 적용 |
|---|---|---|
| 회복 | JP2003 소형 회복: 최대 HP 20%, 공격 전 사용 | 공식 희귀 회복약 0성·1레벨 변경 후 5%. 최대 HP를 분모로 쓰는 것은 구현 가정 |
| 방어막 | JP2003 SHIELD: 공격 1회 차단 | 프로토타입 도구. F3 원작 아이템 수치라는 주장 없음 |
| 더블 | JP2003 DOUBLE FIRE: 동일 각도·힘으로 2회 | 프로토타입 도구. F3의 별도 성장 계수는 적용하지 않음 |
| 이동탄 | JP2003 TELEPORT: 착탄점으로 자신 이동 | 프로토타입 행동. 안전 착지 보정은 구현값 |

출처는 [회복·방어](https://www.4gamer.net/specials/fortress2/07.html), [공격·이동 도구](https://www.4gamer.net/specials/fortress2/09.html), [회복 기준 상세](https://www.4gamer.net/specials/fortress2/14.html)와 [F3 아이템 패치](https://3blue.squadground.com/projects/fortress3blue/community/news/updates/31)이다. F3 아이템 표는 5월 27일 게시물의 **6월 5일 추가 내용**으로 구분한다.

각 탱크의 네 도구 1개씩 지급, 턴당 도구 1회 제한, 도구 추가 딜레이 200은 플레이 구성이다. 특히 JP2003 딜레이 문헌은 아이템 비용 100/200이 충돌하므로 200을 원작 확정값이라고 부르지 않는다. 회복량은 `profileValues.classic=0.2`, `profileValues.blue3=0.05`로 분리한다.

더블 도구를 준비할 때 재고를 차감하고 해당 차례의 추가 딜레이·아이템 사용 기회를 적용한다. 준비된 `status.double`은 지원기·이동탄·턴 넘기기·시간초과로 사라지지 않으며, 다음 `repeatable` 공격 발사 시 해제한다. BLUE3 서든데스에서는 이미 3회 반복하므로 새 더블 도구를 사용할 수 없다. 이미 준비된 효과와 서든 반복은 최대값 3으로 결합하며 6회로 곱하지 않는다. 이 예약·소비·반복 정책은 원문 스냅샷 밖의 실행 모델이다.

## 전투 시간과 맵

[공식 3BLUE 가이드](https://sites.google.com/view/fortress3blueguide/3blue)의 7+3턴과 서든데스 스킬 3회 반복을 참고했다. 문헌의 턴 카운터 단위는 명확하지 않으므로, 여기서는 **각 생존 캐릭터가 한 번 이상 행동한 묶음**을 1라운드로 정의한다. 8라운드부터 서든데스, 10라운드 제한이다. 원작의 정확한 턴 집계 방식을 검증한 결과는 아니다. 25초 행동 제한, 제한 종료 판정과 반복 간격은 구현 규칙이다.

클래식의 팀 크기 1/2/4 선택, 25초 제한, 9라운드 서든데스와 14라운드 제한도 프로토타입 구성이다. JP2003 스피드 모드의 15초를 다른 모드의 근거로 이식하지 않았다.

라운드 제한 종료 시 각 생존 캐릭터의 HP 비율 합과 생존 수 × 0.01로 점수를 비교하며, 같은 점수 또는 양 팀 전멸은 무승부로 처리한다. 무승부의 엔진 값은 `winner=-1`이다. 이 판정과 서든 환경 피해 역시 원작 상수로 복원한 것이 아니다.

바람의 능선(`highlands`), 부유 군도(`islands`), 황혼의 주조소(`foundry`)는 새로 만든 테마·시드·지형이다. 원작 맵의 이름, 지형 마스크, 스폰 좌표 또는 원본 이미지의 복구물이 아니다.

|---|---:|---|

풍향 갱신, 적 AI, 지형 충돌, 탱크 중심·지상 정착, 낙사, 원형 폭발, 상태효과, 발사 지연, 조준 보조는 구현 코드가 정한다. 원작의 중력·탄속·충돌 마스크·피해식이 복원되었다는 표시를 하지 않는다. 플레이어가 조정한 튜닝값은 원문 수치 스냅샷을 덮어쓰지 않아야 한다.

AI는 현재 위치의 무기별 후보를 평가하고 지원 스킬을 선택할 수 있다. 안전 이동이나 이동탄을 사용하는 위치 계획은 이번 구현 범위에 포함하지 않는다. 난이도와 후보 평가도 구현 정책이며 원작 AI의 복원 데이터가 아니다.
