# 클래시 오브 클랜 시스템별 상세 역기획서

> **기준일: 2026-11-13 KST · 한국어 · 공개 자료 기반**

클래시 오브 클랜을 **27개 본문**으로 나누어 분석했다. 목차·출처·용어집·검증 목록을 포함해 **Markdown 31개**와 출처 데이터 `sources.json`으로 구성되어 있다. 각 시스템의 목적, 규칙, 상태 전이, 데이터 구조, 예외, 전략·밸런스 의미, 재구현 검증 항목을 연결한다.

## 1. 문서의 성격

- **[확인]** 공식 공개 자료에서 확인한 규칙. 공개일·현재 적용 범위를 함께 표시한다.
- **[해석]** 그 규칙이 플레이어 선택과 경제·경쟁에 미치는 효과.
- **[제안]** 재구현을 위한 스키마·의사코드·서버 구조·UI·검증 계획.
- **[미확인] / [예고] / [과거]** 내부 구현 미공개, 출처 충돌, 적용 전 발표, 교체된 규칙.

Supercell의 내부 기획서나 소스 코드를 확보한 결과가 아니다. 실제 계정 플레이·성능 측정·전투 표본 수집도 수행하지 않았다. 지정된 나무위키 링크는 접근 오류로 본문 확인이 불가능하여, 공식 블로그와 지원 자료를 주 근거로 삼았다. 상세 기준은 [00 분석 범위](docs/00_scope_and_version_baseline.md)를 따른다.

## 5. 역기획의 주요 결론

### 5.1 전투 횟수와 성장 속도를 분리해 읽어야 한다

현재 구조를 분석할 때 과거의 병력 생산 대기를 기본 전제로 두면 실제 플레이 흐름을 놓친다. 반복 공격의 문턱은 낮아졌지만, 건설·연구·영웅·장비의 성장 계획과 경쟁 모드의 기회 제한은 별도 선택을 만든다. [04 경제](docs/04_resources_loot_and_economy.md), [05 편성](docs/05_army_composition.md).

### 5.2 병력 AI가 전략의 일부다

플레이어는 목표 건물과 진입 경로를 바꾸어 병력의 행동을 유도한다. 따라서 목표 후보·우선순위·재선정·장벽 처리를 단순한 이동 기능으로 보면 전투의 핵심을 놓친다. 문서는 관찰 가능한 행동과 내부 알고리즘 제안을 구분한다. [07 AI](docs/07_unit_ai_and_pathfinding.md).

### 5.3 개인 경쟁과 공동 경쟁은 다른 정산 모델이다

일반 전투, 주간 랭크, Legend I, 일반 클랜전, CWL, 수도가 같은 전투 결과를 서로 다르게 사용한다. 특히 방어 보완점과 방어 손실, 기지별 최고 기록과 누적 피해를 분리하는 것이 중요하다. [12 랭크](docs/12_ranked_leagues_and_tournaments.md), [14 전쟁](docs/14_clan_wars.md), [17 수도](docs/17_clan_capital_and_raid_weekends.md).

### 5.4 배치·편성·보상의 적용 시점이 데이터 구조를 결정한다

편집한 마을이 어느 대회부터 적용되는지, 전투 중 성장 완료가 현재 공격에 영향을 주는지, 결과 화면을 다시 열어도 보상이 한 번만 지급되는지를 먼저 정해야 한다. 이를 위해 출전 계약·스냅샷·원장·버전 구조를 제안했다. [24 아키텍처](docs/24_data_architecture_and_network.md).

### 5.5 장기 경제는 재화 외에도 시간·슬롯·참가 기회로 구성된다

금과 엘릭서가 충분해도 장인·연구·해금·공격권이 병목이 될 수 있다. 상품은 어떤 병목을 해소하는지에 따라 가치가 달라지므로 가격만 비교하지 않는다. [02 건설](docs/02_village_builders_and_construction.md), [03 성장](docs/03_progression_research_and_unlocks.md), [21 수익화](docs/21_monetization_and_magic_items.md).

## 6. 최신성 주의

기준일 이후 적용이 예고된 TH19와 새 별 보너스·Ranked Medals·Prestige Shop 등을 현행 규칙에 합치지 않았다. 일부 공식 지원 자료와 패치의 차이는 해소되지 않은 채 남아 있으므로 [충돌 목록](references/03_uncertainties_and_validation.md)을 함께 읽는다.

모든 병력·건물의 전 레벨 능력치 도감은 이 묶음의 범위가 아니다. 대신 수치가 들어갈 데이터 필드, 계산 관계, 버전 관리, 확인이 필요한 경계 조건을 상세히 제공한다.

## 7. 파일 사용법

ZIP을 풀면 이 README와 `docs/`, `references/`가 같은 폴더에 놓인다. 상대 링크를 유지하려면 폴더 구조를 함께 보관한다. Mermaid 지원 Markdown 뷰어에서는 상태도·구조도가 렌더링되며, 미지원 뷰어에서는 다이어그램 정의가 코드로 표시될 수 있다. 본문 표와 설명만으로도 규칙을 읽을 수 있도록 작성했다.
