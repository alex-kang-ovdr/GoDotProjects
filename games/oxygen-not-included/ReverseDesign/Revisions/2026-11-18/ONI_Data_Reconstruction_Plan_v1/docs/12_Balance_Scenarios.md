# 12. 수치 검산과 운영 시나리오

이 문서의 계산은 공개 참조값을 이용한 **설계 검산**이다. 원작이나 새 웹 엔진에서 이 기지를 직접 장기간 실행한 결과가 아니다. 현재 4.0의 과거 71개 회귀 검사와도 별도다. `node tools/balance-math.mjs`로 주요 결과를 재계산할 수 있다.

## 1. 인구당 호흡 예산

기본 일반 대원의 산소 소비는 0.1kg/s, 기본 칼로리는 1,000kcal/cycle이며 주기는 600초라는 공개값을 사용한다. 특성·난이도·바이오닉 대원은 이 계산에서 제외한다. [C01](https://oxygennotincluded.wiki.gg/wiki/Duplicant) · [R06](https://oxygennotincluded.wiki.gg/wiki/Cycle)

| 대원 | 산소/초 | 산소/주기 | 음식/주기 |
|---|---:|---:|---:|
| 3명 | 0.3kg | 180kg | 3,000kcal |
| 8명 | 0.8kg | 480kg | 8,000kcal |
| 12명 | 1.2kg | 720kg | 12,000kcal |

질식 위험은 평균 산소 생산만으로 판단하지 않는다. 생산실에서 실제 생활 공간까지 전달되지 않은 산소, 저장통 안에 있지만 대원이 가져갈 수 없는 산소는 당장의 생존 공급이 아니다.

## 2. 전해 장치와 실제 가동률

공개 참조값은 물 1kg/s → 산소 0.888kg/s + 수소 0.112kg/s, 전력 120W다. [F02](https://oxygennotincluded.wiki.gg/wiki/Electrolyzer)

- 한 주기 최대 물 소비: 600kg.
- 한 주기 산소: 532.8kg, 수소: 67.2kg.
- 연속 정상 가동의 산소 지원 능력: `0.888 / 0.1 = 8.88명`.
- 8명을 지원하는 최소 가동률: `0.8 / 0.888 ≈ 90.09%`.
- 그 조건의 최소 물: 약 540.54kg/cycle.

8명이라는 표시는 설비가 충분히 가동되고 산소가 대원에게 전달될 때만 성립한다. 출력 막힘·수소 축적·과압·정전·냉각 중단의 합으로 가동률이 90% 아래로 내려가면 평균 공급부터 부족해진다.

## 3. 수소 발전 상한을 고려한다

수소 발전기는 공개 기준 0.1kg/s에서 최대 800W다. 전해 한 대의 수소 전량 0.112kg/s를 활용한 잠재값 `896W`는 **발전기 한 대의 출력이 아니다**. [F09](https://oxygennotincluded.wiki.gg/wiki/Hydrogen_Generator)

| 조건 | 계산 결과 | 필요한 운영 |
|---|---:|---|
| 발전기 1대의 상한 | 800W | 추가 수소를 저장/다른 곳으로 이동 |
| 남는 수소 | 0.012kg/s = 7.2kg/cycle | 영구 누적 시 전해 출력이 막힘 |
| 수소 전량 사용 가능 | 평균 896W 잠재 | 여러 발전기 또는 적절한 시간 버퍼·부하 |

펌프가 충분한 양의 패킷을 모아 이상적으로 켜졌다 꺼진다는 가정에서, 산소·수소·물 펌핑과 전해 자체의 평균 부하는 624W다. 그러므로 잠재 순전력은 여러 발전기를 이용할 때 272W, 한 대일 때 176W와 수소 누적이다. 기체 필터·누설·기동 에너지·배터리 손실·냉각은 제외했다. [설비 계산 JSON](../data/balance-scenarios.json)

UI에 “자립”을 표시하려면 이론값이 아니라 관측 구간의 발전−소비−손실, 산소 생산−호흡, 수소 저장 여유, 출구 막힘률, 온도 추세를 함께 보여줘야 한다.

## 4. Mealwood 생존 농업

Mealwood는 공개 기준 3주기마다 600kcal를 생산해 즉시 수확하는 이상 조건에서 200kcal/cycle이다. 흙은 10kg/cycle이 필요하다. [C38 Mealwood](https://oxygennotincluded.wiki.gg/wiki/Mealwood)

3명은 이론상 최소 15그루와 흙 150kg/cycle이 필요하다. 수확 지연·온도·부패 때문에 실제 계획에는 여유가 있어야 한다. 유효 생산률을 **설계 가정 85%**로 잡은 계산 예는 `ceil(3000 / (200×0.85)) = 18그루`다. 85%는 원작 상수가 아니며 플레이 테스트에서 얻어 교체할 입력이다.

따라서 “물 없이 자라는 작물”과 “외부 공급 없이 지속 가능한 작물”은 다르다. 흙 3,000kg이 있고 15그루를 연속 운영한다면 농업만으로 20주기분이며 초급 연구의 흙 소비를 더하면 줄어든다. 흙 재고와 연구 선택의 기회비용을 같은 대시보드에서 보여줘야 한다.

## 5. 조리 레시피는 재료의 개수와 kcal를 함께 본다

Liceloaf의 선택한 참조는 Meal Lice 2개와 물 50kg → 1,700kcal다. 원재료 1,200kcal 대비 증가 500kcal이지만 물·전력·노동을 사용한다. 일부 작물 페이지에는 재료 수량이 다르게 적혀 있어 레시피 전용 근거를 우선하고 충돌을 남겼다. [C26 Liceloaf](https://oxygennotincluded.wiki.gg/wiki/Liceloaf) · [레시피 데이터](../data/colony-records.json)

Sleet Wheat 18개 수확은 18개의 Frost Bun이 아니다. 곡물 3개당 빵 1개이므로 18개 → 빵 6개 → 7,200kcal, 18주기 생장 기준 평균 400kcal/cycle이다. 종자 보존·수확 지연·조리 노동을 제외한 상한이며, 재파종에 쓸 종자를 음식에 전부 쓰는 상황도 별도 고려해야 한다.

## 6. 위생 순환의 추가 물질

공개 참조 Lavatory는 사용당 물 5kg을 받아 오염된 물 11.7kg을 만든다. 차이 6.7kg은 질량이 보존되는 순수 물 교환식이 아니므로 대원 생물학적 생성항으로 기록한다. [C21](https://oxygennotincluded.wiki.gg/wiki/Lavatory)

대원 3명이 주기마다 각 1회 이용한다는 가정에서는 추가량 20.1kg/cycle이다. 세면대의 사용량, 정화에 필요한 여과재, 병원균, 물 저장 공간은 별도다. “정화가 물질을 Water로 바꿈”과 “미생물이 제거됨”을 같은 이벤트로 처리하면 안 된다.

Carbon Skimmer와 Water Sieve의 물 흐름만 연결한 이상적 계산은 청수 순변화 0이지만 여과재를 소비하고 오염된 흙을 만든다. 따라서 자원 전체의 폐회로가 아니다. 레시피 원장과 장기 여과재 재고를 같이 계산한다.

## 7. 냉각과 열 이동

물 10kg을 14°C 낮출 때 냉각 유체에서 빠지는 열은 585,060DTU다. 제안 엔진은 이 열을 설비 본체/주변 열 원장으로 보낸다. 냉각기가 설정 온도까지 공기를 무조건 깎는 현재 규칙은 이 루프를 만들 수 없다. [F20](https://oxygennotincluded.wiki.gg/wiki/Thermo_Aquatuner) · [R21 물](https://onidb.wiki/elements/water)

이상적인 터빈 예제 2kg/s·200°C → 95°C 물에서는 유체 열 차가 877.59kDTU/s다. 공개 참조의 본체 반납률·고정 발열을 적용한 계산은 별도 JSON에 있다. 터빈 850W 상한, 흡입구 개수, 본체 온도와 출력 정지는 추가 제약이다. 계산 결과를 아무 조건에서나 달성하는 발전량으로 표시하지 않는다.

## 8. 운영 완료를 판단하는 지표

| 지표 | 의미 |
|---|---|
| 공급 가동률 | 설비의 관측 시간 중 실제로 입출력한 비율 |
| 순생산 | 생산−최종 소비−명시적 손실−부패 |
| 위치별 예비량 | 생활 구역·작업 구역까지 전달 가능한 비축 |
| 자원 고갈 예상 | 남은 양/관측 순소비. 순생산 양수는 별도 표시 |
| 열 추세 | 생활 구역 평균·최고 온도 변화와 작물 한계까지 여유 |
| 노동 부담 | 생산·운반·이동·생활·대기 시간 분포 |
| 위기 복구 | 전력/물/관/문 장애 후 복귀 시간과 손실 |

평균값과 최악 조건을 같이 본다. 정상 상태 30주기를 통과해도 방 한 개를 잠갔을 때 전원 질식하거나, 출력관 1칸 파손으로 자원이 복제되면 완성으로 판정하지 않는다.
