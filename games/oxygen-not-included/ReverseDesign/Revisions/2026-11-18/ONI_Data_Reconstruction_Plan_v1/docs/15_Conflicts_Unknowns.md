# 15. 충돌 데이터·결측·후속 복원 목록

## 1. 모든 빈칸을 숫자로 채우지 않는다

복원 데이터의 `null`은 실패를 숨기기 위한 표기가 아니라 확인한 범위를 보존하는 장치다. 0은 무료·무소모·불가능 등 실제 규칙일 수 있으므로 미확인 값에 사용하지 않는다. 이 묶음의 정확한 필드 수와 결측 개수는 [coverage.json](../reports/coverage.json)에 생성한다.

## 3. 이번에 수치를 확정하지 않은 영역

- 원작 전체 기술 트리의 노드별 유형 비용·선행 연결·DLC 분기.
- 대원 경험치 곡선, 각 기술·특성의 세부 수치, 스트레스 확률과 내부 작업 점수.
- 방 가구 태그 전체와 일부 최소 높이·효과 지속 조건.
- 식품 전체의 부패 반응·원소별 대기 보관 효과·세균 오염 속도.
- CPR 제한 시간·작업 시간·회복량·연속 구조 조건.
- 간헐천 분포·월드 seed별 배치 알고리즘·바이옴 질량 생성 분포.
- 모든 크리터의 먹이·번식·행복·야생성·전환 확률.
- 원작의 셀 교환 우선순위·유체 displacement·열 특수 규칙과 부동소수 경계.
- 우주·방사선·다중 소행성·바이오닉·수중 DLC의 전체 데이터.

후속 수집은 기능별 표에 ID를 먼저 만들고, 값 없는 필드를 그대로 남겨 연결을 추적한다. 복원 전용 UI는 결측을 눈에 띄게 표시하며 데이터 승인 전 게임 규칙으로 내보내지 않는다.

## 4. 추가 검증 기록 양식

```json
{
  "entityId": "room.great_hall",
  "field": "required",
  "targetBuild": null,
  "branch": "public",
  "dlcEnabled": [],
  "mods": [],
  "method": "controlled_ingame_observation",
  "setup": "같은 방에서 여가시설 하나만 추가/제거",
  "before": null,
  "after": null,
  "conclusion": "pending",
  "evidenceFiles": []
}
```

양식의 예시를 실행 완료 기록으로 채우지 않았다. 실제 원작 실행 결과가 제공되면 source registry에 새 근거를 추가하고 충돌 상태를 변경한다.

## 5. 완료 판정

이 r1의 완료는 **조사한 사실과 현재 구현을 구분해 데이터화하고, 개선 순서와 수용 기준을 제시하며, 데이터 검산을 재현 가능하게 제공한 상태**다. 전체 원작 내부 데이터 복원, 새 엔진 구현, 원작과 동일한 플레이 검증은 각각 별도의 완료 기준이다.
