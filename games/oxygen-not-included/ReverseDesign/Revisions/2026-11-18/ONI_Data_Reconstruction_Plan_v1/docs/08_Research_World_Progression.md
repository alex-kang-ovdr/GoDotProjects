# 08. 연구·월드·확장 진행 기획

## 1. 현재 목표 진행과 연구를 분리한다

숨 4.0의 연구는 총점 0–100과 설비별 해금 임계값이며 승리는 5단계·20개 목표를 달성하는 흐름이다. 이 방식은 플레이 가능한 압축 캠페인으로 유지할 가치가 있지만, 기술 선택에 따른 자원·시설·인력의 기회비용을 충분히 표현하지 못한다. 현행 규칙의 출처는 [코드 감사](02_Current_Implementation_Audit.md)에 있다.

원작의 초급 연구는 흙을 소모하며 연구 유형과 설비가 나뉜다. 초급 1포인트당 흙 50kg라는 공개 기준을 먼저 복원했다. [R12](https://oxygennotincluded.wiki.gg/wiki/Novice_Research) 고급 연구와 일부 초기 노드는 [대원·생활 데이터](../data/colony-records.json)에 있으며, 전체 원작 기술 트리를 복원했다고 주장하지 않는다.

## 2. 기술 노드 계약

```js
Technology = {
  id, nameKey, contentScope, requiredTechIds,
  pointCosts: { novice: 0, advanced: 0 },
  unlockedBuildingIds, unlockedRecipeIds,
  evidenceIds, sourceBuild,
};
ResearchState = {
  selectedTechnologyId,
  completedTechnologyIds,
  deliveredPointsByTechnology,
};
```

포인트는 연구 작업의 산출물이다. 연구 중인 노드가 바뀌어도 이미 전달된 포인트는 해당 노드에 남는다. 흙/물 등 실제 자원은 작업 입력 버퍼에서 소비하며, 작업 취소·정전·동일 명령 재전송이 중복 포인트를 만들지 않는다. 연구자는 작업 자격과 도달 가능한 연구 설비가 있어야 한다.

기술 노드와 목표는 다르다. 기술은 사용 가능한 설비·제작법을 결정하고, 목표는 플레이어가 이미 사용한 생산·생활 시스템의 안정성을 점검한다. 연구 점수를 얻기만 하면 즉시 자원 보상이 생기는 구조는 별도 캠페인 정책으로 표시한다.

## 3. 웹판 제안 연구 경로

아래 경로는 **새 구현의 권장 구성**이다. 원작 노드의 정확한 선행 관계나 비용을 복원한 표가 아니다. 미확인 비용은 채우지 않았다.

| 경로 | 플레이어가 해결하는 문제 | 새로 요구되는 운영 |
|---|---|---|
| 기본 농업 | 초기 식량 감소 | 종자·흙·수확 동선 |
| 급수와 위생 | 공용 물·용변·세면 | 배관 입력·출력·오수 저장 |
| 환기와 정화 | CO₂ 축적과 대기 분리 | 기체 펌프·배출·여과 |
| 발전과 제어 | 수동 노동을 발전에 과도하게 사용 | 연료 배송·축전·자동화 |
| 가공 식품 | 음식 품질·노동·부패 | 조리 레시피·식당·냉장 저장 |
| 물 기반 산소 | 조류 고갈 | 전해·수소 처리·열 관리 |
| 금속과 냉각 | 산업 폐열·고온 구역 | 재료 선택·냉각 루프 |
| 탐사와 보호 | 원거리 저산소 작업 | 장비 충전·복귀·구조 작업 |

검증되지 않은 큰 기술 트리보다, 선택의 비용이 다른 두 갈래를 실제로 만들고 막힘 원인을 설명하는 UI를 우선한다. 기술 선택 화면에는 필요한 자원/연구 시간의 예상치, 해금 설비, 선행 기술을 함께 표시한다.

## 4. 월드 데이터 복원 절차

현재 제공된 자료에는 원작 월드 생성 원본이 없다. 바이옴의 목록이나 겉보기 비율을 보고 실제 spawn weight·노이즈 파라미터·간헐천 확률을 역산한 값처럼 적지 않는다. 새 월드 생성 데이터에는 `seed`, `generatorVersion`, `worldProfile`, `biomeDistribution`, `resourceBudget`, `guarantees`를 둔다.

초기 웹판에는 다음 보증을 제안한다.

- 시작 대원과 초기 생활 공간이 연결된다.
- 초기 식량·호흡·건설 자원이 명세된 최소 생존 시간 이상을 제공한다.
- 필수 자원을 열기 위해 그 자원으로만 만드는 장비가 먼저 필요한 순환 의존이 없다.
- 각 원정 구역은 위험과 회수 가능한 자원 가치가 다르다.
- 고정 생성원을 두더라도 외부 자원 유입량을 원장에 명시한다.

보증은 지형을 항상 쉽게 만드는 의미가 아니다. 운반 거리·온도·유체·암석 경도·예비 자원의 조합을 조절해 실패 원인이 관찰되게 한다. 최소 생존 시간 수치는 원작값을 추측하지 않고 새 웹 프로파일의 플레이 테스트로 정한다.

## 5. 간헐천과 장기 저장

원작별 분출률·분출 기간·휴면 기간의 전체 범위는 미복원이다. 설계 데이터는 `eruptionRateKgS`, `eruptionDurationS`, `eruptionPeriodS`, `activeDurationS`, `activityPeriodS`, `temperatureC`, `overpressureKgPerCell`로 제안한다. 값과 범위를 같은 필드에 섞지 않는다.

평균 공급률을 계산하는 일반식은 `분출률 × 분출 가동률 × 활동 가동률`이다. 공급원이 꺼진 가장 긴 구간을 버티려면 단순 평균 잉여가 아니라 **누적 공급−누적 수요의 최저점**으로 저장 용량을 구해야 한다. 저장량 계산기는 시뮬레이션 시간표를 만들어 그 최대 적자를 출력하도록 계획한다.

## 6. 생물 사육과 산업 후반부

크리터는 먹이·수명·행복·번식·공간·생산물을 연결하는 후속 축이다. 이번에는 해치·드레코·물고기 전체 수치표를 임의로 만들지 않았다. 복원 우선 필드는 `foodOptions`, `conversionRates`, `caloriesPerCycle`, `reproduction`, `wildness`, `roomSpacePerCritter`, `temperatureRange`, `dropTables`다. 사육 규칙의 버전별 변경 가능성이 있으므로 오래된 단일 고정 번식 배율은 사용하지 않는다.

원유·석유·플라스틱·강철·터빈은 하나의 후반부 체인으로 설계한다. 중간 생성물을 생략한 자동 교환을 피하고, 생산물이 실제로 축적되어야 다음 공정이 시작된다. 우주·방사선·다중 소행성은 이 체인이 안정화된 뒤 별도 콘텐츠 프로파일로 확장한다.

## 7. 캠페인 완료 기준

원작에 없는 웹판 목표는 원작 규칙으로 표기하지 않는다. 기존 20개 목표는 legacy 캠페인 기록으로 유지하고, 새 목표는 규칙 세트 버전과 함께 별도로 정의한다. 완수의 핵심은 특정 건물을 건설했는지가 아니라 해당 공급·소비 흐름이 실제로 작동했는지다.

새 캠페인은 초기 생존 → 물류·위생 → 독립 산소 → 열·전력 안정 → 보호 장비 확장 순으로 제안한다. 각 단계에서 최근 관측 구간의 순생산, 저장 여유, 접근 가능성, 실제 이용 이력을 요구한다. 판정 수치와 유지 시간은 새 프로파일의 설계값이며 이 문서에서 원작 수치로 결정하지 않는다.
