# 03. 원소·대기·액체·열 시뮬레이션 고도화

## 설계 판단

현재의 산소·CO₂ 공간값과 온도 직접 증감을 **물질 종류·질량·열 상태가 있는 셀**로 옮기는 것이 가장 큰 구조 변경이다. 원작의 주 환경 셀은 한 칸에 한 종류의 물질이 차지하는 규칙을 사용한다. 바닥 잔해, 건물, 배관은 별도 레이어이다. [R07](https://oxygennotincluded.wiki.gg/wiki/One_element_per_cell_rule)

원작의 모든 예외를 처음부터 흉내 내기보다, 단일 물질 셀과 명시적인 변환 원장을 우선 구현한다. 아래 알고리즘은 **웹판 개선 설계**이며 원작 내부 소스의 복원이 아니다.

## 1. 재구성한 물성 기준표

비열 단위는 `DTU/(g·°C)`, 열전도도 단위는 `DTU/(m·s·°C)`다. 다음 값은 공개 문서 스냅샷이며 빌드 고정 실측값이 아니다. 상세 필드 출처와 표시 전이점은 [elements.json](../data/elements.json)에 있다.

## 2. 셀 데이터 계약

```js
// 제안 스키마. 제품 코드에는 아직 적용되지 않았다.
Cell = {
  elementId,         // vacuum | oxygen | water | sandstone ...
  massKg,            // 주 환경 셀의 질량
  temperatureC,      // 실제 단일 온도; 열교환은 열량으로 계산
  germSpeciesId, germCount,
  flags,             // 공간 노출, 탐사, 고체 연결 등
};
```

건물 본체·건물 내부 재료·바닥 잔해·관 속 패킷은 같은 셀의 공기와 별도의 질량과 온도를 갖는다. `globalStock`는 UI용 합계이며 소비 권한을 주는 원장이 아니다. 원소 정의에 열용량이 없으면 임의의 기본값을 넣지 않고 해당 기능을 검증 대기로 차단한다.

## 3. 대기 이동과 압력

질량 이동은 출발 셀에서 뺀 양과 도착 셀에 더한 양을 같은 거래로 처리한다. 같은 기체 사이에는 질량 차이를 줄이는 교환을, 다른 기체에는 정해진 순서의 위치 교환 또는 인접 공간 배치를 사용한다. 수소·산소·CO₂의 상대 배치를 제어하는 규칙은 데이터화하되 실제 대기의 이상기체 혼합처럼 표시하지 않는다.

화면의 `산소 82%`처럼 의미가 불분명한 값은 **산소 1.45kg/칸**, **호흡 가능/불가**, **최근 1주기 생산·소비**로 대체한다. 물질 간 무게 순서, 타일당 압력 한도, 과압 체크 위치는 별개다. 장치의 과압 기준에 지형 전체 평균값을 사용하지 않는다.

기체 방출 위치가 막히면 가능한 이웃으로 한 번 이동시킨 후, 공간이 없으면 작동을 대기시킨다. 폐쇄 공간에 밀어 넣다가 기체를 조용히 삭제하지 않는다. 원작의 기체 삭제·무한 저장 기법까지 재현할지는 별도 호환 옵션으로 결정하며 기본 구현 수용 기준에는 넣지 않는다.

## 4. 액체와 상변화

액체는 아래 방향 이동을 먼저 평가하고 같은 높이로 퍼진다. 청수·오수 레이어 두 개가 같은 칸을 독립 점유하는 모델을 주 환경에서는 사용하지 않는다. 실제 액체의 종류와 병원균은 구별한다. 깨끗한 원소 Water에 병원균이 있을 수 있고, Polluted Water를 청수로 바꿨다고 멸균했다고 판정하지 않는다.

상변화는 `fromElement → [{toElement, massFraction}]`로 정의한다. 오염된 물의 공개 DB는 가열 후 증기 99%와 흙 1%를 표시한다. [R24](https://onidb.wiki/elements/polluted-water) 이 비율의 합은 검증하되, 반올림된 표시 온도를 정확한 내부 임계값으로 사용하지 않는다. 온도 히스테리시스, 최소 질량, 잠열·열용량 전환 방식은 추가 검증 항목이다.

전이 후 배치할 공간이 없으면 예약된 물질을 내부 버퍼에 보존하거나 변환을 대기시킨다. 고체 생성·녹음으로 길이 막히면 경로와 방 캐시를 함께 무효화한다. 상태 변화와 UI는 동일 이벤트에서 갱신한다.

## 5. 열량 기반 계산

같은 원소의 질량 `m kg`, 비열 `c DTU/(g·°C)`에 열 `Q DTU`를 추가하면:

`C = m × 1000 × c` 및 `ΔT = Q / C`.

따라서 물 10kg을 14°C 낮추면 이동하는 열은 `10 × 1000 × 4.179 × 14 = 585,060 DTU`다. 이 값은 원작 아쿠아튜너 처리량과 연결한 계산 사례이며 주변 공기 온도를 임의로 낮추는 규칙과 다르다.

제안하는 기본 열교환은 접촉쌍마다 한 번 계산한다. 두 대상에 더하고 빼는 Q가 같아야 한다. 4방향을 동시에 계산할 때는 각 접촉에 `min(Ca, Cb) × abs(Ta-Tb) / 4` 이하의 교환 한도를 두고 새 버퍼에 반영해 음의 열용량·과도한 온도 역전을 방지한다. 전도 계수의 접촉 면적·거리 계수는 웹판 명세로 고정한다. 원작은 타일·잔해·건물·단열관 등에 서로 다른 열교환 규칙을 쓰므로 단일 식이 원작의 완전 복원이라고 설명하지 않는다. [R08](https://oxygennotincluded.wiki.gg/wiki/Thermal_Conductivity)

전력 소비 `J`와 열 `DTU`는 서로 다른 게임 원장이다. 소비 전력 전체를 자동으로 폐열로 바꾸지 않는다. 레퍼런스에 명시된 장치 발열과 유체가 운반하는 열량을 별도로 기록한다.

## 6. 의미 있는 검증

| 재현 장면 | 통과 조건 |
|---|---|
| 문으로 분리한 두 기체실 | 닫힘 시 교환 0, 열 교환은 재료 규칙 적용 |
| 문 열기·폐쇄 | 질량 총계와 열 상태 보존, 방/경로 캐시 갱신 |
| 수소·산소·CO₂ 기둥 | 동일 seed·명령에서 동일 결과, 기체의 이중 점유 없음 |
| 10kg 물의 열교환 | 계산 Q가 양쪽 원장에서 같고 반대 부호 |
| 급격한 온도차·극소 질량 | NaN/Infinity/음수 질량 없음, 온도 최대 원리 검사 |
| 물·얼음·증기 반복 전이 | 입력 질량과 제품 합계 일치 또는 명시적 예외 원장 |
| 탐사·비탐사 경계 | 비탐사 영역을 UI에 노출하지 않아도 시뮬레이션 규칙은 동일 |

정확한 전도·상변화 복원은 이 결과를 고정 빌드 원작 관찰과 대조한 뒤 승인한다. 이번 검증 도구는 데이터의 참조·단위·산술을 확인하며 이 새로운 시뮬레이터가 이미 구현됐다고 판정하지 않는다.
