# 숨 4.0 — 방, 출입문과 안전한 확장

이 문서는 브라우저 게임 **숨 · Breath Colony 4.0**에서 실제로 동작하는 방 분류, 기밀문, 휴대 산소, 기술 성장과 5단계 목표를 설명합니다. 게임을 하는 사람에게는 설계·진단 안내서이며, 코드를 수정하는 사람에게는 화면과 시뮬레이션 사이의 규칙을 확인하는 문서입니다.

숨은 *Oxygen Not Included*에서 영감을 받은 독립적인 소규모 시뮬레이션입니다. 여기의 방 규격, 산소 수치, 시설 크기, 성장 속도는 이 프로젝트의 규칙입니다. 원작의 전체 물성, 장비·수트, 방 판정, 질병·우주 탐사를 재현한 것으로 해석하지 마세요. 산소는 게임 내부 수치이며 실제 질량·기압 단위로 환산하지 않습니다.

주요 근거 코드는 [방·산소·기술 엔진](../dist/frontier.js), [기본 시뮬레이션](../dist/engine.js), [생활·물류 엔진](../dist/community.js), [배관·생활 유지 엔진](../dist/utilities.js), [화면 조작](../dist/app.js), [Canvas 표현](../dist/renderer.js)입니다. 아래 수치는 이 코드의 4.0 규칙을 기준으로 합니다.

## 1. 확장을 시작하는 순서

1. 기지의 산소, 식품, 청수와 화장실·세면대 운영을 안정시킵니다. 방을 만드는 동안에도 기존 생산과 대원의 생활은 계속됩니다.
2. 침상과 식탁을 각각 작은 방으로 나눕니다. 벽은 자연 지형 또는 완공된 타일, 출입구는 완공된 기밀문으로 만듭니다.
3. **구역 탭**과 **R 구역 보기**에서 침실·식당의 유효 여부를 확인합니다. 이름만 침실인 상태와 실제 보너스가 적용되는 상태는 구분됩니다.
4. 생산적인 작업으로 얻은 기술 포인트를 **대원 카드 → 기술**에서 합계 3개 배분합니다. 포인트를 보유하기만 해서는 배분 목표가 진행되지 않습니다.
5. 연구 45를 달성하고 산소가 충분한 생활 구역에 산소 충전소를 설치합니다. 압축에는 8W와 실제 주변 산소가 필요합니다.
6. 대원이 충전소에 방문해 휴대통을 채운 뒤, 귀환할 수 있는 저산소 작업 구역으로 이동합니다. 실제로 휴대 산소를 사용한 시간을 합계 30초 확보합니다.
7. 생활 안정과 방·기술·충전소 접근 조건을 **180초 연속** 유지합니다. 구역 탭에 표시되는 현재 미충족 사유를 해결하면서 시간을 이어갑니다.

공사 전에는 시간을 멈추고 계획을 확인할 수 있습니다. 채굴로 나온 고체는 현장 더미에 남고 대원이 코어·보관함으로 운반해야 건설 재고가 됩니다. 긴 벽을 한꺼번에 닫기 전에 공사 대원의 출입 경로, 사다리와 바닥을 확보하세요. [관련 구현](../dist/engine.js) · [운반과 교대](../dist/community.js)

## 2. 기밀문은 공간과 이동을 어떻게 나누나

### 건설 조건

| 항목 | 실제 규칙 |
|---|---|
| 시설 | 기밀문 `door`, 1칸 |
| 자원 | 광석 6 + 금속 4 |
| 연구 | 시작부터 건설 가능 |
| 위치 | 탐사한 빈칸, 다른 시설·작업과 겹치지 않는 위치 |
| 바닥 | 문 바로 아래에 단단한 바닥이 있어야 예약 가능 |
| 전력 | 필요 없음 |
| 제어 | 시설을 선택한 뒤 정보 탭의 출입문 모드 선택 |

미완공 청사진은 완공된 출입문 역할을 하지 않습니다. 문은 일반 설비의 가동·정지 버튼 대신 출입 모드로 제어합니다. [건설 판정](../dist/engine.js) · [문 제어](../dist/frontier.js)

### 세 가지 출입 모드

| 모드 | 대원 이동 | 실제 개폐 | 산소·이산화탄소·지형의 물 |
|---|---|---|---|
| 자동 출입 `auto` | 통과 가능 | 살아 있는 대원이 근처에 있거나 바로 통과하려 하면 열리고, 그 외에는 닫힘 | 실제 문이 열려 있는 동안 통과 |
| 열어 두기 `open` | 통과 가능 | 열린 상태 유지 | 통과 |
| 잠금 `locked` | 통과 불가 | 닫힌 상태 유지 | 통과 불가 |

살아 있는 대원이 **문 칸 안에 서 있으면 잠금이 거절**됩니다. 다른 칸으로 지나간 뒤 잠그세요. 잠금으로 막힌 예정 경로는 다시 확인되므로, 필수 시설로 가는 유일한 문을 잠그면 작업·생활 접근과 확장 유지 시간이 영향을 받습니다.

닫힌 문은 그 칸과 주변 칸 사이의 기체·물 교환을 막습니다. 문 칸에 이미 있던 유체를 삭제하지 않으며, 열전도는 계속됩니다. 전선·청수관·오수관은 별도 층이므로 문을 지나 연결할 수 있습니다. 기밀문 하나가 자동 온도 차단이나 배관 차단 장치까지 대신하지는 않습니다. [유체·이동 경계](../dist/frontier.js) · [환경 처리](../dist/engine.js)

### 열린 문과 방 경계는 서로 다른 판정

**방을 구분할 때는 완공된 문이 항상 구조적 경계입니다.** 자동문이 대원에게 잠깐 열리거나 열림 유지 모드여도 침실·식당의 면적이 합쳐지지 않습니다. 반면 기체와 물은 그 순간의 실제 열림 상태를 따릅니다.

따라서 열린 문을 둔 침실이 유효한 방으로 표시되면서도 산소가 옆 복도로 퍼질 수 있습니다. 이 동작은 의도된 규칙입니다. 방 보너스를 위한 구획과 실제 공기·물 흐름을 함께 살피려면 **R 구역 보기**와 **O 산소 보기**를 번갈아 확인하세요. [방 분석과 실제 개폐 상태](../dist/frontier.js)

## 3. 방이 유효해지는 조건

### 모든 방에 공통인 조건

- 내부는 탐사한 비고체 칸을 상하좌우로 연결해서 구합니다. 대각선 접촉만으로 두 공간이 이어지지는 않습니다.
- 자연 지형과 완공된 타일은 벽입니다. 완공된 문은 내부 면적에 포함되지 않는 출입 경계입니다.
- 시설이 놓인 비고체 칸은 내부 면적에 포함됩니다. 침상·식탁·농장을 둔다고 그 칸의 면적이 사라지지 않습니다.
- 내부 면적은 **6~64칸**이어야 합니다.
- 경계에 **완공된 문이 1개 이상** 있어야 합니다.
- 지도 끝 또는 아직 탐사하지 않은 비고체 공간으로 열려 있으면 밀폐 조건을 만족하지 않습니다. 미탐사 동굴의 모양은 미리 알려주지 않습니다.
- 용도를 결정하는 시설은 **완공되고 사용 중인 시설**이어야 합니다. 청사진이나 수동 정지한 시설은 해당 용도의 활성 시설로 세지 않습니다.
- 함께 두면 안 되는 시설은 **완공된 시설의 존재 자체**를 확인합니다. 산업 설비나 부적합 시설을 수동 정지해도 같은 방에 남아 있으면 제외 조건이 유지됩니다.

사다리는 이동 수단이며 벽이 아닙니다. 내부에 사다리를 두는 것은 가능하지만, 사다리 통로가 위아래의 넓은 동굴과 연결되어 있으면 그 공간까지 같은 방에 들어갈 수 있습니다. [방 탐색과 분류](../dist/frontier.js)

### 종류별 시설과 효과

| 분류 | 필요한 사용 중 시설 | 함께 두면 분류 조건을 깨는 완공 시설 | 실제 효과 |
|---|---|---|---|
| 침실 | 침상 1개 이상 | 농장, 조리대, 화장실, 식탁, 산업 시설 | 침상에서 실제 쉴 때 기력 회복 +25%, 긴장 회복 추가 0.2/초 |
| 식당 | 식탁 1개 이상 | 침상, 농장, 화장실, 산업 시설 | 이 방의 식탁에서 실제 식사를 마칠 때 긴장 추가 3 감소 |
| 온실 | 농장 2개 이상 | 침상, 식탁, 조리대, 화장실, 산업 시설 | 기본 생장 조건과 급수를 만족할 때 실제 성장 속도 +20% |
| 미분류 | 전문 용도 미충족 | — | 전문 방 보너스 없음; 미충족 사유 표시 |

이 판정에서 산업 시설은 **수동 발전기, 석탄 발전기, 수소 발전기, 연구 작업대, 정화기, 전해장치, 물 수집기**입니다. 식당에는 조리대·냉장고·보관함을 함께 둘 수 있습니다. 위 목록에 없는 시설을 막연히 모두 산업 시설로 보지는 않습니다.

분류는 침상 → 식탁 → 농장 순서로 판단합니다. 예를 들어 침상과 식탁을 같은 공간에 넣으면 두 방 보너스를 함께 얻지 않으며, 침실 후보에 부적합 시설이 있다는 이유가 표시됩니다. 필요한 침상·식탁·농장을 껐다 켜면 사용 가능한 시설 목록이 달라져 분류도 다시 계산됩니다. 반대로 부적합 시설은 정지만으로 제거되지 않으므로 다른 공간으로 분리하거나 철거해야 합니다. [분류 우선순위와 제외 목록](../dist/frontier.js)

### 보너스는 실제 행동에 적용

침실 안에 서 있는 것만으로 수면 효과가 발생하지 않습니다. 침실의 침상에서 수행하는 휴식 작업이어야 합니다. 침실 침상의 기본 기력 회복은 3/초에서 3.75/초가 되며, 긴장은 기본 침상 휴식 회복에 0.2/초가 추가됩니다. 수치는 최대 기력과 최소 긴장 범위에서 제한됩니다.

식당 보너스는 실제 식탁 식사가 완료될 때 적용됩니다. 방을 만들거나 식탁을 클릭하는 것으로 식사 횟수가 늘지 않습니다. 온실 보너스도 급수, 온도, 산소와 침수 조건을 건너뛰지 않습니다. 작물이 완전히 자라면 대원이 실제로 수확해야 식량이 들어옵니다. [생활 행동](../dist/community.js) · [방 보너스](../dist/frontier.js) · [농장 생장](../dist/engine.js)

## 4. 좌표로 보는 작은 방 설계

다음은 **내부 3칸 × 2줄 = 6칸**인 최소 크기 침실의 구조 예시입니다. 좌표는 설계를 읽기 위한 예시이며, 현재 저장 파일에서 같은 좌표가 비어 있다고 보장하지 않습니다. 기존 지형·시설을 살펴보고 같은 구조를 만들 수 있는 위치로 옮겨 적용하세요.

| y / x | 14 | 15 | 16 | 17 | 18 | 19 |
|---|---|---|---|---|---|---|
| 9 | 벽 | 천장 | 천장 | 천장 | 벽 | 방 바깥 |
| 10 | 벽 | 내부 공기 | 내부 공기 | 내부 공기 | 벽 | 복도 공기 |
| 11 | 벽 | 침상 | 침상 | 침상 | **기밀문** | 복도·접근 칸 |
| 12 | 바닥 | 바닥 | 바닥 | 바닥 | 문 아래 바닥 | 복도 바닥 |

여기서 벽·천장·바닥은 기존 자연 고체를 이용하거나 타일로 만들 수 있습니다. 방 내부는 `(15,10)~(17,11)`의 6칸입니다. 문 `(18,11)`과 외부 복도 `(19,11)`은 이 침실 면적에 포함되지 않습니다. 문 아래 `(18,12)`와 외부 접근 칸 아래 `(19,12)`에 바닥이 있어야 출입을 계획하기 쉽습니다.

이 예시에서는 침상 하나만 있어도 용도 조건을 만족합니다. 여러 침상은 여러 대원이 사용할 자리를 마련하기 위한 선택입니다. 위쪽 천장 한 칸을 뚫으면 연결된 외부 공간까지 다시 탐색하여 면적·밀폐 조건을 판정합니다. 문을 열어 두는 것과 벽을 제거하는 것은 결과가 다릅니다. [구조 분석](../dist/frontier.js)

### 같은 외곽을 식당으로 바꾸는 예

위 표의 침상을 모두 제거하고 `(16,11)`에 식탁을 놓으면 식당 후보가 됩니다. `(15,11)`의 조리대와 `(17,11)`의 냉장고를 함께 둘 수도 있습니다. 이 경우에도 조리대의 청수·전력, 냉장고의 전력과 대원이 식탁까지 걸어올 경로를 별도로 확보해야 합니다. 방 조건을 만족한다고 배관이나 전력이 자동으로 생기지 않습니다.

### 같은 외곽을 온실로 바꾸는 예

침상·식탁·조리대를 두지 않고 `(15,11)`, `(17,11)`에 농장 두 개를 둡니다. 각 농장에 청수관을 연결하고 적절한 온도·산소를 유지합니다. 농장이 하나뿐이면 방 이름이 온실 후보로 보일 수 있지만 “농장 2개 이상 필요” 사유가 남아 유효 보너스는 적용되지 않습니다.

### 공사 순서에서 지킬 점

먼저 외부에서 내부로 들어가는 바닥·문 위치를 확보하고, 내부 시설과 배관을 정리한 다음 천장과 벽을 닫는 편이 진단하기 쉽습니다. 대원이 서 있는 칸을 타일로 막는 계획이나 완공하기 전에 출입구를 잠그는 계획은 피하세요. 방의 형태가 유효해도 대원이 실제로 접근할 수 없으면 5단계 확장 조건은 만족하지 못합니다. [작업과 접근 경로](../dist/engine.js) · [확장 접근 판정](../dist/frontier.js)

## 5. 산소 충전소와 휴대통

### 5.1 압축과 충전은 서로 다른 과정

산소 충전소는 새로운 산소를 만드는 설비가 아닙니다. 주변 칸에 존재하는 산소를 저장 탱크로 옮기고, 방문한 대원이 그 재고를 휴대통으로 옮깁니다. 생활 공간의 산소 공급을 먼저 확보해야 오래 사용할 수 있습니다.

| 항목 | 값 또는 조건 |
|---|---|
| 건설 비용 | 광석 20 + 금속 12 |
| 해금 | 연구 45 |
| 압축 전력 | 8W |
| 저장 용량 | 충전소당 산소 18 |
| 최대 압축 속도 | 0.08/초 |
| 압축할 주변 영역 | 상하좌우 경로로 반경 2칸; 고체·닫힌 문을 통과하지 않음 |
| 원본 칸의 잔량 | 칸마다 산소 0.35를 남기며 가져옴 |
| 산소 채취 가능한 칸 | 탐사한 비고체 칸이며 물 수치 0.7 미만 |
| 충전소 침수 제한 | 시설 칸의 물 수치 0.5 이상이면 압축·방문 충전 불가 |
| 압축 과열 제한 | 일반 전력 소비 설비와 같이 시설 칸 온도 58 초과 시 대기 |
| 휴대통 용량 | 대원당 산소 6 |
| 방문 충전 속도 | 최대 1.5/초, 실제 탱크 재고와 휴대통 여유량 이내 |

압축에는 배관이 필요하지 않습니다. 충전소를 전력망에 연결하고 주변 공기를 확보하세요. 저장량이 18에 도달하면 팬이 멈추는 것은 정상 대기이며, 저장한 산소는 남습니다. 압축을 멈춘 상태라도 완공·사용 중이고 침수되지 않은 충전소에 재고가 있다면 방문 충전은 가능합니다. 최종 확장 유지 목표에서는 별도로 전력 연결 상태를 요구합니다. [압축·충전 수치](../dist/frontier.js) · [일반 전력 소비 조건](../dist/engine.js)

### 5.2 대원이 바로 충전하러 가지 않을 때

자동 충전은 새로운 작업을 고르는 시점에 다음 조건을 확인합니다. 충전 때문에 긴급한 생존 행동을 계속 미루도록 설계하지 않았습니다.

| 대원 상태 | 충전 작업을 고르기 위한 기준 |
|---|---|
| 휴대 산소 모드 | 자동 |
| 현재 휴대 산소 | 1.5 미만 |
| 호흡 | 70 이상 |
| 포만감 | 48 이상 |
| 기력 | 24 이상 |
| 용변 수치 | 70 미만 |
| 위생 | 65 이상 |
| 교대 | 자동 일정이거나 현재 작업 시간 |
| 충전소 | 완공·사용 중, 저장 산소 0.55 이상, 비침수, 다른 대원이 사용 중이지 않음, 걸어서 접근 가능 |

대원은 실제 충전소 칸의 중심으로 이동한 뒤 재고를 이전합니다. 멀리 있는 충전소를 선택하거나 화면에서 대원을 이동시키는 것만으로 휴대통이 차지 않습니다. 충분히 채웠거나 충전소가 비었을 때 작업이 끝나며, 도중에 포만감·기력이 낮아지거나 생활 일정·긴급 욕구가 바뀌면 중단될 수 있습니다. 이미 이전한 산소는 휴대통에 남습니다. [자동 작업 선택과 충전 중단](../dist/frontier.js) · [생활 우선순위](../dist/community.js)

### 5.3 실제 호흡에 사용하는 시점

휴대 산소 모드가 **자동**이면 현재 칸의 산소가 **0.16 이하**이거나 물 수치가 **0.7 이상**일 때 휴대통을 사용합니다. 사용량은 **0.055/초**입니다. 충분한 휴대 산소가 있으면 그 시간의 호흡을 지원하며 같은 호흡을 위해 현재 칸 산소를 중복 소비하지 않습니다.

가득 찬 6의 휴대통은 연속 사용을 가정하면 약 **109초** 분량입니다. 이 값은 `6 ÷ 0.055`의 산술 환산이며, 실제 작업·귀환 시간과 동일하지 않습니다. 숨 쉴 수 있는 공기에서는 휴대통을 아끼고, 사용 안 함 모드에서는 남은 산소를 보존하며 자동 충전도 하지 않습니다.

휴대통이 비면 기본 호흡 감소와 안전한 공기로의 긴급 이동 규칙으로 돌아갑니다. 물속 호흡은 지원하지만 고온 피해와 물속 이동 비용을 없애지 않습니다. 현재 장비는 방열 수트나 모든 환경을 견디는 탐사복이 아닙니다. 사망한 대원의 휴대 산소는 몸에 남아 저장되며, 살아 있는 다른 대원에게 자동 이전되지 않습니다. [휴대 산소 소비](../dist/frontier.js) · [기본 호흡과 이동](../dist/engine.js)

### 5.4 철거와 저장

산소가 남은 충전소를 철거하면 주변의 실제 기체 칸으로 저장 산소를 되돌려 놓습니다. 각 칸의 수용량과 열린 경로를 고려하므로 방출할 공간이 부족하면 철거 예약 또는 진행이 대기합니다. 먼저 대원이 산소를 충전하도록 하거나 주변 공기 공간을 넓히세요. 철거가 시작된 뒤 상황이 바뀌어도 완료 전에 다시 확인합니다.

저장 파일은 충전소 재고, 대원의 휴대 잔량·마스크 모드, 진행 중 충전 작업과 실제 소비 기록을 보존합니다. 충전소 저장량과 휴대통의 합계는 실제 시설·대원 상태에서 계산하며, 충전소에서 휴대통으로 옮긴 양을 새로운 산소 생산량으로 다시 세지 않습니다. [철거 보존과 저장 검증](../dist/frontier.js)

## 6. 기술을 배분하면 무엇이 달라지나

경험은 실제 생산적인 작업에서 얻습니다. 누적 경험 **60마다 1레벨과 기술 포인트 1개**, 최대 **6레벨·경험 360**까지 성장합니다. 기술 하나는 최대 3단계이며, 단계 하나에 포인트 1개를 직접 배분합니다. 역할·교대표를 바꾸어도 이미 배분한 기술은 유지됩니다. [성장과 기술 배분](../dist/frontier.js)

| 기술 | 1단계 | 2단계 | 3단계 | 영향을 받지 않는 것 |
|---|---|---|---|---|
| 굴착 | 채굴 속도 ×1.20 | ×1.40 | ×1.60 | 광맥의 자원 산출량 |
| 공학 | 건설·철거 ×1.15, 연구 ×1.10 | ×1.30, ×1.20 | ×1.45, ×1.30 | 건설 자원 비용·물 소비 규칙 |
| 생활 | 조리·수확 작업 ×1.15 | ×1.30 | ×1.45 | 한 배치의 음식 산출량·작물 자체 성장 속도 |

채굴·건설·철거·연구·조리의 기술 배율은 기존 긴장에 따른 작업 효율과 함께 적용되며, 기존에 적용되던 역할 효과도 유지합니다. 수확은 기존 3초 작업에 생활 기술 배율을 적용하며 별도의 긴장 배율은 없습니다. 온실의 **식물 성장** 보너스와 생활 기술의 **대원 수확 작업** 속도는 서로 다른 단계에 적용됩니다. 높은 기술이 식량이나 건설 자원을 무료로 만들지는 않습니다.

경험 대상에는 실제로 진행한 채굴·건설·철거, 수동 발전, 연구, 수확·조리, 수거·반납 작업과 실제 산소 충전이 포함됩니다. 걸어가는 시간, 가만히 기다리는 시간, 전력·재료가 없어 진행하지 못한 시간에는 생산 작업 경험을 주지 않습니다. 수거·반납은 각 단계가 실제 완료될 때 짧은 처리 시간을 기록하고, 산소 충전은 실제 이전량을 충전 속도로 환산한 작업 시간을 기록합니다. 상세 적립 위치는 [기본 작업](../dist/engine.js), [운반·조리](../dist/community.js), [충전 경험](../dist/frontier.js)에 있습니다.

대원 카드에서 미배분 포인트를 확인한 뒤 기술 버튼을 누르세요. Canvas에는 실제 배분된 기술의 뱃지와 단계 점이 표시됩니다. 일반 보기에서는 대표 기술, 선택·마우스 확인 시에는 배분한 기술들이 나타납니다. 기술 포인트를 남겨 둔 대원은 이름 옆의 작은 표시로도 구분할 수 있습니다.

## 7. 5단계 목표와 현재 유지 시간

| 목표 | 달성 기준 | 흔한 오해 |
|---|---|---|
| 머무를 공간 | 유효한 침실과 식당을 각각 하나 이상 | 침실 두 개만으로는 두 종류를 채우지 못함 |
| 쌓이는 경험 | 기술 합계 3단계 직접 배분 | 포인트 3개를 얻고 미배분 상태로 두면 미달성 |
| 숨을 가지고 나아가다 | 대원들의 실제 휴대 산소 호흡 합계 30초 | 산소통을 채운 양이나 안전한 공기에서 기다린 시간은 포함되지 않음 |
| 안전한 확장 | 현재 확장 조건 180초 연속 유지 | 과거에 생활 목표를 달성했더라도 현재 상태가 불안정하면 시간이 늘지 않음 |

기존 16개 목표에 위 네 목표가 추가되어 최종 완료는 **20개 목표**입니다. 한 번 달성한 목표와 승리는 이력으로 남습니다. 그러나 화면의 **현재 유지 시간**은 이후 조건이 깨지면 0으로 돌아갈 수 있습니다. 완료 표시가 남으면서 현재 유지 시간이 0인 상황은 모순이 아닙니다. [목표와 유지 시간](../dist/frontier.js)

### 현재 확장 조건

180초 타이머는 다음을 함께 확인합니다.

- 기존 생활 정착 조건이 현재 충족되어 있어야 합니다.
- 유효한 침실과 식당이 각각 있어야 하며, 모든 생존 대원이 사용할 침실과 식당에 도달할 수 있어야 합니다.
- 배분한 기술 합계가 3단계 이상이어야 합니다.
- 누적 실제 휴대 산소 호흡이 30초 이상이어야 합니다.
- 완공·사용 중이며 전력망에 연결되고 침수되지 않은 산소 충전소가 있어야 합니다. 모든 생존 대원이 사용할 충전소에 도달할 수 있어야 합니다.

충전소가 가득 차 압축을 쉬는 상태여도 마지막 조건을 만족할 수 있습니다. 압축 팬이 계속 돌아야 하는 조건은 없습니다. 문 잠금, 사다리 철거 또는 통로 타일 공사로 접근을 끊으면 방과 충전소가 존재하더라도 타이머가 끊길 수 있습니다. [현재 확장 사유 계산](../dist/frontier.js)

### 생활 정착 조건도 계속 유지해야 함

기존 생활 정착은 건강 80 이상의 생존 대원 최소 3명, 모든 생존 대원 긴장 35 이하, 전체 식품 20끼 이상과 조리식 3끼 이상, 대원마다 교대표와 실제 침상 수면 이력을 요구합니다. 실제 운반 80, 조리식 생산 12끼, 식탁 식사 6회와 사용 가능한 보관함·조리대·식탁·가동 중인 냉장고도 확인합니다.

그 아래의 생활 유지 조건에는 생활 구역 산소 55% 이상, 청수 20L 이상, 위생·용변 관리, 연구 100, 실제 취수·정화·수소 발전 이력과 연결된 생활·생산 설비가 포함됩니다. 오수 저장 여유도 필요합니다. 각 수치가 변할 때 **구역·목표·운영 탭의 현재 사유**를 함께 확인하세요. 이미 달성한 과거 목표 숫자만 보고 현재 생산·생활을 멈추면 확장 유지가 중단될 수 있습니다. [생활 정착](../dist/community.js) · [기본 유지 조건](../dist/utilities.js)

## 8. 화면을 읽는 방법

| 표시 | 뜻 |
|---|---|
| R 구역 보기 | 실제 연결된 내부 칸을 색칠; 침실 연보라, 식당 황금색, 온실 연두, 미분류 회색 |
| 실선 / 점선 경계 | 유효한 전문 방 / 조건이 남은 방 |
| 굵은 선택 경계 | 현재 선택한 칸이 속한 실제 방 |
| 방 이름과 칸 수 | 엔진이 판정한 용도와 실제 내부 면적 |
| 선택한 부적합 방의 짧은 문구 | 첫 번째 미충족 이유; 전체 이유는 구역·정보 탭에서 확인 |
| 문짝의 실제 틈 | `doorOpen`에 따른 현재 열림 상태 |
| 문 표시등·잠금 장식 | 선택한 출입 모드 |
| 충전소 팬 회전 | 충전소가 현재 주변 산소를 압축하고 있음 |
| 충전소 탱크의 높이 | 실제 저장량 비율 |
| 충전소와 대원 사이 호스 | 충전 작업을 맡은 대원이 실제 충전 위치에 도착한 상태; 흐름 방향이나 임의 생산량을 애니메이션으로 추정하지 않음 |
| 대원의 작은 산소통 | 실제 휴대 재고 또는 현재 충전 작업 |
| 대원의 얼굴 마스크 | 그 시점에 실제 휴대 산소로 호흡 중 |
| O₂ 숫자 | 실제 재고/용량; 산소 보기 또는 선택 시 확인 |

시설·대원의 게임플레이 애니메이션은 시뮬레이션 시간을 따릅니다. 일시정지하면 작동·호흡·작업 표현도 멈춥니다. 배경 먼지·배경 조명·선택 안내처럼 상태 변화로 해석하지 않는 장식은 별도 화면 시간을 사용할 수 있습니다. Canvas는 엔진 상태를 읽기만 하며 방 분류·산소 생성·기술 배분을 대신 수행하지 않습니다. [렌더러](../dist/renderer.js)

## 9. 문제 해결표

| 증상 | 먼저 확인할 것 | 해결 방법 |
|---|---|---|
| 침실 이름은 보이지만 보너스가 없음 | 유효 여부, 면적, 문 완공, 부적합 시설 | 구역 탭의 모든 사유를 해결; 이름만으로 유효함을 판단하지 않기 |
| 면적이 예상보다 큼 | 천장 틈, 사다리 통로, 열려 있는 벽 | 실제 색칠된 칸을 따라 외부 연결을 찾고 벽·문으로 구획 |
| 문을 열어도 방 면적이 그대로 | 구조 경계와 실제 유체 경계의 차이 | 정상 동작; 공기 흐름은 산소 보기로 확인 |
| 문이 자동으로 열리지 않음 | 잠금 여부, 실제 대원 접근, 완공 여부 | 정보 탭에서 자동 출입으로 변경하고 바닥·경로 확인 |
| 문 잠금이 거절됨 | 살아 있는 대원이 문 칸 안에 있는지 | 대원이 다른 칸으로 이동한 뒤 다시 시도 |
| 방은 유효한데 확장 시간은 0 | 모든 생존 대원의 방·충전소 접근, 기존 생활 조건 | 현재 미충족 사유를 읽고 잠금·통로·위생·식품·냉장 상태 해결 |
| 충전소 팬이 돌지 않음 | 탱크 가득 참, 전력, 사용 중 여부, 온도, 침수, 주변 산소 | 가득 찬 경우 정상 대기; 그 외 상태 문구에 맞춰 공급·환경 조정 |
| 충전소를 켰더니 주변 산소가 줄어듦 | 충전소가 산소를 이동시킨다는 점 | 확산기·전해장치 생산을 유지하고 충분한 산소 공간에서 압축 |
| 대원이 충전하러 가지 않음 | 휴대 잔량·모드, 포만·기력·위생·용변, 교대, 충전소 재고 | 생존·생활 욕구를 먼저 해결하고 작업 시간과 접근 경로 확보 |
| 산소통은 있는데 마스크가 안 보임 | 현재 칸이 호흡 가능한지, 모드가 자동인지 | 정상 공기에서는 휴대통을 아낌; 저산소에서 실제 사용하는지 확인 |
| 산소통을 채웠는데 30초 목표가 안 오름 | 실제 휴대 산소 사용 여부 | 귀환 가능한 저산소 구역에서 실제 호흡을 지원한 시간을 확인 |
| 충전소 철거가 대기함 | 저장 산소를 주변에 방출할 공간 | 방문 충전으로 저장량을 줄이거나 주변의 연결된 공기 공간 확보 |
| 경험·기술 효과가 늘지 않음 | 실제 작업 진행, 미배분 포인트 | 전력·재료·경로 문제를 해결하고 기술을 직접 배분 |
| 온실이지만 농장이 자라지 않음 | 급수, 생장 온도, 산소, 침수, 이미 완전히 자랐는지 | 기본 생장 조건 해결 또는 실제 수확 작업 기다리기 |
| 승리 이후 현재 타이머가 0 | 완료 이력과 현재 유지 상태가 다름 | 승리 이력은 유지됨; 현재 기지 조건을 다시 회복하면 재측정 |

## 10. 구현을 이어갈 때 확인할 데이터

방 목록 `game.rooms`의 `cells`는 실제 내부 셀의 숫자 인덱스입니다. 변환은 `index = y * game.w + x`이며, `x = index % game.w`, `y = Math.floor(index / game.w)`로 복원합니다. `bounds`는 편의를 위한 외곽 범위이므로 오목한 방을 사각형 전체로 칠하거나 외곽 중심을 무조건 내부로 가정하면 안 됩니다.

| 데이터 | 의미 |
|---|---|
| `room.type`, `name`, `valid`, `reasons` | 용도 후보, 표시명, 실제 사용 가능 여부와 실패 사유 |
| `room.cells`, `area`, `bounds` | 실제 연결 성분, 면적, 외곽 좌표 |
| `room.buildingIds`, `doorIds` | 내부 시설과 경계 출입문 |
| `room.sealed`, `bonus` | 구조 밀폐 여부와 효과 설명 |
| `building.doorMode`, `doorOpen` | 설정한 모드와 실제 개폐를 분리한 값 |
| `building.oxygenStored`, `oxygenCapacity` | 충전소의 실제 재고와 용량 |
| `crew.portableOxygen`, `portableCapacity`, `maskMode`, `usingPortable` | 대원 재고, 용량, 설정과 실제 호흡 사용 여부 |
| `crew.experience`, `level`, `skillPoints`, `skills` | 누적 경험·레벨·미배분 포인트·배분한 3개 기술 |
| `game.equipment` | 실제 시설·대원 탱크에서 합산한 저장·휴대·용량·압축 중 설비 수 |
| `game.frontier` | 현재 유지 시간·목표 시간·현재 건강 조건·미충족 사유 |

외부 UI는 `setDoorMode(id, mode)`, `setCrewMaskMode(id, mode)`, `trainCrew(id, skill)`의 결과 `{ok, message}`를 확인합니다. 모드나 포인트를 화면 코드에서 직접 수정하지 않습니다. 실제 효과는 엔진이 계산하고, `production.oxygenCompressed`, `oxygenRefilled`, `portableOxygenUsed`, `protectedSeconds`, `trainingPointsSpent`, `bedroomRestSeconds`, `messhallMeals`, `greenhouseHarvests`가 실제 처리 이력을 기록합니다.
