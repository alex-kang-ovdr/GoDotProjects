# 08 · Offline Edition 28.1 실행 및 저장 계약

## 1. 제공 형식

| 산출물 | 용도 |
|---|---|
| `dark_descent_offline.html` | 다운로드 후 브라우저로 여는 단일 실행 파일 |
| `dark_descent_offline_web.zip` | 실행 파일, 원본 JS·CSS·데이터, 시스템 문서, 검사 코드 |
| 패키지의 `index.html` | 단일 실행 파일과 동일한 게임 콘텐츠 |
| `START_GAME.cmd` / `.command` / `.sh` | 같은 폴더의 `index.html`을 기본 연결 앱으로 여는 보조 실행기 |

게임은 CSS, JavaScript, 참조 데이터와 절차적 그래픽을 HTML에 포함합니다. 플레이 과정에서 npm 설치, 외부 CDN, 서버 실행, 계정 로그인을 요구하지 않습니다. 전체 파일을 내려받은 뒤에는 네트워크 연결 없이 실행하도록 구성했습니다. 보조 실행기를 쓰지 않고 HTML을 직접 열어도 됩니다.

소스 수정 후 `python build.py`로 `index.html`을 다시 만듭니다. Python은 개발용 빌드 도구이며 플레이의 의존성이 아닙니다.

## 2. 시작 화면과 세션 시작

시작 화면에는 정상 로컬 기록 이어하기, 새 탐험의 7직업 선택, Seed 입력, JSON 기록 가져오기가 있습니다. 시작 화면이 열린 동안 전투와 이동은 진행하지 않으며, 대기용 게임 상태가 이전 저장 기록을 자동으로 덮지 않도록 저장 진입점을 차단합니다.

| 선택 | 결과 |
|---|---|
| 이어하기 | 정상적으로 검증된 기존 기록을 복원하고 시작 |
| 새 탐험 | 선택한 직업과 Seed로 새 상태 생성 |
| JSON 파일 가져오기 / JSON 붙여넣기 | 지원 스키마를 검증·이관한 후 일시정지 상태로 복원; P로 재개 |
| 손상되거나 읽을 수 없는 기록 | 복구 안내와 JSON 경로 제공; 조용한 초기화 또는 자동 덮어쓰기를 하지 않음 |

Seed는 새 월드의 생성 입력이며 비우면 새 입력을 생성합니다. 같은 Seed만으로 이미 플레이한 캐릭터의 장비·퀘스트·진행을 되살리지는 못합니다. 그 상태를 옮기려면 JSON 저장 기록을 사용해야 합니다. 플레이 중 시작 메뉴를 열었다가 **현재 탐험으로 돌아가기**를 선택하면 같은 세션으로 복귀합니다.

## 3. 저장 형식과 보호

릴리스 표기는 **28.1**이지만 게임 상태의 `version`과 저장 `schema`는 **28**입니다. XXVIII에서 만든 정상 v28 기록을 이어 쓰며, 기존 v26/v27 이관 검증은 `07_Save_Migration.md`를 따릅니다.

로컬 저장은 다음 원칙을 사용합니다.

1. 세션을 시작하기 전에는 자동 저장을 허용하지 않습니다.
2. 새 기록을 주 슬롯에 쓰기 전에 기존 정상 기록을 백업 슬롯에 보관합니다. 이전 기록이 없는 첫 저장에는 복원할 과거 백업이 없습니다.
3. 주 슬롯이 손상된 것으로 판정되면 자동 덮어쓰기를 보호합니다. 새 탐험은 가능하지만 저장은 차단합니다. 상단 **원문 보관 후 저장**을 선택하면 손상 원문 보관을 먼저 수행한 후 현재 탐험을 주 슬롯에 쓰며, 원문 보관이 실패하면 주 슬롯을 덮지 않습니다.
4. 저장·복구 결과와 저장소 제한을 화면에 표시합니다. 실패한 쓰기를 저장 성공으로 표시하지 않습니다.
5. 탭 숨김과 페이지 종료 이벤트에서 저장을 시도합니다. 이벤트 전달이나 저장 성공을 보장할 수 없는 강제 종료·브라우저 충돌까지 안전하게 저장되었다고 간주하지 않습니다.

저장 키는 기존 `dark-descent-xxviii`를 유지합니다. 직전 정상 기록은 `dark-descent-xxviii.backup`, 보호 중인 손상 원문은 저장 전환 시 `dark-descent-xxviii.damaged`에 보관합니다. 백업 슬롯은 직전 정상 저장 1개를 유지하며 이후 저장 때 갱신된다. 이전 캐릭터의 영구 보관함은 아니므로 별도 JSON 파일로 보관한다. 정상 백업이 있으면 시작 메뉴에 **이전 저장 복구**가 표시됩니다. 손상된 주 슬롯이 있는 상태에서 이 복구를 선택한 경우에도 손상 원문 보관을 먼저 수행하고 복구된 상태 저장을 시도합니다.

주 슬롯과 백업·손상 원문 슬롯은 같은 브라우저 저장 공간에 있습니다. 브라우저 데이터 삭제, 파일별 저장 정책, 저장소 거부로부터 독립적인 백업은 **별도로 내보낸 JSON 파일**입니다. 보호 중인 원문을 외부에 보관하려면 저장 전환 전에 시작 메뉴의 **기존 저장 원문 백업**을 사용합니다. 다른 브라우저·컴퓨터·파일 위치로 이동할 때도 JSON을 사용합니다.

## 4. 저장소가 제한된 환경

로컬 저장 접근이 거부되어도 현재 세션의 전투·탐험을 계속할 수 있습니다. 저장 기능은 다음 경로를 제공합니다.

| 경로 | 목적과 한계 |
|---|---|
| JSON 파일 내보내기 | 현재 정상 게임 상태를 파일로 보관 |
| JSON 파일 가져오기 | 보관한 상태를 검증한 뒤 복원 |
| JSON 텍스트 복사 | 파일 다운로드가 불편한 환경에서 별도 텍스트 문서로 보관 |
| JSON 텍스트 붙여 넣기 | 보관한 텍스트를 검증한 뒤 복원 |

화면 상단 **JSON 백업**을 누르면 파일 다운로드를 요청하면서 JSON 텍스트 화면도 함께 엽니다. **전체 선택**을 누른 뒤 **Ctrl+C 또는 ⌘C**로 직접 복사하여 `.json` 파일로 보관할 수 있습니다. 자동 클립보드 접근은 요구하지 않습니다.

다운로드 요청 표시는 운영체제에 파일이 실제 저장되었다는 보장이 아닙니다. 브라우저의 다운로드 목록과 저장된 파일을 확인하세요. 저장이 차단된 세션을 닫은 뒤 자동 이어하기가 가능하다고 보장하지 않습니다. JSON 가져오기는 파일과 텍스트 모두 동일한 검증 경로를 사용하며, 성공 후 게임은 일시정지 상태입니다. **P** 또는 계속 버튼으로 재개하고 저장 버튼으로 브라우저 슬롯에 보관할 수 있습니다.

가져오기가 실패하면 현재 플레이 상태를 유지하고 오류를 표시합니다. 오류를 피하려고 파일의 버전 숫자나 장비 계산값을 임의로 바꾸는 것은 이관 절차가 아닙니다.

## 5. 입력과 화면 복구

### 키보드

게임 단축키는 `KeyboardEvent.code`의 물리 키 위치를 사용합니다. 한국어 입력 상태의 `ㅈ/ㅁ/ㄴ/ㅇ` 등 문자값 대신 W/A/S/D 위치를 이동키로 처리합니다. 직업·Seed·저장 JSON 등 입력칸에 포커스가 있을 때는 게임 단축키로 처리하지 않습니다. 창 포커스를 잃으면 눌린 키 상태를 정리하여 복귀 후 이동이 계속되는 상황을 방지합니다.

### 그래픽

WebGL을 사용할 수 없거나 컨텍스트가 중단되면 Canvas 2D 표시 경로를 사용합니다. 렌더러 전환은 캐릭터·장비·지역 상태를 새로 만드는 작업이 아닙니다. 중단 시 게임이 일시정지되었다면 화면 안내에 따라 계속할 수 있습니다. 3D 복구와 실제 GPU별 동작은 브라우저와 기기 환경에 따라 검증해야 합니다.

## 6. 운영체제별 실행기

| 실행기 | 동작 | 실패 안내 |
|---|---|---|
| Windows `.cmd` | 자신의 폴더로 이동 후 `start`로 `index.html` 열기 | HTML이 없으면 압축 전체 해제 안내 |
| macOS `.command` | 자신의 폴더를 구한 뒤 `open`으로 HTML 열기 | HTML이 없으면 오류를 출력하고 종료 |
| Linux `.sh` | 자신의 폴더를 구한 뒤 `xdg-open`으로 HTML 열기 | HTML 또는 데스크톱 열기 도구가 없으면 직접 열기 안내 |

실행기는 파일 경로의 공백을 고려하여 인수를 인용합니다. 서버·포트·관리자 권한·패키지 설치를 사용하지 않습니다. 운영체제가 HTML을 다른 앱과 연결해 두었다면 브라우저를 직접 선택합니다. macOS/Linux의 실행 권한 문제도 `index.html` 직접 열기로 피할 수 있습니다.

## 7. 검증 기준과 미검증 범위

검사 숫자와 실제 실행 환경은 릴리스의 `QA_REPORT.md`를 기준으로 합니다. 시작 전 자동 저장 방지, 정상 슬롯 백업, 손상 슬롯 보호, 저장소 거부, JSON 왕복, 입력칸 단축키 예외, 그래픽 장애 전환을 각각 확인해야 합니다.

Node DOM/Canvas 대역에서 실행한 엔진 검사는 실제 브라우저의 다운로드 창·클립보드 권한·운영체제 파일 연결·WebGL 출력 검증을 대신하지 않습니다. 보조 실행기의 구문·경로 처리를 확인한 것과 Windows/macOS/Linux 각각에서 더블클릭 플레이까지 확인한 것은 구분합니다.

멀티플레이, 온라인 계정 저장, 서버 동기화, 설치형 앱 패키지는 이 오프라인 실행판의 범위에 포함하지 않습니다.
