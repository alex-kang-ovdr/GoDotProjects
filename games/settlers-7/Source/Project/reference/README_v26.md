# 세틀러 7 v26 — 생산 목표·반복 보급·조작 개선

## 바로 실행
`Settlers7_Play_v26.html`을 브라우저로 엽니다. Windows는 `Start_Game.bat`으로 열 수 있습니다. 파일 하나에 데이터·공통 엔진·UI·그래픽이 포함됩니다. 외부 라이브러리, CDN, 서버, 로그인은 필요하지 않습니다. 분리 소스의 시작점은 `game/index.html`입니다.

모바일 파일 앱이 HTML 실행 대신 미리보기만 제공하면 PC 브라우저에서 열거나, 파일을 정적 웹서버에 올려 사용하세요. 공개 호스팅 주소는 제공하지 않습니다.

## v26 주요 변화
| 기능 | 실제 동작 |
|---|---|
| 지역 생산 목표 | 같은 지역에서 같은 자원을 만드는 모든 작업장에 목표·재개 기준을 적용합니다. |
| 반복 보급 | 출발·도착 창고와 자원, 목표, 출발지 보유량, 우선순위를 지정합니다. 실제 운반자가 반복 배송합니다. |
| 일괄 운송 | 1~100개를 선택하면 최대 3개씩 운반하는 여러 작업으로 분할합니다. 전체 재고·공간이 부족하면 주문하지 않습니다. |
| 생산망 탐색 | 빵 → 밀가루 → 곡물처럼 원료를 클릭하여 생산 체인을 따라갑니다. 운영 중인 작업장의 지도 위치로 이동합니다. |
| 지도 조작 | WASD·방향키, 두 손가락 이동·확대, 가운데 버튼 드래그, 우클릭 배치 취소를 지원합니다. |
| 이동 표현 | 0.25초 시뮬레이션 위치 사이를 렌더링에서만 보간합니다. 게임 규칙·속도·자원에는 영향을 주지 않습니다. |
| 입력·도움말 | 지역을 바꿀 때 입력값이 섞이지 않으며, 도움말에서 복귀하면 기존 일시정지 상태가 유지됩니다. |
| 안전 | 새 게임 확인, 숨겨진 탭의 자동 일시정지, v24·v25 저장 가져오기, 운영 정책 저장을 지원합니다. |

## 생산 목표 설정 예
1. **운영** 탭에서 내 지역과 `빵`을 선택합니다. 상단 빵 아이콘으로도 이동합니다.
2. 목표 `20`, 재개 `8`을 입력하고 **생산 목표 적용**을 누릅니다.
3. 공급 예정량이 20 이상이면 새 생산 배치를 시작하지 않고, 8 이하이면 자동 재개합니다.

**공급 예정량**은 지역 창고 가용 재고 + 작업장 완제품 + 현재 가공 중인 배치 산출 + 해당 지역 창고로 향하는 예약·운송입니다. 가용 재고에서는 출고 예약을 뺍니다. 완제품을 아직 픽업하지 않은 작업과 이미 픽업한 작업은 중복 합산하지 않습니다. 원료로 작업장 안에 배정된 입력 버퍼와 반환 경로가 아직 없는 회수 화물은 이 공급량에 넣지 않습니다.

목표는 강제 저장 상한이 아닙니다. 이미 시작한 배치는 완료되고, 식량으로 증가한 배치 수량 때문에 목표보다 더 생산할 수 있습니다. 배송은 계속되며, 사용자가 직접 정지한 작업장을 자동으로 재개하지 않습니다. 조림처럼 물품을 생성하지 않는 작업장에는 물품 목표가 적용되지 않습니다.

## 반복 보급 예
새 영토를 확보한 뒤 **운영** 탭에서 판자를 선택합니다. 출발지를 수도 창고, 목적지를 새 영토 창고, 목적지 목표를 `20`, 출발지 최소 보유를 `10`으로 지정합니다. 목적지의 가용 재고와 입고 예정량이 20에 미달하면 실제 창고 운반자가 보급합니다.

보급 규칙은 같은 목적 창고·자원마다 하나입니다. 같은 조합을 다시 저장하면 갱신합니다. 같은 자원의 활성 규칙으로 순환 경로를 만들 수 없습니다. 다른 자원의 반대 방향 거래는 허용됩니다. 도로·중계 창고·공간·재고가 부족하면 원인을 표시하고 기다립니다.

**출발지 최소 보유량은 해당 보급 규칙에만 적용됩니다.** 기존 작업장의 원료 자동 중계, 모집·건설·교역 등 다른 소비를 차단하는 전역 자원 잠금이 아닙니다. 인구·물자 부족을 해결하는 전능한 자동 운영 AI가 추가된 것은 아닙니다.

규칙 해제는 미픽업 첫 구간의 예약만 취소합니다. 이미 출발한 화물과 중간 창고까지 도착한 물품은 기존 배송을 완료합니다. 그래서 해제 후에도 화물이 도착할 수 있습니다. 출발·도착 창고가 점령당하면 규칙을 비활성화하고 기존 점령·화물 회수 정책으로 처리합니다.

## 조작과 안전
마우스 드래그·WASD·방향키는 지도 이동, 휠·+/−·두 손가락은 확대·축소, 가운데 버튼은 지도 드래그, 우클릭·Esc는 배치 취소입니다. 입력란에 글자를 입력할 때 WASD·방향키가 지도에 전달되지 않습니다. Space는 일시정지, B는 건설 탭입니다. 두 손가락을 순서대로 떼어도 마지막 손가락으로 건물이 배치되지 않습니다.

시뮬레이션 틱은 계속 0.25초입니다. 이동 보간은 표시 전용이며, 멈추면 정확한 시뮬레이션 위치를 표시합니다. 브라우저 탭이 숨겨지면 안전하게 멈추며 복귀 후에는 직접 재개합니다. 도움말은 진입 전의 일시정지 상태로 복귀합니다.

## 저장과 호환
v24·v25 JSON을 읽으면 재고·예약·운반 중 화물을 그대로 유지하고 빈 운영 정책을 추가합니다. 새 저장 형식은 `S7-PLAYABLE-26`, state.version은 26입니다. 기존 실행 데이터의 프로필 ID `v24_playable_hybrid`는 유지합니다. 운영 기능은 `data/runtime_v26.json`에 분리합니다.

v26 저장은 이전 실행판에서 읽을 수 없습니다. v26 브라우저 저장 키는 `S7_V26`, 이전 백업 두 개는 `S7_V26_BACKUP_1/2`입니다. 시작 화면은 v26, v25, v24 순서로 기존 저장을 찾습니다. 파일 경로·브라우저 정책 때문에 localStorage를 사용하지 못하면 JSON 내보내기를 사용하세요. 잘못된 파일은 현재 왕국을 덮어쓰지 않습니다.

## 검증
최종 보고서는 `Implementation_Report.html`과 `reports/release_summary.json`입니다.

- 엔진: 기존 60개 + v25 회귀 49개 + v26 신규 33개 = **142개 통과**.
- 브라우저: 기존 34개 + v25 회귀 26개 + v26 신규 31개 = **91개 통과**.
- 이전 suite 이름이 있는 보고서도 이번 v26 소스/배포 HTML에서 다시 실행한 결과입니다. 버전·탭 수·저장 키 관련 기대값은 명시적으로 갱신했습니다.
- v25 운송 중 픽스처는 원본 v25 엔진으로 생성했습니다. 사용자 실제 플레이 기록을 수집한 자료가 아닙니다.
- 보급 중 해제, 2단계 중계, 동일 원료 공유, 순환 규칙 거절, 저장 후 같은 결과, 15분 4개 보급 경로의 자원 수지 등을 검사했습니다.
- 기존 정상 비용 승리 시나리오, 30분 경제 및 다중 시드 AI 회귀 검사도 재실행했습니다.

브라우저는 **정확한 배포 HTML을 Chromium의 `page.set_content`로 읽는 방식**입니다. `file://` 직접 탐색은 실제 시도했으나 환경 정책 `ERR_BLOCKED_BY_ADMINISTRATOR`로 차단됐습니다. 직접 파일 실행 성공이나 실제 브라우저 재시작 후 localStorage 지속성을 검증했다고 주장하지 않습니다. 두 손가락 테스트는 Chromium CDP 터치 입력, 모바일 검사는 891×411·412×891 뷰포트이며 물리 기기 검사가 아닙니다. 숨김 탭 이벤트의 모든 브라우저별 동작을 전수 검증하지 않았습니다.

## 원작과의 차이
원작 v23 JSON·복원 ZIP과 기존 게임 데이터 `game/data.js`, `data/playable_profile.json`은 수정하지 않았습니다. 생산 시간·전투 수치·연구 비용·승리 조건은 기존 실행용 설정입니다. 새 생산 목표·보급 규칙·UX는 이 실행판의 개선 정책이며 원작 기능 복원으로 주장하지 않습니다. 전역 예약 최적화, 모든 상황의 교착 방지, 자동 경제 건설 AI, 원작 전체 캠페인, 3D 그래픽, 개별 병사 조작은 이번 범위에 없습니다.

## 재현
```bash
python tools/build_standalone.py
python tools/run_checks.py
# 선택: Playwright와 /usr/bin/chromium이 설치된 환경
python tools/run_checks.py --browser
python tools/package_release.py
```
게임에는 Python·Node가 필요하지 않습니다. 검증 시에만 Node와 Python을 사용합니다.

## 구조
`game/`는 공통 시뮬레이션과 UI, `data/`는 변경하지 않은 경제 프로필과 새 운영 계약, `tests/`는 재현 테스트, `reports/`는 이번 실행 결과, `reference/`는 원작 참고 자료와 과거 README, `docs/`는 기능·한계 명세입니다. `SHA256_MANIFEST.json`은 배포 파일의 해시입니다.
