# v25 구현 계약

## 읽기 전용 API
`inspectPlacement(type,x,y,owner)`는 건물 종류, 정수 좌표, 소유권, 지형, 점유, 도로, 지역 창고 연결, 인구, 예약을 제외한 자재를 검사한다. 반환값은 `{ok,code,message,missing?}`이다. 논리 상태와 원장을 바꾸지 않는다. 경로 캐시는 갱신할 수 있다. 실제 `_build`도 같은 검사를 호출한다.

`planRoad(from,to,owner)`는 소유 육지와 기존 도로 위의 4방향 BFS다. 건물 타일·물·다른 소유권은 통과하지 않는다. 이동 거리 기준 최단 경로이며 건설 수 최소화·혼잡·비용을 최적화하지 않는다. `{path,tiles}` 중 tiles만 신규 도로다. command('roadPlan')에서 매번 재계산 후 한 번에 반영하며 중간 실패로 일부 도로가 남지 않는다. 현재 도로 비용은 기존 프로필대로 무료다.

`diagnoseWorkshop(id)`는 가동·식량 정책·환경 자원·도로·저장 공간·배송·예약·공급 순서로 검사한다. 원인 라벨은 휴리스틱이며 공급 최적성 증명이 아니다. 부족 자원별 생산자를 데이터의 output 필드에서 역조회한다.

`resourceReport(owner)`는 최대 13개, 5 시뮬레이션 초 간격 스냅샷을 사용한다. 최신 시각과 약 60초 전 사이의 실제 차이로 분당 값을 환산한다. 신규 세이브 마이그레이션은 이전 통계를 추정하지 않고 해당 틱부터 기록한다. 재고 이전·점령도 창고 순변화에 포함된다. 산출과 최종 납품은 다른 지표다.

## 변경 명령
`recruitBatch({unit,sector,count})`: count는 1~8 정수. UI는 1·3·5명. 시설·대기열8명·인구·전체 비용을 먼저 검사한다. 한 명이라도 들어갈 수 없으면 전체 요청을 거절한다. 성공 시 기존 순차 모집을 count회 실행한다.

`pauseGroup({ids,paused})`: 최대300개 고유 작업장 ID, 모두 요청자 소유인지 사전검사. 현재 배치는 끝까지 가공하며 새 배치를 멈춘다.

## 점령 계약
원장의 자원량은 보존한다. 영토 안의 창고·작업장 재고는 새 소유자에게 넘어가며 별도의 생성 이벤트를 만들지 않는다. 관련 배송 예약은 취소하고 이미 픽업된 물자는 운반자 재고에 남긴다. 소속이 이전된 인력이 주인 변경된 끝점에 예전 작업을 수행하지 않게 해제한다. 화물 회수는 사용 가능한 자기 창고에 배달하며 공간 부족 시 대기한다.

점령된 시설의 모집은 비용 반환 없이 취소한다. 연구는 중단하고 이전 소유자의 남은 지역으로 성직자를 반환한다. 해당 지역에 있던 군사·상인·성직자 roster는 해산한다. 출발지 밖 원정대는 원래 소유권을 유지하고 자기 지역으로 복귀한다. 이 규칙은 원작 사실이 아니라 모호한 상태를 일관되게 종료하기 위한 실행 정책이다.

실제 수도 점령에만 즉시 경기 종료를 적용한다. 기존 6점·30초 유지 조건은 별도로 유지한다. 직접 자기 지역을 재점령 처리하는 호출은 아무것도 바꾸지 않는다.

## 저장
format=S7-PLAYABLE-25, state.version=25. 경제 profile ID는 변경하지 않았다. v24 파일은 v24 규칙 검사 + 새 구조·참조 검사 후 metrics만 새로 시작한다. 재고·작업·화물·시간·난수는 재계산하지 않는다. 미래 버전·지원하지 않는 프로필·잘못된 연결·음수·불연속 경로·변조된 통계는 거절한다. 유효성 검사는 서버 보안 경계나 부정행위 방지 기능은 아니다.

`S7.saveWithBackups(storage,text)`는 UI가 사용하는 공통 함수다. 유효한 현재 저장을 backup1으로, 기존 backup1을 backup2로 옮긴 뒤 새 현재 저장을 기록한다. 동일 파일은 회전하지 않는다. 저장소 예외는 UI로 전파해 JSON 내보내기를 안내한다. 테스트 MemoryStorage는 실제 브라우저 디스크 저장 검증이 아니다.
