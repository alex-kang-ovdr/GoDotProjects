# v27 변경 기록 — 편성·증원·전투 인원 보존

v26 실행판을 기준으로 실제 명령·시뮬레이션·화면·저장을 함께 수정했습니다. 원작의 미확인 수치나 규칙을 새로 확정한 버전은 아닙니다.

## 신규 플레이 기능

| 영역 | v26 상태 | v27 동작 |
|---|---|---|
| 아군 지역 이동 | 아군 영토 사이의 인원 재배치 명령 없음 | 병사·성직자·상인 11종을 선택해 실제 소유 도로로 이동 |
| 군사 편성 | 총인원을 받아 엔진이 병종을 선택 | 병종별 가용·선택·잔류 인원을 보여 주고 정확한 편성으로 출발 |
| 출발 전 판단 | 명령 실행 후 오류 확인 중심 | 출발 가능 여부, 인원·물품 비용, 경로, 이동 예상 시간을 사전 표시 |
| 증원 확인 | 이동 상태와 주둔 인원의 연결 설명 부족 | 이동 카드·지도 경로·현재 위치·귀환 버튼을 연결 |
| 교전 중 방어군 | 과거 방어 명단과 실제 주둔 인원이 어긋날 수 있음 | 실제 주둔군과 전투 명단을 동기화하고 기존 HP·탄약 보존 |
| 가득 찬 창고로 귀환 | 도착한 원정의 상태가 이동 완료처럼 보일 수 있음 | 화물 입고 대기를 명시하고 ETA를 비움 |

## 재현한 결함과 수정

### 방어군 중복

v26에서 창병 10명이 방어하는 지역의 창병 5명을 다른 곳으로 출정시키면, 주둔군은 5명이 되지만 다음 전투 갱신에서 과거 명단의 10명이 복원되었습니다. 이미 떠난 5명도 남아 있어 인원이 중복되었습니다.

v27에서는 교전 중인 출발지의 군사·매수·포교·재배치 출발을 거절합니다. 명령이 거절되면 인원과 자원은 변하지 않습니다. 전투 갱신도 실제 주둔군을 기준으로 처리합니다.

### 증원 소실

v26에서 방어전 중 새 대포가 주둔군에 합류하면 다음 전투 갱신의 오래된 방어 명단에 덮여 사라질 수 있었습니다. v27에서는 모집 완료, 도착한 재배치 부대, 귀환 부대를 방어 명단에 반영합니다. 이미 싸우고 있던 병사의 HP와 탄약은 초기화하지 않습니다.

### 귀환 입고 대기

창고 공간이 부족한 귀환 상단은 물품과 인원을 원정 상태에 보존합니다. 상태는 `귀환 물품 입고 대기`, `blocked: true`, `etaSeconds: null`입니다. 필요한 공간이 생기면 기존 귀환 처리로 입고·합류합니다.

## 화면·입력 수정

- 군사 원정에는 전투 병종 5종, 아군 지역 재배치에는 전체 인원 11종을 표시합니다.
- 총인원 빠른 편성은 **전투병 편성** 버튼으로 적용합니다. 직접 입력한 병종별 인원과 혼동하지 않도록 역할을 구분했습니다.
- 출발지·목적지·명령 종류별 초안을 유지하며, 가용 인원 감소 시 조정 안내를 표시합니다.
- 출발 조건을 먼저 통과하지 못해 비용을 아직 계산하지 않은 경우 `출발 조건 확인 후 표시`로 안내합니다.
- 일괄 모집 비용을 선택한 전체 인원 기준으로 표시합니다.
- 도움말 뒤에서 Space가 게임을 재개하지 않도록 수정했습니다. 버튼에 포커스가 있으면 Space는 그 버튼을 실행합니다.
- 불러오기·이어하기·백업 복원 성공 시 과거 배치 도구와 편성 초안을 정리합니다.

## 호환성과 보존

저장 형식은 `S7-PLAYABLE-27`입니다. v24·v25·v26 읽기 경로를 유지하고 실제 과거 엔진에서 생성한 운송 중 픽스처로 검사합니다. 옛 전투 저장의 방어 명단은 저장된 실제 주둔군에 맞춰 정합화하며, v27 저장 자체의 모순된 명단은 거절합니다.

`game/data.js`, `data/playable_profile.json`, `reference/reference_master_v23.json`, `reference/Settlers7_ReverseDesign_v23.zip`은 v26 입력과 바이트 단위로 같습니다. 기존 생산 목표·반복 보급·건설·연구·교역·승리 규칙의 회귀 검사를 포함합니다.

검사 결과는 새로 실행한 `reports/check_run.json` 및 `Implementation_Report.html`을 기준으로 합니다. 브라우저 시작 차단은 통과로 집계하지 않습니다.
