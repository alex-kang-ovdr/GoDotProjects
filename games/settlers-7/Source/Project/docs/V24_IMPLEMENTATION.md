# v24 구현 계약

## 단일 시뮬레이션
0.25초 고정 틱으로 모든 시스템을 처리한다. 브라우저 requestAnimationFrame은 누적 시간을 전달하고 그림을 그릴 뿐 별도 재고를 갖지 않는다. 배속은 0.75/1/1.5이며 긴 탭 정지 이후 벽시계 전체 시간을 한꺼번에 보상하지 않는다. 모든 명령은 엔진에 소유권·시설·입지·비용·인구 검사를 요청한다.

## 생산과 식량
본관과 작업장을 별도 엔티티로 관리한다. 투입 원료·식량·출력 공간을 모두 확보해야 생산을 시작한다. 소비는 시작 시 한 번, 산출은 완료 시 한 번 기록한다. 진행 중인 배치는 식량 정책 변경으로 재작성하지 않는다. 원료 부족·배송 중·출력 공간 부족·환경 자원 고갈·식량 없음·일시정지를 구별한다. 숲·광맥·어장 등은 지역 단위 유한 공급원이며 나무 개체별 추적은 아니다.

## 운반
작업장 작업자가 원료를 창고에서 가져오고 완제품을 창고에 놓는다. 창고 소속 운반자는 창고 사이를 중계한다. 공용 순간이동 재고를 만들지 않는다. 예약은 실제 재고와 별개이고 물리적 픽업에서 차감한다. 빈손 이동·적재 이동 모두 도로를 따른다. 창고 간 요청은 중간 창고에서 인계한다. 도로 편집은 경로 캐시를 무효화한다. 단절된 운반자는 화물을 보유한 채 우회 또는 복구를 기다린다. 기본 간선 및 운반자가 점유한 노드는 안전을 위해 제거하지 않는다.

## 자원 수지
자원별 초기 재고 + 생성 - 소비 = 창고 + 작업장 입력 + 출력 + 운반자 화물 + 원정 에스크로. 수지 검사에서 예약을 재고로 중복 더하지 않는다. 미완료 운송, 훈련 취소·환불, 상단 귀환, 매수 철수에 동일 장부를 사용한다.

## 군사와 점령
군대 전체가 간선 도로를 따라 이동한다. 도착 후 1초 단위 병종 집계 교전으로 성벽과 부대를 처리한다. 전투 수치는 실행용이다. 개별 부대 마이크로·충돌 회피·발사체·실제 포병 탄약 창고 배송은 없다. 사격 소모량은 원정당 임시 한도이다. 포위·지연·철수·점령·잔존병력은 게임 상태에 남는다.

## 평화적 확장
매수 물자는 원정 출발 시 에스크로로 이동한다. 성공 시 소비, 철수하면 반환한다. 상인은 귀환한다. 포교 계수는 참고 공식을 사용하지만 정수 인원은 명시한 실행용 올림이다. 원작의 반올림이 복원된 것이 아니다.

## AI와 승리
AI는 같은 건설·모집·연구·무역·원정 명령을 사용하고 비용을 낸다. 초기 재고와 지도는 작성한 시나리오이며 무료 주기 수입은 없다. 상대 전략은 제한된 휴리스틱이며 상용 수준 적응형 AI라고 주장하지 않는다. 동적 점수는 자산/영토/연구/거래의 실행 임계값으로 결정한다. 선두 동점에는 기존 소유자를 유지한다. 6점 유지 카운트는 점수가 내려가면 초기화한다.

## 저장 검증
버전·프로필·ID·좌표·참조·식량 정책·기술 ID·부대·재고 및 자원 수지를 확인한 뒤 교체한다. 불량 JSON은 진행 중 게임을 교체하지 않는다. 텍스트가 UI의 코드로 해석되지 않도록 경계값을 검사하고 이스케이프한다. 기존 저장을 자동 업그레이드하지 않는다.
