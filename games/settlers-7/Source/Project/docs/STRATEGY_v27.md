# v27 전략 플레이와 엔진 계약

## 1. 플레이 목적

새 영토를 확보한 후 수도의 병력·상인·성직자를 전방으로 옮겨 다음 행동을 준비할 수 있습니다. 경제에서 마련한 인원이 **생산·모집 → 이동 → 도착·주둔 → 정복·매수·포교**로 이어집니다. 물품 보급은 v26의 창고 운송 규칙을 사용하고, 인원 이동은 이번 재배치 명령을 사용합니다.

## 2. 실제 조작

1. 중립 지역을 정복·매수·포교하여 두 번째 영토를 확보합니다.
2. **원정** 탭에서 목적지로 새 아군 지역을 고릅니다.
3. 출발 지역을 수도로 지정하고 병종별 인원을 입력합니다. 가용·선택·잔류 수량을 확인합니다.
4. **병력·인원 이동 출발**를 누릅니다. 출발한 인원은 즉시 수도 주둔군에서 빠지지만, 목적지에는 아직 추가되지 않습니다.
5. 이동 카드의 **지도 보기**로 실제 위치를 확인합니다. 소유 도로를 따라 도착하면 목적지 주둔군에 합류합니다.
6. 다음 목표로 인접한 비소유 지역을 고르고, 출발 지역을 전방 영토로 지정하여 원정을 편성합니다.

상인과 성직자도 같은 방식으로 이동합니다. 매수·포교는 해당 지역의 필요 인원과 물품을 충족해야 하며, 연구·모집·교역은 기존 시설·해금 조건을 따릅니다. 재배치 자체가 영토를 점령하거나 시설을 자동 건설하지는 않습니다.

## 3. 선택 가능한 인원

| 명령 | 편성 | 목적지와 경로 | 도착 결과 |
|---|---|---|---|
| 군사 | 창병·총병·기병·대포·기수, 총 1~35명 | 인접한 비소유 지역, 원정 도로 | 기존 전투 규칙으로 교전 |
| 재배치 | 데이터에 등록된 병사·성직자·상인 11종, 총 1~35명 | 다른 아군 지역, 소유 도로로 여러 지역 통과 가능 | 목적지 주둔 인원에 합류 |
| 매수 | 기존 규칙이 선택한 상인 1명과 해당 비용 | 인접한 중립 지역 | 기존 매수 규칙으로 점령 후 상인 귀환 |
| 포교 | 기존 지역별 포교 비용에 필요한 성직자 | 인접한 중립 지역 | 기존 포교 규칙으로 점령, 투입 성직자 소비 |

기수만으로 군사 출정을 할 수 없습니다. 성벽이 있는 목적지에는 **선택한 부대 안에** 총병 또는 대포가 있어야 합니다. 수도에 해당 병종이 남아 있는 것만으로는 출정 조건을 충족하지 않습니다.

이동 기본 속도는 기존 원정의 1.1 타일/초를 사용합니다. 기존 강행군 기술이 있으면 군사 원정과 군사 인원으로만 구성한 재배치의 속도가 두 배가 됩니다. 민간 인원이 섞인 재배치는 기본 속도를 사용합니다. 이 수치는 실행판의 설정입니다.

## 4. 사전 검사와 명령 처리

`Game.inspectExpedition(args, owner)`는 직렬화되는 게임 상태를 바꾸지 않고 다음을 반환합니다.

```js
const preview = game.inspectExpedition({
  from: 0,
  to: 1,
  kind: 'redeploy',
  units: { pikeman: 3, hawker: 1, novice: 1 }
}, 0);
// ok, code, message, units, remainingUnits,
// cost, unitCost, route, etaSeconds, missing(실패 종류에 따라)

if (preview.ok) {
  game.command('redeploy', {
    from: 0, to: 1,
    units: { pikeman: 3, hawker: 1, novice: 1 }
  });
}
```

위 예시는 0·1번 지역을 모두 소유하고 해당 인원이 가용한 상태를 전제로 합니다. 명령이 실행될 때 같은 검사를 다시 합니다. 미리보기 이후 다른 명령이 병력·자원을 소비했으면 출발 전체를 거절합니다. 부족한 인원만 빼고 일부가 출발하는 처리는 하지 않습니다.

검사 순서는 출발·목적지와 소유권, 명령 종류, 종료 여부, 출발지 교전 여부, 목적지 조건, 편성·비용, 경로입니다. 앞선 단계에서 실패하면 이후 단계의 비용·ETA가 계산되지 않을 수 있습니다. 화면은 이때 비용을 무료로 표현하지 않습니다.

기존 `count` 기반 군사 명령도 유지하지만, `units`가 주어지면 명시한 병종과 수량을 우선합니다. UI의 빠른 편성은 총인원을 병종별 초안으로 바꾼 뒤 그 명시 편성을 전달합니다.

## 5. 이동과 귀환

| 상태 | 화면 표시 | 인원·화물 처리 |
|---|---|---|
| 유효한 아군 경로로 이동 | 재배치 중 + 이동 ETA | 원정 객체에 존재, 양쪽 주둔군에 중복 추가 없음 |
| 목적지·현재 경유지 소유권 상실 또는 소유 도로 경로 단절 | 귀환 전환 후 귀환 상태 | 생존한 아군 지역으로 귀환, 적 영토에 합류하지 않음 |
| 이동 취소 | 이동 취소·귀환 | 현재 위치와 진행도를 보존하여 복귀 |
| 유효한 귀환지가 없음 | 대기 상태 | 인원을 보존하고 적 주둔군에 넣지 않음 |
| 귀환 물품을 받을 공간 부족 | 귀환 물품 입고 대기, ETA 없음 | 화물과 인원은 원정에 유지 |
| 아군 도착 | 부대 합류 이벤트 | 목적지 주둔군에 추가한 뒤 원정 객체 제거 |

도로가 바뀌어도 다른 유효한 소유 도로가 있으면 우회할 수 있습니다.

지도에서 금색 점선은 출발 예정 경로, 파란 선은 진행 중인 경로, 주황색은 대기 표시입니다. ETA는 현재 경로의 **이동 예상 시간**으로, 전투·점령 완료 시간이나 승률을 예측하지 않습니다. 경로·소유권·기술 상태가 바뀌면 예상도 달라집니다.

## 6. 방어전과 증원

출발지가 교전 중이면 군사·매수·포교·재배치 출발을 막습니다. 이미 그 지역을 향해 오고 있던 아군 증원은 도착할 수 있고, 모집 중이던 병력도 완료 후 방어에 합류합니다.

전투 부대는 주둔 인원과 별도로 HP·탄약을 가집니다. `syncDefenders`는 살아 있는 기존 전투 개체를 실제 주둔 수량 범위에서 유지하고, 새로 추가된 수량만 새로운 전투 개체로 만듭니다. 따라서 증원 때문에 기존 부대의 HP·탄약이 회복되지 않습니다. 전투 사상자를 주둔군에 반영할 때는 군사 5종만 갱신하여 상인·성직자를 덮어쓰지 않습니다.

이 정책은 동시 출발·증원에서 인원 보존을 명확히 하기 위한 실행판 정책입니다. 원작의 모든 전투·증원 규칙을 복원했다는 의미는 아닙니다.

## 7. 저장

- 새 형식: `S7-PLAYABLE-27`, `state.version = 27`.
- 읽기 지원: v24·v25·v26·v27. 형식과 데이터가 유효해야 합니다.
- 브라우저 저장: `S7_V27`, 이전 두 백업 `S7_V27_BACKUP_1/2`.
- 이어하기 탐색: v27 → v26 → v25 → v24.
- 새 저장은 이전 실행판에 역호환되지 않습니다.
- 과거 버전의 재고·예약·운송 중 물품을 유지하며, v26 운영 정책도 유지합니다.
- v24~v26의 방어 명단은 저장된 주둔 인원에 맞춰 정합화합니다. v27의 불일치한 전투 명단·잘못된 병종·HP·탄약·이동 단계는 거절합니다.
- 성공한 불러오기 후 편성 초안·배치 도구 등 화면의 일시 상태를 지웁니다. 잘못된 파일은 현재 게임을 교체하지 않습니다.

운송 중 저장 픽스처는 사용자 실제 플레이 자료가 아니라 과거 엔진으로 생성한 검증용 상태입니다. v26 픽스처에는 생산 목표·보급 규칙과 실제 픽업된 화물이 포함됩니다.
