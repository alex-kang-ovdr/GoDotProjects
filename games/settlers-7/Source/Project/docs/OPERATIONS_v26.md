# 운영 정책 구현 계약

## 데이터
`state.operations = {version:1, productionTargets:[], supplyRules:[]}`.

생산 목표: `{owner,sector,resource,high,low,holding}`. `0 <= low < high <= 2000`. 지역 소유자만 변경한다. 인구/도구 같은 물품이 아닌 결과는 다루지 않는다.

보급 규칙: `{id,owner,from,to,resource,target,reserve,priority,enabled}`. 목표 1~2000, 보유량 0~2000, 우선순위 0/1/2. 소유자·목적지·자원 키는 유일하고, 활성 동일 자원의 유향 순환은 금지한다. 상호 순환이 없는 임의의 여러 자원 조합이 모든 생산 교착을 막는다는 보장은 없다.

## 생산 적용 지점
기존 `stepWorkshops()`에서 이미 가동 중인 배치를 진행하고 완제품 운송을 요청한 다음, 새 배치/입력 운송 직전에 `productionTargetHold()`를 검사한다. `stepRelays()`의 자동 원료 요청도 목표 대기를 존중한다. 정책 때문에 원료를 소비했다 취소하거나, 생산품을 생성하지 않은 것으로 처리하지 않는다.

## 공급 예정량 계산
`productionCoverage()` = 지역 창고 가용량 + 지역 작업장 출력 버퍼 + 해당 물품의 active.qty + 목적 지역 창고로 확정된 입고. 창고 가용량은 `stock - reservedOut`이므로 소비/출고 예약은 다른 사용 가능 재고로 다시 세지 않는다. 미픽업 출력물은 작업장 버퍼에서, 픽업 후 화물은 입고에서 센다. 중계 물품은 최종 목적지에서 한 번만 센다. 성직자/병력과 교역 원정의 예치 화물은 별도다.

## 반복 보급 처리
1 시뮬레이션 초마다 규칙을 우선순위·안정 ID 순으로 평가한다. 필요한 양은 `max(0,target-destination.available-finalIncoming)`이다. 실제 요청은 source.available-reserve, 운반량, 최종 창고 빈칸, 첫 중계 창고 빈칸 중 최소값이다. `createJob('relay',...)`로 기존 물류 큐를 사용한다. 새 재고 장부, 원격 즉시 입고, 가상 운반자는 없다.

같은 중계 경로의 뒤쪽 창고 공간은 기존 인계 직전에 다시 확인하므로 중간에서 대기할 수 있다. 출발지가 보유량을 보장하는 전역 은행은 아니며 다른 소비와 자동 원료 운송이 계속 가능하다. 부족 사유는 reserve/route/capacity/ownership/off/transit/ready/shipping으로 반환한다.

## 해제/점령/복원
첫 구간 미픽업만 예약 취소하며, 운반자 연결을 해제한다. 픽업 후 또는 두 번째 구간 이후의 인계는 기존 최종 배송을 완료한다. 해제한 규칙은 저장에 유지해 남은 작업의 참조를 보존한다. 점령은 기존 v25 경제 소유권/회수 정책을 먼저 적용한 뒤 소유권을 잃은 규칙을 비활성화한다.

저장은 120개 보급 규칙, 156개 생산 정책 상한을 검사하고, 유효 자원·창고·소유권·유일성·수치·순환·작업 참조를 검증한다. `resourceDetail`과 `supplyStatus`, 진단 UI의 조회는 상태를 바꾸지 않는다. 정책 평가 중 실제 히스테리시스 전이만 holding을 바꾼다.

## 일괄 수송
`shipment(qty 1..100)`은 원료와 도착/첫 중계 공간을 전체 수량으로 검사한다. 조건이 맞으면 운반량 3개 이하의 relay 작업으로 분해한다. 실패 시 어떤 작업도 만들지 않으며 부분 성공을 보고하지 않는다. 기존 `transfer`는 과거 API의 호환 때문에 회당 한 화물 계약을 유지한다.
