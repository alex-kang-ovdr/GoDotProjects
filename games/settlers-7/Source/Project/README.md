# 세틀러 7 v27 — 부대 편성·영토 간 증원·전투 안정화

v26 실행판에서 이어진 플레이 구현 개선판입니다. 원정 화면에서 병종을 고르고, 아군 영토 사이에 병사·성직자·상인을 이동시키며, 도착한 인원을 다음 원정이나 방어에 사용할 수 있습니다.

## 실행

`Settlers7_Play_v27.html`을 내려받아 브라우저로 여세요. Windows에서는 `Start_Game.bat`도 사용할 수 있습니다. 데이터·엔진·UI·그래픽이 한 HTML에 포함되어 게임 자체에는 서버·로그인·외부 라이브러리·Python·Node가 필요하지 않습니다. 분리 소스 시작점은 `game/index.html`입니다.

모바일 파일 앱이 HTML을 실행하지 않고 미리보기만 제공하는 경우에는 PC 브라우저에서 파일을 여세요. 실제 사용자 브라우저의 로컬 파일 실행과 저장 정책은 이번 환경에서 검증하지 못했습니다. 공개 호스팅 주소는 제공하지 않습니다.

## v27의 실제 변경

| 기능 | 플레이에서 달라진 점 |
|---|---|
| 병종별 군사 편성 | 전투 병종 5종의 가용·선택·잔류 인원을 보고 정확한 편성을 출정시킵니다. |
| 아군 영토 간 재배치 | 병사·성직자·상인 11종을 최대 35명씩 소유 도로로 이동합니다. 여러 소유 지역을 통과할 수 있습니다. |
| 출발 전 검토 | 군사·매수·포교·재배치의 가능 여부, 실패 이유, 비용, 경로, 이동 예상 시간을 확인합니다. |
| 증원 연결 | 실제 도착한 인원만 목적지에 합류합니다. 방어전 중 도착한 증원과 모집 완료 병력도 방어에 합류합니다. |
| 전투 인원 보존 | 교전 중 주둔군을 출정시킨 뒤 중복되던 문제와 새 병력이 과거 명단에 덮여 사라지던 문제를 수정했습니다. |
| 이동 확인·귀환 | 이동 카드에서 상태·현재 위치를 확인하고 이동을 취소하여 현재 위치에서 귀환시킬 수 있습니다. |
| 입력과 저장 | 출발지별 편성 초안, 인원 감소 안내, 도움말의 Space 처리, 가져오기 후 배치 도구 정리를 개선했습니다. |

원작 생산·전투·승리 수치를 새로 확정한 버전은 아닙니다. 재배치·사전 검사·교전 중 출발 제한 등은 이 실행판의 구현 정책입니다.

## 먼저 해볼 플레이

1. 새 왕국을 시작하고 중립 지역 하나를 정복·매수·포교로 확보합니다.
2. **원정** 탭에서 목적지로 확보한 아군 지역을 선택합니다.
3. 출발지는 수도를 선택하고 창병·상인·성직자 등 가용한 인원을 입력합니다.
4. 잔류 인원과 이동 예상 시간을 확인한 뒤 **병력·인원 이동 출발**를 누릅니다.
5. 부대 카드의 **지도 보기**로 이동을 확인합니다. 출발지 인원은 즉시 줄고, 목적지 인원은 실제 도착 후 늘어납니다.
6. 다음 목표로 인접한 비소유 지역을 선택하고 전방 영토에서 새 원정을 보냅니다.

군사 총인원 입력은 **전투병 편성** 버튼으로 병종별 초안에 적용합니다. 성벽을 공격할 때는 선택한 부대에 총병 또는 대포를 포함해야 합니다. 기수만으로는 공격할 수 없습니다. 매수·포교는 중립 지역에만 적용되며 필요 물품·상인·성직자 조건을 충족해야 합니다.

도로가 바뀌면 다른 소유 도로로 우회할 수 있습니다. 목적지·현재 경유지의 소유권을 잃거나 소유 도로로 목적지에 도달할 수 없으면 부대는 귀환합니다. 교전 중인 지역에서는 새 원정·재배치 출발을 막지만, 이미 이동 중인 증원은 도착할 수 있습니다. 귀환 화물을 받을 창고 공간이 없으면 **귀환 물품 입고 대기**로 표시하고 인원·화물을 보존합니다.

ETA는 이동 예상 시간입니다. 전투 완료 시간이나 승률을 뜻하지 않습니다. 편성·이동·증원 계약의 자세한 내용은 `docs/STRATEGY_v27.md`에 있습니다.

## v26 운영 기능도 유지

**운영** 탭에서 지역별 생산 목표와 반복 보급을 설정합니다. 예를 들어 빵 목표 20·재개 8을 설정하면 공급 예정량을 기준으로 새 생산 배치를 중단·재개합니다. 이미 시작한 가공과 운송은 계속됩니다.

새 영토에 판자 보급 목표 20·출발지 보유 10을 지정하면 실제 운반자가 반복 배송합니다. 목적지 가용 재고와 확정 입고를 함께 계산하며, 같은 자원의 순환 규칙은 거절합니다. 보유량은 해당 보급 규칙에만 적용되며 건설·모집 등 모든 소비를 잠그는 전역 예약은 아닙니다.

1~100개 일괄 물품 운송, 원료를 따라가는 생산망 탐색, 다중 창고·물류 중계, 건설·연구·교역·기존 승리 판정도 유지합니다. 이전 운영 기능의 상세 명세는 `docs/OPERATIONS_v26.md`와 `reference/README_v26.md`에서 확인합니다. 과거 README의 검증 수치는 당시 기록이며 이번 결과는 아래 보고서를 기준으로 합니다.

## 조작

드래그·WASD·방향키는 지도 이동, 휠·+/−·두 손가락은 확대·축소, 가운데 버튼은 지도 드래그, 우클릭·Esc는 배치 취소입니다. 입력란에서는 지도 단축키를 무시합니다. Space는 일시정지이며, 버튼에 포커스가 있으면 그 버튼을 실행합니다. 도움말에서 Space를 눌러 뒤의 게임이 재개되지 않습니다.

브라우저 탭이 숨겨지면 시뮬레이션을 멈추고 복귀 후 직접 재개합니다. 도움말은 진입 전 일시정지 상태로 돌아옵니다. 시뮬레이션 틱은 기존 0.25초이며 이동 보간은 표시만 바꿉니다.

## 저장과 이전 버전

새 형식은 `S7-PLAYABLE-27`이며 유효한 v24·v25·v26 저장도 읽습니다. 기존 경제 프로필 ID `v24_playable_hybrid`는 유지합니다. 저장 키는 `S7_V27`, 백업은 `S7_V27_BACKUP_1/2`이고 이어하기는 v27→v26→v25→v24 순서로 찾습니다. 새 v27 저장은 이전 실행판에서 읽지 못합니다.

이동·귀환·방어전 도중 상태를 저장하고 이어갈 수 있습니다. v26의 생산 목표·보급 정책도 유지합니다. 과거 방어전의 오래된 병력 명단은 저장된 실제 주둔군에 맞춰 정리하며, v27의 불일치한 전투 명단은 거절합니다. 불러오기에 성공하면 과거 편성 초안과 배치 도구를 비웁니다. 잘못된 파일은 현재 게임을 덮어쓰지 않습니다.

브라우저 저장을 사용할 수 없으면 상단 **내보내기**로 JSON을 저장하고 **불러오기**로 이어갈 수 있습니다. 브라우저 재시작 뒤 저장 지속성은 이번 검사 범위에 포함되지 않습니다.

## 검증 결과의 기준

최종 결과는 `Implementation_Report.html`과 `reports/release_summary.json`입니다. 검사 실행 기록·해시는 `reports/check_run.json`, 개별 결과는 각 suite의 JSON에 포함됩니다.

- 엔진은 기본 60개, v25 회귀 49개, v26 회귀 33개, v27 신규 28개를 이번 공통 엔진으로 검사합니다.
- UI 순수 템플릿 9개는 실제 엔진의 사전 검사 결과·편성 초안·표시 문자열을 확인합니다. DOM·레이아웃 검사가 아닙니다.
- 브라우저 시작은 현재 환경의 `socket() failed: Operation not permitted` 오류로 차단되었습니다. 작성한 v27 브라우저 시나리오 20개는 실행 통과로 집계하지 않습니다.
- 과거 브라우저 통과 수치와 스크린샷을 이번 결과에 포함하지 않습니다. 화면 조작·모바일 표시·직접 파일 실행은 미검증입니다.
- 과거 버전 운송 중 픽스처는 각각 과거 엔진으로 생성한 검증 자료이며, 실제 사용자 플레이를 수집한 자료가 아닙니다.

## 원작 자료와 한계

`game/data.js`, `data/playable_profile.json`, `reference/reference_master_v23.json`, `reference/Settlers7_ReverseDesign_v23.zip`은 v26에서 그대로 보존했습니다. 출처 해시와 비교 결과가 패키지에 포함됩니다.

생산 시간·전투 능력치·연구 비용·포교 계산·승리 조건은 기존 실행용 혼합 프로필을 유지합니다. 원작 전체 캠페인·연구판·장군·3D 그래픽·개별 병사 조작·새 경제 건설 AI를 완성한 버전은 아닙니다. 원작 일치율이나 모든 조건에서의 균형을 수치로 주장하지 않습니다.

## 재현

```bash
python tools/run_checks.py
# 실행 가능한 Chromium과 Playwright가 있는 환경에서 선택:
python tools/run_checks.py --browser
python tools/package_release.py
```

`run_checks.py`가 단일 HTML을 먼저 빌드합니다. 패키징은 검사 이후 소스와 결과 파일이 바뀌지 않았는지 확인한 뒤 보고서·ZIP·배포 HTML을 만듭니다. Python·Node는 개발·검증에만 필요합니다.

## 구조

- `game/`: 실제 데이터·시뮬레이션·UI·스타일.
- `data/`: 보존한 경제 프로필 및 버전별 구현 계약.
- `docs/`: 변경 기록·플레이 방법·검증 범위.
- `tests/`: 엔진·템플릿·브라우저 검사와 이전 저장 픽스처.
- `reports/`: 이번 검사 결과와 브라우저 환경 제한 기록.
- `reference/`: 원작 참고 자료, 과거 README, v26 기준 해시.
- `SHA256_MANIFEST.json`: 패키지 내 파일별 해시.
