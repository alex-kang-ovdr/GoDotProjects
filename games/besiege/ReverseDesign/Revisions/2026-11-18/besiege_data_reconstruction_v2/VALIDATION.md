**검증일: 2026-11-18 · 대상: 문서·데이터·검사 도구**

| XML 검사 도구 | 아래 합성 입력 7사례의 실행 결과 | 통과 |

`jsonschema.Draft202012Validator`가 이 환경에 설치되어 있어 전체 스키마 검사를 실제 수행했다. 표준 라이브러리의 기본 의미 검사만 수행하고 전체 규격을 검증했다고 표시한 것이 아니다. 외부 네트워크에서 schema를 가져오지 않았다.

### XML 검사 도구의 7사례

1. 합성 UTF-8 XML: Block 이름의 요소 2개, 한글 보존, 입력 SHA-256 불변.
2. 합성 UTF-16 XML: 같은 내용과 원본 보존.
3. UTF-8 DTD 선언 거부.
4. UTF-16 DTD 선언 거부.
5. 잘못된 XML 거부.
6. 기존 출력 파일 덮어쓰기 거부와 내용 보존.
7. 입력 파일을 출력 경로로 지정한 작업 거부.

위 fixture는 테스트용으로 작성한 XML이다. 실제 Besiege 설치본에서 얻은 `.bsg`가 아니며 원작 importer 호환성 시험으로 집계하지 않는다.

## 2. 실제 소스와 과거 문서의 대조

패키지 내부 검사와 별도로 현재 작업 공간의 실제 저장소와 비교했다. 결과는 [code_and_baseline_verification.json](research/code_and_baseline_verification.json)에 기록했다.

| 대조 | 결과 |
|---|---|
| 기준 commit | `af19c56113079416b4763ce2c0d4d2148ee1592f` 일치 |
| Git 작업 트리 | 변경 없음 |
| V4 소스 SHA-256 및 크기 | 12/12 일치 |
| 과거 기획 보관본 | 22/22 파일이 기존 원본과 byte 단위 일치 |

V4 스냅샷은 10부품, 6프리셋, 캠페인 6개+샌드박스 1개, 상수 49개를 포함한다. 이 숫자는 원작 콘텐츠 수가 아니다. 현재 게임 소스를 수정하거나 기존 게임 테스트를 다시 실행하지 않았다.

## 3. 파일 무결성

[manifest.json](manifest.json)은 자신을 제외한 배포 파일의 상대 경로·크기·SHA-256을 기록한다. 보고서 생성 후 manifest를 만들고, `--json-report` 없이 검증하여 해시 검증 중 보고서가 갱신되는 순환 문제를 피한다.

**최종 manifest 검사: 통과.** 전체 13개 검사 그룹이 통과했고 실패·생략은 0개다. Manifest에 기재된 72개 파일의 크기와 SHA-256을 확인했다. 본문 보고서는 manifest 생성 전의 12개 통과/1개 명시 생략 상태를 보존하며, 최종 검사는 이후 별도로 완료했다.

사용자는 압축 해제 후 다음 명령으로 본문과 manifest를 함께 검증할 수 있다.

```bash
python3 scripts/validate_pack.py
```

새 검사 보고서를 원하면 기존 manifest에 포함된 파일을 덮어쓰지 않는 경로를 선택한다.

```bash
python3 scripts/validate_pack.py --json-report ../besiege-r2-local-validation.json
```

## 4. 검증 범위의 한계

- 원작 설치판에서 40개 실험을 실행하지 않았다. 결과는 모두 `null`이다.
- 원작 질량·마찰·파단력·관성·내구도·접점 등의 현행 수치를 새로 실측하거나 채택하지 않았다.
- 새 기획의 브라우저 실행, GPU 렌더링, 모바일 조작, 게임플레이 완주를 시험하지 않았다. 백로그 23개는 구현 예정이다.
- Markdown 검사는 상대 파일의 존재를 확인한다. 외부 사이트의 지속 접근 가능성이나 문서 안 anchor의 정확성까지 보장하지 않는다.
- 과거 보관 문서 22개는 내용 보존만 확인했다. 현재 기준의 사실 검증·링크 검사 대상으로 다시 집계하지 않는다.
- V2 예제의 구조·참조가 유효하다는 사실은 런타임 카탈로그의 포트나 물리 모델이 이미 구현되어 있다는 뜻이 아니다.

이 검증으로 확인한 것은 연구 자료의 구조적 일관성, 출처 추적 가능성, 기존 구현 기준점, 보조 검사 도구의 동작이다.
