# 04. 육상·공중·수상 이동의 데이터 복원과 설계 개선

> 2026-11-18 조사. 공식 공개 기능은 출처와 발표 버전을 붙인다. 계수·수식·튜닝 목표는 별도 독립 설계이며 원작 내부 코드 복원값이 아니다. 원작 설치본 계측은 아직 실행하지 않았다.

## 1. 가장 큰 대응 오류부터 수정한다

IRONWOOD 4.0의 `propeller`는 키 입력으로 추력을 만드는 통합 추진기이고, `float`는 추가 부력을 받는 전용 부품이다. 원작 블록 명칭과 그대로 대응시키면 부품을 조합하는 이유가 사라진다. 후속 기획에서는 **직접 추진원, 회전 구동원, 수동 공력면, 수동 수력면, 부력 장치**를 분리한다.

| 역할 | 현재 독립 구현 | 원작 분석 시 구분할 대상 | 필요한 데이터 |
|---|---|---|---|
| 축 방향 직접 추진 | `propeller` | Flying Block(역할 가설·실험 대기), Aquatic Screw, Booster의 환경·자원별 차이 | thrust axis, medium, input, resource |
| 회전 구동 | 구동 바퀴·회전 관절 | Spinning Block, Powered Cog 등 | driven axis, target speed, torque |
| 수동 공력면 | `wing` | Wing, Wing Panel·Propeller 계열(수동성 가설·실험 대기), 설정된 Surface | local normal, aerodynamic enabled, coefficients |
| 수중 방향 저항 | 간략 물 항력 | Paddle, Rudder, 형상 의존 항력 | submerged area, lateral axis, damping |
| 부력 | `float` 중심 | 객체별 buoyancy와 조절 가능한 Barrel | buoyancy property, immersion, force point |

Propeller를 수동 공력면으로 다루는 해석은 기존 분석의 유력 가설이다. 공식 V1.10의 회전축 주변 자동 정렬은 회전 장치와의 결합을 뒷받침하지만, 자체 입력·추력 유무와 정확한 공력식을 전부 확정하지는 않는다. **EXP-020/021의 원작 매퍼·정지 대조·회전 대조가 끝나기 전에는 기능 매핑의 확정 등급을 높이지 않는다.** [PHY-014 공식 V1.10](https://store.steampowered.com/news/posts/?appids=346010&enddate=1652972552&feed=steam_community_announcements)

## 2. 육상 이동: 회전·접지·조향·현가의 분리

### 2.1 공식 변경이 알려 주는 경계

V1.26은 바퀴 충돌체 변경, 구형 저장 기체의 바퀴 구성 보존, 가감속 구현 변경을 별도 항목으로 공지했다. 가감속까지 구형 저장에 보존되는지는 추가로 확인한다. 조향 블록·힌지의 tension과 Spinning Block의 free-spin도 이 버전의 변경이다. 따라서 “같은 블록 이름이므로 같은 주행 곡선”이라고 가정하면 안 된다. V1.65의 Roller Wheel은 모터가 없는 특정 축 구름 장치이며 강성 조절이 있다. V1.75의 Small Wheel은 구형(spherical) 충돌체와 자유 구름으로 변경됐다. 이 두 장치의 횡방향 움직임을 한 가지 바퀴 유형으로 묶지 않는다. ### 2.2 독립 구현 계약

구동 바퀴는 지정 축에 토크를 가하고 차체 이동은 접촉으로 생기게 한다. 키가 차체 위치를 직접 변경하지 않게 한다. 선회 입력은 차량 전체에 요 토크를 주는 보조와 좌우 모터 출력을 바꾸는 차동 구동을 구분해 기록한다. 보조가 켜진 시험을 접지 기반 차량 시험과 혼동하지 않는다.

| 상태 | 물리 의미 | UI/보고서 표시 |
|---|---|---|
| 구동 입력 | 모터에 속도/토크 목표 전달 | 입력 방향·설정 출력 |
| 모터 포화 | 요구 토크가 한계에 도달 | 출력 상한 표시 |
| 헛돎 | 바퀴 회전에 비해 차체 이동 부족 | 각속도와 차체 접선속도 비교 |
| 접지 상실 | 바퀴의 유효 접촉 없음 | 공중 바퀴 표시 |
| 제동 | 회전에 반대 토크/마찰 작용 | 브레이크 활성 |
| 중립 | free-spin 또는 hold 정책 | 현재 중립 모드 |

`slipRatio = (wheelAngularSpeed × radius − tangentialSpeed) / max(abs(tangentialSpeed), ε)`는 독립 진단식의 예다. 저속·정지 근처에서 수치가 커지는 특성이 있으므로 임계치만으로 “미끄럼 오류”를 경고하지 않는다. 실제 원작의 타이어 모델을 이 식으로 추정하지 않는다.

### 2.3 추가할 설계 과제

현가 장치를 추가한 뒤 같은 차체로 평지, 낮은 턱, 교차축 지형을 비교한다. 속도를 높이는 과제와 적재물을 보존하는 과제를 분리하면 강한 모터만 선택하는 해법을 줄일 수 있다. 지형·하중·제한 시간은 IRONWOOD의 새 튜닝값이며 원작 캠페인 수치가 아니다.

## 3. 비행: 부품 하나가 아니라 힘의 배치를 조립한다

### 3.1 확인된 사실과 남은 변수

Build Surface는 도입 시 공력 특성이 소개됐지만 V1.75의 새 표면 기본값은 공력 OFF다. 형상 생성, 재질, 공력 활성화를 서로 다른 필드로 보존해야 한다. Surface를 추가하면 항상 날개처럼 작동한다고 문서화하지 않는다. [PHY-015 도입 설명](https://store.steampowered.com/news/posts/?appids=346010&enddate=1652972552&feed=steam_community_announcements), [PHY-004 후속 변경](https://store.steampowered.com/news/posts/?appgroupname=Besiege&appids=346010&enddate=1772123201&feed=steam_community_announcements)

원작 Wing/Propeller의 정확한 양력 계수·실속각·질량·면적 기준·공력 중심은 공개 자료에서 확정하지 않았다. 날개 블록의 외형 면적만으로 숫자를 만들지 않는다. 현재 V4 날개의 설치각과 양력 모델은 독립 구현값이다.

### 3.2 후속 공력 모델 — 제안

힘을 부품 중심 한 점에만 주는 방식에서 단계적으로 다음을 분리한다.

1. 부품의 공력 작용점에서 `vPoint = vCOM + ω × r`를 계산한다.
2. 바람과 매질 속도를 빼서 상대 공기속도를 얻는다.
3. 로컬 날개축에서 받음각·옆미끄럼을 구한다.
4. 독립 튜닝 곡선 `CL(α)`, `CD(α)`와 면적 배율로 힘을 계산한다.
5. 작용점에 힘을 가하여 편심 모멘트가 자연스럽게 생기게 한다.
6. 파손된 면은 힘을 잃고, 떨어졌지만 살아 있는 면은 계속 공력을 받게 한다.

일반적인 후보식 `L = 0.5 × ρ × v² × S × CL(α)`와 `D = 0.5 × ρ × v² × S × CD(α)`는 **독립 구현의 설명식**이다. 이를 원작의 실제 함수, SI 교정 또는 실속 구현 여부의 증거로 사용하지 않는다.

회전 블레이드는 각 블레이드의 상대속도로 평가한다. 회전 구동원과 블레이드를 합친 편의 부품을 유지하려면 팔레트에 “통합 추진기”로 표시하고 원작 Propeller와 다른 대응을 명시한다. 기존 저장의 `propeller`를 새 수동 블레이드로 자동 치환하면 비행기와 선박이 작동하지 않으므로 이행을 금지한다.

### 3.3 플레이어 진단 UX

- 질량중심, 추력 방향, 공력 작용점은 서로 다른 표시로 둔다.
- 비행 보조 ON/OFF를 기록과 함께 저장한다.
- 상승 힘 부족, 피칭 불안정, 추력 편심, 날개 분리를 다른 도움말로 안내한다.
- “양력 부족”은 힘 표본과 체중 비교가 가능한 경우에만 사용하고, 단순 추락 결과로 원인을 확정하지 않는다.
- 좌우 대칭 배치 시 메시 반사와 블레이드 회전 방향을 함께 미리 본다.

초기 비행 과제는 이륙·수평 유지·선회·착륙으로 나누고, 뒤 단계에서 적재량과 구조 보존을 요구한다. 자동 자세 토크만으로 완주하는 과제와 조립한 조종면이 작동하는 과제를 별도로 검증한다.

## 4. 물: 객체 부력과 선체 침수를 구분한다

개발사는 모든 물리 객체에 부력 속성이 있고, 잠긴 블록을 기준으로 부력중심을 계산하며, 형상에 따라 수중 저항이 달라진다고 설명했다. 부력 시각화의 정확성에도 한계가 있음을 함께 밝혔다. [PHY-005](https://store.steampowered.com/news/posts/?appids=346010&enddate=1716555565&feed=steam_community_announcements)

이 설명으로 **밀폐된 선체 내부 공기, 구멍을 통한 침수 유량, 펌프 배수, 체적 기반 유체 연성**까지 확인한 것은 아니다. 외형상 배가 가라앉는 결과와 그런 내부 모델의 존재는 다르다. 원작 밀폐 효과는 EXP-025에서 질량과 부품 수를 통제해 확인한다.

### 4.1 현재 구현과 차이

V4의 `_applyFluidForces`는 여러 부품에 물 항력을 적용하고 살아 있는 `float`에 추가 부력을 준다. `corePosition`의 깊이가 일정 시간 지속되면 침수 실패로 판정한다. 이 실패는 임무 상태 규칙이며 선체 내부에 물이 차는 시뮬레이션이 아니다. 원작 복원 테이블에는 이 수치를 옮기지 않는다.

후속 우선순위는 먼저 모든 관련 재질/부품에 `buoyancyProfile`을 부여하고, 잠김과 방향별 항력을 일반화하는 것이다. 밀폐 선체 침수는 원작 관측 근거와 제품 목표가 확보된 뒤 별도 확장으로 판단한다.

### 4.2 수상 부품의 역할 분리

| 부품 | 공식 공개 역할의 요약 | 원작 수치 미확정 | 독립 구현에서 필요한 상태 |
|---|---|---|---|
| Barrel | 부력 조절과 rise/sink 입력 | 부력 상한·입력 힘 | buoyancy setting, vertical command |
| Sail Panel | 바람 추진, 젖으면 추진 중단 후 회복 | 회복 지연·풍력 곡선 | deployed, wetness, recovery |
| Aquatic Screw | 전후 추진, 연속열 설정 공유, 기어 상호작용 | 연속열 힘 합성·매질 의존 | shaft group, throttle, submerged |
| Paddle | 노·외륜·횡방향 감쇠 | 방향별 저항 계수 | local face, relative water speed |

기능 근거는 2024-04-26의 개발사 소개이며 출시 후 수치를 측정한 표가 아니다. [PHY-006](https://store.steampowered.com/news/posts/?appids=346010&enddate=1714752154&feed=steam_community_announcements)

### 4.3 부력과 저항의 독립 모델

실용적인 웹 구현 후보는 부품별 여러 표본점을 이용한 잠김 근사다. 수면 높이를 각 표본점에서 평가하고 양의 부력을 더한다. 표본 위치에서 힘을 적용하면 롤·피치 복원 효과를 얻을 수 있다. 총 부력만 차체 중심에 몰아 주면 배치 변화의 의미가 약해진다.

`Fbuoyancy = profileStrength × submergedFraction`, `Fdrag,i = −Ci × abs(vLocal,i) × vLocal,i`는 초기 구현의 후보다. 계수는 독립 튜닝 네임스페이스에 둔다. 원작 공식 부력식·유체 계수를 복원한 것으로 표기하지 않는다. 물속에서 각속도 감쇠와 표면 물보라 효과는 별도 시스템이다.

파도가 기체를 흔들고 대형 수중 폭발이 밀어냄 뒤 당김을 만드는 동작은 공식 소개에 있다. 그러나 물 표면 방정식과 폭발 감쇠 함수는 미공개다. 초기에는 물리용 높이장과 시각용 파면이 같은 위상을 사용하도록 하는 독립 구현을 제안한다. [PHY-007](https://store.steampowered.com/news/posts/?appids=346010&enddate=1714752154&feed=steam_community_announcements)

## 6. 완료 기준

새 모델은 기존 V4 프리셋을 그대로 덮어쓰지 않는다. `physicsProfileVersion`으로 이전 버전을 읽고, 새 프리셋은 새 규칙으로 생성한다. 동작 비교에는 원본 설계 해시, 입력 시퀀스, 환경 프로필, 시간배율, 보조 제어 상태를 저장한다.

필수 수용 조건은 단순 완주뿐 아니라 무동력 대조, 부품 손실, 모터 포화, 좌우 반사, 저장 후 재실행이다. 주행·항해·비행에 같은 입력이 사용되더라도 입력 해석과 실제 힘의 발생 경로를 구분해 보고서에서 설명할 수 있어야 한다.
