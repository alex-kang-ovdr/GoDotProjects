# IRONWOOD 4.0 — 피스톤·직선 구동 장치

기준 구현: [linear-actuator.js](../dist/linear-actuator.js), [physics.js](../dist/physics.js), [parts.js](../dist/parts.js). 이 문서는 이 웹 게임의 실제 구현 규칙이며 Besiege 원작의 비공개 내부 수치를 설명하는 문서가 아닙니다.

## 1. 플레이 목적과 조립 규칙

피스톤은 고정된 그림을 늘리는 장치가 아니라, 지지 강체에 대한 이동 머리 강체의 상대 위치를 제어하는 기계 부품입니다. 위에 연결한 부품도 그 강체의 구속을 통해 함께 올라갑니다. 무거운 물체를 들어 올릴 수 있는지는 구동 힘, 중력, 접촉, 연결 경로에 따라 결정됩니다.

| 속성 | 값 |
| --- | --- |
| 타입 / 이름 | `piston` / 선형 피스톤 |
| 질량 / 자재 / HP | 1.8kg / 4 / 70 |
| 기본 최대 이동 | 1.5m |
| 최대 이동 설정 범위 | 0.25~2m |
| 출력 배율 | 0.3~2.0 |
| 구동 힘 한도 | 120 × 출력 배율 N |
| 목표 이동 속도 | 0.8 × 출력 배율 m/s |
| 가이드 연결 강도 기준 | 1800, 게임 내 제약 하중비의 분모 |

아래 셀 `(x,y-1,z)`에 지지 부품이 있어야 합니다. 지지→피스톤 사이에는 `piston` 연결 하나를 만들고, 위 셀의 일반 부품은 이동 머리에 고정합니다. 옆면 접촉은 자동으로 용접하지 않습니다. 바퀴는 지지부가 될 수 없습니다. 관절·피스톤을 쌓으면 위쪽 장치가 자신의 하부 기계 연결을 생성합니다.

피스톤과 그 상부 탑재물을 하부 차체까지 별도의 고정 구조로 이어 붙이면, 우회하는 구속 때문에 이동이 막힐 수 있습니다. 이는 실제 연결 그래프의 결과입니다. 격자에서 겹치지 않더라도 신장 중 주변 부품에 닿으면 접촉 반력이 발생합니다.

## 2. 조작과 상태

| 입력 | 구동 목표 |
| --- | --- |
| Z / 터치 ‘늘리기’ | 목표 이동량 증가 |
| X / 터치 ‘줄이기’ | 목표 이동량 감소 |
| 두 입력 동시 | 상쇄, 현재 목표 유지 |
| 입력 없음 | 유한한 힘으로 현재 목표 유지 |
| 코어 연결 상실 또는 HP 0 | 동력 차단 |

입력은 `actuate ∈ [-1,1]`로 변환합니다. 매 물리 스텝의 목표는 다음과 같습니다.

`target = clamp(target + actuate × 0.8 × power × dt, 0, stroke)`

목표가 이동해도 강체를 그 위치로 순간이동하지 않습니다. 솔버가 허용된 힘 범위 안에서 목표에 접근하게 하므로 관성, 중력, 무거운 하중 또는 걸림 때문에 **실제 이동량과 목표 이동량이 다를 수 있습니다**. 부품 점검 창에 두 값을 따로 표시합니다.

모든 피스톤은 공통 Z/X 입력을 받습니다. 개별 타이밍 채널·자동 시퀀서·수평 방향 재배치는 현재 범위에 포함하지 않습니다. `rot`은 기존 Y축 회전이므로 수직 축을 수평으로 바꾸지 않습니다. 다만 시험 중 지지 강체가 회전하면 피스톤 축도 그 지지부의 로컬 +Y를 따라 회전합니다.

## 3. 실제 구속 구현

`LinearActuatorConstraint`는 cannon-es의 `LockConstraint`를 확장합니다. 좌우 두 방향의 이동과 세 회전 축을 가이드로 제한하고, 남은 축의 방정식은 이동하는 로컬 피벗을 따라갑니다. 기본 PointToPoint 방정식의 법선을 매 스텝 지지부의 로컬 X/Y/Z 방향으로 변환합니다.

구동 축 방정식의 힘은 유한합니다. 별도의 단방향 접촉 방정식 두 개가 하단과 상단의 기계적 이동 제한을 담당합니다. 코어에서 분리되면 구동 방정식을 끄지만, 손상되지 않은 가이드와 끝단은 남습니다. 가이드 연결 자체가 파단되면 전체 구속을 세계에서 제거합니다.

현재 포함된 cannon-es 0.20.0의 GSSolver는 방정식 `minForce/maxForce`를 누적 임펄스 λ에 적용하고 `multiplier=λ/dt`를 제공합니다. 따라서 이 장치에서는 원하는 힘 F에 대해 한도를 **F×dt**로 설정합니다. 120Hz에서 120N 한도는 한 스텝당 1N·s입니다. 기존 바퀴·포탑 튜닝은 이 변경으로 다시 해석하거나 수정하지 않습니다.

| 설정 | 값 / 의도 |
| --- | --- |
| 고정 물리 간격 | 1/120초 |
| 축 구동 강성 / 완화 | 5×10⁵ / 4 |
| 가이드 강성 / 완화 | 10⁷ / 4 |
| 끝단 최대 반력 한도 | 10,000N을 스텝 임펄스로 변환 |
| 목표 제한 | 0 ≤ target ≤ stroke |
| 부품 충돌 | 연결된 지지·머리 사이 충돌 제외, 다른 물체와 접촉 유지 |

솔버 허용 오차와 유한한 제약 강성 때문에 실제 위치는 끝단에서 아주 조금 벗어날 수 있습니다. 이동량을 강제로 clamp해 강체 위치를 고치는 방식은 사용하지 않습니다.

## 4. 상태 API와 렌더링

`getPistonState(id)`는 피스톤에 대해 다음 데이터를 반환하고 다른 타입에는 `null`을 반환합니다.

| 필드 | 의미 |
| --- | --- |
| `extension` | 초기 지지·머리 중심 간 거리 1m를 기준으로 실제 상대 위치 변화를 로컬 +Y축에 투영한 추가 이동량 |
| `target` | 구동 목표 거리 |
| `stroke` | 설정한 최대 이동 거리 |
| `load` | 현재 축 구동 힘 / 한도, 표시용 0~1 값 |
| `connected` | 살아 있는 코어와 연결되고 가이드가 끊어지지 않은 상태 |

외형의 머리는 해당 강체를 따르고, 하부 하우징과 로드는 실제 지지부·머리 위치에서 길이와 방향을 계산합니다. 목표값으로 외형만 먼저 늘리지 않습니다. 가이드 파단 후 연결 로드를 남겨 두지 않습니다.

점검 창의 **구동 사용률**과 일반 연결의 **강도 대비 하중비**는 다른 값입니다. 사용률 100%는 피스톤이 최대 힘을 사용한다는 뜻이고, 연결이 반드시 파단된다는 뜻은 아닙니다. 일반 연결 하중비는 여러 제약 방정식 중 가장 큰 값을 강도 기준으로 나눈 게임용 비율이며 재료의 Pa 응력이 아닙니다.

## 5. 승강 시험대

설계 메뉴의 **승강 시험대**는 자유 제작을 함께 엽니다. 3×3 지지 바닥과 피스톤, 상부 십자형 목재 탑재물로 구성합니다. 총 15부품, 질량 20.2kg, 자재 30이며 피스톤 머리와 상부 탑재물의 합은 6.8kg입니다.

Space로 시작하고 Z를 약 2초 누르면 신장합니다. 입력을 놓아 높이 유지를 관찰하고, X로 수축합니다. 피스톤을 클릭하면 일시정지하여 실제 이동량·목표·구동 사용률을 볼 수 있습니다. 출력을 줄이거나 상부 부품을 늘려, 구동 한도가 운동 결과에 미치는 영향을 비교할 수 있습니다.

일반 입력으로 탑재물을 약 1.5m 올리고 유지·수축하는 검사, 낮은 출력에서의 정지, 전원 단절, 기울어진 지지, 직렬 장치와 파단 검사는 [physics_v4.test.mjs](../tests/physics_v4.test.mjs)에 있습니다. 최종 수치는 [VALIDATION.md](../VALIDATION.md)에 기록합니다.
