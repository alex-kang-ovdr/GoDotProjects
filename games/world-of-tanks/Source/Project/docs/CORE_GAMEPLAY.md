# IRON FRONT v3 — 코어 게임플레이 구현 명세

이 문서의 수치·확률·판정은 **이 JavaScript 프로토타입 자체의 규칙**이다. 월드 오브 탱크의 공식 수치나 내부 구현을 설명하지 않는다.
기준 소스: [engine.js](../dist/js/engine.js), [geometry.js](../dist/js/geometry.js), [maps.js](../dist/js/maps.js). UI 연결은 [app.js](../dist/js/app.js), 결과 저장은 [career.js](../dist/js/career.js)를 따른다.
단위는 월드 좌표 `u`, 초 `s`, 라디안이다. `10u = 게임 내 1m`, 속도 표시는 `abs(speed) × 0.36 km/h`. x는 오른쪽, y는 아래쪽이며 각도 0은 오른쪽이다.

## 1. 전차 클래스와 전장

`TANKS`의 기본 전투 수치다. 피해·관통력은 발사 때 변동하며 장갑은 피격 면에 따라 선택한다.

| 클래스 | 이름 | HP | 기본 피해 D | 기본 관통 P | 재장전 s | 전면/측면/후면 장갑 | 구경 메타데이터 |
|---|---|---:|---:|---:|---:|---|---:|
| scout | R-41 정찰형 | 820 | 170 | 128 | 2.65 | 62 / 34 / 24 | 76 |
| medium | M-47 기동형 | 1180 | 242 | 162 | 3.65 | 112 / 68 / 42 | 105 |
| heavy | H-90 중장갑 | 1650 | 335 | 198 | 4.90 | 168 / 94 / 58 | 122 |

| 클래스 | 전진/후진 u/s | 전진 km/h | 가속 u/s² | 차체 회전 rad/s | 포탑 회전 rad/s | 시야 u | 이동 충돌 반경 u |
|---|---:|---:|---:|---:|---:|---:|---:|
| scout | 145 / 74 | 52.20 | 130 | 1.68 | 2.10 | 770 | 18 |
| medium | 112 / 55 | 40.32 | 98 | 1.27 | 1.75 | 660 | 22 |
| heavy | 82 / 39 | 29.52 | 67 | 0.95 | 1.25 | 590 | 25 |

구경은 현재 관통 계산에 사용하지 않는다. 별도 포탑 장갑, 약점 부위, 구경에 따른 장갑 무시 판정은 없다.
전장은 모두 `2400×1600u`다. 일반 전장 ID는 `valley`, `depot`, `ridge`, 훈련은 `training`이다.
일반전 양 팀 편성은 동일한 `[선택 클래스, scout, medium, heavy, medium]`으로 5대씩이며 아군 첫 전차가 플레이어다. 난이도는 HP나 장갑을 바꾸지 않는다.

## 2. 생성·입력·시간 계약

```js
const state = createBattle({
  tankClass: 'medium', difficulty: 'normal', seed: 42,
  mapId: 'valley', mode: 'standard', battleId: 'unique-per-battle'
});
stepBattle(state, {
  throttle: 1, steer: 0, moveAngle: null, movePower: 0,
  aimX: 900, aimY: 800, fire: false, repair: false, smoke: false, ammo: 'AP'
}, 1 / 60);
```

- `throttle`, `steer`는 −1~1로 제한된다. 유효한 `moveAngle`과 `movePower > 0.05`가 있으면 방향 이동 입력이 두 값을 대체한다.
- `aimX/Y`는 화면 좌표가 아닌 월드 좌표다. `ammo`는 `AP` 또는 `HE`; 나머지 액션은 불리언이다.
- UI는 누산기로 `1/60s` 고정 틱을 실행한다. 엔진 API는 유효한 양수 dt를 받고 호출당 최대 `0.25s`, 내부 단계당 최대 `1/30s`로 나눈다.
- `paused`, `phase !== 'playing'`, 0·음수·비유한 dt에서는 전투 상태를 변경하지 않는다. UI 카운트다운은 별도 모드이며 그동안 `paused = true`다.
- 한 틱의 순서는 시간/만료 → 부품·장전·쿨다운 감소 → 탐지 및 고정/집중 표적 유효성 갱신 → 입력/AI와 이동 → 전차 간 분리 → 고정 유효성·발사 조건 재확인 → 발사 → 포탄 충돌 → 점령 → 전멸/시간 판정이다.
- 연막·수리는 UI에서 한 번 요청한 뒤 첫 실제 틱에서 해제한다. 계속 참으로 넣으면 쿨다운과 조건이 다시 충족될 때 재사용된다.
- 같은 seed, 입력, 틱 호출 순서에서 난수가 재현된다. 기본 `battleId`는 seed 기반이므로 저장할 실제 전투에는 UI처럼 고유 ID를 제공한다.

## 3. 이동·충돌·포탑 조준

`moveTank`, `separateTanks` 기준이다. 아래 `clamp`는 범위 제한, `angleDelta`는 −π~π의 최단 각도 차이다.

```text
방향 이동: steer = clamp(angleDelta(moveAngle, hullAngle) × 2.7, −1, 1)
            throttle = clamp(movePower, 0, 1) × clamp(1 − abs(각도차)/1.7, 0, 1)
회전 계수 = 1 − min(0.25, abs(speed)/기본전진속도 × 0.25)
차체각 += steer × 기본회전속도 × 회전계수 × 지형선회배율 × dt
엔진 계수 = 엔진 손상 중이면 0.6, 그 외 1
목표속도 = throttle × (전진속도 또는 후진속도) × 엔진계수 × 지형속도배율
가속한도 = 기본가속 × 엔진계수 × 지형가속배율 × (abs(목표속도)<abs(현재속도) ? 1.8 : 1)
속도 += clamp(목표속도−속도, −가속한도×dt, 가속한도×dt)
```

`surfaceAt(map,x,y)`는 현재 전차 중심의 지형을 반환하며 `tank.surfaceId`는 이동 이후 위치의 지형 ID다. 배율을 기본 클래스 수치에 한 번 곱해 계산하고, 매 틱 현재 수치에 누적 곱하지 않는다.

| 지형 ID | 표시 | 최고 속도 배율 | 가속 배율 | 차체 선회 배율 |
|---|---|---:|---:|---:|
| plain | 평지 | 1.00 | 1.00 | 1.00 |
| road | 도로 | 1.08 | 1.15 | 1.00 |
| mud | 진흙 | 0.64 | 0.58 | 0.78 |
| rough | 험지 | 0.82 | 0.75 | 0.88 |

지형 판정은 `surfaceZones` 타원 → 도로 선분 → 평지 순서다. 타원은 `((x-cx)/rx)²+((y-cy)/ry)² <= 1`로 판정하며 겹치면 배열의 앞 타원이 우선한다. 도로는 선분까지의 최단 거리가 폭의 절반 이하인 영역이다. 주 도로 폭은 88u, 나머지는 62u이며 `roadWidths`가 실제 렌더링과 판정에 공통으로 쓰인다.
`SURFACES`에 직접 정의된 ID만 인정한다. `constructor`와 같은 상속 속성 이름은 지형으로 사용하지 않는다. 잘못된 좌표는 평지로 처리한다.
도로와 타원은 시각 효과만이 아니라 실제 기동 성능을 바꾼다. 엔진 손상과 지형을 동시에 적용한 진흙의 최고속도는 기본값×0.64×0.6이다. 후진도 같은 지형 배율을 쓰며 포탑 회전에는 지형 배율을 적용하지 않는다.

이동은 차체 방향으로 적분한다. 전차 중심은 맵 경계에서 `radius+6u` 이상 떨어져야 하며 장애물과 원형 충돌한다.
전체 이동이 막히면 x·y축을 순차 시도해 벽을 따라 미끄러진다. 일부 이동 성공 시 속도 ×0.86, 완전 차단 시 ×0.2다.
살아 있는 전차끼리는 최소 거리 `r1+r2+2u`를 확보하도록 양쪽을 밀어낸다. 충돌·충각에 의한 HP 피해는 없다.
궤도 손상 중에는 가속 입력과 차체 회전 입력이 0이고 잔여 속도에 `exp(−18dt)`를 추가 적용한다. 포탑·사격은 계속 가능하다.
포탑은 차체와 독립된 월드 각도를 유지하며 조준점 방향으로 틱당 `turretRate×dt`까지만 회전한다. 자유 조준의 발사는 포탑 정렬을 강제하지 않으며, 목표 고정 중의 발사는 아래 고정 조건을 추가 확인한다.

```text
목표 bloom = abs(speed)/기본전진속도 × 0.026 + abs(포탑회전량)/max(dt,0.001) × 0.009
bloom += (목표bloom − bloom) × min(1, dt×3.2)
분산각 dispersion = 0.006 + bloom
발사각 = 현재포탑각 + (U1 + U2 − 1) × dispersion
발사 후 bloom = min(0.07, bloom + 0.018)
```

U는 각각 독립적인 `[0,1)` 난수다. 유효 조준 입력이 없으면 bloom은 `exp(−3.2dt)`로 감쇠한다. 분산은 원형 명중 확률 모델이 아닌 2D 각도 오차다.

## 4. 발사·재장전·장갑·AP

`fire`, `updateProjectiles`, `armorAtAngle`, `hitTank` 기준이다. 살아 있고 `reloadLeft <= 0`일 때만 발사한다. 탄약 수량은 제한하지 않는다.
최초 AP는 즉시 발사 가능하다. 탄종 변경 시 `ammo`를 즉시 바꾸고 **현재 유효 재장전 시간 전체를 다시 요구**한다. 같은 탄종을 유지하면 장전을 다시 시작하지 않는다.
포구는 중심에서 `radius×1.95+6u` 앞이다. 중심→포구 선분에서 장애물과 다른 생존 전차의 차체를 함께 검사하고 가장 가까운 교차점보다 0.1u 앞쪽, 즉 발사자 쪽에서 포탄을 생성한다. 포신이 벽이나 밀착한 전차 내부에 있을 때 대상을 건너뛰거나 진입 장갑 면을 잃지 않는다.
AP 속도는 `1090u/s`, HE 속도는 그 0.78배다. 공통 사거리 기준은 `1270u`; 중력·곡사·관통 후 잔여 포탄은 없다.
포탄은 매 틱 이동 선분의 가장 가까운 장애물 또는 생존 전차와 충돌한다. 차체 피탄 형상은 회전 직사각형 `길이 2.2r × 폭 1.56r`이며 실제 교차면으로 장갑 부위를 정한다.
사거리·맵 이탈 제거보다 그 틱의 선분 충돌이 먼저 평가되므로 사거리 끝은 한 틱 단위 근사다. 사거리 끝에서 HE는 피해 없는 시각 효과만 낸다.

```text
발사 피해 Droll = 기본피해 × (0.875 + U×0.25)       // ±12.5%
발사 관통 Proll = 기본관통 × (0.85 + U×0.30)      // ±15%
유효장갑 E = 해당면 명목장갑 A / max(0.04, cos(입사각 α))
거리계수 F = 1 − clamp((포구부터 비행거리 − 450)/5000, 0, 0.16)
AP 관통 조건 = α < 70° 이고 Proll×F >= E
HP 피해 = min(현재HP, max(1, round(Droll)))
```

입사각은 포탄 진행 방향의 반대쪽과 피격 면 법선의 각도 차이며 0~90°다. 면이 주어지지 않은 보조 계산은 전방 ±45°를 전면, 후방 ±45°를 후면, 나머지를 측면으로 분류한다.
AP 불관통·도탄은 HP 피해 없이 피격 전차 `blocked`에 `round(Droll)`을 더한다. 튕겨 나간 포탄의 추가 충돌은 시뮬레이션하지 않는다.
아군은 AP를 막지만 피해를 받지 않는다. 아군에 HE가 충돌하면 폭발은 발생하며 적군만 피해 대상이 된다.

## 5. HE 직격·폭발·엄폐물

`explodeHE`, `damageObstacle` 기준이다. 직격 계산은 경사에 따른 유효장갑 대신 **명목장갑 A**를 사용하며 거리 관통 감소·자동 도탄을 적용하지 않는다.

```text
HE 관통 = Proll×0.32 > A
직격배율 M = 관통이면 1.18, 아니면 max(0.22, 0.63 − A/530)
직격 피해 = Droll×M
폭발거리 d = max(0, 폭발점과 전차중심 거리 − 전차반경)
폭발 피해 = Droll×0.58×(1 − d/82)×max(0.23, 1 − A/275)
```

폭발은 `d <= 82u`인 다른 적 전차만 검사하며 직격 대상을 중복 공격하지 않는다. 계산 피해 5 미만은 무시하고 이후 공통 HP 반올림·잔여 HP 제한을 적용한다.
폭발 장갑 A는 폭발점→대상 방향으로 선택한다. 별도 폭발 표면 추적은 하지 않으며, 부품 판정에 전달하는 면은 `side`다.
폭발점은 충돌면 법선 방향으로 1.5u 이동시켜 시선을 검사한다. 장애물 뒤 전차는 보호되며, 이번 직격으로 생긴 직접 대상의 잔해만 폭발 차폐에서 제외한다.
벽은 기본 HP 360이며 AP로 `Droll×0.8`, HE로 `Droll×2` 피해를 받는다. 파괴 시 즉시 충돌·탐지 차폐에서 제외되고 `map.version`이 증가한다.
건물·바위·전차 잔해는 현재 파괴할 수 없다. 벽에 포탄이 충돌하면 벽을 먼저 손상시키므로 같은 HE로 무너진 벽은 이어지는 폭발 시선을 더 이상 막지 않는다.

## 6. 조준 예측 API의 의미와 한계

`aimStatus(state,x,y)`는 플레이어 위치에서 조준점 거리+45u까지, 최대 1270u의 광선을 검사한다. 미발견 적은 예측 대상에서 제외하지만 실제 포탄 충돌에서는 제외하지 않는다.
반환값은 `target`, `distance`, `effectiveArmor`, `hitZone`, `penetrable`, `blocked`, `blockedReason`, `penetrationChance`, `angleDegrees`, `aligned`, `estimatedDamage`다.
적 대상이 있으면 distance는 두 전차 중심 거리다. 대상이 없으면 조준점 거리다. 엄폐·아군 차단은 `blockedReason: 'cover' | 'ally'`; 아군을 target으로 반환하지 않는다.

```text
aligned = abs(angleDelta(조준점각, 현재포탑각)) < 0.035
Pavg = 기본관통 × 거리계수(포구→예상 피격점)
AP 확률 q = 도탄각이면 0, 아니면 clamp((Pavg×1.15 − E)/(Pavg×0.30), 0, 1)
AP penetrable = q >= 0.5; 예상피해 = round(기본피해×q)
HE 내부 관통확률 h = clamp((기본관통×0.32×1.15 − A)/(기본관통×0.32×0.30), 0, 1)
HE 예상피해 = round(기본피해×[h×1.18 + (1−h)×max(0.22,0.63−A/530)])
```

HE는 `penetrable: null`, 외부 `penetrationChance: 0`으로 반환하므로 UI는 폭발 예상 피해를 표시한다.
예측은 조준선 직격 조건의 수치다. 분산·표적 이동·잔여 HP·폭발 다중 피해를 포함하지 않으며, 미정렬·엄폐 시에도 계산값 자체를 0으로 바꾸지 않는다. UI가 `aligned`와 `blocked`를 별도 표시해야 한다.
확대 조준은 카메라 표시만 바꾸며 관통력·분산·시야 수치를 강화하지 않는다.

### 6.1 목표 고정

| API | 반환·동작 |
|---|---|
| `acquireTarget(state,aimX,aimY)` | 고정 가능한 전차 객체 또는 `null`; 조준점 부근과 조준 방향에서 후보 검색 |
| `setTargetLock(state,targetId)` | 성공 여부 불리언; 유효한 적을 `state.lockTargetId`에 저장 |
| `setTargetLock(state,null)` | 고정 해제, 성공 시 `true` |
| `getLockedTarget(state)` | 현재 조건을 만족하는 고정 표적 객체 또는 `null`; 유효하지 않은 객체를 반환하지 않음 |

고정 대상은 플레이어가 살아 있는 진행 중 전투의 생존 적이며, 팀 가시성과 `visibleUntil`이 모두 유효하고 중심 거리가 1270u 이하여야 한다. 새 고정은 일시 정지 중에 거부한다. 훈련의 항상 보이는 표적에는 고정을 사용할 수 있다.
획득은 짧은 터치 조준점 거리로 끝나지 않고 최대 고정 범위의 후보를 검색한다. 커서와 표적 거리 `max(65u,2.6r)` 이내 또는 조준 방향과의 각도차 0.28rad 이내를 후보로 삼는다. 점수 `각도차×900 + 커서거리×0.18 − (커서 범위 안 ? 400 : 0)`이 가장 낮은 표적을 선택한다.
고정 상태에서는 플레이어의 조준 입력 좌표를 표적 중심으로 바꾼다. 포탑 속도·분산·장전·피해는 기존 계산을 유지하며 AI처럼 속도 기반 선행 조준을 하지 않는다. 고정만으로는 `fire`를 만들지 않는다.
발사 입력이 있고 고정이 유효할 때는 이동·차체 분리 후의 실제 포탑과 표적 방향 오차가 0.035rad 미만이어야 한다. 고체 엄폐물이 없고, 발사자→표적 선분이 생존 아군의 `radius+7u` 원을 지나지 않아야 한다. 일반 재장전·생존 조건도 그대로 적용한다.
사망·팀 가시성 상실·1270u 초과·플레이어 격파·종료로 유효하지 않으면 고정을 해제한다. 고정을 잃는 틱에는 이전 고정 상태의 발사 요청을 실행하지 않는다. `getLockedTarget`은 다음 틱의 저장 상태 정리 전에도 유효성을 다시 확인한다.
UI의 R·고정 버튼은 획득/해제를 전환한다. 터치 조준 스틱의 수동 입력은 고정을 해제한다. 터치 HUD의 장갑 예측은 짧은 화면 조준점과 별도로 같은 방향의 1270u 지점을 `aimStatus`에 전달하므로 화면 크기 때문에 예측 사거리가 줄지 않는다.

## 7. 부품 손상·수리

`damageTank`, `damageModule`, `syncReloadMultiplier` 기준이다. 부품은 별도 HP가 아닌 남은 손상 시간으로 관리하며 재손상은 `max(기존시간, 새지속시간)`이다.

| 부품 | 발생 조건 | 지속 | 기능 영향 |
|---|---|---|---|
| 궤도 | HP 피해 측면 24%; 그 외 HE 16%, AP 5% | 4.2s | 차체 가속·회전 중지, 잔여 속도 급감 |
| 궤도 | AP 측면 불관통·도탄 중 10% | 2.8s | 동일 |
| 엔진 | 관통한 후면 HP 피해 중 32% | 8s | 전진·후진 최고속도와 가속 ×0.6 |
| 탄약고 | 관통한 측면 HP 피해 중 22% | 12s | 재장전 시간 ×1.6 |

HE 직격은 실제 HE 관통 시에만 엔진·탄약고를 손상시킨다. HE 주변 폭발은 전달 면이 side여서 궤도 확률 24%이며 엔진·탄약고 관통 손상은 없다.
궤도 판정은 엔진·탄약고 판정과 별도로 수행해 동시 손상이 가능하다. 이벤트의 `module`은 마지막으로 선택된 한 부품이므로 전체 상태는 tank의 타이머를 읽는다.
탄약고 손상·복구 전환 시 `reloadLeft = reloadLeft / 이전배율 × 새배율`로 진행률을 보존한다. 매 틱 1.6배를 누적 적용하지 않는다.
수리 입력은 손상 부품이 있고 쿨다운 0일 때 궤도·엔진·탄약고를 모두 복구한다. HP는 회복하지 않으며 쿨다운은 30s, 사용 횟수 제한은 없다.

## 8. 팀 탐지·수풀·연막·정찰 지원

`detectable`, `updateVisibility`, `creditAssistance` 기준이다. 탐지는 약 0.12s 간격으로 갱신되며 모든 생존 아군 관측자의 결과를 공유한다.
거리 85u 이하는 근접 탐지로 장애물·연막·수풀을 무시한다. 그 밖에는 연막 차폐 → 시야 거리 → 고체 장애물 → 수풀 감소 순서로 검사한다.
기본 탐지 거리는 관측자 클래스의 viewRange다. 대상이 경전차면 ×0.92; 대상이 발사 후 3.3s 내면 ×1.18이며 수풀 감소를 무시한다.
발사 노출 중이 아니고 대상 중심이 수풀 원 안이면, 대상 `abs(speed)>18`일 때 ×0.72, 그 외 ×0.47을 추가 적용한다. 수풀은 물리 충돌이나 포탄을 막지 않는다.
한 관측자라도 발견하면 상대 팀의 `visibleUntil`을 현재 시각+4s로 갱신한다. 기억 시간 중에도 적 위치·HP는 가시 상태로 갱신되며 이후 `lastSeen`이 남는다.
최초 발견 수는 대상·팀별 한 번만, 그때 탐지 가능한 가장 가까운 관측자에게 준다. 플레이어 피탐 경고는 새 피탐 전환이고 직전 경고로부터 6s 초과일 때 발생한다.

연막은 차량마다 2회, 반경 145u, 지속 7s, 재사용 대기 25s다. 전개 위치에 고정되며 `smokeClouds`로 관리한다.
관측자→대상 선분이 연막 원과 교차하면 85u 밖의 탐지를 막는다. 연막은 이동·포탄·폭발 시선을 막지 않는다.
아무 관측자도 발견하지 못하고 일부 관측자의 시선에 연막이 걸렸다면 기존 탐지 기억을 최대 1s로 단축한다. 다른 아군이 계속 발견하면 공유 탐지가 유지된다.
연막은 궤도·엔진·탄약고 수리와 독립된 자원이다. 사격 중에도 사용할 수 있으며 훈련 표적은 항상 보이는 예외다.

지원 피해는 공격자가 직접 탐지할 수 없는 적에게 팀 탐지를 이용해 HP 피해를 줄 때만 발생한다. 현재 탐지자 또는 유효 기억 내 마지막 탐지자 중 생존하고 공격자가 아닌 전차가 대상이다.
실제 HP 피해를 탐지자 수로 나눠 정수 배분하고 마지막 대상에게 나머지를 준다. 직접 피해와 지원 피해는 별도 필드이며 최초 발견과 지원 피해도 별개다.

## 9. AI·명령·잔해·경로 탐색

`aiControl`은 0.12s마다 판단한다. 팀이 발견한 적만 후보로 삼고 거리, 사선 차단 +240, 기존 표적 −65, 한 발 격파 예상 −90, 유효한 집중 사격 대상 −10000 점수를 합산해 가장 낮은 후보를 선택한다.
적 AI 난이도별 기본 반응은 쉬움/보통/어려움 `0.9/0.55/0.25s`, 조준 오차 최대값은 `0.072/0.043/0.022rad`다. 새 표적 반응은 기본값~2배의 난수이며 아군 AI는 항상 보통이다.
이동 표적 조준은 `표적 위치 + 표적 속도×(거리/1090)×0.72`를 사용한다. AI는 AP만 쓰고, 엄폐·연막·아군 사선·거리<1170u·포탑 오차<0.065rad·반응 시간을 확인한 뒤 발사한다.
선호 교전 거리는 경전차 425u, 중형 410u, 중전차 330u다. 경전차는 거리 210~640u, 적 정면 범위, HP>35% 조건에서 측면 260u 지점으로 우회한다.
중형·경전차는 거리<620u에서 재장전>1.2s 또는 HP<30%이면 가까운 고체 엄폐를 찾는다. 중전차는 차체 정면을 적 쪽으로 유지하며 가까운 전선을 선호한다.
AI는 손상 부품이 있으면 수리를 요청한다. HP<32%, 최근 2.2s 내 피격, 피탐 중이며 재장전>1s 또는 부품 손상일 때 연막을 요청한다.
아군 때문에 사선이 막힌 시간이 0.4s 이상이고 장전이 1.2s 미만 남았으며 엄폐 이동 중이 아니면, 표적 방향의 좌우 75/120/180u와 뒤 20u를 조합한 후보에서 새 사격 위치를 찾는다. 이동 가능성·이동 경로·표적 사선·연막·다른 아군과의 간격을 확인하며 이 조건을 무시하고 사격하지 않는다.
엄폐 위치와 사격 위치를 고를 때 다른 아군과 반경 합+12u보다 가까운 후보를 제외하고, 130u 안의 혼잡과 다른 아군의 엄폐 목표에도 비용을 더한다.

`issueOrder(state,'attack'|'defend'|'follow'|'move',details)`는 25s 동안 아군 AI 이동 목표를 조정한다. 공격은 중원 이후 기지 집중, 방어는 아군 기지 주변 분산, 지원은 플레이어 뒤·옆의 대형이다.
`move`의 `details`는 유한한 월드 좌표 `{x,y}`다. 중전차 반경+15u, 즉 40u의 여유를 적용하고 맵 경계에서 추가 6u를 둔다. 고체 장애물과 겹친 지점은 중전차 경로 격자의 가까운 빈 셀로 보정하되 320u 이내에서 안전한 지점을 찾지 못하면 명령을 거부한다. 실패한 요청은 이전 명령을 덮어쓰지 않는다.
이동 명령 상태는 `{type:'move',x,y,until}`이다. 분대는 기준점에서 `(−60,−60)`, `(60,60)`, `(−60,60)`, `(60,−60)`u의 개별 목표를 갖고 각 위치도 같은 안전 보정을 거친다. 목표 45u 안에서는 멈추며 근처의 사선 확보 기동을 허용한다.
명령은 유효 표적과 사격 판단을 유지한다. 아군 기지 점령>5이며 해당 AI와 기지 거리<1300u인 긴급 방어가 명령보다 우선한다. 훈련·일시 정지·종료·플레이어 사망 상태에서는 명령을 거부한다.

`issueFocusFire(state,targetId)`는 생존하고 팀이 현재 발견한 적을 15s 우선 표적으로 지정하고 불리언을 반환한다. `state.focusTarget={targetId,until}`은 이동 명령인 `state.order`와 별개이며 기존 이동 명령 객체를 바꾸지 않는다. 아군의 다음 판단을 즉시 요청하지만 반응 지연·시야·사거리·포탑 정렬·사선·장전 조건을 생략하지 않는다.
집중 대상은 플레이어로부터 1270u 제한을 추가로 받지 않는다. 공유 시야로 보이는 적에 명령할 수 있고 각 아군은 자신의 교전 조건에 따라 접근하거나 발사한다. 대상 격파·팀 가시성 상실·15s 만료·플레이어 격파·전투 종료 시 해제한다. 훈련·일시 정지·종료·플레이어 사망 중의 신규 집중 명령은 거부한다.

경로는 64u 격자 A*의 8방향 탐색이며 대각선 모서리 통과를 금지한다. 클래스별 격자 여유 반경은 `tank.radius+15u`, 평활화 시 여유는 `radius+7u`다.
장애물 때문에 경로 탐색이 필요할 때 셀 이동 비용에 지형 최고속도 배율의 역수를 사용한다. 경로 평활화도 32u 간격으로 추정한 지형 통과 비용을 비교해 원래 경로보다 3%를 초과해 비싸지는 지름길은 채택하지 않는다. 고체 장애물 없는 직접 이동은 목표로 직진하므로 언제나 최단 시간의 도로 우회를 찾는 전역 최적화는 아니다.
경로 재계산은 보통 1.3~1.8s 간격 또는 목표가 125u 초과 이동한 경우다. 1.3s 동안 주행 요청 대비 이동<10u이면 0.85s 후진·회전해 막힘을 해소한다.
격파 전차는 `1.8r×1.5r`의 축 정렬 불파괴 장애물이 된다. 이동·시선·포탄을 막고 `map.version`을 올려 다음 경로 격자 조회 때 캐시를 폐기한다. 잔해 장애물의 `invisible`은 중복 그림 방지용이며 물리 비활성 표시가 아니다.
격파 순간 보이지 않던 적의 잔해는 미발견 상태를 유지한다. 생존 아군이 85u 근접 범위에 들어오거나, 해당 아군 시야 거리 안에서 연막과 고체 차폐 없이 관측하면 발견된다. 이 잔해 자체의 장애물 ID만 발견 시선에서 제외하며 다른 장애물은 계속 차폐한다. 발견한 정지 잔해는 `visibleToPlayer=true`, `visibleUntil[0]=Infinity`, `lastSeen.hp=0`으로 알려진 정보가 되어 이후 시야 밖에서도 남는다.

## 10. 점령·승패·훈련 종료

일반전 기지는 `(240,800)`, `(2160,800)`, 반경 125u다. 중심이 원 안에 있는 생존 전차를 참가자로 센다.
적 기지 공격자 n대의 총 점령 속도는 `4×min(3,n)`%/s다. 각 참가자에게 이를 n으로 나눠 기여를 적립하므로 1/2/3대 점령은 방해가 없으면 약 25/12.5/8.33s가 걸린다.
수비자가 함께 있으면 추가 적립만 멈춘다. 공격자가 원을 벗어나거나 HP 피해를 받거나 격파되면 그 전차의 기존 기여가 지워진다. 다른 참가자의 기여는 남는다.
기여 합계가 100%면 승리, 한 틱에서 양쪽 기지가 동시에 완료되면 무승부다. 점령 판정은 같은 틱의 전멸·시간 판정보다 먼저 실행된다.
점령으로 끝나지 않았다면 양 팀 전멸은 무승부, 한쪽만 전멸하면 반대쪽 승리다. 플레이어 개인 격파 후에도 아군이 살아 있으면 전투는 계속된다.
360s 제한 시간에는 생존 대수 우선, 동수면 생존 전차의 `sum(hp/maxHp)`를 비교한다. 두 합의 차가 0.01 미만이면 무승부다.
종료는 `phase='ended'`, `winner=0|1|null`, `resultReason`을 확정하고 `end` 이벤트를 한 번 남긴다. 이후 stepBattle 호출은 전투를 진행하지 않는다.
훈련은 플레이어 1대와 고정 표적 3대, 기지 없음, AI 사격·이동 없음, 표적 항상 가시 상태다. 시작점은 `(400,800)`이며 정면/측면/후면 방향의 표적을 배치한다.
표적 3대가 모두 파괴되어야 훈련 완료다. 표적이 남은 채 360s가 지나면 `winner=null`의 미완료 종료이며 잔존 내구도로 수료를 주지 않는다. 훈련 결과는 career에 기록하지 않는다.

## 11. 상태·통계·이벤트 소비 계약

공유 상태의 주요 그룹은 시간/phase, map/bases, tanks/projectiles, smokeClouds, effects/events, order, lockTargetId, focusTarget이다. `state.statistics`는 플레이어 `tank.stats`와 **같은 객체**이므로 이중 합산하지 않는다.
전차는 위치·차체각·포탑각·속도, surfaceId, HP/alive, ammo/reloadLeft/reloadTime, trackDisabled, modules, 수리·연막 쿨다운, smokeCharges, visibleUntil/visibleToPlayer/lastSeen을 가진다.
통계는 damage, kills, shots, hits, blocked, assisted, spots, captures, damageReceived, distanceTravelled다. damage는 실제 감소 HP이며 과잉 피해를 포함하지 않는다.
AP는 적 차체에 닿으면 불관통도 hits에 포함한다. HE는 한 발이 여러 적을 피해 줘도 hits는 최대 1이다. 아군·장애물만 맞힌 경우는 명중으로 세지 않는다.
distanceTravelled는 월드 단위의 주행 이동량이며 전차 간 겹침 보정 이동은 포함하지 않는다. captures는 플레이어의 순간 기여 최고값을 반올림한 수치이고 점령 횟수나 전체 팀 누적 점령량이 아니다.
이벤트 공통 필드는 `{id,type,time}`다. id는 전투 내 증가하며 최근 40개만 보존하므로 소비자는 마지막 처리 ID를 기억한다. 영구 리플레이 로그가 아니다.

| type | 핵심 추가 필드와 소비 주의 |
|---|---|
| fire / ammo | actor, team, ammo; fire에만 x/y |
| hit | actor, target, team, x/y, damage; 전차 피해에는 ammo, hitZone, angle, angleDegrees, penetrated, critical, module, visibleToPlayer |
| bounce | actor, target, damage=0; 일반 장갑 판정은 ammo, hitZone, angleDegrees, penetrated=false, ricochet; 아군 차단 이벤트는 일부 필드 없음 |
| destroyed | actor가 null일 수 있음; target, team, x/y, visibleToPlayer; team은 보통 공격자 팀 |
| repair / smoke | actor, team, x/y, text; repair의 target은 없음 |
| spot / assist | 플레이어에게 발생한 알림; actor, target, team, text; assist에는 damage; x/y 없음 |
| spotted / order | spotted는 플레이어 피탐 경고와 x/y; order는 actor, team, text와 지점 이동일 때 x/y 추가 |
| lock / focus | actor, target, team, visibleToPlayer=true, text; 고정 해제 이벤트의 target은 null |
| capture / end | capture는 참가자 actor·기지 target·x/y; end는 team=승자 또는 null, actor/target=null |

낮은 담장 파괴도 `hit`이지만 damage=0이고 전차 피격 부가 필드가 없다. 이벤트 이름만 보고 모든 필드가 존재한다고 가정하지 않는다.
effects는 화면 연출용이며 최대 140개를 보존한다. ownerId, targetId, visibleToPlayer로 가시성을 확인하고 숨겨진 적의 연출을 노출하지 않는다. 렌더러·오디오는 전투 규칙의 원본 상태를 변경하지 않는다.

## 12. 전술 지도·입력·기록 UI 계약

`renderer.renderTacticalMap(state,canvas,{cursor})`와 미니맵은 같은 지도 투영과 가시성 규칙을 사용한다. 맵 전체를 종횡비 유지로 맞추고 CSS 크기와 최대 2배 DPR에 따라 캔버스 해상도를 설정한다. `tacticalMapToWorld(canvas,cssX,cssY)`는 최근 투영을 역변환하며 맵 내용 밖의 여백이나 비유한 좌표는 `null`이다.
아군·현재 보이는 적·알려진 잔해·기지 점령·알려진 연막만 현재 정보로 표시한다. 적의 마지막 발견 위치는 최대 24s 동안 흐린 점선과 경과 시간으로 구분한다. 숨겨진 적이 죽어도 기존 마지막 발견 표시는 원래 만료 시각까지 유지하므로 사망 여부를 지도에서 먼저 알 수 없다. 목표 고정·집중 사격 표시는 생존하고 가시 상태인 대상만 사용한다.
T·지도 버튼·미니맵 입력은 전술 지도 모달을 열고 전투를 정지한다. 빈 지점 선택은 지점 이동, 발견된 적 선택은 집중 사격 명령이다. 정상 전투의 생존 플레이어만 명령할 수 있으며 명령 확정 시 전투를 재개한다. 실패하면 안내하고 지도로 돌아온다. 일시 정지 창에서 열었다가 명령 없이 닫으면 원래 일시 정지 창으로 복귀한다.
지도 방향키는 80u, Shift+방향키는 160u 간격으로 커서를 움직인다. 지도 캔버스에 초점이 있을 때 Enter가 선택을 확정한다. Tab·Shift+Tab은 모달 안의 초점을 순환하며 T·Esc·돌아가기로 취소할 수 있다. 훈련·출격 대기·격파 후에는 지도 열람만 가능하다.
WASD·방향키·Space 같은 연속 입력은 카운트다운 중부터 누름/뗌 상태를 기록한다. 탄종·수리·연막·명령처럼 한 번 실행하는 동작은 실제 전투 중에만 요청한다. 마우스 사격과 터치 사격 버튼은 각 포인터 소유권을 기록해 다른 손가락을 떼는 이벤트로 사격이 끊기지 않게 한다. 모달·포커스 이탈 시 입력과 포인터 캡처를 해제한다.
탄종 버튼은 플레이어 격파 후 비활성화하고 훈련에서는 적의 공격 능력이 없는 표적에 대한 피탐 경고를 HUD에 표시하지 않는다. 이 UI 예외가 일반 전투의 실제 탐지 판정을 바꾸지는 않는다.
전적의 총 전투 수에는 v1에서 가져온 승패 미확인 전투가 남아 있을 수 있다. 승률 표시는 `sum(operations.wins)/sum(operations.played)`로 계산하고 알려진 경기가 없으면 `—`를 표시한다. 이전 미확인 경기를 패배로 간주하지 않으며 전체 전투 수와 최고 피해 이관은 유지한다.
