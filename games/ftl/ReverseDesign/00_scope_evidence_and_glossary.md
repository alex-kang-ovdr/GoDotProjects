# 00. 분석 범위·근거 수준·공통 용어

> 대상: **FTL: Faster Than Light / PC판 / 원작 규칙 + Advanced Edition(AE)**  
> 작성·자료 확인: **2026-11-13**  
> 문서 성격: 공개 자료로 확인한 게임 규칙을 바탕으로 한 역기획. 내부 소스코드 분석이나 실제 실행 계측 보고서가 아니다.

## 1. 이 문서 묶음의 목표

FTL의 플레이 경험을 재현하려면 함선 공격 기능만 만드는 것으로 충분하지 않다. 항해에서는 한 번 더 탐색할 가치와 반군의 추격을 비교하고, 전투에서는 같은 전력을 실드·엔진·무기·산소 중 어디에 사용할지 결정해야 한다. 이 과정에서 승무원의 위치, 문, 산소, 수리, 적의 행동이 서로 영향을 준다.

이 역기획서는 그 연결을 **상태, 조건, 입력, 처리 결과, 예외, 검증 시나리오**로 풀어 설명한다. 개별 시스템의 상세 문서는 독립적으로 읽을 수 있고, 재구현 설계는 실제 게임에서 확인되는 규칙과 분리한다.

### 예상 독자와 사용 방법

| 독자 | 먼저 볼 문서 | 활용 목적 |
|---|---|---|
| 게임 기획자 | 01~04, 14, 18 | 선택 구조·성장·콘텐츠 분포 파악 |
| 게임플레이 프로그래머 | 05~13, 15~16, 19 | 상태와 시스템 간 계약 정의 |
| UI/UX 담당자 | 01, 07, 17 | 일시정지와 명령·정보 표현 설계 |
| 콘텐츠 제작자 | 02~03, 14~16, 20 | 이벤트·함선·적·보스 제작 규칙 |
| QA 담당자 | 00, 21, 90 | 사실과 가설을 분리하고 검증 우선순위 설정 |

## 2. 포함·제외 범위

| 항목 | 범위 |
|---|---|
| 기본 플레이 | 싱글플레이, 한 척의 함선, 승무원 관리, 실시간 전투와 일시정지 |
| 항해 | 섹터·비콘 이동, 반군 추격, 위험 지역, 이벤트, 연료 부족 |
| 함선 | 방·문·시스템·서브시스템·전력·실드·선체 |
| 전투 | 무기·드론·강습·화재·균열·산소·회피·적 AI |
| 확장 | 해킹·정신 지배·클론실·보조 배터리·라니우스 등 AE 요소 |
| 장기 진행 | 함선 및 레이아웃 해금, 업적, 런 결과 |
| 최종전 | The Last Stand와 반군 기함 3단계 |
| 재구현 지원 | 데이터 모델, 콘텐츠 제작 규칙, 저장 경계, 테스트 목록 |
| 범위 밖 | Multiverse·Captain's Edition·Hyperspace 등 모드 고유 규칙, 멀티플레이 설계, 원본 리소스의 추출·배포 |
| 별도 확인 필요 | iPad 고유 조작, 플랫폼별 버그, 특정 패치의 프레임 단위 동작 |

공식 소개는 실시간 중 일시정지, 승무원 명령, 전력 분배, 무기 표적 선택, 무작위 여정과 영구 사망을 핵심으로 제시한다. AE는 무료 확장으로 본편에 통합되어 있다. 이 문서는 AE 기능을 포함하되 해당 내용이 기본 모드에도 적용되는지 구분한다. [O1][O2]

## 3. 근거 표기 규칙

| 표기 | 의미 | 읽는 방법 |
|---|---|---|
| **[확인]** | 공식 설명 또는 게임 규칙 자료에서 확인한 동작 | 공개 문헌 확인이며 모든 항목을 실행 검증했다는 의미는 아님 |
| **[해석]** | 여러 규칙으로부터 도출한 설계 의도·전략적 의미 | 개발자의 공식 발언으로 인용하면 안 됨 |
| **[재구성안]** | 같은 경험을 구현하기 위해 제안하는 구조·알고리즘 | 원작의 클래스명·소스코드·정확한 내부 처리 순서가 아님 |
| **[검증 필요]** | 자료 충돌, 접근 제한, 특정 빌드에서의 예외 | 실제 실행 또는 허가된 로컬 데이터 확인 전 상수로 고정하지 않음 |

별도 표시가 없는 JSON, 타입 정의, 의사코드, 이벤트 ID 예시는 **재구성안**이다. 예를 들어 `RunState`, `DamagePacket`, `EventDefinition` 같은 이름은 문서 설명용이며 원본의 실제 식별자가 아니다. 예시에서 임의로 부여한 보상이나 확률은 **예시값**으로 표시한다.

### 출처 수준

| 수준 | 자료 | 장점 | 제한 |
|---|---|---|---|
| A | 개발사 소개, 개발자가 작성한 패치노트, 판매사에 게시된 공식 설명 | 제품 의도와 제공 기능의 일차 근거 | 전투 상수나 예외를 모두 공개하지 않음 |
| B | FTL 커뮤니티 위키의 개별 메커니즘 문서 | 수치·예외·관찰 결과가 상세 | 버전 누락·편집 오류·페이지 간 충돌 가능 |
| C | 플레이어의 실험 자료·분석 도구 | 경계 사례의 재현 조건 파악 | 표본과 실험 설정을 확인해야 함 |
| D | 이 문서의 분석 및 설계 제안 | 구현을 위한 완결된 계약 제공 | 원작 구현과 동일하다고 보장하지 않음 |

## 4. 자료 접근과 버전의 한계

사용자가 제공한 링크의 실제 목적지는 FTL 문서다. 표시 문자열에 다른 게임명이 포함되어 있어도 분석 대상은 FTL로 일관되게 해석했다.

제공된 [나무위키 FTL 문서](https://namu.wiki/w/FTL:%20Faster%20Than%20Light)는 이번 조사에서 본문을 직접 열 수 없었다. 따라서 해당 페이지를 읽었다고 주장하거나 그 내용을 출처로 인용하지 않았다. 공식 페이지 일부와 Fandom 페이지도 직접 열기가 제한되어, 검색 결과에 노출된 본문으로 확인한 항목이 있다. 각 문서의 출처와 90번 근거 문서에 접근 범위를 남긴다.

정확한 실행 파일 빌드 번호를 고정하지 않았으므로 “2026년 최신 패치의 모든 동작”을 보증하지 않는다. 원작/AE의 일반적인 PC 규칙을 기준으로 하며, 과거 패치노트는 현재 버그 존재의 근거가 아니라 **변경 이력과 회귀 테스트 후보**로 사용한다.

## 5. 원작 관찰과 구현 선택의 경계

### 5.1 동일한 결과가 동일한 구현을 뜻하지 않는다

전투 중 무기 충전이 멈추는 장면을 관찰해도 원작이 고정 시간 간격, 가변 시간 간격, 개별 타이머 중 어떤 내부 구조를 쓰는지는 확정할 수 없다. 따라서 이 문서는 외부 동작을 먼저 정의하고, 내부 구조는 별도 제안으로 적는다.

### 5.2 수치의 사용 원칙

1. 출처로 확인되는 정수 상수는 단위·적용 조건과 함께 기록한다.
2. 회피 확률과 회피 증가량은 `%`와 `%p`를 구분한다.
3. 충전 속도 증가와 충전 시간 감소를 동일하게 계산하지 않는다.
4. 방 전체 산소 평균과 해당 방의 산소 농도를 구분한다.
5. 일반 실드의 층수와 졸탄 실드의 흡수량을 같은 변수로 취급하지 않는다.
6. 어려움에 따른 보상·AI·기함 연결 구조 차이를 단순 체력 배율로 축약하지 않는다.
7. 확정하지 못한 초당 피해·확률·반올림은 `TBD` 또는 `[검증 필요]`로 남긴다.

### 5.3 예외의 우선순위

**[재구성안]** 공통 규칙을 먼저 적용하고, 함선·장비·종족·이벤트가 명시적으로 예외를 부여하게 설계한다. 예외는 설명 문자열에 숨기지 말고 데이터 조건으로 드러낸다. 예를 들어 `requiresOxygen=false`, `bypassNormalShields=true`, `revivableByClone=false`는 서로 다른 축이다.

## 7. 완료와 추가 검증의 기준

이 문서 묶음은 주요 시스템의 책임, 연결, 예외와 재구현 구조를 설명하는 **설계 산출물**이다. 모든 무기·이벤트·적 함선의 완전한 원본 데이터베이스를 제공하는 것은 아니다. 대표 데이터를 활용해 공통 구조를 정하고, 미확인 수치를 숨기지 않는다.

실제 재구현을 시작할 때는 다음 순서를 권장한다.

1. 특정 PC 빌드와 AE 설정을 고정한다.
2. 90번 문서에서 충돌하거나 미확인인 항목을 선택한다.
3. 21번 테스트 목록으로 대표 상호작용을 기록한다.
4. 확인된 결과를 데이터 테이블에 반영한다.
5. 확정 규칙과 자체 개선사항의 구분을 끝까지 유지한다.
