# STARWARD v7 — 빈 시스템 슬롯·설치·확장

## 1. 설계 목적

v6의 보조 시스템은 무기실·기관실·의료실 등 기존 방을 공유했다. v7의 새 함선은 실제 빈 격실을 보조 시스템 설치 공간으로 사용한다. 방을 고르고 스크랩을 지불하면 시스템이 그 방에 들어가며, 피격·화재·수리·파괴 공작과 전력 배분이 같은 설치 위치를 참조한다.

이 문서는 웹 구현의 규칙이다. 원작의 함선별 시스템 수 제한이나 전체 설비 구성을 그대로 복제했다는 뜻은 아니다.

## 2. 구조와 데이터

새 레이아웃은 기존 여섯 핵심 시스템 방과 여섯 보조 설치 구획으로 이루어진다. 보조 구획은 각각 2×2 사각 타일이며 통로와 문으로 연결된다. 최초 네 설치 마운트를 사용할 수 있고, 나머지 두 마운트는 스크랩을 지불해 순차적으로 확장한다. 확장 전에도 방의 물리적인 바닥·산소·문은 존재한다. 잠긴 것은 설치 마운트이다.

기존에 설치된 드론·텔레포터와 함선별 시작 능력도 각자 보조 구획을 차지한다. 새 출항에서 비어 있는 사용 가능 슬롯이 최소 하나 남는다. 동일한 시스템을 여러 슬롯에 중복 설치하지 않는다.

| 개념 | 저장·조회 원칙 |
|---|---|
| 방 | 물리적인 위치, 타일, 산소, 화재, 균열, 연결 문을 가진다. |
| 시스템 | `id`는 기능, `roomId`는 실제 설치 위치이다. |
| 슬롯 | 안정된 ID, 연결 방, 사용 가능 여부, 설치한 시스템 ID를 가진다. |
| 빈 슬롯 | 시스템이 없으며 전력을 소모하지 않는다. 방 자체는 이동·피격·화재 대상이다. |
| 확장 구획 | 설치 마운트를 해제하면 빈 슬롯으로 전환된다. |

`room.id === system.id`를 보조 시설에 적용하지 않는다. `getRoomSystem(shipOrId, roomId)`와 `getSystemRoom(shipOrId, systemId)`로 기능과 위치를 연결한다. 핵심 시스템의 원래 ID는 기존 표적·퀘스트·전력 명령 호환을 위해 유지한다.

## 3. 설치 흐름

격납고 또는 전투 밖의 정비 화면에서 **시스템 설치**를 연다. 슬롯을 선택하면 설치 가능한 시스템, 비용, 현재 스크랩, 불가 사유가 표시된다. 실제 구매 명령은 화면에 표시된 조건을 신뢰하지 않고 실행 순간 다시 검사한다.

1. 유효한 본함 슬롯인지 검사한다.
2. 정비가 가능한 항해 상태인지 검사한다.
3. 마운트가 열렸고 비어 있는지 검사한다.
4. 해당 시스템이 이미 설치되어 있지 않은지 검사한다.
5. 보유 스크랩과 가격을 검사한다.
6. 모든 조건이 맞으면 한 번만 비용을 지불하고 슬롯·시스템 위치·레벨을 함께 갱신한다.
7. 새 시스템은 1레벨, 전력 0으로 설치한다. 사용자가 전력 패널에서 배분한다. 배터리는 기존 규칙대로 별도 전력 배분이 없다.

설치 실패는 자원·슬롯·난수·ID·로그를 부분적으로 변경하지 않는다. 화면을 열어 둔 사이 다른 구매로 자금이 줄어들어도 음수 스크랩이나 중복 시스템이 생기지 않는다.

## 4. 비용과 확장

기존 v6의 장비 설치 비용을 유지한다. 은폐는 60, 해킹은 55, 정신 지배는 50, 배터리는 35스크랩이다. 보조 구획 확장은 첫 번째 40, 두 번째 60스크랩이다. 이미 존재하는 시설의 개량은 별도의 레벨 상한과 개량 비용을 적용한다.

드론과 텔레포터는 기본 시작 시설로 자신의 구획을 사용한다. 최초 드론 관제의 2레벨, 텔레포터의 1레벨은 기존 시작 성능을 유지한다. 시스템 레벨이 늘어도 물리적 구획을 추가 소비하지 않는다. 슬롯 확장과 시스템 레벨 개량을 구분한다.

정비 허용 상태는 출항 준비·지도·상점·보상 화면이다. 진행 중인 교전과 해결하지 않은 이벤트에서 시스템을 설치하거나 마운트를 확장할 수 없다. 전력 재배분은 기존 전투 규칙을 유지한다.

## 5. 전투와의 연결

| 사건 | 적용 대상 |
|---|---|
| 포격·빔·이온 | 실제 표적 방과 그 방의 설치 시스템 |
| 화재 | 해당 방의 설치 시스템과 물리적으로 머무는 승무원 |
| 수리 | 해당 방에 도착한 우호 승무원이 설치된 손상 시스템을 수리 |
| 파괴 공작 | 적대 승무원이 실제 설치된 시스템을 공격 |
| 해킹 | 대상 방의 시스템에 맞는 교란 효과, 부착 위치와 문 잠금 유지 |
| 텔레포트 집결 | 현재 텔레포터가 설치된 방으로 이동 |
| 빈 방 명중 | 선체·방 환경 피해는 처리하되 존재하지 않는 시스템에는 접근하지 않음 |

능력의 레벨·전력·손상 데이터와 설치 위치는 분리된다. 화면을 2D에서 3D로 바꾸어도 이 값은 변경되지 않는다.

## 6. 상점·이벤트 보상과 호환

상점의 신규 보조 시스템 구매도 슬롯 정책을 통과해야 한다. 슬롯이 가득 찼으면 확장 또는 다른 선택이 필요하며 비용만 차감해서는 안 된다. 이미 설치된 시스템은 같은 위치에서 개량한다.

퀘스트의 무료 시스템 보상도 빈 슬롯 한도를 무시하지 않는다. 설치 공간이 없을 때는 실제 구현의 대체 스크랩 보상과 안내를 적용한다. 퀘스트 완료 기록 자체를 잃지 않는다.

## 7. 이전 항해

기존 v1~v6 항해의 도면을 임의로 늘리거나 승무원·전투·장비를 다시 만들지 않는다. 예전 도면의 공유 보조 시스템 위치는 호환 상태로 유지하고, 새 빈 구획 건설은 새 함선 항해에서 제공한다. 기존 항해에서는 설치 가능한 범위와 제한을 명확히 표시한다.

v7 저장은 슬롯 ID·방 연결·중복 배치·설치 레벨·사용 가능 개수·시스템 위치의 일관성을 검사한다. 저장 파일에 존재하지 않는 구획이나 중복 시스템을 넣어도 현재 항해를 바꾸지 않고 거부한다.
