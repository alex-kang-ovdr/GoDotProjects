# 21. QA 계획·인수 기준·원작 비교 검증

> 조사 기준일: 2026-11-13. 대상: PC판 FTL 본편 및 AE, 모드 제외.\
> **이 문서는 실행 결과가 아니라 테스트 설계다. 아래 64개 항목은 모두 미실행 상태다.** 공개 근거를 확인한 것과 게임을 직접 실행해 통과를 확인한 것을 구별한다.

관련 문서: [범위·근거](00_scope_evidence_and_glossary.md), [전투](07_combat_timing_and_damage.md), [무기](08_weapons_shields_and_targeting.md), [승무원](10_crew_species_and_training.md), [AE](13_advanced_edition_systems.md), [데이터·저장](19_data_architecture_and_save.md).

## 1. 테스트를 세 종류로 나눈다

| 구분 | 수량 | 의미 | 합격 판정 |
|---|---:|---|---|
| G: 확인 규칙의 재현 | 16 | 문서에서 [확인]으로 분류한 게임 동작 | 제시한 기대 결과와 일치 |
| R: 재구성 설계의 품질 | 36 | 원작 내부 구조와 무관한 제안 구현 계약 | 제안 사양·불변식 만족 |
| O: 원작 관찰 필요 | 12 | 수치·동시성·예외를 아직 확정하지 않은 문제 | 먼저 관찰 자료를 확보하고 기대값 승인 |
| 합계 | 64 | 이 문서의 최소 회귀 세트 | 실행 보고서와 별도 관리 |

G와 R을 함께 통과했다고 원작을 완전히 복제한 것은 아니다. O의 관찰 공백과 전체 콘텐츠 미수록 범위가 남는다. 특히 해킹·이온·은폐·클론은 상호작용에서 드러나는 예외가 많다.

## 2. 테스트 환경과 기록 항목

**[재구성안]** 결과를 비교할 때 다음 정보를 함께 저장한다.

| 구분 | 필수 기록 |
|---|---|
| 실행 환경 | 게임/프로토타입 버전, 플랫폼, 실행 설정, UI 배율 |
| 런 설정 | 난이도, AE 여부, 함선·레이아웃, 현재 섹터 |
| 초기 상태 | 장비, 전력, 승무원, 실드, 선체, 위험·환경 |
| 입력 | 명령 종류, 표적, 실행 순서, 정지·재개 시점 |
| 관찰 | 영상 또는 타임라인, 수치 변화, 이벤트 로그 |
| 무작위성 | 재구현 시 시드·스트림·추첨 인덱스, 원작이면 반복 횟수 |
| 판정 | 기대 결과, 실제 결과, 근거 문서, 결함 번호 |

원작에서 고정 시드나 내부 상태를 직접 지정할 수 있다고 가정하지 않는다. 원작 비교는 실제 재현 가능한 저장·상황·영상으로 구성하고, 완전한 상태 지정은 자체 구현의 개발 도구에서 제공한다.

## 4. R 그룹: 재구성 사양의 품질 36개

이 그룹의 기대 결과는 **[재구성안]**이다. 예를 들어 저장 스키마나 RNG 스트림 분리가 원작과 같다는 주장을 하지 않는다.

O-01은 자료마다 화재 피해 수치가 다르게 제시될 수 있으므로 숫자를 보류했다. 초당 평균값, 실제 피해 tick, 한 타일의 화재와 여러 화재의 중첩을 같은 수치로 오인하지 않도록 기록한다.

## 6. 실제 패치에서 도출하는 회귀 우선순위

**[확인]** 개발자의 1.5.10 공지에는 이벤트 저장 불일치, 점프 중 저장, 의료 시스템 교체와 일부 특수 능력 상호작용을 수정한 이력이 있다. 이후 공식 변경 이력에도 중복 보상과 비행 중 ASB 저장 수정이 기록되어 있다. [Q6][Q7]

이 사실은 현재 버전에서 같은 결함이 남아 있다는 증거가 아니다. 복합 상태와 저장 경계에 회귀 테스트를 배치해야 할 이유로 활용한다.

| 위험 묶음 | 관련 항목 | 우선도 |
|---|---|---|
| 저장으로 결과가 바뀌는 문제 | R-14, R-25~R-29, O-10 | 최상 |
| 소속·생명 상태가 섞이는 문제 | R-04~R-06, O-03, O-07 | 최상 |
| 결과가 두 번 적용되는 문제 | R-12~R-17, R-36 | 최상 |
| 전력 공급과 사용량 불일치 | R-01~R-03, O-05 | 높음 |
| 지도·콘텐츠가 진행을 막는 문제 | R-19~R-24 | 높음 |
| 입력·정보 표현 오류 | R-32~R-35 | 높음 |

## 7. 실행 순서와 최소 통과 게이트

**[재구성안]** 구현 단계마다 전체 테스트를 무조건 반복하기보다 변경된 규칙과 위험이 연결된 묶음을 실행한다.

1. **단일 함선 단계:** 전력, 문, 이동, 산소, 위험과 UI 정지.
2. **단일 교전 단계:** 무기 유형별 방어 판정, 승무원 피해, 조우 종료.
3. **성장·탐험 단계:** 지도, 자원 거래, 이벤트, 상점과 해금.
4. **AE·보스 단계:** 복합 능력, 복제, 기함 페이즈 지속 상태.
5. **저장·재개 단계:** 각 단계의 대표 경계 상태를 저장 후 비교.

공개 배포 전에는 무한 교전·도달 불가능 목표·정상 저장 손상·보상 중복·승무원 복제·전력 초과 같은 진행·상태 결함을 우선 막는다. 불확실한 원작 수치가 남아 있다면 어떤 값이 재구성 값인지 사용자 문서에 남긴다.

## 8. 결함 보고 양식

```text
ID:
검증 기준: 원작 확인 규칙 / 재구성 계약 / 관찰 필요
버전·난이도·AE·함선:
초기 상태:
재현 입력:
기대 결과와 근거:
실제 결과:
재현 빈도와 표본 수:
첨부: 상태 스냅샷, 명령 로그, 영상
영향: 진행 차단 / 상태 손상 / 밸런스 / 표시
```

무작위 실패는 “가끔 발생”으로 끝내지 않는다. 표본 수, 발생 횟수, 통제한 변수를 기록한다. 확률 검증에서 표본이 부족하면 통과로 결론 내리지 않고 관찰 부족으로 남긴다.
