## 1. 시스템을 세 층으로 나누는 이유

**[분석]** “불”이라는 표현만으로는 유닛이 불타는 것인지, 타일이 불타는 것인지, 이번에 화염 효과가 적용되는 것인지 알 수 없다. 원인·지속 상태·지형을 분리해야 이동과 수리의 결과를 설명할 수 있다.

| 층 | 저장 대상 | 예시 |
| --- | --- | --- |
| 유닛 상태 | 유닛 ID | Burning, Frozen, A.C.I.D., Shield |
| 타일 상태 | 격자 좌표 | Fire, Smoke, Cracked, A.C.I.D. Pool |
| 예약 이벤트 | 턴·순서·영향 좌표 | 지진, 낙뢰, 공습, 컨베이어 |

**[제안]** 유닛이 이동하면 유닛 상태와 타일 상태를 따로 갱신한다. 연기에서 나온 유닛 때문에 원래 타일의 연기가 따라다니거나, 불타는 메크가 움직였다고 출발 타일을 자동 발화시키는 추론을 하지 않는다.

## 2. 상태 규칙의 최소 요약

다음 표는 **[확인]**된 공개 설명의 요약이다. 특정 무기·파일럿·패시브는 기본 효과를 수정할 수 있다. [C06, C07, C12, C13, C26]

| 상태·효과 | 기본 변화 | 흔한 오해 |
| --- | --- | --- |
| Fire | 지속 피해를 줌; 수리 등으로 해제 가능 | 불을 붙이면 현재 공격도 자동 취소됨 |
| A.C.I.D. | 받는 무기 피해 증가; Armor 무력화 | 매 턴 자체 피해를 주는 독 효과 |
| Frozen | 이동·일반 공격 불가; 보통 피해로 해동 | 어떤 즉사 환경에서도 무적 |
| Smoke | 일반적으로 공격·수리 불가 | 이동도 금지하거나 모든 패시브도 정지 |
| Webbed | 일반 이동 불가, 공격은 가능 | 모든 행동이 금지되는 기절 |
| Shield | 해당되는 피해 1회 보호, 특정 새 상태 차단 | 이미 걸린 화상까지 치료 |
| Boosted | 다음 행동의 피해·회복 강화 | 매 턴 영구 공격력 증가 |
| Armored | 받는 무기 피해 감소 | 모든 피해 유형 감소 |
| Stable | 강제 위치 변경 제한 | 피해도 받지 않는 무적 |

표의 “흔한 오해”는 비교를 위한 **[분석]**이다. 상태 아이콘을 단어 하나로 기억하기보다 금지 행동과 피해 처리 대상을 각각 읽어야 한다.

## 3. 화상과 불타는 타일

### 3.1 Fire의 확인 범위

**[확인]** Fire 상태는 턴 경계에서 1 피해를 주며, 수리나 물에 잠기기·연기로 이동하기 등의 방법으로 제거될 수 있다. 비행 유닛은 물 위에서 잠기지 않는다는 차이가 있다. [C07]

**[분석]** 화상은 지연 피해다. HP가 남는 적은 이번 공격을 수행할 수 있으므로, 화상 부여만으로 건물 위협을 제거했다고 판단하면 안 된다. 이번 지속 피해 시점에 실제로 죽는지 계산해야 한다.

### 3.2 숲이 불타는 과정

**[확인]** 숲은 타일 자체에 피해가 들어가면 발화한다. 위에 선 유닛의 충돌 피해만으로 숲이 항상 발화하는 것은 아니다. 유닛을 피해와 함께 밀어 숲 밖으로 내보내는 경우, 이동한 유닛이 원래 숲의 후속 점화 때문에 반드시 불타지는 않는다. [C09]

**[분석]** 이 규칙은 유닛 피해와 타일 피해가 별개라는 중요한 사례다. `유닛 HP 감소 ⇒ 아래 타일도 피격`으로 처리하면 숲·모래·얼음에서 연쇄 오류가 생긴다.

### 3.3 화염 타일의 지속성

**[확인]** 직접 화염 효과로 만들어진 Fire Tile은 숲 발화와 발생 원인이 다르지만, 동결·연기 효과로 제거될 수 있다. [C17]

**[제안]** 타일의 원래 지형을 보존한다. 숲이 불타고 다시 꺼졌을 때 무엇으로 복원되는지와, 보통 지면 위 화염이 꺼졌을 때의 결과를 같은 문자열 치환으로 처리하지 않는다.

## 4. 연기: 공간을 점유하는 공격 취소 수단

**[확인]** Smoke는 일반적으로 공격과 수리를 막고, 연기 속으로 이동하면 화상을 끌 수 있다. 모래에 무기 피해를 가하면 연기가 생성된다. Storm Generator는 연기에 적 피해를 추가하고, 일부 유닛·파일럿은 연기의 행동 제한을 무시한다. [C08]

**[분석]** 연기는 적을 죽이지 않고 행동을 막으므로 HP가 높은 적에게도 가치가 있다. 동시에 아군에게 필요한 사격 위치를 닫을 수 있어 “무조건 유리한 지형”이 아니다.

| 상황 | 판단 포인트 |
| --- | --- |
| 적이 건물을 조준한 상태에서 연기 생성 | 공격 예고가 취소되는지 확인 |
| 아군이 연기 칸에 정지 | 무기·수리 가능 여부와 면역 확인 |
| 연기 속 적이 죽어 폭발 | 공격 금지와 사망 효과는 별개 |
| 출현 칸에 연기 | 연기가 출현 자체를 막는다고 가정하지 않음 |
| 화염 무기로 연기 칸 공격 | 상태 교체 이후 남는 예고 확인 |

**[미확인]** 취소된 적을 같은 턴에 연기 밖으로 다시 꺼냈을 때 기존 의도가 어떤 조건으로 유지·복원되는지는 개별 상황을 직접 확인한다. 타일의 현재 연기 여부만으로 공격 의도 상태를 자동 재생성하지 않는다.

## 5. 동결: 행동 억제와 일회성 보호의 결합

**[확인]** 동결된 유닛은 일반 이동·공격을 할 수 없지만 밀릴 수 있다. 메크는 수리로 스스로 해동할 수 있으며, 보통 피해를 받으면 그 피해를 막고 해동한다. 동결된 적은 같은 턴 해동되어도 취소된 공격을 새로 준비하지 않는다고 커뮤니티 문서가 설명한다. [C12]

**[확인]** 동결된 비행 유닛은 지상 상태가 되어 Chasm 위에서 죽을 수 있고, Frozen은 특정 즉사 효과를 막지 않는다. [C12]

### 5.1 동결의 전술적 가치

**[분석]** 동결은 적에게는 공격 차단, 아군·건물에는 일회성 보호, 보드 전체에는 새로운 장애물 생성으로 작용한다. HP가 큰 적을 얼리는 것은 즉시 위협을 제거하지만 그 칸을 계속 점유시킨다.

| 동결 대상 | 얻는 효과 | 주의할 결과 |
| --- | --- | --- |
| 적 | 현재 공격 취소·장기 정지 | 통로를 막는 고정 장애물처럼 남음 |
| 아군 메크 | 일반 피해 완충 | 다음 행동을 위해 해동 필요 |
| 건물 | 보통 피해 보호 | 후속 다단 공격에는 별도 취약 |
| 임무 장치 | 상황에 따라 보호 | 장치가 해야 할 행동까지 멈출 수 있음 |
| 비행 유닛 | 행동 억제 | 아래 지형이 즉사 지형인지 확인 |

### 5.2 해동을 외부 이벤트에 맡기기

**[확인]** Cryo-Launcher는 대상과 사용자를 함께 얼린다. 출현 지점에서 사용해 출현 저지 피해로 사용자의 동결을 깨는 운용이 공개 무기 설명에 소개된다. [C28]

**[분석]** 이는 수리 행동을 아끼는 방식이다. 그러나 출현 직전까지 그 칸을 계속 점유하는지, 먼저 다른 피해를 받아 해동된 뒤 저지 피해를 HP로 받는지까지 순서로 계산해야 한다.

## 6. 산성: 유닛 상태와 두 종류의 지형

**[확인]** A.C.I.D. 상태는 무기 피해를 두 배로 만들고 Armor를 무력화한다. 충돌·화상·출현 저지 피해까지 두 배로 만들지는 않는다. 자기 피해에도 적용될 수 있다. [C26]

**[확인]** A.C.I.D. Pool은 지면 위 상태 부여 효과이고, A.C.I.D. Tile은 액체 지형이다. 액체에 잠기지 않는 비행과 지면 위 산성 효과에 대한 면역은 같은 것이 아니다. [C07, C11]

| 구분 | 의미 | 재구현 시 분리할 데이터 |
| --- | --- | --- |
| 유닛 A.C.I.D. | 유닛이 산성에 오염됨 | `unit.status.acid` |
| A.C.I.D. Pool | 지면 위 상태 부여 층 | `tile.overlay.acidPool` |
| A.C.I.D. Tile | 액체 지형 | `tile.terrain.acidLiquid` |
| Frozen A.C.I.D. | 동결된 산성 지형 상태 | 해빙 후 복원할 기본 지형 |

위 데이터 필드는 **[제안]**이다. 비행을 산성 전체 면역으로 구현하거나, 산성 타일을 모두 일반 물로 저장하면 이 차이를 잃는다.

## 7. 지형 상태 전이

다음은 **[확인]**된 주요 지형 규칙을 최소한으로 요약한 것이다. [C10, C11, C18]

| 지형 | 트리거 | 결과 |
| --- | --- | --- |
| 일반 얼음 | 유효 타일 피해 | 손상된 얼음 |
| 손상된 얼음 | 다시 유효 타일 피해 | 물 |
| 얼음 | 화염 효과 | 물로 바로 변화 가능 |
| 물 | 동결 효과 | 얼음 |
| 산 | 첫 유효 타격 | 손상된 산 |
| 손상된 산 | 다음 유효 타격 | 잔해·통로 변화 |
| 균열 지형 | 다시 타일 피해 | Chasm |
| Chasm | 비행하지 않는 유닛이 들어옴 | 추락·제거 |

### 7.1 피해량과 타격 횟수

**[분석]** 얼음과 산의 단계 변화를 일반적인 HP 감소와 구분해야 한다. 무기 피해 4를 한 번 주었다는 사실과 서로 독립된 타일 타격을 두 번 주었다는 사실을 같게 취급하지 않는다. 실제 적용되는 “유효 타격”의 조건은 무기 효과 정의로 확인한다.

### 7.2 물·용암·구멍의 차이

**[확인]** 일반 지상 Vek 다수는 물에서 죽지만 메크·Massive·Flying은 다른 처리를 받는다. 물에 잠긴 생존 유닛은 무기 사용에 제약이 있고, 용암은 생존한 잠수 유닛에 Fire를 줄 수 있다. Chasm은 비행하지 않는 유닛을 제거한다. [C03, C11, C18]

**[분석]** “물로 밀기 = 무조건 즉사”는 보스·비행 유닛에서 실패한다. “메크는 물에서 살기 때문에 구멍에서도 산다”는 추론도 성립하지 않는다.

## 8. 상태 상호작용 결정표

| 조합 | 공개 자료에서 확인되는 부분 | 설계상 확인 질문 |
| --- | --- | --- |
| Armor + A.C.I.D. | 산성이 Armor를 무력화 | 산성 해제 후 방어 복원 시점 |
| Shield + 새 Fire/Freeze | 해당 상태 차단 | 상태 부여만으로 Shield를 소모하는지 분리 |
| 기존 Fire + 새 Shield | Shield가 기존 화상을 치료하지 않음 | 지속 피해와 보호막 소모를 각각 표시 |
| Frozen + 보통 피해 | 보호 후 해동 | 같은 공격의 후속 충돌까지 계산 |
| Flying + Frozen + Chasm | 비행 상실로 추락 가능 | 도착·동결·제거 이벤트 순서 |
| Smoke + 일반 메크 | 공격·수리 제약 | 면역·연기 소비 패시브를 먼저 평가 |
| Fire + Smoke | 연기가 화상을 끌 수 있음 | 유닛 상태와 타일 상태를 함께 확인 |
| Boost + 자기 피해 무기 | 자기 피해도 강화 가능 | 적과 사용자에게 별도 피해 계산 |
| Webbed + 일반 공격 | 공격은 가능 | 공격이 이동을 수반할 때 별도 검증 |
| Stable + 밀기 | 강제 위치 변경 제한 | 밀기 실패와 무기 피해를 독립 처리 |

**[확인]** 부분은 C03·C06·C07·C08·C12·C13·C26의 공개 설명을 교차 요약한다. 마지막 열은 **[제안]**하는 검증 질문이다.

## 9. 환경 이벤트와 상태 피해의 순서

**[미확인]** 일반 가이드 사이에 환경·화상·전기 연기의 일괄 순서가 다른 부분이 있다. [03](03_턴구조_행동경제_되돌리기.md)의 자료 충돌 표를 참조한다. 여기서는 실제 Attack Order와 이벤트별 관찰을 우선한다.

**[확인·커뮤니티 자료]** Blood Psion 설명은 재생이 화상·전기 연기 피해 뒤, 출현 저지 피해보다 앞에 발생한다고 명시한다. 따라서 화상 상태 HP 1 적과 출현 지점을 막는 HP 1 적은 재생 오라가 있을 때 같은 결과를 내지 않을 수 있다. [C29]

**[분석]** 지속 피해는 화면에 동시에 보이더라도 판정은 순서에 민감할 수 있다. 오라 제공자가 죽는 순간과 다른 적이 죽는 순간의 선후를 바꾸면 사망 시 폭발 같은 결과도 바뀔 수 있다.

## 10. 재구현용 이벤트 모델

**[제안]** 상태를 매 프레임 임의 순서로 순회하는 대신 의미 있는 사건을 기준으로 갱신한다.

```yaml
StatusRule:
  id: example_burning
  owner: unit
  triggers:
    - event: scheduledBurnTick
      effect: damage
    - event: explicitRepair
      effect: removeStatus
  blocksActions: []
  damageTags: [periodic]
  stacking: singleInstance
```

이 예시의 필드명·스택 정책은 제안이다. 원작의 지속 효과 타이밍이나 모든 수리 원인이 해제 효과를 공유한다는 사실을 주장하지 않는다.

### 10.1 효과 입력·출력 계약

| 사건 | 입력 | 출력 |
| --- | --- | --- |
| 상태 부여 | 대상·상태·원인 | 적용/면역/차단 결과 |
| 타일 도착 | 대상·이전 칸·새 칸·이동 원인 | 착지 상태·액체 반응 |
| 피해 | 종류·양·원인·순서 | 보호 소모·HP 변화·사망 |
| 상태 제거 | 명시적 제거 원인 | 실제 제거 목록 |
| 지형 변화 | 이전 지형·타격 종류 | 다음 지형·점유자 재평가 |

`Repair`라는 이름의 효과가 모두 동일한 상태 해제까지 하는지는 능력마다 명시한다. 단순 HP 회복과 명시적 수리를 무조건 같은 이벤트로 합치지 않는다.
