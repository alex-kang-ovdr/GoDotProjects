## 1. 시스템의 역할

**[분석]** 이동은 공격 대상을 찾기 위한 준비에 그치지 않는다. 다음 공격의 방향, 투사체 차단 위치, 적 출현 저지, 다른 메크의 진입로를 동시에 결정한다. 같은 무기와 같은 HP에서도 위치가 한 칸 달라지면 해결할 수 있는 위협의 집합이 바뀐다.

전장의 공간은 세 가지 자원으로 해석할 수 있다.

| 공간 자원 | 소비 또는 확보 방식 | 판단 질문 |
| --- | --- | --- |
| 접근 가능한 칸 | 이동력과 통로로 확보 | 필요한 공격 위치에 이번 턴 도달하는가? |
| 밀려날 빈칸 | 다른 유닛·구조물이 점유하면 소실 | 공격을 취소시킬 방향이 열려 있는가? |
| 안전한 종료 위치 | 적 공격과 환경 예고를 피해서 확보 | 행동 후 더 이상 이동하지 못해도 생존하는가? |

이동력은 거리 수치이면서 동시에 **선택 가능한 해법의 수를 늘리는 업그레이드**다. 다만 막힌 통로, 사거리 최소값, 직선 사격 조건이 있으면 이동력 증가가 즉시 유효 행동 증가로 이어지지는 않는다.

## 2. 전장 좌표와 표현

### 2.1 확인된 공간 구조

**[확인]** 일반 전투는 8×8 격자에서 이루어진다. 개발자 인터뷰에서도 작은 8×8 지도 규모를 설명한다. [C00]

**[확인]** 이동력은 한 턴에 이동 가능한 격자 수를 나타낸다. 상하좌우 인접 칸을 따라 이동하며, 일반 지상 유닛은 적이나 구조물 때문에 돌아가야 한다. 아군 유닛은 통과할 수 있지만 같은 칸에 정지할 수 없다. [C02, C21, C23]

### 2.2 이 문서의 좌표 규약

**[제안]** 예제와 테스트는 열을 A–H, 행을 1–8로 표기한다. `A1=(0,0)`, `H8=(7,7)`로 대응한다. 게임의 등각 화면 방향과 혼동하지 않도록 이동을 “화면 왼쪽”보다 “D4→C4”로 기록한다.

| 항목 | 문서 규약 | 이유 |
| --- | --- | --- |
| 좌표 | `column, row` | 저장·검증 시 화면 투영과 분리 |
| 인접 | `(±1,0)`, `(0,±1)` | 대각선을 한 칸으로 세지 않음 |
| 좌표 차이 | `target - origin` | 강제 이동 후 공격 예고 재계산 |
| 경계 | `0 ≤ x,y < 8` | 실제 구멍과 지도 바깥을 구분 |
| 화면 위치 | 논리 좌표로부터 계산 | 시각적 높이·애니메이션과 판정 분리 |

장애물이 없을 때만 맨해튼 거리 `|dx|+|dy|`가 최소 이동 칸 수와 일치한다. 장애물이 있는 상황에서 이 식만으로 이동 가능 여부를 판정해서는 안 된다.

## 3. 통과 가능성과 정지 가능성

**[확인]** Flying은 적·건물·산 같은 장애물을 넘어가는 경로를 허용하지만, 다른 유닛이나 산이 있는 칸을 최종 위치로 공유하는 기능은 아니다. Massive는 액체에 빠져 즉사하지 않는 성질이고, 비행과 다르다. Stable은 강제 위치 변경에 대한 별도 제약이다. [C03]

**[분석]** 세 특성을 모두 “지형 무시”로 묶으면 재구현에서 오류가 발생한다. 경로 탐색과 도착 후 지형 반응은 서로 다른 질문을 다룬다.

| 질문 | 예시 | 별도 판정이 필요한 이유 |
| --- | --- | --- |
| 중간 칸을 지나갈 수 있는가? | 비행이 산을 넘음 | 통과가 가능해도 정지는 불가능할 수 있음 |
| 목적지에 정지할 수 있는가? | 적이 있는 칸 | 통과 특성과 점유 규칙이 다름 |
| 도착 후 생존하는가? | 물에 밀린 일반 지상 Vek | 자발적 경로와 강제 이동의 허용 범위가 다름 |
| 도착 후 공격할 수 있는가? | 물속에 선 메크 | 생존 가능과 무기 사용 가능이 다름 |
| 위치를 바꿀 수 있는가? | Stable 장치 | 피해 가능과 밀기 가능이 다름 |

### 3.1 재구현용 이동 프로필

**[제안]** 아래 항목은 원작 내부 데이터 구조가 아니라 테스트 가능한 기능 분해다.

```yaml
MovementProfile:
  range: 3
  neighborhood: orthogonal
  transit:
    allies: true
    enemies: false
    buildings: false
    mountains: false
  endpoint:
    requireEmpty: true
    allowLiquid: true
    allowChasm: false
  landingReaction:
    liquid: submerged
    fire: applyBurning
  forcedDisplacement:
    movable: true
```

`allowLiquid: true`는 예시 메크를 위한 값이다. 모든 유닛에 공통으로 복사하면 일반 지상 Vek까지 물 위로 걸어 들어가는 오류가 생긴다.

### 3.2 질의 함수의 책임

| 질의 | 반환 정보 | 부작용 |
| --- | --- | --- |
| `CanTraverse(unit, tile)` | 경유 가능 여부·거부 원인 | 없음 |
| `CanStop(unit, tile)` | 정지 가능 여부·점유 원인 | 없음 |
| `FindReachable(unit)` | 거리·경로·목적지 목록 | 없음 |
| `PreviewLanding(unit, tile)` | 지형·상태 변화 예상 | 실제 상태 변경 없음 |
| `CommitMove(command)` | 최종 위치와 발생 이벤트 | 명시적 실행 시에만 변경 |

플레이어에게 보이는 이동 가능 영역은 `FindReachable` 결과에서 만들어야 한다. 다른 로직으로 강조 영역만 계산하면 눌렀는데 이동하지 않는 칸이 생긴다.

## 4. 이동 명령의 처리 계약

**[제안]** 표준 이동 명령을 다음 순서로 정의한다.

1. 플레이어 행동 단계인지 확인한다.
2. 유닛이 살아 있고 이번 턴 이동 권한이 있는지 확인한다.
3. 이동을 금지하는 상태와 특성 예외를 평가한다.
4. 출발 위치를 기준으로 도착점까지의 합법 경로를 찾는다.
5. 목적지가 점유·지형 규칙을 만족하는지 확인한다.
6. 도착 후 상태 변화와 공격 가능 여부를 미리 보여준다.
7. 확정 시 이동 전 스냅샷을 기록한다.
8. 위치를 변경하고 착지 이벤트를 처리한다.
9. 공격 예고, 경로, UI의 영향을 다시 계산한다.

이 중 3·8번에 해당하는 화상·산성·연기·웹 등의 세부 규칙은 [05](05_상태이상_지형_환경.md)에서 관리한다. 이동 구현 안에 상태별 예외를 분산해서 하드코딩하지 않는다.

### 4.1 사용 가능한 행동과 도착 위치

**[확인]** 일반 메크는 무기를 사용한 뒤 통상 이동을 할 수 없다. 일부 파일럿 능력은 이 기본 규칙을 바꾼다. [C01]

**[분석]** 따라서 이동 미리보기에는 “지금 안전한가”뿐 아니라 “행동 후 거기 남아도 안전한가”가 필요하다. 공격으로 길을 뚫은 뒤 같은 메크가 걸어 나갈 수 있다고 착각하면 퍼즐을 잘못 계산한다.

| 위치 선택 | 당장 얻는 효과 | 남는 위험 |
| --- | --- | --- |
| 적과 건물 사이 | 직사 공격을 대신 받음 | 메크가 쓰러지거나 후속 공격이 관통할 수 있음 |
| 출현 표식 위 | 출현 저지 가능성 | 저지 피해를 감당해야 함 |
| 물속 | 화상 제거·사선 차단에 활용 가능 | 일반적으로 무기 사용 제약 |
| 연기 안 | 적의 일부 공격 취소에 활용 | 아군도 일반적으로 공격·수리 제약 |
| 적의 측면 | 밀기 방향 확보 | 다른 적의 다음 턴 이동 범위에 노출 |

위 표의 사용 가치는 **[분석]**이다. 액체·연기·저지 피해의 원작 규칙은 각각 연결된 상세 문서를 따른다.

## 5. 초기 배치의 역기획

**[확인]** 임무 시작 시 메크를 배치하고, 임무별 아군 장치·지형·적 구성과 함께 전투를 시작한다. 배치 관련 화면과 개별 파일럿 능력은 일반 이동과 다른 단계에 속한다. [C01, C21]

**[미확인]** 모든 임무가 동일한 줄 수의 배치 영역을 쓰는지, 특수 배치 능력이 모든 제한을 동일하게 우회하는지는 여기서 일반화하지 않는다. 실제 배치 강조 영역이 우선이다.

### 5.1 배치에서 평가할 다섯 축

**[분석]** 다음 평가는 원작의 자동 평가 함수가 아니라 플레이어의 의사결정을 정리한 것이다.

| 축 | 좋은 배치의 조건 | 나쁜 배치의 징후 |
| --- | --- | --- |
| 도달 범위 | 서로 다른 방향의 위협에 대응 | 세 메크가 같은 통로에 몰림 |
| 공격 각도 | 전방·측면·후방의 밀기 가능성 확보 | 적 뒤가 건물이라 밀 수 없음 |
| 최소 사거리 | 포격 메크 앞의 빈 공간 유지 | 근접 적에 포격이 닿지 않음 |
| 사선 | 직사 메크가 건물 뒤에 갇히지 않음 | 주포가 매번 아군을 먼저 맞힘 |
| 회복 가능성 | 첫 턴 후 다른 해법으로 전환 가능 | 하나의 적 행동에만 과도하게 최적화 |

### 5.2 배치 품질을 수치로 검토하는 예

**[제안]** 배치 검증 도구가 있다면 각 메크의 도달 가능 칸 집합을 `R_i`, 해당 위치에서 실행 가능한 공격으로 대응할 수 있는 위협 집합을 `T_i`라 하자.

- 지도 커버리지: `|R_1 ∪ R_2 ∪ R_3|`.
- 대응 다양성: 서로 다른 위협에 유효한 `(메크, 위치, 행동)` 조합 수.
- 의존도: 한 메크만 처리할 수 있는 위협의 수.
- 충돌 위험: 이동·밀기 목적지가 서로 겹치는 해법의 수.

높은 커버리지 자체가 정답은 아니다. 여러 칸에 갈 수 있어도 어떤 방향으로 밀어도 건물을 맞히는 배치라면 유효 해법은 적다. 최종 평가는 공격과 지형을 함께 계산해야 한다.

## 6. 자발적 이동·강제 이동·교환의 분리

**[분석]** 위치를 바꾸는 세 종류의 동작은 화면상 비슷해도 자원과 제약이 다르다.

| 이동 종류 | 소비 주체 | 주요 제약 | 설계상 별도 이벤트 |
| --- | --- | --- | --- |
| 일반 이동 | 해당 메크의 이동 권한 | 이동력·경로·상태 | `MoveCommitted` |
| 밀기·당기기 | 무기를 쓴 유닛의 행동 | 밀림 가능성·목적지 충돌 | `DisplacementResolved` |
| 교환·순간이동 | 해당 능력의 행동 | 능력 사거리·특수 제한 | `SwapResolved` |
| 지도 장치 이동 | 환경 또는 장치 | 장치 규칙 | `EnvironmentDisplaced` |

**[제안]** 강제 이동이 일반 이동 권한을 자동으로 소비하게 만들지 않는다. 그러나 이동을 강제로 받았다고 공격을 이미 끝낸 유닛의 일반 행동권을 복구해서도 안 된다. 위치와 행동권은 독립 상태로 둔다.

**[미확인]** 특정 파일럿의 “이동하지 않았으면” 조건이 강제 이동을 어떻게 취급하는지는 파일럿별 테스트 대상이다. 이런 예외를 기본 이동 규칙에서 추정하지 않는다.

## 7. 실제 구멍과 지도 바깥

**[확인]** 지도 경계 너머로 유닛을 밀어 떨어뜨리는 것과 지도 안의 Chasm에 밀어 넣는 것은 다르다. 지도 바깥으로 밀어 제거하는 일반 규칙은 없다. [C24]

**[분석]** 화면이 섬 가장자리처럼 보여도 논리 타일이 없다는 사실만으로 낙사 지형이 되지는 않는다. 동일한 화살표 모양을 쓴다면 경계에서 이동이 발생하지 않는다는 프리뷰를 별도로 제공해야 한다.

**[미확인]** 경계에 대한 세부 충돌 피해 규칙은 적·무기별 미리보기와 실행 결과를 비교하는 항목으로 남긴다. 본 문서는 경계를 임의의 산이나 즉사 구멍으로 환산하지 않는다.

## 8. 대표 이동 예제

**[제안·가상 사례]** 이동력 3인 지상 메크가 C3에 있다. C4에는 아군, D3에는 적, C5에는 빈칸, D4에는 건물이 있다.

| 후보 목적지 | 단순 거리 | 실제 검토 | 판정 |
| --- | --- | --- | --- |
| C5 | 2 | C4의 아군을 지나감 | 빈 목적지이면 가능 |
| D3 | 1 | 적이 점유 | 정지 불가 |
| E3 | 2 | D3을 우회해야 함 | 다른 경로가 3칸 이내인지 재계산 |
| D4 | 2 | 건물 점유 | 일반 지상 정지 불가 |

E3은 C3→C2→D2→E2→E3이라면 4칸이므로 이동력 3에서 불가하다. `|dx|+|dy|=2`만 확인하면 잘못된 이동 영역을 표시한다.

동일한 메크가 비행한다면 D3의 적을 통과해 E3에 도착하는 경로는 허용될 수 있다. 그렇더라도 D3의 적과 같은 칸에 정지하는 것은 별개다.
