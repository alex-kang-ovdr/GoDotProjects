# 18. 검증 체크리스트와 미확인 항목

> [전체 목차](00_README_문서안내.md) · [전투 사례](17_대표전투_턴별분석.md) · [출처 대장](19_출처_버전_근거대장.md)

## 1. 검증 범위

본 문서 집합은 공개 자료를 조사하고 서로 대조한 **문헌 기반 역기획서**다. 원작 실행 파일에 대한 자동 테스트, 디컴파일, 개발사 내부 자료 확인을 수행한 결과가 아니다.

아래 테스트는 원작에서 경계 조건을 확인하거나 재구현 결과를 비교할 때 사용하는 **[제안] 검증 계획**이다. `기대 결과`는 확정 근거가 있는 경우의 비교 기준이며, 자료가 충돌하는 항목은 `확인할 결과`로 적었다. 미실행 항목을 통과했다고 표시하지 않는다.

## 2. 근거 등급과 문서 라벨

| 등급 | 자료 종류 | 무엇을 뒷받침하는가 | 한계 |
| --- | --- | --- | --- |
| A | 개발사 제품 설명·패치·개발자 발표 | 발표된 기능·변경점·설계 의도 | 모든 실제 예외를 열거하지 않음 |
| B | 위키의 구체적 규칙 설명 | 사용자에게 관찰되는 규칙 | 구버전·편집 오류 가능 |
| C | 플레이어 가이드·사례 보고 | 특정 상황의 결과와 검증 가설 | 빌드·모드·초기 상태 누락 가능 |
| D | 본 문서의 분석·구현 제안 | 규칙의 의미와 재구현 설계 | 원작 내부 구현의 증거 아님 |

`[확인]`은 A만 뜻하지 않는다. 어떤 자료에서 확인했는지 출처와 함께 읽는다. `[분석]`, `[제안]`, `[미확인]`을 원작의 확정 규칙으로 옮기지 않는다. 검색 색인으로만 읽은 자료는 [19번](19_출처_버전_근거대장.md)에 접근 상태를 남긴다.

## 3. 실행 검증 환경 기록 양식

| 항목 | 기록 예 |
| --- | --- |
| 플랫폼 | PC / Switch / 모바일 |
| 실행 버전 | 실제 설정·파일 정보에서 확인한 값 |
| AE 옵션 | 적·장비·파일럿·미션 관련 실제 선택값 |
| 난이도 | Easy / Normal / Hard / Unfair |
| 모드 | 순정 여부, 모드 목록과 버전 |
| 스쿼드 | 메크와 장착 무기·강화 |
| 파일럿 | 능력·승급·현재 HP |
| 전장 | 좌표·지형·건물·스폰·환경 |
| 턴 | 표시 카운터와 실제 사건 횟수 |
| 명령열 | 선택 순서와 정확한 대상 |
| 결과 | 사건 순서·최종 상태·화면 기록 |

자료에 “마지막 턴”이라고만 적혀 있으면 시작 턴을 포함했는지 알기 어렵다. 최종전처럼 카운터 해석이 중요한 경우, **입력 전 카운터 → End Turn 누른 횟수 → 사건 → 입력 후 카운터**를 함께 남긴다.

## 4. 최소 재현 보드 원칙

**[제안]** 규칙 하나를 검증할 때는 다른 효과를 최대한 제거한다.

- 파일럿 추가 능력·패시브·강화를 비활성화하거나 모두 기록한다.
- 먼저 일반 지형·일반 유닛으로 기준 결과를 얻는다.
- 다음 실험에서는 상태 또는 지형을 한 종류만 바꾼다.
- 체력 1·피해 1 같은 경계값과, 치명적이지 않은 값을 둘 다 사용한다.
- 예고 표시와 실제 결과를 각각 기록한다.
- 원작을 변형하는 모딩 실험은 순정 플레이 검증과 구분한다.

## 11. 공식 패치에서 도출한 회귀 검증 방향

**[확인]** 공식 1.2.82·1.2.88 기록에는 목표/적 조합, 소형 적 분류, 처치 후 효과와 경험치, 상점 Undo를 이용한 코어 복제, 예측 UI 및 밀기 순서의 일관성 수정이 있다. [O06](https://steamcommunity.com/app/590380/allnews/)

**[분석]** 이 기록은 내부 구현을 알려 주지는 않지만, 다음 경계에 집중적으로 테스트를 배치할 이유를 제공한다.

| 경계 | 검증하는 질문 |
| --- | --- |
| 콘텐츠 생성 × 목표 | 생성 가능한 조합이 목표 달성을 막지는 않는가? |
| 유닛 분류 × 보상 | 소환체를 일반 적으로 집계하지 않는가? |
| 처치 사건 × 후속 효과 | 피해 경로에 따라 발동이 누락되지 않는가? |
| 상점 × 되돌리기 | 아이템과 비용이 서로 다른 시점에 복원되지 않는가? |
| 판정 × 미리보기 | 실행 순서와 표시 순서가 같은가? |

위 패치 번호는 **해당 역사적 변경을 확인한 식별자**다. 2026-11-13 현재 모든 플랫폼의 최신 빌드를 의미하지 않는다.

## 13. 문서 산출물 검증과 게임 검증의 구분

문서 산출물에서는 파일 존재, 내부 상대 링크, 코드 블록 닫힘, 필수 문서 구성, ZIP 파일 무결성을 확인한다. 이 검사는 읽고 배포할 수 있는 문서라는 뜻이며, 모든 규칙이 실제 게임에서 재현되었다는 뜻은 아니다.

[17번](17_대표전투_턴별분석.md)의 가상 전투 사례는 주어진 좌표와 명령을 따랐을 때 설명이 일관되는지 확인하는 용도다. 원작 플레이 녹화나 실제 리플레이로 오인하지 않는다.

## 14. 향후 문서 갱신 절차

1. 자료 또는 실행 빌드의 버전을 기록한다.
2. 기존 주장과 다른 결과가 나타난 최소 보드를 보존한다.
3. 규칙 변경·자료 오류·플랫폼 차이·표기 차이 중 무엇인지 분류한다.
4. 해당 시스템 문서의 확정 규칙과 예외를 함께 수정한다.
5. 연결된 가상 사례·데이터 제안·QA의 기대값을 갱신한다.
6. [19번 출처 대장](19_출처_버전_근거대장.md)에 근거와 변경 이유를 추가한다.
