## 재현 방법

프로젝트 루트에서 다음 명령을 실행합니다. 외부 테스트 패키지는 필요하지 않습니다.

```sh
node --test tests/engine.test.cjs tests/campaign.test.cjs tests/v2.test.cjs tests/app.test.cjs
```

캠페인 완주 검증은 별도 실행합니다. 아래는 이 보고서의 실제 여섯 완주 기록을 얻은 명령입니다. 기본값이 보통 난이도, 문자열 시드 `20261114`, 세 분대, 안전·위험 경로입니다.

```sh
node tests/playthrough-v2.cjs --max-ms=180000
```

같은 조건을 명시하고 여섯 승리를 자동으로 요구하려면 다음 명령을 사용합니다.

```sh
node tests/playthrough-v2.cjs --seed=20261114 --difficulty=normal --max-ms=180000 --require-win
```

한 조합만 재현하려면 분대와 경로를 지정합니다.

```sh
node tests/playthrough-v2.cjs --squads=gravity --routes=risk --seed=20261114 --difficulty=normal --max-ms=60000 --require-win
```

스크립트는 임무별 진행 기록, 각 실행의 `RESULT`, 전체 `SUMMARY`를 출력합니다. `--max-ms`는 전체 실행 시간의 상한입니다. 시간 초과는 종료 코드 2이며 엔진 오류와 구분합니다. `--require-win`이 있으면 자동 정책의 패배는 종료 코드 1입니다. 해당 옵션이 없으면 패배도 결과로 보고하며, 불변 조건 위반이나 엔진의 유효 명령 거부는 항상 오류로 처리합니다.

### 자동 정책의 범위

정책은 현재 행동 가능한 모든 메크에 대해 이동하지 않는 선택과 공개된 이동 위치를 비교합니다. 각 위치에서 주무기·보조 무기 목표, 수리, 대기를 열거하고 실제 `forecast()` 결과를 평가합니다. 전력망과 폭탄 생존을 가장 높게 평가하며 메크 생존, 적 제거, 출현 차단, 포드 회수도 고려합니다.

배치와 강화에는 분대 특성을 반영했습니다. 그래비티 분대의 첫 임무에서는 견인 메크를 전진 배치합니다. 이후 임무에서는 안전한 하단 배치 칸 중 전방 위치를 선택합니다. 리프트 분대는 곡사포 피해와 기동을, 컨트롤 분대는 주먹·연막 피해를, 그래비티 분대는 광선 피해와 이동 거리를 먼저 강화합니다.

실제 캠페인 상태를 바꾸는 경로는 `createRun`, `deploy`, `beginBattle`, `command`, `upgrade`, `equipSecondary`, `nextMission`, `endTurn`뿐입니다. 체력·전력·적·임무 번호를 직접 조작하지 않습니다. 통제된 단위 테스트의 인위적인 전장 배치는 완주 검증과 분리했습니다.

매 실제 명령 후 `validateState()`와 유닛 중복 점유 검사를 수행합니다. 매 턴 종료 시 다음 조건도 확인합니다.

- `forecast()`와 `endTurn({trace:true})`의 최종 상태가 완전히 같습니다.
- 마지막 재생 프레임의 상태가 실제 최종 상태와 같습니다.
- 예측과 재생 계산이 원본 상태를 변경하지 않습니다.
- 모든 캠페인이 정해진 턴 상한 안에서 승리 또는 패배로 종료됩니다.

별도의 변환 표본은 V1 보상 단계도 다룹니다. 이미 지급된 코어를 다시 주거나 파일럿 XP를 소급 지급하지 않으며, 다음 작전 진입으로 보상이 중복되지 않습니다. 현재 전투에 새로운 환경 위험을 끼워 넣지 않는 것도 확인합니다.

### 손상 데이터 거부

지원하지 않는 스키마, 64개가 아닌 타일 배열, 유닛 좌표·ID 중복, 최대 체력을 넘는 HP, 음수 충전량, 알 수 없는 장비·파일럿, 손상된 특성 적용 기록, 잘못된 RNG·코어·증원·환경 예고·공격 방향을 거부합니다. `null`, 배열, 문자열 등 잘못된 최상위 값도 예외를 던지지 않고 오류로 반환합니다.

V2를 다시 읽어도 이미 적용한 정찰 이동력이나 계급 2 HP 보너스가 중복 적용되지 않습니다. 베테랑 이월 XP는 4로 제한되며 등록되지 않은 파일럿을 입력해 보너스를 얻을 수 없습니다.

## 밸런스 판단과 남은 한계

첫 자동 정책은 기본 배치를 유지하고 근접 공격력에 강화를 집중했습니다. 그 상태에서는 여섯 조합 중 세 조합이 전력망 손실로 패배했습니다. 전진 배치, 필요한 이동 거리, 광선·곡사포의 피해 기준을 반영한 정책으로 바꾸자 같은 시드와 보통 난이도에서 여섯 조합 모두 승리했습니다. **이 검증을 위해 전투 수치나 적 배치를 낮추지 않았습니다.** 최초 패배는 약한 자동 정책의 결과로 분류했습니다.

| 정책 | 승리 / 실행 | 패배한 조합 |
| --- | --- | --- |
| 최초: 기본 배치·근접 강화 우선 | 3 / 6 | 리프트 위험, 그래비티 안전, 그래비티 위험 |
| 최종: 전진 배치·분대별 강화·보조 장비 | 6 / 6 | 없음 |

그래비티 위험 경로는 최종 전력이 3으로 여유가 가장 적었습니다. 견인과 광선은 공격 순서·사선·아군 피해를 고려해야 하므로 단순한 한 단계 탐색으로 최적 해법을 찾았다고 볼 수 없습니다. 이 결과만으로 난이도 하향이나 상향을 권고하지 않습니다.

검증하지 않은 범위:

- 모든 시드와 모든 분기 혼합 순서의 완주 가능성
- 모든 장비 조합과 베테랑 선택에 대한 전수 밸런스
- 사람의 학습 난이도와 평균 플레이 시간
- 실제 브라우저의 데스크톱·모바일 렌더링, 터치, 접근성 및 오프라인 실행

이 보고서 작성 시 실제 브라우저 검증은 관리형 미리보기 주소가 작업 프로젝트가 아닌 다른 프로젝트를 표시하는 환경 문제로 보류되어 있습니다. 별도 임의 서버로 검증한 것처럼 기록하지 않았습니다. 브라우저 검증이 해결되면 관측한 화면·입력 결과를 별도 항목으로 추가해야 합니다.
