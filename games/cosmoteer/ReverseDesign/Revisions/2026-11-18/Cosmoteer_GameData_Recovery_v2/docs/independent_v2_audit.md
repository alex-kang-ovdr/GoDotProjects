- 검토 입력: `support_proposals.json`, `combat_proposals.json`, `economy_proposals.json` 및 세 시스템 설계 Markdown.

## 1. 발견 사항과 처리 조건

### P2 — 현재 핵공장 설명과 과거 보류 설명을 분리해야 함

기준선 `nuclear_missile_factory.notes`에는 가격과 재료 모두 null로 보류한다는 현재형 설명이 있습니다. 정식 0.26.2의 가격 25,000을 채택하면서 이 설명을 그대로 두면 필드 값과 모순됩니다.

**권고:** 당시의 보류 판단은 이력으로 보존하고, 현재 설명은 “0.26.2 공지에서 가격만 채택; 건조 재료와 선행 청사진 충돌은 유지”로 바꿉니다. 원재료 수량을 새 가격에 맞춰 역산하면 안 됩니다. 경제 제안 작성자도 동일한 통합 주의를 이미 남겼습니다.

### P2 — 생산 예약과 이미 투입한 원료의 용어를 구분해야 함

`ship_logistics_design.md` C2의 “함내 재고 + 승무원 화물 + 예약된 생산 입력 = 실제 보유량”에서 “예약된 생산 입력”은 `reservedOut`과 `inProcess`를 혼동할 수 있습니다. 예약만 한 원료는 아직 함내 재고에 있으므로 다시 더하면 이중 계상입니다.

**권고:** 마지막 항을 **“이미 재고에서 차감한 미완료 배치 투입량”**으로 씁니다. 같은 문서 B5의 `activeBatch`, 경제 문서의 `inProcess`와 일치하는 표현입니다. 이는 코드 오류의 발견이 아니라 향후 구현 계약을 정확하게 만드는 문서 교정입니다.

### P3 — 게임을 한정하지 않은 Steam 피드의 본문 위치를 명시해야 함

다음 출처의 URL에는 `appids=799600`이 없어 여러 게임의 기사가 함께 반환됩니다.

- `V2-CMB-PATCH-0304`
- `V2-ECO-01`
- `V2-ECO-02`

첫 두 URL에서 실제 Cosmoteer 정식 공지 본문을 독립 확인했습니다. 따라서 수치가 다른 게임에서 잘못 전사된 사례는 아닙니다. 다만 페이지 첫 부분만 보는 독자는 해당 발표를 찾기 어렵습니다. `appids`를 붙인 URL이 열리지 않는 경우, **실제로 읽힌 URL을 유지하면서 정확한 발표 제목·버전·날짜·`located_section`·확인 본문 위치 및 혼합 피드라는 설명**을 기록하는 루트의 처리 방침이 타당합니다. 단순히 문자열에 `appids`를 추가하고 새 URL을 검증한 것처럼 표시하면 안 됩니다.

**P1 결함은 발견하지 못했습니다.** 위 세 항목은 루트에 우선 메시지로 전달했습니다.

## 4. 경제 분석 재계산

별도 읽기 전용 검토에서 탄약·HE 부품·코일·하이퍼 코일·프로세서·다이아몬드의 원료비와 난이도별 판매 공헌이익을 v1 단가·입력비율로 재계산했고 제안과 모두 일치했습니다. 코일과 다이아몬드의 미확인 출력률은 null이며 시간당 이익도 채우지 않았습니다.
