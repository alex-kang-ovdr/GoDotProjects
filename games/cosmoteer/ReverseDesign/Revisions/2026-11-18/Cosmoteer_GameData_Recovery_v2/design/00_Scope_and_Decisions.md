# 개선 범위와 결정 사항

기획 개정일: **2026-11-18 / Asia·Seoul**. 대상은 Cosmoteer 문헌 복구 데이터 v2와 STARFORGE의 다음 구현 기획이다. 이번 산출물은 데이터·분석·설계 개정이며, 배포 중인 STARFORGE v4의 게임 규칙이나 저장 파일을 변경하지 않았다.

## 1. 이번 개정의 목적

설계가 전투 결과에 영향을 주는 경로를 더 명확하게 만든다. 부품을 늘리기 전에 **점유 공간 → 접근 가능한 작업장 → 운반 시간 → 장치 가동률 → 피해와 손실 → 회수·재건**이 같은 상태와 원장을 사용하도록 정의한다. 화면에 화력이 높다고 표시되더라도, 문이 막혀 있거나 운용 인원이 없고 전지 공급이 부족하면 실제 화력은 낮아져야 한다. 플레이어는 그 차이의 원인을 읽고 설계를 고칠 수 있어야 한다.

기획의 현재 구현 기준은 `6ca48f00f86857f821422619827b617f0de549a3`의 STARFORGE v4다. [추출 데이터](../data/starforge_v4.json)와 [근거 코드](../reference_code/v4/)를 함께 제공한다. 과거 v3 추출은 역사 자료로 유지하며 현재 구현의 기능 유무 판단에 사용하지 않는다.

## 2. 근거와 값의 네 가지 층

| 층 | 저장 위치 | 의미 | 게임 적용 원칙 |
| --- | --- | --- | --- |
| 출시된 원작의 문헌 관측 | `data/cosmoteer_original.json` | 위키·개발자 정식 패치에 명시된 관측값 | 단위·판본·필드 상태를 검토한 뒤 매핑 |
| 원작 개발 예고 | `data/roadmap_observations.json` | 개발 중이거나 이후 단계로 연기된 기능 | 현행 규칙이나 확정 수치에 합산하지 않음 |
| 현재 웹 게임 | `data/starforge_v4.json` | 고정 커밋의 런타임 상수와 코드 검토 | 구현 차이를 판단하는 기준 |
| 다음 웹 게임 제안 | `planning/`, `design/` | 이번에 선택한 알고리즘·계약·우선순위 | 별도 개발·플레이 검증을 통과한 뒤 반영 |

`patch_confirmed`는 그 패치의 명시값이라는 뜻이다. 패치 이후의 모든 빌드에서 같은 값임을 바이너리로 입증했다는 뜻은 아니다. `wiki_snapshot`은 조회 시점의 문헌 관측이며, 위키가 정확히 어떤 설치 빌드를 반영했는지는 미확정이다. `derived`는 관측값에 명시한 산식을 적용한 결과다. **공식 설치 데이터 전체 복구율은 계산하지 않는다.** 원본 전체 파일 수·키 수라는 분모가 없기 때문이다.

## 3. 데이터 개정의 채택 기준

1. 기존 미확정 필드와 같은 개념·단위의 수치를 직접 확인했을 때 값을 채운다. 다른 버전의 상대 변경률만 있을 때 현재 절대값을 합성하지 않는다.
2. 값이 맞더라도 범위를 과장한 필드는 철회하거나 의미가 좁은 필드로 대체한다. 화재에 의한 탄약 폭발 조건을 파괴 폭발 전체의 필수조건으로 확장하지 않는다.
3. 자료의 가격과 재료 합계가 다르면 합계에 맞추기 위해 재료 수량을 임의 조정하지 않는다. 가격만 정식 패치로 확인되면 가격만 복구할 수 있다.
4. 부품 크기에서 문 좌표·작업장 좌표·배기 금지 구역을 추론하지 않는다. 툴팁의 전체 영역과 실제 바닥·벽·발사 공간은 별도 데이터다.
5. 숫자 `0`, `null`, 해당 없음, 미확정, 상충을 유지한다. 설정 값이 없는 상태를 비활성화 값이나 0초 시간으로 실행하지 않는다.

각 변경의 이전 값, 새 값, 상태, 출처, 사유는 [revision_v2.json](../data/revision_v2.json)에 있다. 새 규칙 추가와 기존 null 복구를 별도로 집계해 복구량을 부풀리지 않는다.

## 4. 개선에서 먼저 고정할 결정

| 결정 | 선택 | 이유 |
| --- | --- | --- |
| 원작 수치 이식 | 필드별 허용 목록 | 세계 거리·전지·가격·열의 단위가 현재 웹 게임과 다름 |
| 공간 | 부품 인스턴스와 점유 셀 분리 | 큰 발전기 하나가 여러 칸을 차지해도 HP·재고가 중복 생성되면 안 됨 |
| 연결 | 구조·통행·열망 각각 독립 | 붙어 있다는 이유만으로 통행·열 전달을 허용할 수 없음 |
| 작업 | 운용·운반·정비 슬롯 분리 | 운반 승무원이 무장을 동시에 운용하는 가상의 인력 공급 방지 |
| 재고 | 실물·예약·운송 중·제작 중 분리 | 작업 취소·파괴·거래에서 자원 증식과 소실을 추적 |
| 방어 | 발생기별 실드 상태 | 각도·위치·전지·재가동 조건을 계산하기 위함 |
| 열 | 선체 열과 배관 열 분리 | 연결 파괴·단열·배관 방향이 냉각 능력에 영향을 주도록 설계 |
| 저장 | 구 규칙 세이브 보존, 명시적 전환 | 한 칸 설계를 다칸 부품으로 자동 확장하면 중첩·경제 변화가 발생 |

## 5. 완료와 미완료의 경계

이번에 완료하는 범위는 출처를 갖춘 데이터 개정, 현재 코드와의 차이 분석, 상태·테이블 계약, 구현 의존 순서, 재현 가능한 데이터 검증이다. 다음 게임의 문·경로·방향성 실드·열망·재료 건조 기능은 **제안**이다. 수용 사례는 향후 구현을 검사하기 위한 명세이며 이번에 해당 게임 기능이 통과한 테스트 수로 집계하지 않는다.

기존 25개 역기획 MD는 [reverse_design_v1](../reverse_design_v1/README.md)에 보존했다. 이번 `design/`이 현재 개선안이며, 이전 문서와 해석이 다를 때는 새 근거·철회 이력·수용 조건을 갖춘 이번 문서를 우선한다. 원본 나무위키 링크는 기존 조사에서 본문에 접근하지 못해 확인 근거로 사용하지 않았고, 이번 수치 보강도 공식 위키와 개발자 공지를 기준으로 한다.
