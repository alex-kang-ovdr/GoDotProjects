# 함선 기하·문·연결 개선

[개선 기획 목차](README.md) · [개정 범위](00_Scope_and_Decisions.md)

작성 2026-11-18 · 제안 대상 v5 · 원작 정확한 게임 빌드 미확인

이 문서는 공개 원작 자료를 보완하고 STARFORGE v4 다음 구현 범위를 결정하기 위한 설계안이다. **원작 확인**은 공식 위키 또는 명시된 개발자 패치 당시의 관측이다. **제안**은 새 프로토타입의 구현 계약이며 원작 엔진 알고리즘을 복원했다는 뜻이 아니다. 기존 게임 코드와 v1 원본 데이터는 변경하지 않았다. 추가 채택 후보는 [support_proposals.json](../authoring/support_proposals.json)에 출처별로 기록했다.

이번 개선의 목표는 큰 모듈의 공간 비용, 작업자의 자리 점유, 문과 통로가 만드는 운송 시간을 실제 선택으로 만드는 것이다. 신규 부품 수를 늘리기 전에 배치·통행·운송·저장 복원에서 같은 좌표와 자원 원장을 사용해야 한다. 기존 6/12/18 전력 운반 상한 등 프로토타입 조정값을 원작 단위로 다시 해석하지 않는다.


## A. 함선 기하·연결

### A1. 복원한 사실과 남은 자료

**원작 확인.** 문은 방실 사이 승무원 통행과 화재 전파에 관여한다. 문이 놓일 수 있는 위치는 공개 모딩 문서에서 AllowedDoorLocations라는 별도 목록으로 설명된다. 해당 문서는 회전 전 좌상단 기준, 오른쪽·아래쪽 양의 축, 부품 바깥의 인접 셀 좌표를 설명한다. 이 설명만으로 특정 원작 부품의 문 좌표를 만들어서는 안 된다. [문](https://cosmoteer.wiki.gg/wiki/Door), [문 위치 정의](https://cosmoteer.wiki.gg/wiki/Door_Locations)

**원작 확인.** 모딩 문서에는 corridor와 conveyor가 비벽체(IsWalled=false) 예로 제시된다. 일반 비벽체 이웃은 문 없이 접근하는 예외가 있으므로 “모든 부품 경계에 문 필요”라는 요약만으로 통행 그래프를 만들면 잘못된다. 같은 문서는 물리 영역과 이동 제한 필드도 따로 다룬다. 다만 작성 중인 문서이며 특정 현재 빌드의 원본 파일 검사는 아니다. [공개 데이터 필드](https://cosmoteer.wiki.gg/wiki/Modding/Data_fields)

**원작 확인.** 개발자 0.29.0 공지는 코일·하이퍼코일·프로세서 공장의 모든 저장 타일 옆에 문을 허용한 변경을 명시한다. 추가 JSON은 이 관계만 보존한다. 저장 타일의 실제 좌표를 확보하지 않았으므로 문 좌표 배열은 만들지 않는다. [0.29.0 개발자 공지](https://store.steampowered.com/news/posts/?appids=799600&enddate=1753322128&feed=steam_community_announcements)

복구된 너비·높이는 형상의 경계를 정하는 자료다. **점유 마스크, 충돌 모양, 보행 셀, 문 포트, 조작석, 배기 금지영역을 모두 확정하는 자료는 아니다.** 표에서 값이 없는 것과 원본 .rules에서 필드를 생략한 것은 서로 다르다. 특히 문 위치 목록 생략 시의 모딩 기본 동작을 위키의 정보 누락에 적용하면 안 된다.

### A2. 정의와 배치 상태를 분리한다 — 제안

모듈 정의에는 출처 정보와 프로토타입 형상을 함께 두되 출처 상태를 구분한다. 실제 개체에는 정의 ID, 기준 셀, 회전, 손상, 재고만 저장한다. 처음에는 원자로·조종실·저장고·레이저를 대상으로 제작자가 검수한 작은 형상 집합을 만든다. 원작 크기를 참고해 직사각형 보행 영역을 그리더라도 그것은 authored_prototype 값이다.

~~~json
{
  "definitionId": "prototype.reactor_medium.v1",
  "sourceRecordId": "medium_reactor_core",
  "geometryAuthority": "authored_prototype",
  "bounds": {"width": 3, "height": 3},
  "occupiedCells": [[0,0],[1,0],[2,0]],
  "walkCells": [[0,0],[1,0]],
  "ports": [{"id":"west-0","cell":[0,0],"normal":[-1,0],"kind":"door"}],
  "workstations": [],
  "clearanceRegions": [],
  "geometryVersion": 1
}
~~~

이 축약 예시의 좌표는 **설명용 제안**이다. 완성 부품 데이터도, 원작 원자로의 실제 셀 목록도 아니다. 모든 배열은 검수된 정의 파일에 명시하며, 빈 배열은 “없음”, null은 “미확인”으로 구분한다. 미확인 원작 값을 사용하려면 별도의 프로토타입 정의가 필요하다.

anchor는 회전된 경계 상자의 좌상단 **셀 인덱스**다. 셀 중심을 정수 좌표로 취급하면 v4의 중심 좌표 체계와 연결하기 쉽다. 각 개체의 고유 ID는 회전이나 위치 변경에도 유지한다. 문은 두 모듈 ID와 두 포트 ID를 참조하며 좌표만으로 소유자를 추정하지 않는다.

### A3. 네 방향 회전과 포트 — 제안

회전 전 크기를 w×h, 내부 셀을 (u,v), 시계 방향 회전을 r이라 한다. 화면의 x는 오른쪽, y는 아래쪽이다.

| r | 회전 셀 Rr(u,v) | 회전 후 크기 |
|---:|---|---|
| 0 | (u,v) | (w,h) |
| 1 | (h−1−v,u) | (h,w) |
| 2 | (w−1−u,h−1−v) | (w,h) |
| 3 | (v,w−1−u) | (h,w) |

배치 셀은 anchor+Rr(u,v)다. 포트의 바깥 법선은 평행이동 없이 같은 회전만 적용한다. r=1에서는 (dx,dy)→(−dy,dx)이다. 포트가 맞닿으려면 두 포트의 셀이 변을 공유하고 법선이 반대여야 한다. 내부 자원 출입점과 조작석도 동일 변환을 사용한다.

회전 편집은 선택한 기준 셀을 고정하고 결과 점유 영역 전체를 미리 보여준다. 사용자가 보는 그림, 충돌 검사, 통행 위치가 같은 변환 함수를 사용해야 한다. 편집기의 미러링은 단순 회전과 분리하며 비대칭 문 위치까지 함께 변환한다.

### A4. 점유와 세 종류의 연결 — 제안

| 구조 | 노드와 연결 | 판단하는 것 |
|---|---|---|
| 구조 연결 | 살아 있는 모듈과 허용 접촉변 | 선체 분리와 몸체 귀속 |
| 승무원 통행 | 보행 셀과 통행 가능한 공유변 | 도달 가능성과 운송 시간 |
| 열 연결 | 해당 장치의 검수된 열 포트 | 열 전달 여부 |
| 배치 금지 | 셀/영역과 금지 레이어 | 추진기·무장 주변의 배치 허용 |

장갑이 두 방을 물리적으로 연결해도 승무원 경로가 생기지는 않는다. 반대로 문 하나를 철거한다고 선체가 곧바로 분리되어서는 안 된다. 벽체 사이에는 합법적인 문 연결이 필요하고, 일반 통로류의 비벽체 공유변은 직접 연결한다. 화재 전파가 문을 통과할 수 있다는 사실을 모든 열 전달에 같은 그래프를 써도 된다는 의미로 확대하지 않는다.

공개 모딩 자료는 추진기·무장 금지영역을 Prohibits, ProhibitedBy, ProhibitRects 등의 별도 정의로 설명한다. [배치 금지영역](https://cosmoteer.wiki.gg/wiki/Modding/Data_fields/Part_placement_blocking) **제안:** v5는 occupiedCells와 clearanceRegions를 독립 검사하고 금지 레이어를 필터링한다. 원작 배기 거리와 사각형을 확인할 때까지 자체 금지영역임을 표시한다. 모듈을 붙이기 전에 기존 금지영역에 새 선체가 들어가는지와 새 금지영역에 기존 선체가 들어가는지를 양방향 검사한다.

### A5. 한 번의 편집 트랜잭션 — 제안

previewRefit은 원본을 복제하고 작업 취소·화물 정산·모듈 재사용·회전·문 연결을 같은 순서로 계산한다. 결과에는 비용, 재고 이전·매각, 사라지는 문, 새로 고립된 장치, 승무원 도달 불가 목록이 포함된다. applyRefit은 동일 계획의 원본 리비전이 유지될 때만 커밋한다. 생산이나 화물 이동으로 원장이 변했다면 새 견적을 제시한다.

설계의 중간 단계는 비합법적일 수 있어도 최종 상태로 검증한다. 이는 원작 청사진 모드의 공개 설명과 부합한다. [Ship Editor](https://cosmoteer.wiki.gg/wiki/Ship_Editor) 단, 제안하는 견적 토큰·리비전·원자 커밋은 프로토타입 구현 방법이다. 자동 문 배치는 합법 포트끼리만 생성하며 기존 문을 추측해서 복원하지 않는다.

## D. 구체 수용 사례 — 모두 제안 테스트

| 사례 | 입력·조작 | 수용 결과 |
|---|---|---|
| 네 번 회전 | 2×3 모듈, 셀(1,2), r=1 | 셀(0,1), 크기3×2. r=0~3 변환 후 원래 방향 복귀 시 모든 셀·포트·재고 동일 |
| 포트 회전 | 셀(0,1), 바깥 법선(−1,0), 2×3 모듈 r=1 | 회전 셀(1,0), 법선(0,−1). 그림과 walk edge가 같은 위치 |
| 점유 중복 | 2×2 모듈 anchor(0,0), 새 1×1 anchor(1,1) | 설치 거부. 크레딧·기존 문·화물·ID 순번 불변 |
| 문과 선체 분리 | 벽체 A/B를 변으로 붙인 뒤 문만 제거 | 구조 연결 유지, 양쪽 보행 경로 단절. 장갑을 통로로 취급하지 않음 |
| 비벽체 통로 | 통로(0,0), 이동 보도(1,0), 문 없음 | 합법 직접 통행. 벽체 방(2,0)에는 합법 문 필요 |
| 배기 양방향 검사 | 회전한 추진기 금지영역에 새 장갑 배치 및 역순 | 두 순서 모두 동일하게 거부, 원작 거리로 표시하지 않음 |
| 조작석 점유 | 조작석 1개, 조작 후보 2명, 운송 작업 1개 | 한 명만 조작 lease 소유. 운반자는 실제 도착 전 조작 효과 없음 |
| 작업 중 파괴 | 화물 보유자의 목적 포트 파괴 | 예약 해제, 화물 유지, 새 경로 탐색. 작업자 무료 생성·순간 배달 없음 |
| 중계 순환 | 원자로→축전기A→축전기B, 역방향 연결 시도 | 순환 경고 또는 방향 정책 거부. 60초 후 무의미한 A↔B 왕복량 0 |
| 제조 중 저장 | 황1 소비, 탄약 배치40% 진행에서 왕복 저장 | 입력·진행 동일. 완료 후 탄약20 한 번만 생성 |
| 견적 일치 | 만재 중포18, 철거 저장고 탄약1, 운반 탄약8 | 견적과 적용 모두9발 처리. 반복 견적은 읽기 전용, 재적용 중복 환급 없음 |
| v4 전투 이관 | 운반·탄체·서비스 작업이 존재하는 저장 | legacy 형상으로 동일 상태 재개. 도크 전환 실패 시 원본 저장 완전 유지 |
