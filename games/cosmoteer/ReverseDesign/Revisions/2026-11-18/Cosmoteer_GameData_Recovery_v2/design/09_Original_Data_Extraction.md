# 원작 데이터 복원의 후속 추출 명세

## 1. 확보된 것과 아직 없는 것

현재 패키지는 공개 문헌의 레코드·값·근거와 고정 커밋의 자체 웹 게임 데이터를 갖는다. **원작 설치 폴더의 `.rules`, 사용한 Mod 목록, 설치 빌드의 파일 해시는 제공되지 않았다.** 따라서 실제 파일 키, 상속 완료 값, 개별 문·작업장 좌표, 일부 열·피해 함수, 정확한 제작 배치 단위는 확정할 수 없다.

현재 공개 데이터의 `engine_id`는 null이다. `game_id_reported`가 있는 항목은 위키가 보고한 식별자이며, 설치 파일에서 직접 검증한 ID와 구분한다. 원본 전체 개수에 대한 복구율이나 최신 설치 빌드와의 수치 일치율은 표시하지 않는다.

## 2. 설치 데이터가 확보되면 필요한 입력

아래 절차는 후속 추출의 명세이며 이번 작업에서 실행한 분석은 아니다.

| 입력 | 기록 목적 | 누락 시 영향 |
| --- | --- | --- |
| 앱 빌드·게임 버전 문자열 | 패치 기준 식별 | 위키·패치와 exact build 대조 불가 |
| 파일 경로·바이트 길이·SHA-256 | 같은 추출 재현 | 파일 변동 여부를 판단할 수 없음 |
| 기본 Data와 활성 Mod 순서 | 재정의 순서 확인 | 기본 게임과 모드 값 혼합 가능 |
| 상속·include 참조 | 최종 효력 값 계산 | 부분 템플릿을 완성 부품으로 오인 |
| 언어 리소스 키 | 번역과 고정 ID 분리 | 번역 이름 변경이 외래키를 깨뜨림 |
| 사용 환경·확인일 | 결과 해석 범위 | 추출과 문헌 관측의 시점을 구별하기 어려움 |

## 3. 원문·해석·정규화의 세 단계

**원문 단계:** 파일을 변경하지 않고 해시와 위치를 기록한다. include 경로를 안전하게 해석하되 데이터 파일을 스크립트로 실행하지 않는다. 알 수 없는 구문은 생략하지 않고 `parse_error`로 원문 범위와 함께 남긴다.

**해석 단계:** 상속과 덮어쓰기의 순서를 그래프로 만든다. 순환·미해결 참조·같은 키 중복을 검출한다. 각 최종 필드는 원래 파일 위치, 상속 경로, 마지막 재정의 경로를 함께 보존한다. 정적 수치, 표현식, 조건부 값은 구분하며 런타임 조건이 필요한 표현식을 상수로 확정하지 않는다.

**정규화 단계:** 명시한 변환 규칙으로만 현재 catalogue 스키마에 옮긴다. 단위 변환 전 값을 `raw_value`로 남기고, 배열이 물리 타일·저장 슬롯·이미지 영역 중 무엇인지 필드 단위로 지정한다. 데이터가 없다는 이유로 문 좌표를 사각형 외곽에 자동 배치하지 않는다.

## 4. 우선 추출 테이블

| 우선 | 테이블 | 필요한 필드 | 주된 해소 대상 |
| --- | --- | --- | --- |
| 1 | part_geometry | 실제 점유·벽·문 후보·작업 위치·금지 영역·회전 | 다칸 부품과 접근성 |
| 1 | crew_jobs | 필요 인원·동시 작업·운반 제한·역할 설정 | 운용·운송 인력 분리 |
| 1 | power_shield | 저장·충전·기동 조건·피격 비용·호/투영 | 발생기별 실드 구현 |
| 2 | thermal_ports | 포트·방향·연결·열량·열용량·열 교환 식 | 선체 열과 배관 열망 |
| 2 | projectile_damage | 속도·피격 순서·관통·저항·폭발 자원 식 | 무장·방어·탄약 유폭 |
| 2 | recipe_batches | 입출력의 개수 단위·시간·전력·동작 조건 | per-part / per-missile 혼합 |
| 3 | economy_progress | 자원 적재·가격 식·수리·명성·진영 | 재료 경제와 성장 |

각 테이블의 채택 기준은 '필드에 숫자가 있다'가 아니다. 다른 입력을 갖는 동일 이름 모드를 구분하고, 관련 저장·피해·제작 자료와 단위가 연결되어야 한다. 예를 들어 완성 미사일 수와 미사일 부품 수를 같은 `count`로 축약하면 2배·9배의 오차가 생겨도 외래키 검사만으로는 발견되지 않는다.

## 5. 문헌과 설치 데이터의 차이 처리

비교 결과는 `unchanged`, `changed_by_version`, `source_conflict`, `unit_mismatch`, `scope_mismatch`, `unparsed` 중 하나로 분류한다. 설치 자료가 새 값이라고 해서 역사적 문헌을 지우지 않는다. 정확한 빌드와 파일 해시가 확인된 추출을 별도 dataset으로 만들고, 이번 v2의 각 필드에 대조 연결을 추가한다.

미확정 함수에 임의 계수를 넣어 시뮬레이션을 계속하는 대신, 웹 게임 전용 조정값은 별도 `prototype_tuning`에 둔다. 공개 문헌·추출 원문·웹 조정값이 한 셀을 서로 덮어쓰는 구조를 피한다. 원작과 웹 게임에서 관찰하는 값의 단위가 같아도 처리 순서가 다르면 결과가 달라지므로, 방어·파괴·작업 취소는 대표 전투 사례까지 비교해야 한다.

## 6. 복원 완료 판단

개별 시스템의 복원 완료는 지원할 부품·모드 목록을 먼저 고정한 뒤, 그 범위의 필수 필드가 모두 해석되고 provenance가 남으며 상속·외래키·단위·대표 동작 사례가 통과할 때 선언한다. 문헌 필드 수가 늘어난 것만으로 원작 전체 복원이 완료됐다고 선언하지 않는다. 현재 패키지의 검사기는 데이터 전달의 일관성을 확인하며 원작 실행 결과와의 동일성 검사는 포함하지 않는다.
