# 06. v4 저장·재고 보존·편집 정산

작성 기준: 2026-11-18. 실행은 [sim.js](../../dist/sim.js), 편집 트랜잭션은 [editor.js](../../dist/editor.js)에 있습니다.

## 1. 저장 계약

v4는 이전 전투·승무원·탄체·화재·정비·기술 상태에 황과 생산 상태를 추가합니다.

| 상태 | 의미 |
| --- | --- |
| part.sulfur | 해당 부품에 실제로 저장된 황 |
| part.production.enabled | 개별 공장의 생산 허용 상태 |
| part.production.progress | 전력이 공급된 작업 시간, 0 이상 10 미만 |
| part.production.batchActive | 원료를 이미 차감한 배치가 진행 중인지 여부 |
| crew.cargo / cargoAmount | 전지·탄약·황의 실제 운반 원장 |
| crew.job | 출발/도착 대상, 경로, 단계, 예약량 |
| metrics.ammoProduced | 완료된 생산으로 생성된 탄약 누적 |
| metrics.sulfurDelivered | 실제 황 배달량 누적 |
| metrics.powerPacketsDelivered | 전지 운송 완료 횟수 |
| metrics.sulfurSalvaged / sulfurSold | 회수·매각 원료 누적 |

생산 상태 코드는 현재 전력·연결·저장량에서 다시 계산할 수 있는 표시 값입니다. 작업의 진행과 이미 소비한 황을 나타내는 배치 상태가 경제적 원장의 핵심입니다.

## 2. 구형 저장 이관

v1·v2·v3를 모두 읽습니다. 출시된 버전에서 동결한 파일로 이관을 검사하며, 최신 엔진에서 만든 파일의 버전 번호만 바꾸는 검사를 대신 사용하지 않습니다.

- 기존 부품의 ID·종류·위치·HP·전력·탄약과 승무원 화물을 보존합니다.
- 원래 없던 황은 0으로 시작합니다. 초기 황 6은 새 원정에만 지급합니다.
- 기존 기술·정비 자재·화재·작전·보상 청구 상태는 원래 버전이 보유한 범위에서 유지합니다.
- v1에 원래 없던 비행 중 탄체는 새로 만들어 복원하지 않습니다.
- 이관 후 저장하면 VERSION 4가 됩니다.

실제 v3 커밋 f90387acd3f7ca25a8285423f235352dd47d07e4에서 개량 도크와 화재·운반·탄체가 존재하는 전투 상태를 추출했습니다. tests/fixtures/legacy-v3.cjs는 이 출시 코드의 고정 표본입니다.

## 3. 원자성

불러오기는 숫자 범위와 버퍼 용량, 부품 유형, 작업의 공급원/도착지, 화물 종류와 크기, 경로 및 생산의 조합을 검증한 뒤 적용합니다. 늦은 단계에서 입력이 잘못되어도 현재 게임의 일부만 바뀌지 않습니다.

황이 음수·NaN·무한대이거나 용량을 넘으면 거부합니다. 공장이 아닌 부품에 생산 상태를 넣거나 투입하지 않은 배치에 진행도를 넣어 원료를 건너뛰는 입력도 거부합니다. 대형 팩을 지원하더라도 모든 화물에 18이라는 느슨한 공통 상한을 적용하지 않습니다. 전지·탄약·황은 각각의 상한과 작업 관계를 검증합니다.

## 4. 생산 보존

배치 시작 시 황 1을 저장 원장에서 빼고 투입 원장으로 옮긴 것으로 취급합니다. 전체 황은 저장·운반·미완료 배치의 투입량을 합산합니다. 완료된 배치에서만 투입 원장을 제거하고 탄약 20을 생성합니다.

공장 정지와 전력 부족은 진행 상태를 보존합니다. 파일을 저장하고 불러와도 원료 차감과 완제품 생성은 다시 실행되지 않습니다. 파괴된 공장은 설비와 그 안의 원료·미완료 작업을 상실합니다. 도크 복구가 잃은 원료와 탄약을 무료로 재생성하지 않습니다.

## 5. 철거와 청사진

부품 자체의 환불은 기존과 같이 최대 65%, 내구도 비례입니다. 제거 부품의 살아 있는 재고와 미완료 공장 배치는 별도로 처리합니다.

1. 남는 부품의 유효한 저장 공간으로 재고를 먼저 이전합니다.
2. 더 이상 넣을 곳이 없는 탄약과 황을 자동 매각 정산합니다.
3. 황의 매각 단가는 1.2 C, 탄약은 0.27 C이며 합산한 금액을 내림합니다.
4. 미완료 공장 배치는 투입한 황 1의 가치로 반환하며, 완성되지 않은 탄약 20을 지급하지 않습니다.
5. 정산한 원료와 금액을 결과 메시지와 로그로 알립니다.

이미 운반 중인 화물은 기존 규칙대로 정착할 공간 또는 운반 인원을 보존합니다. 운반 화물을 가진 마지막 승무원까지 사라져 자원이 유실되는 거래는 거부합니다.

청사진 견적은 부품 환불과 초과 재고 매각을 함께 계산합니다. 적용은 복제 상태에서 수행하고 모든 검증을 통과한 뒤 한 번에 커밋합니다. 편집 이력도 생산·자원 변화 이후 오래된 상태를 복원하여 자원을 늘리지 않도록 무효화합니다.

## 6. 검증 경로

- 실제 원료 운반이 완료되기 전 생산이 시작되지 않는 경로
- 원료·완제품·미완료 투입을 합산한 물질 보존
- 전력 부족·출력 포화·개별 정지·함선 일시정지
- 진행 중 배치와 운반 중 화물 저장 왕복
- 철거·청사진 재적용·도크 복구의 원료 및 탄약 정산
- 구형 이관과 잘못된 저장 입력의 원자적 거부
- 자연 승리 이후 한 번만 지급되는 황 회수

최종 실행 결과와 환경상 확인하지 못한 부분은 [검증 기록](../VERIFICATION.md)에 별도로 적습니다.
