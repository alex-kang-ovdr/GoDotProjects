# STARFORGE v4 검증 기록

검증일: 2026-11-18. Node.js v24.22.1. v4는 분석 데이터 어댑터와 황·탄약 생산, 원자로 등급별 보급을 추가합니다.

## 생산형의 실제 캠페인

FORGE 생산형을 초기 850 C에서 543 C로 적용한 뒤, 실제 순찰 전투와 보상만으로 중형 원자로·승무원실·실드·무장·방열판을 구매했습니다. 적 HP 변경, 무료 크레딧, 강제 승리, 테스트 전용 무기를 사용하지 않았습니다. 구간 사이 v4 저장을 불러왔습니다.

| 구간 | 시작 모듈 | 결과 | 해당 교전 시간 | 누적 탄약 생산 | 귀환 후 C |
| --- | ---: | --- | ---: | ---: | ---: |
| 1 | 53 | 승리 | 약 41초 | 120 | 1,757 |
| 2 | 58 | 승리 | 약 41초 | 200 | 2,047 |
| 3 | 64 | 승리·원정 완료 | 약 58초 | 260 | 2,649 |

황 총 18을 회수하고, 마지막 저장 초과분 3은 3 C로 정산했습니다. 이는 특정 설계와 구매 순서의 자연 완주를 검증한 결과이며 모든 조합의 승리를 보장하지 않습니다. [원시 캠페인 결과](verification/v4_campaign_smoke.json)에 구매 항목과 자원 기록을 보관했습니다.

## 독립 검수와 수정

분석 선별본의 23개 관측 레코드·28개 출처가 복구 원본과 일치하고 원본 SHA256도 일치함을 확인했습니다. 확인 상태와 충돌·미확인 null 값은 유지됩니다. 원작의 정확한 내부 배치 주기와 다칸 점유는 구현했다고 표시하지 않습니다.

운반 탄약 8과 철거 예정 저장고 탄약 1이 있을 때 견적 86 C와 실제 환급 88 C가 어긋나는 결함을 발견했습니다. quote와 apply가 같은 격리된 화물 반환/계획 절차를 사용하도록 수정했습니다. 이제 두 결과 모두 탄약 9 매각·재고 환급 2 C·순환급 88 C로 일치합니다. 반복 견적은 상태를 바꾸지 않으며 자금 경계, Undo/Redo, 재적용의 중복 수익 방지를 확인했습니다.

## 브라우저 검증의 한계

관리형 미리보기 서버는 실행 상태였지만, 안내된 정확한 URL을 클라우드 브라우저에서 열면 ERR_CONNECTION_REFUSED가 발생했습니다. 다른 포트·호스트·서버로 우회하지 않았습니다. 따라서 v4의 신규 HTML/CSS 화면 배치와 터치·실제 버튼 조작은 이번 환경에서 미검증입니다. ID 연결·문법·Canvas와 상태 로직 확인을 실제 브라우저 확인으로 표현하지 않습니다.

이전 v3의 Chrome 화면 검수는 [v3 기록](VERIFICATION_v3.md)에 보존했으며, v4의 새 화면 검증 근거로 사용하지 않습니다.

## 배포와 산출물

배포는 검증한 소스를 Sites 저장소에 커밋·푸시하고 해당 커밋으로 만든 정적 아카이브를 사용합니다. 접근 범위는 기존 소유자 비공개를 유지합니다. 최종 배포 상태와 커밋·압축 파일 해시는 통합 ZIP의 RELEASE.json에 기록합니다. 이 문서는 배포 성공 이전에 작성했으며 배포 성공 자체는 별도의 반환 상태로 확인합니다.
