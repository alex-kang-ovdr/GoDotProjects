## 1. 플레이어가 관리하는 문제

화재는 추가 피격이 없어도 내구도를 깎고 열을 높이며 주변 모듈로 번질 수 있다. 승무원은 현장으로 이동해 불을 끄고, 불이 꺼진 뒤 자재를 써서 손상을 수리한다. 이 승무원들은 평소 전지·탄약을 나르는 인력과 같다. 생존에 더 많은 인원을 배정하면 단기 복구는 빨라지지만 보급량이 줄어들 수 있다.

정비 코드는 도크와 전투에서 모두 진행한다. 도크 상태에 손상이나 화재가 남아 있으면 현장 작업의 대상이 될 수 있다. 일시 정지 상태에서는 시뮬레이션 시간이 흐르지 않으므로 화재·이동·소화·수리도 함께 멈춘다.

화면에서는 정비 정책을 **균형 / 생존 우선 / 보급 집중**으로 선택하고, 아군 모듈을 선택한 뒤 **G**로 현장 우선 대상을 지정하거나 해제한다. **손상 오버레이**는 이 상태를 살펴보는 용도다. 실제 실행 규칙은 아래의 상태와 경로 조건을 따른다.

## 2. 상태와 단위

| 상태 | 위치 | 의미 |
| --- | --- | --- |
| `fire` | 모듈 | 0~1의 화재 강도. 0이면 불이 없다. |
| `heat` | 모듈 | 장비 열. 화재 강도와 별도로 유지한다. |
| `hp / maxHp` | 모듈 | 현재·최대 내구도. hp가 0인 모듈은 현장 수리 대상이 아니다. |
| `repairStock` | 함선 | 공유 정비 자재. 소수 값을 유지하며 상한은 240이다. |
| `repairPolicy` | 게임 | 플레이어 정비 인력 배분 정책 |
| `serviceTargetId` | 게임 | 현장 작업의 우선 대상. 없으면 자동으로 후보를 고른다. |
| `crew.job` | 승무원 | 작업 종류, 목적지, 현장 위치, 경로, 작업 진행 |

열을 낮추는 방열과 불을 끄는 소화는 각각 처리한다. 소화가 끝나도 남아 있는 열을 즉시 0으로 만들지 않는다. 높은 열 때문에 다시 점화될 수 있으므로 오버클럭과 냉각 상태도 함께 관리해야 한다. 파괴된 모듈의 화재는 정리하며, 분리되어 활성 상태를 잃은 모듈에는 현재 함선의 화재 진행과 현장 작업을 적용하지 않는다. [상태 처리 구현](../../dist/sim.js)

## 3. 점화·성장·피해·확산

현재 수치는 플레이를 위한 자체 규칙이다. 확률 판정은 게임에 저장되는 의사 난수 상태를 사용한다.

### 지속 처리

활성 상태인 살아 있는 모듈의 화재가 진행할 때 다음 규칙을 적용한다. 아래의 F는 해당 처리에서 사용하는 화재 강도이며, 시간 단위는 초다.

| 항목 | 현재 규칙 |
| --- | --- |
| 화재 성장 | 초당 0.035, 최대 강도 1 |
| 화재로 인한 열 증가 | 초당 8 × F |
| 화재 피해 | 초당 2.4 × F HP |
| 소화 속도 | 현장 작업자 1명당 초당 0.30의 강도 감소 |

화재는 한 번 점화된 뒤 별도의 피격 없이 지속된다. 작업자가 진압 중이면 성장과 소화가 함께 작용한다. 한 모듈에는 동시에 한 명의 현장 작업자만 배정하므로, 같은 불에 여러 명을 붙여 위 소화 속도를 단순히 배수로 늘리는 구조는 아니다.

### 확산과 과열 점화

0.5초 주기에서 다음 조건을 검사한다.

| 조건 | 판정·결과 |
| --- | --- |
| 화재 강도 F > 0.35 | 확률 0.075 × F로 확산 시도 |
| 확산 성공 | 상하좌우의 활성 모듈 중 불이 없는 후보 하나를 골라 강도 0.18로 점화 |
| 열 ≥ 100, 현재 불이 없음 | 확률 min(0.45, 0.10 + (열 − 100) / 150)로 강도 0.22 점화 |

대각선 모듈이나 떨어진 모듈로 직접 확산하지 않는다. 후보가 없으면 새 불을 만들지 않는다. 확률적 처리이므로 같은 강도의 불이 항상 같은 시간에 번지는 것은 아니다.

### 피격 점화

레이저·중포·파편 피해·폭발 피해를 받은 뒤에도 HP가 남아 있는 모듈은 점화 판정 대상이다. q를 해당 타격의 실제 피해 / 모듈 최대 HP로 놓으면 다음과 같다.

- 점화 확률: 장갑은 0.06, 나머지 모듈은 0.16에 min(0.26, 0.55 × q)를 더한다.
- 초기 강도: min(0.60, 0.18 + 0.65 × q).

화재 피해 자체는 이 피격 점화 판정을 반복 호출하지 않는다. 지속 화재의 확산은 별도의 주기 규칙으로 처리한다. [점화·피해 구현](../../dist/sim.js)

## 4. 작업 장소와 실제 이동

현장 작업은 목표 모듈 자체의 칸 또는 상하좌우 한 칸을 작업 장소로 삼는다. 그 장소는 승무원이 걸을 수 있는 활성 칸이어야 하며, 현재 승무원 위치에서 실제 경로가 있어야 한다.

장갑은 승무원이 통과할 수 없지만, 인접한 통로에서 장갑을 수리하거나 소화할 수 있다. 반대로 장갑으로만 이어진 외부 장치는 함선 구조에 연결되어 있어도 승무원이 접근할 수 없을 수 있다. 이런 대상의 수동 우선 지정은 이유를 표시하며 거부한다.

작업 흐름은 **후보 선택 → 경로 이동 → 현장 도착 → 소화 또는 수리 → 완료·취소**다. 선택 버튼을 누르거나 경로가 만들어졌다는 이유만으로 HP를 회복하지 않는다. 현장에 도착한 승무원의 실제 좌표가 작업 장소와 일치해야 효과가 발생한다.

부품 파괴로 경로가 끊기거나 대상이 사라지면 작업을 재검토한다. 유효하지 않은 현장 작업은 취소하거나 다시 경로를 잡으며, 기존 경로를 무시하고 떨어진 곳에서 계속 수리하지 않는다.

## 5. 소화와 수리의 조건

| 작업 | 시작·계속 조건 | 결과 |
| --- | --- | --- |
| 소화 | 대상이 살아 있고 활성 상태이며 불이 있음 | fire 감소. 정비 자재를 소비하지 않음 |
| 수리 | 대상이 살아 있고 활성 상태이며 불이 꺼져 있고 HP가 부족하며 자재가 있음 | 초당 최대 8 HP 회복. 회복한 HP의 0.25만큼 자재 소비 |
| 파괴 모듈 복구 | 현장 작업으로 수행하지 않음 | 도크의 유료 설계 복구를 사용 |

수리량은 남은 손상과 자재가 허용하는 양을 넘지 않는다. 자재 1단위는 4 HP를 회복할 수 있다. 예를 들어 0.75단위만 남아 있다면 최대 3 HP를 회복한 뒤 멈춘다. 실제 회복량만큼만 비용을 적용하므로 HP 상한을 넘기거나 재고가 음수가 되지 않는다.

정비 자재는 함선이 공유하는 수치다. 승무원이 자재를 창고에서 집어 현장까지 나르는 단계는 현재 구현에 없다. 전지·탄약 운반은 기존의 물리적인 화물 작업을 유지한다.

## 6. 정책과 인력 경쟁

| 정책 | 현장 작업 인원 한도 | 수리 |
| --- | --- | --- |
| 균형 | 승무원 수 × 25%를 내림, 승무원이 있으면 최소 1명 | 허용 |
| 생존 우선 | 승무원 수 × 60%를 내림, 승무원이 있으면 최소 1명 | 허용 |
| 보급 집중 | 소화 최대 1명 | 중지 |

승무원이 0명이면 현장 작업도 0명이다. 12명이 있는 기본 함선에서는 균형이 최대 3명, 생존 우선이 최대 7명을 현장 작업에 사용한다. 이는 상한이며, 대상이나 경로가 부족하면 실제 인원이 더 적다.

빈손인 승무원에게 새 현장 작업을 배정한다. 이미 화물을 들고 있는 운반자의 전지·탄약을 임의로 지우지 않는다. 긴급 배정은 아직 화물을 집기 전의 보급 작업을 전환할 수 있고, 정책을 바꾸면 기존 현장 작업도 새 인원 한도에 맞게 정리한다.

우선 대상은 후보 점수를 높인다. 그 대상에도 경로·자재·정책·모듈당 한 명 제한을 그대로 적용한다. **보급 집중에서 G로 지정해도 수리를 시작하지 않는다.** 자동 후보 선택에서는 화재, 손상 비율, 조종실·원자로, 거리와 작업 장소의 화재를 함께 고려한다.

## 7. 도크 복구·조립·저장과의 관계

- 유료 선체 복구가 실행되면 설계에 맞춰 HP를 복구하고 화재를 정리한다. 기존 정비 자재는 유지하며 자동으로 보충하지 않는다.
- 청사진 재사용은 부품의 손상과 재고를 유지한다. 현장 작업과 화재가 진행된 뒤에는 오래된 조립 Undo로 피해·진압·시간을 되돌리지 못하도록 편집 이력을 무효화한다.
- v3 저장은 fire, 자재, 정책, 우선 대상, 현장 경로와 작업 진행을 함께 보존한다. 상세 형식은 [저장 문서](03_save_v3_and_migration.md)를 따른다.

현장 작업 통계는 `firesExtinguished`, `hullRepaired`, `repairStockUsed`다. 실제 승무원 작업으로 진압·회복·소비한 양을 기록한다. 모듈이 파괴되어 불이 사라지거나 도크에서 일괄 복구한 결과를 현장 작업 실적으로 세지 않는다.

## 8. 검증과 현재 한계

자동 검사는 무인 화재의 지속 피해·확산, 소방 인력의 실제 도착, 소화의 무자재 처리, HP 회복과 소비의 일치, 장갑으로 막힌 경로, 소수 자재 고갈, 파괴 부품의 비재생, 정책별 실제 수리·보급량 차이를 확인한다. 화재 진행 뒤 Undo가 게임 상태를 되돌리지 않는 검사도 포함한다.

확산 검사는 고정된 난수 상태에서 재현되는 경로를 확인한다. 확률 분포 전체나 모든 함선 구조의 생존성을 입증하는 검사는 아니다. 산소·감압·연료 종류·개인 장비·선외 작업은 구현하지 않았으며, 정비 자재의 함내 운반도 생략한다. 문서의 속도와 확률은 현재 프로토타입 수치다.
