# v13 구현 메모

## 상태 소유권

`CryptGame.Game`이 전투·AI·아이템·결과의 단일 상태를 소유합니다. DOM 계층은 입력을 전달하고 게임 이벤트를 받아 표시합니다. Game 모듈에는 DOM·WebGL·타이머 접근이 없습니다. `core.js`와 `game.js`는 Node에서도 동일하게 동작합니다.

## 프레임과 시간

렌더링은 requestAnimationFrame, 시뮬레이션은 누적 시간으로 1/60초 단계를 실행합니다. 느린 프레임에서 무한 추격하지 않도록 한 프레임에 최대 6단계만 처리합니다. 장시간 탭 정지 후 경과 시간을 한꺼번에 적용하지 않습니다. 이 선택은 저성능 환경에서 실제 시간보다 게임 시간이 느려질 수 있다는 절충을 갖습니다.

## 근접 충돌

`bladePose → Game.getBlade`의 같은 위치를 시각화와 `swingSweep`이 공유합니다. 공격 활성 구간을 최대 약 6ms 단위로 나누고, 검 길이 약 12cm 간격의 점을 따라 이전/현재 위치 사이 선분을 검사합니다. 검사 반경은 5.5cm입니다. 시간 구간마다 가장 빠른 벽·방패·신체 접촉을 선택합니다. 신체 대상은 공격별 Set으로 중복 피해를 차단합니다.

월드 벽은 AABB, 방패는 OBB, 신체는 머리·몸통·다리 구체입니다. 무기 메시를 그대로 충돌 삼각형으로 처리하지 않으며, 날의 공간 샘플 사이 틈이나 급격한 시점 회전에는 근사 오차가 남습니다. 플레이어의 시점은 시뮬레이션 단계 안에서 보간하지 않으므로 이것을 완전한 6자유도 CCD라고 부르지 않습니다.

## AI

각 적은 하나의 공격 객체와 `idle / chase / windup / active / recovery / stagger / dead` 상태를 사용합니다. 벽 차폐와 거리로 플레이어를 관측하고, 기억 시간 동안 마지막으로 본 위치로 추적합니다. A*는 격자 기반이며 보행 충돌을 별도로 검사합니다. 청각 기반 탐지, 복잡한 군집 회피, 원위치 복귀 패턴은 이번 버전 범위 밖입니다.

## 인벤토리 원자성

인벤토리의 유일한 배치는 아이템 인스턴스의 `x, y, rotated`입니다. UI는 이를 표시합니다. 이동과 회전은 검증 후 반영합니다. 장착은 선택 아이템 제거 및 이전 장비 보관을 시도하고 실패하면 전체 배치를 복구합니다. 루팅은 대상 가방에 삽입 성공 후 원본 컨테이너에서 제거합니다. 이 모델은 로컬 단일 스레드의 원자적 처리이며 온라인 DB 트랜잭션과 동일하지 않습니다.

## 렌더링

외부 라이브러리 없는 WebGL1입니다. 던전 정적 메시와 매 프레임 생성하는 동적 메시를 각 한 번 그립니다. 절차적 캐릭터 관절은 스키닝 대신 로드·박스·저폴리 구체를 구성합니다. 동적 메시 재생성은 CPU/GC 비용이 있으므로 이후 대규모 콘텐츠에는 캐시·인스턴싱 최적화가 필요합니다. 광원 네 개, 플레이어 조명, 포탈 조명과 거리 안개를 사용합니다. 실제 그림자 맵·GI는 없습니다.

## 개발자 인터페이스

`window.cryptDebug.getState()`와 `getV13()`으로 상태를 관찰합니다. `setAuto(false)`는 자동 시뮬레이션만, `setRenderAuto(false)`는 자동 렌더링만 정지합니다. `step(seconds, controls)`는 테스트 전진, `render()`는 한 프레임 렌더링입니다. 실제 배포 보안을 제공하지 않는 로컬 디버그 기능입니다.
