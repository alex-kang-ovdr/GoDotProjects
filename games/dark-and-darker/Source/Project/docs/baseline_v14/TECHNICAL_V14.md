# v14.1 입력 수정 안내

이 문서 아래의 그래픽 설명은 v14 기준이다. v14.1은 터치 입력과 모바일 UI를 추가했다.
신규 `src/touch.js`는 포인터 소유권, 조이스틱 데드존 14%, 시점 드래그, 행동 버튼의 유지/해제를 관리한다.
`src/app.js`가 키보드와 터치 축을 합산 후 [-1, 1]로 제한하며, 게임 시뮬레이션이 대각선 길이를 1 이하로 제한한다.
터치 기본 감도는 CSS 픽셀당 0.006 라디안이며 설정의 100%에 해당한다. 마우스 감도와 분리된다.
입력 상태는 플레이 중/일시정지/배낭 상태와 동기화하며, 터치 조작에 Pointer Lock을 요구하지 않는다.
검증 범위는 `tests/TEST_REPORT.md`를 우선한다. 아래의 v14 검사 수나 스크린샷을 v14.1 모바일 검증으로 인용하지 않는다.

# v14 기술 설명

## 실행 구조

`core.js`와 `game.js`는 v13 원본을 유지한다. 렌더러는 게임 스냅샷을 읽으며 전투·AI·보상 계산을 바꾸지 않는다.
`scene.js`는 매 프레임 동적 메시를 한 버퍼로 작성한다. `buildDungeonMesh`는 출전 시 정적 메시를 생성한다.
게임 시뮬레이션은 기존 고정 간격 루프를 사용한다.

## 렌더 순서

1. CPU에서 동적 모델·효과·뷰모델 정점 생성.
2. 선택적으로 정적 + 월드 동적 메시를 랜턴 그림자 맵에 기록.
3. 정적·동적 메시를 장면 프레임버퍼에 렌더.
4. 선택적으로 1/4 크기 버퍼에 밝은 영역을 추출하고 수평·수직 블러.
5. 최종 화면에서 경량 FXAA, 발광 합성, 필름형 톤 매핑 및 감마 변환.

균형·고품질 설정에서 드로우 호출은 그림자 2 + 장면 2 + 후처리 3 = 7이다.
성능 설정에서는 장면 2 + 최종 합성 1 = 3이다. 이 값은 드로우 수이며 GPU 렌더 패스 수와 구별한다.
GPU 전체 시간, CPU 동적 메시 생성 시간, 해상도와 오버드로우까지 고려해야 실제 성능을 판단할 수 있다.

## 그림자 범위

카메라 주변 랜턴 한 개의 투영 그림자다. RGB에 깊이를 저장하고 셰이더에서 4탭 비교한다.
모든 횃불에 각각 그림자 맵이 있는 것은 아니다. 가까운 횃불 4개는 추가 점광원으로 선택하며 카메라에서 벽으로 가려진 후보를 우선 제외한다.
포탈은 푸른 점광원 기여를 한다. 랜턴 외 광원의 모든 가림과 간접광을 계산하지 않으므로 일부 빛샘이 남을 수 있다.
1인칭 무기는 그림자 캐스터에서 제외하며, 몬스터·상자 등 월드 동적 메시만 그림자를 만든다.

## 재질

재질당 256×256 타일, 4×2 배치의 1024×512 아틀라스 두 장을 사용한다.
첫 번째 RGB는 색, A는 국부 AO다. 두 번째 RGB는 노멀, A는 거칠기다.
아틀라스 경계에는 4픽셀의 순환 여백을 두고 내부 범위로 UV를 제한한다.
면의 주요 축으로 투영하는 셰이더이므로 변형 메시 전용 UV·탠전트 공간이 있는 제작 파이프라인은 아니다.
금속과 비금속의 단순화한 반사 응답, 표면 요철, 바닥 가장자리 음영, 거리·높이 안개를 결합한다.
실시간 GI, SSR, SSAO, 지오메트리 변위, 레이트레이싱은 없다.

## 모델

구·타원체·봉·삼각형·모서리를 깎은 박스를 조합한 절차적 관절 모델이다.
외부 캐릭터 에셋, 스킨 웨이트, 리깅된 애니메이션 클립을 로드하지 않는다.
검의 손잡이·끝점은 게임의 `getBlade()` 결과를 사용한다. 충돌도 같은 기본 궤적에서 계산되지만, 장식된 칼날 전체를 삼각형 단위로 Sweep하지는 않는다.
방패의 그래픽 실루엣은 기존 OBB 충돌체를 바탕으로 한다. 모서리까지 완전히 같은 물리 메시 판정은 아니다.
장식은 기존 맵 위에 붙이며 벽·바닥·AI 내비게이션 규칙은 변경하지 않는다.

## 옵션과 정리

해상도 변경 시 장면·블러 버퍼를 재할당하고 이전 자원을 해제한다.
고품질로 전환할 때 그림자 맵을 2048로 재생성하며 균형에서는 1024를 사용한다.
이미지 로드 실패는 기본 재질을 유지한다. WebGL 컨텍스트 손실 시 기존 UI에서 재시작 안내를 표시한다.
모든 재질 PNG는 HTML에 data URI로 내장된다. 런타임 네트워크 의존성은 없다.

## 진단

```js
cryptDebug.getV14()
cryptDebug.renderer.setPreset('performance')
cryptDebug.renderer.setPreset('balanced')
cryptDebug.renderer.setPreset('cinematic')
```

`renderCpuMs`는 함수 호출 전후 CPU 시간이다. GPU를 기다리는 측정 방식이 아니므로 FPS로 환산하면 안 된다.
검증용 `cryptDebug`는 개발 편의 인터페이스이며 온라인 게임의 보안 경계가 아니다.
