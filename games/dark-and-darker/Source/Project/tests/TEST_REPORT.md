## 의미 있는 확인 항목

- WASD의 카메라 기준 이동, 대각선 최고속 제한, 부분 조이스틱 입력 보존.

- 방향키 기본 비활성, 사용자가 켠 보조 설정, Pointer Lock 실패·부재·복구.
- 포인터별 이동/시점/버튼 소유, 여러 손가락 동시 사용, 두 번째 손가락의 조작 탈취 차단.
- 포인터 취소·캡처 상실·화면 회전·blur·visibility·메뉴·재시작에서 입력 초기화와 오래된 이벤트 무시.
- 활/주문 준비 전 해제·완료 후 발사·취소 시 자원 미소비·혼합 마우스/터치 소유권.
- 실제 클래스 제한, 스킬 지속·재사용·횟수, 2초 단위 휴식, 물약 사용 후 지속 회복, 피격 중단.
- 화염구의 직접/폭발/연소 성분, 얼음 화살의 둔화, 전격의 벽 차폐, 선택 주문 R 해제.

## 발견 후 수정한 회귀 결함

하이브리드 기기에서 마우스로 활을 당기는 도중 다른 보조 행동 터치가 취소되면, 이전 전역 취소 호출이 활 당김까지 삭제했습니다. 취소된 채널만 해제하도록 수정했습니다. 독립 방패 유지 및 동일 채널의 마우스 소유 유지 사례도 함께 재검증했습니다.

## 정적 모바일 배치 확인

360×640, 844×391, 320×568, 667×375에서 CSS에 명시된 위치·크기 산술 기준으로 18개 행동 버튼과 이동 패드의 겹침·화면 밖 배치·44px 미만 버튼이 없음을 확인했습니다. 안전 영역 0 가정입니다. 시점 레이어는 z-index 1, 조작 그룹은 3입니다.

이는 **브라우저가 실제 계산한 레이아웃 측정이 아닙니다.** 글꼴·안전 영역·화면 확대·주소 표시줄·기기별 뷰포트는 실제 기기 확인이 남아 있습니다.

## 환경 제한과 해석

이 세션의 Chromium 시작은 `socket() failed: Operation not permitted (1)`로 실패했고, 별도 브라우저 환경의 로컬 파일 접근도 보안 정책으로 차단되었습니다. 해당 차단을 우회하지 않았습니다. 따라서 신규 브라우저 화면 캡처·실기기 터치 성공·모바일 FPS·GPU 성능 수치를 제공하지 않습니다.

Node DOM fixture는 이벤트 전파와 Pointer Capture를 모델링하고 실제 입력 코드를 실행합니다. 스타일 레이아웃과 GPU는 대체되어 있습니다. 생성 메시 검사는 정점 유효성과 장비 선택 연결을 검증하며 시각적 품질을 증명하지 않습니다. 자동 검사 150개 통과를 원작과 완전히 동일하거나 모든 휴대폰에서 검증되었다는 의미로 사용하지 않습니다.
