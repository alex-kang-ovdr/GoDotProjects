## 문제와 수정

기존 v14의 input()은 WASD만 이동값으로 전달하고, 시점은 마우스 이동과 Pointer Lock에 의존했다. 터치 이동·시점 영역과 전투 버튼이 없어 Android에서 화면만 표시되고 이동할 수 없는 구조였다.

새 터치 컨트롤러는 각 pointerId에 이동, 시점, 행동 버튼 중 하나의 역할을 부여한다. 조이스틱은 중앙 14% 데드존과 아날로그 크기를 적용하고, 게임 쪽에서는 길이가 1을 넘을 때만 정규화한다. 키보드의 직선·대각선 최고속은 유지한다.

터치 모드에서는 Pointer Lock을 요청하지 않는다. 화면 버튼의 동작은 pointerdown에서 한 번 실행하며, 호환 마우스 클릭으로 공격이 중복되지 않도록 처리했다. 유지 버튼은 해제·취소·캡처 상실 시 풀린다. 일시정지·배낭·재시작·창 전환·숨김·화면 회전에서도 상태를 초기화한다.

## 입력 통합 검사 방식

Node v24.22.1에서 **배포 소스 app.js, touch.js, core.js, game.js를 그대로 실행**했다. 입력 병합이나 행동 콜백을 테스트 코드에 복사하지 않았다. 최소 DOM fixture가 이벤트의 capture/bubble, pointer capture와 element 상태를 제공하며, 렌더러·장면 출력은 대체했다.

따라서 게임 좌표 변화, 시점 변화, 공격 횟수와 자원 소비, 수색 타이머, 입력 잔류 여부에 대한 검사다. 실제 브라우저의 CSS 배치, 네이티브 터치 이벤트 생성, WebGL 렌더링 또는 기기별 입력 전달까지 검증한 것은 아니다.

통과 항목:

- 중앙 데드존, 작은 기울기의 느린 이동, 큰 대각선 입력의 최고속 제한.
- 이동 + 시점 + 공격을 독립 포인터로 동시에 처리하고 실제 위치·yaw·공격 횟수가 변경됨.
- 두 번째 이동 손가락이나 같은 버튼의 추가 손가락이 기존 소유권을 빼앗지 않음.
- 한 손가락만 해제하면 나머지 입력은 유지됨.
- pointercancel, lostpointercapture, 영역 밖 해제 및 동기적인 캡처 해제 재진입.
- 수색 유지 중 진행, 도중 해제 시 취소, 완료 후 상자와 배낭 열림.
- 키보드와 터치의 이동·수색을 병합하고 한 입력원의 해제가 다른 입력원을 취소하지 않음.
- 메뉴·배낭·재시작·회전·resize·blur·숨김 상태에서 입력 초기화.
- 활·화염구·장전·물약의 실제 자원 소비, 점프·달리기·회피.
- PC WASD, 방향키 시점, 마우스 공격·방어 어댑터.
- 터치 표시 수동 전환과 하이브리드 기기의 첫 터치 감지.

## 브라우저 제한

Playwright가 Chromium을 시작하는 단계에서 다음 환경 오류로 종료되었다.

`socket() failed: Operation not permitted (1)`

페이지를 로드하지 못했으므로 모바일 브라우저 검사는 **BLOCKED / executed 0**으로 기록했다. 별도 브라우저 점검 경로에서도 로컬 파일 프로토콜이 정책상 허용되지 않아 중단했다. 해당 제한을 바꾸거나 우회하지 않았다.

`test_touch.py`는 실행 가능한 환경에서 실제 Chromium 터치 이벤트를 통해 재검사할 수 있는 스크립트다. 스크립트에 검사가 존재한다는 사실을 통과로 세지 않았다. 세로 391×844, 360×640 및 가로 844×391의 화면·버튼 검사는 이번 환경에서 미실행이다.

## 소스 보존 / 패키지

- core.js, renderer.js, scene.js, assets.js: 원본 v14 ZIP과 바이트 단위 동일.
- game.js: 이동 입력 정규화 한 줄 변경. diff는 movement_change.diff에 있다.
- 신규 touch.js와 수정된 app.js / template.html / style.css를 단일 HTML에 포함.
- BUILD_MANIFEST.json에 최종 HTML 크기·해시와 소스 해시 기록.
- 기존 v14의 112개 검사 기록은 baseline_v14/에 보관. 이번 수정본에서 다시 실행한 브라우저 결과가 아니다.
- docs/*.png는 기존 v14 캡처이며 v14.1 모바일 신규 캡처가 아니다.

## 재실행

```sh
python3 build.py
node tests/test_core.cjs
node tests/test_touch_unit.cjs
# Chromium을 정상 실행할 수 있는 환경에서:
python3 tests/test_touch.py
```

단일 HTML의 file:// 또는 Android content:// 실행, 영구 저장 유지, 기기별 터치와 GPU 성능은 실제 대상 기기에서 추가 확인해야 한다.
