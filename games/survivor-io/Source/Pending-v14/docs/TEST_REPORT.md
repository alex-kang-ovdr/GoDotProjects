실제 배포 HTML 전체를 Chromium에 주입했습니다. 테스트는 실제 렌더링/게임 로직을 호출하며 스텝과 난수를 제어합니다. 키보드·터치, 슬롯과 진화, 공격과 타격, 보조 수치, 수호자 탄환 차단, 탄창/재장전, 부품 효과, 저장 형식, 열린 카드 유지, 패배·승리·정산 중복 방지, 5/15분 보스 일정, WebGL 및 2D 대체 경로를 검사했습니다. 모바일 크기는 390×844와 844×390입니다. 160마리 전투 장면도 렌더링 오류와 드로우콜 상한을 확인했습니다.

저장 검사는 **인메모리 localStorage 어댑터**를 이용한 새 문서 복원입니다. 실제 사용자 디스크 지속성이나 브라우저 재시작 저장의 검증이 아닙니다. 기능 검사의 임의 강화/테스트 상태는 일반 플레이에 적용되지 않습니다. `#test`에서만 `window.__test`를 노출합니다.

## 파일 원점 실행 제한

`file://` 실제 탐색을 시도했으나 관리 정책의 `ERR_BLOCKED_BY_ADMINISTRATOR` 오류로 차단되었습니다. 해당 검사는 성공으로 집계하지 않았습니다. `tests/file_origin_probe.json`에 원문을 기록했습니다. 오프라인 단일 HTML로 구성했지만 이 환경에서 파일 원점에서의 실행·브라우저 재시작 후 저장 유지 검사를 완료하지 못했습니다.

실제 Android/iOS 기기, Safari, 모바일 GPU 성능·발열·장시간 메모리, 다중 탭 동시 플레이는 미검증입니다. 자동 검사 통과는 원작 사양 일치나 상용 게임 QA 완료를 의미하지 않습니다.

## 재실행

게임 실행에는 Python/Node가 필요하지 않습니다. 검사는 개발 환경에서만 수행합니다.

```bash
python build.py
python tests/validate_package.py
# Playwright + Chromium + 표시 서버가 있는 Linux 개발 환경
DISPLAY=:99 python tests/test_v14.py
DISPLAY=:99 python tests/balance_probe.py
```

브라우저 테스트 코드는 Chromium 실행 경로 `/usr/bin/chromium`을 사용합니다. 다른 환경에서는 해당 경로와 headless/표시 서버 설정을 조정해야 합니다. 테스트 재실행은 `tests/report.json`, 봇 결과 및 캡처를 덮어씁니다.
