## 공개 명령으로 이어지는 실제 플레이

### 기본 정착지에서 구조선 응답까지

`seed:314159`, `difficulty:'standard'`에서 `command()`와 `update()`만 사용한다. 자원·지도·능력치·적·시계에 직접 값을 주입하지 않는다. 전기·냉장·통신 연구, 거처·발전·축전, 식량 생산·보관, 습격 방어, 마지막 구조 전송이 연결된다.

| 항목 | 결과 |
| --- | ---: |
| 구조 성공 시각 | 1239.3 시뮬레이션 초 |
| 생존 주민 | 3명 |
| 실내 침대 | 3개 |
| 방어한 습격 | 5회 |
| 채집량 | 330 |
| 조리한 식사 | 50 |
| 부패한 식량 | 75 |
| 자연 낙뢰 | 3회 |
| 주민의 직접 진화 | 4회 |

직전 v3 시나리오와 같은 결과다. 연구·운반·구조 신호 충전 중 저장한 복원본도 원본과 동일하게 진행한다. 이는 한 가지 재현 가능한 운영 전략을 검증하며 모든 플레이 방식의 성공을 보장하는 수치는 아니다.

### 제작에서 교역과 장착까지

같은 기본 시드·표준 난도에서 공개 명령으로 일정을 자율로 바꾸고 제작·운반 역할을 배정한다. 첫 자연 방문 안에 아래 흐름을 **180 시뮬레이션 초 이전**에 완료했다.

1. 제작대를 실제로 건설한다.
2. 목재·강철을 운반해 작업 도구 1개를 제작하고 창고로 나른다.
3. 자연적으로 도착한 상인에게 도구 1개와 목재 10개를 판다.
4. 받은 은화 44개를 바닥에서 수거해 창고 은화를 60→104개로 만든다.
5. 소총 1개를 100 은화에 구매한다. 구매 직후 창고에는 소총이 없어 장착 명령이 거절되는 것도 확인한다.
6. 소총을 창고로 운반하고 주민이 수령·장착한다. 남은 창고 은화는 4개, 소총 총 소유량은 1개이며 주민 3명이 생존한다.

구체적인 테스트는 [economy-scenario.test.mjs](../tests/economy-scenario.test.mjs)에 있다. 이 테스트는 원래 식량·지도·기술·전투 수치를 직접 수정하지 않는다. 일정과 업무 우선순위 변경은 실제 사용자에게 제공하는 공개 명령이다.

## UI·렌더 검증과 한계

[ui.test.mjs](../tests/ui.test.mjs)는 실제 `app.js`를 Node VM에서 실행한다. HTML과 이벤트를 모사하는 [ui-harness.mjs](../tests/ui-harness.mjs)는 테스트 전용 DOM 대역이며 실제 브라우저가 아니다. 10개 패널의 생성과 버튼·키보드·입력 이벤트가 실제 엔진 명령에 연결되는지, 입력 중 갱신이 값을 지우지 않는지, 다른 패널로 이동할 수 있는지 확인했다.

별도 Canvas 대역 검증은 새 제작대, 4종 물품, 소총·조끼·도구, 상인의 3단계와 일반·온도·전력 3개 레이어를 실행했다. 숫자 인수가 유한하고 렌더링 전후 게임 상태가 동일한지 확인했다. 상인 우회·회전 중 20개 스냅샷을 저장·복원하는 별도 검증에서도 이후 진행이 일치했다.

**브라우저 미리보기 접근 제한으로 v4의 실제 브라우저 화면 검증은 완료하지 못했다.** DOM·Canvas 대역은 CSS 배치, 실제 마우스·터치 동작, 기기별 그래픽·성능을 증명하지 않는다. 실제 모바일 기기 시각·성능 검증도 별도다. 서버 배포 성공과 시뮬레이션·UI 이벤트 수용 검증을 이 한계와 구분한다.
