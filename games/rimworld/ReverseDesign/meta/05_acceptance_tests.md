# 통합 수용 기준과 문서 검증

[전체 목차](../README.md) · [공통 계약](02_system_dependencies.md)

> **아래 게임 테스트는 전부 [제안]이며 실행하지 않았다.** 원작 빌드나 재구현 프로그램을 돌려 통과시킨 보고서가 아니다. 실제로 수행한 Markdown 파일 검증은 마지막 절에 별도로 기록한다.

## 1. 검증 환경을 고정하는 방법

원작 대조를 시작할 때는 플랫폼·정확한 빌드·DLC·모드·시나리오·스토리텔러·난도·시드·게임 속도를 기록한다. 기본 게임 규칙을 보려면 모드를 끄고 필요한 DLC만 활성화한다. 특정 무작위 결과를 확인하는 테스트와 결정적인 상태 보존 테스트를 분리한다.

재구현 검증에서는 최소 맵과 작은 인구를 사용해 입력과 결과를 추적한다. 아래의 인원·재고·시간 값은 검증용 가정이며 원작의 기본 시작 설정을 뜻하지 않는다.

## 6. 결과 기록 양식

```yaml
# [제안] 실행 시 채울 기록 양식
test_id: IT-01
build: unrecorded
content_set: []
seed: null
initial_save: null
execution_status: not_run
observed_result: null
expected_result_reference: IT-01
evidence: []
```

확률 결과는 한 번의 성공·실패만으로 확정하지 않는다. 분포를 검증할 때는 표본 수·설정·신뢰 범위를 별도 보고한다. 상태 보존 테스트에서는 총량뿐 아니라 실제 소유자와 대상 ID를 확인한다.

## 7. 이 문서 묶음에서 수행한 검토

시스템 문서는 서로 다른 담당자가 교차 검토했다. 그 과정에서 다음 오해 가능성을 수정했다.

- 정신 이상 위험 경고와 실제 행동 발동에 따른 작업 중단을 분리했다.
- 아이템 정의의 기본값과 품질·상태에 따른 최종 시장가치를 분리했다.
- 소실된 부위의 보철 수술과 이미 없는 부위의 적출을 구분했다.
- 일반 동물의 오물과 DLC의 독성 오염 용어를 구분했다.
- 기본 1.6 상단의 캠프와 즉시 출발 기능을 보완했다.
- UI 문헌의 가속 배율 불일치는 확정 수치에 포함하지 않았다.

기계적 문서 검증 결과는 아래에 최종 기록한다. 이것은 게임 규칙의 실행 검증과 다르다.

| 문서 검사 항목 | 결과 | 범위와 한계 |
| --- | --- | --- |
| Markdown 파일 | 30개 확인 | 기본 18·DLC 5·공통 7 |
| 메타데이터 | 30개 YAML frontmatter 해석 성공 | 필수 필드와 문서 ID 중복 확인 |
| 시스템 양식 | 23개 문서의 1~12절 확인 | 순서·누락 검사 |
| 상대 링크·앵커 | 437개 유효 | 압축 내부 파일과 문서 제목 기준 |
| Markdown 파싱 | 30개 성공 | 제목·표·코드블록의 GFM 파싱 |
| 데이터 예시 | YAML 27개 해석 성공 | 원작 데이터 검증을 뜻하지 않음 |
| Mermaid | 26개 정적 문법·흐름 검토 | 괄호·레이블·분기 확인; 렌더러 실행 검증은 미실시 |
| 게임 수용 시나리오 | 시스템별 129개 + 통합 30개 작성 | 모두 실행 전 계획 |
| 출처 | 고유 URL 86개 색인 | 개별 출처 키 참조 검사 |

문서 구조 검사에서 누락된 파일 링크·출처 키·메타데이터 오류는 발견하지 않았다. 게임 수치·확률·호환을 실제 실행으로 검증했다는 의미는 아니다.


## 8. 후속 확인 우선순위

1. 실제 대상 PC 빌드와 DLC 구성을 고정한다.
2. 위키에 보완·미확인 표시가 있는 수치 중 구현에 필요한 것만 확인한다.
3. 작업 예약·중단·물품 소유권·저장 연속성을 먼저 실행 검증한다.
4. 정상 기능을 검증한 뒤 확률·밸런스·규모별 성능을 측정한다.

이 순서는 검증 제안이다. 원작 전체를 복제하거나 모든 조합을 이미 검증했다는 의미가 아니다.
