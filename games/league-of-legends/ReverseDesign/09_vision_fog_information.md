## 1. 범위와 근거 표기

- 기준 대상: PC 소환사의 협곡 5대5. 조사일: 2026-11-13.
- **[공식]**은 공개 자료에 명시된 범위, **[분석]**은 플레이 의사결정 해석, **[제안]**은 재현용 시스템 설계다.
- 와드의 현재 지속시간·충전시간·반경과 챔피언별 은신 예외를 전수 검증한 표는 아니다.
- 과거 개발 자료는 당시 구현 또는 설계 설명으로만 인용한다.

## 2. 시스템의 목적

**[공식·기술 역사]** Riot는 전장의 안개를 챔피언·능력·와드 등의 시야가 확보되지 않은 공간을 가리는 시스템으로 설명했다. 2016년 글은 당시 시야 데이터와 그 화면 표현을 따로 개선한 사례다. 현재 엔진의 격자 크기를 확인하는 자료는 아니다. [W-V01]

**[분석]** 시야의 핵심은 맵을 밝게 만드는 것이 아니라 **상대의 다음 행동에 대한 불확실성을 줄이는 것**이다. 적을 한 명 발견한 정보는 그 지역에 대한 정보이면서, 다른 지역에 그 적이 없다는 간접 정보가 된다.

| 설계 기능 | 플레이어 경험 |
| --- | --- |
| 매복 가능성 유지 | 강한 팀도 준비 없이 전진하면 위험 |
| 정찰의 가치 부여 | 직접 피해를 주지 않는 행동도 승리에 기여 |
| 상대 경로 추론 | 한 번 얻은 정보가 이후 판단에 계속 사용됨 |
| 행동의 은폐 | 보이지 않는 시간이 공격·귀환·낚시의 선택권이 됨 |
| 팀 협업 유도 | 앞에서 공간을 확보하는 사람과 시야를 설치하는 사람이 협력 |

## 3. 시야가 알려주는 것과 알려주지 않는 것

**[분석]** 다음 네 질문을 구분하면 시야 오류와 정보 과신을 줄일 수 있다.

1. **그 지역을 현재 보고 있는가?**
2. **그 유닛을 현재 식별할 수 있는가?**
3. **그 유닛을 대상으로 지정할 수 있는가?**
4. **마지막으로 확인한 정보가 얼마나 오래되었는가?**

공간이 밝다고 모든 은신 상태를 발견하는 것은 아니며, 위치의 단서를 얻었다고 반드시 대상을 지정할 수 있는 것도 아니다. 반대로 보이지 않는 적도 방향을 지정하는 공격 범위에 들어갈 가능성은 있다. 실제 대상 판정은 능력별 규칙과 함께 확인해야 한다.

## 4. 정보의 단계

아래 표는 UI와 AI를 설계하기 위한 **[제안]**이며 실제 Riot 내부 열거형이 아니다.

| 정보 상태 | 이용할 수 있는 정보 | 허용하면 안 되는 추론 |
| --- | --- | --- |
| 현재 확인 | 현재 위치와 허용된 공개 상태 | 숨겨진 재사용 대기시간까지 자동 확정 |
| 부분 탐지 | 위치 단서·실루엣 등 해당 효과가 제공한 내용 | 완전한 대상으로 취급 |
| 마지막 확인 | 과거 위치와 확인 시각 | 과거 좌표를 현재 좌표처럼 고정 |
| 추정 | 이동 가능한 지역과 행동 후보 | 사실처럼 미니맵에 표시 |
| 미확인 | 신뢰할 직접 정보 없음 | 상대가 없다고 단정 |

특히 “미니맵에 적이 없다”와 “그곳에 적이 없다”를 같게 취급하지 않는 것이 정보전의 출발점이다.

## 5. 시야 획득원의 기능

**[분석]** 정확한 수치보다 지속성·위험·범위의 교환을 먼저 읽는다.

| 수단 | 주된 쓰임 | 지불하는 비용 | 주의할 점 |
| --- | --- | --- | --- |
| 챔피언의 직접 접근 | 빠른 확인과 공간 점유 | 사망 위험·위치 노출 | 확인 전에 공격받을 수 있음 |
| 일반 와드 | 일정 시간 경로 감시 | 충전·설치 기회 | 지나가지 않는 길을 보면 실효 가치 낮음 |
| 제어 와드 | 유지 가능한 정보 거점과 시야 경쟁 | 구매·슬롯·수비 필요 | 놓았다는 사실만으로 안전이 보장되지 않음 |
| 원거리 정찰 수단 | 위험한 지역을 멀리서 확인 | 재사용 대기시간·낮은 지속성 등 | 확인 직후 적이 이동할 수 있음 |
| 탐지·제거 수단 | 적 정보망 약화와 진입 준비 | 자기 위치 노출·공격 시간 | 제거 중 상대의 역공 가능 |
| 미니언·구조물 | 라인과 기지의 지속 정보 | 지도 진행도에 의존 | 정글의 우회까지 모두 알려주지 않음 |
| 지도 오브젝트·능력 | 특정 지역·방향 확인 | 지도 상태·자원·스킬 선택 | 기능별 공개 범위가 다름 |

## 6. 은신과 탐지를 별개로 설계하기

**[공식·설계 역사]** 2017 시즌 안내는 위장과 투명을 구분하고, 제어 와드가 모든 투명 챔피언을 드러내는 도구는 아니라고 명시했다. [W-V02]

**[분석]** 이 구분은 “탐지 수단을 샀으니 모든 은신을 무효화한다”는 단일 대응을 피한다. 긴 이동 경로를 숨기는 전략적 은신과 짧은 교전의 위치를 바꾸는 은신은 다른 대응 시간을 요구한다.

**[제안]** 재현 시에는 `보임/안 보임` 하나로 끝내지 말고 다음 속성을 분리한다.

- 가시 영역 안에 있는지.
- 수풀·벽·시야 감소의 영향을 받는지.
- 은신 유형이 무엇인지.
- 현재 탐지 효과가 어느 은신 유형에 대응하는지.
- 완전 공개인지 위치 단서만 제공하는지.
- 공격·피격·거리 조건이 은신을 어떻게 바꾸는지.
- 대상을 지정할 수 있는지와 방향성 공격에 맞을 수 있는지.

챔피언별 세부 상호작용은 개별 스킬 툴팁과 해당 버전의 검증이 필요하다. 위장·투명·대상 지정 불가는 동일 상태로 구현하지 않는다.

## 7. 수풀과 벽의 정보 차이

**[분석]** 수풀은 통과 가능한 공간에 은폐 조건을 더하고, 벽은 이동과 시야의 관계에 다른 제약을 만든다. 따라서 같은 반경에 들어 있어도 설치 위치에 따라 얻는 정보가 달라진다.

### 사례: 강가 입구 와드와 깊은 정글 와드

| 설치 지점 | 먼저 알게 되는 것 | 알기 어려운 것 | 알맞은 목적 |
| --- | --- | --- | --- |
| 라인 근처 입구 | 바로 다가오는 위협 | 상대의 긴 경로 | 짧은 시간 생존 |
| 여러 경로의 교차점 | 상대의 이동 방향 | 특정 라인으로의 확정 진입 | 다음 행동 예측 |
| 깊은 캠프 근처 | 정글의 자원 회수 | 설치하러 가는 동안의 안전 | 상대 정글 경로 추적 |
| 목표물 뒤쪽 | 우회 진입·접근 | 다른 측면의 전투 | 목표물 확보와 퇴로 준비 |

깊은 와드는 정보의 선행 시간을 늘리지만 설치 위험이 크다. 안전하게 넣을 수 있는 팀 상태가 와드 자체의 성능만큼 중요하다.

## 8. 2026의 위치 기반 시야 확장

**[공식·26.1 도입]** 요정불빛(Faelights)은 지정 지점에 설치한 와드가 주변의 추가 영역을 일시적으로 밝히는 기능이다. [W-V03]

**[공식·26.3 변경]** 이후 강가 일부 요정불빛의 추가 시야 형태와 초반 노란 장신구 재사용 대기시간이 조정되었다. 도입 수치를 현행 값으로 그대로 재사용하면 안 된다. [W-V04]

**[분석]** 이 구조는 같은 와드 한 개라도 **위치와 시점에 따라 다른 정보 품질**을 주는 장치다. “와드를 몇 개 설치했는가”에 더해 “어떤 행동을 할 동안 필요한 영역을 확보했는가”가 중요해진다.

**[제안]** 추가 영역의 형상·지속시간·시작 조건·기본 와드와의 연결·파괴 시 정리를 별도의 규칙 데이터로 둔다. 단순히 모든 와드의 원형 반경을 늘리는 구현으로 치환하면 위치별 의도와 대응 방식이 달라진다.

## 9. 목표물 전 시야 작업의 실제 흐름

**[분석 사례]** 다음 목표물에 도전할 팀은 생성 직전에 한 번 와드를 놓는 것으로 준비를 끝내지 않는다.

1. 먼저 인접 라인의 웨이브를 밀어 상대가 즉시 이동할 때 지불할 비용을 만든다.
2. 귀환과 구매를 맞춰 설치 자원·체력·스킬을 준비한다.
3. 앞에 설 수 있는 아군과 함께 강가의 첫 안전 구역을 확보한다.
4. 적의 기존 와드를 탐지하거나, 적이 볼 가능성이 높은 경로를 피한다.
5. 목표물 자체보다 적의 진입 경로를 볼 위치를 선택한다.
6. 적이 시야를 다시 확보하러 오면 교전·추격·목표물 시작 중 하나를 고른다.
7. 설치한 시야가 사라지거나 적이 다른 방향에서 나타나면 계획을 갱신한다.

이 흐름에서 시야는 교전의 사전 작업인 동시에 상대를 움직이게 하는 미끼가 된다.

## 10. 시야 거부와 낚시

**[분석]** 목표물 지역에 들어갔다는 사실을 보여준 다음 상대의 시야를 없애면, 상대는 세 가지 가능성을 구분해야 한다.

- 실제로 목표물을 공격하고 있다.
- 목표물 주변에서 접근하는 적을 기다리고 있다.
- 시야가 없는 동안 다른 지역으로 이동했다.

정보를 지운 팀은 이 선택권을 얻지만, 시간이 지나면 자신도 라인 자원을 잃거나 적에게 다른 목표를 내줄 수 있다. 시야 거부가 무한히 좋은 상태가 되지 않는 이유다.

## 11. 오래된 정보의 가치 감소

**[분석]** 적 정글이 상단에서 보였다는 정보는 즉시 하단의 공격 가능성을 높일 수 있지만, 시간이 흐르면 여러 경로가 다시 가능해진다.

**[제안·설명용]** 분석 UI에서는 마지막 확인 좌표 대신 다음 요소를 함께 기록한다.

```yaml
LastSeenRecord:
  entity_id: champion_id
  team_observer: observing_team
  seen_at: authoritative_time
  last_position: visible_position
  observed_direction: optional_direction
  information_source: ward_or_champion_or_ability
  confidence: not_a_claim_of_current_position
```

이 기록으로 실제 적 좌표를 추적해서는 안 된다. 가능한 이동 영역을 추정하더라도, 플레이어가 당시 몰랐던 이동기 사용이나 귀환 완료를 정답 데이터로 넣으면 분석의 정보 조건이 왜곡된다.

## 12. 시야 판정과 표현의 분리

**[제안]** 판정 데이터와 화면의 부드러운 안개 경계는 다른 책임을 가진다.

| 계층 | 책임 | 실패 사례 |
| --- | --- | --- |
| 게임 규칙 | 해당 팀이 유닛 정보를 알 수 있는지 | 숨겨야 할 상태가 공개됨 |
| 대상 지정 | 현재 입력 대상이 유효한지 | 보이지 않는 적을 자동 추적 |
| 복제 정책 | 클라이언트에 전달할 정보를 결정 | 화면만 숨겼지만 데이터는 노출 |
| 렌더링 | 안개 경계와 공개 전환을 읽기 쉽게 표현 | 시야가 보이는 것처럼 보여 잘못 접근 |
| UI | 미니맵·경고·핑에 일관된 정보 제공 | 본 화면에서는 숨었는데 미니맵에 남음 |

Riot의 과거 시야 렌더링 글은 이 분리를 생각할 수 있는 역사적 참고자료다. 그 글의 격자 해상도나 필터 방식을 현재 제품의 구현 명세로 복사하지 않는다. [W-V01]

## 13. 재구성 상태 모델

다음 상태와 이벤트는 **[제안]**이다.

```yaml
VisionSource:
  source_id: unique_id
  owner_team: team_id
  geometry_rule: radius_or_region
  visibility_policy: normal_or_detection_policy
  active_from: time
  expires_at: optional_time
  suppressed: boolean
  linked_entity_id: optional_id

VisibilityResult:
  observer_team: team_id
  subject_id: entity_id
  visibility_level: hidden_or_partial_or_visible
  targetable: boolean
  reason_codes: []
  effective_at: authoritative_time
```

시야원 제거와 연결된 추가 영역 제거는 같은 사건으로 확정한다. 와드는 사라졌는데 확장 시야만 계속 남는 오류를 방지하기 위해서다.

## 14. 시야 점수의 해석

**[공식·역사적 설명]** 2017년 Riot 설명은 시야 점수를 제공한 시야·제거한 시야·특수 시야 행동을 함께 보는 근사 지표로 설명했다. 현재의 모든 보정식을 검증한 자료는 아니다. [W-V05]

**[분석]** 시야 점수가 높다고 중요한 목표물 준비를 잘했다고 자동 결론내릴 수는 없다. 오래 유지되었지만 아무 행동도 지원하지 못한 와드와, 짧게 존재했지만 결정적 진입을 발견한 와드는 서로 다르다.

| 검토 지표 | 실제로 평가할 질문 |
| --- | --- |
| 설치 후 적 첫 발견 시간 | 충분한 사전 경고를 주었는가? |
| 시야 확보 후 아군 행동 | 안전한 파밍·공격·퇴각에 활용했는가? |
| 시야 제거 후 상대 반응 | 상대가 확인 비용을 지불했는가? |
| 시야 작업 중 사망 | 이익보다 설치 위험이 컸는가? |
| 목표물 접근 경로 확인율 | 필요한 방향을 적시에 보았는가? |
