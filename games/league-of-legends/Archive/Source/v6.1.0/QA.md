### 발견한 오류와 수정

- 큰 맵에서도 터치 지점·돌진 조준이 기본 `1572` 경계에 잘릴 수 있었다. `presentGame()`에서 조준을 해제하고 현재 맵의 `28..width/height-28`로 경계를 갱신했다. 1.5배·2배에서 큰 좌표 조준, 1배 로비에서 2배 저장 복원, 이후 1배 새 경기의 경계 재설정을 검사한다.
- 맵만 확대하고 지형 캐시를 기존 크기로 그리면 전장의 일부가 비게 된다. 월드 전체로 그리는 목적 사각형과 지도별 강·카메라·미니맵·안개를 일치시키고, 오프스크린 지형의 긴 변은 2048픽셀로 제한했다.
- 최초 통합 검사에서는 기존 포커스 테스트 하나가 현재 저장 버전을 6으로 기대했다. 기대값만 7로 수정하고 과거 fixture는 유지했다. 이후 최종 전체 230개가 통과했다.

### 새 전투 규칙의 회귀 범위

- 준비가 끝나기 전에는 피해·투사체·강화 공격 소비가 발생하지 않는다. 근접과 원거리 영웅 모두 실제 발사를 확인한다.
- 이동·정지·귀환·성공한 QWER/D·기절·사망·유효하지 않은 대상은 준비를 취소한다. F·와드·실패한 스킬·같은 대상 반복 클릭은 준비를 유지한다.
- 발사 후 이동은 날아가는 공격이나 남은 대기 시간을 지우지 않는다. 반복 이동으로 공격 간격을 줄일 수 없다.
- 일반 이동 중 자동 공격을 시작하지 않는다. 공격 이동은 사거리에서 정지해 준비한다. AI는 정상 준비를 끝내지만 포탑 위험·목표물 예고·낮은 체력에는 회피한다.
- 실제 `app.js` 이벤트와 실제 엔진을 연결한 검사는 버튼·키보드·마우스 입력, 준비 HUD, 일시정지 후 한 번의 발사를 확인한다. DOM·프레임 스케줄러·그리기는 대역이므로 실제 기기의 멀티터치·픽셀 검증과 구분한다.
- 렌더링 검사는 세 영웅의 준비·대기·일시정지 상태가 그리기 전후 동일한지, 숨겨진 공격자·대상이 표시에 쓰이지 않는지 확인한다.

### 발견한 오류와 회귀 범위

- 터치 입력 뒤 넓은 화면으로 바꾸면 이후 PC 클릭까지 계속 차단될 수 있었다. 버튼마다 실제 처리한 포인터 ID만 추적하고 새 pointerdown에서 오래된 억제를 지워 해결했다. 터치 탭의 한 번 시전, 취소 뒤 지연된 놓기, 키보드 활성화, 두 번째 손가락 거부 후 PC 클릭을 검사한다.
- A 영웅을 클릭해 추격하던 중 B를 고정하면 이전 A 추격이 남을 수 있었다. 다른 영웅으로 고정을 바꿀 때 이전 직접 영웅 추격만 해제한다. B가 사거리 안에 있으면 실제 기본 공격이 B를 향하고, 사거리 밖이면 새 추적 이동이 생기지 않는 것을 검사한다. 동일 대상 재고정과 방향·클릭·공격 이동 보존도 검사한다.
- 지도 가장자리의 원거리 AI 후퇴 목적지가 1600을 넘어 저장 복원을 실패시킬 수 있었다. 경로 목적지를 플레이 가능 범위로 제한하고, 실제 경계 후퇴 후 저장·복원을 검사한다. 저장 데이터 검증을 느슨하게 만들지 않았다.
- `app-controls`는 실제 게임·입력·저장·앱 모듈을 함께 실행하며 DOM, 프레임 스케줄러, 그리기만 대체한다. 이동과 조준의 서로 다른 포인터, blur·일시정지·resize·pagehide·사망 시 취소와 저장 입력 0을 검증한다. 실제 터치 기기나 브라우저 레이아웃 검사를 대신하지 않는다.

### 2. v4 저장 생명주기 코드 검토

`app.js`의 reset/present/continue/persist/modal/end/visibility/pagehide 경로를 별도로 읽어 검토했다. Continue는 일시정지로 복원한 뒤 계속하기에서 재개하고, 저장하고 나가기는 저장에 성공할 때만 준비 화면으로 이동한다. 새 경기의 최초 상태를 즉시 저장하고, 종료된 경기는 자동 저장하지 않는다. 경기가 끝나면 진행 슬롯을 제거하고 완료 기록을 생성하며, 삭제 실패도 화면 문구에 반영한다. 이는 코드 검토 결과이며 실제 브라우저 입력 검증과 구분한다.

### 4. v4 최종 단일 HTML과 전달 파일

`node scripts/build-offline.cjs`로 만든 최종 [nexus-front-offline.html](dist/nexus-front-offline.html)은 **394,435바이트**다. 파일 자체에서 **인라인 스크립트 8개**, 외부 JavaScript 참조 **0개**, 외부 CSS 참조 **0개**를 확인했다. 원본 JavaScript 7개와 단일 HTML의 인라인 스크립트 8개를 모두 Node VM으로 구문 분석하여 통과했다. 구성은 `navigation → game → renderer → history → checkpoint → coach → app`의 일곱 게임 모듈과 다운로드 보조 스크립트다.

최종 단일 HTML을 브라우저에서 HTTP로 직접 열어 다음 동작을 확인했다.

- 키라를 선택하면 기본 추천 폭풍 활 **550G**, 예상 잔액 **50G**가 표시됐다.
- 출전 장비를 **장비 없이 시작**으로 바꾸고 실제 경기를 시작하자 **600G**를 보유했다.
- Q 시전 후 마나는 **350/380**, 길잡이는 스킬 사용을 반영해 **1/6**으로 표시됐다.
- 항복 → 결과 저장 완료 흐름을 수행했으며 앱 오류는 관측하지 않았다.

**다운로드 버튼을 통한 파일 수신 완료는 이번에 확인하지 못했다.** 일반 버튼 클릭 후 다운로드 이벤트 대기와 별도 다운로드 대기가 각각 시간 초과로 끝났다. 따라서 최종 파일의 생성·원본 검사·HTTP를 통한 실제 실행은 검증했지만, 브라우저의 다운로드 완료 이벤트나 내려받은 파일 재검사를 성공으로 기록하지 않는다. 최종 파일의 `file://` 직접 실행도 이번에는 다시 검증하지 않았다. 소스나 스타일을 수정한 경우 단일 HTML과 소스 묶음을 다시 생성해야 한다.

#### 2. 기지 이동 결함과 후속 회귀

개발 중 v3의 기존 76개 검사를 통과한 뒤 실제 UI에서 기지 복귀 후 이동 정체를 발견했다. 해당 76개 결과는 마감 결과로 사용하지 않는다.

##### 실패 재현

`seed: 97`, 리아(`mage`), 표준 난이도에서 실제 사망 → 부활 → `commandMove(1080, 1080)` 순서로 재현했다. 모든 구조물·다른 개체와 기본 자동 공격 설정을 유지했다.

- 부활 위치는 약 `(173, 1435)`였다.
- 이동 명령은 성공했지만 30초 뒤 `(238.863, 1365.793)`에 멈춰 목적지까지 약 **888.363**이 남았다.
- 정상 귀환 후 같은 명령도 `(238.849, 1365.800)`에 멈췄다.
- 기지 포탑과 중앙 억제기의 겹친 충돌 영역에서 서로 다른 밀어내기·회피 처리가 진행을 막았다.

이를 `core-v3.test.cjs`에 두 회귀로 추가했다. 각각 세 영웅을 검사하므로 실제 부활·귀환 후 이동은 총 **6개 경로**를 다룬다. 목표의 12 이내에 30초 안으로 도달해야 통과한다.

##### 수정과 추가로 발견한 문제

살아 있는 구조물과 지형을 하나의 이동 충돌 집합으로 다루도록 바꾸고, 구조물 공격은 중심점 대신 공격 사거리 앞의 접근점을 사용하도록 수정했다. 이 변경 뒤 영웅의 6개 기지 이탈 경로는 통과했다.

이어 실행한 전체 회귀에서는 기존 웨이브 이동 검사 두 개가 실패했다. 첫 웨이브의 `minion-3/top`이 약 `(200.7, 1380.7)`에 멈췄고, 전체 실행 시간도 **246.53초**로 늘었다. 해당 실행은 **76개 통과·2개 실패**인 중간 결과이며 최종 성공으로 취급하지 않는다.

미니언의 연결된 소환 위치와 비교전 전방 목표를 보정하고, 하나의 원형 장애물에서 빠져나오는 경우에는 방사 방향 투영을 먼저 검사하도록 최적화했다. 후속 단기 검사에서 첫 웨이브 전원 기지 이탈과 세 영웅의 부활·귀환 경로가 통과했다.

남은 이동 검사는 5초 시점 미드 미니언이 실제 적 미니언과 교전 중인 상태를 비교전 이동으로 가정하고 있었다. 공격 표적·재사용 대기시간·HP 감소를 확인한 뒤, 양 팀 세 공격로의 웨이브 존재 검사는 유지하고 이동 소구간에서만 적과 이미 발사·예약된 공격을 제거했다. 아군 구조물과 유닛, 별도의 첫 웨이브 전원 기지 이탈 검사는 그대로 유지했다. 이 보정 뒤 자연 경기 항목을 제외한 관련 단기 검사 **53개가 모두 통과**했고, 이어 최종 전체 **78개가 모두 통과**했다. 앞선 76개 중간 통과 및 2개 실패 실행과 구분되는 마감 결과다.

#### 5. 렌더링 대역 검사와 이전 검사

##### v3 변경 분기 검사

Node의 Canvas 2D 대역과 Proxy를 이용한 통제 fixture 검사에서 **868회 Canvas 호출**의 숫자 인자가 유한함을 확인했다.

- 현재 보이는 지면에만 경고 원을 잘라 표시하고, 원의 중심이 안개 속이어도 보이는 위협 부분을 유지한다.
- 진행률 부채꼴, 예정 시각 도달 후 0.34초 타격 파동과 만료를 확인했다. 예정 시각 전에 취소된 경고에는 타격 파동이 없다.
- 플레이어를 겨눈 포탑 연결선과 최근 연속 공격 단계를 표시하고 숨김·보호 조건을 반영한다.
- `canLastHit`가 참인 적 미니언은 최대 HP 상태인 경우를 포함해 금색 체력바와 표식으로 표시한다.
- 드래곤·심연 거인의 전장·미니맵 아이콘과 색이 일치한다.
- 렌더링 전후 게임 상태가 바뀌지 않는다.

이 검사는 변경된 그리기 분기의 호출·상태 검사다. 실제 브라우저/GPU의 화질, 전체 경기의 프레임 성능 측정은 아니다.

##### 이전 v2에서 실시한 검사

다음은 이전 버전에서 실시한 추가 검사이며 이번 v3에서 같은 횟수로 다시 실행했다고 주장하지 않는다.

- 고정 난수로 생성한 500개 시작·목표 경로의 도달·선분 안전 검사. 그중 332개는 우회 경로였다.
- Canvas 대역의 21,540회 호출 유한성, 경로·지시·시야 처리 검사.
- 브라우저의 Shift+W 학습, 공격 이동·정지, 조합 차액·판매와 인벤토리 초점, 조이스틱 입력 확인.

기존 v2 자동 테스트 파일들은 현재 전체 회귀에도 포함된다. 이전 브라우저 수동 확인과 현재 자동 회귀는 서로 다른 검증 근거다.

#### 6. 오프라인 단일 HTML과 배포 파일

생성 명령은 `npm run build:offline`이며 출력은 [dist/nexus-front-offline.html](dist/nexus-front-offline.html)이다.

v3 단일 HTML에서 경기 시작·Q 시전, 일시정지 중 항복, 저장 알림, 보고서 표시와 키보드 초점을 실제로 확인했다. 구조물 이동 보정이 포함된 최적화 전 파일은 내장 다운로드 완료와 반환 파일까지 검사하여 **인라인 스크립트 6개 구문 분석 통과, 외부 script/CSS 참조 0개**를 확인했다. 구성은 `navigation.js`, `game.js`, `history.js`, `renderer.js`, `app.js`와 다운로드 보조 스크립트다.

후속 경로 성능·미니언 이동 보정을 포함한 최신 단일 HTML은 **339,207바이트**로 재생성됐고, 인라인 스크립트 6개 구문 분석과 외부 script/CSS 참조 0개 검사를 통과했다. 이 마지막 파일을 브라우저에서 다시 여는 시도는 URL 보안 정책의 프로토콜·탭 권한 거절로 차단되어 우회하지 않았다. 따라서 **최신 최적화 파일의 브라우저 재플레이·재다운로드를 완료한 것으로 기록하지 않는다.** UI 코드는 앞서 실제 검증한 버전과 같으며 최신 엔진은 최종 Node 회귀와 인라인 구문 검사로 검증한다.

소스가 변경되면 단일 HTML과 소스 묶음을 다시 생성해야 한다. 파일 크기는 해당 생성물의 관측값이며 이후 재빌드의 고정 기준이 아니다.

#### 7. 범위와 한계

- 실제 모바일 기기의 멀티터치, 장시간 배터리·발열, 모든 브라우저 조합의 성능은 전수 검증하지 않았다.
- 세 시드의 무조작 자연 경기와 특정 수동 조작 사례를 모든 영웅·지시·아이템 빌드의 밸런스 보장으로 해석하지 않는다.
- 로컬 기록 저장소 접근이 차단되거나 쓰기가 실패하면 모듈은 표시 가능한 기록과 `persisted: false`를 반환한다. 이 경우 브라우저 재시작 뒤 영구 보존을 보장하지 않는다.
- 온라인 대전·서버 동기화는 구현 범위에 없으며 관련 검증도 없다.
