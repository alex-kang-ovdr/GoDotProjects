# v9 게임플레이 고도화 · 분석 데이터 반영 기록

작업 기준일: **2026-11-18 KST**. 이 문서는 v8의 복원 챔피언·스킬·아이템을 전제로, 분석 문서의 관측 정보 경계와 성장·구매·복귀 흐름을 실행 코드에 연결한 이유와 계약을 설명한다. 최종 수행한 검사 수와 브라우저 결과는 [QA.md](../QA.md)에 기록한다.

## 1. 원본 정적 데이터와 프로젝트 규칙

원본 정적 데이터 기준은 계속 **Data Dragon 16.22.1**이다. 도감의 챔피언 173명·최상위 QWER 692개·아이템 863개와 실제 플레이 가능한 복원 6명·24스킬·25아이템의 구분을 유지한다. 기존 영웅 3명과 기존 아이템도 유지한다. 상세 정적 필드와 지원 범위는 [복원 로스터](RESTORED_ROSTER.md), [데이터 계약](restored-data-contract.md)에 있다.

소스 ZIP의 [고정 사실 입력](../data/restored-input.json)에는 원본 URL·버전·실행 정의를, [자산 목록](../data/restored-assets.json)에는 공식 이미지 URL과 해시를 포함한다. 별도 분석 패키지의 파일명은 아래에서 작업의 계보를 설명하는 식별자로 사용하며, 이번 구현에 적용한 규칙·판단 근거·검증 경계는 이 문서에 요약했다. 따라서 소스 패키지만으로 현재 코드와 분석 대응을 확인할 수 있다.

이번에 연결하는 분석의 핵심은 개별 숫자를 더 많이 복사하는 것보다 **실제 상태 → 팀 관측 → 화면·조준·AI·길잡이**의 소비 경계를 맞추는 것이다. 원작 데이터 패키지의 `docs/10_prototype_gap_and_roadmap.md`는 이를 P4 관측·지형 단계로, 구매를 거친 반복 성장 흐름을 P3 경기 생태 단계로 구분했다.

| 근거 | 이번 실행 계약 | 확인할 코드 |
|---|---|---|
| 분석 P4: 팀 관측 뷰를 출력·입력·AI가 함께 사용 | 숨은 실제 구조물 상태로 안내 목표를 바꾸거나 진행 미션을 완료하지 않음 | `game.js` 관측 API, `coach.js` |
| 사용자 요청: 벽·언덕 시야 차단 | 이동 가능 여부와 시야 통과 여부를 별도 판정 | `vision.js`, `game.js` |
| 사용자 요청: 보이지 않는 공격 위치의 일시 공개 | 공격 당시 위치와 만료 시각을 사용하며 이동한 공격자를 자동 추적하지 않음 | `vision.js`, `game.js` |
| 사용자 요청: 고정 건물 마지막 관측 상태 | 복사한 HP·생존·보호 상태를 기억하고 재관측 때 갱신 | 구조물 관측 API, `renderer.js`, `app.js`, `coach.js` |
| 분석 P3: 성장→구매→복귀 반복 | 체력이 충분한 AI도 마나 부족 또는 유효한 장비 구매 기회에 안전 귀환 | `tactical-ai.js`, `game.js` |
| 분석 경제: 조합은 재료 개수와 슬롯을 함께 계산 | AI 구매 귀환 견적도 중복 재료·소비 슬롯·고유 그룹을 검사 | `tactical-ai.js`의 `plannedPurchase()` |
| 분석 정보 경계: 정글 홈 좌표와 생존 상태는 다른 정보 | 모르는 목표물은 정찰 안내, 현재 확인한 생존 목표물은 공략 안내 | 목표물 관측 API, `coach.js`, `app.js` |

**언덕 높이에 따른 가시성과 맵 배율·배속은 사용자가 요청한 프로젝트 확장 규칙**이다. 이를 원작 LoL에 동일하게 존재하는 규칙으로 표시하지 않는다. 공개된 원작 정적 데이터와 재구성한 피해식·이동·시야·AI 튜닝은 별개의 근거 수준이다.

## 2. 길잡이의 관측 데이터 소비

### 구조물 안내

`NexusCoach.read(game, previousJourney)`는 `game.getStructureObservations(player.team)`의 복사 스냅샷을 사용한다. 구조물별 현재 HP·생존·보호 상태를 직접 읽어 먼 곳의 목표를 선택하지 않는다.

- **미탐색 건물:** 관측 목록에 없으므로 특정 건물의 현재 상태를 안내하지 않는다. 미니언과 전진하여 시야를 확인하도록 안내한다.
- **관측 중인 건물:** 해당 시점의 살아 있음·보호 상태를 사용해 공성 대상을 안내한다.
- **기억 속 건물:** 마지막 관측값을 사용하고 “마지막 관측 정보”라는 설명을 붙인다. 실제 상태가 변해도 안내는 유지한다.
- **관측된 파괴:** 첫 구조물 이정표를 완료할 수 있다. 이미 완료한 이정표는 시야를 잃거나 억제기가 재생성되어도 취소하지 않는다.

길잡이 저장 형식은 `journey.version = 1`을 유지한다. 기존 `origin`과 `completed`를 정규화하며 호출자의 이전 기록을 수정하지 않는다. 새 관측 정책을 적용한다고 과거에 완료한 정상 진행을 초기화하지 않는다.

### 정글 목표 안내

목표물의 이름·종류·홈 위치는 공개된 맵 정의다. 살아 있는지, 최근 처치되었는지, 어느 시각에 재생성할지는 별도 관측 데이터다. 길잡이는 `game.getObjectiveObservation(id, team)`을 통해 이 둘을 구분한다.

| 관측 상태 | 길잡이 동작 |
|---|---|
| 현재 시야에서 살아 있음 확인 | 동료가 합류할 수 있는 조건이면 공략 준비 안내 |
| 처음부터 미확인 | 생존 여부를 단정하지 않고 구역 정찰 안내 |
| 전에 살아 있었지만 현재 시야 없음 | 정찰로 현재 상태를 다시 확인하도록 안내 |
| 마지막 관측에서 사망 확인 | 관측한 대기 시간까지 제외하고, 그 시간이 지나면 생존을 단정하지 않고 정찰 후보로 복귀 |

적의 숨은 생존 상태만 바꾼 두 게임에서 관측 스냅샷이 같으면 길잡이 결과도 같아야 한다. 이 불변식을 별도 검사한다. 보이는 둥지가 비어 있다는 사실만으로는 숨은 곳으로 유인된 몬스터의 죽음·재생성 시각을 알 수 없으므로 `presence:'absent',known:false`를 사용한다. 사망 타이머는 처치 당시 관측한 팀·확보한 팀에 제공하고 공개된 최초 등장 일정은 별도로 사용할 수 있다.

### 자원·상점 안내

마나가 15% 미만이고 가까운 시야에 적이 없으면 귀환을 제안하고, 기지 안에서는 마나 회복을 기다리도록 안내한다. 리 신의 기력과 가렌의 무자원 상태에는 마나 부족 안내를 적용하지 않는다. 이는 이 프로젝트의 접근성·전투 안내 기준이다.

마법사의 추천 빌드에 기본 장화가 들어 있더라도 이미 상위 장화를 가지고 있으면 그 하위 목표는 충족한 것으로 처리한다. 고유 그룹 제한 때문에 구매할 수 없는 기본 장화를 계속 추천해 귀환 안내가 반복되는 문제를 막는다. 실제 구매 가격과 가능 여부는 여전히 엔진의 거래 API를 따른다.

## 3. 전술 AI의 안전 귀환 정책

`tactical-ai.js`는 전투 엔진에 의존하지 않는 순수 정책 모듈이다. `getBuild(hero)`는 v8에서 사용하던 영웅 유형별 구매 순서를 보존한다. `plannedPurchase(hero, definitions)`는 기지에 도착했을 때 가능한 다음 거래를 계산하고, `getRetreatReason(game, hero, definitions)`는 마나 또는 구매 목적의 귀환 필요성을 반환한다. 함수를 호출하는 것만으로 자원·좌표·난수·인벤토리를 바꾸지 않는다.

### 공통 전제

새 귀환 요청은 진행 중이고 일시정지되지 않은 경기의 살아 있는 AI 영웅에만 적용한다. 다음 조건을 만족해야 한다.

1. 게임 시각이 45초 이상이고, 자신의 기지에서 월드 200단위보다 멀리 있다.
2. 이미 후퇴 중이거나 귀환·공격 준비·기절 상태가 아니다.
3. 마지막 피격 이후 게임 시간 5초 이상 지났다.
4. 시야에 보이는 공격 위협이 위험 반경 안에 없다. 기본 반경은 460이며 적 사거리가 더 길면 그 사거리·영웅 반경·40 여유값을 사용한다.

적 좌표와 전투 상태는 `isVisible()`이 참인 후보에 대해서만 조회한다. 시야 밖 적의 이동만으로 귀환 판단이 달라지지 않는다. 시야 밖 공격자가 나중에 실제로 공격하면 기존 피격 로직이 귀환을 취소한다. “보이는 위협 없음”은 보이지 않는 적까지 없다는 보장이 아니다.

### 마나와 구매 목적의 구분

| 목적 | 추가 조건 | 처리 |
|---|---|---|
| 마나 재정비 | 실제 마나 사용자이며 현재 마나가 최대치의 15% 미만 | 기존 후퇴·귀환·기지 회복 흐름을 사용 |
| 장비 구매 | 현재 구매 순서의 다음 아이템이 재료·슬롯·고유 그룹·골드 조건을 만족 | 안전한 자리에서 귀환한 뒤 엔진이 거래를 재검증 |

리 신의 기력은 자연 회복과 기본 공격 사이의 운용 자원이다. 기력이 0이라는 이유만으로 구매·마나 귀환을 시작하지 않는다. 가렌은 최대 마나가 0이므로 나눗셈 없이 자원 조건을 생략한다.

구매를 위해 라인을 너무 자주 비우지 않도록 보유 골드 문턱을 게임 단계별로 둔다.

| 게임 시각 | 구매 귀환의 최소 보유 골드 |
|---|---:|
| 45초 이상, 120초 미만 | 450G |
| 120초 이상, 300초 미만 | 650G |
| 300초 이상 | 850G |

이 문턱과 안전 반경·대기 시간은 **Nexus Front의 짧은 경기용 AI 튜닝**이다. 공식 LoL 봇의 행동 테이블을 복원한 수치가 아니다. 시간은 게임 시각이므로 0.75배 등의 속도 선택은 시뮬레이션 시간을 통해 한 번만 반영된다. 맵 배율은 기지 좌표를 선택할 때 사용하고 구매 반경·스킬 사거리에 다시 곱하지 않는다.

### 거래 견적의 불변 조건

- 같은 재료가 두 번 필요하면 서로 다른 인벤토리 슬롯 두 개를 소비해야 한다.
- 인벤토리가 6칸이어도 재료를 소비하는 조합은 허용할 수 있다.
- 기존 고유 아이템과 충돌하는 구매를 위해 귀환하지 않는다.
- 구매 계획이 끝났거나 알 수 없는 영웅의 계획이면 임의의 다른 빌드를 적용하지 않는다.
- 귀환 전에 계산한 견적은 거래 자체가 아니다. 기지 도착 후 기존 엔진 `_buy()`가 비용·슬롯·고유 그룹을 다시 확인한다.

## 4. 부분 복원 수치를 무리하게 적용하지 않은 범위

기존 분석의 `rules_verified_parameters.csv`는 공식 패치에서 확인한 변경값과 현행 전체 인증을 구분한다. 역할 퀘스트의 전체 진행·보상, 미니언 경험치 공유식, 포탑 방패의 모든 보상·불워크 구간, 정글 목표물의 모든 시간표는 정적 데이터만으로 완결되지 않는다.

따라서 이 버전은 해당 분석의 미확정 칸을 기존 게임 상수로 채워 “원작 복원 완료”로 표시하지 않는다. 예를 들어 분석에 있는 근접 미니언 430HP와 90초당 35 증가, 미니언끼리의 현재 HP 비례 추가 피해는 특정 패치 근거를 가진 개별 값이다. 이 숫자만 짧은 독자 경기의 전체 웨이브에 적용하면 구조물 공성 속도·골드·성장까지 바뀌므로 별도 규칙 프로필과 검증이 필요하다.

정적 복원 6명·24스킬·25아이템은 계속 실행 범위이며, 지도·웨이브·기본 경제·정글 목표물의 나머지 부분은 문서화한 프로젝트 규칙을 사용한다.

## 5. 저장·이어하기 호환

브라우저 저장 슬롯의 바깥 스키마는 계속 `version = 1`이고, 새 경기 엔진 스냅샷은 기존 영웅·복원 챔피언 모두 `engineVersion = 9`를 사용한다. 챔피언 프로필 자체는 기존 영웅의 `nexus-v7`과 복원 챔피언의 `lol16.22`로 구분한다. 저장 형식 버전이 바뀌었다고 기존 영웅을 원작 챔피언으로 교체하지 않는다.

`checkpoint.js`는 v4·v5·v6·v7·v8·v9를 받아 엔진 검증을 거친다. 실제 v4/v5/v6 저장 자료는 수정하지 않고 계속 호환 검사에 사용한다. v7 이후 저장에서는 매치의 맵 배율로 길잡이 위치 범위를 계산하므로, 2배 맵에서 x=3100과 같은 원점도 이어하기에 유지된다. 이전 2배 속도 값은 현재 허용된 최고 속도인 1.5배로 정규화한다.

v9에는 탐색 영역과 팀 관측 기억이 포함된다. 예전 저장에 기록되지 않은 과거 탐색·관측 결과는 복원 시 만들어내지 않고, 로드한 경기의 현재 시야에서 시작한다. 기존 영웅의 장비·스킬과 복원 챔피언의 재시전·충전·탄약 상태는 해당 프로필로 복원한다. 이어하기 활성화 직후에는 일시정지 상태이며 사용자가 재개하기 전에는 타이머가 진행되지 않는다.

저장은 새 스냅샷을 분리 직렬화하고 실제로 복원할 수 있는지 먼저 검사한 뒤, 하나의 저장소 쓰기로 이전 슬롯을 교체한다. 데이터 버전 불일치·알 수 없는 프로필·손상된 엔진 상태 또는 저장 실패가 이전 정상 슬롯을 먼저 삭제하지 않는다. 기존 2MiB 저장 크기 제한도 유지한다.

## 6. 관련 검증

[v9-coach-tactics.test.cjs](../tests/v9-coach-tactics.test.cjs)는 관측 변경의 비노출, 기존 길잡이 진행 보존, 목표 정찰/공략 구분, 마나·기력·무자원 예외, 구매 견적과 안전 귀환 판단을 검사한다. 엔진의 전체 시야·저장·렌더링 검증은 각각의 v9 테스트 및 최종 [QA 기록](../QA.md)을 따른다.

해당 신규 검사 **16개**는 정책 함수뿐 아니라 실제 엔진의 구매 귀환 완료, 피격에 의한 취소, 마나 회복을 기다린 후 라인 복귀, 귀환 중 저장 후 재개한 전체 상태의 일치, 관측한 목표 재생성 대기 종료 후 정찰 복귀를 포함한다. [기존 길잡이 검사](../tests/coach.test.cjs)의 구조물·목표물 사례는 실제 관측 조건을 갖추도록 설정을 보완했고, [복원 저장 검사](../tests/restored-persistence.test.cjs)는 현재 출력 버전 v9와 기존 입력 자료의 호환을 구분한다.

단순히 값이 존재하는지 보는 검사보다, **숨은 실제 상태만 바꾸어도 결과가 같아야 하는 경우**, **저장 후 같은 입력으로 재개하면 결과가 같아야 하는 경우**, **거래 전제 조건이 변하면 최종 거래가 다시 거부되어야 하는 경우**를 중심으로 검증한다.
