# v9 전투 적용 · 기본 공격 검산과 시전자별 표식

기준일: 2026-11-18. 대상: `Nexus Front`의 `lol16.22` 복원 프로필. 정적 데이터 빌드는 **Data Dragon 16.22.1**이다.

이번 변경은 복원 데이터의 전투 효과가 화면 판단과 저장 상태까지 일관되게 이어지도록 한다. v8의 여섯 챔피언·24개 QWER·25개 아이템 범위를 유지하며 피해 수치를 새로 추정하지 않는다. 세부 수치와 원작 재현 한계는 [복원 로스터](RESTORED_ROSTER.md)를 따른다.

## 1. 분석에서 구현으로 연결한 계약

기존 분석의 전투 문서는 피해 성분별 저항 계산, 원 피해·보호막·체력 감소의 분리, 시전자/시전별 상태 소유, 읽기 전용 검산과 실제 판정의 구분을 제안했다. v8에서는 실제 공격에 복원 효과가 적용되어도 막타 표시가 기본 AD만 읽었고, 리 신 Q/E의 표식 소유자가 피해 대상의 단일 필드에 저장되어 서로 덮어쓸 수 있었다.

| 문제 | v9 반영 |
|---|---|
| 가렌 Q 강화·애쉬 서리/Q·진 네 번째 탄환이 막타 표시에서 빠짐 | 실제 공격과 공유하는 순수 계산 함수로 현재 공격의 최소·최대 피해 예측 |
| 럭스 표식의 마법 피해가 물리 기본 공격과 별개인데 표시에서 빠짐 | 물리/마법 성분을 분리한 뒤 각각 방어력/마법 저항력 적용 |
| 확률 치명타를 확정 처치처럼 표시할 위험 | 확정 최소와 가능한 최대를 별도 반환, 확정 최소만 막타 표시의 근거로 사용 |
| 미리보기 호출이 RNG나 탄약을 소비할 위험 | 계산과 발사 시 상태 변경을 분리, 반복 조회 전후 저장 상태 동일성 검사 |
| 다른 리 신의 E가 기존 Q 재시전 표식 소유자를 덮어씀 | Q는 시전자 자신의 재시전 상태를 권위 표식으로 사용 |
| 여러 리 신 E가 같은 대상을 때리면 먼저 시전한 E의 재시전 대상이 사라짐 | 각 E 시전의 적중 대상 ID 목록을 해당 시전자의 재시전 상태에 보존 |
| 이동한 공격자의 현재 위치가 뒤늦은 피해로 노출됨 | 투사체·지연 효과의 원점을 보존하여 시야 계층에 전달 |

## 2. 기본 공격 예측 API

사용자 화면은 다음 API를 사용한다.

```js
const prediction = game.getBasicAttackPreview(targetOrId, hero);
```

`hero`를 생략하면 플레이어다. 엔진의 공개 래퍼는 관측 가능한 적만 허용한다. 보이지 않는 적의 HP·보호막·표식·방어력으로 피해를 계산해 UI에 노출하지 않는다. 적법한 대상이 없으면 `null`을 반환한다.

복원 전투 모듈의 내부 계산 함수는 다음과 같다.

```js
NexusRestoredGameplay.previewBasicAttack(game, hero, target, baseDamage)
```

| 필드 | 의미 |
|---|---|
| `sourceId`, `targetId`, `snapshotAt` | 어느 공격자·대상의 어느 게임 시각 상태를 계산했는지 |
| `rawMin`, `rawMax` | 현재 공격의 치명타 결과 범위를 포함한 방어 보정 전 잠재 피해 |
| `mitigatedMin`, `mitigatedMax` | 성분별 방어 보정 후 잠재 피해. 초과 피해를 포함할 수 있음 |
| `shieldDamageMin`, `shieldDamageMax` | 현재 보호막에서 예상되는 감소량 |
| `hpDamageMin`, `hpDamageMax` | 현재 HP를 상한으로 한 예상 체력 감소량 |
| `guaranteedKill` | 최소 피해로 현재 HP와 보호막을 소진할 수 있는지 |
| `possibleKill` | 최대 피해라면 현재 HP와 보호막을 소진할 수 있는지 |
| `critical` | `none`, `possible`, `guaranteed` 중 하나 |
| `components` | 물리·마법 성분의 이름, 원 피해와 방어 보정 후 최소·최대 |

**판정 기준은 현재 상태의 공격 한 번이다.** 이후 대상 이동, 다른 유닛의 공격, 보호막 만료, 도착 전 표식 만료, 추가 회복, 재시전 입력까지 예측하는 미래 시뮬레이션은 아니다. 공격 가능 거리·쿨다운·행동 불가 여부는 별도 UI 조건이다. 체력이 낮아 물리 타격만으로 사망하면 실제 럭스 추가 표식 피해는 발생하지 않지만, 예상 HP 감소량은 대상의 현재 HP에서 잘리므로 표시가 초과하지 않는다.

확률 치명타는 조회 중 난수를 뽑지 않는다. 예를 들어 다른 보정이 없는 100 피해 공격, 치명타 확률 50%, 기본 치명타 배수 2, 적 HP 150이라면 최소 100·최대 200이고 `guaranteedKill=false`, `possibleKill=true`다. 이 예시의 100·50%·150은 검산을 위한 입력이며 챔피언 밸런스 값이 아니다.

현재 프로토타입의 일반 치명타 배수는 v8부터 이미 **2.0**이며 이번에 1.75에서 변경한 것이 아니다. 이는 분석 원장이 기록한 [공식 26.1 패치의 일반 치명타 기준](https://www.leagueoflegends.com/en-us/news/game-updates/patch-26-1-notes/)과 같은 기본값이다. 애쉬와 진의 예외는 기존 v8 재구성 계산을 유지한다. 이 일치가 모든 원작 치명타 예외를 검증했다는 뜻은 아니다.

### 계산과 상태 변경의 경계

- `attackPayload`: 공격 발사 시 확정되는 피해와 강화 여부를 순수 계산한다.
- `impactDamage`: 진의 네 번째 탄환 등 적중 시 대상 상태에 의존하는 기존 성분을 계산한다.
- `luxMarkDamage`: 현재 시전자에게 유효한 럭스 표식의 기존 피해를 계산한다.
- `attack`: 실제 치명타 난수 판정, 진 탄약 소비, 가렌 강화 소비, 리 신 질풍 소비·기력 회복을 수행한다.
- `attackHit`: 실제 보호막·체력 차감, 흡혈, 표식 소비와 후속 효과를 적용한다.

예측은 앞의 순수 계산만 읽는다. 아이템으로 증가한 AD·AP·치명타와 실제 대상의 방어력이 같은 경로를 통과한다. 피해 종류별 저항·드래곤 강화·난이도 보정 등은 공통 `game._damageValue`를 그대로 사용한다.

## 3. 리 신 Q/E 표식 소유

Q 재시전은 `hero.restored.recasts.q`의 `targetId`와 만료 시각을 사용한다. 대상이 살아 있고 적이며 자신의 재시전 창이 유효하면, 다른 리 신의 표식 필드 변경으로 취소되지 않는다. 한 리 신이 Q2를 사용해도 다른 리 신의 남아 있는 Q 재시전은 보존된다.

E 첫 시전은 살아남은 적중 대상 ID를 `hero.restored.recasts.e.targetIds`에 저장한다. E 재시전은 이 목록에 있고, 살아 있으며, 적이고, 현재 재시전 거리 안에 있는 대상에게만 둔화를 적용한다. E 첫 시전 뒤 새로 접근한 적은 목록에 들어오지 않는다. 서로 다른 리 신은 서로 다른 목록을 가진다.

기존 `leeMarkedBy`, `leeMarkUntil`, `leeEMarkUntil` 필드는 이전 저장의 해석과 호환을 위해 남아 있지만, 새 Q/E 판정의 공통 소유권 필드로 사용하지 않는다.

## 4. v8 저장의 이전과 검증

신규 v9는 리 신 E 재시전에 `targetIds`를 요구한다. 목록은 배열이어야 하며 512개 이하, 중복 없는 유효 문자열 ID만 허용한다. 다른 챔피언·다른 슬롯에 이 필드를 끼워 넣는 저장도 거절한다.

v8 저장에는 해당 배열이 없으므로, `migrateState(game, oldEngineVersion)`가 당시 저장된 `leeMarkedBy`·`leeEMarkUntil`을 읽어 아직 확인 가능한 E 적중 목록을 복구한다. **v8에서 이미 다른 리 신에게 덮어써져 소실된 정보는 추정 복구하지 않는다.** Q는 시전자 자신의 재시전 대상이 이미 저장되어 있으므로 이를 보존한다. 원본 체크포인트 객체를 직접 수정하지 않는다.

실제 이전 저장 fixture는 다음 소스에서 만들었다.

- 파일: `tests/fixtures/v8-combat-checkpoint.json`
- 원본 소스 커밋: `b34e44cfacee5cac08261eff09c4db58bf8bc3a7`
- 생성 방법: 그 커밋의 `navigation.js`, `restored-data.js`, `restored-gameplay.js`, `game.js`를 Git에서 읽어 메모리 VM에서 실행하고, 실제 v8 `exportState()` 결과를 저장.
- 내용: 70개 개체, 리 신 Q/E 재시전, 럭스 구역과 진 함정. v9 저장에서 필드를 삭제해 만든 모의 이전 저장이 아니다.

## 5. 공격 원점과 시야 연결

피해 처리의 다섯 번째 인수인 `{ x, y }`로 공격 원점을 전달한다. 이 좌표는 피해가 발생한 뒤 공격자의 현재 위치를 추적하는 용도가 아니다.

| 공격 종류 | 기록·전달하는 원점 |
|---|---|
| 발사체 스킬 | 발사 당시 `originX`, `originY` |
| 기본 공격 투사체 | 엔진이 보존한 발사 원점, `attackHit` 여섯 번째 인수로 전달 |
| 럭스 지연 광선 | 광선을 시전한 위치 |
| 진 유탄 연쇄 | 최초 투척 위치 |
| 럭스 구역·진 함정 | 설치된 구역·함정 위치 |
| 아리 여우불·즉시 근접 효과 | 해당 타격을 발사/실행하는 순간의 위치 |

지속 효과도 `originX`, `originY`를 저장한다. v9에서는 맵 경계 안의 유한 좌표가 필수이며, v8의 생략된 원점은 구역·함정이면 설치 위치, 나머지는 로드 당시 소스 위치로 명시적으로 이전한다. 과거 저장에 없는 정확한 발사 위치를 복원했다고 주장하지 않는다.

## 6. 검사 범위

`tests/v9-combat.test.cjs`는 다음 계약을 검사한다.

1. 여섯 챔피언의 예측 반복 조회가 RNG·탄약·표식·버프·자원·전체 저장을 바꾸지 않음.
2. 복원 효과를 포함한 예상 체력·보호막 감소와 실제 공격 결과 일치.
3. 확률/확정 치명타와 애쉬의 결정적 서리 피해 구분.
4. 럭스 물리·마법 피해의 개별 저항 및 공통 보호막 처리.
5. 강화 공격의 막타 판정과 비관측 적의 공개 예측 차단.
6. 두 리 신의 Q/E 소유권 분리, E 첫 시전에 맞지 않은 적 제외.
7. 실제 v8 저장 이전과 신규 상태 보존, 손상된 목록·원점 거절.
8. 공격자 이동 이후에도 투사체·지연 광선·설치 함정의 원점 보존.

실행 결과와 전체 회귀 수는 최종 [QA 문서](../QA.md)에 기록한다. 이번 작업은 원작 피해식·진 공격 속도 전환·애쉬 치명타 전체 규칙·모든 CC 예외의 정밀 복원을 추가한 작업이 아니다.
