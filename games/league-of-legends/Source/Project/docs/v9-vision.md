## 1. 분석에서 실행 규칙으로 옮긴 범위

기존 `FogOfWar_Unreal_Design_KR.md`와 원작 분석 `05_vision_information_terrain.md`의 사용자 확장 요구를 웹 실행판에 옮겼다. 다음 규칙은 **이 프로젝트의 커스텀 규칙**이다. LoL의 원본 지형 데이터나 현재 서버의 정확한 내부 시야 판정을 복원했다는 뜻이 아니다.

| 요구 | v9 실행 결과 |
|---|---|
| 벽이 시야를 차단 | 기존 정글 장애물 12개를 절대 시야 차단체로 사용한다. |
| 낮은 곳에서 높은 곳의 적을 볼 수 없음 | 정글에 통과 가능한 고지대 4개를 배치하고 높이 단계를 검사한다. |
| 높은 곳에서 낮은 곳 관측 | 시야 반경과 벽 조건을 충족하면 가능하다. |
| 고지대·시야 밖에서 공격받은 위치 단서 | 실제 피해가 발생하면 피격 팀에 공격 당시 좌표를 1.5초 표시한다. |
| 이전 탐색 고정 건물 유지 | 관측한 건물의 HP·최대 HP·생존·보호 상태를 스냅샷으로 유지한다. |
| 시야 밖 건물 변경은 미갱신 | 숨은 피해·회복·파괴·재건축은 기억값을 바꾸지 않는다. 다시 관측하면 갱신한다. |
| 저장 후 탐색·기억 유지 | 두 팀의 탐색 비트, 건물·중립 목표 관측, 임시 공격 단서를 v9 저장에 포함한다. |

아군 건물은 팀 소유 정보로 항상 최신 상태를 안다. 적 건물은 최초 탐색 전에는 상태나 기억 프록시를 제공하지 않는다. 지도 지형은 안개 아래 윤곽이 남고, 적 유닛·건물 표시는 별도 개체 판정을 거친다.

## 2. 지형과 LOS

### 2.1 이동 충돌과 시야 차단을 분리

지도 인스턴스는 다음 데이터를 별도로 가진다.

```js
map.obstacles = [ /* 기존 원형 정글 벽 */ ];
map.highGrounds = [
  { id: 'height-west',  x: 545,  y: 665,  r: 112, tier: 1 },
  { id: 'height-east',  x: 1055, y: 935,  r: 112, tier: 1 },
  { id: 'height-north', x: 920,  y: 370,  r: 105, tier: 1 },
  { id: 'height-south', x: 680,  y: 1230, r: 105, tier: 1 }
];
```

표의 좌표는 1배 지도다. 1.5배·2배 지도에서는 위치와 반경을 지도 배율에 따라 바꾼다. 영웅·와드 등의 시야 반경은 지도와 함께 늘어나지 않는다.

고지대는 이동 NavMesh의 벽으로 추가하지 않는다. 플레이어가 걸어 올라갈 수 있고, 현재 월드 위치가 어느 높이 영역에 속하는지에 따라 시야가 바뀐다. 기존 벽은 이동도 차단하고 시야도 차단하지만 두 판정이 같은 함수를 공유하지는 않는다.

### 2.2 구현한 높이 규칙

`groundHeightAt(x,y)`는 지점이 포함된 고지대 중 가장 높은 단계를 반환한다. 일반 지면은 0, 현재 고지대는 1이다.

`hasLineOfSight(ax,ay,bx,by)`의 순서는 다음과 같다.

1. 대상 지점의 높이 단계가 관측자보다 높으면 차단한다.
2. 관측자와 대상의 선분이 절대 차단 벽 내부를 통과하면 차단한다.
3. 관측자보다 높은 고지대 내부를 선분이 통과하면 차단한다.
4. 나머지는 통과시킨다.

따라서 낮은 지면의 두 지점을 잇는 선이 언덕을 가로지르는 경우도 막힌다. 높은 곳의 관측자는 같은 높이의 고지대 너머나 낮은 지면을 볼 수 있지만 절대 벽을 투시하지 못한다.

현재 지도는 원형 장애물을 사용하므로 선분과 원의 교차 구간을 해석적으로 계산한다. 수많은 물리 Line Trace를 호출하거나 매 대상마다 NavMesh 경로를 구하지 않는다. 수학적으로 한 점만 접하는 접선은 차단하지 않고 원 내부를 실제로 통과한 경우 차단한다. 이는 현재 단순 지형에 맞춘 구현이며 임의의 3D 메시·곡면의 광학적 가시성 계산은 아니다.

### 2.3 일반 시야원과 정찰 능력

| 시야원 | 반경 · 월드 단위 | 지형 검사 |
|---|---:|---|
| 아군 기지 | 450 | 벽·높이 적용 |
| 영웅 | 420 | 벽·높이 적용 |
| 포탑 | 420 | 벽·높이 적용 |
| 넥서스 | 450 | 벽·높이 적용 |
| 억제기 | 270 | 벽·높이 적용 |
| 와드 | 480 | 벽·높이 적용 |
| 미니언 | 250 | 벽·높이 적용 |
| 애쉬의 정찰 효과 | 해당 효과 데이터의 반경 | 명시적 비행 정찰 예외 |

일반 와드는 높은 곳과 벽을 투시하지 않는다. 기존 애쉬 E의 비행 정찰은 능력 정의에 따른 별도 시야원으로 유지하고 수풀의 대상을 공개한다.

수풀 속 적 영웅을 볼 때는 **동일한 하나의 시야원**이 반경, 벽·높이 LOS, 수풀 공개 조건을 모두 만족해야 한다. 벽 반대편의 아군이 수풀 내부에 있다는 이유만으로 다른 곳의 시야와 합성하여 대상을 공개하지 않는다. 기존 공격·능력의 `revealedUntil`은 일반 공간 시야 안에서 수풀 숨김을 해제하는 역할이며, 새 공격 원점 단서와 별개다.

## 3. 공격 당시 위치의 일시적 공개

### 3.1 발사 좌표를 보존

실제 기본 공격 발사와 일반·복원 스킬의 투사체에는 `originX`, `originY`를 기록한다. 지연 범위 공격과 지속 효과도 발동 방식에 맞는 원점을 보존한다.

| 공격 | 단서 원점 |
|---|---|
| 원거리 기본 공격 | 투사체를 실제로 발사한 위치 |
| 일반·복원 스킬 투사체 | 해당 투사체의 발사 위치 |
| 럭스 궁극기 등 지연 공격 | 시전 당시 기록한 위치 |
| 진의 함정·설치 구역 | 설치 효과의 위치 |
| 아리 여우불 등의 즉시 타격 | 해당 타격을 발사한 순간의 위치 |

엔진의 공통 피해 함수는 선택적 5번째 인수로 원점을 받는다.

```js
game.damage(target, amount, source, damageType, { x: originX, y: originY });
```

피해가 보호막에만 흡수되어도 피격 사실이 발생한 것으로 처리한다. 공격이 빗나갔거나 피해 판정이 거부된 경우에는 단서를 만들지 않는다.

### 3.2 위치 단서와 적 유닛 공개를 구분

현재 일반 시야에서 원점을 볼 수 없는 팀이 피해를 받으면 반경 76, 1.5초의 고정 단서를 생성한다. 표시는 황금색 원점 표시와 미니맵 단서로 연결된다.

- 단서는 생성 시점의 좌표에 고정된다.
- 공격자가 이동하거나 사망해도 그 좌표를 따라가지 않는다.
- 단서가 존재해도 `isVisible(enemy)`나 타깃 고정 권한은 늘어나지 않는다.
- 단서 위치의 건물 HP나 중립 몬스터 정보를 새로 관측하지 않는다.
- 같은 공격자의 동일 원점에서 반복 피해가 발생하면 만료 시각만 연장한다.
- 팀별로 격리하고, 최대 128개의 활성 단서로 제한한다.
- 표시용 API에는 공격자의 ID를 반환하지 않는다.

이는 원점의 **위치 단서**를 제공하는 정책이다. 적 모델을 추적 공개하거나 그 주변의 모든 오브젝트를 관측하는 효과는 아니다.

## 4. 건물의 마지막 관측 상태

### 4.1 저장하는 필드

```js
{
  id, name, type, team, x, y, r, range,
  lane, structureTier,
  hp, maxHp, alive, protected,
  observedAt
}
```

스냅샷에는 원래 건물 객체를 참조하는 포인터나 HP 바인딩을 넣지 않는다. 표시 API는 복사본과 `visible`, `remembered`를 반환한다. 호출자가 그 복사본을 수정해도 기억 상태는 바뀌지 않는다.

| 실제 상태 변화 | 해당 위치가 현재 관측됨 | 시야 밖 |
|---|---|---|
| 피해·회복 | 최신 HP를 저장 | 기존 HP 유지 |
| 보호 상태 해제 | 최신 보호 상태를 저장 | 이전 보호 상태 유지 |
| 파괴 | 파괴·HP 0을 저장 | 살아 있던 기억 프록시 유지 |
| 같은 슬롯의 새 건물 | 관측한 새 상태로 교체 | 이전 건물 상태 유지 |
| 실제 건물 객체 제거 | 빈 슬롯을 관측하여 파괴 상태로 전환 | 삭제 사건만으로 기억을 지우지 않음 |

현재 게임에는 플레이어의 건물 재건축 기능이 없다. 시스템 검사는 같은 ID의 새 상태로 교체되는 관측 계약까지 확인한다.

### 4.2 AI와 안내에서 숨은 상태를 사용하지 않기

적 건물의 목표 선정·공격로 진행·포탑 위험 판단은 관측한 건물 상태를 사용한다. 숨은 포탑이 파괴되어도 마지막 관측이 살아 있는 포탑이면 AI는 재확인하기 전까지 그 위치를 경계한다. 공격 명령 승인과 발사 직전은 현재 개체 가시성을 다시 검사한다.

적 건물 파괴가 팀 0의 시야 밖에서 발생하면 파괴 로그로 그 상태를 알려 주지 않는다. 아군 소유 건물과 최종 넥서스 승패는 팀·경기 정보로 처리한다. 전체 권위 상태를 담는 개발용 `getSnapshot()`과 `exportState()`는 여전히 진단·저장 API이며 플레이어용 관측 API를 대신하지 않는다.

## 5. 중립 목표의 관측과 빈 슬롯

원작 분석에서 지적한 중립 몬스터의 전체 상태 참조도 함께 줄였다. `getObjectiveObservation(id,team)`은 미관측 상태에서는 `alive`와 정확한 `respawnAt`을 주지 않는다.

| presence | 의미 | `known` | 공개 정보 |
|---|---|---:|---|
| `present` | 실제 몬스터를 관측 | true | 마지막 관측 생존 상태 |
| `dead` | 처치 당시 위치를 관측했거나 해당 팀이 확보 | true | 처치 확인과 재생성 예정 시각 |
| `pending` | 공개된 최초 등장 일정에 앞서 슬롯 관측 | true | 기존 경기 규칙의 최초 등장 시각 |
| `absent` | 보이는 홈 위치에 현재 몬스터를 확인할 수 없음 | false | 부재 관측만, 생사·재생성 시각 생략 |
| 기록 없음 | 아직 해당 슬롯을 관측하지 않음 | false | 공개 지도상의 이름·종류·홈 좌표 |

**빈 홈 위치는 죽음의 증거가 아니다.** 몬스터가 벽 뒤로 끌려간 상태에서 보이는 홈을 관측해도 숨은 생사나 정확한 재생성 타이머를 읽지 않는다. 이 상황에서 벽 뒤 몬스터가 살아 있을 때와 사망한 후의 공개 관측 객체가 동일한지 회귀 검사한다.

보지 못한 중립 목표에는 정찰 지시를 내릴 수 있다. 숨은 사망 자체로 정찰 지시를 취소하지 않고, 관측한 죽음과 남은 재생성 대기 시간은 지시 가능 여부에 반영한다. 정글 AI는 최근 확인한 빈 홈을 즉시 반복 방문하지 않으며, 기억만 있는 목표는 공개 홈 좌표로 접근하고 현재 보이는 실제 목표만 타깃으로 지정한다.

## 6. 마스크 계산과 렌더링 분리

### 6.1 판정과 표시

현재 개체 가시성은 **현재 위치의 거리와 정확한 선분/지형 검사**를 사용한다. 렌더러의 부드러운 안개 픽셀이나 과거 탐색 마스크로 타깃 지정을 승인하지 않는다.

지형 안개는 20월드 단위 셀로 만든 팀별 두 마스크를 사용한다.

- `visible`: 마지막 시야 갱신에서 보이는 지면 셀.
- `explored`: 한 번 이상 관측한 지면 셀. 시야를 잃어도 유지.

| 맵 배율 | 지형 크기 | 팀별 마스크 크기 | 2팀×현재·탐색 4배열 |
|---|---|---|---:|
| 1배 | 1600×1600 | 80×80 | 25,600바이트 |
| 1.5배 | 2400×2400 | 120×120 | 57,600바이트 |
| 2배 | 3200×3200 | 160×160 | 102,400바이트 |

0.1게임초 간격으로 갱신하므로 일시정지 시 마스크·만료 타이머도 멈춘다. 표시 마스크에는 이 간격의 지연과 셀 중심 표본 오차가 있다. 실제 타깃 판정은 그 마스크를 읽지 않으므로 같은 지연을 사용하지 않는다.

### 6.2 계산량을 줄인 방법

1. 각 시야원의 반경 사각형 안에서만 셀을 순회한다.
2. 다른 시야원이 이미 밝힌 셀은 추가 LOS 검사를 생략한다.
3. 제곱거리로 반경 밖을 먼저 제거한다.
4. 시야원 목록은 공간 인덱스 갱신 시 재구성하고 위치는 살아 있는 객체 참조에서 읽는다.
5. 벽과 높이 데이터는 경기 지도에 보존하고 재사용한다.
6. `revision`이 바뀔 때만 렌더러의 안개 이미지를 다시 쓴다.
7. 조회용 함수는 탐색·기억·타이머를 진행시키지 않는다.

두 와드가 겹친 곳에서 하나가 제거되어도 남은 시야원으로 합집합을 다시 구성하므로 잘못 어두워지지 않는다.

### 6.3 측정한 CPU 마스크 비용

2026-11-18, 이 작업의 Node **v24.22.1** 실행 환경에서 측정했다. 분산 배치한 미니언 120개, 영웅 10명, 건물 24개, 기지 2개로 **팀당 78개 시야원**을 만들었다. 8회 워밍업 후 양 팀 마스크와 관측을 전체 갱신하는 호출을 40회 측정했다.

| 맵 | 중앙값 | 95백분위 표본 | 최대 표본 | 마지막 갱신 LOS 검사 수 |
|---|---:|---:|---:|---:|
| 1배 | 3.875ms | 12.654ms | 44.383ms | 25,129 |
| 1.5배 | 5.649ms | 6.091ms | 6.563ms | 36,400 |
| 2배 | 7.749ms | 8.155ms | 8.421ms | 48,828 |

95백분위 열은 정렬한 40개 중 38번째 표본이다. 1배에서 큰 일회성 표본이 관측되었으므로 평균적으로 항상 일정한 프레임 시간을 보장하는 수치로 해석하지 않는다. 이 측정에는 Canvas 렌더링·실제 기기 브라우저·모바일 열 제한이 포함되지 않는다. 실제 게임에서는 이렇게 전역에 분산된 156개 시야원을 항상 유지하는 상황과 배치가 다를 수 있다.

## 7. 저장과 이전 버전 복원

신규 경기는 기존 영웅과 복원 영웅 모두 **`engineVersion: 9`**로 내보낸다. 이전 v4·v5·v6·v7·v8 입력을 받아들인다. 원래 저장에 없었던 탐색·기억은 복원 시 현재 허용되는 시야부터 초기화하며, 과거에 어디를 탐색했는지 추측해서 채우지 않는다.

`_visionState`에는 다음을 저장한다.

```js
{
  version: 1,
  profile: 'terrain-memory-v1',
  nextRefreshAt,
  nextRevealId,
  explored: [ /* 팀별 16진 문자열 청크 */ ],
  structures: [ /* 팀별 마지막 관측 스냅샷 배열 */ ],
  objectives: [ /* 팀별 중립 목표 관측 배열 */ ],
  reveals: [ /* 아직 유효한 공격 원점 토큰 */ ]
}
```

탐색 4셀을 16진 문자 1개에 저장하고 청크당 2,048문자로 나눈다. 기존 저장의 배열 2,048개·문자열 4,096자 제한을 넘지 않는다. 두 팀 합계 탐색 문자열은 1배 3,200자, 1.5배 7,200자, 2배 12,800자다.

현재 가시 마스크는 파생 데이터이므로 저장하지 않는다. 불러올 때 계산하되 저장한 탐색 비트·관측 스냅샷·다음 갱신 시각은 그대로 복원한다. 렌더링이나 조회 때문에 저장된 탐색 범위가 늘어나지 않는다.

저장 검증은 프로필, 지도별 비트 길이, 문자열 인코딩, 좌표, HP 범위, 건물 타입, 중복 ID, 미래 관측 시각, 원점 반경과 만료 범위, 원점 ID 카운터를 검사한다. v8 이전 공격 데이터의 누락된 발사 원점은 로드 시점의 저장된 발사자 위치를 호환값으로 사용한다. 그 과거 버전이 기록하지 않은 실제 발사 좌표를 복구했다고 주장하지 않는다.

## 8. 엔진 API

| 함수 | 계약 |
|---|---|
| `groundHeightAt(x,y)` | 현재 지형 높이 단계 |
| `hasLineOfSight(ax,ay,bx,by)` | 반경·팀 정보 없이 순수 지형 LOS |
| `visibilityAt(x,y,team)` | 해당 팀의 현재 일반 공간 시야 |
| `isVisible(entity,team)` | 현재 공간 시야와 수풀·개체 정책 |
| `getVisionMask(team)` | 공유 읽기 전용 마스크와 크기·revision |
| `getStructureObservations(team)` | 관측한 건물의 복사 배열 |
| `getStructureObservation(id,team)` | 관측한 한 건물 복사 또는 null |
| `getObjectiveObservation(id,team)` | 중립 목표 관측·부재·미확인 상태 |
| `getAttackOriginReveals(team)` | 해당 팀에만 공개할 현재 원점 단서 복사 배열 |
| `_updateVision(true)` | 테스트·명시적 경기 동기화용 즉시 마스크/관측 갱신 |

시뮬레이션은 생성·시작·진행·불러오기에서 시야를 갱신한다. 테스트에서 객체 좌표를 직접 바꾼 경우에는 `_rebuildIndex()`와 `_updateVision(true)`를 호출한다. UI의 프레임마다 갱신 함수를 호출하지 않는다.

## 9. 검증 범위

전용 검사 21개는 다음을 확인한다.

- 벽 뒤·열린 측면, 낮음→높음과 높음→낮음, 고지대 너머와 절대 벽.
- 수풀 조건을 서로 다른 시야원에서 잘못 합성하지 않음.
- 비행 정찰 예외와 일반 와드의 차이.
- 겹친 시야원 제거, 탐색 유지, 게임 시간 갱신, 조회 순수성.
- 미탐색 건물 비공개, 숨은 HP·파괴·보호·재건축 동결, 빈 건물 슬롯 재관측.
- 공격 원점 고정·만료·팀 격리·타깃 권한 미부여·건물 관측 미갱신.
- 중립 목표의 숨은 생사 유지와, 보이는 홈 뒤 벽에서 발생한 처치의 타이머 미노출.
- 1·1.5·2배 셀 크기와 고지대 통과, 2배 탐색·기억의 정확한 저장 복원.
- 실제 날아가는 기본 공격의 발사자 이동 이후 원점 유지.
- 숨은 건물 파괴 로그 억제, 미확인 중립 목표 정찰 지시.
- 저장 손상·미래 관측·잘못된 좌표 거부.

복원 전투 검사는 여기에 더해 럭스 지연 공격과 진 설치 함정의 원점 전달, 실제 v8 저장 이행, 재시전 상태를 검사한다. 전체 회귀 및 실제 화면 검증 결과는 [QA.md](../QA.md)를 참조한다.

## 10. 적용 경계

이 구현은 싱글플레이 시뮬레이션의 관측·표시·AI 정책이다. 전체 권위 상태가 JavaScript 메모리에 존재하므로 온라인 게임의 서버 권한 분리나 치트 방지 구현을 대체하지 않는다. 시야 프로필과 원본 데이터 버전은 서로 별개이며, 실제 LoL의 모든 은신·감지·지형 예외는 여전히 별도 복원 범위다.
