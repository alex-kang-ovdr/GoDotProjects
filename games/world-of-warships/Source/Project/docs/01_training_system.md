# 기초 훈련 시스템 명세

이 문서는 IRON TIDE V3에 구현된 훈련의 동작을 설명합니다. 기준 코드는 `dist/training.js`, 실제 전투 판정은 `dist/sim.js`, 화면 전환과 저장은 `dist/game.js`입니다. 원작의 훈련 콘텐츠를 복제한 문서가 아니라 이 웹 프로토타입의 구현 명세입니다.

## 1. 목적과 기본 규칙

플레이어가 조함, 고폭탄, 철갑탄, 측면 어뢰, 거점 점령을 짧은 독립 장면에서 익히도록 합니다. 버튼을 누른 사실이 아니라 실제 이동·탄착·점령 결과로 통과를 판정합니다.

- 훈련 함선은 표준 장비의 순양함이며 난이도 설정은 `easy`입니다. 항구에서 선택한 함종·장비·난이도는 훈련 때문에 바뀌지 않습니다.
- 매 단계와 재시도는 새로운 시뮬레이션으로 시작합니다. 이전 장면의 피해·탄약 재장전·발사체·표적 손상은 다음 장면으로 옮기지 않습니다.
- 정지 표적은 일반 함종의 HP와 장갑을 사용합니다. `aiDisabled=true`로 AI 조작을 끄고 기관 출력을 0으로 두며, 표적의 부포 사거리도 0으로 설정합니다. 안내에 명시된 무반격 표적입니다.
- 플레이어의 무장, 포탑 정렬, 탄 비행, 충돌, 장갑, 피해, 이동, 점령은 일반 전투 엔진을 사용합니다. 통과를 위해 피해나 명중 이벤트를 만들어 넣지 않습니다.
- 훈련은 경험치·전적·원정 진행을 지급하지 않으며, 진행 중인 자유·원정 전투의 저장을 보존합니다.

## 2. 다섯 장면

모든 장면에서 플레이어는 월드 좌표 `(2100, 2200)`에서 북쪽을 향해 정지한 상태로 시작합니다. 표의 `step`은 코드의 0 기반 값이며, 화면에는 1~5단계로 표시합니다.

| step / 화면 | 장면 구성 | 실제 통과 조건 | 핵심 조작 |
|---|---|---|---|
| 0 / 첫 항해 | `(2100, 1880)`, 반경 110의 도착 구역 | 누적 이동 거리 30 이상이면서 도착 구역 내부에 위치 | W/＋로 증속, A·D/좌우 버튼으로 조타 |
| 1 / 고폭탄 사격 | 570 앞에 측면을 보이는 정지 순양함 | 플레이어 주포 HE가 지정 표적에 양의 직접 피해 | 1 → 조준 → 정렬 후 발사 |
| 2 / 철갑탄과 측면 | 새로운 정지 순양함, 동일한 측면 배치 | 플레이어 주포 AP가 지정 표적에 양의 직접 피해 | 2 → 측면 조준 → 발사 |
| 3 / 측면 어뢰 발사 | 오른쪽 450 거리에 정지 구축함 | 플레이어 어뢰의 실제 충돌로 지정 표적에 양의 피해 | 3 → 오른쪽 표적 조준 → 측면 발사 |
| 4 / 거점 확보 | `(2100, 1880)`, 반경 145의 거점 A | 거점 소유자가 아군이고 플레이어의 점령 횟수가 1 이상 | 이동 후 S/−로 감속하고 구역 안에 머무름 |

거점의 중립 상태부터 점령 완료까지는 일반 엔진의 점령 시간이 적용됩니다. 훈련에서 시간을 생략하지 않습니다. 어뢰 표적은 순양함의 실제 측면 발사각 안에 배치되어 있어 출발 위치에서도 발사할 수 있습니다.

화면 진행률은 이동 단계에서 도착 구역까지 줄어든 거리를, 점령 단계에서 실제 `zone.progress`를 사용합니다. 값의 범위는 0~1입니다. 사격 단계는 피해가 확인되기 전 0, 통과 후 1입니다.

## 3. 상태 전이

| 현재 상태 | 조건·행동 | 다음 상태와 처리 |
|---|---|---|
| 생성 전 | `create({step, seed})` | 해당 단계의 새 장면, 미완료·실패 아님 |
| 진행 중 | `tick(session, dt, controls)` | 일반 엔진 한 틱을 실행하고 실제 결과 평가 |
| 진행 중 | 목표 달성 | `stageComplete=true`; 즉시 진행을 멈추고 결과 모달 표시 |
| 진행 중 | 기함 격침 또는 목표 무장 명중 전 표적 격침 | `failed=true`; 실패 이유를 표시하고 진행 정지 |
| 단계 통과 | 다음 훈련 | `advance()`가 다음 단계의 새 장면 반환 |
| 마지막 단계 통과 | 수료하고 항구로 | `advance()`가 `complete=true`인 세션 반환 후 항구 복귀 |
| 통과·실패·진행 중 | 같은 단계 재시도 | `restart()`가 같은 단계·시드의 새 장면 반환 |
| 미완료·실패 | `advance()` 호출 | 기존 세션 유지; 단계를 건너뛰지 않음 |

`stageComplete`는 현재 단계의 통과, `session.complete`는 전체 과정의 종료 처리입니다. `brief().complete`는 현재 단계의 통과를 뜻합니다. 마지막 목표를 달성한 직후에는 `stageComplete=true`, `session.complete=false`일 수 있지만 저장 진도는 이미 수료 상태로 취급합니다.

통과·실패 후에는 `tick()`이 전투를 더 진행하지 않습니다. 플레이어가 다음 단계·재시도·항구 중 하나를 선택해야 상태가 바뀝니다. 컨트롤러는 이 전환마다 키 입력, 발사 유지, 예약 발사, 터치 조타를 초기화합니다.

## 4. 명중 판정과 잘못된 통과 방지

매 틱에는 마지막 처리 이벤트 ID보다 큰 새 이벤트만 평가합니다. 사격 훈련을 통과하려면 아래 조건을 모두 만족해야 합니다.

| 이벤트 필드 | 요구 조건 |
|---|---|
| `type` | `hit` |
| `ownerId` | 플레이어 ID와 일치 |
| `shipId` | 현재 단계의 지정 표적 ID와 일치 |
| `ammo` | 해당 단계의 `HE`, `AP`, `TORP`와 일치 |
| `secondary` | 정확히 `false` |
| `damage` | 0보다 큼 |
| `result` | 어뢰 단계에서는 `torpedo`; 주포는 양의 실제 피해 결과 |

발사 뒤 다른 탄종으로 바꾸어도 **탄착 이벤트의 탄종**으로 판정합니다. 탄종 선택 자체, 발사만 한 경우, 빗나감, 피해 0인 도탄·비관통, 다른 무장, 자동 부포, 화재·침수 피해는 목표 명중으로 인정하지 않습니다.

올바른 명중으로 표적을 격침한 틱은 통과입니다. 같은 틱에 기함이 격침되면 기함 상실을 먼저 처리해 실패합니다. 올바른 무장 명중 없이 표적이 사라지거나 HP가 0이 되면 실패하고 재시도를 제공합니다. 이 방식으로 잘못된 무장 사용이나 오래 기다리는 동안의 부포 피해가 훈련을 막힌 상태로 남기지 않습니다.

훈련의 `game.trainingMode=true`는 일반 점수·시간 종료·적 함대 전멸에 의한 승리를 건너뛰게 합니다. 기함 격침 판정은 유지하며, 단계 성공은 훈련 어댑터가 맡습니다.

## 5. API와 세션 데이터

전역 `IronTide.Training`을 내보내는 클래식 스크립트입니다. 로드 순서는 `operations.js → sim.js → training.js`이며, 화면 모듈은 그 뒤에 로드합니다.

| API | 반환·책임 |
|---|---|
| `create({step=0, seed=711})` | 독립 `session` 생성 |
| `tick(session, dt, controls)` | 세션을 한 틱 갱신하고 같은 세션 반환; 유효하지 않거나 0 이하인 시간은 무시 |
| `advance(session)` | 통과한 경우에만 다음 장면 또는 수료 세션 반환 |
| `restart(session)` | 같은 단계·시드의 초기 장면 반환 |
| `brief(session)` | 화면용 단계 번호·제목·설명·목표·진행률·성공·실패·표적·도착 구역 |
| `progress(session)` | 현재 세션을 저장 가능한 진도로 변환 |
| `normalizeProgress(value)` | 저장 진도의 버전·타입·범위를 검증하고 기본값 적용 |
| `mergeProgress(previous, next)` | 두 진도를 정규화한 뒤 이미 달성한 단계를 보존하여 병합 |

세션의 핵심 필드는 다음과 같습니다.

```js
{
  game, step, seed,
  stageComplete: false, failed: false, complete: false,
  targetId, checkpoint, failureReason,
  lastEventId, movedDistance, lastX, lastY, initialDistance,
  hitEvidence // 통과를 확인한 실제 명중의 id/ammo/damage/result/ownerId
}
```

`checkpoint`는 `{x, y, radius}` 또는 `null`입니다. `brief()`는 구역 좌표의 복사본을 반환하므로 화면에서 값을 바꾸어도 세션의 통과 구역이 바뀌지 않습니다.

## 6. 진도 저장과 재개

저장 키는 `iron-tide.training.v1`이며 데이터는 다음 세 필드입니다.

```json
{"version":1,"step":3,"completed":false}
```

이 예시는 0~2단계를 통과했으며 다음에 3번 단계, 즉 화면의 어뢰 훈련을 새 장면으로 시작한다는 뜻입니다. 도중 위치·HP·발사체는 저장하지 않습니다.

- 미완료 장면은 현재 `step`을 저장합니다. 단계를 통과하면 다음 미완료 `step`을 저장합니다. 마지막 단계 통과는 `{version:1, step:4, completed:true}`입니다.
- 단계 종료, 일시정지, 항구 복귀, 페이지 종료 시 컨트롤러가 진도를 저장합니다. 훈련은 일반 전투의 3초 주기 스냅샷 저장 대상에서 제외됩니다.
- 저장할 때 `mergeProgress(기존 진도, 현재 세션 진도)`를 사용합니다. 수료 여부는 논리합, 미수료 단계는 최댓값입니다. 이미 통과한 단계를 반복하다 나가거나 수료 후 처음부터 재연습해도 달성 진도가 낮아지지 않습니다.
- 수료 후 훈련 시작은 현재 플레이 장면을 0단계로 새로 만듭니다. 저장된 수료 상태와 연습 중인 현재 단계는 별개입니다.
- 알 수 없는 버전, 배열, 잘못된 숫자 타입·단계 값은 안전한 기본값을 적용합니다. 유효한 버전에서 `completed=true`이면 `step=4`로 맞춥니다.
- 저장 실패는 안내 문구로 표시하며 현재 페이지에서 훈련은 계속할 수 있습니다.

일반 전투 키 `iron-tide.active.v2`와 경력 키 `iron-tide.career.v2`는 훈련 저장에서 수정하지 않습니다. 엔진의 `serializeGame(trainingGame)`도 `null`을 반환합니다. 경력 요약은 `trainingMode`를 우선해 세션 유형을 훈련으로 정하고 보상을 0으로 만들며, `Career.record()`는 훈련 결과의 등록 자체를 거부합니다.

## 7. 검증 범위

실행 명령:

```bash
node tests/training.test.cjs
```

V3 구현 검증에서 **21/21 검사 통과**를 확인했습니다. 테스트는 Node VM에서 실제 `operations.js`, `sim.js`, `training.js`를 함께 실행합니다.

| 검증 영역 | 확인 내용 |
|---|---|
| 실제 훈련 진행 | 정상 이동, HE 탄 비행·명중, AP 피해, 측면 어뢰 충돌, 실제 거점 점령으로 다섯 단계 순차 통과 |
| 판정 정확성 | 제자리 선회·잘못된 탄종·부포로는 통과하지 않음; 발사 뒤 탄종 변경은 탄착 메타데이터로 판정 |
| 재시도·전환 | 잘못된 무장의 실제 표적 격침 → 실패 → 새 장면 → 정상 통과; 미완료 단계 건너뛰기 차단 |
| 정지 | 성공·실패 후 시간이 더 진행하지 않음 |
| 진도 | 현재 단계의 새 장면 복원, 통과 단계 반복·수료 후 반복으로 진도 퇴행 방지, 손상 데이터 정규화 |
| 격리 | 훈련 스냅샷·XP·전적·원정 등록 거부; 기존 일반 전투를 보유한 상태에서 전 과정을 실행해도 그 전투 스냅샷이 동일 |

완료 검증은 테스트가 HP나 명중 이벤트를 만들어 통과시키는 방식이 아닙니다. 브라우저의 배치·터치·포커스 검증은 이 Node 검사의 범위와 구분합니다.
