# 12. 맵·전투 모드·거점·작전 목표

> 기준: PC 글로벌 15.10 시점의 공개 자료. 일반 규칙과 모드·맵별 오버라이드를 구분한다.

[전체 목차](README.md) · [승리 판정](01_core_loop_and_victory.md) · [매칭](13_matchmaking_ranked_and_clans.md) · [탐지](08_detection_vision_and_information.md)

## 1. 역할과 범위

[분석] 맵은 배경 지형이 아니라 **누가 누구를 언제 발견하고, 어떤 탄도로 공격하며, 얼마나 안전하게 물러날 수 있는지**를 정하는 전투 시스템이다. 모드는 같은 지형에 다른 이동 이유를 부여한다.

따라서 아래 세 항목을 구분한다.

| 계층 | 정의 | 예시 |
|---|---|---|
| 전투 종류 | 참가·보상·매칭의 틀 | 무작위, 협동, 작전, 랭크 |
| 목표 규칙 | 전투 중 이기는 방법 | 일반전, 점령전, 군비 경쟁 |
| 맵 변형 | 같은 지형 위 실제 설정 | 스폰, 거점 배치, 날씨, 티어 범위 |

“무작위 전투는 점령전이다”처럼 전투 종류와 목표 규칙을 동일한 enum으로 만드는 것은 확장에 불리하다.

## 2. 전투 종류의 구조

| 종류 | 상대와 팀 구성의 성격 | 주요 판단 | 버전 처리 |
|---|---|---|---|
| 무작위 | 대표적으로 12 대 12, 큐 상황에 따른 예외 | 불완전한 정보에서 팀 역할 수행 | 매칭 프로필 별도 |
| 협동 | 플레이어 측과 봇 측 | 빠른 목표 파악·기본 조작 | 보상·봇 구성 별도 |
| 작전 | 협력 PvE, 시나리오와 부가 목표 | 목표물 보호·타이밍·동선 | 시나리오별 참가 조건 |
| 랭크 | 개인 진입 경쟁 진행 | 소규모 팀 내 역할·시즌 진척 | 티어·인원·별 규칙 시즌 데이터 |
| 클랜전 | 조직된 팀 경쟁 | 구성·콜·교차 사격 계획 | 제한 함선·레이팅·운영 시간 |
| 난투 | 제한된 구성·변형 규칙 | 특정 교전 양식에 최적화 | 회차별 독립 프로필 |
| 비대칭 | 적은 플레이어와 다수 봇의 전투 | 화력 분산·누적 생존·진형 | 운영 기간과 난도 조정 가능 |
| 훈련 | 조건을 통제하는 실험 공간 | 규칙 검증 | 경제·임무 집계와 분리 |

대표 인원·분류의 공개 근거는 [R05]다. 이 표의 '주요 판단'은 분석이다. 비대칭 전투는 15.10 공지에서 16.3까지 연장을 안내한 상태로, 영구 모드가 확정되었다고 기술하지 않는다. [R01]

## 3. 일반전과 점령전의 차이

[확인·버전 의존] 대표 일반전은 상대 기지 점령이 즉시 승리와 연결된다. 점령전은 거점을 확보해 정기적으로 점수를 얻고, 격침·손실 점수가 함께 누적된다. 점령 중 피격은 해당 함선의 점령 기여를 줄이고, 양팀 함선이 같은 거점에 있으면 점령이 경합한다. [R05]

| 질문 | 일반전 | 점령전 |
|---|---|---|
| 목표 공간 | 각 팀의 기지 | 여러 개의 지역 |
| 진입의 의미 | 상대 수익 중단·기지 압박 | 소유권 획득·수익 차이 형성 |
| 점령 완료 효과 | 대표 설정에서 승리 조건 충족 | 보유 거점의 정기 점수 획득 |
| 방어자의 선택 | 귀환·점령 초기화·전멸 경쟁 | 한 거점 양보 후 다른 거점 교환 |
| 설계 긴장 | 전선 우세와 후방 방어 | 분산·집중·재배치 |

### 3.1 공개된 대표 수치와 적용 범위

아래 값은 모든 모드의 상수가 아니라 위키가 설명하는 기본 프로필의 예다. [R05]

| 항목 | 대표값 |
|---|---|
| 일반전 적 기지 점령 | 1척 180초 / 2척 이상 120초 |
| 일반 점령전 거점 점령 | 1척 60초 / 2척 이상 40초 |
| 3거점의 대표 수익 | 거점당 5초마다 3점 |
| 4거점의 대표 수익 | 거점당 9초마다 4점 |
| 일반 무작위의 구축함 격침 예 | 아군 +30, 적군 -45 |

일부 맵은 시작 점수와 격침 점수가 다르다. 랭크·클랜전·군비 경쟁·이벤트 값을 위 표로 덮어쓰면 안 된다.

## 4. 점령을 구현할 때 구분해야 할 상태

[제안] 거점의 소유 상태와 진행 상태를 분리한다.

```yaml
ControlArea:
  owner: neutral_or_team_id
  occupancy: participating_ship_ids_by_team
  progress: capture_contribution_by_ship
  contested: boolean
  score_generation_enabled: boolean
  capture_rule_id: data_id
  scoring_rule_id: data_id
```

`소유 중`이면서 `적 진입으로 수익 중단`인 상태가 가능하다. 따라서 `Neutral / A / B` 세 상태만으로는 충분하지 않다.

### 4.1 경계 조건

- 거점 밖으로 나가는 순간 기여를 유지·삭제하는 정책.
- 함선 중심·선체 일부 중 무엇을 경계 판정에 사용하는지.
- 보이지 않는 적이 들어왔을 때 경합 정보만 공개할지.
- 피격이 성공했으나 HP 피해가 0인 경우 점령 방해로 처리되는지.
- 잠수함 깊이 상태별 점령 참가 여부.
- 같은 순간 거점을 획득하고 점수 지급 주기가 도래한 경우.

이 세부 경계의 실제 내부 구현은 자료만으로 확정하지 않는다. 재현 프로파일에서는 각각 독립 테스트와 설정이 필요하다.

## 5. 점령 기여를 함선별로 보관해야 하는 이유

[분석] 두 함선이 거점을 점령할 때 한 척만 피격되었다면, '거점 전체 진행률을 무조건 절반으로 만들기'는 함선별 기여를 잃는다. 공개 규칙의 표현을 충실히 재현하려면 참가자별 기여와 전체 진행의 합성 방식을 고려해야 한다.

[제안] 다음처럼 계산 계층을 나눈다.

1. 참가 가능한 함선 목록 계산.
2. 양팀 참가 여부로 경합 판정.
3. 참가 수에 따른 진행 속도 상한 적용.
4. 각 함선의 기여 기록.
5. 피해·이탈·격침에 따른 기여 갱신.
6. 소유권 변환과 점수 수익 갱신.

이는 원작 공식 알고리즘이 아니라 경계 조건을 표현하기 위한 명세 방식이다.

## 6. 군비 경쟁과 이동 목표

[확인] 군비 경쟁은 전장 내 강화 요소와 후반 목표를 결합한 모드다. 과거 Epicenter 및 Airship Escort의 일반 무작위 편입 여부는 변경 이력이 있으므로, 과거 등장했다는 이유만으로 현재 무작위의 상시 규칙에 포함하지 않는다. [R05]

[분석] 서로 다른 목표는 다음처럼 행동을 바꾼다.

| 목표 형태 | 이동을 유도하는 방법 | 발생하기 쉬운 문제 | 대응 설계 |
|---|---|---|---|
| 고정 거점 | 지속 수익 차이 | 유리한 섬 뒤 장기 대치 | 다중 접근·측면 사선 |
| 시간차 강화 | 먼저 도착하는 보상 | 빠른 함선 독점·스노우볼 | 생성 위치·종류·타이밍 |
| 이동 호위 | 목표의 경로 강제 | 특정 함종의 역할 소멸 | 속도·접근 범위·방어 역할 |
| 파괴 대상 | 화력 집중 요구 | 목표 공격만 하는 단조로움 | 노출 시간·호위·우회 목표 |
| 생존 파동 | 전력 보존 | 수동적 대기 | 주기적 위치 변경·부가 목표 |

## 7. 작전의 구조

[확인] 작전은 주 목표와 부가 목표를 가진 협력 PvE다. 15.8에는 낮은 티어를 위한 세 작전이 추가되었다. 따라서 '작전은 특정 중간 티어 전용'이라는 과거 설명은 그대로 적용하지 않는다. [R06]

[제안] 시나리오를 다음 구성 요소로 분리한다.

| 구성 | 소유 데이터 |
|---|---|
| 참가 | 조건·팀 전력 스케일 |
| 진행 | 단계별 목표 그래프 |
| 적 전력 | 파동·이동 경로 |
| 보호 | 호위 대상·탈출 조건 |
| 결과 | 주 목표 성공·실패 |
| 추가 성과 | 부가 목표·보상 |
| 정산 | 종료·지급 정책 |

위 구성은 목록이며 실제 원작 파일 구조를 뜻하지 않는다.

### 7.1 가정 시나리오

1. 수송선 3척을 집결지까지 호위한다.
2. 해협 진입 시 첫 적 파동이 활성화된다.
3. 적 정찰 함선이 살아 있으면 측면 증원이 발생한다.
4. 기지 방어 시설을 파괴하면 호위 경로가 단축된다.
5. 수송선 1척 이상이 도착하면 주 목표 성공.
6. 전원 도착·제한 시간·특정 적 제거를 부가 목표로 둔다.

**이 시나리오는 설명용 창작**이다. 목표 그래프와 난도 조정의 관계를 보여 주기 위한 예이며, 실제 특정 작전의 공략이 아니다.

## 8. 맵을 평가하는 기하학적 요소

[확인] 공식 위키는 맵 크기·적용 티어·주요 지형을 제공한다. 게임의 표시 거리와 함선 크기가 현실의 축척을 그대로 따르는 것은 아니다. [R07]

[분석] 맵별 수치보다 재사용 가치가 높은 평가 항목은 다음과 같다.

| 항목 | 측정 질문 | 연결 시스템 |
|---|---|---|
| 최초 접촉 거리 | 스폰에서 적을 처음 볼 때까지 얼마나 걸리는가 | 기동·탐지 |
| 유효 사선 | 어느 위치에서 몇 방향을 공격할 수 있는가 | 탄도·장갑 |
| 퇴로 | 전진 후 선회·후진을 안전하게 할 공간이 있는가 | 기동·어뢰 |
| 거점 지원 | 거점 밖 함선이 내부를 얼마나 지원할 수 있는가 | 조준·레이더 |
| 측면 가치 | 이동 비용 대비 새로운 공격각을 얻는가 | 장갑·소모품 |
| 장애물 높이 | 시야는 막지만 고각탄은 넘을 수 있는가 | 탐지·탄도 |
| 수중 통로 | 잠수함과 대잠 무장의 접근이 어떻게 다른가 | 잠수함·ASW |
| 공중 접근 | 항공기가 지형·대공망을 어떻게 이용하는가 | 항공·대공 |

보이지 않는 것, 포탄이 닿지 않는 것, 어뢰가 통과하지 못하는 것은 서로 다른 판정이다.

## 9. 날씨와 정보 제한

[버전 의존] 날씨는 화면 효과와 게임 규칙 효과를 구분해야 한다. Ocean에는 15.9부터 특수 Cyclone 변화가 반영되었다. 이 사례는 '섬 없는 맵은 항상 전역 시야 교전'이라는 고정 해석을 약화시킨다. [R07][R08]

[제안] 날씨 프로필은 `visual_profile`, `detection_modifier`, `render_limit`, `zone_shape`, `activation_time`, `duration`, `movement_path`를 분리한다.

안개를 렌더링에만 추가하면서 게임상 탐지는 그대로 두는 것과, 서버가 실제 공유 가능 정보를 줄이는 것은 전혀 다른 시스템이다. 영향을 받는 주체가 함선인지 항공기인지도 별도 지정해야 한다.

## 10. 설계 분석: 좋은 거점 배치의 조건

[분석]

- 거점 내부에 들어갈 이유와 거점 밖에서 지원할 이유가 함께 있어야 한다.
- 가장 가까운 스폰의 선점이 자동 승리로 이어지지 않아야 한다.
- 한쪽 측면에서 이긴 팀이 반대편에 개입할 시간은 충분하되 즉시 전장을 덮지는 않아야 한다.
- 함종별 강점이 이동 가능한 여러 위치에서 발휘되어야 한다.
- 상성 불리한 함선에게도 탐지·교란·수익 중단 등 작은 기여 경로가 필요하다.
- 시간 종료를 앞두고 점수와 남은 목표가 분명히 읽혀야 한다.

이 원칙은 원작 개발사의 선언이 아니라 공개된 규칙을 바탕으로 한 평가 기준이다.
