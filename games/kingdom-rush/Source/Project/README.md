# Kingdom Rush · 자료 복원 플레이 v18

**12개 전장을 플레이하고, 진행 중인 전투를 저장해 이어가며, 지도·타워·몬스터·웨이브 데이터를 살펴보는 JavaScript 타워 디펜스입니다.** 사용자가 제공한 `KingdomRush_Reconstructed_v14.zip`의 분석 자료와 공개 플레이 기록을 전투 엔진, 복원 지형, 전장 도감으로 연결했습니다. v18은 전투 이어하기, JSON 백업, 작은 화면의 선택과 조작, 전투 결과 분석을 보강합니다.

**자료 기준 규칙 / 웹 지원 규칙**, **복원 지도 / 웹 전용 지도** 선택을 유지합니다. 원작에서 관측한 값, 시각 추정한 지형, 웹 실행을 위해 보완한 값을 구분합니다. `자료 기준`은 출처 자료를 적용하는 프로필 이름이며 원작 실행 파일과 일치하는 실측판이라는 뜻은 아닙니다. 전투 저장은 이 웹 엔진의 상태를 보존하는 새 기능이며 원작 저장 파일을 읽는 기능이 아닙니다.

## 이번 v18에서 달라진 점

- **전투 이어하기:** 타워·병력·적의 위치와 체력, 비행 중 공격, 대기 스폰, 상태 이상, 재사용 대기시간, 시설·화산 이벤트, 난수 상태와 통계를 저장합니다. 다시 열면 일시정지 상태에서 이어할 전투를 확인합니다.
- **자동 저장:** 전투 시뮬레이션 시간 5초마다, 성공한 전투 명령 직후, 일시정지·메뉴 열기·백그라운드 전환·페이지 이탈 시 저장을 시도합니다. 화면에 전투 시간과 최근 저장 상태를 표시합니다.
- **JSON 백업:** 설정에서 최고 기록과 진행 중인 전투를 내보내고 가져옵니다. 가져오기는 더 좋은 기록을 합치며 현재 브라우저의 설정·별 강화 배분은 유지합니다. 전투까지 가져오는 선택은 현재 전투를 교체하고 일시정지 상태로 엽니다.
- **확대 지도와 터치 선택:** 확대 중 전체 지도로 현재 시야·적·타워를 확인하고 클릭·드래그·방향키로 시야를 이동합니다. 적 선택은 화면에 보이는 몸체와 CSS 픽셀 기준의 터치 허용 범위를 사용하며 확대 배율에 맞춰 보정합니다.
- **전투 결과 분석:** 피해 유형, 통과한 적의 종류와 수, 실제 생명 손실, 지출·주문 사용, 활약한 방어 시설을 표시합니다. 판매한 타워의 이전 피해와 이후 도착한 공격도 해당 타워의 성과에 남깁니다.
- **읽기와 조작 개선:** 주요 버튼·보조 글자·숫자를 확대하고, 작은 화면에서는 타워 선택 패널을 전체 너비로 제공합니다. 키보드 포커스, 높은 대비와 동작 줄이기 설정을 반영했습니다.

v17의 엘프 훈련소·태양광선 탑·화산 이벤트와 전장 요소 도감은 그대로 포함합니다. 시설의 숫자는 [커뮤니티 후보 자료](docs/SPECIAL_COMPONENTS_v17.md)이며 원작 빌드에서 직접 실측한 값이라고 주장하지 않습니다. **12개 맵·36개 전장/모드 조합·260개 웨이브 슬롯·10,443기 최초 편성은 변경하지 않았습니다.** 특수 시설의 근거 파일은 계속 `data/special-components-v17.json`을 사용합니다.

## 바로 실행

전달 파일 **`KingdomRush_Playable_v18.html`**, 또는 소스 ZIP **`KingdomRush_Playable_v18_Source.zip`** 안의 `dist/index.html`을 최신 브라우저에서 엽니다. Canvas 2D와 현재 코드에서 사용하는 JavaScript 기능을 지원하는 최신 Chrome·Edge·Firefox·Safari 계열을 대상으로 합니다. 브라우저별 확인 범위는 아래 검증 문서에서 구분합니다.

**설치·npm 패키지·로그인·서버·외부 이미지·폰트가 필요 없는 단일 HTML**입니다. 게임 데이터, 엔진, 그림, 전장 도감이 모두 파일에 포함되어 오프라인에서도 실행됩니다. 도감의 출처 링크를 열 때만 인터넷이 필요합니다.

기본 선택은 **웹 지원 규칙 + 복원 지도**입니다. 원정 지도나 설정에서 규칙·지도·난이도를 변경하면 **다음 출전부터** 적용됩니다. 현재 전투의 도중에 규칙을 바꾸지는 않습니다.

모바일 파일 앱이 HTML을 문서 미리보기로 여는 경우에는 브라우저에서 실행하거나 제공된 웹 플레이 주소를 이용하세요. 별·강화·설정과 진행 중인 전투는 해당 브라우저에 저장합니다. 저장을 사용할 수 없으면 화면에 현재 세션 또는 저장 불가 상태가 표시되며, 설정에서 JSON 백업을 내려받을 수 있습니다. `file://` 실행에서는 브라우저의 로컬 파일 저장 정책에 따라 현재 세션에서만 유지될 수 있습니다.

## 규칙과 지도 선택

전투 규칙과 지도는 독립된 선택입니다. 같은 지도에서 규칙을 비교하거나 같은 규칙으로 복원 지도와 기존 웹 지도를 비교할 수 있습니다.

### 전투 규칙

| 선택 | 적용되는 내용 | 자료 해석 |
|---|---|---|
| **웹 지원 규칙** `assisted` | 시작 골드 보정, 자체 영웅 아렌, 자유로운 타워 진화, 웹 강화 18단계 | v15의 플레이 보조 방향을 유지한 프로필 |
| **자료 기준 규칙** `reference` | 자료의 시작 골드, 타워 해금 순서, 영웅 제한, 도전의 별 강화 상한, 복원 별 강화 30개 | 확인된 자료를 우선 적용하고 누락된 실행값은 명시적인 보완 규칙 사용 |

자료 기준에서는 초반에 고급 타워를 바로 선택할 수 없고, 영웅이 허용되지 않은 모드에서는 영웅 조작이 비활성화됩니다. 도전의 **별 강화 단계 제한**과 **타워 건설 단계**는 별개의 규칙으로 처리합니다. 모드의 원문 값이 비어 있거나 출처 후보가 충돌하는 경우에는 원문 후보·해결용 값·보완 사유를 함께 보존합니다.

### 지도

| 선택 | 배치 | 용도 |
|---|---|---|
| **복원 지도** `reconstructed` | 공개 기록의 건설 위치와 원작 화면에서 읽은 도로 | 원작 레벨의 굴곡·분기·합류·사거리 관계 분석 |
| **웹 전용 지도** `authored` | v15에서 작성한 12개 자체 경로와 공터 | 기존 웹 플레이 배치 유지와 비교 |

복원 지형은 **일반 공터 152개 + 캠페인 기존 궁수탑 1개 + 특수 시설 2개**입니다. Silveroak의 E7 궁수탑은 캠페인에서만 선배치합니다. B8 엘프 훈련소와 Stormcloud A1 태양광선 탑은 일반 공터와 다른 건물로 표시하며, v17부터 구현한 수리·고용·집결 및 충전·수동 조준 기능을 유지합니다. 시설은 복원 지도에서 이용하며 웹 전용 지도에는 임의 좌표를 추가하지 않습니다.

복원 좌표는 1920×1080 참고 이미지에서 1000×620 월드로 두 축을 각각 변환한 값입니다. 원작 엔진의 좌표·사거리 단위나 종횡비를 그대로 옮긴 것이 아닙니다. 자세한 근거와 전체 좌표는 [레벨 복원 문서](docs/LEVEL_RECONSTRUCTION_v16.md)에 있습니다.

## 첫 전투

1. **남부 항구 / 캠페인 / 복원 지도**를 선택합니다.
2. `T` 또는 전술 표시 버튼으로 도로 방향과 A9·B5 등의 지점명을 켭니다.
3. **B5에 궁수 1단계, C3에 마법 1단계, B3에 병영 1단계**를 건설합니다.
4. **전투 시작**을 누릅니다. 다음 웨이브는 자동으로 진행되며 `N`으로 조기 호출할 수도 있습니다.
5. 자료 기준 규칙에서는 영웅이 출전하지 않습니다. 수입이 쌓여 골드가 100 이상이면 **E3에 마법 1단계**를 추가하는 배치를 시도할 수 있습니다.

이 배치는 아래 회귀 검증에서 사용한 예입니다. 실제 플레이의 시드, 추가 조작, 조기 호출 시점에 따라 결과가 달라질 수 있습니다. 기존 v15의 숫자 공터 02·04·05 안내는 웹 전용 지도에 관한 기록이므로 복원 지도에 그대로 적용하지 않습니다.

첫 웨이브 전 판매는 전액을 환불합니다. 전투 중 환불은 웹 지원 규칙의 65%, 자료 기준의 기본 60% 및 해당 별 강화 효과에 따라 달라집니다. 구매·판매·집결 가능 여부는 현재 전투 규칙으로 판정합니다.

| `2` | 불의 비 선택 후 목표 위치 지정 |
| `H` | 영웅 선택 후 이동 위치 지정; 허용 모드에서 사용 |
| `N` | 첫 웨이브 시작 / 다음 웨이브 조기 호출 |
| `Space` 또는 `P` | 일시정지 / 재개 |
| `F` | 배속 순환 |
| `T` | 경로 방향·입구 번호·건설 지점명 표시 전환 |
| `Esc` | 목표 지정 취소 → 선택 해제 → 일시정지; 메뉴에서는 닫기 |
| 우클릭 | 스킬·이동 목표 지정 취소 |
| 상단 `이어하기` 또는 재개 버튼 | 저장·일시정지 상태의 전투를 재개 |

병영 또는 병력을 소환한 타워의 집결 위치는 선택 패널에서 지정합니다. 집결 미리보기는 엔진의 실제 허용 범위를 사용합니다. 공격 우선순위는 공격 가능한 적 가운데 적용하며, 지상 전용 타워에 공중 우선을 선택해도 공중 공격 능력이 생기지는 않습니다.

모든 주요 조작은 화면 버튼으로도 사용할 수 있습니다. 메뉴·도감을 열거나 브라우저가 백그라운드로 이동하면 전투 시간이 멈춥니다.

적의 선택 범위는 확대 배율과 표시 크기를 반영합니다. 터치에는 최소 22 CSS 픽셀의 선택 반경을 적용하고, 여러 적이 겹치면 화면에서 누른 위치에 더 가까운 몸체를 우선합니다. 공중 적은 지상의 그림자와 구분하며 죽은 적과 카메라 밖 적은 선택에서 제외합니다. 판정은 [선택 모듈](src/picking.js)과 [선택 검증](tests/picking.test.js)에 있습니다.

## 별 강화와 저장

캠페인 최고 별은 전장마다 최대 3개, 영웅·강철은 각각 1개입니다. 같은 전장·모드의 최고 별만 합산하여 최대 **60개**를 얻을 수 있고, 반복 클리어로 별을 계속 늘릴 수는 없습니다.

| 강화 프로필 | 구성 | 배분 방식 |
|---|---|---|
| 웹 강화 | 6계열 × 3단계 = 18단계 | 단계 비용 1·2·3별; 웹 지원 규칙에 적용 |
| 복원 강화 | 6계열 × 5개 = 30개 | 각 강화의 복원된 비용과 효과; 자료 기준 규칙에 적용 |

두 프로필은 **같은 획득 별을 각각 배분**하며 서로 다른 배분 상태로 저장합니다. 어느 한쪽의 초기화가 다른 쪽 배분을 지우지 않습니다. 강화는 다음 전투부터 적용하고, 무료로 초기화할 수 있습니다. 도전 모드에 별 강화 상한이 있으면 구매한 단계 중 허용 범위까지만 전투에 적용합니다.

### 진행 기록 이관

v18은 `localStorage`에 진행 기록과 전투 상태를 별도로 저장합니다.

| 저장 키 | 내용 |
|---|---|
| `kr_frontier_v18_progress` | 최고 별·최고 처치, 규칙/지도/난이도별 전투 기록, 두 별 강화 배분, 설정, 튜토리얼 상태 |
| `kr_frontier_v18_battle` | 현재 준비 또는 진행 중인 전투의 v18 스냅샷과 카메라 위치 |

v18 진행 기록이 없으면 같은 출처(origin)의 `kr_frontier_v17_progress`, `kr_frontier_v16_progress`, `kr_frontier_v15_progress` 순서로 **처음 발견한 진행 기록**을 읽어 정상화합니다. 알려진 전장·모드·설정만 받아들이고 별 상한과 배분 예산을 검사합니다. 이전 저장 키는 삭제하지 않습니다. 파일별 저장 영역을 나누는 브라우저에서는 이전 HTML의 기록에 접근하지 못할 수 있습니다.

최고 별은 전장·모드 기준으로 공유하고, 상세 전투 기록은 규칙·지도·난이도별로 구분합니다. **v15~v17의 진행 기록 이관과 v18의 전투 중간 저장은 서로 다른 기능입니다.** v17 이전의 진행 중 전투를 복원하거나 원작 저장 파일을 변환하지 않습니다. 구현과 검증은 [진행 모듈](src/progress.js), [진행·백업 검증](tests/progress.test.js)에 있습니다.

### 전투 자동 저장과 이어하기

준비 중 또는 진행 중인 전투를 한 슬롯에 보존합니다. 전투 시뮬레이션 시간 5초마다, 성공한 명령 직후, 일시정지 전환, 메뉴 열기, 브라우저 백그라운드 전환, `pagehide` 시점에 저장을 시도합니다. **5초는 실제 벽시계 시간이 아니라 전투 시간**입니다. 배속에 따라 실제 저장 간격이 달라지고, 일시정지 중에는 전투 시간이 흐르지 않습니다.

새로고침·재방문 시 호환되는 저장이 있으면 저장된 전투를 **일시정지 상태**로 열고 전장·웨이브·생명·골드·경과 시간을 보여 줍니다. 사용자가 이어하기를 선택한 뒤 시간이 진행됩니다. 게임을 닫아 둔 시간만큼 적 이동이나 스킬 충전을 추가하지 않습니다. 다른 전장에 출전하거나 다시 시작하면 현재 전투 슬롯을 교체하며, 전투가 끝나면 이어하기 슬롯을 지웁니다.

저장에는 타워·병력·적, 진행 거리, 영웅 관계, 투사체와 대기 이벤트, 상태 이상, 능력·시설 타이머, 난수 상태, 판매한 타워의 통계까지 포함됩니다. 구성 데이터 지문과 버전·참조를 검사하므로, 전투 데이터가 다른 빌드나 손상된 파일을 무조건 적용하지 않습니다. 복원 범위와 형식은 [v18 전투 저장 문서](docs/CHECKPOINT_V18.md)에 있습니다.

### JSON 백업 가져오기와 내보내기

설정의 **백업 내려받기**는 최고 기록·진행 기록과 현재 이어갈 수 있는 전투를 `KingdomRush_Save_v18_YYYY-MM-DD.json`으로 내려받습니다. 끝난 전투의 실행 상태는 포함하지 않습니다. 파일을 다른 브라우저의 설정에서 선택하면 형식·버전·크기·전투 호환성을 검사한 뒤 가져올 내용을 먼저 표시합니다.

| 선택 | 적용 방식 |
|---|---|
| 기록만 합치기 | 전장/모드별 최고 별·최고 처치와 더 좋은 상세 기록을 병합하며 현재 전투는 유지 |
| 기록과 전투 가져오기 | 기록을 병합하고 백업의 전투로 현재 전투를 교체; 일시정지 상태로 열기 |

어느 선택에서도 **현재 브라우저의 설정과 별 강화 배분은 유지**합니다. 상세 기록은 별, 남은 생명, 완료 시간을 순서대로 비교하며 낮은 기록으로 기존 최고 기록을 덮어쓰지 않습니다. 백업에 진행 중인 전투가 없으면 기록 병합만 제공합니다. 이 기능은 수동 파일 이동이며 온라인 계정 동기화 기능은 포함하지 않습니다.

브라우저 저장을 사용할 수 없을 때도 현재 세션의 플레이와 백업 내보내기를 사용할 수 있습니다. 화면의 저장 상태를 확인하고 보관할 기록은 JSON으로 내보내세요. 페이지가 강제로 종료되거나 운영체제가 브라우저를 중단하면 마지막 저장 이후의 조작은 남지 않을 수 있습니다.

## 전투 결과 읽기

결과에는 처치·생명·시간 외에 피해 유형별 구성, 통과한 적, 실제 생명 손실, 누적 지출, 주문 사용, 활약한 방어 시설을 표시합니다. **통과한 적의 개체 수**와 **잃은 생명**을 별도로 집계하므로 생명 비용이 큰 적이나 마지막 생명을 넘는 통과 피해를 구분할 수 있습니다.

타워를 판매해도 해당 타워가 이미 입힌 피해·처치가 사라지지 않습니다. 판매 전에 발사한 투사체와 지속 피해가 나중에 적중하면 기존 타워의 통계에 귀속합니다. 결과에서 판매 여부를 표시하고 일반 타워와 특수 시설의 유효 피해를 비교합니다. 결과의 추천 문장은 통과한 적의 종류·생명 손실·방어 특성을 바탕으로 제시하는 웹 플레이 피드백입니다. 원작의 최적 배치를 실측한 공략으로 취급하지 않습니다. 자세한 집계 기준과 회귀 항목은 [v18 엔진 문서](docs/ENGINE_V18_NOTES.md)에 있습니다.

## 데이터 복원과 미확정 범위

### 편성과 입구

260개 웨이브 슬롯의 선택된 최초 편성은 **10,443개체**이며 v14의 후보 선택 수량을 유지합니다. 소환체와 어둠의 탑의 후속 보스는 이 합계에 포함하지 않습니다. 13개 충돌 슬롯은 후보와 선택 기록을 그대로 보존하며, 선택한 후보가 원작의 정답으로 확정되었다고 처리하지 않습니다.

현재 실행 편성은 **797개 그룹**입니다.

- **325개 그룹**은 원문 입구 라벨을 복원 지도 경로에 연결합니다.
- **22개 그룹**은 가시 이동 경로가 하나인 맵에서 그 경로에 연결합니다.
- 나머지 **450개 그룹**은 입구별 배분을 복원하지 못했습니다. 복원 지도에서 동굴·거미 숲의 특수 접근로를 제외한 일반 주경로에 결정적으로 균등 배분합니다. 도감에는 입구 배분 미확인으로 표시하며 런타임 상태값은 `custom_primary_route_distribution`입니다.

이 배분은 전체 개체 수를 유지하기 위한 웹 실행 규칙입니다. 동굴이나 동쪽 거미 접근로에 적을 무작위로 추가하지 않습니다. 확인된 입구가 있는 그룹의 경로는 그대로 유지합니다. 생성 간격과 그룹 간 시차는 별도로 작성한 실행값입니다.

## 빌드와 검증

Python 3과 Node.js가 있는 환경에서 프로젝트 폴더를 열고 실행합니다. 외부 패키지 설치는 필요하지 않습니다.

```bash
python3 tools/prepare_data.py
python3 tools/build.py
node tests/engine.test.js
node tests/camera.test.js
node tests/picking.test.js
node tests/checkpoint.test.js
node tests/progress.test.js
```

`src/data.js`가 이미 포함되어 있으므로 데이터 변환 없이 `python3 tools/build.py`만 실행해도 HTML을 만들 수 있습니다. 결과는 `dist/index.html`입니다. 전달용으로 같은 파일을 `KingdomRush_Playable_v18.html`이라는 이름으로 보관할 수 있습니다.

번들에 포함되는 순서는 `data.js`, `engine.js`, `camera.js`, `picking.js`, `checkpoint.js`, `progress.js`, `render.js`, `atlas.js`, `app.js`입니다. 이 순서에서 각 모듈의 브라우저 전역 API를 연결합니다. 외부 CDN·모듈 가져오기·런타임 데이터 다운로드를 사용하지 않습니다.

v14 추출 폴더에서 참조를 새로 읽으려면 `python3 tools/prepare_data.py --source /path/to/KingdomRush_v14`를 사용합니다. 지형 파일의 원문 좌표·시각 추정 경로·출처는 별도 보존됩니다.

### 현재 v18 브라우저 UI 확인

데스크톱에서 건설·전투 시작, 자동 저장·새로고침·이어하기, 실제 JSON 다운로드·가져오기, 확대 전체 지도의 클릭·방향키 이동을 확인했습니다. 360/390px 크기에서는 가로 넘침이 없었고 360px에서 타워 선택과 도감 열기를 확인했습니다. 정상 엔진 재생으로 만든 마지막 적 직전 백업을 UI로 가져와 재개하여 데스크톱/360px에서 3별·20생명·56처치 결과와 피해/타워 성과, 다음 전장 진입을 관찰했습니다. 처음부터 수동 완주한 검증과 구분하며, 실제 모바일 기기·Safari·두 손가락 제스처·전체 전장 밸런스는 검증 범위에 포함하지 않았습니다. 상세 관찰은 [v18 브라우저 검증 문서](tests/browser-qa-v18.md)에 있습니다.

### 이전 v16·v17 회귀 근거 — 역사 기록

v17 당시 **엔진 회귀 검증 41개와 카메라 좌표 검증 4개**가 통과했습니다. v16의 34개 엔진 검증에 시설 구매·전투·이벤트·전체 Silveroak 재생 7개 시나리오를 추가한 기록입니다. 당시 구매 실패 시 상태 보존, 모드 제한, 참조 수치, 해금, 별 강화, 공격 선택, 원거리 적, 피해·면역·저지, 소환·보스, 재현성, 웨이브 편성 보존과 입구 배분을 확인했습니다. v16의 12맵 × 2지형 렌더 검사와 v17의 카메라·시설·이벤트 검사 기록은 각 버전 문서에 보존합니다.

다음은 **일반 난이도, 복원 지도, seed 42, 별 강화 0, 실험실 미사용**의 Southport 캠페인 회귀 시나리오 결과입니다. 시간은 1/60초 고정 스텝의 시뮬레이션 시간입니다.

| 규칙 | 배치·명령 | 남은 생명 | 처치 | 시간 | 별 |
|---|---|---:|---:|---:|---:|
| 웹 지원 | B5 궁수 1 + C3 마법 1 + B3 병영 1; 추가 구매·스킬 사용 없음 | 20 | 56 | 174.40초 | 3 |
| 자료 기준 | 같은 초기 배치; 골드 100 도달 시 E3 마법 1 추가; 영웅 없음 | 19 | 55 | 173.98초 | 3 |

**v17에서 추가한 전체 캠페인 회귀:** 은빛 참나무 숲, 일반/웹 지원/복원 지도, seed 42, 별 0, 실험실 미사용. 실제 골드로 시설과 일반 타워를 구매하고 스킬·재고용을 사용하는 시나리오가 **446.12초, 생명 20, 별 3**으로 승리했습니다. 엘프는 유료 9회 고용되어 153기를 처치했습니다. 이 시나리오는 현재 자동 검증에도 남아 있으며 재실행 기록은 `tests/test-report.txt`에서 확인할 수 있습니다.

실제 UI는 다른 초기 시드를 사용하므로 위 숫자는 고정된 자동 검증 시나리오의 결과입니다. 전체 36개 모드의 난이도를 모두 완주 검증하거나 원작과 일치한다고 보장하는 결과는 아닙니다.

`data/BALANCE_NOTES.md`, `data/balance-validation.json`, `tools/balance_probe.js`는 **v15 웹 전용 지형과 당시 규칙의 역사 자료**입니다. 그 안의 공터 번호·완주 수치·권장 배치를 이후 복원 지도의 검증 결과로 사용하지 않습니다. 현재 변경의 회귀 기준은 위 다섯 테스트 파일과 v18 구현·검증 문서입니다.

### 이전 v17 브라우저 UI 확인 — 역사 기록

v17 당시 데스크톱 Chrome에서 Silveroak 시설 선택·수리·고용·집결·전투 시작, 확대·드래그·전체 보기, Stormcloud 마법사 고용·선레이 조준·101 표시 피해(평균 100.5)·19초 충전을 확인한 기록입니다. 모바일 크기 360/390px iframe에서는 가로 넘침 없이 표시하고, 360px에서 2배 확대·복귀와 시설 구매·도감 열기를 확인했습니다. 당시 도감 모달의 clientWidth와 scrollWidth는 모두 319px였습니다. 이는 v18 변경 후 UI의 확인 결과를 대신하지 않습니다. 자세한 과거 관찰은 [v17 브라우저 기록](tests/browser-qa-v17.md), [v16 브라우저 기록](tests/browser-qa-v16.md)에 남아 있습니다. 실제 손가락 두 개의 제스처, 모바일 Safari와 실기기 성능은 이 과거 기록으로 검증되었다고 처리하지 않습니다.
