## 결과 화면 재현 방법

결과 UI를 빠르고 반복 가능하게 확인하기 위해, `tests/engine.test.js`와 같은 seed42 남부 항구 정상 플레이를 Node에서 재생했다. B5 궁수1, C3 마법1, B3 병영1, 별 강화0, 추가 명령/실험실 사용 없이 55처치 시점(173.7833초, 마지막 적1기)에 `KRCheckpoint.capture`로 백업을 만들었다. 파일 선택기로 가져오기→전투 이어하기→남은 적 처치의 실제 UI 흐름으로 56처치/3별 결과를 관찰했다. 전체 캠페인을 이번 브라우저 세션에서 처음부터 손으로 완주했다고 표현하지 않는다.

## 한계

- 360/390px 검증은 브라우저 iframe 크기 검증이며 실제 스마트폰 OS·터치 하드웨어 검증이 아니다. 실제 두 손가락 제스처, 모바일 Safari, 저사양 기기 성능은 확인하지 않았다.
- 터치 반경의 확대 독립성과 공중·화면 밖·사망 표적 배제는 `picking.test.js`의 4개 좌표 시나리오로 별도 확인했다. 브라우저 마우스 클릭을 실제 터치 하드웨어 검사로 세지 않는다.
- 모든 12전장×3모드×3난이도의 수동 완주·밸런스 인증은 수행하지 않았다. 자동 정상 플레이 및 저장 비교 범위는 `test-report.txt`를 참조한다.
- 브라우저 저장 금지/용량 초과의 실제 환경 재현은 수행하지 않았다. 코드에서 실패를 처리하며 내보낸 JSON으로 수동 보관할 수 있다.
- 한 슬롯 저장이므로 여러 탭의 전투는 같은 출처의 저장을 공유한다. 검증용 다중 iframe은 제품에 포함하지 않는다.
- 미리보기용 `qa-mobile.html`과 결과 재현용 임시 JSON은 배포·소스 ZIP에서 제외한다.
