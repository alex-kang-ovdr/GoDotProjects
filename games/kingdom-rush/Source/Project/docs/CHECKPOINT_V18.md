# v18 전투 이어하기 저장 형식

`src/checkpoint.js`는 브라우저 DOM, 저장소, 외부 패키지에 의존하지 않는 전투 스냅샷 모듈이다. 현재 전투 엔진의 상태를 저장하고 복구한다. 원작 게임의 저장 형식을 복원한 기능은 아니다. 진행도 및 별 업그레이드 기록의 v15–v18 이관은 별도 진행도 모듈이 담당한다.

## API

엔진 스크립트 뒤에 모듈을 불러온다. 브라우저 전역과 Node CommonJS에서 같은 API를 제공한다.

```js
const payload = KRCheckpoint.capture(world);
localStorage.setItem('battle', JSON.stringify(payload));

const metadata = KRCheckpoint.describe(KR_DATA, payload);
if (metadata.valid) {
  world = KRCheckpoint.restore(KR_DATA, payload);
}
```

| API | 동작 |
| --- | --- |
| `capture(world)` | `ready` 또는 `playing` 전투를 JSON에 바로 넣을 수 있는 일반 객체로 반환한다. 유효하지 않거나 종료된 전투는 오류를 던진다. |
| `restore(data, payload)` | 일반 객체 또는 JSON 문자열을 검증한 뒤 새 `KRWorld`를 반환한다. 오류는 `KRCheckpointError`이며 `code`와 한국어 메시지를 제공한다. |
| `describe(data, payload)` | 전체 검증 후 안전한 표시용 메타데이터를 반환한다. 오류를 던지지 않고 `{valid:false, reason, code}`를 반환한다. |
| `supportedVersion` | 정수 `18`. 이전 전투 스냅샷 형식은 자동 변환하지 않는다. |

유효한 메타데이터에는 `valid`, `version`, `capturedAt`, `stageId`, `stageName`, `mode`, `difficulty`, `ruleset`, `layout`, `state`, `time`, `wave`, `totalWaves`, `lives`, `maxLives`, `gold`, `cheated`, `towerCount`, `enemyCount`, `heroEnabled`가 들어간다. `capturedAt`은 저장 시각의 Unix 밀리초이고 `time`은 전투 시뮬레이션 경과 초이다. 원본 payload의 임의 문자열이나 실행 코드를 UI에 반환하지 않는다.

## 복원 범위

전투 옵션으로 새 `KRWorld`를 구성한 다음 명시적으로 허용한 런타임 필드를 복원한다. 골드와 건설 이력만 재생하는 방식이 아니므로 진행 중인 전투의 타이밍이 유지된다.

| 상태 | 복원하는 값 |
| --- | --- |
| 시뮬레이션 | 난수 시드, 개체 ID 일련번호, 경과 시간, 현재 웨이브, 다음 호출 타이머, 호출 잠금, 초기 웨이브 시작 시각 |
| 전장 옵션 | 전장, 모드, 난이도, 규칙 프로필, 요청한 지형 프로필, 실제 지형 프로필을 결정하는 원본 데이터, 별 업그레이드 |
| 경제 및 승패 | 골드, 생명, 최대 생명, 보스 소환 여부, 개발자 설정 사용 여부 |
| 타워 및 병력 | 타워 단계, 능력 단계와 개별 재사용 대기시간, 집결점, 병사 소유자, 영웅 이동 명령·경험치·사망/복귀 타이머 |
| 적 | HP, 경로와 진행 거리, 상태 이상, 지속 피해, 보스 단계, 소환자와 발생 이벤트, 공격·특수 능력 타이머 |
| 공격 | 비행 중인 아군/적군 투사체, 아직 발생하지 않은 적 등장, 유성, 지면 피해, 클러스터 폭발 |
| 시설 및 이벤트 | 엘프 훈련소 수리와 고용, 태양광선 인원과 재사용 대기시간, 화산 이벤트 일정·기록, 이미 생성된 이벤트 전용 경로 |
| 통계 | 처치, 피해, 적 종류별 누수, 실제 생명 손실, 지출, 주문 사용, 웨이브 이력, 판매한 타워의 누적 성과 |
| 표시 상태 | 현재 효과와 최근 알림. 카메라/메뉴/선택된 버튼 등 UI 상태는 앱에서 관리한다. |

`world.hero`와 `world.units`의 영웅 항목은 복원 후에도 **같은 객체**이다. 영웅 사용이 금지된 모드에서는 비활성 영웅을 별도로 복원하고 병력 배열에 넣지 않는다. `availableTowerIds`는 실제 `Set`으로 복원한다.

`Infinity`는 일반 JSON에서 손실되므로 `{"$number":"Infinity"}`로 저장한다. 비활성 영웅의 `deadUntil` 및 자동 복귀하지 않는 엘프의 `respawn`/사망 타이머에만 허용한다. 다른 위치의 비유한 수치, `NaN`, 음의 무한대는 거부한다.

기본 경로와 구성요소 정의는 저장 파일에서 덮어쓰지 않는다. 데이터와 생성자로 다시 구성한다. 화산 경로는 저장된 이벤트 ID/순서를 확인한 뒤 엔진의 `eventPath()`로 같은 좌표와 길이를 재생성한다. 기본 웨이브 경로 목록은 늘어나지 않는다.

## 검증과 호환성

파일에는 형식 식별자 `kingdom-rush-battle`, 정수 버전 `18`, 구성 데이터 체크섬, 전장 및 옵션, 명시적인 런타임 상태가 들어간다. 체크섬은 버전, 전투 구성요소, 웨이브, 모드 규칙, 해금 조건, 지형 좌표, 시설/이벤트를 정렬한 JSON에 대해 계산한다. 전투에 쓰는 데이터가 바뀌면 이전 스냅샷을 거부한다. 체크섬은 호환성을 확인하는 용도이며 변조 방지 서명은 아니다.

자동 저장 때마다 큰 구성 데이터를 직렬화하지 않도록 `capture`는 전투 객체별 체크섬을 캐시한다. 전투 중 구성 정의는 고정이라는 엔진 전제를 사용하며, 새 전투나 데이터 객체/버전 교체 때 다시 계산한다. `restore`와 `describe`는 이 캐시를 사용하지 않고 항상 현재 데이터를 새로 검사한다. 같은 데이터 객체의 하위 수치가 수정된 경우도 로드 시 불일치를 검출한다. 런타임 개체·타이머·참조 검증은 자동 저장 때마다 계속 수행한다.

검증은 새로운 월드에 값을 적용하기 전에 수행한다. 지원하지 않는 필드, 모드와 프로필, 누락된 필수 필드, 잘못된 정의 ID, 중복 개체 ID, 존재하지 않는 병력 소유자, 잘못된 건설 부지, 잘못된 경로, 허용되지 않는 능력 단계, 불가능한 영웅 관계를 거부한다. 원본 데이터 정의나 엔진 메서드에 payload 객체를 통째로 대입하지 않는다.

이미 죽은 적을 향한 화살, 판매한 타워가 쏜 투사체, 사라진 지원군을 향한 적의 투사체는 정상적인 상태다. 이 참조는 해당 개체가 현재 배열에 없어도 일련번호 범위 안에 있으면 보존한다. 현재 존재하는 개체를 참조할 때는 유형도 확인한다. 병력의 소유 타워/시설처럼 반드시 살아 있어야 하는 참조는 실제 개체를 요구한다.

입력은 최대 2,000,000 JSON 문자, 180,000 방문 노드, 16단계 깊이로 제한한다. 개별 상한은 타워 128, 시설 32, 적 4,096, 병력 512, 투사체 8,192, 대기 이벤트 12,000, 화면 효과 300, 전장 이벤트 32, 이벤트 로그 24개이다. 문자열·좌표·타이머·개체 ID에도 별도 범위를 적용한다. 순환 참조, getter, `__proto__` 등의 프로토타입 관련 키는 거부한다. JSON 문자열을 파싱할 때도 먼저 크기를 확인한다.

`capture`, `restore`, `describe`는 호출자가 넘긴 payload를 수정하지 않는다. 복원된 런타임 배열과 객체는 저장 객체와 독립적이다. 구성 데이터와 기본 경로의 불변 정의만 엔진의 기존 방식대로 참조한다.

## 앱 연동 원칙

앱은 진행 중인 전투를 일정한 시뮬레이션 시간 간격, 주요 사용자 행동, 메뉴 복귀, 페이지 이탈 시점에 저장할 수 있다. 저장소 용량 오류는 앱이 처리하고, 이전의 유효한 저장 파일을 유지해야 한다. 전투가 끝났거나 사용자가 새 전투를 명시적으로 시작하면 이어하기 저장을 앱 정책에 맞춰 지운다. 페이지를 열 때 저장 파일을 임의로 즉시 실행하지 않고 메타데이터로 이어하기 선택을 표시할 수 있다.

복원 시 실제 시간 경과를 시뮬레이션에 더하지 않는다. 예를 들어 재사용 대기시간 10초를 남기고 닫으면 다음 접속에도 10초에서 이어진다. 시뮬레이션은 앱이 실행을 재개할 때부터 진행한다.

## 검증 실행

```sh
node tests/checkpoint.test.js
node tests/engine.test.js
```

회귀 검증은 두 규칙 프로필의 남부 항구 일반 캠페인을 같은 프레임에서 분기하여 계속 진행하고, 결과·난수 시드·ID·병력·공격·통계가 동일한지 비교한다. 이외에 12개 전장의 3개 모드와 2개 규칙 프로필, 비활성 영웅, 비행 중 공격과 대기 유성, 지속 피해와 보스 단계, 판매된 타워의 공격 귀속, 시설, 화산 이벤트 경로, 입력 불변성, 손상 데이터 거부를 확인한다.
