# v17 전투 엔진: 특수 시설과 화산 이벤트

## 적용 범위

`src/engine.js`는 DOM에 의존하지 않는 고정 시간 단계 시뮬레이터다. v16의 타워 20상태, 적 34정의, 일반 웨이브 260개 및 레이아웃을 유지하면서 `KR_DATA.specialComponents`를 실행한다. 특수 시설 수치는 공개 커뮤니티 자료의 **후보값**이며 원작 실행 파일에서 측정한 확정값이 아니다. 필드별 출처와 미확정 항목은 `data/special-components-v17.json` 및 `docs/SPECIAL_COMPONENTS_v17.md`에 있다.

특수 시설은 `layout:'reconstructed'`일 때 기록된 특수 지점에만 생성한다. 기존 authored 레이아웃에 임의의 시설 좌표를 추가하지 않는다. Silveroak의 Iron 모드에서 보고된 두 번째 엘프 시설은 위치를 복원하지 못했으므로 B8 한 곳만 실행한다. 원본 시설·별 강화의 플랫폼 차이가 모두 해결되었다는 의미는 아니다.

## 시설 API

`world.facilities`의 시설 객체는 다음 필드를 가진다.

```js
{
  id, siteIndex, type, x, y,
  restored, workers, cd, cooldown,
  rally: {x, y}, damage, kills, shots, invested, disabled
}
```

`id`는 타워·유닛과 공유하는 세션 내부 숫자 식별자다. UI 지점 번호와 혼동하지 않도록 `getFacilityAtSite(siteIndex)`로 찾는다. 시설 정의는 `facilityDef(facilityOrId)`에서 반환하며 실행 수치는 그 정의의 `.runtime`이다.

| API | 동작 |
| --- | --- |
| `getFacility(id)` | 시설 객체 또는 `null` |
| `getFacilityAtSite(siteIndex)` | 해당 건설 지점의 시설 또는 `null` |
| `facilityDef(facilityOrId)` | 출처 정보와 runtime을 포함한 구성요소 정의 |
| `facilityInfo(facilityOrId)` | UI용 현재 비용·인원·피해 범위·재충전·생존 유닛 ID |
| `facilityRallyRange(facilityOrId)` | 현재 적용 중인 집결 반경 |
| `restoreFacility(id)` | 엘프 훈련소 수리. 유효성 확인 뒤 골드를 차감 |
| `hireFacilityUnit(id)` | 엘프 1명 또는 태양광선 마술사 1명 고용 |
| `setFacilityRally(id, x, y)` | 가까운 길 위로 엘프 집결 지점을 투영 |
| `fireSunray(id, enemyId)` | 특정 살아 있는 적 1명에 발사 |
| `fireSunray(id, x, y)` | 선택 좌표 반경 안의 가장 가까운 적 1명에 발사 |

변경 API는 `{ok, message}`를 반환한다. 잘못된 ID, 종료된 전투, 골드 부족, 최대 고용 인원, 발사 재사용 대기, 비어 있는 표적 선택은 비용·인원·쿨다운·발사 횟수를 변경하지 않는다. `facilityInfo().count`는 엘프의 경우 살아 있는 고용 병력 수, 태양광선 탑의 경우 마술사 수다.

## 실반 엘프 훈련소

- 수리 100골드, 고용 100골드, 생존 인원 최대 4명이다.
- 일반·베테랑 HP 100, 캐주얼 HP 120 후보를 적용한다. 근접 피해 25–50 / 1초, 화살 26–50 / 1.5초를 사용한다.
- 피해는 엔진의 기존 정책에 따라 범위 평균으로 고정한다. 원작 난수 분포의 복원이 아니다.
- 엘프는 지상 적을 저지하며 원거리에서는 지상·비행 적에게 화살을 쏜다. 이미 근접 공격 사거리의 적과 교전 중이면 화살을 동시에 발사하지 않는다.
- 화살의 보고된 최소/최대 거리 50/205 및 기본 집결 거리 145를 웹 좌표계에 적용한다. 원작 거리 단위와 동일하다고 확정하지 않는다.
- 비전투 2초 후 초당 20HP를 회복한다. 화살 발사와 피격도 전투 시각을 갱신한다.
- 사망한 엘프는 자동 부활하지 않는다. 고용 슬롯이 비고 사용자가 다시 골드를 지불해야 한다. 사망 유닛은 다음 업데이트에서 제거된다.
- 병영의 개선된 배치가 활성화되면 집결 반경 후보 배수 1.2를 적용한다. 가시 갑옷은 엘프가 실제 잃은 HP에 의해 잘리지 않은 **입력 피해량**의 10%를 반사한다. 이는 기존 일반 병영 반사 계산을 바꾸지 않는다.
- 이동 속도 85 world units/s, 경로 투영 및 충돌 처리는 웹 구현 보정이다.

## 태양광선 탑

수리 없이 선택 가능한 상태에서 시작한다. 마술사는 1명당 100골드, 최대 4명이다. 고용 직후 충전 대기를 0으로 만들어 발사할 수 있다. 시설은 자동 공격하지 않으며 전투 중 사용자가 적을 선택해야 한다.

| 마술사 수 | 보고된 피해 범위 | 엔진 고정 평균 피해 | 발사 후 재충전 |
| --- | ---: | ---: | ---: |
| 1 | 76–125 | 100.5 | 19초 |
| 2 | 126–175 | 150.5 | 16초 |
| 3 | 176–225 | 200.5 | 13초 |
| 4 | 226–275 | 250.5 | 10초 |

지상·비행 적 1명을 전장 거리 제한 없이 공격한다. 고정 피해 유형인 `true`는 방어력과 마법 저항을 무시하며, 기존 엔진의 보호막 규칙은 유지한다. 즉사 효과가 아니므로 보스도 해당 피해량만 받는다. 주변 적에게 광역 피해를 주지 않는다. 터치 선택 반경 38은 웹 UI 보정이며 원작 데이터가 아니다.

시설이 누적한 피해·처치·발사 횟수는 시설 객체에 집계한다. 엘프가 가한 근접·원거리 피해도 고용 시설에 귀속한다.

## Forsaken 화산 이벤트

기존 v14 후보 이벤트 `forsaken_lava`의 첫 웨이브 시작 후 400초, 이후 120초마다 마그마 정령 1마리라는 간격을 사용한다. 세 가지 모드에 적용되며 준비 화면에서는 시간이 흐르지 않는다. 일시정지 시 앱이 `world.update()`를 호출하지 않으므로 이벤트 시계도 멈춘다.

`world.stageEventState`의 실행 상태는 다음과 같다.

```js
{
  id, nameKo, enabled,
  status: 'waiting' | 'armed' | 'stopped',
  nextAt, remaining, count, occurrences,
  routeIndex, warningIssued, definition
}
```

- `waiting`: 준비 상태. `nextAt:null`, `remaining:400`.
- `armed`: 첫 `callWave()`에서 `battleStartedAt`을 기록하고 절대 시뮬레이션 시각 `nextAt`을 설정한다. `remaining`은 업데이트 때 갱신된다.
- `count`: 이 이벤트로 생성한 적의 누계. `occurrences`는 발생 횟수다.
- `stopped`: 승리 또는 패배. `nextAt`과 `remaining`을 `null`로 바꾸고 추가 생성하지 않는다.

분출 10초 전 알림은 웹 편의 기능이다. 이벤트 적은 `sourceEventId:'forsaken_lava'`, `sourceWave:null`, `sourceEntryLabel:'volcano'`로 표기하므로 일반 웨이브 원본 수량에 섞이지 않는다. 기본 마그마 정령 보상 골드를 유지한다.

복원 레이아웃에서는 v16에서 시각 추정한 `volcano_connector`를 서쪽 본선의 세 번째 점 이후에 연결한다. 이 경로는 이벤트 발생 시 `world.paths`에 한 번만 추가한다. `world.stage.paths`, 소스 경로와 `primaryPathIndices`를 변경하지 않으므로 일반 웨이브는 기존 경로로만 출현한다. **항상 서쪽을 선택하는 것은 웹 보정이며 원작 좌우 선택 확률의 복원이 아니다.** authored 레이아웃에서는 첫 주 경로 입구로 생성하고 `custom_authored_primary_entry`로 표시한다.

일반 웨이브와 현재 생존 적을 모두 처리하여 마지막 웨이브가 비었으면, 미래 분출 대기와 관계없이 승리한다. 같은 시간 단계에서 마지막 적이 처리되었을 때도 승리를 먼저 확인한다. 따라서 반복 이벤트가 무한히 승리를 막지 않는다.

`world.eventLog`는 최근 24개 발생 기록을 유지한다.

```js
{id, time, eventId, label, enemyId, count, x, y, routingStatus}
```

전투 결과에는 `facilityHires`, `sunrayShots`, `stageEventSpawns`를 추가한다. 개발자 쿨다운 초기화는 태양광선에도 적용하며 기존처럼 실험 기록으로 표시한다.

## 검증 결과

`node tests/engine.test.js`에서 **41개 테스트**가 통과했다. 기존 34개 테스트의 기대치를 바꾸지 않고 새로운 7개 시나리오를 추가했다.

1. 기록된 위치·모드에서만 시설을 생성하고 authored 레이아웃은 유지한다.
2. 수리·고용 실패의 비용 원자성, 최대 인원, 사망 후 자동 부활 금지 및 유료 재고용.
3. 엘프의 지상 저지, 대공 화살, 회복 지연, 집결 범위, 치명타에도 입력 피해량을 기준으로 한 가시 갑옷 반사.
4. 태양광선의 준비·고용·충전 상태, 방어/저항이 높은 비행 적에 대한 원거리 단일 고정 피해, 새 마술사 고용 즉시 충전, 종료 후 동작 금지.
5. 첫 웨이브 기준 400/120초 타이머, 독립 이벤트 출처·보상, 연결로 재사용, 일반 경로와 수량 보존.
6. 미래 이벤트가 마지막 웨이브 승리를 지연시키지 않으며 authored 보정 경로를 명시한다.
7. 실제 골드로 시설을 수리·고용하고 일반 타워·주문을 병행해 Silveroak 전체 일반 캠페인을 완주한다. seed 42의 assisted/reconstructed 설정, 영구 강화 0, 치트 없이 446.12초·20생명·3별로 승리했다. 엘프 시설은 9회 유료 고용, 153처치, 약 9,481.64 피해를 기록했다.

기존 Southport 정상 플레이 검증도 유지된다. 이 검증은 모든 12개 스테이지의 전체 난이도 균형이 확정되었다는 뜻은 아니다. 묘지 부활 영역과 JT 반복 증원 간격처럼 미확정인 이벤트는 v14 정의를 보존하고 실행하지 않는다.
