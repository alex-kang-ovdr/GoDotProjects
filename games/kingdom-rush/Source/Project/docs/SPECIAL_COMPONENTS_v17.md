# v17 특수 시설·전장 이벤트 데이터

## 범위

v16에서 위치만 표현하던 **Silveroak Forest의 실반 엘프 훈련소**, **Stormcloud Temple의 태양광선 탑**을 실행 가능한 시설 데이터로 확장한다. Forsaken Valley의 주기적 화산 출현도 별도 이벤트로 연결한다.

정규 타워 20개 상태, 기존 웨이브 260개 및 시작 적 수를 수정하지 않는다. 고용된 아군과 이벤트 추가 적은 기존 웨이브 집계와 구분한다. 이 문서의 숫자는 특정 원본 빌드에서 측정한 확정값이 아니라 공개 자료의 후보값이며, 개별 필드의 근거는 [special-components-v17.json](../data/special-components-v17.json)에 있다.

## 데이터 계약

`KR_DATA.specialComponents`에 JSON 전체를 삽입한다. `schemaVersion`은 17이다.

| 경로 | 용도 |
| --- | --- |
| `facilities[id].sourceFacts` | 문서에서 확인한 후보값. 미확정 이동 속도 등은 null을 보존 |
| `facilities[id].runtime` | 웹 엔진이 사용하는 값. 실행에 필요한 보정값 포함 |
| `facilities[id].placement` | v16에서 기록한 시설 지점과 모드별 복원 범위 |
| `facilities[id].fieldProvenance` | 필드별 출처, 자료 상태, 보정 이유 |
| `stageEvents[]` | 시간 원점과 반복 조건이 있는 이벤트 |
| `unresolved[]` | 미확정 배치, 시점, 영역 등 |

`secondary_candidate`는 커뮤니티 자료에서 확인했지만 대상 원본 빌드에서 직접 검증하지 않았다는 의미다. `custom_web`은 웹판 구현을 위해 선택한 값이다. `source_number_custom_world_units`는 보고된 수치를 웹 좌표계에 적용했으며 원작 거리 단위와의 관계를 확인하지 못한 경우다.

## 시설의 행동

### 실반 엘프 훈련소

복원 지점은 Silveroak B8이다. 시설을 수리한 뒤 엘프를 한 명씩 고용한다. 생존 고용 인원만 한도에 포함되며, 사망자는 자동으로 돌아오지 않는다. 사용자는 다시 비용을 지불해 빈 자리를 채운다.

아군은 집결 위치로 이동해 적을 저지하고, 원거리 조건을 충족하면 비행 적도 사격한다. 근접 사정거리 안에 저지 대상이 있으면 사격을 보류하는 우선순위를 적용해 같은 프레임의 두 공격을 막는다. 이 우선순위는 웹판의 명시적 구현 선택이다. 전투에서 벗어난 뒤 체력을 회복한다. 구체적인 비용·체력·공격·회복값은 JSON의 단일 정의를 따른다. 보고된 집결 거리 145와 사격 최대 거리 205를 1000×620 웹 좌표에 직접 적용하며, 원작 좌표 변환이 검증된 값으로 취급하지 않는다. 웹 이동 속도는 원작 값을 얻지 못해 별도 보정으로 두었다.

별 강화 중 집결 거리와 반사 피해의 적용 후보를 함께 기록했다. 기존 병영의 모든 강화가 엘프에게 자동 적용된다고 가정하지 않는다.

### 태양광선 탑

복원 지점은 Stormcloud A1이다. 시설 자체는 처음부터 존재하며 수리 비용이 없다. 마술사를 추가 고용하면 단계가 높아지고 발사 준비도 즉시 완료된다. 사용자가 살아 있는 적 한 명을 선택해 발사한다. 피해는 지상·비행을 모두 대상으로 하고, 발사 후 현재 단계의 재충전이 시작된다.

빈 공간이나 이미 사망한 적을 선택했을 때 충전은 소모하지 않아야 한다. 연속 클릭이 같은 준비 상태를 중복 사용하지 않도록 발사 성공과 재충전 변경을 원자적으로 처리한다. 선택 보정 반경은 원작 통계가 아닌 웹 입력값이다.

두 시설의 피해 범위는 원자료 후보로 보존하고 실행 시 평균값을 사용한다. 이 결정은 기존 웹 전투의 재현 가능한 계산과 연결하기 위한 보정이며 원작 난수 분포와 같다고 가정하지 않는다.

## 화산 이벤트

`forsaken_lava`는 첫 웨이브 시작을 시간 원점으로 삼는다. 자료의 첫 지연 **400초**, 이후 간격 **120초**를 사용한다. 준비 화면 대기 시간은 포함하지 않는다. 일시정지하면 진행하지 않고, 배속은 시뮬레이션 시간과 함께 적용한다. 시작 적 목록의 마그마 정령과 이벤트 생성 정령은 서로 다른 발생 원인이다. [출처: Forsaken Valley](https://wikily.gg/kingdom-rush/stages/forsaken-valley/)

경로는 v16에서 시각적으로 추정한 중앙 화산의 서쪽 연결로를 본선에 접합하는 웹 구현 규칙이다. 원작의 좌우 분배 확률이나 세부 이동 경로를 복원한 것으로 표시하지 않는다. 기존 본선 목록을 그대로 두고 이벤트 전용 경로를 분리해야 정규 웨이브의 경로 선택에 영향을 주지 않는다. 재구축 이전의 authored 지형에서는 기본 경로 입구를 대체 위치로 사용하며 이 차이를 데이터로 기록한다.

이벤트는 전투 종료 뒤 생성되지 않는다. 다음 이벤트 시간이 남아 있다는 이유로 이미 완수된 전투의 승리를 지연하지 않는다. 10초 예고는 웹판의 편의 기능이며 원작에서 확인한 연출 시간이 아니다.

## 출처를 적용한 범위

- [Ironhide 공식 공략](https://www.kingdomrush.com/kingdom-rush-strategy-guide)은 스테이지와 공식적으로 소개된 공략 영상 링크를 확인한다. 시설의 비용·피해·재충전 수치를 제공하는 문서는 아니다.
- [Scott Louvau의 직접 플레이 분석 저장소](https://github.com/ScottLouvau/kingdomrush)는 v16 지형과 시설 지점의 출처다. 고정 커밋 `a3c8218c19fab8e43596309de31eeeeb4a0bc8d6`의 일반 타워 데이터에는 이번 특수 시설의 전투 수치가 없다. 따라서 해당 저장소를 시설 통계의 근거로 승격하지 않았다.
- [실반 엘프](https://wikily.gg/kingdom-rush/towers/sylvan-elf/)와 [태양광선 탑](https://wikily.gg/kingdom-rush/towers/sunray-tower/) 문서에서 수치 후보를 확인했다.
- [Stormcloud Temple](https://wikily.gg/kingdom-rush/stages/stormcloud-temple/) 문서에서 마술사 고용 직후 발사 준비가 완료된다는 후보 규칙을 확인했다.

확인일은 2026-11-19이다. 공식 페이지의 자료와 커뮤니티 수치를 같은 증거 수준으로 취급하지 않는다. 원작 이미지나 자산은 새 데이터 패키지에 포함하지 않았다.

## 아직 해결하지 않은 항목

[Silveroak Forest 자료](https://wikily.gg/kingdom-rush/stages/silveroak-forest/)는 Iron 모드의 엘프 시설이 두 곳이라고 서술한다. v16의 고정 이미지에서 기록한 B8 한 곳만 구현하며, 두 번째 위치를 임의로 만들어 원작 좌표로 저장하지 않는다. 도전 모드의 기존 궁수탑 및 Stormcloud Iron의 기존 마법사탑도 모드별 좌표가 확인되지 않아 후보 기록으로 남긴다.

묘지 부활은 영역 판정과 최대 체력 기준이 미확정이다. J.T.의 반복 지원군은 시작 지연·반복 간격이 미확정이다. 기존 v14 정의를 보존하며 이번 데이터가 임의의 확정값을 채워 넣지 않는다.

## 검증 기준

시설 비용의 중복 차감 방지, 최대 고용 인원, 사망 후 재고용, 비행 적 사격, 충전 전 발사 거절, 고용 시 즉시 충전, 전장 전체의 단일 표적 피해를 확인한다. 화산은 첫 웨이브 이전 비활성, 정확한 시간 원점, 반복 간격, 전투 종료 후 생성 중단, 정규 웨이브 경로·적 수 보존을 검증한다. 실제 통과 결과는 엔진 테스트 보고서와 v17 변경 기록에서 확인한다.
