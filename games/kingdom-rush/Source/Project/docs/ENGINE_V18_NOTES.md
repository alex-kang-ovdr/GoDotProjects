# v18 전투 결과 집계

## 목적과 범위

이번 변경은 전투가 끝난 뒤 무엇이 통과했고 어떤 타워가 기여했는지 설명하기 위한 집계다. 타워·적의 수치, 웨이브 구성, 피해 계산, 난수 소비 순서, 공격 순서와 승패 조건은 변경하지 않았다. 원작 데이터 복원 범위의 확대를 뜻하지 않는다.

## 누수와 생명 손실

기존 `stats.leaks`는 적의 수가 아니라 탈출한 적의 `lifeCost` 합계였다. 이 필드를 그대로 유지하면서 다음 필드를 추가했다.

| 필드 | 의미 |
| --- | --- |
| `escapedEnemies` | 탈출한 적 개체 수 |
| `leaksByEnemy` | 적 정의 ID별 탈출 개체 수 |
| `leaks` | 탈출한 적의 명목상 생명 비용 합계. 기존 의미 유지 |
| `lifeLoss` | 실제로 차감한 생명 합계 |
| `lifeLossByEnemy` | 적 정의 ID별 실제 생명 차감 합계 |

예를 들어 생명이 1 남았을 때 생명 비용이 3인 오우거 1마리가 통과하면 `escapedEnemies += 1`, `leaks += 3`, `lifeLoss += 1`이다. 무적 실험 상태에서도 통과 개체 수와 명목상 비용은 기록하지만 실제 생명 손실은 0이다. 같은 적을 다시 업데이트해도 중복 집계하지 않는다.

생명 손실의 전장 표시도 고정된 화면 좌표 대신 해당 경로의 실제 출구에 표시한다. 출구가 화면 가장자리에 걸쳐 있으면 글자가 잘리지 않도록 위치를 화면 안으로 제한한다. 글자는 실제 손실을 표시하며 무적 상태에서는 `생명 보호`를 표시한다.

## 타워와 시설의 기여도

`world.towerPerformance()`는 다음 구조의 새 배열을 반환한다.

```js
{
  id,         // 한 전투 안의 고유 건물 ID
  defId,      // 최종 타워 정의 ID 또는 특수 시설 ID
  nameKo,
  kind: 'tower' | 'facility',
  sold,       // 판매된 타워 여부. 시설은 false
  damage,     // 적에게 실제 적용한 HP 손실
  kills,
  invested    // 해당 건물에 누적한 건설·강화·고용 비용
}
```

배열은 피해 내림차순, 처치 내림차순, 건물 ID 오름차순으로 정렬한다. 같은 타워를 강화해도 하나의 건물 ID로 누적하므로 `defId`는 마지막 타워 형태다. 강화 전과 후의 기여도를 분리한 통계는 아니다. 병영 병사와 소환물의 귀속 피해는 소유 타워에, 엘프 병력의 귀속 피해는 훈련소에 합산한다. 영웅·주문처럼 타워에 귀속하지 않는 피해는 전체 피해와 피해 유형별 집계에는 포함되지만 타워 순위에는 들어가지 않는다.

타워를 판매하면 그 시점의 행을 `stats.retiredTowers`에 보존한다. 이미 발사한 탄환이나 부여한 지속 피해가 판매 뒤 적중하면 동일한 건물 ID를 찾아 피해와 처치를 계속 기록한다. 이 보존 객체는 **통계 귀속에만** 사용한다. 판매된 타워는 표적 선정, 강화, 병력 소유권 또는 방어 관통 계산의 활성 타워로 취급하지 않으므로 기존 전투 동작은 유지된다.

`invested`는 개별 건물의 누적 투자 값이며 환급 후의 순지출이 아니다. 미리 배치된 타워의 기존 장부 가치도 포함할 수 있다. 전투 중 실제 구매한 골드는 별도의 `spent`로 표시한다. `spent` 역시 판매 환급을 빼지 않은 총 구매 지출이다.

## 결과 스냅샷

`world.finish()`의 `result`에는 기존 필드에 다음 값을 추가한다.

```js
{
  stageId, mode, difficulty, maxLives,
  leaks, escapedEnemies, lifeLoss,
  leaksByEnemy, lifeLossByEnemy,
  spent, damage, spellCasts,
  towerPerformance
}
```

맵과 기여도 행은 새 객체로 복사한다. 결과 화면을 연 뒤 원래 통계나 타워 객체가 바뀌어도 완료한 전투 결과가 함께 바뀌지 않는다. 저장 모듈은 진행 중인 전투의 새 통계 필드와 판매 기록을 보존하고, 종료된 전투 결과는 엔진이 마지막 상태에서 생성한다.

## 검증

`node tests/engine.test.js`의 **44개 시나리오가 통과**했다. 기존 41개 기대치를 유지하고 다음 3개 시나리오를 추가했다.

1. 서로 다른 두 출구의 생명 손실 위치, 개체 수와 명목 비용·실제 손실의 구분, 마지막 생명의 초과 손실 방지, 무적 상태, 중복 집계 방지.
2. 타워 판매 전 피해와 판매 후 탄환·독 피해의 연속 귀속, 처치와 비용·주문 통계, 완료 결과 객체의 독립성.
3. 태양광선 시설과 일반 타워의 실제 피해 순위, 건물 종류와 고유 ID, 투자 비용, 활성 건물에서 분리된 결과 스냅샷.

기존 정상 플레이 기준도 유지됐다. seed 42, 영구 강화 0, 치트 없음 조건에서 복원 지도 Southport는 assisted 20생명/56처치/174.40초, reference 19생명/55처치/173.98초로 승리했다. Silveroak assisted는 20생명/359처치/446.12초로 승리했고 엘프 시설의 153처치와 약 9,481.64 피해도 유지됐다. 이는 이 세 가지 기존 플레이 시나리오의 회귀 검증이며 전체 스테이지의 균형 검증을 대신하지 않는다.
