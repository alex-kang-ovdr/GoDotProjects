# v16 변경 기록

버전: **16.0.0**  
정리일: **2026-11-18**  
기준: 사용자 제공 v14 복원 자료와 v15 웹 플레이 구현

v16은 기존의 실행 가능한 타워 디펜스에 **근거가 있는 지형·구성 요소 복원, 선택 가능한 규칙, 전장 도감**을 연결한다. 자료 복원 정도와 웹 실행을 위해 작성한 규칙을 화면과 데이터에서 구분한다.

## 1. 원작 레벨 지형 재구축

본편 12개 맵을 대상으로 기록 좌표와 원작 화면의 도로를 다시 연결했다.

| 항목 | v15 | v16 |
|---|---|---|
| 지도 | 자체 작성한 12개 지도 | 복원 지도 12개와 기존 웹 지도 모두 선택 가능 |
| 이동 경로 | 웹용 경로 | 27개 시각 추정 경로, 원좌표·변환값·출처 보존 |
| 건설 위치 | 웹용 공터 | 기록 위치 155개: 일반 공터 152, 기존 탑 1, 특수 시설 2 |
| 지점명 | 배열 순번 | 복원 지도에서 공개 분석 자료의 A9·B8 등 지점명 표시 |
| 종점 | 웹 지도 설계 | 원작 화면에 보이는 파란 목표 표식에 대응 |
| 증거 | v14의 지형 공백을 웹 설계로 보완 | 커밋·이미지 URL·크기·SHA-256·근거 수준을 맵마다 기록 |

좌표 자료의 출처는 Scott Louvau의 공개 MIT 저장소이며 고정 커밋은 `a3c8218c19fab8e43596309de31eeeeb4a0bc8d6`이다. 1920×1080 참고 이미지를 1000×620 월드로 변환하고 원본 픽셀 좌표를 함께 보존했다. 스크린샷은 연구 참고로 확인했으며 배포하지 않는다.

Silveroak E7의 기존 궁수탑은 이미지의 `WAVE 0/15, gold 700, lives 20`이라는 캠페인 근거에 따라 캠페인에서만 선배치한다. Silveroak B8 엘프 훈련소와 Stormcloud A1 태양광선 탑은 `buildable: false` 시설로 분리한다. 특수 시설의 위치는 복원했지만 고유 능력은 구현하지 않았다.

관련 파일: `data/geometry_reconstruction_v16.json`, `docs/LEVEL_RECONSTRUCTION_v16.md`.

## 2. 두 전투 규칙과 두 지도 프로필

다음 선택을 독립적으로 제공한다.

| 축 | 프로필 | 동작 |
|---|---|---|
| 전투 규칙 | `assisted` — 웹 지원 | 시작 골드 보정, 자체 영웅, 자유로운 타워 진화, 기존 웹 강화 |
| 전투 규칙 | `reference` — 자료 기준 | 자료의 시작 골드·영웅 제한·타워 해금·도전 상한·별 강화 적용 |
| 지도 | `reconstructed` — 복원 지도 | 기록 건설 위치와 원작 화면의 시각 추정 경로 |
| 지도 | `authored` — 웹 전용 지도 | v15 자체 지형 유지 |

기본값은 웹 지원 규칙과 복원 지도다. 설정 변경은 다음 출전부터 적용한다. 전투 결과에는 규칙·지도·난이도를 보존한다.

자료 기준 규칙도 원작 실행을 실측한 완전한 복제 모드는 아니다. 이동·사거리 단위, 일부 공격 간격, 생성 타이밍, 보스 및 사건 처리에 웹 보완값이 남는다. 원문 누락·충돌과 보완 사유를 삭제하지 않는다.

## 3. 웨이브 개체 수와 입구 정보 연결

260개 슬롯의 선택된 편성 수량 **10,443개체**를 유지했다. 13개 충돌 슬롯의 후보·선택 기록도 보존한다. 원문 후보 하나를 선택한 사실을 충돌 해결로 표현하지 않는다.

실행 편성 797개 그룹의 경로 연결은 다음과 같다.

| 그룹 | 연결 방식 | 런타임 의미 |
|---|---|---|
| 325 | 관측 입구 라벨 → 복원 경로 | 기록된 입구 대응을 유지 |
| 22 | 가시 경로가 하나인 맵 → 단일 경로 | 입구별 배분 선택이 발생하지 않음 |
| 450 | 입구별 배분 미복원 | 일반 주경로에 결정적 균등 배분 |

총 347개 직접 연결 그룹은 지정된 경로를 유지한다. 미복원 그룹은 동굴 라벨과 Silveroak의 `east_spiders` 경로를 일반 분배 대상에서 제외한다. 이를 통해 근거 없이 짧은 특수 접근로로 일반 적을 보내는 오류를 막는다. 상태값은 `custom_primary_route_distribution`이며 도감에서 입구 배분 미확인으로 표시한다.

입구 라벨을 보완할 때에는 선택된 적 수와 일치하는 관측만 이용한다. 그룹 생성 간격·시작 시차·정확한 서브패스는 별도 웹 실행 규칙이다.

## 4. 타워·몬스터·진행 구성 요소

기존 20개 타워 상태, 18개 전문 능력, 34개 몬스터에 다음 자료를 연결했다.

- 난이도별 HP와 미확정 값의 보존.
- 원문 근접 공격, 원거리 공격 파라미터, 피해 유형과 면역 집합.
- 원거리 적이 병사를 공격하는 실행 동작과 적 투사체 구분.
- 전장 구성 요소, 5개 사건 정의, 9개 해금 이벤트 자료.
- 타워 개방 순서, 원문 모드 설정, 능력의 단계별 파라미터.
- 단계별 편성·HP·공중·방어·저항·원거리·첫 출현 분석.

구성 요소를 조회 가능한 데이터로 저장한 범위와 모든 사건을 원작처럼 실행한 범위를 혼동하지 않는다. 사건 이름·조건이 자료에 있어도 굴 이동·묘지 영역·특수 시설의 고유 기능 등은 추가 구현이 필요하다.

관련 파일: `data/enemy-components-v16.json`, `data/tower-components-v16.json`, `data/progression-components-v16.json`, `data/level-design-v16.json`, `data/DATA_NOTES.md`.

## 5. 별 강화 30개와 웹 강화 18단계

자료 기준 프로필에 6계열 × 5개, 총 **30개 별 강화**의 비용·효과를 연결했다. 기존의 6계열 × 3단계 웹 강화는 웹 지원 프로필에서 유지한다.

같은 획득 별을 두 프로필에 각각 배분하고, 상태를 별도로 저장·초기화한다. 순서대로 구매하며 다음 전투부터 적용한다. 자료 기준 도전 모드에 상한이 있으면 허용 단계까지만 반영한다. 별 강화 상한을 타워의 건설 단계 상한으로 잘못 적용하지 않는다.

범위·가격·환불·병사·지원군·불의 비와 관련된 실행 효과는 엔진에서 계산한다. 렌더러의 집결·유성 미리보기는 `world.rallyRange(tower)`, `world.meteorRadius()`를 사용해 판정 값과 연결한다.

## 6. 전장 도감 추가

새 `src/atlas.js`는 게임 안에서 네 가지 분석 화면을 제공한다.

| 화면 | 기능 |
|---|---|
| 지도 | 12개 지도, 공터 선택, 사거리 조절, 경로 포함 비율, 구성 요소·해금·출처 |
| 웨이브 | 260개 슬롯, 기본 HP 그래프, 개체 수·골드·속성 구성, 입구 연결 상태 |
| 타워 | 20개 상태와 18개 능력, 추가 비용·기본 DPS·공격 간격·웹 사거리·원문 파라미터 |
| 몬스터 | 34종 검색, 공중·방어·원거리·보스 필터, 난이도 HP·행동·캠페인 출현 |

선택한 지도·웨이브·타워·몬스터를 버전·시각·근거 안내와 함께 JSON으로 내보낼 수 있다.

지도 포함 비율은 경로 길이 기준이며 겹친 경로를 각각 합산한다. HP 그래프는 일반 난이도의 최초 편성 합계다. 기본 DPS·사거리 포함 비율·HP 합계는 전투 전체 난이도나 실전 효율을 완전히 나타내는 값이 아니므로 해당 화면에서 산출 범위를 설명한다.

## 7. 전투 지휘와 렌더링

- 공격 타워에 선두·최고 체력·가까운 적·공중 우선 선택을 추가했다. 공격 가능 표적 제한은 그대로 적용한다.
- 타워 선택 패널에 누적 피해와 처치 수를 표시한다.
- `T`로 경로 방향, 입구 번호, 원문 지점명을 표시한다.
- 같은 맵의 지도 프로필을 변경해도 이전 지형 이미지가 남지 않도록 캐시 키에 경로·지점·프로필을 포함한다.
- 특수 시설은 일반 `+` 공터 대신 별도 건물과 이름으로 그린다.
- 영웅 출전이 금지된 모드에서 사망 영웅 표식을 그리지 않는다.
- 적의 화살·마법탄·도끼를 붉은 계열로 구분한다.
- 복원 지도에는 임의의 개울을 생성하지 않고 기록된 강·절벽·보조도로·다리 정보를 사용한다.

그림은 기존 Canvas 절차적 스타일을 확장했다. 원작 이미지·스프라이트·폰트·음원을 추가하지 않았다.

## 8. 저장 이전과 오프라인 빌드

v16 저장 키는 `kr_frontier_v16_progress`다. 해당 기록이 없으면 `kr_frontier_v15_progress`를 읽어 최고 별, 기존 웹 강화, 설정, 튜토리얼 상태를 이전한다. 자료 기준 강화는 별도로 저장하고, 전투 결과는 규칙·지도·난이도를 포함해 구분한다.

최고 별은 전장·모드 단위로 공유하고 반복 클리어로 누적 증식하지 않는다. 실험실을 사용한 전투는 별 기록에 추가하지 않는다. 실시간 전투의 중간 저장과 계정 간 동기화는 구현하지 않았다.

`tools/build.py`가 `data.js`, `engine.js`, `render.js`, **`atlas.js`**, `app.js`를 묶어 `dist/index.html`을 생성한다. CSS·데이터·코드가 모두 포함되어 오프라인 실행 시 외부 다운로드가 필요 없다.

## 9. 검증 결과

**v16 엔진 시나리오 34개가 모두 통과했다.** 기준 파일은 `tests/engine.test.js`다. 데이터 보존, 해금·제한·강화, 공격·면역·표적 선택, 원거리 적, 소환·보스, 결정적 재생, 입구 연결·미복원 분배, 승리·패배 시나리오를 포함한다.

Southport 캠페인에서 일반 난이도, 복원 지도, seed 42, 별 강화 0, 실험실 미사용의 결과는 다음과 같다.

| 규칙 | 검증 명령 | 생명 | 처치 | 시뮬레이션 시간 | 별 |
|---|---|---:|---:|---:|---:|
| `assisted` | B5 궁수 1 / C3 마법 1 / B3 병영 1; 이후 구매·스킬 없음 | 20 | 56 | 174.40초 | 3 |
| `reference` | 같은 초기 배치; 골드 100 도달 시 E3 마법 1 추가; 영웅 없음 | 19 | 55 | 173.98초 | 3 |

UI의 기본 시드는 이 회귀 테스트와 다르므로 정확한 처치 시각을 모든 플레이에 보장하지 않는다. 36개 모드 전체의 균형을 확정한 검증도 아니다.

렌더러는 12맵 × 2지형의 24개 실행 검사, 캐시 전환, 지점 라벨, 특수 시설 분리, 영웅 제한, 적 투사체 색, 집결·유성 범위 API 전달을 확인했다. 가상 Canvas 실행 검사는 브라우저의 실제 픽셀 검토와 구분한다.

`data/BALANCE_NOTES.md`, `data/balance-validation.json`, `tools/balance_probe.js`에 남은 결과는 **v15 당시의 웹 지도·규칙에 대한 역사 자료**다. 해당 공터 번호와 수치를 v16 복원 지형의 현행 검증으로 재사용하지 않는다.

## 10. 남은 원작 재현 범위

다음 항목은 자료로 확인된 부분과 웹 구현을 구분해 유지한다.

- 원본 엔진의 경로 서브패스, 비행 전용 경로, 충돌 마스크, 분기 확률.
- 원작 좌표계와의 사거리·속도·프레임별 이동 비교.
- 웨이브 내부의 정확한 생성 시점과 입구별 동시 출현.
- 특수 시설의 고유 동작, 굴 이동, 묘지·화산·마법진의 정확한 반복 사건.
- 보스 패턴·발동 조건·변신·봉인의 원작 프레임 일치.
- 플랫폼·빌드별 차이와 아직 충돌하는 원문 후보의 확정.

v16의 `reference`는 자료를 더 많이 반영한 실행 프로필이다. 확인하지 못한 동작까지 원작과 동일하다고 표시하지 않는다. 자세한 가정은 `data/DATA_NOTES.md`, `docs/LEVEL_RECONSTRUCTION_v16.md`, `docs/ENGINE_V16_NOTES.md`에 기록한다.
