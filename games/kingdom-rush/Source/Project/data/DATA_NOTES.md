# v16 데이터 복원·재구성 명세

v16은 사용자가 제공한 `KingdomRush_Reconstructed_v14.zip`의 수치·관측 기록을 웹 게임의 실제 실행 데이터에 다시 연결한 빌드다. v15에서 빠졌던 난이도별 HP, 원거리 공격, 면역·특수 행동, 별 업그레이드, 스테이지 사건, 타워 개방 순서, 원문 모드 제한을 복원했다. 추가로 플레이 기록의 지도 좌표와 지도 화면 판독 경로를 별도 프로필로 제공한다.

**원작 실행 파일에서 추출한 완전한 게임 데이터라는 뜻은 아니다.** v14의 후보값·충돌·미확인값을 유지하고, 웹 게임이 실행되기 위해 선택한 보조값을 분리한다. 특정 플랫폼·빌드와의 수치 및 동작 일치는 아직 확정되지 않았다. 원본 아카이브는 수정하지 않는다.

타워 `cost`는 해당 단계에서 추가로 지불하는 비용이다. 기초 타워부터의 비용은 `cumulativeBaseCost`로 따로 보관한다. 능력 `values`는 v14 `levels[].parameters`의 값이다. 임의의 재설계 수치를 원문 값으로 덮어쓰지 않는다.

## 2. 원문 데이터와 실행값의 분리

적은 `hpByDifficulty`, `sourceMelee`, `sourceRanged`, `sourceBehaviors`에 원문 후보를 보존한다. `ranged`, `behaviors`, `speed` 등은 엔진이 소비하는 실행 스키마다. 원문에 없는 픽셀 사거리·속도·공격 간격의 보조값에는 `fieldDecisions` 및 해당 필드의 상태를 남긴다.

원거리 적의 웹용 사거리는 그림자 궁수 155px, 강령술사 145px, 트롤 챔피언 160px이다. 세 원문 사거리 값은 미확인이므로 `reportedRange:null`과 `rangeStatus:custom_pixel_radius_source_range_unknown`을 함께 둔다. 치유·보호막·격노·사망 폭발의 웹용 효과 반경도 각각 150·145·140·65px로 명시한다. 이 값들은 원작의 좌표 단위를 환산한 확정값이 아니다.

소서러의 원문 고유 저주는 별도 `intrinsicEffects`로 복원했다. 후보 매개변수는 방어력 배율 0.5, 지속시간 5초, 1.25초마다 고정 피해 10, 명목상 4회, 비중첩이다. 타워의 지상·공중 표적 가능 여부는 `canSelectGround`, `canSelectAir`로 전달한다.

30개 별 업그레이드에는 비용과 효과 전체를 보관하며, v16 원문 규칙 엔진은 각 업그레이드를 일반 타워·지원군·유성에 연결한다. 원작 영웅을 구현하지 않았으므로 정밀 사격의 Bolin, 비전 파쇄의 Elora·Magnus, 감속 저주의 Magnus 연계는 적용 대상이 없다. 정밀 조준은 웹 엔진의 범위 피해 감쇠를 제거하지만, 원문에서 미확인인 테슬라 정책을 확정하지 않는다. 가시 갑옷의 피해 반올림 등에도 미실측 실행 선택이 남는다. 실제 엔진의 적용 범위·자동화 검증·남은 동작 차이는 빌드 설명과 엔진 검증 결과를 함께 확인해야 한다. 특수 시설도 위치·종류·원문 사건의 복원과 작동 구현을 구분한다.

## 3. 웨이브 수량과 입구별 편성

### 선택 정책

v14는 103슬롯에서 출처가 일치하고, 144슬롯은 단일 출처이며, 13슬롯에 수량 충돌이 남아 있다. 실행 데이터는 기존과 같이 **wikily 후보가 있으면 해당 후보를 선택**한다. 이는 재현 가능한 실행 선택이며, 충돌이 해소됐다는 의미는 아니다.

충돌은 Silveroak Forest·Coldstep Mines·Stormcloud Temple의 강철 1웨이브와 The Dark Tower 캠페인 3·4·6·8·10·11·12·13·14·15웨이브에 남아 있다. `provenance.json`에는 선택된 관측·출처·수량 및 충돌한 후보를 모두 보관한다.

### 입구별 관측 복원

v15는 수량 후보를 선택하면서 다른 출처에만 남아 있던 입구별 세부 편성을 활용하지 않았다. v16은 **선택한 전체 적 수량과 종류가 정확히 같은 관측 중 입구 라벨이 있는 기록**을 찾아 편성을 복원한다. 수량의 출처와 입구 편성의 출처를 각각 남긴다.

- 103개 슬롯: 동일한 총수를 가진 관측에서 입구별 편성을 복원했다.
- 나머지 157개 슬롯: 명시적인 입구별 수량 관측이 없다. 보이는 길이 하나인 경우를 제외하면 원작의 경로 배분은 미복원이다.
- 실행 그룹 총 797개 중 325개는 관측 입구 라벨로 경로를 연결하고, 22개는 단일 경로라는 지형 조건으로 연결한다. 450개 그룹의 경로 배분은 미확정이다.

각 그룹의 `sourceEntryLabel`, `routingSourceId`, `routingObservationId`가 편성의 근거를 가리킨다. `referencePath`는 복원 지도 경로 인덱스이며 `referencePathStatus`/`routingStatus`에 근거 종류를 남긴다. `path`는 기존 자체 맵의 보조 인덱스로 별도 유지한다. 관측 라벨로 연결된 모든 `referencePath`가 지도 `entryPathMap`과 일치하는지 검증한다.

생성 순서와 시간은 복원하지 않았다. v14에서 `sourceOrderIsSpawnOrder`는 확인되지 않았고, 웹 엔진은 자체 그룹 시차와 생성 간격을 사용한다. 미확정 경로의 런타임 분배 역시 자체 규칙이다. 입구 라벨을 알아도 원작의 프레임별 출현 순서까지 알아낸 것으로 해석해서는 안 된다.

## 4. 지도·건설점·특수 시설

복원 지도는 Scott Louvau의 직접 플레이 기록과 공개 저장소의 위치 데이터를 근거로 한다.

- 플레이 기록: <https://relentlessoptimizer.com/KR/>
- 좌표·지도 기록: <https://github.com/ScottLouvau/kingdomrush>
- 사용 커밋: `a3c8218c19fab8e43596309de31eeeeb4a0bc8d6`
- 좌표 원문: `js/data/positions.json`
- 판독한 지도: `source-data/maps/L1.png`부터 `L12.png`

타워 위치는 작성자가 기록한 1920×1080 화면 좌표를 1000×620 웹 좌표계로 변환했다. 경로 중심선은 같은 화면을 보고 판독한 추정값이다. 좌표의 출처, 원본 픽셀, 변환식, 이미지 해시, 경로별 판독 상태를 `geometry_reconstruction_v16.json`에 남긴다. 이는 **원작 엔진의 내부 좌표 추출물이 아니며**, 화면 종횡비 변환으로 원작 사거리 단위와도 직접 호환되지 않는다.

155개 기록 위치는 일반 건설점 152개, 사전 배치 타워 1개, 특수 시설 2개로 분리한다.

| 위치 | 분류 | 실행상 처리와 근거 |
|---|---|---|
| Silveroak B8 | 엘프 훈련장 | 특수 시설, 일반 타워 건설 불가 |
| Silveroak E7 | 사전 배치 궁수 3단계 | 캠페인 시작 배치 후보. 지도 HUD의 0/15웨이브·700골드·20생명이 모드 근거 |
| Stormcloud A1 | 태양 광선 탑 | 특수 시설, 일반 타워 건설 불가 |

v14의 Silveroak `preplaced_sharpshooter` 특성은 시설 존재의 정합성을 제공하지만, 모드를 직접 명시한 증거는 아니다. 캠페인 판정 근거는 지도 화면이다. 엘프 훈련장·태양 광선 탑의 원문 전투 수치가 부족한 부분은 일반 타워로 치환하지 않는다.

12개 지도에는 총 27개 가시 경로가 있다. Citadel·Icewind·Wastes·Forsaken은 경로는 판독했지만 해당 웨이브의 입구별 수량 자료가 없어 `routing_inferred_without_per_entry_wave_counts`를 남긴다. 원작 비행 전용 경로, 동굴 전환 프레임, 개별 경로별 생성 타이밍은 복원되지 않았다.

기존 v15 자체 지도는 `paths`·`sites`로 유지하며, 복원 지도는 `referencePaths`·`referenceSites` 및 `referenceGeometry`로 제공한다. 두 프로필은 각자 출처와 상태가 있다. 상세 판독과 MIT 저작권 고지는 `../docs/LEVEL_RECONSTRUCTION_v16.md`에 있다. 원작 지도 이미지·스프라이트·실행 코드·음원은 게임 에셋으로 배포하지 않는다.

## 5. 원문 규칙과 보조 규칙

`stage.originalModes`는 원문 후보 규칙이고, `stage.modes`는 기존 플레이 보조 규칙이다. 같은 지도에서도 선택한 규칙에 따라 시작 골드·영웅 사용·타워 계열 제한·업그레이드 개방이 달라진다.

원문 규칙에는 시작 골드·생명, 허용 타워 계열, 영웅 사용 가능 여부, 별 업그레이드 단계 제한, 타워 단계 제한, 사전 배치 규칙 ID를 유지한다. 미확인값은 null이며, 별 업그레이드 단계 제한을 타워 단계 제한으로 해석하지 않는다. 실행에 필요한 미확인값은 보조 규칙으로 대체할 수 있으나 원문 값 자체는 바꾸지 않는다.

타워 개방 사건은 2스테이지의 2단계, 4스테이지의 3단계, Silveroak 5웨이브의 레인저, 이후 스테이지의 전문화 순서를 반영한다. `availableTowerIdsAtStart`는 해당 스테이지 이전에 열린 타워와 해당 스테이지 시작 사건을 합친 값이다. Silveroak의 웨이브 활성화 사건은 시작 보유 목록에 앞당겨 넣지 않는다.

보조 규칙은 캠페인 1~3스테이지의 시작 골드를 최소 300으로 맞춘다. 영웅 모드는 `max(원문 골드, 650 + 90 × 순번)`, 강철 모드는 `max(ceil(원문 골드 × 1.25), 1100 + 125 × 순번)`을 사용한다. 원문 골드가 없으면 해당 보조식을 적용한다. 보조 규칙은 모든 전문화를 허용하고 자체 영웅을 제공한다. 성채 강철의 허용 계열은 확인되지 않은 사전 배치 방어 시설을 대신하기 위해 궁수·병영·마법으로 확장하며, 원문 규칙의 병영 제한은 별도로 보존한다.

출처 ID는 `louvau_play_transcription_2026_11_18`이다. `startingGoldCandidates`, `startingGoldStatus`, `unknownFields`로 상태를 확인할 수 있다. 같은 플레이 기록의 재확인이므로 v14에 동일 URL이 있었다면 독립된 출처의 교차 검증으로 계산하지 않는다.

## 6. 레벨디자인 분석 데이터

`level-design-v16.json`과 런타임 `stage.waveMetrics`는 260개 웨이브의 초기 적 수, 보통 난이도 HP 합계, 기본 처치 골드, 공중·물리 방어·마법 저항·지원 적 수를 제공한다. 스테이지별 모드 합계, 가장 개체 수가 많은 웨이브, HP 합계가 높은 웨이브, 캠페인 최초 등장 적도 계산한다.

`normalHp`는 적의 보통 난이도 HP를 합한 값이며 방어력을 적용한 실효 HP가 아니다. `baseBounty`는 초기 편성의 처치 골드를 합한 값이며 시작 골드·웨이브 보너스·조기 호출 보상은 제외한다. 묘지 생성·강령술사의 해골·거미 알·저거너트 소환물, 치유·재생, 무한 반복 행동도 제외한다. 시간표가 미복원이므로 이 값으로 원작의 초당 압박량이나 필수 DPS를 확정하지 않는다.

보고된 수입은 `reportedIncome`으로 별도 보존하고, 기본 처치 골드와의 차이는 `reportedIncomeMinusBaseBounty`로 계산한다. 이 차이를 확인 없이 조기 호출 보상으로 단정하지 않는다. 원문에 기록된 최대 조기 호출 보상 후보는 `reportedEarlyCallBonusMaxCandidate`다.

적의 역할 분류와 스테이지 설계 의도는 분석자의 해석이며 `derived_classification`·`analytical_interpretation`으로 표시한다. 첫 등장 기록은 선택된 캠페인 최초 편성을 기준으로 한다. 소환되어 나타나는 적의 실제 최초 출현은 이 집계보다 빠를 수 있다.

저거너트는 성채 캠페인 17웨이브, J.T.는 사원 캠페인 19웨이브 재고에 포함된다. 베즈난은 어둠의 탑 15개 일반 웨이브 이후 별도 보스로 연결하고, 두 단계 HP 후보는 각각 6,666이다. 초기 재고 10,443에 베즈난을 추가하지 않는다.

## 7. 재구성으로 남아 있는 부분

이동속도와 사거리의 화면 단위, 생성 간격·순서, 미확정 입구 분배, 일부 근접 공격 보조값, 영웅, 보스 스크립트·타워 봉인 해제 조건, 시각 효과·아트·소리는 웹용 구현이다. 성기사·야만전사의 공격 간격 1.47초·1.37초도 플레이용 선택이다. 원문에 있는 행동 매개변수를 복원했더라도 원작의 애니메이션 타이밍이나 판정 프레임까지 일치한다고 주장하지 않는다.

`BALANCE_NOTES.md`와 `balance-validation.json`은 v15 엔진·자체 지도에서 실행한 과거 결과다. `historicalOnly:true`로 표시했으며 v16 복원 지도나 원문 규칙의 난이도 검증으로 재사용하지 않는다. v16의 데이터 검증과 최신 엔진 테스트를 구분해서 읽어야 한다.

## 8. 파일 구조와 재생성

| 파일 | 내용 |
|---|---|
| `reference_v14.json` | 사용자 원본에서 가져온 후보 수치·관측·출처의 축약 참조 |
| `geometry_reconstruction_v16.json` | 12개 지도의 근거·원본 픽셀·변환 좌표·경로·특수 시설 |
| `provenance.json` | 선택 정책, 260개 관측 선택, 충돌 후보, 보조값 결정, 지도 근거 |
| `data-validation.json` | 수량·원문 필드·입구 연결·지도 구조 검증 결과 |
| `level-design-v16.json` | 260개 웨이브 지표와 스테이지·모드·타워 개방 분석 |
| `enemy-components-v16.json` | 34개 적의 원문·실행 구성요소와 등장 기록 |
| `tower-components-v16.json` | 20개 타워 상태·18개 전문화 능력 |
| `progression-components-v16.json` | 30개 별 업그레이드·5개 스테이지 사건·모드 및 개방 규칙 |
| `../src/data.js` | 브라우저가 실제 소비하는 동일 런타임 데이터 |
| `../tools/prepare_data.py` | 표준 Python만 사용하는 결정적 변환·검증 스크립트 |

저장된 참조와 지도 근거로 다시 생성한다. 외부 패키지나 네트워크는 필요 없다.

```bash
python3 tools/prepare_data.py
```

사용자 원본 추출 폴더에서 참조를 새로 가져오려면 다음 명령을 사용한다.

```bash
python3 tools/prepare_data.py --source /path/to/KingdomRush_v14
```

출처 URL·기록 날짜·접근 방식은 `provenance.json`의 `sources`에 있다. v14에 기록된 접근 날짜를 v16의 재검증 날짜로 바꾸지 않는다. 새로 확인한 플레이 기록은 별도 출처 ID와 접근일을 사용한다. 참조 데이터 해시는 `referenceHash`로 보관해 같은 데이터에서 결과를 다시 만들 수 있다.
