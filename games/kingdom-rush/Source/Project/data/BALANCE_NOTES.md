# 플레이 가능성 확인: 제한된 정상 규칙 전략 프로브

## 확인한 결과

`tools/balance_probe.js`는 게임 엔진의 건설·강화·능력 구입·판매·영웅 이동·주문 호출 API만 사용한다. 무적, 골드 지급, 적 삭제, 생명 변경, 피해량 수정은 사용하지 않는다. 엔진의 자동 다음 웨이브 규칙을 따른다.

아래 두 실행은 **보통 난이도, 영구 업그레이드 0, 시드 20261118, 치트 없음**으로 관찰한 결과다.

| 스테이지 | 완료 범위 | 결과 | 생명 | 처치 | 게임 시간 |
|---|---|---|---:|---:|---:|
| 왕국의 성채 | 캠페인 17웨이브 + 저거너트 | 승리, 별 3개 | 20 | 480 | 약 735초 |
| 폭풍구름 사원 | 캠페인 19웨이브 + J.T. | 승리, 별 3개 | 20 | 268 | 약 728초 |

처치 수에는 전투 중 생성된 소환물이 들어갈 수 있다. 웨이브 정의의 최초 배치 수와 같은 통계가 아니다. 시간은 게임 내부 시간이며, 화면 배속에 따라 실제 대기 시간은 달라진다.

## 사용한 전략

### 성채: 레인저 → 원소술사 → 방어선 확장

공통 경로의 3번 건설점에 레인저와 맹독 화살을 먼저 준비한다. 4번 건설점에는 원소술사, 5번에는 두 번째 레인저를 배치한다. 대지 정령으로 적을 붙잡고 이후 비전의 탑·테슬라·병영을 확장한다. 큰 무리에 유성 폭격, 선두 지상 적에 지원군을 사용한다. 영웅은 공통 경로의 주요 방어 지점에 배치한다. 건설점 번호는 코드의 0부터 시작하는 인덱스다.

```bash
node tools/balance_probe.js citadel --ranger
```

### 사원: 고체력 적 처리 → 보스에 맞춰 후방 재배치

3·4·5번 건설점에 비전의 탑과 죽음의 광선을 먼저 마련해 설인 등 고체력 일반 적을 처리한다. 레인저·원소술사 등으로 보완한다. J.T.가 등장하면 영웅을 보스 근처로 이동하고, 보스의 남은 이동 경로를 더 이상 공격할 수 없는 앞쪽 타워는 판매하여 후방 마법 타워를 강화한다. 판매 환급과 실제 남은 골드 안에서만 다시 건설한다.

```bash
node tools/balance_probe.js stormcloud --ray
```

## 이 확인이 보장하지 않는 범위

이 결과는 두 캠페인에서 정상 게임 규칙으로 실제 승리할 수 있음을 확인한다. **36개 스테이지/모드 조합과 모든 난이도의 밸런스 인증은 아니다.** 모든 전략의 승리, 초보 사용자의 평균 승률, 모바일 조작 난이도도 이 스크립트로 판정하지 않는다.

어둠의 탑은 보통 난이도·영구 업그레이드 0으로 입구 중심 레인저/비전의 탑 전략을 시험했으며 7웨이브까지 진행한 뒤 패배했다. 최종 스테이지 전체 승리 전략은 이 프로브에서 완료하지 않았다. 그 결과를 승리로 기록하지 않는다. 원작 후보의 적 수를 줄여서 결과를 맞추지도 않았다.

초기 프로브에서 자동 웨이브 간격이 너무 짧아 여러 웨이브가 급격히 겹치는 문제가 확인되었다. 현재 엔진은 자체 출현 일정에 따라 자동 호출 간격을 35~65초로 조정하고, 적을 모두 처치했을 때는 3초 후 다음 웨이브로 넘어간다. 수동 조기 호출은 그대로 가능하다. 이는 원작 생성 시각을 복원한 값이 아니라 이 웹 프로필의 플레이 조정이다.

숫자 요약은 `balance-validation.json`에 있으며, 데이터 자체의 260슬롯/개체 수/능력 보존 검증은 별도 `data-validation.json`에 있다.
